## MA-001 로그인

> 유형: 화면
> URL 경로: `/login` (앱 진입 직후 화면)
> 연결 기능: `MFN-001`

### 1. 목적
회원 또는 직원(트레이너·골프강사·FC·스태프) 계정으로 로그인하여 역할별 네비게이션으로 분기시키는 진입 화면입니다. 회원은 전화번호 + 비밀번호로, 직원은 아이디 + 비밀번호로 로그인하며 직원 로그인은 트레이너/FC/스태프 하위 유형 선택 후 진입합니다.

### 2. UI 구성
- **상단 로고**: FitGenie 브랜드 로고
- **로그인 유형 탭**: 회원 로그인 / 직원 로그인 2탭
- **회원 로그인 폼**: 전화번호 입력(자동 하이픈), 비밀번호 입력(8자 이상)
- **직원 로그인 폼**: 아이디 입력, 비밀번호 입력, 하위 역할 라디오(트레이너 / FC / 스태프)
- **로그인 버튼**: 전체 폭 강조 버튼
- **비밀번호 찾기**: 회원 탭에서만 노출, SMS 인증 경유
- **앱 가입 / 연동**: 신규 회원의 첫 진입 경로 (MA-002)

### 3. 액션 / 흐름
1. 앱 실행 → 자동으로 본 화면이 표시됩니다.
2. 회원 로그인 탭: 전화번호 + 비밀번호 입력 → 로그인 클릭 → CRM의 회원 마스터와 매칭 → 매칭 시 MemberNavigator(홈/예약/QR/이용권/MY) 진입
3. 직원 로그인 탭: 하위 역할 선택 → 아이디 + 비밀번호 입력 → 로그인 클릭 → role 매칭 후 해당 Navigator 진입 (TrainerNavigator / FcNavigator / StaffNavigator)
4. golf_trainer 계정은 직원 로그인의 "트레이너" 선택에서 진입합니다.
5. 선택한 직원 유형과 실제 계정 role이 다르면 로그인이 거부됩니다.

### 4. 핵심 상태
| 상태 | 설명 |
|---|---|
| 초기 | 회원 로그인 탭이 기본 활성, 입력 폼 빈 상태 |
| 로그인 중 | 버튼 로딩 스피너, 입력 비활성 |
| 인증 실패 | 빨강 토스트 "로그인 정보를 확인해주세요" + 입력값 보존 |
| 비밀번호 만료 | 비밀번호 재설정 화면으로 강제 이동 |
| role 불일치 | "선택한 역할과 계정이 일치하지 않습니다" 차단 |

### 5. 권한
모든 미로그인 사용자가 진입 가능합니다. 로그인 성공 시 role 클레임에 따라 자동 분기됩니다.

### 6. 필수 예외처리
| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| 전화번호 형식 오류 | 인라인 "올바른 전화번호를 입력해주세요" | 입력 차단 |
| 비밀번호 8자 미만 | 인라인 "비밀번호는 8자 이상" | 차단 |
| 5회 연속 실패 | 계정 일시 잠금 안내 + 30분 후 재시도 | 보안 알림 |
| 회원 미연동 (CRM 미등록) | "앱 가입 / 연동에서 먼저 연동해주세요" | MA-002 진입 안내 |
| 탈퇴 회원 | "탈퇴 처리된 계정입니다" | 차단 |
| 직원 role 불일치 | "선택한 역할이 계정과 다릅니다" | 차단 |
| 네트워크 오류 | 토스트 + 재시도 | 자동 재시도 1회 |

### 7. 연동 / 자동화 참조
| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| CRM 회원 마스터 | 회원 로그인 시도 | role=member 매칭 검증 |
| CRM 직원 마스터 | 직원 로그인 시도 | role + 하위 유형 매칭 검증 |
| SMS 인증 | 비밀번호 찾기 | SMS 발송 + 만료 5분 |
| 푸시 토큰 등록 | 로그인 성공 | FCM/APNs 토큰 백엔드 등록 |

### 8. 핵심 디자인 요청사항
- 공통 색상, 간격, 폰트, 토스트 규칙은 `_공통/디자인_시스템.md`, `_공통/토스트_메시지.md`를 따릅니다.
- 본 섹션에 별도 명시된 UI 상태와 권한 차이가 있으면 도메인 공통보다 화면 정의를 우선합니다.

## MA-002 앱 가입 / 연동

> 유형: 화면
> URL 경로: 로그인 화면의 "앱 가입 / 연동" 진입
> 연결 기능: `MFN-002`

### 1. 목적
이미 CRM에 등록된 회원이 앱을 처음 사용할 때 본인 명의 전화번호 + SMS 인증으로 CRM 회원 마스터와 연동하는 화면입니다. 앱에서 자체 가입은 불가능하며, 센터에서 사전 등록된 회원만 연동 가능합니다.

### 2. UI 구성
- **단계 표시기**: 1. 본인 확인 → 2. SMS 인증 → 3. 비밀번호 설정
- **이름·전화번호 입력**: CRM 마스터와 매칭 검증
- **SMS 인증 코드 입력**: 6자리, 만료 5분, 재발송 30초 후
- **비밀번호 설정**: 8자 이상 + 영문/숫자/특수문자 조합, 비밀번호 확인 일치
- **완료 버튼**: 회원 가입 확정 후 홈(MA-100) 자동 진입

### 3. 액션 / 흐름
1. 이름 + 전화번호 입력 → CRM 매칭 확인
2. SMS 인증 코드 발송 → 회원이 입력
3. 비밀번호 설정 → 가입 완료 → MA-100 자동 이동
4. `app_linked_at` 타임스탬프가 CRM에 저장됩니다.

### 4. 핵심 상태
| 상태 | 설명 |
|---|---|
| 본인 확인 중 | 이름·전화번호 입력 후 매칭 검증 |
| SMS 발송됨 | 60초 카운트다운 |
| 인증 완료 | 비밀번호 설정 단계 |
| 가입 완료 | "환영합니다" 모달 + 홈 이동 |

### 5. 권한
미로그인 사용자가 진입 가능합니다.

### 6. 필수 예외처리
| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| CRM 미등록 | "센터에 먼저 등록 후 다시 시도해주세요" | 차단 + 센터 연락처 표시 |
| 이름·전화번호 불일치 | "입력 정보가 일치하지 않습니다" | 차단 |
| SMS 인증 만료 | "재발송해주세요" | 재발송 버튼 활성 |
| 5회 인증 실패 | 30분 일시 잠금 | 보안 알림 |
| 이미 연동된 회원 | "이미 앱 연동이 완료된 계정입니다. 로그인해주세요" | 로그인 화면 이동 |
| 탈퇴 회원 재가입 시도 | "탈퇴 처리된 계정입니다" | 차단 |

### 7. 연동 / 자동화 참조
| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| CRM 회원 매칭 | 이름·전화번호 입력 | 단일 매칭 검증 |
| SMS 인증 | 본인 확인 | SMS 발송 + 5분 만료 |
| `app_linked_at` | 가입 완료 | CRM 회원 마스터 갱신 |
| 신규 회원 환영 모달 | 첫 가입 완료 | MA-900 신규 회원 환영 자동 호출 |

## MA-100 회원 홈 대시보드

> 유형: 화면
> URL 경로: 로그인 후 디폴트 (member Tab의 홈)
> 연결 기능: `MFN-101`

### 1. 목적
회원이 앱을 열었을 때 가장 먼저 보이는 메인 허브로, 오늘의 예약·이용권 잔여·만료 D-day·최근 출석·푸시 알림 미확인 건수를 한 화면에 통합 표시합니다. 회원의 헬스장 사용 흐름의 시작점이며 다른 화면으로의 진입 허브 역할도 합니다.

### 2. UI 구성
- **상단 인사**: "안녕하세요, {회원명}님"
- **오늘의 수업 카드**: 다음 예약 1건의 시간·강사·종목·QR 입장 버튼 (수업 30분 전 노출)
- **이용권 카드**: 활성 이용권 1~3개 — 종류·잔여 횟수 또는 D-day·만료일
- **HQ-09 만료 알림 배너**: docs4/V1 D10 HQ-09 회원 이용권 만료 step 대상일 때 표시
- **빠른 액션 4종**: 수업 예약 / QR 입장 / 체성분 보기 / 상품 스토어
- **최근 활동 5건**: 최근 출석·예약·결제·체성분 측정
- **공지사항 배너**: 활성 공지 1건 (드래그로 닫기)
- **하단 탭바**: 홈 · 예약 · QR · 이용권 · MY (5탭)

### 3. 액션 / 흐름
1. 로그인 직후 또는 탭바 홈 클릭 시 본 화면 진입.
2. 오늘의 수업 카드 클릭 → 수업 예약 상세(MA-121).
3. QR 입장 버튼 클릭 → MA-110 QR 화면 풀스크린.
4. 이용권 카드 클릭 → 이용권 상세(MA-131).
5. 빠른 액션 → 각 화면으로 이동.
6. HQ-09 만료 알림 배너 클릭 → 재등록 추천 플랜(MA-138).

### 4. 핵심 상태
| 상태 | 설명 |
|---|---|
| 정상 | 오늘 수업 + 이용권 + 활동 정상 표시 |
| 오늘 수업 없음 | "오늘 예정된 수업이 없어요" + 예약 안내 |
| 이용권 없음 | "이용권을 구매해주세요" + 스토어 진입 |
| HQ-09 만료 step 대상 | 만료 알림 배너 강조 |
| 만료 회원 | 전체 카드 회색 + 재등록 안내 |
| 데이터 로딩 실패 | 재시도 버튼 + 캐시 데이터 표시 |

### 5. 권한
- `member`: 본인 데이터만 표시
- 트레이너·FC·스태프는 본 화면에 진입하지 않습니다 (각 역할 전용 홈 사용)

### 6. 필수 예외처리
| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| 네트워크 오류 | 캐시 데이터 + "오프라인" 배지 | 자동 재시도 |
| 푸시 권한 거부 | 상단 인라인 "푸시를 허용해주세요" | 설정 진입 안내 |

| 알림 99+ | "99+" 배지 표시 | - |

### 7. 연동 / 자동화 참조
| 연계 대상 | 트리거 | 영향 |
|---|---|---|

| CRM 예약 시스템 | 오늘 예약 조회 | 5분 캐시 |

### 8. 핵심 디자인 요청사항
- 공통 색상·간격·폰트·토스트 규칙은 `_공통/디자인_시스템.md`, `_공통/토스트_메시지.md`를 따른다.
- 본 섹션에 별도 명시된 UI 상태와 권한 차이가 있으면 도메인 공통보다 화면 정의를 우선한다.

## MA-110 QR 입장

> 유형: 화면
> URL 경로: 탭바 QR (member Tab) 또는 홈 카드
> 연결 기능: `MFN-110`

### 1. 목적
회원이 본인 QR 코드를 표시하여 센터 키오스크·게이트에 스캔해 자동 출석 처리하는 풀스크린 QR 표시 화면입니다.

### 2. UI 구성
- **풀스크린 QR 코드**: 회원 ID + 타임스탬프 + 회전 토큰 (7일 만료)
- **밝기 자동 최대화**: 화면 진입 시 시스템 밝기 100%
- **남은 갱신 시간**: 7일 D-day 표시
- **닫기 X**: 우상단

### 3. 액션 / 흐름
1. 탭바 QR 또는 홈 카드 → 풀스크린 QR 화면.
2. 화면 진입 시 시스템 밝기 100% + QR 코드 표시.
3. 회원이 센터 키오스크에 스캔 → 출석 자동 등록 (CRM 자동 차감).
4. 닫기 클릭 또는 5분 무동작 시 자동 닫힘 + 밝기 복원.

### 4. 핵심 상태
| 상태 | 설명 |
|---|---|
| 정상 | QR 표시 + 밝기 100% |
| QR 만료 (7일) | 자동 갱신 + "갱신됨" 토스트 |
| 카메라 권한 거부 (수동 입력) | "코드 직접 입력" 옵션 안내 |
| 회원 비활성 | "이용권을 확인해주세요" + 차단 |

### 5. 권한
`member`만 가능합니다. 직원 역할은 QR 본인 표시가 아닌 수동 출석(MA-520) 사용.

## MA-111 출석 이력

> 유형: 화면
> URL 경로: MY > 출석 이력
> 연결 기능: `MFN-103`

### 1. 목적
회원이 본인의 출석 이력을 월별 캘린더 + 리스트로 조회하는 화면입니다. 출석 결과 3종(성공/실패/중복)을 색상으로 구분하여 표시합니다.

### 2. UI 구성
- **월별 캘린더**: 출석일에 점 표시, 색상별 결과 구분 (녹색 성공·회색 중복·빨강 실패)
- **리스트 (최근 30건)**: 일시·결과·체크인 방식(QR/수동/얼굴인식)·체크인 지점
- **월 이동 화살표**: 좌우 스와이프 또는 화살표
- **요약**: 이번 달 출석 N회 / 평균 주 N회

### 3. 액션 / 흐름
1. MY 탭 → 출석 이력 진입.
2. 캘린더에서 날짜 탭 → 해당 일 상세.
3. 리스트 행 탭 → 출석 상세 (해당 수업·강사 표시).

### 4. 핵심 상태
| 상태 | 설명 |
|---|---|
| 이력 있음 | 캘린더 + 리스트 정상 표시 |
| 이력 없음 | "아직 출석 이력이 없어요" |
| 데이터 로딩 중 | 스켈레톤 |

### 5. 권한
`member` 본인 이력만 조회 가능합니다.

### 6. 필수 예외처리
| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| 데이터 12개월 초과 | 12개월 이전 데이터는 별도 로드 | 페이지네이션 |
| 결과=실패 사유 표시 | 만료·미등록·미수금 등 사유 비고 표시 | - |

### 7. 연동 / 자동화 참조
| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| CRM 출석 레코드 | 화면 진입 | 5분 캐시 |

## 핵심 정책 (도메인 공통)

### 로그인 정책
- 회원: 전화번호 + 비밀번호 (8자 이상)
- 직원: 아이디 + 비밀번호 + 하위 역할 선택
- 5회 연속 실패 → 30분 잠금
- role 불일치 → 차단

### 회원가입 정책
- CRM에 사전 등록된 회원만 앱 연동 가능 (자체 가입 불가)
- SMS 인증 5분 만료, 재발송 30초 후
- `app_linked_at` 타임스탬프로 연동 시점 추적

### 출석 정책 (docs4/V1 D11 SCR-I001 정합)
- 결과 3종: `성공` / `실패` / `중복` (docs4 _공통/상태전이.md 정본)
- QR 입장 기본, 수동 출석은 스태프만 가능
- 당일 중복 체크인 차단
- 이용권 만료·정지·페널티 회원은 출석 차단

### 예약/취소 정책 (docs4/V1 D04 정합)
- 취소 마감 시간: 수업 시작 N시간 전까지 (센터별 설정, 기본 2시간)
- 마감 후 취소 = 노쇼 처리
- 동일 시간대 중복 예약 불가
- 회원이 트레이너에게 예약 요청 시 강사 승인 후 확정
- 횟수 차감 시점: 수업 완료(completed) 시 (CLS-07 정합)

### 이용권 정책 (docs4/V1 D02 정합)
- 기간제: 시작일~종료일 무제한 이용
- 횟수제: 잔여 횟수 차감, 0회 만료
- 홀딩: 기간제만, 최소 7일~최대 30일 (센터 설정)
- 만료 알림: docs4/V1 D10 HQ-09 본사 step + 지점 추가 step 결과 표시만

### 결제 정책 (docs4/V1 D03 정합)
- 결제 수단: 토스페이먼츠 (카드/계좌이체/간편결제)
- 결제 완료 후 이용권 자동 생성
- 환불은 CRM 관리자(Owner(지점장)/매니저) 승인 후 처리
- 쿠폰은 결제 시 1장만 적용
- PAY-06 결제링크는 docs4 _정책확인필요에 따라 고객사 확인 전까지 회원앱에서 노출하지 않음

### 알림 정책
- 푸시 채널: 예약·이용권·상담·공지·HQ-09 만료 알림
- 카카오 알림톡 fallback 옵션
- 99+ 배지 표시

### 데이터 접근 정책
- 회원은 본인 데이터만 조회 가능
- CRM과 동일 회원·예약·이용권 기준 공유
