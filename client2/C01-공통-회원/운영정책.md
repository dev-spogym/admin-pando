# C01-공통-회원 회원앱 — 운영정책

> 개발사용 운영정책입니다. 이 파일만으로 해당 도메인의 운영 기준, 정책값, 예외 기준을 확인할 수 있도록 재구성했습니다.

## 1. 핵심 원칙
- 회원앱은 관리자 CRM(`docs4`)의 모바일 확장이며 회원·예약·이용권·결제·출석 데이터는 CRM과 동일 기준을 공유한다.
- 회원이 자체적으로 가입할 수 없고, CRM에 사전 등록된 회원만 앱 연동이 가능하다.
- 한 계정은 하나의 역할만 가지며 역할은 CRM에서 사전 지정된다.
- 회원앱 role: `member / trainer / golf_trainer / fc / staff` (5종).
- 관리자 CRM 권한(`superAdmin / primary / owner / manager / fc / trainer / staff / readonly`)과 분리 운영한다.
- 만료 알림 기준일은 회원앱이 직접 정의하지 않고 docs4/V1 D10 HQ-09 회원 이용권 만료 step 결과를 표시한다.

## 2. 상태 / 운영 정의

### 회원 실제 상태 7종 (docs4 정본)
| 코드 | 한글 | 설명 |
|---|---|---|
| ACTIVE | 활성 | 이용권 유효 + 정상 출석 가능 |
| EXPIRED | 만료 | 이용권 종료일 도달 |
| SCHEDULED | 예정 | 만료일 D-30 ~ D-8 범위 |
| EXPIRING | 임박 | 만료일 D-7 ~ D-Day 범위 |
| HOLDING | 홀딩 | 일시 정지 (기간제만, 7~30일) |
| UNREGISTERED | 미등록 | 일부 정보만 들어와 있고 정식 등록 미완 |
| WITHDRAWN | 탈퇴 | 운영자 탈퇴 처리 완료 |

회원 제한 플래그 `정지`는 실제 회원 상태값이 아니라 현재 상태 위에 추가되는 이용 제한 플래그이며, 회원앱에서는 본래 상태 화면에 정지 배지로 함께 노출된다.

### 출석 결과 3종 (docs4 정본)
`성공` / `실패` / `중복`
- `실패` 사유 세부: 만료·미등록·미수금 차단·정지·페널티·중복 외 차단·허용 시간 외
- `중복`은 10분 이내 재시도 (별도 카운트, 실패 합산 안 함)

### 결제링크 5종 상태 (docs4/V2 PAY-06 정본, 회원앱 노출 대기)
`발송됨` / `결제완료` / `만료` / `무효화` / `발송실패`

## 6. 정책 결정 근거
- 화면별 구현 판단은 `UI 구성`, `액션 / 흐름`, `권한`, `필수 예외처리` 순서로 확인한다.
- 여러 항목 값이 충돌하면 client2 안에서 하나의 기준값으로 보정해 반영한다.
- CRM 데이터(회원 마스터·예약·이용권·결제·출석)는 docs4 정본을 따른다.
- 정책값이 확정되지 않은 항목은 docs4 `_정책확인필요.md`에 별도 관리한다.

## 8. CRM 정합 기준
회원앱은 다음 docs4 도메인의 정본 데이터를 참조한다.
- 회원 마스터: docs4/V1 D02 회원관리
- 예약 / 수업: docs4/V1 D04 수업관리
- 이용권 / 상품: docs4/V1 D05 상품관리
- 결제 / 환불: docs4/V1 D03 매출관리
- 만료 step (HQ-09): docs4/V1 D10 본사관리 + D02 회원 상태/이용권 데이터
- 출석 결과 3종: docs4 _공통/상태전이.md
- 결제링크 5종: docs4/V2 PAY-06 (회원앱 노출은 고객사 확인 후)

회원앱 UX 영역:
- QR 입장 흐름·갱신 주기는 D11 출입/출석 기준과 보안 정책을 따른다.
- 푸시 알림 토큰·채널·우선순위는 NFR-19와 EXT-MSG-01 기준을 따른다.
- 오프라인 큐잉·재시도는 docs4 공통 에러/상태전이 기준을 따른다.
- 딥링크 라우팅은 회원앱 진입 UX이며, 도착 화면의 데이터 판정은 각 docs4 도메인을 따른다.
- 디바이스 정보·앱 버전 호환성은 C08 시스템공통과 docs4 외부연동 기준을 따른다.
- SMS 인증 흐름은 EXT-MSG-03 기준을 따른다.
