## 오른쪽 설명 패널 보강 기준

회원앱 검수 화면은 왼쪽에 실제 모바일 화면을 두고, 오른쪽에는 해당 화면을 기획자가 설명하는 방식으로 구성한다. 설명은 화면을 보며 바로 대조할 수 있어야 하므로 화면 목적만 쓰지 않고, 현재 구현된 화면 블록과 공통 UI 요소까지 함께 적는다.

노출 범위는 퍼블리싱, UX/UI, 화면 상태, 목업 데이터 기준으로 제한한다. API, DB, 내부 파일 구조, 개발 구현 방식은 클라이언트 검수용 설명에 노출하지 않는다.

## 목업 데이터 기준

퍼블리싱 검수 단계에서는 화면에 필요한 데이터가 모두 목업으로 제공되어야 한다. 센터, 강사, 상품, 이용권, 예약, 결제, 리워드, 커뮤니티, 업무 대상 데이터는 실제 연동 여부와 무관하게 정상 상태와 빈 상태를 모두 확인할 수 있어야 한다.

상태별 표현은 정상, 데이터 없음, 제한, 완료, 실패, 처리 중, 만료 예정, 사용 완료를 화면에서 구분할 수 있어야 한다. 특히 결제 실패, 환불, 신고/차단, 권한 요청, 앱 업데이트처럼 사용자가 불안해할 수 있는 상태는 이유와 다음 행동을 같은 화면에서 안내한다.
