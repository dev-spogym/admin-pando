# 회원앱 권한 매트릭스

> 본 문서는 회원앱(FitGenie Mobile App) 5종 role의 권한 매트릭스입니다. 관리자 CRM(`docs4`) 권한 매트릭스와 별도로 운영되며, 같은 표기인 `fc`, `staff`도 채널에 따라 접근 범위가 다릅니다.

## 1. 회원앱 5종 role

| code | display | scope | 주요 capabilities | limits |
|---|---|---|---|---|
| `member` | 회원 | 본인 데이터 | 예약·QR·결제·이용권·체성분·후기·커뮤니티 | 본인 데이터만 |
| `trainer` | 트레이너 | 본인 담당 수업·회원 | 수업 시작/완료·서명·체성분 기록·평가 | 담당 외 회원 read-only/hidden |
| `golf_trainer` | 골프강사 | 본인 담당 수업·회원 | 트레이너 + 쌍방서명·레슨 확인서 | 동일 |
| `fc` | FC | 본인 담당 리드·회원 | 상담 등록·만료 회원 재등록·메모 | 등록완료 수동 저장 불가 (등록 요청만) |
| `staff` | 스태프 | 전체 회원 조회 | 회원 조회 read-only·수동 출석 | 수정·삭제·엑셀 불가 |

## 3. 핵심 권한 분기

### 로그인 분기 (MA-001)
```
앱 실행
  └─ 로그인 화면 (MA-001)
       ├─ 회원 로그인 (전화번호 + 비밀번호)
       │    └─ member → MemberNavigator (홈/예약/QR/이용권/MY)
       └─ 직원 로그인 (아이디 + 비밀번호)
            ├─ 트레이너 선택 → trainer / golf_trainer → TrainerNavigator
            ├─ FC 선택     → fc                       → FcNavigator
            └─ 스태프 선택  → staff                    → StaffNavigator
```

### 데이터 접근 정책 (docs4/V1 D02 정합)
| 역할 | 회원 데이터 | 수업 데이터 | 결제 데이터 | 리드 / 상담 |
|---|---|---|---|---|
| member | 본인만 | 본인 예약만 | 본인 결제만 | 본인 관련만 |
| trainer / golf_trainer | 본인 담당만 (담당 수업 1+) | 본인 담당만 | 미접근 | 미접근 |
| fc | 본인 담당만 | 미접근 | 미접근 | 본인 담당 리드 + strict_owner |
| staff | 전체 read-only | 전체 read-only | 미접근 | 미접근 |

### 회원 등록 권한
- member: 본인 가입 (CRM 사전 등록 회원만 앱 연동)
- fc: **회원 등록 직접 확정 불가** → "회원 등록 요청" 생성 → Owner(지점장)/매니저 이어받기 (docs4/V1 D08 SCR-070 정합)
- staff: 회원 등록 불가
- trainer / golf_trainer: 회원 등록 불가

## 4. CRM 권한과 분리 원칙

### docs4 CRM 권한 (관리자 웹) - 별도 채널
`superAdmin / primary / owner / manager / fc / trainer / staff / readonly`

### client2 회원앱 권한 - 본 문서
`member / trainer / golf_trainer / fc / staff`

### 같은 표기 `fc` / `staff`도 채널 분리
- CRM `fc`: 관리자 웹의 FC 권한 (D08 마케팅 SCR-070 등에서 사용)
- 회원앱 `fc`: 회원앱 채널의 FC 권한 (MA-4XX FC 화면 사용)
- 같은 직원이 두 채널 모두 사용 가능 (CRM에 한 명, 회원앱에 한 명으로 매핑)
- 데이터 접근 범위는 채널 별도 정의 (회원앱은 본 문서, CRM은 docs4 정본)

### 멀티 역할 금지
한 계정은 하나의 역할만 가지며, 역할은 CRM에서 사전 지정됩니다. 트레이너이면서 회원인 경우 별도 계정 사용.

## 5. 권한 변경 시 동기화
- CRM에서 직원 권한 변경 → 회원앱 다음 로그인 시 반영 (JWT 토큰 갱신)
- 직원 퇴사 처리 → 회원앱 자동 로그아웃 + 토큰 무효화
- 회원 탈퇴 → 회원앱 진입 시 차단 + 안내
- 회원 정지 플래그 ON → 회원앱 QR 출석 차단 (조회는 가능)

## 6. 권한 차단 UX 일관성
- 1차 진입점에서 메뉴 자체 숨김 (예: 스태프는 결제·예약 메뉴 숨김)
- 직접 URL/딥링크 접근 시 권한 차단 안내 + 홈 자동 이동
- 백엔드 응답 403 → "권한이 없어요" 토스트 + 변경 적용 안됨
- 모든 권한 차단 이벤트는 docs4 SCR-097 감사 로그에 기록
