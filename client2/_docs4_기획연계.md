# client2 - docs4 기획 연계 매트릭스

작성일: 2026-05-29

이 문서는 회원앱 `client2`에 정의된 화면과 기능을 관리자 CRM 기준 문서 `docs4`에 연결하기 위한 정합성 매트릭스입니다. 개발자는 회원앱 화면 동작은 `client2`를 기준으로 구현하되, 회원·예약·결제·이용권·출석·권한·알림처럼 CRM과 같은 데이터를 쓰는 기능은 아래 `docs4` 기준 문서를 함께 확인합니다.

## 판정 기준

| 판정 | 의미 |
|---|---|
| docs4 정합 | 데이터·상태·정책 기준이 `docs4`에 있으며, 회원앱은 모바일 채널 UI만 별도로 구현한다. |
| 부분 정합 | `docs4`에 CRM 기준은 있으나 모바일 UX, 외부 SDK, 실시간 동기화, 앱 전용 정책은 `client2` 또는 추가 기획이 필요하다. |
| V2/개발 대기 | `docs4/V2` 또는 `docs4/_정책확인필요.md`에 걸려 있어 고객사/판도 확인 전에는 완료 범위로 보지 않는다. |
| 기획 필요 | `docs4`에 대응 기능이 없거나 관리자 CRM 범위를 넘어서는 회원앱 전용 기능이다. 별도 화면·정책·데이터 기획이 필요하다. |

## 무결성 보정

- C05 결제주문 화면 ID는 C03 FC 화면과 충돌하지 않도록 `MA-8XX`로 분리했다.
- C06 리워드활동 화면 ID는 C03 스태프 화면과 충돌하지 않도록 `MA-7XX`로 분리했다.
- C04 탐색플랫폼 `MA-312/313`은 C02 골프 서명 화면과 충돌하지 않도록 `MA-314/315`로 보정했다.
- C01에서 참조하던 신규 회원 환영 모달은 C08 실제 화면 ID와 맞춰 `MA-900`으로 통일했다.
- `client2` 내부의 CRM 정합 참조는 `docs4` 기준으로 교체했다.

## 운영 원칙

1. `docs4 정합` 항목은 `docs4/V1` 기준을 우선 적용한다.
2. `V2/개발 대기` 항목은 `docs4/V2` 또는 `docs4/_정책확인필요.md` 확인 전에는 개발 완료 범위로 보지 않는다.
3. `기획 필요` 항목은 `client2`에 현재 UX 초안이 있더라도 `docs4` 기준에서 가져올 수 없는 기능이므로 별도 기획 확정 후 개발한다.
4. 모바일 화면 ID는 이 문서의 보정 결과를 기준으로 유지한다. 새 화면을 추가할 때는 기존 `MA-XXX`와 중복되지 않는지 먼저 확인한다.
