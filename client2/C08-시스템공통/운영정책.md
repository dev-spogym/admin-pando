# C08-시스템공통 회원앱 — 운영정책

## 1. 핵심 원칙
- 시스템 공통 도메인은 모든 역할이 공통으로 사용하는 시스템 레벨 화면과 공통 컴포넌트를 다룬다.
- docs4/V1 D01 공통의 모바일 채널 역할이며 권한 매트릭스·상태전이·디자인 시스템은 docs4 정합을 따른다.
- 공통 컴포넌트 4종(토스트·모달·로딩·에러 바운더리)은 docs4 디자인 시스템, 에러/예외 표준, 토스트 메시지 기준을 따른다.
- 오프라인 모드·네트워크 오류·앱 업데이트는 회원앱 UX이며 운영 안내·공지·알림 기준은 docs4 공통/D09 기준을 따른다.

## 2. 상태 / 운영 정의

### 앱 업데이트 종류 2종
- Critical (강제): 보안 패치·치명 버그
- Minor (권장): 기능 추가·UI 개선

### 네트워크 상태 4종
온라인 / 오프라인 / 약한 연결 (3G) / 서버 점검

### 권한 요청 종류
푸시 / 위치 / 카메라 / 사진 / 마이크 (선택)

### 토스트 종류 4종
성공 (녹색) / 정보 (파랑) / 경고 (노랑) / 오류 (빨강)

### 약관 종류 2종 (가입 시)
- 필수: 서비스 이용약관, 개인정보 처리방침
- 선택: 마케팅 정보 수신 동의

## 3. 권한·책임 분리
| 역할 | 본 도메인 접근 |
|---|---|
| member / trainer / golf_trainer / fc / staff | 전체 공통 화면 사용 (역할 분기 없음) |
| 비로그인 | 약관·서버 점검·앱 업데이트만 접근 |

## 4. KPI / 성과 측정
| KPI | 산식 | 측정 주기 |
|---|---|---|
| 앱 충돌률 | 충돌 세션 / 전체 세션 × 100 | 일 단위 |
| 강제 업데이트 적용률 | 업데이트 적용 사용자 / 강제 업데이트 대상 × 100 | 24시간 단위 |
| 푸시 권한 허용률 | 푸시 허용 / 가입 회원 × 100 | 월 단위 |
| 오프라인 큐잉 성공률 | 복구 후 동기화 성공 / 오프라인 큐 발생 × 100 | 일 단위 |
| 평균 앱 시작 시간 | cold start ~ 첫 화면 표시 평균 | 일 단위 |

## 5. 자동화 정책
| 자동화 | 실행 시점 | 처리 동작 |
|---|---|---|
| 푸시 토큰 갱신 | 로그인 시점 + 24시간 주기 | FCM/APNs 토큰 백엔드 등록 |
| 앱 버전 체크 | 앱 진입 시 | 강제 업데이트 시 진입 차단 |
| 오프라인 큐 동기화 | 네트워크 복구 시 | 자동 동기화 |
| 에러 리포트 전송 | 충돌 발생 시 | Sentry/Crashlytics 자동 전송 |
| 캐시 만료 | 5분 TTL | 자동 무효화 |
| QR 캐시 갱신 | 매일 자정 | 7일 경과 QR 자동 갱신 (C01 정합) |
| 공지 배너 갱신 | 매시간 | 활성 공지 배너 갱신 |

## 6. 운영 예외 처리
| 케이스 | 처리 방식 | 후속 조치 |
|---|---|---|
| 네트워크 단절 | 오프라인 배지 + 캐시 데이터 표시 | 자동 재시도 |
| 서버 점검 (5xx) | MA-920 점검 화면 + 복구 시간 안내 | 복구 후 자동 진입 |
| 강제 업데이트 | 진입 차단 + 스토어 이동 | - |
| 권장 업데이트 | 24시간 후 재안내 | 회원 선택 |
| 푸시 권한 거부 | 인라인 안내 + 설정 진입 | - |
| 위치 권한 거부 | 수동 입력 fallback | - |
| 카메라 권한 거부 (QR) | "코드 직접 입력" 옵션 | - |
| 앱 충돌 | 에러 바운더리 fallback + 재시도 | 자동 리포트 |
| 오프라인 큐 100건 초과 | "오프라인 큐가 가득 찼습니다" 경고 | 동기화 권장 |
| 약관 미동의 가입 시도 | "필수 약관에 동의해주세요" | 차단 |
| OS 미지원 (iOS 13 이하·Android 7 이하) | 진입 차단 + OS 업데이트 안내 | - |
| 디바이스 시간 변조 (QR 등) | 보안 검증 실패 + 차단 | - |
| 무한 로딩 (60초 초과) | "재시도" 버튼 표시 | 자동 timeout |
| 푸시 토큰 등록 실패 | retry 3회 → 운영자 알림 | 자동 |
| 첫 진입 약관 동의 거부 | 가입 진행 불가 | - |

## 7. CRM 정합 기준
- 약관 / 개인정보 동의: docs4/V1 D02 회원관리 (consent_at, consent_version)
- 공지사항: docs4/V1 D09 SCR-085 정본
- 본사 점검 안내: docs4/V1 D09 운영정책
- 푸시 알림 채널: docs4 NFR-19 정합
- 디자인 시스템: docs4 `_공통/디자인_시스템.md` 정합

회원앱 UX 영역:
- 신규 회원 환영 UX는 D02 회원 등록/연동 결과를 모바일에서 안내한다.
- 오프라인 큐잉/동기화는 docs4 공통 에러/상태전이 기준을 따른다.
- 앱 업데이트 강제·권장 흐름은 D09 공지/점검 및 공통 토스트 기준을 따른다.
- 푸시 알림 토큰 관리는 EXT-MSG-01/NFR-19 기준을 따른다.
- 디바이스 권한 요청 UX는 D01 공통/권한 및 외부연동 기준을 따른다.
- 공통 컴포넌트와 디자인 토큰은 docs4 디자인 시스템/토스트/에러 표준을 따른다.
- 에러 리포트는 PII 제외, 운영자 요약 알림 기준을 따른다.

## 8. 보안 정책
- HTTPS 통신 필수
- API 통신은 JWT 토큰 (만료 1시간 + refresh 토큰)
- 푸시 알림은 회원 식별자 없이 토픽 기반 또는 디바이스 토큰 사용
- 회원 PII는 에러 리포트에서 자동 제외
- 디바이스 시간 변조 감지 시 보안 검증 차단
- 로그아웃 시 토큰·캐시·QR 모두 삭제
