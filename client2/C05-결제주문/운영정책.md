# C05-결제주문 회원앱 — 운영정책

## 1. 핵심 원칙
- 회원앱 결제·주문 도메인은 docs2 D03 매출관리 PAY-01 결제 처리의 모바일 채널이다.
- 결제 수단은 토스페이먼츠 (카드/계좌이체/간편결제) 한국 시장 전용.
- PAY-06 결제링크는 docs2 _정책미확정에 따라 고객사 확인 전까지 회원앱에서 노출하지 않는다.
- 모든 결제·환불 데이터는 CRM 매출관리 정본을 공유한다.
- 환불은 회원이 신청, CRM Owner(지점장)/매니저가 승인 후 처리.

## 2. 상태 / 운영 정의

### 결제 상태 6종
대기 / 결제중 / 결제완료 / 결제실패 / 환불요청중 / 환불완료

### 결제 수단
- 카드 (토스페이먼츠)
- 계좌이체 (토스페이먼츠)
- 간편결제 (카카오페이, 토스페이, 네이버페이 등 토스페이먼츠 통합)
- 결제링크 (PAY-06): docs2 _정책미확정, 회원앱 노출 보류

### 환불 상태 4종
요청대기 / 승인됨 / 환불완료 / 거절

### 쿠폰 적용 규칙
- 결제 시 1장만 적용 (중복 할인 방지)
- 마일리지와 동시 사용 가능

### 마일리지 정책
- 적립률: 결제 금액 1% (센터 설정)
- 사용 기준: 1마일리지 = 1원
- 사용 단위: 100원 단위
- 다른 혜택과 중복 가능

## 3. 권한·책임 분리
| 역할 | 회원앱 권한 |
|---|---|
| member | 본인 결제·환불 요청·결제수단 관리 |
| trainer / golf_trainer | 본 도메인 미접근 |
| fc | 본 도메인 미접근 (CRM POS는 D03 별도) |
| staff | 본 도메인 미접근 |

환불 승인 권한은 CRM 관리자(Owner(지점장)/매니저)에게 있으며, 회원앱에서는 요청만 가능.

## 4. KPI / 성과 측정
| KPI | 산식 | 측정 주기 |
|---|---|---|
| 결제 성공률 | 결제완료 / 결제 시도 × 100 | 일 단위 |
| 평균 결제 금액 | 총 결제 금액 / 결제 건수 | 일 단위 |
| 환불률 | 환불 건수 / 결제 건수 × 100 | 월 단위 |
| 쿠폰 사용률 | 쿠폰 사용 결제 / 전체 결제 × 100 | 월 단위 |
| 구독 유지율 | 활성 구독자 / 전체 구독 등록자 × 100 | 월 단위 |

## 5. 자동화 정책
| 자동화 | 실행 시점 | 처리 동작 |
|---|---|---|
| 이용권 자동 생성 | 결제 완료 즉시 | docs2 D05 상품 마스터 기준 이용권 INSERT |
| 영수증 PDF 자동 발급 | 결제 완료 | 회원 알림 + 영수증 함 등록 |
| 만료 쿠폰 자동 비활성 | 매일 00:00 | 만료일 도달 쿠폰 비활성 처리 |
| 자동결제 D-3 사전 알림 | 매월 약정일 D-3 | 회원 푸시 + 인앱 알림 (결제수단 변경 유도) |
| 자동결제 실행 | 매월 약정일 | 등록 결제수단으로 자동 결제 |
| 자동결제 실패 알림 | 실패 시점 | 회원 알림 + 운영자 알림 (NFR-19) |
| 자동결제 grace period | 실패 후 7일 | 7일 내 미결제 시 구독 일시정지 |
| 결제 완료 → CRM 매출 카드 갱신 | 결제 완료 후 5초 이내 | docs2 SCR-S001 매출 카드·리스트 갱신 |
| 세금계산서 자동 생성 | 사업자 회원 결제 완료 | 자동 발급 + 회원 알림 |

## 6. 운영 예외 처리
| 케이스 | 처리 방식 | 후속 조치 |
|---|---|---|
| 결제 시도 후 토스페이먼츠 응답 지연 | 30초 대기 후 timeout | 재시도 또는 결제 수단 변경 |
| 결제 실패 (카드 한도·계좌 잔액 부족) | 토스 응답 메시지 표시 | 재시도 |
| 결제 완료 후 이용권 생성 실패 | 트랜잭션 롤백 + 운영자 알림 | 수동 처리 큐 |
| 동일 회원·금액 5분 이내 재결제 | "이미 진행된 결제가 있습니다" 경고 | 사용자 확인 후 진행 |
| 쿠폰 2장 이상 적용 시도 | "쿠폰은 1장만 적용 가능" | 차단 |
| 만료 쿠폰 적용 시도 | "만료된 쿠폰입니다" | 차단 |
| 환불 사유 10자 미만 | "사유를 자세히 입력해주세요" | 차단 |
| 환불 요청 후 운영자 거절 | 거절 사유 회원에게 표시 | 회원 재요청 또는 종료 |
| 자동결제 실패 | grace period 7일 + 알림 | 7일 후 구독 일시정지 |
| 토스페이먼츠 API 장애 | "결제 시스템 점검 중" | 운영자 알림 + 안내 배너 |
| 영수증 PDF 생성 실패 | retry 1회 → 운영자 알림 | 재시도 |
| 동시 결제 시도 (이중 클릭) | 멱등성 키로 차단 | - |
| 세금계산서 발행 정보 미입력 | 인라인 안내 | 정보 입력 안내 |

## 7. CRM 정합 기준
- 결제 / 환불 / 매출 카드: docs2 D03 매출관리 정본 (PAY-01)
- 이용권 자동 생성: docs2 D05 상품관리 정본
- 영수증 / 세금계산서: docs2 D03 SCR-S010 정본
- 매출 통계 / KPI: docs2 D03 SCR-S004 / D10 SCR-094

회원앱 자체 정본 영역:
- 토스페이먼츠 SDK 호출 흐름
- 결제 수단 등록·관리 UX (빌링키 저장)
- 결제 실패 fallback UX
- 영수증 PDF 다운로드 흐름
- 구독·자동결제 일시정지 UX
- 환불 요청 입력 UX

## 8. 보안 정책
- 카드 정보는 회원앱에 저장하지 않음 (토스페이먼츠 빌링키만 보관)
- 결제 통신은 HTTPS 필수
- 결제 완료 응답은 토스페이먼츠 서명 검증
- 환불 요청은 본인 인증 필수 (앱 비밀번호 또는 생체인증)
