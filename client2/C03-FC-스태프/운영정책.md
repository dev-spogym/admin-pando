# C03-FC-스태프 회원앱 — 운영정책

## 1. 핵심 원칙
- FC는 리드 관리·상담 이력·만료 예정 회원 재등록 상담을 회원앱에서 수행한다.
- 스태프는 회원 조회(read-only)와 수동 출석 처리만 수행한다.
- 회원앱 role: `fc` / `staff` 2종.
- FC는 docs4/V1 D08 SCR-070 리드 관리 정합 정책에 따라 `등록완료` 직접 확정 불가, 회원 등록 요청만 생성 가능.
- 회원 등록 요청은 Owner(지점장)/매니저에게 이어받기 알림이 발송된다.
- 스태프는 회원 조회 read-only (수정·삭제·엑셀 불가), 수동 출석 처리만 가능.

## 2. 상태 / 운영 정의

### 상담 단계 7종 (docs4 정본)
신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류
- `등록완료`는 조회 필터에만 포함, FC가 수동 저장 불가
- `보류` 30일 경과 시 자동 알림

### 상담 결과 3종
등록 / 미등록 / 보류 — "완료" 단계일 때만 입력

### 유입경로 9종
간판 / 인터넷 / 전단지 / 추천 / SNS / 카카오톡 / 전화문의 / 방문 / 기타

### 상담 방식 3종
대면 / 유선 / 부재

## 3. 권한·책임 분리
| 역할 | 본인 담당 리드/회원 | 타 FC 담당 리드/회원 | 회원 등록 |
|---|---|---|---|
| fc | 등록·수정·상담 등록·메모 | hidden 또는 read-only (strict_owner) | 등록 요청 생성 (Owner/매니저 이어받기) |
| staff | 전체 회원 조회 (read-only) | - | 수동 출석만 가능 |

타 FC 담당 리드 수정 시도 시 "담당 리드만 수정할 수 있습니다" 안내 + hidden 처리.

## 4. KPI / 성과 측정 (FC 본인 + 관리자 KPI 합산)
| KPI | 산식 | 측정 주기 | FC 화면 |
|---|---|---|---|
| 상담 건수 | 본인 등록 상담 합산 | 일 단위 | MA-400, MA-440 |
| 등록 전환율 | 등록완료 / 전체 상담 × 100 | 월 단위 | MA-440 |
| 재등록률 | 만료 → 재등록 회원 / HQ-09 step 대상 × 100 | 월 단위 | MA-440 |
| 보류 30일+ 비율 | 30일 경과 보류 / 전체 보류 × 100 | 주 단위 | MA-400 |
| 후속 미처리율 | 후속 예정일 미처리 / 전체 후속 × 100 | 일 단위 | MA-400 |

회원앱 KPI는 docs4/V1 D08 SCR-094 KPI 대시보드의 FC 영역과 동일 데이터 (1:1 매칭).

## 6. 정책 결정 근거
- FC `등록완료` 수동 저장 불가 정책은 docs4/V1 D08 SCR-070 2026-05-23 정합화에 따른다.
- 데이터 보호를 위해 FC는 본인 담당 회원만, 스태프는 read-only만 가능하다.
- 상담 단계 7종은 운영 합의로 고정이며 임의 추가·삭제 불가.

## 8. CRM 정합 기준
- 리드 관리 / 상담 이력: docs4/V1 D08 CRM-01 (SCR-070)
- 회원 데이터 / 만료 step: docs4/V1 D02 회원관리 + D10 HQ-09
- 만료 알림 결과 동기화: docs4 NFR-05 매일 새벽 03:00 이후
- 출석 결과 3종: docs4 _공통/상태전이.md
- 직원 권한 매트릭스: docs4 _공통/권한매트릭스.md (회원앱 fc/staff와 분리 운영)

회원앱 자체 정본 영역:
- 모바일 칸반 DnD UX (PC 칸반 대체)
- FC 푸시 알림 채널·우선순위
- 후속 예정일 D-1 알림 흐름
- 스태프 수동 출석 빠른 검색 UX
- 회원 등록 요청 → CRM 이어받기 알림 흐름
