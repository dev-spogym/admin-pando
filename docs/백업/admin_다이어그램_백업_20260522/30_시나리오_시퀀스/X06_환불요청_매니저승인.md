# X06 — 환불 요청 → 부분환불 계산 → 정산 반영

## 1. 시나리오 개요

회원이 이용권 환불을 요청 → 매니저가 환불 계산 미리보기에서 차감금/위약금/미수 상계와 혼합결제 환불 배분을 확인 → 외부 POS/현금 환불 또는 결제링크 PG 환불 → 정산 반영까지의 환불 플로우.

| 항목 | 내용 |
|------|------|
| 트리거 | 회원 환불 요청 (방문/전화) |
| 종료 조건 | 환불 완료 또는 링크 취소 완료 + 정산 반영 |
| 참여 도메인 | 매출관리(D3), 회원관리(D2) |

## 2. 전제조건

- 매니저 계정 로그인 상태 (환불 처리 권한 보유)
- 환불 대상 결제건이 존재하며 환불 가능 상태
- 외부 POS 환불 또는 결제링크 PG 환불이 가능해야 함
- 환불 정책(위약금/기간별 공제율) 설정 완료

## 3. 참여 액터

| 액터 | 설명 |
|------|------|
| 회원 | 환불 요청자 |
| 매니저 | 환불 승인 권한 보유 |
| CRM API | FitGenie CRM 백엔드 |
| DB | 데이터베이스 |
| POS/PG | 외부 POS 또는 결제링크 환불 처리 시스템 |
| 알림서비스 | 환불 완료 알림 발송 |

## 4. 시퀀스 다이어그램

```mermaid
    actor MB as 회원
    actor M as 매니저
    participant API as CRM API
    participant DB as DB
    participant EXT as 외부POS/PG
    participant N as 알림서비스

    MB->>M: 1. 환불 요청
    M->>API: 2. GET /payments?member_id=?&status=APPROVED|INSTALLMENT
    API->>DB: 3. 환불 가능 결제 조회
    DB-->>API: 4. 결제 목록
    API-->>M: 5. 결제 이력
    Note over M: SCR-M004 결제이력 탭 또는 SCR-S012 진입

    M->>API: 6. GET /refund-preview?sale_id=...
    API->>DB: 7. refund_policy, membership 사용량, prior_refund, remaining_unpaid 확인
    DB-->>API: 8. preview 계산값 {original, deduction, penalty, prior_refunded, unpaid_offset, refundable}
    API-->>M: 9. 환불 가능 금액 미리보기
    Note over M: SCR-S012 환불 계산 박스 확인

    alt 미결제 링크 건
        M->>API: 10. POST /payment-links/cancel {link_id, reason}
        API->>DB: 11. payment_link status=CANCELED
        API-->>M: 12. 200 OK
        API->>N: 13. 링크 취소 알림
        N-->>MB: 14. 결제링크 취소 안내
    else 매니저 환불 승인
        M->>API: 15. POST /refunds {sale_id, reason, refund_amount, deduction, penalty, tender_refund_lines[]}
        API->>DB: 16. 잔여 미수 선상계 확인 + 혼합결제 환불 가능액 계산

        alt 현장 카드/현금/계좌이체 결제 환불
            M->>EXT: 17. 외부 POS 또는 계좌 환불 선처리
            EXT-->>M: 18. 환불 승인/이체 완료 증빙
        else 결제링크 카드 환불
            API->>EXT: 19. PG 환불 요청 {actual_refund_amount}
            EXT-->>API: 20. 환불 응답 또는 webhook 대기
        end

        API->>DB: 21. refunds {status=COMPLETED|PENDING, actual_refund_amount, tender_refund_lines[]}
        API->>DB: 22. payments SET status=PARTIAL_REFUNDED or REFUNDED
        opt 전액 환불
            API->>DB: 23. memberships SET status=REFUNDED
        end
        API->>DB: 24. branch_settlement_ledger {paymentBranchId, usageBranchId, salesAttributionBranchId, settlementBranchId, incentiveOwnerId, refund_amount}
        DB-->>API: 25. OK
        API->>N: 26. 환불 완료 알림 트리거
        N-->>MB: 27. SMS/카카오톡 - 환불 완료 + 환불 금액 안내
        API-->>M: 28. 200 OK {refund_id, actual_refund_amount}
        Note over M: SCR-S007 환불 관리에 기록 반영

    else 매니저 환불 거절
        M->>API: 29. POST /refunds/reject {sale_id, reason}
        API->>DB: 30. refund_request status=REJECTED
        DB-->>API: 31. OK
        API->>N: 32. 환불 거절 알림 트리거
        N-->>MB: 33. 환불 거절 사유 안내
        API-->>M: 34. 200 OK
    end
```

## 5. 주요 메시지 설명

| 번호 | 메시지 | 설명 |
|------|--------|------|
| 6 | GET /refund-preview | `원금 - 차감금 - 위약금 - 기환불 - 미수상계 = 환불가능액` 계산 + 혼합결제 환불 가능 행 분해 |
| 10 | POST /payment-links/cancel | 미결제 링크 건은 환불이 아니라 링크 취소 |
| 15 | POST /refunds | `refund_amount`는 preview 이내에서 매니저 조정 가능 |
| 21 | refunds COMPLETED/PENDING | 실제 환불액과 수단별 환불행 기준으로 환불 기록 생성 |
| 24 | branch_settlement_ledger | 환불이 귀속 지표와 정산 장부에 반영됨 |

## 6. 예외/분기

| 상황 | 처리 방법 |
|------|-----------|
| 현금/계좌이체 환불 | 외부 환불 또는 계좌이체 완료 후 CRM 기록 |
| 부분 환불 | `refund_amount < original_amount` 허용, `PARTIAL_REFUNDED` 상태 |
| 이미 환불된 건 | refundable=false 체크 → 환불 불가 안내 |
| 환불 가능 기간 초과 | 정책에 따라 환불 불가 또는 위약금 100% |
| 결제링크 PG 취소 실패 | 수동 계좌이체 환불로 fallback |
| 미결제 링크 건 | 환불 대신 링크 취소 |
