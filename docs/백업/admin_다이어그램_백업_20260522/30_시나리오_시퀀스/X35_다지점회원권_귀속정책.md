# X35 — 다지점 회원권 설정 → 결제 귀속 저장 → KPI/정산 반영

## 1. 시나리오 개요

운영자가 상품 마스터에서 법인/홈&오피스/주말/통합 회원권 정책을 설정하고, 실제 결제 시점에 결제지점·이용지점·매출 귀속 지점·정산 지점·인센티브 귀속자를 저장한 뒤, 회원 상세/KPI/환불/급여까지 같은 귀속 기준을 참조하는 시나리오.

| 항목 | 내용 |
|------|------|
| 트리거 | 운영자가 다지점 회원권을 등록하거나 판매 |
| 종료 조건 | 귀속 필드 저장 완료 + KPI/정산/급여 반영 |
| 참여 도메인 | 상품관리(D5), 매출관리(D3), 회원관리(D2), 직원관리(D7) |

## 2. 전제조건

- 상품 마스터에 운영 정책 구분이 정의되어 있음
- 허용 이용 지점과 기본 귀속 정책이 설정되어 있음
- 결제 처리 시 귀속 필드를 검토할 권한이 있음

## 3. 참여 액터

| 액터 | 설명 |
|------|------|
| 운영자 | 상품 등록, 결제 등록, 이관/환불 처리 담당 |
| 회원 | 회원권 구매 및 이용 주체 |
| CRM API | FitGenie CRM 백엔드 |
| DB | 데이터베이스 |
| KPI/정산엔진 | KPI 롤업, 정산, 페이롤 계산 서비스 |

## 4. 시퀀스 다이어그램

```mermaid
    actor OP as 운영자
    actor MB as 회원
    participant API as CRM API
    participant DB as DB
    participant CALC as KPI/정산엔진

    Note over OP,API: [상품 정책 정의]
    OP->>API: 1. POST /products {policy_type, allowed_usage_branches, default_usage_branch, default_sales_branch, default_settlement_branch, default_incentive_policy}
    API->>DB: 2. product_policies 저장
    DB-->>API: 3. product_id

    Note over OP,API: [결제 시 귀속 확정]
    OP->>API: 4. POST /sales/preview {product_id, member_id}
    API->>DB: 5. 상품 정책 + 회원 기본 귀속값 조회
    DB-->>API: 6. default attribution
    API-->>OP: 7. 결제지점 / 이용지점 / 매출 귀속 지점 / 정산 지점 / 인센티브 귀속자 제안
    OP->>API: 8. POST /sales {paymentBranchId, usageBranchId, salesAttributionBranchId, settlementBranchId, incentiveOwnerId}
    API->>DB: 9. payment + membership + attribution fields 저장

    Note over MB,API: [회원 이용 및 변경]
    MB->>API: 10. 출석 / 예약 / 수업 이용
    API->>DB: 11. usage_branch_id 기준 이용 이력 저장
    OP->>API: 12. 환불 또는 지점이관 처리
    API->>DB: 13. refund/member_transfer에 동일 귀속 기준 저장 또는 재배정

    Note over CALC,DB: [후속 집계]
    CALC->>DB: 14. payments, refunds, classes, payroll source 조회
    CALC->>CALC: 15. KPI 귀속 = salesAttributionBranchId / 정산 = settlementBranchId / 강사 실적 = incentiveOwnerId
    CALC->>DB: 16. KPI snapshot, settlement ledger, payroll source 반영
```

## 5. 주요 메시지 설명

| 번호 | 메시지 | 설명 |
|------|--------|------|
| 1 | POST /products | 운영 정책 구분과 허용 지점 정의 |
| 7 | default attribution | 상품 정책 + 회원 기본값을 합쳐 제안값 생성 |
| 9 | attribution fields 저장 | 거래 단위 귀속 필드를 immutable하게 저장 |
| 15 | 집계 규칙 | KPI·정산·급여가 서로 다른 귀속 기준을 참조 가능 |

## 6. 예외/분기

| 상황 | 처리 방법 |
|------|-----------|
| 단일지점 상품 | 모든 귀속 필드를 동일 지점으로 자동 채움 |
| 법인 회원권 | 이용 가능 지점 복수 허용, 매출/정산은 계약 기준 지점 유지 가능 |
| 홈&오피스 | 평일/시간대 및 복수 이용 지점 정책 함께 저장 |
| 주말 이용권 | 요일 제한 + 이용 가능 지점 정책 함께 저장 |
| 통합 회원권 | 이용 가능 지점 복수 허용, 결제/이용/정산 귀속 분리 저장 |
| 타지점 수업 진행 | 급여 계산 시 수행 지점/판매 지점/정산 지점 중 정책 기준을 선택 |
