# kiosk-pando 퍼블리싱 체크리스트

> 문서 버전: v0.1
> 작성일: 2026-05-04
> 목적: `kiosk-pando` 퍼블리싱 작업 시 공통 패턴, 상태, 예외, 검수 기준을 빠르게 확인

---

## 1. 공통 기준

### 1.1 레이아웃

- [ ] 모든 화면은 풀스크린 키오스크 기준으로 상하 여백이 안정적으로 보인다.
- [ ] 상단 헤더는 `뒤로` 또는 `종료`, 화면명, 우측 균형 영역의 3단 구조를 유지한다.
- [ ] 버튼 크기는 터치 기준으로 충분히 크다.
- [ ] 자동 복귀가 필요한 화면은 남은 시간을 명확히 보여준다.
- [ ] 공지 배너/토스트/상태 메시지는 화면의 주 목적을 방해하지 않는다.
- [ ] 일반 portrait 웹 화면이 아니라 실제 스탠드형 키오스크의 눈높이/터치 거리 기준으로 보인다.
- [ ] 장식용 SVG, 캐릭터 일러스트, 가짜 회원 아바타, 과한 radial/gradient 배경을 사용하지 않는다.
- [ ] 밝은 배경, 충분한 여백, 큰 터치 카드, 명확한 상태 배지 중심의 단정한 운영형 스타일을 유지한다.

### 1.2 공통 UI 패턴

- [ ] 하단 체크인 도크 버튼 패턴
- [ ] 숫자 키패드 패턴
- [ ] 스캔/인식 대기 프레임 패턴 (장식용 스캔 라인 제외)
- [ ] 성공 회원정보 모달 / 실패 결과 패턴
- [ ] 대형 번호 표시 패턴
- [ ] 상태 배지 패턴
- [ ] 카드형 리스트 패턴
- [ ] 하단 자동 복귀 안내 패턴

### 1.3 상태 표현

- [ ] 로딩
- [ ] 빈 상태
- [ ] 정상 데이터
- [ ] 성공
- [ ] 실패
- [ ] 비활성/진입 차단
- [ ] 예외 발생 시 대체 안내

---

## 2. 메인 / 출석 체크리스트

### 2.1 대기 화면

- [ ] 마케팅형 이미지 히어로가 아니라 입장/퇴장 CTA가 즉시 보이는 운영형 첫 화면이다.
- [ ] `입장하기`, `퇴장하기` 대형 버튼이 첫 화면의 주 액션으로 보인다.
- [ ] 예약 확인/사물함 번호/골프 입장·예약/주차 등록 보조 카드가 하단 또는 하위 영역에 정리된다.
- [ ] 얼굴 인식이 자동 시작되는 지점은 스탠드형 키오스크의 중앙 메인 시선 영역으로 유지된다.
- [ ] 기능이 꺼진 메뉴는 숨김 또는 비활성 처리 기준이 명확하다.
- [ ] 공지 배너가 있을 때와 없을 때 레이아웃이 무너지지 않는다.
- [ ] 카메라 준비 중 / 접근 차단 / 비활성 상태가 같은 레이아웃에서 처리된다.
- [ ] 관리자 숨김 진입 영역이 퍼블리싱에서 어색하게 보이지 않는다.

### 2.2 QR / RFID / 바코드

- [ ] 인식 대기 메시지가 한 줄로 명확하다.
- [ ] 중앙 인식 영역이 충분히 크게 보인다.
- [ ] 장식용 스캔 라인 없이 상태 배지와 안내문으로 인식 상태가 전달된다.
- [ ] 장비 미연동 상태에서도 목업 퍼블리싱이 자연스럽다.
- [ ] 실패 후 재시도 흐름 문구가 있다.

### 2.3 얼굴 인식

- [ ] 대기 상태와 포커싱 상태가 시각적으로 구분된다.
- [ ] "정면을 바라봐주세요" 안내가 읽기 쉽다.
- [ ] 1~3초 정지 감지 과정이 시각적으로 이해된다.
- [ ] 다중 얼굴 또는 미인식 예외 안내가 있다.
- [ ] 얼굴 윤곽선 그림, 장식용 SVG, 스캔 라인 애니메이션 없이 카메라 패널과 상태 문구로 구성된다.

### 2.4 전화번호 입력

- [ ] 숫자 키패드와 입력값 표시가 멀리서도 읽힌다.
- [ ] 초기화 / 삭제 / 확인 버튼 역할이 명확하다.
- [ ] 회원과 직원이 같은 입력 화면을 써도 문구가 어색하지 않다.
- [ ] 직원은 별도 버튼 없이 인증 결과에서 자동 판별된다는 흐름이 설명된다.

---

## 3. 결과 / 락커 전달 체크리스트

### 3.1 출석 결과 공통

- [ ] 성공과 실패가 색, 아이콘, 문구에서 명확히 구분된다.
- [ ] 성공 시 전체 전환 화면이 아니라 회원 정보 모달처럼 보인다.
- [ ] 회원 식별, 이용 시작일, 이용 종료일, 이용 상품, 남은 이용 정보가 한눈에 읽힌다.
- [ ] 실제 승인 사진이 없으면 가짜 SVG 사진 대신 이니셜/회원명으로 표시한다.
- [ ] 회원명/직원명 표기 방식이 일관적이다.
- [ ] 복귀 카운트다운이 항상 같은 위치에 있다.
- [ ] 성공 4초 / 실패 7초 자동 복귀 기준이 유지된다.
- [ ] 락커 배정 중 상태가 성공 화면과 충돌하지 않는다.

### 3.2 영수증 출력 방식

- [ ] 락커 번호가 가장 먼저 보인다.
- [ ] "영수증을 가져가세요" 메시지가 명확하다.
- [ ] 출력 실패 시 대체 안내가 있다.

### 3.3 앱 발송 방식

- [ ] 앱에서 확인해야 한다는 점이 즉시 이해된다.
- [ ] 앱 미연동 회원 예외 안내가 있다.
- [ ] 전송 실패 시 프런트 문의 또는 대체 안내가 있다.

### 3.4 신발장 밴드 방식

- [ ] 신발장 번호가 대형 숫자로 보인다.
- [ ] "해당 신발장에서 밴드를 수령"과 "같은 번호 락커 사용"이 함께 보인다.
- [ ] 밴드 없음/번호 없음 예외 상태가 있다.

---

## 4. 회원 정보 체크리스트

### 4.1 회원 정보 메뉴

- [ ] 2x2 메뉴 카드의 크기와 간격이 균일하다.
- [ ] 비활성 기능은 눌러보지 않아도 비활성임을 알 수 있다.

### 4.2 이용권 조회

- [ ] 상태, 만료일, 잔여 일수/세션이 우선순위대로 보인다.
- [ ] 데이터 없음과 조회 실패가 같은 화면으로 보이지 않는다.

### 4.3 예약 조회

- [ ] 예약 상태 배지가 명확하다.
- [ ] 일반 예약과 골프 예약이 섞여도 읽히는 구조다.
- [ ] 골프 예약 노출 시 타석 번호를 담을 자리가 확보돼 있다.

### 4.4 락커 조회

- [ ] 락커 번호는 한눈에 보이는 크기다.
- [ ] 배정 없음 상태 문구가 과도하게 허전하지 않다.

### 4.5 공지사항

- [ ] 고정 공지가 일반 공지보다 먼저 보인다.
- [ ] 긴 공지 본문도 줄바꿈이 자연스럽다.

---

## 5. 골프 예약 체크리스트

### 5.1 골프 예약 진입

- [ ] 회원 인증 후 예약 가능/불가가 바로 이해된다.
- [ ] 이용권 없음, 중복 예약, 예약 가능 시간 아님 예외가 분리된다.

### 5.2 날짜/시간 선택

- [ ] 날짜 선택과 시간 선택이 한 화면에서 헷갈리지 않는다.
- [ ] 마감/예약 가능/대기 가능 상태 차이가 보인다.

### 5.3 타석 선택

- [ ] 타석 그리드가 실제 시설 느낌에 가깝게 읽힌다.
- [ ] 사용 가능/예약/점검 상태가 색만으로 구분되지 않는다.
- [ ] 선택한 타석 요약 패널이 있다.
- [ ] 만석 시 대기 예약 버튼이 명확하다.

### 5.4 예약 완료

- [ ] 예약 완료와 대기 등록 완료가 다른 메시지로 구분된다.
- [ ] 예약 일시, 타석 번호, 이용 시간이 빠르게 읽힌다.

---

## 6. 주차 등록 체크리스트

- [ ] 버튼만 있는 최소 버전도 어색하지 않다.
- [ ] 안내형 / 외부 이동형 / 프런트 문의형 3가지 타입을 같은 레이아웃 뼈대에서 처리할 수 있다.
- [ ] 미지원 지점 안내 문구가 준비돼 있다.

---

## 7. 관리자 체크리스트

### 7.1 관리자 PIN

- [ ] 키패드가 회원용 입력 화면과 비슷하되 관리자 톤으로 구분된다.
- [ ] PIN 오류 메시지가 과도하게 위협적이지 않다.

### 7.2 관리자 패널

- [ ] 기기 정보, 설정 정보, 운영 액션의 3구획이 명확하다.
- [ ] 위험 액션(문 열기)은 시각적으로 분리된다.
- [ ] 토스트 메시지가 다른 정보 카드와 겹치지 않는다.

---

## 8. 퍼블리싱 우선순위 체크

- [ ] P0: 메인/출석/결과 기본 흐름
- [ ] P1: 락커 전달 3안
- [ ] P2: 회원 조회
- [ ] P3: 골프 예약
- [ ] P4: 주차 등록
- [ ] P5: 관리자 보강

---

## 9. 최종 검수 기준

- [ ] 각 화면의 목적이 3초 안에 이해된다.
- [ ] 장비가 없어도 목업 상태만으로 흐름을 설명할 수 있다.
- [ ] 성공/실패/예외 상태가 모두 준비돼 있다.
- [ ] 센터별 운영 차이(락커 전달, 주차 방식)가 화면 레벨에서 설명 가능하다.
- [ ] 퍼블리셔가 이 문서만 보고도 화면 분량과 반복 패턴을 파악할 수 있다.
