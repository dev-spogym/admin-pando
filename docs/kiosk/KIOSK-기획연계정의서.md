# 키오스크 기획연계정의서

> 문서 버전: v0.2
> 작성일: 2026-05-14
> 목적: 키오스크 화면이 `admin-pando` / `client-pando` 기획서의 어느 화면·기능과 연결되는지 매핑한다. 키오스크가 단독으로 정의하는 신규 기능과, 다른 채널의 데이터/정책을 단순 표시하는 기능을 구분한다.

---

## 1. 채널 역할 정리

| 채널 | 책임 | 키오스크와의 관계 |
|---|---|---|
| `admin` (관리자웹) | 출석/락커/골프 타석/매점/이용권 운영 정책의 **원천** | 키오스크는 admin이 정의한 정책을 단말에서 실행 |
| `client` (회원앱) | 회원 셀프 서비스(예약/이용권/QR) | 키오스크와 데이터 원천 동일, 채널만 다름 |
| `kiosk` (본 채널) | 입구 단말의 **즉시 처리** | 출석/락커 안내/현장 셀프 예약/주차 안내 |

키오스크는 admin/client 화면을 모방하지 않는다. **같은 데이터 원천을 키오스크 UX로 축약 표시**한다.

## 3. 데이터/정책의 원천 위치

### 3.1 출석/입장 (ATT)

- 정책 원천: `admin/화면설계서/D11-통합운영/SCR-I001-통합출석관리`
- 키오스크 설정: `admin/화면설계서/D11-통합운영/SCR-I002-키오스크설정`
- 운영 원칙: `admin/기능명세서/통합운영_IOT_헬스.md`
- 직원 분기: `admin/기능명세서/D07-직원관리/근태` (staffAttendance 연동)

### 3.2 락커 후처리

- 락커 정책: `admin/화면설계서/D06-시설관리/SCR-050-락커관리`
- 카드/밴드 매핑: `admin/화면설계서/D06-시설관리/SCR-052-밴드카드관리`
- 영수증/앱/신발장 토글: `admin/화면설계서/D11-통합운영/SCR-I002-키오스크설정`

### 3.3 골프 타석 예약 (GLF)

- 운영자 화면: `admin/화면설계서/D06-시설관리/SCR-054-골프타석관리`
- 회원 화면: `client/화면설계서/D12-회원앱/SCR-MA-123-골프예약상세`
- 시퀀스: `admin/다이어그램/30_시나리오_시퀀스/X31_회원앱_골프예약_타석선택_대기전환.md`
- 경계: 키오스크에서 생성/대기 등록까지 가능한 예약은 골프 타석 예약만이다. 일반 PT/GX/OT 수업은 KIO-303에서 조회만 하며, 수업 마스터와 예약 원장은 admin `SCR-C002`/`SCR-C016`을 따른다.

### 3.4 주차 (PRK)

- 정책 원천: `admin/화면설계서/D11-통합운영/SCR-I002-키오스크설정` (주차 토글, 외부 링크, 안내 문구)
- 회원 채널 영향 없음 (키오스크 단독 기능)

### 3.5 회원 조회 (KINF)

- 이용권 조회 원천: `admin/화면설계서/D02-회원관리/SCR-M004-회원상세` 이용권 탭 + `admin/화면설계서/D05-상품관리/SCR-P001-상품관리`
- 일반 수업 예약: `admin/화면설계서/D04-수업관리/SCR-C002-수업관리`, `admin/화면설계서/D04-수업관리/SCR-C016-예약목록` ↔ `client/SCR-MA-122`
- 골프 타석 예약: `admin/화면설계서/D06-시설관리/SCR-054-골프타석관리` ↔ `client/SCR-MA-123`
- 락커: `admin/D06-시설관리/SCR-051`
- 공지: `admin/D08-마케팅/공지` (지점 공지 텍스트)

### 3.6 매점/결제 (SHP)

- 상품 원천: `admin/D05-상품관리`
- 장바구니 구성: `admin/SCR-S002-POS판매`
- 결제 원장: `admin/SCR-S003-결제처리`
- 취소/부분환불: `admin/SCR-S012-결제취소-부분환불`
- 회원 결제 이력 반영: `client/SCR-MA-133-결제내역`

### 3.7 관리자/설정 (ADM, KSET)

- PIN/권한: `admin/D09-설정관리/SCR-081-권한설정`
- 기기 설정: `admin/D11-통합운영/SCR-I002-키오스크설정`

## 4. 신규 정의 영역 (키오스크가 원천)

다음 항목은 admin/client 어느 채널에도 없고 키오스크가 처음 정의한다. 추후 admin 정책으로 승격될 수 있으나 **현재 시점 원천은 키오스크**다.

| 코드 | 항목 | 원천 문서 |
|---|---|---|
| ATT-04-03 | 락커 번호 영수증 출력 | `KIOSK-운영기획서.md § 5.1 ATT-05-01` |
| ATT-04-04 | 락커 번호 앱 전송 | `KIOSK-운영기획서.md § 5.1 ATT-05-02` |
| ATT-04-05 | 신발장 밴드 수령 유도 | `KIOSK-운영기획서.md § 5.1 ATT-05-03` |
| KSET-02-01 | 얼굴 인식 정지 판정 시간 | `KIOSK-운영기획서.md § 5.1 ATT-01` |
| KSET-02-03 | 락커 번호 전달 방식 설정 | `KIOSK-운영기획서.md § 5.6` |
| SHP-01 | 매점 상품 탐색 및 장바구니 | `KIOSK-운영기획서.md § 5.5` |
| SHP-02 | 매점 결제 처리 | `KIOSK-운영기획서.md § 5.5` |
| PRK-* | 주차 등록 v1 정책 | `KIOSK-운영기획서.md § 5.4` |

이 영역은 admin 측에 신규 설정 키 또는 화면이 추가되어야 하므로, 합의 시점에 `admin/관리자문서_통합_ID대응표.md`에 ID를 부여해 정합화한다.

## 5. 동기화 원칙

1. **데이터 원천 단일화**: 같은 회원/예약/이용권은 admin DB 단일 원천을 사용한다. 키오스크는 별도 원천을 만들지 않는다.
2. **정책은 admin 우선**: 출석/락커/골프 운영 규칙은 admin 정책이 우선이다. 키오스크는 표시/입력만 담당한다.
3. **신규 설정 키 합의**: 키오스크가 새로 요구하는 설정(영수증/앱/신발장 토글 등)은 admin `SCR-I002-키오스크설정` 화면에 명시 후 키오스크가 수신한다.
4. **이력은 admin으로 적재**: 출석/예약/결제/관리자 액션 모두 admin 운영 로그로 적재되며, 키오스크는 자체 영구 저장소를 두지 않는다.
5. **오프라인 큐**: 일시 단절 시 키오스크가 로컬 큐를 보유할 수 있으나, 복구 즉시 admin 원천에 반영한다.

## 6. 문서 변경 트리거

이 문서는 다음 경우에 갱신해야 한다.

- admin 측 화면 ID 변경 (`관리자문서_통합_ID대응표.md` 변경 발생 시)
- client 측 회원앱 화면 ID 변경 (`회원앱2 / MA-*` 체계 변경 시)
- 키오스크 신규 화면(`KIO-NNN`) 추가
- 채널 간 데이터 흐름 방향이 바뀌는 정책 변경
