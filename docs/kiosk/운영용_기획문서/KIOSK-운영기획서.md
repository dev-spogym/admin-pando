# kiosk-pando 운영기획서

> 문서 버전: v0.1
> 작성일: 2026-05-04
> 기준 프로젝트: `kiosk-pando`
> 참조 문서: `admin-pando`의 통합운영/시설관리/회원앱 기획

---

## 1. 문서 목적

- `admin-pando` 기획 중 키오스크에서 직접 써야 하는 기능만 선별해 `kiosk-pando`용 운영 기획으로 재정리한다.
- 헬스 입장용 얼굴 인식 출석, 골프 타석 예약, 주차 등록 버튼을 하나의 키오스크 UX 안에서 정리한다.
- 현재 구현된 화면과 신규 기획 범위를 분리해 이후 개발 우선순위를 명확히 한다.

## 2. 범위

- 출석/입장: QR, RFID, 얼굴 인식, 전화번호, 바코드
- 출석 후처리: 출입문 개방, 출석 기록, 락커 배정, 락커 번호 전달, TTS
- 회원 안내: 이용권, 예약, 락커, 공지
- 신규 확장: 골프 타석 예약, 주차 등록 버튼
- 운영 기능: 관리자 PIN, 연결 테스트, 설정 새로고침, 기기 정보, 운영 로그

본 문서는 기획/퍼블리싱 기준 문서이며, 실제 설정 키명, enum 값, DB 필드 설계는 범위에서 제외한다.

## 5. 상세 기획

### 5.1 ATT 출석 및 입장 관리

#### ATT-01 실시간 얼굴 인식 대기

키오스크는 헬스 입구에서 항상 카메라를 켠 상태로 대기한다. 사용자가 전면에 접근하면 얼굴 박스를 먼저 탐지하고, 사용자가 1~3초 정도 가만히 있으면 촬영을 고정한 뒤 얼굴 인식을 수행한다.

| 항목 | 기본안 | 설명 |
|---|---|---|
| 얼굴 감지 대기 | 상시 ON | 대기 화면 진입 시 카메라 준비 |
| 정지 판정 시간 | 2초 | 센터 정책에 따라 1~3초 조정 |
| 인식 대상 | 1명 우선 | 중앙 또는 가장 크게 잡힌 얼굴 우선 |
| 인식 실패 후 재시도 | 3초 후 재대기 | 과도한 연속 호출 방지 |
| 얼굴 인식 비활성화 시 | 메뉴 숨김 | 설정에서 OFF 시 얼굴 체크인 미노출 |

#### ATT-02 인증 수단별 체크인

- QR, RFID, 얼굴 인식, 전화번호, 바코드 중 지점 설정값에 따라 노출한다.
- 대기 화면의 우측 메인 영역은 실시간 얼굴 인식 캠을 고정 노출한다.
- 하단 메인 체크인 메뉴는 `QR 체크인`, `전화번호 체크인` 2개를 기본 구조로 사용한다.
- RFID, 바코드, 회원정보, 공지, 매점, 직원출석 등은 보조 메뉴 영역에서 노출한다.
- 직원 출퇴근은 회원과 같은 인증 화면에서 처리하고, 인증 결과에서 회원/직원을 자동 판별한다.
- 직원 출퇴근이 허용되지 않은 지점은 동일한 체크인 흐름 안에서 `직원 출퇴근 불가`로 차단한다.

#### ATT-03 출석 성공/실패 처리

성공 시에는 출석 기록과 출입문 개방을 동시에 수행한다. 실패 시에는 사유를 명확히 보여주되, 운영자가 나중에 확인할 수 있도록 이력은 남겨야 한다.

| 결과 | 처리 |
|---|---|
| 성공 | 출석 기록 생성, 출입문 5초 개방, 성공 TTS 재생 |
| 만료 | 실패 화면 + 프런트 문의 안내 |
| 미등록 | 실패 화면 + 재시도 안내 |
| 중복 | 실패 화면 + 잠시 후 재시도 안내 |
| 미수금 | 정책에 따라 경고 또는 차단 |
| 직원 불가 | 직원 출석 허용 OFF 시 차단 |

성공 출석 시에는 전면 결과 페이지 전체를 바꾸기보다, 배경 위에 회원 정보 모달이 떠 있는 형태로 처리한다. 모달에는 아래 정보를 함께 노출한다.

- 회원 사진
- 이용 시작일
- 이용 종료일
- 현재 이용 상품명
- 남은 이용일수 또는 남은 세션 수

성공 모달은 기본 4초 후 자동으로 닫히고 대기 화면으로 복귀한다. 실패 화면은 별도 안내 성격이 강하므로 기존 자동 복귀 시간을 유지하거나 운영 정책에 맞춰 더 길게 둘 수 있다.

#### ATT-04 출석 후 후처리

- 회원 성공 출석 시 지점 운영 정책에 따라 락커 후처리를 수행한다.
- 출석만 완료: 락커 관련 후속 처리 없이 종료
- 수동 배정 대기: 프런트에서 배정받으라는 안내 문구 노출
- 자동 배정 시도: 지정 존에서 자동 배정을 시도하고, 실패 시 수동 안내로 전환

자동 배정 또는 수동 확정 후에는 락커 번호를 사용자에게 전달해야 한다. 본 프로젝트에서는 전달 방식을 별도 정책으로 분리한다.

#### ATT-05 락커 번호 전달 방식

센터는 아래 3가지 방식 중 하나를 선택해서 운영할 수 있어야 한다.

| 방식 | 설명 | 운영 전제 |
|---|---|---|
| 종이 영수증 출력 | 얼굴 인식 등으로 출석 완료 후 락커 번호가 적힌 영수증을 즉시 출력 | 키오스크 프린터 연결 필요 |
| 앱 발송 | 출석 완료 후 회원 앱으로 락커 번호를 보내고, 키오스크에는 "앱에서 확인" 안내를 표시 | 회원 앱 연동/로그인 회원 식별 필요 |
| 신발장 밴드 수령 | 출석 완료 후 신발장 번호를 노출하고, 사용자는 해당 신발장에서 밴드를 꺼낸 뒤 같은 번호의 옷 락커를 사용 | 신발장-밴드-옷락커 번호 일치 정책 필요 |

##### ATT-05-01 종이 영수증 출력 방식

1. 키오스크 얼굴 인식 또는 다른 인증 수단으로 출석 성공
2. 시스템이 락커 번호를 배정
3. 프린터로 `회원명 / 출석시각 / 락커번호 / 안내문구`가 포함된 영수증 출력
4. 사용자는 영수증을 보고 락커 사용

운영 원칙:

- 프린터 출력 실패 시 키오스크 화면에 락커 번호를 임시 표시하고 프런트 문의를 안내한다.
- 영수증에는 과도한 개인정보를 넣지 않는다. 회원명은 마스킹 또는 이름만 표기 권장.
- 영수증 재출력은 관리자 또는 프런트 예외 처리 기능이 필요하다.

##### ATT-05-02 앱 발송 방식

1. 키오스크 출석 성공
2. 시스템이 락커 번호를 배정
3. 회원 앱으로 푸시 또는 인앱 메시지 발송
4. 키오스크에는 `앱에서 락커 번호를 확인해주세요` 메시지 노출
5. 사용자는 앱 화면에서 번호 확인 후 락커 사용

운영 원칙:

- 앱 미연동 회원은 이 방식을 기본값으로 사용할 수 없다.
- 앱 전송 실패 시 즉시 대체 수단으로 전환해야 한다. 권장 대체 순서는 `영수증 출력` 또는 `프런트 안내`다.
- 앱 화면에는 락커 번호, 유효 시간, 사용 안내를 함께 보여주는 것이 맞다.

건강 데이터 연동 안내:

- 센터가 건강 프로그램을 운영하는 경우, 앱 발송 방식 화면에서 `건강 데이터 연동` 안내를 함께 노출할 수 있다.
- 키오스크는 권한을 직접 받지 않고 회원앱 `MA-159`로 진입시키는 보조 채널만 수행한다.
- 이 안내는 출석 성공 경험을 방해하지 않는 비차단 안내여야 한다.

##### ATT-05-03 신발장 밴드 수령 방식

1. 키오스크 출석 성공
2. 시스템이 신발장 번호를 배정하거나 기존 매핑 번호를 확정
3. 키오스크 화면에 `신발장 번호`를 크게 노출
4. 사용자는 해당 신발장에서 밴드를 꺼낸다
5. 사용자는 동일 번호의 옷 락커를 사용한다

운영 원칙:

- `신발장 번호 = 밴드 번호 = 옷 락커 번호`의 1:1 매핑 정책이 필요하다.
- 번호 체계가 어긋나는 센터에는 적용할 수 없다.
- 신발장 내 밴드 분실/반납 누락 시 해당 번호는 즉시 배정 불가 상태로 전환해야 한다.
- 이 방식은 사실상 락커 배정과 밴드 재고 관리가 결합되므로 RFID/밴드 운영 정책과 함께 설계해야 한다.

현재 구현 기준 기본값은 다음과 같다.

| 항목 | 현재 기본값 |
|---|---|
| 중복 체크인 방지 | 10분 |
| 출입문 개방 시간 | 5초 |
| 성공 모달 자동 복귀 | 4초 |
| 실패 화면 자동 복귀 | 7초 |
| 자동 락커 배정 존 | A, B |

추가 제안 설정:

| 항목 | 초안 |
|---|---|
| 락커 번호 전달 방식 | 영수증 / 앱 / 신발장 밴드 중 1택 |
| 전달 실패 시 대체 방식 | 프런트 안내 또는 보조 전달 방식 |

### 5.2 INF 회원 조회 및 안내

회원 조회는 모두 본인 확인 이후에만 진행한다. 현재 `kiosk-pando`는 전화번호 기반 본인 확인 흐름을 이미 갖고 있으므로, 신규 기능도 같은 인증 패턴을 재사용한다.

| 코드 | 기능 | 처리 원칙 |
|---|---|---|
| KINF-02 | 이용권 조회 | 상태, 만료일, 잔여일/세션 표시 |
| KINF-03 | 예약 조회 | 일반 수업 예약 목록 우선, 골프 예약은 동일 목록에 통합 가능 |
| KINF-04 | 락커 조회 | 오늘 배정 락커 번호와 유효기한 표시 |
| KINF-05 | 공지사항 조회 | 고정 공지 우선, 최신순 정렬 |

추가로 홈 하단 보조 메뉴에는 센터 정책에 따라 아래 항목을 토글할 수 있어야 한다.

- 회원 정보
- 공지사항
- 골프 타석 예약
- 주차 등록
- 매점/상품 구매

### 5.3 GLF 골프 타석 예약

골프 예약은 관리자용 타석 현황 화면(`SCR-054`)과 회원용 예약 상세 흐름(`SCR-MA-123`)을 키오스크용 셀프 예약으로 축소 적용한다. 키오스크는 운영 관리 화면이 아니라 회원의 빠른 예약/대기 등록 채널 역할을 한다.

#### GLF-01 진입 및 검증

1. 사용자가 `골프 타석 예약` 버튼을 누른다.
2. 전화번호 또는 회원 QR로 본인 인증을 수행한다.
3. 시스템은 골프 이용권 보유 여부, 예약 가능 시간, 중복 예약 여부를 검증한다.
4. 조건이 맞으면 예약 가능 화면으로 이동한다.

#### GLF-02 예약 가능 화면

| 항목 | 기본안 |
|---|---|
| 날짜 범위 | 당일 우선 노출, 운영 정책으로 확장 가능 |
| 시간 단위 | 30분 또는 1시간 단위 |
| 타석 표시 | 사용 가능 / 예약 / 마감 / 점검 |
| 대기 가능 여부 | 만석 시 대기 버튼 노출 |
| 안내 정보 | 담당 프로, 이용 시간, 차감 대상 이용권 |

#### GLF-03 예약 확정/대기 전환

| 상황 | 처리 |
|---|---|
| 빈 타석 있음 | 타석 선택 후 즉시 예약 확정 |
| 모든 타석 만석, 대기 허용 | 대기 예약으로 전환 |
| 이용권 없음 | 예약 차단 + 프런트 문의 안내 |
| 동일 시간대 예약 존재 | 중복 예약 차단 |

예약 완료 화면에는 아래 정보를 보여준다.

- 예약 일시
- 타석 번호
- 이용 시간
- 예약 상태
- 안내 문구

#### GLF-04 운영 연동 원칙

- 키오스크 예약 데이터는 `admin-pando`의 타석 운영 데이터와 같은 원천을 사용해야 한다.
- 예약 확정/취소/대기 승격은 관리자 타석 현황에도 즉시 반영되어야 한다.
- 대기열 자동 승격은 관리자 정책을 따르며, 키오스크는 결과만 표시한다.

### 5.4 PRK 주차 등록

주차 등록은 빌딩마다 정책과 연동 방식이 다르므로, 공통 입력폼을 먼저 강제하지 않는다. v1에서는 버튼 중심의 최소 범위로 정의한다.

#### PRK-01 v1 기본안

- 홈 화면 또는 정보 메뉴에 `주차 등록` 버튼을 노출한다.
- 버튼 노출 여부는 지점별 설정값으로 제어한다.
- 버튼 클릭 시 지점별 처리 방식을 따른다.

#### PRK-02 처리 방식

| 방식 | 설명 | 권장도 |
|---|---|---|
| `guide` | 안내 문구/운영시간만 팝업 노출 | 기본 |
| `external_link` | 외부 주차 등록 페이지 또는 웹뷰 연결 | 권장 |
| `staff_call` | 프런트 호출 또는 직원 문의 안내 | 대체 |

#### PRK-03 공통 원칙

- 주차는 센터 공통 기능이 아니라 빌딩 종속 기능으로 본다.
- 따라서 v1에서는 차량번호 입력/검증 로직을 공통화하지 않는다.
- 관리자 설정에는 버튼 라벨, 설명 문구, 외부 링크 정도만 두는 것이 맞다.

### 5.5 SHP 매점 및 현장 결제

매점은 출석 핵심 흐름은 아니지만, 센터에 따라 부가 매출 채널로 직접 노출할 수 있다. 키오스크에서는 상품 탐색과 빠른 현장 결제 UX만 담당하고, 상품 원천/결제 원장은 admin 기준을 따른다.

| 코드 | 기능 | 비고 |
|---|---|---|
| SHP-01 | 상품 탐색 및 장바구니 | KIO-701 |
| SHP-02 | 결제 처리 | KIO-702 |

#### SHP-01 상품 탐색

- 카테고리 탭으로 상품을 탐색한다.
- 상품 카드는 이미지, 이름, 가격, 담기 버튼을 기본으로 한다.
- 장바구니는 우측 또는 하단 고정 패널로 유지한다.
- 매점 토글 OFF 지점에서는 메뉴 진입 자체를 막는다.

#### SHP-02 결제 처리

- 장바구니 주문 내역과 최종 금액을 확인한다.
- 결제 수단을 선택한 뒤 결제를 요청한다.
- 성공 시 영수증 또는 결제 완료 안내를 제공한다.
- 회원 결제라면 client 결제내역과 동일 원장으로 반영한다.

### 5.6 ADM 관리자 및 운영

현재 구현된 관리자 패널은 현장 운영에 필요한 최소 기능을 이미 포함한다. 기획상으로는 아래 범위를 기본 운영 기능으로 고정한다.

| 코드 | 기능 | 비고 |
|---|---|---|
| ADM-01 | 관리자 PIN 인증 | 숨김 터치 진입 |
| ADM-02 | 기기 정보 확인 | kioskId, branchId, version |
| ADM-03 | 연결 테스트 | 서버/브리지 상태 확인 |
| ADM-04 | 설정 새로고침 | admin 설정 재반영 |
| ADM-05 | 대기 화면 미리보기 | 운영 확인 |
| ADM-06 | 원격 문 열기 | 예외 대응 |
| ADM-07 | TTS 샘플 재생 | 운영 점검 |
| ADM-08 | 감사 로그 기록 | 로그인/문열기/재생 등 |

### 5.7 관리자 설정 항목 초안

기획/퍼블리싱 단계에서는 실제 필드명 대신, 관리자 화면에서 조정해야 할 항목 수준까지만 정의한다.

| 설정 묶음 | 설정 항목 |
|---|---|
| 얼굴 인식 설정 | 얼굴 인식 사용 여부, 정지 판정 시간, 재시도 대기 시간 |
| 출석 방식 설정 | 기본 출석 방식, 사용 가능한 인증 수단, 직원 출석 허용 여부 |
| 락커 후처리 설정 | 출석만 완료 / 수동 배정 대기 / 자동 배정 시도 |
| 락커 번호 전달 설정 | 종이 영수증 출력 / 앱 발송 / 신발장 밴드 수령 |
| 전달 실패 예외 설정 | 전달 실패 시 프런트 안내 여부, 보조 전달 방식 사용 여부 |
| 영수증 설정 | 출력 문구, 안내 문구, 재출력 허용 여부 |
| 앱 안내 설정 | 앱 안내 문구, 앱 미연동 회원 예외 처리 |
| 신발장 밴드 설정 | 동일 번호 정책 사용 여부, 밴드 분실/미반납 예외 처리 |
| 메뉴 노출 설정 | 회원 정보, 예약 조회, 골프 예약, 주차 등록, 매점/공지 노출 여부 |
| 주차 설정 | 버튼 라벨, 안내 문구, 외부 이동 여부 |

## 7. 확정 필요 사항

아래 항목은 초안 작성 시 합리적으로 가정한 값이며, 실제 개발 전 확정이 필요하다.

| 항목 | 현재 초안 |
|---|---|
| 얼굴 인식 정지 판정 시간 | 기본 2초, 1~3초 조정 가능 |
| 얼굴 인식 엔진 | 외부 SDK/API 연동 전제 |
| 락커 번호 전달 기본 방식 | 영수증 / 앱 / 신발장 밴드 중 센터별 선택 |
| 전달 실패 시 대체 방식 | 필수 확정 필요 |
| 신발장-밴드-옷락커 번호 체계 | 1:1 동일번호 운영 가능 여부 확인 필요 |
| 골프 예약 범위 | 당일 우선, 추후 일정 확장 가능 |
| 골프 예약 단위 | 30분 또는 1시간 |
| 주차 등록 방식 | 버튼 + 안내/외부 링크 중심 |
| 주차 입력 폼 공통화 | v1 제외 |

## 8. 요약

- `kiosk-pando`는 이미 출석, 결과 처리, 정보 조회, 관리자 기능의 골격을 갖고 있다.
- 이번 기획의 핵심은 대기 화면을 `우측 실시간 얼굴 인식 캠 + 하단 QR/전화번호 체크인` 구조로 바꾸고, 성공 출석 시 회원 정보 모달을 4초간 노출한 뒤 자동 복귀시키는 것이다.
- 동시에 출석 후 락커 번호 전달 방식을 `영수증 / 앱 / 신발장 밴드` 3안 중 선택 가능하게 만드는 것이 운영상 중요하다.
- 그 다음 단계로 `admin-pando`의 골프 타석/키오스크 정책을 키오스크 셀프 UX로 축소 이식하는 것이 맞다.
- 주차 등록은 센터 공통 로직보다 지점별 버튼 정책으로 보는 것이 맞으며, v1에서는 최소 범위로 처리하는 것이 가장 현실적이다.
