# 키오스크 — 출석 및 입장 관리 (ATT) 기능명세서

> **도메인**: ATT (Attendance / 출석 및 입장)
> **연관 화면**: KIO-001, KIO-101 ~ KIO-105, KIO-201 ~ KIO-204
> **작성일**: 2026-05-04
> **버전**: 0.1

---

## 1. 도메인 개요

키오스크 ATT 도메인은 회원/직원이 센터에 입장하기 위해 단말에서 본인을 인증하고, 출석 기록을 생성하고, 출입문 개방과 락커 후처리까지 마무리하는 핵심 흐름을 다룬다. `admin-pando`의 통합출석관리(`SCR-I001`) 정책을 단말 UX에 맞춰 실행한다.

## 2. 인증 주체별 처리 원칙

| 주체 | 인증 수단 | 처리 결과 |
|---|---|---|
| 회원 | QR / RFID / 얼굴 / 전화번호 / 바코드 | 입퇴장 기록 생성, 출입문 개방, 락커 후처리 |
| 직원 | 같은 입력 화면, 인증 결과로 자동 판별 | `staffAttendance` 적재. 직원 출퇴근 허용 OFF 지점에서는 차단 |
| 미식별 | 인증 실패 | 실패 화면 + 사유별 안내 |

## 4. ATT-01 입장/퇴장 대기 및 회원 식별

### 4.1 화면 목적

키오스크는 헬스 입구에서 항상 카메라를 켠 상태로 대기한다. 사용자가 전면에 접근하면 얼굴 박스를 먼저 탐지하고, 사용자가 1~3초 가만히 있으면 촬영을 고정해 얼굴 인식을 수행한다.

### 4.2 주요 기능

- **얼굴 감지 대기**: 대기 화면 진입 시 카메라 준비, 상시 ON
- **정지 판정**: 기본 2초, 센터 정책에 따라 1~3초 조정 가능
- **단일 얼굴 우선 인식**: 중앙 또는 가장 크게 잡힌 얼굴 우선
- **인식 실패 후 재시도**: 3초 후 재대기, 과도한 연속 호출 방지
- **얼굴 인식 비활성화 시**: 메뉴 숨김 (설정 OFF면 얼굴 체크인 미노출)

### 4.3 비즈니스 규칙

- 얼굴 인식 엔진은 외부 SDK/API 연동을 전제로 한다. 활성/비활성 정책은 admin `SCR-082-키오스크설정`을 따른다.
- 다중 얼굴 감지 시 한 명만 화면 앞에 서달라는 안내를 표시한다.
- 카메라 접근 차단 또는 비활성 상태에서도 같은 레이아웃에서 안내한다.

## 5. ATT-02 다중 인증 체크인

### 5.1 화면 목적

지점 설정값에 따라 노출된 인증 수단으로 회원/직원이 체크인한다. 대기 화면의 중앙 메인 시선 영역은 실시간 얼굴 인식 캠을 고정하고, 하단은 `QR 입장`, `전화번호 입장` 2개를 기본 도크로 사용한다.

### 5.2 인증 수단별 정책

| 코드 | 수단 | 권장 경로 | 상태 | 비고 |
|---|---|---|---|---|
| ATT-02-01 | QR | `/check-in/qr` | 기존 | 회원앱 발급 QR (`client/SCR-MA-110`) |
| ATT-02-02 | RFID | `/check-in/rfid` | 기존 | admin 카드 매핑(`SCR-052`) |
| ATT-02-03 | 얼굴 인식 | `/check-in/face` | 부분 구현 | 실카메라 연동 필요 |
| ATT-02-04 | 전화번호 | `/check-in/phone` | 기존 | 회원/직원 공용 |
| ATT-02-05 | 바코드 | `/check-in/barcode` | 기존 | 상세 정책 보강 필요 |

### 5.3 비즈니스 규칙

- 직원 출퇴근은 회원과 같은 인증 화면에서 처리한다. 인증 결과로 회원/직원을 자동 판별한다.
- 직원 출퇴근 허용 OFF 지점에서는 동일 흐름에서 `직원 출퇴근 불가`로 차단한다.
- 보조 메뉴(RFID, 바코드, 회원정보, 공지, 직원출석 등)는 admin `SCR-082-키오스크설정`의 메뉴 노출 정책에 따라 노출/숨김 처리한다.

## 6. ATT-03 출석 결과 처리

### 6.1 화면 목적

성공 시 입퇴장 기록 생성과 출입문 개방을 동시에 수행하고, 회원 정보를 모달형으로 4초간 표시한다. 실패 시 사유를 명확히 보여주고 이력은 운영자가 나중에 확인할 수 있도록 남긴다.

### 6.2 결과별 처리

| 결과 | 처리 |
|---|---|
| 성공 | 입퇴장 기록 생성, 출입문 5초 개방, 성공 TTS 재생, 모달 4초 노출 |
| 만료 | 실패 화면 + 프런트 문의 안내, 실패 7초 후 자동 복귀 |
| 미등록 | 실패 화면 + 재시도 안내 |
| 중복 | 실패 화면 + 잠시 후 재시도 안내 (10분 중복 방지) |
| 미수금 | 정책에 따라 경고 또는 차단 |
| 직원 불가 | 직원 출석 허용 OFF 시 차단 |

### 6.3 성공 모달 표시 정보

- 회원 사진
- 이용 시작일
- 이용 종료일
- 현재 이용 상품명
- 남은 이용일수 또는 남은 세션 수

### 6.4 비즈니스 규칙

- 성공 출석 시 전면 결과 페이지로 전환하지 않고, 배경 위에 회원 정보 모달을 띄우는 형태로 처리한다.
- 성공 모달 자동 복귀 4초, 실패 화면 자동 복귀 7초가 기본값이다.
- 락커 후처리 진행 중 상태가 성공 모달과 충돌하지 않게 처리한다.
- Health Connect/회원 건강 연동(SCR-I007, 회원앱 MA-159)은 키오스크·IoT 장비 구현 범위가 아니므로 출석 성공 화면에 안내 QR/딥링크를 노출하지 않는다.

## 7. ATT-04 출석 후 후처리

### 7.1 락커 후처리 정책 분기

회원 성공 출석 시 지점 운영 정책에 따라 다음 중 하나를 수행한다.

| 분기 | 처리 |
|---|---|
| 출석만 완료 | 락커 관련 후속 처리 없이 종료 |
| 수동 배정 대기 | 프런트에서 배정받으라는 안내 문구 노출 |
| 자동 배정 시도 | 지정 존(기본 A, B)에서 자동 배정 시도. 실패 시 수동 안내로 전환 |

### 7.2 락커 번호 전달 방식

자동 배정 또는 수동 확정 후 락커 번호를 사용자에게 전달한다. 0518 기준 `ATT-05`는 삭제하고, 전달 방식은 `ATT-04` 출석 후 후처리 하위 정책으로 흡수한다.

| 방식 | 설명 | 운영 전제 |
|---|---|---|
| ATT-04-03 영수증 출력 | 락커 번호가 적힌 영수증을 즉시 출력 | 키오스크 프린터 연결 필요 |
| ATT-04-04 앱 발송 | 회원 앱으로 락커 번호 발송, 키오스크에는 "앱에서 확인" 안내 | 회원 앱 연동/로그인 회원 식별 필요 |
| ATT-04-05 신발장 밴드 수령 | 신발장 번호를 노출, 사용자는 해당 신발장에서 밴드 수령 | 신발장-밴드-옷락커 번호 1:1 매핑 |

### 7.3 비즈니스 규칙

- 자동 배정 실패 시 즉시 수동 안내로 전환한다.
- 락커 후처리는 `docs4/V1/D06-시설관리/시설관리.md` SCR-050/SCR-051 및 `docs4/V1/D11-통합운영/통합운영.md` SCR-I004의 락커·사물함 상태와 동기화된다.

## 8. 락커 번호 전달 상세

### 8.1 ATT-04-03 영수증 출력

1. 출석 성공
2. 시스템이 락커 번호 배정
3. 프린터로 영수증 출력 (회원명/출석시각/락커번호/안내문구)
4. 사용자는 영수증을 보고 락커 사용

운영 원칙:

- 출력 실패 시 키오스크 화면에 락커 번호를 임시 표시하고 프런트 문의를 안내한다.
- 영수증에 과도한 개인정보를 넣지 않는다. 회원명은 마스킹 또는 이름만 표기 권장.
- 영수증 재출력은 관리자/프런트 예외 처리 기능이 필요하다.

### 8.2 ATT-04-04 앱 발송

1. 출석 성공
2. 락커 번호 배정
3. 회원 앱으로 푸시/인앱 메시지 발송
4. 키오스크에는 `앱에서 락커 번호를 확인해주세요`
5. 사용자는 앱 화면에서 번호 확인 후 락커 사용

운영 원칙:

- 앱 미연동 회원은 이 방식을 기본값으로 사용할 수 없다.
- 전송 실패 시 즉시 대체 수단으로 전환한다 (권장: `영수증 출력` → `프런트 안내`).
- 앱 화면에는 락커 번호, 유효 시간, 사용 안내를 함께 표시한다.
- Health Connect/회원 건강 연동(SCR-I007, 회원앱 MA-159)은 앱 발송 결과와 결합하지 않는다.

### 8.3 ATT-04-05 신발장 밴드 수령

1. 출석 성공
2. 신발장 번호 배정 (또는 기존 매핑 번호 확정)
3. 키오스크에 신발장 번호 대형 노출
4. 사용자는 해당 신발장에서 밴드 수령
5. 동일 번호의 옷 락커 사용

운영 원칙:

- 신발장 번호 = 밴드 번호 = 옷 락커 번호 1:1 정책 필수.
- 번호 체계가 어긋나는 센터에는 적용 불가.
- 밴드 분실/반납 누락 시 해당 번호는 즉시 배정 불가로 전환.
- RFID/밴드 운영 정책과 함께 설계 (`docs4/V1/D06-시설관리/시설관리.md` SCR-052).

### 8.5 기본값/타이머

| 항목 | 현재 기본값 |
|---|---|
| 중복 체크인 방지 | 10분 |
| 출입문 개방 시간 | 5초 |
| 성공 모달 자동 복귀 | 4초 |
| 실패 화면 자동 복귀 | 7초 |
| 자동 락커 배정 존 | A, B |
