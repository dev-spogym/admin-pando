# 2026-05-16 운영 요구사항 적용 여부 및 보강 계획

## 0. 검토 기준

- 검토 범위: `docs/admin`, `docs/client`, `docs/kiosk`, `src`
- 관리자 기획 정본 기준: `docs/admin/화면설계서`
- `docs/client`, `docs/kiosk`는 각각 모바일웹앱, 키오스크 제품 기획으로 분리 검토
- `docs/백업`은 정합성 판단의 정본에서 제외
- 아래의 "적용됨"은 현재 기획/퍼블리싱/코드 검색 기준으로 반영 흔적이 명확하다는 뜻이며, 실제 DB/API 구현 완료를 보장하지 않는다.

## 1. 상태 구분

| 상태 | 의미 |
|---|---|
| 적용됨 | 화면설계서/기능명세서/퍼블리싱 또는 코드에 명시 반영되어 있음 |
| 부분 적용 | 큰 방향은 있으나 정책값, 산식, 예외, TC, 코드 구현 중 일부가 부족함 |
| 미적용 | 현재 검토 범위에서 명확한 기획/화면/코드 반영을 찾지 못함 |
| 고객사 확인 필요 | 운영 기준이 없으면 기획 확정이 어려운 항목 |
| 개발사 확인 필요 | 연동사, SDK, 장비, DB/API 구현 방식 확인이 필요한 항목 |

## 7. 권장 답변 방향

아래처럼 답변하는 것이 안전하다.

> 말씀 주신 항목들은 기획 범위에서 제외하는 것이 아니라, 운영상 필요한 기준으로 보고 반영하겠습니다. 다만 저희 산출물 기준으로는 기획서, 화면설계서, 퍼블리싱 화면, TC 검수 기준까지 명확히 정리하는 것이고, 실제 DB/API, VAN/POS 연동, Android SDK, 급여 계산 엔진 구현은 개발사와 연동사 스펙 확인 후 구현 범위로 분리해야 합니다.
>
> 현재 결제/POS/영수증 업로드, 혼합결제, 부분환불, 지점/담당자/귀속 필드, 예외 회원권, KPI/페이롤 기본 화면은 문서상 반영되어 있습니다. 다만 산식, 승인 플로우, 장비 연동, 메시지 비용 단가, 모바일 지점 전환, TC 연결은 보강이 필요하므로 별도 매트릭스로 반영 상태와 확인 필요 항목을 관리하겠습니다.
