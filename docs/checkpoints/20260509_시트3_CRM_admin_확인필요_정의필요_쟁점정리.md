**대상 시트**: `3.CRM (admin)`
**작성일**: 2026-05-09
**목적**: 고객/내부 개발팀 협의가 필요한 항목만 별도 분리

## 사용 방법

- 이 문서는 `확인필요`, `정의필요` 판정 항목만 묶어서 본다.
- 각 묶음마다 `관련 시트 행`, `현재 판단`, `왜 애매한지`, `확인 질문`, `권장 방향`을 같이 본다.
- 최종 확정 시에는 이 문서를 기준으로 `V1-기본`, `V1-개발기반`, `V2-후보`로 재배치하면 된다.

## 1. 회원관리 확장 기능

### 1-1. 세그먼트/자동 판정

- 관련 시트 행: `143`, `188~196`, `221`
- 관련 코드: `MBR-01-13`, `MBR-ADV-06`, `MBR-EXT-04`
- 현재 판단: `확인필요`
- 애매한 이유:
  - 회원 목록 표시 수준인지, 자동 판정 엔진/배치 재계산/마케팅 연동까지 포함하는지 범위가 크다.
  - 문서는 있으나 `퍼블링 완료/데이터 미연동` 상태 메모가 있어 V1 기본 확정이 어렵다.
- 확인 질문:
  - V1에서 필요한 범위가 `세그먼트 라벨 표시`인지, `조건 빌더 + 자동 재계산`까지인지?
  - 마케팅 액션 연결까지 V1에 포함되는지?
- 권장 방향:
  - `라벨 표시만`이면 `V1-기본 또는 확인 후 V1`
  - `조건 빌더/자동 판정/액션 연결 포함`이면 `확인 후 V2 또는 고도화 범위`

### 1-2. 회원 병합

- 관련 시트 행: `198~204`
- 관련 코드: `MBR-EXT-01`
- 현재 판단: `확인필요`
- 애매한 이유:
  - 민감 기능이고 되돌리기 어려운 데이터 처리다.
  - 주/부 계정, 필드 선택 병합, 후처리 정책까지 포함돼 운영 정책 확인이 필요하다.
- 확인 질문:
  - 실제 운영상 V1 오픈 시점에 반드시 필요한지?
  - 병합 후 이력/복구 정책까지 요구하는지?
- 권장 방향:
  - 필수 운영 요구가 명확하면 `V1`
  - 운영 빈도가 낮고 정책 미확정이면 `V2`

### 1-3. 가족 회원 / 회원 등급

- 관련 시트 행: `205~220`
- 관련 코드: `MBR-EXT-02`, `MBR-EXT-03`
- 현재 판단: `확인필요`
- 애매한 이유:
  - 가족 할인, 그룹 결제, 등급 혜택, 자동 갱신 등 정책형 기능이다.
  - 기본 CRUD가 아니라 할인/혜택/배치 처리까지 연결된다.
- 확인 질문:
  - V1에서 필요한 것이 `조회/표시`인지, `정책 설정 + 자동 반영`까지인지?
  - 결제/혜택/예약 우선권과 실제 연동까지 포함하는지?
- 권장 방향:
  - 단순 표시/관리면 `확인 후 일부 V1`
  - 혜택 정책/자동화까지면 `V2` 검토

## 2. 엑셀/내보내기 계열

  - 일부는 운영상 필수일 수 있으나, 일부는 후속 요청 가능성이 높다.

  - 각 화면에서 다운로드가 `오픈 필수`인지, `운영 편의`인지?
  - 월말 보고/제출 용도로 반드시 필요하다는 계약/운영 근거가 있는지?
- 권장 방향:
  - 법정 제출/정산 필수는 `V1`
  - 일반 반출 편의는 `확인 후 V2 또는 후속`

## 9. 우선 협의 순서 제안

### A. 이번 주말 내 반드시 정리할 것

- `시설관리(FAC-01~06)` 포함 여부
- `IoT 계약 범위(IoT-02, IoT-03)` 포함 여부
