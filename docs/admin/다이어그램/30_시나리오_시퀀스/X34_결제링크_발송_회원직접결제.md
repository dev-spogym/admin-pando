# X34 — 직원 결제링크 발송 → 회원 직접 결제 → 매출 반영

## 1. 시나리오 개요

직원이 CRM에서 회원과 상품을 선택하고 고정 금액 결제링크를 발송한 뒤, 회원이 앱/웹 결제 화면에서 직접 결제하고 결과가 매출과 회원 상세에 반영되는 흐름.

| 항목 | 내용 |
|------|------|
| 트리거 | 직원이 SCR-S003에서 `결제링크 발송` 실행 |
| 종료 조건 | 링크 상태 `PAID`, 원결제 `APPROVED`, 영수증 발행, 관리자 화면 반영 |
| 참여 도메인 | 매출관리(D3), 회원관리(D2), 회원앱(Client) |

## 2. 전제조건

- 회원이 CRM에 등록되어 있고 연락처가 유효함
- 상품/금액/할인이 직원 화면에서 최종 확정됨
- 링크 발송 후 회원은 금액·할인·쿠폰·마일리지를 수정할 수 없음
- 링크 기본 유효기간은 7일이며, 운영자는 활성 링크를 같은 링크로 재발송하거나 강제 만료할 수 있음

## 3. 참여 액터

| 액터 | 설명 |
|------|------|
| FC | 결제링크를 생성·발송하는 직원 |
| 회원 | 링크를 수신하고 직접 결제하는 고객 |
| CRM API | 관리자 결제링크 / 매출 처리 백엔드 |
| Client App | 회원앱 또는 웹 결제 진입 화면 |
| PG | 결제 대행사 |
| DB | 데이터베이스 |

## 4. 시퀀스 다이어그램

```mermaid
    actor FC as FC
    actor MB as 회원
    participant API as CRM API
    participant APP as Client App
    participant PG as PG사
    participant DB as DB

    FC->>API: 1. POST /payment-links {member_id, product_id, fixed_amount, expire_at}
    API->>DB: 2. payment_link {status=SENT, token, expire_at, fixed_amount, discount_snapshot}
    DB-->>API: 3. link_id, token
    API-->>FC: 4. 200 OK {link_url}
    Note over FC: DLG-S016 발송 완료

    API-->>MB: 5. SMS/카카오톡 결제링크 발송
    MB->>APP: 6. 링크 열기
    APP->>API: 7. GET /payment-links/{token}
    API->>DB: 8. payment_link status=OPENED
    DB-->>API: 9. 고정 금액 / 상품 정보
    API-->>APP: 10. 결제 정보 응답
    Note over APP: MA-140 결제하기 - 링크 진입

    MB->>APP: 11. 결제수단 선택 후 결제
    APP->>API: 12. POST /payments/checkout {token, payment_method}
    API->>DB: 13. payment {payment_channel=LINK, collection_mode=FULL, status=PENDING}
    API->>PG: 14. 승인 요청

    alt 승인 성공
        PG-->>API: 15. 승인 응답 {approval_no, approved_at}
        API->>DB: 16. payment status=APPROVED
        API->>DB: 17. payment_link status=PAID
        API->>DB: 18. memberships ACTIVE 또는 기존 정책 반영
        DB-->>API: 19. payment_id, membership_id
        API-->>APP: 20. 200 OK {receipt_url}
        Note over APP: MA-142 영수증 상세
        API->>DB: 21. 매출현황 / 회원상세 조회 데이터 갱신
    else 승인 실패
        PG-->>API: 22. 실패 응답
        API-->>APP: 23. 결제 실패 안내
        Note over APP: 링크는 만료 전까지 재시도 가능
    else 링크 만료
        API-->>APP: 24. linkStatus=EXPIRED
        Note over APP: 재발송 요청 안내
    end
```

## 5. 주요 메시지 설명

| 번호 | 메시지 | 설명 |
|------|--------|------|
| 1 | POST /payment-links | 직원이 고정 금액 결제링크 생성 |
| 10 | 결제 정보 응답 | 회원은 상품명/금액 확인만 가능, 수정 불가 |
| 12 | POST /payments/checkout | 링크 토큰 기반 결제 실행 |
| 13 | payment PENDING 생성 | 고객이 실제 결제를 제출한 시점에만 원결제 레코드 생성 |
| 16 | payment APPROVED | 승인 성공 시 원결제 상태 갱신 |
| 17 | payment_link PAID | 링크 자체 상태는 별도 관리 |

## 6. 예외/분기

| 상황 | 처리 방법 |
|------|-----------|
| 연락처 없음 | 링크 발송 자체 차단 |
| 활성 링크 존재 | 같은 링크 재발송 가능, 필요 시 강제 만료 후 새 링크 생성 |
| 링크 만료 | 회원은 결제 불가, 직원 재발송 필요 |
| 결제 실패 | 링크 만료 전 재시도 가능 |
