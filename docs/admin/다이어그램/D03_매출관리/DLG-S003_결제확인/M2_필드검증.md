## 1. 목적
DLG-S003 결제확인 모달에서 현장 결제 등록 정보 유효성 검증 흐름을 표현한다.

## 2. 전제조건
- DLG-S003 열림 상태

## 3. 다이어그램

```mermaid
flowchart TD
    OPEN[DLG-S003 열림] --> VALIDATE{결제 등록 정보 검증}

    VALIDATE -->|": 장바구니 유효"|AMOUNT_CHECK{금액 검증}
    VALIDATE -->|": 장바구니 비어있음"|ERR_CART[장바구니 오류\n상품을 선택해주세요.]

    AMOUNT_CHECK -->|": 결제가격 + 포인트 = 합계"|METHOD_CHECK{결제수단 확인}
    AMOUNT_CHECK -->|": 불일치"|ERR_AMOUNT[금액 오류\n결제 총액이 장바구니 합계와 다릅니다.]

    METHOD_CHECK -->|": 수단 선택됨"|RECEIPT_CHECK{영수증 첨부 확인}
    METHOD_CHECK -->|": 수단 미선택"|ERR_METHOD[결제수단 미선택 오류]

    RECEIPT_CHECK -->|": 첨부됨"|PAID_AT_CHECK{결제일시 확인}
    RECEIPT_CHECK -->|": 미첨부"|ERR_RECEIPT[영수증 파일 필수 오류]

    PAID_AT_CHECK -->|": 입력됨"|POINT_CHECK{포인트 사용 검증}
    PAID_AT_CHECK -->|": 누락"|ERR_PAID_AT[결제일시 누락 오류]

    POINT_CHECK -->|": 미사용 또는 충분"|CONFIRM_READY[확인 버튼 활성]
    POINT_CHECK -->|": 회원 미선택"|ERR_MEMBER[포인트 사용 회원 미선택 오류]
    POINT_CHECK -->|": 보유 부족"|ERR_POINT[포인트 부족 오류]

    classDef system fill:#EDE7F6,stroke:#5E35B2
    classDef success fill:#E8F5E9,stroke:#2E7D32,color:#1B5E20
    classDef error fill:#FFEBEE,stroke:#C62828,color:#B71C1C

    class VALIDATE,AMOUNT_CHECK,METHOD_CHECK,RECEIPT_CHECK,PAID_AT_CHECK,POINT_CHECK system
    class CONFIRM_READY success
    class ERR_CART,ERR_AMOUNT,ERR_METHOD,ERR_RECEIPT,ERR_PAID_AT,ERR_MEMBER,ERR_POINT error
```

## 4. 엣지 설명

| 출발 | 도착 | 설명 |
|------|------|------|
| VALIDATE | AMOUNT_CHECK | 장바구니 유효 |
| VALIDATE | ERR_CART | 장바구니 빈 상태 |
| AMOUNT_CHECK | METHOD_CHECK | 결제가격 + 포인트 사용액이 장바구니 합계와 일치 |
| AMOUNT_CHECK | ERR_AMOUNT | 결제 총액 불일치 |
| METHOD_CHECK | RECEIPT_CHECK | 결제수단 선택됨 |
| RECEIPT_CHECK | PAID_AT_CHECK | 영수증 첨부됨 |
| PAID_AT_CHECK | POINT_CHECK | 결제일시 입력됨 |
| POINT_CHECK | CONFIRM_READY | 포인트 검증 통과 |
