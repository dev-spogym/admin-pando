## 기능 목적

운동복, 보충제, 용품, 식음료 등 실물 상품(category=PRODUCT, productType=GENERAL)의 재고 현황을 관리하는 화면이다. 현재 재고 수량을 확인하고 입고·출고 처리를 기록하며, 재고 실사 후 수동 조정(가감)할 수 있다. 안전 재고 미달 시 경고 표시 + 자동 알림으로 재주문 시점을 식별하고, 모든 입출고·조정 이력은 처리자·시간·사유와 함께 추적 가능하다. POS 판매(SCR-S002) 시 자동 차감되며 매입 단가 입력으로 마진 분석(SCR-S004 매출통계)도 지원한다.

운영 맥락:
- **신규 상품 입고**: 거래처에서 운동복 100벌 입고 → DLG-P019-입고등록 입고 등록 → 단가·거래처·비고 입력 → 재고 갱신
- **POS 판매 자동 차감**: 카운터에서 보충제 1통 판매 → SCR-S003 결제 완료 → 자동 출고 처리 + 재고 -1
- **수기 출고 (폐기/내부 사용/이동)**: 유통기한 초과 보충제 폐기 → DLG-P020-출고등록 출고 등록 → 사유 "폐기" 선택
- **재고 실사 조정**: 분기별 실사 → DLG-P021-재고조정 재고조정 → 시스템 100 vs 실물 95 → 차이 -5 + 사유 "분실/파손" 기록
- **안전 재고 미달 알림**: 운동복 안전 재고 20 미만 시 자동 경고 + NFR-19 알림 센터로 발주 권유
- **입고 단가 / 매입 원가 추적**: 단가 입력 시 매입 원가 자동 누적, SCR-S004에서 마진율 분석
- **입출고 이력 감사**: DLG-P022-입출고이력 → 시간순 모든 거래 + 처리자 + 사유 + 단가 표시
- **거래처 관리**: 단가 + 거래처 입력으로 거래처별 매입 통계 (선택 기능)
- **카테고리·재고 상태 필터**: 운동복/보충제/용품 분류 + 충분/부족/품절 상태별 조회

## 주요 구성요소

### 재고 통계 카드 (3개)

| 카드 | 내용 |
|------|------|
| 전체 품목 수 | 관리 중인 실물 상품 종류 |
| 부족 재고 | 안전 재고 미달 품목 수 |
| 품절 | 재고 0인 품목 수 |

### 필터 / 검색

- 상품 카테고리 필터
- 재고 상태 필터 (충분 / 부족 / 품절)
- 상품명 검색
- 거래처 필터(선택)

### 재고 현황 테이블

| 컬럼 | 내용 |
|------|------|
| 상품명 | 실물 상품 이름 |
| 카테고리 | 분류 |
| 현재 재고 | 보유 수량 |
| 안전 재고 | 최소 유지 기준 |
| 재고 상태 | 충분 / 부족 / 품절 |
| 최근 입고일 | YYYY-MM-DD |
| 최근 입고 단가 | 매입 단가 |
| 누적 매입 원가 | 매입 누적 |
| 액션 | [입고] / [출고] / [조정] / [이력] |

### 입고 등록 (DLG-P019-입고등록)

| 입력 | 설명 |
|------|------|
| 입고 수량 | 숫자 (필수) |
| 입고일 | YYYY-MM-DD (기본 오늘) |
| 단가 | 매입 단가 (선택, 마진 분석용) |
| 거래처 | 텍스트 (선택) |
| 비고 | textarea (선택) |

### 출고 등록 (DLG-P020-출고등록)

| 입력 | 설명 |
|------|------|
| 출고 수량 | 숫자 (필수) |
| 출고 사유 | 판매 / 폐기 / 이동 / 내부 사용 / 분실 |
| 출고일 | YYYY-MM-DD (기본 오늘) |
| 비고 | textarea (필수, 폐기/분실 시) |

### 재고 조정 (DLG-P021-재고조정)

실사 후 실제 수량 입력 → 차이만큼 자동 조정 + 사유 기록 (필수). 차이 양수는 추가, 음수는 감소.

### 입출고 이력 (DLG-P022-입출고이력)

상품별 시간순 입출고·조정 기록 표시.

| 컬럼 | 내용 |
|------|------|
| 일시 | YYYY-MM-DD HH:mm |
| 구분 | 입고 / 출고 / 조정 / 자동 차감(POS) |
| 수량 | +N / -N |
| 사유 | 사유 또는 비고 |
| 단가 | 입고 시 단가 |
| 처리자 | 직원 이름 |
| 잔량 | 처리 후 잔량 |

### 강조 표시

| 상태 | 색상 | 조건 |
|------|------|------|
| 충분 | 기본 | 현재 재고 ≥ 안전 재고 |
| 부족 | 노랑/주황 | 0 < 현재 재고 < 안전 재고 |
| 품절 | 빨강 | 현재 재고 = 0 |

## 주요 UX 흐름

**입고 처리**
1. 사이드바 → "상품관리 > 재고 관리" 진입
2. 상품 행 [입고] → DLG-P019-입고등록
3. 수량·날짜·단가·거래처 입력
4. 저장 → 재고 갱신 + 이력

**출고 처리**
1. 행 [출고] → DLG-P020-출고등록
2. 수량·사유 입력 (폐기/분실은 비고 필수)
3. 저장 → 재고 차감 + 이력

**재고 조정**
1. 실사 후 행 [조정] → DLG-P021-재고조정
2. 실제 수량 입력 + 사유
3. 저장 → 차이 자동 보정 + 이력

**이력 조회**
1. 행 [이력] → DLG-P022-입출고이력
2. 시간순 입출고·조정 기록

### 분기·예외 흐름

- **출고 수량 > 현재 재고**: 빨강 인라인 "현재 재고 {개수}개를 초과할 수 없어요" + 저장 차단
- **POS 판매 자동 차감 + 재고 0**: SCR-S003에서 사전 검증으로 결제 차단, 재고 0인 상품은 결제 불가
- **재고 조정 차이 0**: "변경 사항이 없어요" 안내 + 저장 차단
- **재고 조정 음수 결과(현재 재고 < 차이)**: 결과가 0 미만이 되도록 입력하면 차단
- **단가 미입력 입고**: 매입 원가 누적 안 됨, 노랑 경고 "단가 입력 시 마진 분석 가능"
- **거래처 미입력**: 거래처별 통계에서 "미지정" 그룹으로 집계
- **안전 재고 미설정 상품**: 부족 알림 발송 안 됨 + 노랑 경고 "안전 재고 설정 권유"
- **POS 자동 차감 실패(재고 부족 race condition)**: 결제 트랜잭션 롤백 + "재고 부족" 토스트
- **수동 출고 + POS 판매 동시(동시성)**: 낙관적 락 또는 비관적 락으로 처리, 충돌 시 재시도
- **이력 1만 건 초과**: DLG-P022-입출고이력 페이지네이션 또는 기간 필터
- **상품 비활성 + 재고 보유**: 재고 관리는 정상, 신규 판매만 차단
- **상품 삭제 시도 + 재고 보유**: "재고 {개수}개 보유 중" 안내 + 출고 후 삭제 안내
- **거래처 텍스트 자유 입력 + 오타**: 거래처 통계 흩어짐, 자동 완성으로 정규화 권장
- **단가 0원 입력**: "단가는 0보다 커야 해요" + 노랑 경고 (무료 입고는 비고 필수)
- **출고 사유 미선택**: 인라인 "사유 선택 필수" + 저장 차단
- **폐기/분실 + 비고 미입력**: 인라인 "비고 입력 필수" + 저장 차단
- **재고 조정 + 사유 미입력**: 인라인 "사유 입력 필수" + 저장 차단
- **권한 없음 + 직접 URL 진입**: 읽기 전용 모드
- **이력 조회 + 다른 사용자 입출고 진행 중**: 5초 캐시 + [새로고침] 버튼
- **본사 통합 모드 + 입출고 시도**: "지점을 먼저 선택해주세요" + 차단
- **재고 카드 노출 + 회원앱 연동**: 회원앱은 재고 정보 미노출(어드민 only), 카탈로그에는 "재고 부족" 배지만

## 비즈니스 규칙

1. 안전 재고 미달 품목은 자동으로 경고 색상이 표시된다 (노랑/주황).
2. 재고 0 품목은 자동 품절 표시되며 카운트에 포함된다 (빨강).
3. 재고 조정 시 사유 입력은 필수이며 감사 로그(SCR-097)에 기록된다.
4. 출고 사유는 판매/폐기/이동/내부 사용/분실 5종으로 구분되어 통계에 반영된다.
5. 입고 시 단가 입력은 선택이지만 입력 시 매입 원가 추적에 활용된다 (SCR-S004 마진 분석).
6. 모든 입출고·조정은 처리자·시간이 자동 기록된다.
7. **POS 판매 자동 차감**: SCR-S003 결제 완료 이벤트 → 자동 출고 INSERT (구분: 자동 차감, 처리자: 결제자, 잔량: 갱신 후).
8. **출고 사유 비고 필수 정책**: 폐기 / 분실 사유는 비고 입력 필수, 판매 / 이동 / 내부 사용은 선택.
9. **재고 조정 차이**: 실사 수량 - 시스템 수량. 차이 양수는 추가, 음수는 감소. 0이면 변경 없음으로 차단.
10. **안전 재고 정책**: 상품 등록(PRD-EXT-01)에서 설정. 미설정 시 부족 알림 미발송 + 노랑 경고 표시.
11. **부족 알림 트리거**: 출고 후 현재 재고 < 안전 재고 시 NFR-19 알림 센터로 발송. 동일 상품 24시간 1회 (스팸 방지).
12. **품절 알림 트리거**: 재고 0 도달 시 즉시 알림 + 키오스크 / 회원앱에서 "품절" 배지.
13. **매입 원가 누적**: 입고 시 단가 × 수량 누적. SCR-S004 매출통계에서 마진율 = (판매가 - 평균 매입가) / 판매가.
14. **거래처 정보**: 텍스트 자유 입력. 거래처별 통계는 정규화 후 집계 (오타 자동 완성 권장).
15. **이력 보존 정책**: 최근 1년 즉시 조회, 1년 경과는 SCR-097 감사 로그에서 조회.
16. **재고 음수 차단**: 현재 재고 - 출고 수량 ≥ 0 필수. 음수 결과는 저장 차단.
17. **권한별 액션**:
    - 슈퍼관리자/센터장/매니저/재고 관리 권한: 입고·출고·조정·이력
    - 일반 직원: 조회만 (출고는 POS 자동만)
    - readonly: 접근 불가
18. **POS 자동 차감 동시성**: 동시 결제로 재고 부족 시 결제 트랜잭션 롤백 + 토스트 안내.
19. **상품 비활성 + 재고 보유**: 재고 관리는 정상, 신규 판매만 차단. 잔여 재고 출고는 "이동" 사유로 처리.
20. **상품 삭제 + 재고 보유**: 차단. 재고 0으로 만든 후에만 삭제 가능.
21. **본사·지점 컨텍스트**: 재고는 지점 단위. 본사 통합 모드는 조회만, 입출고는 지점 컨텍스트 필수.
22. **회원앱·키오스크 연동**: 재고 정보는 어드민 전용. 카탈로그·키오스크에는 "재고 부족" / "품절" 배지만 표시.
23. **감사 로그**: 입고·출고·조정·자동 차감 모두 SCR-097에 기록. `actor_id, product_id, type, quantity, before, after, reason`.

## 자동화 / 배치 / 이벤트 연계

| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| POS 자동 차감 | SCR-S003 결제 완료 | 자동 출고 INSERT (구분: 자동 차감) |
| NFR-19 알림 센터 | 안전 재고 미달 / 품절 도달 | 발주 권유 알림 (24시간 1회) |
| SCR-097 감사 로그 | 입고·출고·조정·자동 차감 | INSERT (actor·before·after·reason) |
| SCR-S004 매출통계 | 입고 단가 등록 | 매입 원가 누적 + 마진 분석 |
| 회원앱 / 키오스크 동기화 | 재고 0 도달 / 부족 | "품절" / "재고 부족" 배지 표시 |
| 카탈로그 (PRD-05) | 재고 0 도달 | "품절" 배지 자동 표시 |
| 부족 / 품절 알림 (Cron) | 매일 09:00 | 일일 부족·품절 리포트 발송 |
| 매입 원가 평균 갱신 | 입고 INSERT | 가중 평균 매입가 갱신 |
| 거래처 통계 | 입고 + 거래처 입력 | 거래처별 매입 누적 |
| 이력 1년 경과 아카이브 | 매월 1일 04:00 | 감사 로그로 이관 |
| 동시성 락 | 입출고·자동 차감 | 비관적 락으로 race condition 방지 |

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `PRD-07`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-P007`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-P019-입고등록 입고등록, DLG-P020-출고등록 출고등록, DLG-P021-재고조정 재고조정, DLG-P022-입출고이력 입출고이력`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
