## 기능 목적

상품 판매 시 사용할 할인 정책을 등록·수정·삭제·조회하는 화면이다. 정률(%) 또는 정액(원) 방식, 최소 계약 기간 조건, 최대 할인 한도, 적용 상품, 적용 기간을 관리한다. v1 개발 기준에서 본 기능은 할인 정책의 등록/관리까지만 포함하며, 결제 화면(SCR-S003) 자동 적용 로직은 개발 기준으로 삼지 않는다. 변경 이력 타임라인을 통해 최근 수정 내역을 한 화면에서 확인한다.

v1 제외 / 후속 확인:
- 결제 자동 적용, 중복 적용, 우선순위, 직원 수동 변경 가능 여부는 고객사 확인 후 확정한다.
- 쿠폰/마일리지는 자동 적용하지 않고 사용자 선택 시에만 적용하는 방향이다.
- 마일리지는 다른 혜택과 중복 가능하되, 마일리지를 제외한 할인/쿠폰/시즌특가/등급할인은 중복 적용하지 않는 방향이다.
- 시즌특가와 등급할인이 동시에 걸리면 더 큰 할인 1개만 적용하는 방향이나, 고객사 확인 전까지 개발 기준으로 보지 않는다.
- 직원은 결제 자동 적용 결과를 임의로 바꾸지 못하고, 사용자 선택 기반으로만 적용하는 방향이나, 이 역시 후속 확정 대상이다.
- 아래 결제 적용 예시는 후보 운영 시나리오이며, v1 개발 기준이 아니다.

운영 맥락:
- **장기 계약 인센티브**: 12개월 이상 헬스 계약 시 10% 정률 할인 후보 정책 등록 → 계약 갱신율 증대
- **VIP 등급 회원 정률 할인**: VIP/Gold/Silver 등급별 5/10/15% 후보 정책 등록
- **신규 가입 첫 구매 정액 할인**: 첫 구매 회원 5만원 정액 할인 (1회성)
- **재등록 할인**: 만료일 이전 재구매 시 정률 할인
- **세그먼트 기반 마케팅**: "최근 90일 미방문 회원" 세그먼트 대상 정률 할인 메시지
- **단체 할인**: 회사 / 학교 단체 가입 시 정률 할인
- **할인 한도 정책**: 정률 50% 할인 + 한도 10만원 → 고가 상품에서 할인 폭 제한
- **할인 종료 / 비활성**: 캠페인 종료 시 비활성 토글. 결제 반영은 v1 개발 기준 제외
- **할인 변경 이력 추적**: 누가 / 언제 / 무엇을 변경했는지 타임라인 + 감사 로그(SCR-097)

후속 확인 기준안(개발 기준 아님):
1. **쿠폰/마일리지**는 자동 적용하지 않고 사용자 선택 시에만 적용한다.
2. **마일리지**는 다른 혜택과 중복 가능하다.
3. **마일리지를 제외한 할인/쿠폰/시즌특가/등급할인**은 중복 적용하지 않는다.
4. **시즌특가와 등급할인**이 동시에 걸리면 더 큰 할인 1개만 적용한다.
5. 직원은 사용자 선택 없이 임의로 할인/쿠폰/마일리지 적용값을 바꾸지 못한다.

### 할인 삭제 (DLG-P011-할인규칙삭제확인)

삭제 확인 다이얼로그 + 사용 중 상품 / 적용 중 회원 안내.

### 변경 이력 타임라인

최근 등록·수정·삭제 이력 시간순 표시. 이력 0건이면 섹션 숨김.

| 항목 | 표시 |
|------|------|
| 날짜·시간 | YYYY-MM-DD HH:mm |
| 작업 구분 | 등록 / 수정 / 삭제 |
| 할인명 | 대상 |
| 요약 | 변경 내용 (예: 값 10% → 15%) |
| 작업자 | 이름 |

## 주요 UX 흐름

**할인 추가**
1. 사이드바 → "상품관리 > 할인 설정" 진입
2. [할인 추가] → DLG-P007-할인규칙등록
3. 이름·유형·값·조건·한도 입력
4. 적용 상품·후보 조건·기간·메모를 설정한다. 결제 자동 적용/중복 정책은 v1 개발 기준에서 제외한다.
5. 저장 → 목록 추가 + 이력 추가

**할인 수정**
1. 행 [수정] → DLG-P009-할인규칙수정
2. 정보 변경 → 저장
3. 이력 추가

**할인 삭제**
1. 행 [삭제] → DLG-P011-할인규칙삭제확인
2. 사용 중 상품 / 적용 중 회원 안내
3. 확인 → 삭제 + 이력

### 분기·예외 흐름

- **정률 값 0 또는 100 초과**: 인라인 "1~100% 사이로 입력해주세요" + 저장 차단
- **정액 값 0 이하**: "0보다 큰 금액을 입력해주세요" + 저장 차단
- **정률 한도 입력 + 정액 선택**: "정액 할인은 한도 입력 불가" + 한도 필드 비활성
- **적용 기간 시작일 > 종료일**: "종료일은 시작일 이후여야 해요" + 저장 차단
- **적용 상품 0개**: "적용 상품을 선택해주세요" + 저장 차단. 자동 적용 후보 조건만으로는 저장 기준을 충족하지 않는다.
- **결제 적용 후보 조건 다중 선택(VIP + 세그먼트)**: 후보 조건으로만 저장. 결제 반영 기준은 v1 제외.
- **할인 한도 < 정률 적용 금액**: 한도까지만 차감 (기능 정상 작동)
- **삭제 시 적용 중 회원 있음**: "현재 적용 중인 회원 {인원수}명이 있습니다, 비활성으로 전환하시겠어요?" 분기
- **시즌 가격(PRD-08) 중복**: v1 결제 기준 제외. 후속 기준안은 시즌특가와 등급할인 중 더 큰 할인 1개만 적용.
- **쿠폰·마일리지 결합**: v1 결제 기준 제외. 후속 기준안은 쿠폰/마일리지 모두 사용자 선택 시에만 적용하며, 마일리지만 다른 혜택과 중복 가능.
- **결제 적용 기준 충돌**: v1 결제 기준 제외. 후속 기준안은 직원 임의 변경 불가, 사용자 선택 기반 적용.
- **적용 기간 외 정책**: v1 결제 기준 제외. 관리 화면에서는 적용 기간 외 정책을 비활성/회색 상태로 표시한다.
- **할인 후 가격 < 0**: "할인 후 가격이 0 이하가 됩니다, 한도 또는 값 조정 필요" 안내
- **할인명 중복(동일 지점)**: "이미 등록된 할인명입니다" + 저장 차단
- **권한 없음 + 직접 URL 진입**: 읽기 전용 모드
- **이력 50건 초과**: 페이지네이션 또는 [더보기] 버튼
- **동시 수정 충돌**: "다른 사용자가 먼저 저장했어요" 낙관적 락

## 비즈니스 규칙

1. 정률 할인은 1~100% 범위, 정액 할인은 0 초과 금액으로 검증한다.
2. 최대 할인금액(한도)은 정률 할인에만 적용 가능하며, 한도 이상 할인되지 않는다.
3. 최소 계약 기간 조건이 있으면 해당 기간 미만 상품에는 적용되지 않는다.
4. 결제 적용 후보 조건(등급/세그먼트)은 v1에서 결제 화면 자동 적용 기준으로 사용하지 않는다.
5. 비활성 할인은 적용 대상에서 제외된다.
6. 등록·수정·삭제 시 변경 이력이 자동 기록되고 SCR-097 감사 로그에도 INSERT된다.
7. 적용 기간 외에는 자동으로 비활성된다.
8. **할인명 정책**: 1~30자, 동일 지점 내 중복 불가. 한글·영문·숫자·일부 특수문자 허용.
9. **적용 상품 정책**: 다중 선택 또는 "전체 상품" 토글. "전체 상품"은 카테고리 필터(MEMBERSHIP / PT / GX / PRODUCT / SERVICE)로 좁히기 가능.
10. **결제 적용 후보 조건**: 회원 등급(VIP/Gold/Silver/일반), 세그먼트(MBR-EXT-04 연계, 다중 가능)는 후보값으로만 관리한다. v1 결제 자동 적용 기준으로 사용하지 않는다.
11. **후속 중복 적용 기준안(개발 기준 아님)**: 마일리지는 다른 혜택과 중복 가능. 마일리지를 제외한 할인/쿠폰/시즌특가/등급할인은 중복 적용하지 않는다.
12. **쿠폰·마일리지 기준안(개발 기준 아님)**: 쿠폰과 마일리지는 자동 적용하지 않고 사용자 선택 시에만 적용한다. 직원은 임의로 대신 선택하거나 변경하지 않는다.
13. **적용 횟수 제한**: 1회성(회원당 1회) / 무제한. 1회성은 회원 ID + 할인 ID로 중복 차단.
14. **결제 적용 변경 권한 기준안(개발 기준 아님)**: 직원은 할인/쿠폰/마일리지 적용을 임의로 바꾸지 못하고, 사용자 선택에 따른 적용만 허용하는 방향이다.
15. **할인 후 가격 0 이하**: 결제 시 0원으로 처리하지 않고 0원 결제 차단(0 미만 허용 토글은 정책에 따름).
16. **권한별 액션**:
    - 슈퍼관리자/센터장/관리자 권한: 등록·수정·삭제
    - 매니저: 등록·수정 (삭제 제외)
    - 일반 직원: 조회만
17. **비활성 vs 삭제**: 적용 중 회원 있는 할인은 삭제 대신 비활성 권장. 강제 삭제 시 적용 중 결제는 영향 없음(이미 적용된 가격 유지).
18. **변경 이력 50건 초과**: 페이지네이션 또는 [더보기]. 1년 경과 이력은 SCR-097에서 조회.
19. **동시 수정 충돌**: 낙관적 락 (`updated_at` 비교).
20. **본사 vs 지점 할인**: 본사 슈퍼관리자가 정의한 할인은 전 지점 공통, 센터장 정의는 소속 지점만 적용.
21. **할인 미리보기**: DLG에서 적용 상품 1개 선택 후 미리보기 → "100,000원 → 90,000원" 시뮬레이션.
22. **세그먼트 후보값 갱신**: 후보 조건이 세그먼트인 경우 세그먼트 멤버 갱신값을 참조할 수 있으나, v1 결제 자동 적용에는 사용하지 않는다.
23. **감사 로그**: 등록·수정·삭제·활성/비활성 토글 모두 SCR-097에 기록. `actor_id, discount_id, action, before, after`.

## 예외 / 에러 처리

| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| 정률 값 0 또는 >100 | 인라인 "1~100% 사이" | 저장 차단 |
| 정액 값 ≤0 | "0보다 큰 금액" | 저장 차단 |
| 정액 + 한도 입력 | 한도 필드 비활성 | 정률만 한도 |
| 시작일 > 종료일 | "종료일은 시작일 이후" | 저장 차단 |
| 적용 상품 0개 | "적용 상품을 선택해주세요" | 저장 차단 |
| 할인명 중복 | "이미 등록된 할인명" | 저장 차단 |
| 삭제 + 적용 중 회원 | "회원 {인원수}명, 비활성 권장" | 비활성 / 강제 삭제 |
| 시즌 가격 중복 정책 미설정 | v1 결제 기준 제외 | 고객사 확인 후 확정 |
| 할인 후 가격 ≤0 | "할인 후 0 이하" | 한도/값 조정 |
| 적용 기간 외 정책 | 관리 화면 회색 처리 | 결제 반영은 v1 제외 |
| 결제 적용 기준 충돌 | 정책 미확정 안내 | v1 개발 기준 아님 |
| 권한 없음 + 직접 URL | 읽기 전용 | - |
| 이력 50건 초과 | 페이지네이션 | - |
| 동시 수정 충돌 | "다른 사용자 먼저 저장" | [최신 보기] / [덮어쓰기] |
| 1회성 적용 회원 재시도 | "이미 사용한 할인" | 차단 |
| 본사 정의 할인 + 지점 수정 시도 | "본사 정의 할인은 수정 불가" | 차단 |
| 세그먼트 0명 | 노랑 경고 "적용 대상 없음" | 진행 가능 |
| 할인 미리보기 상품 선택 0 | 미리보기 비활성 | 상품 선택 안내 |
| 카테고리 필터 + 적용 상품 충돌 | 명시 적용 상품 우선 | 안내 토스트 |

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `PRD-04`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-P004`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-P007-할인규칙등록, DLG-P009-할인규칙수정, DLG-P011-할인규칙삭제확인, DLG-P013-할인정책추가수정, DLG-P015-할인정책삭제확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
