## 기능 목적

센터 내 운동룸(GX룸·PT룸·스피닝룸·필라테스룸 등)의 현황과 예약 슬롯을 관리하는 화면(SCR-053)이다. 각 룸의 운영 상태를 확인하고, 오늘의 시간대별 예약 혼잡도를 시각적으로 파악할 수 있다. 새 운동룸을 등록하거나 기존 룸 정보를 수정·삭제하고, 운영 상태를 빠르게 전환할 수 있다.

운영 맥락:
- **신규 운동룸 도입**: 시설 확장 시 [+ 새 운동룸 등록](DLG-053-001) → GX/PT/스피닝/필라테스 등 유형 분류 + 정원·게이트 입력
- **시설 점검 시 즉시 차단**: ⚙ 버튼으로 운영중 → 점검중 즉시 전환, SCR-C001 캘린더 자동 반영하여 예약 차단
- **고장 룸 격리**: 운영중 → 고장 토글로 신규 예약·진행 모두 차단 + 회원 알림 (FAC-EXT-02 수리 접수 연계)
- **혼잡 시간대 분석**: 오늘 슬롯 바로 시간별 혼잡도 시각 인지, 만석(빨강) 발견 시 추가 룸 운영 검토
- **운동룸 폐지**: 더 이상 사용하지 않는 룸 삭제(DLG-053-002), 사용 중 일정 0건일 때만 가능
- **본사 통합 모드 운영**: 지점별 룸 분리 관리, 본사 슈퍼관리자는 전 지점 룸 통합 조회
- **유형별 필터 운영**: PT룸만 필터하여 PT 강사 배정 회의 (SCR-C006 강사 근무와 연계)

상태 전환·등록·수정·삭제 모두 SCR-097 감사 로그에 기록되며, 상태 변경은 즉시 SCR-C001 캘린더 예약 시스템에 반영된다.

## 주요 UX 흐름

**기본 조회**
1. 사이드바 → "시설관리 > 운동룸 관리" 진입
2. 카드 보기 기본 + 유형별 그룹
3. 유형 필터로 좁히기

**룸 등록**
1. [+ 새 운동룸 등록] → DLG-053-001
2. 정보 입력 → 저장

**룸 수정**
1. 카드 [수정] → DLG-053-001
2. 변경 → 저장

**룸 삭제**
1. 카드 [삭제] → DLG-053-002
2. 사용 중 일정 있으면 차단 → 종료

**상태 전환**
1. 카드 [⚙] 클릭
2. 운영중 → 점검중 → 고장 → 운영중 순환

### 분기·예외 흐름
- **룸명 중복 등록 시도**: 동일 지점 내 룸명 중복 시 인라인 "동일 룸명이 이미 존재합니다" + 저장 차단
- **정원 0 또는 음수 입력**: 인라인 "정원은 1 이상 입력해주세요"
- **삭제 시 사용 중 일정 존재**: 모달 "오늘/이후 예약 N건이 있어 삭제할 수 없습니다. 일정 정리 후 다시 시도하세요" + [예약 화면으로] / [취소]
- **점검중 → 고장 전환 시 진행 중 수업 존재**: 경고 "현재 진행 중인 수업 N건이 있습니다. 강제 종료하시겠어요?" + [강제 종료] / [취소]
- **고장 → 운영중 복구 시 수리 미완료**: 경고 "수리 완료 기록이 없습니다. 그래도 운영중으로 전환하시겠어요?" + 강행 옵션
- **유형 변경(GX → PT) 후 기존 예약 영향**: 경고 "기존 예약 일정에 영향이 있을 수 있습니다" + [계속] / [취소]
- **룸 등록 직후 예약 가능 시점**: 등록 즉시 예약 가능, SCR-C001 캘린더 자동 반영
- **상태 전환 권한 부족**: ⚙ 버튼 hidden 또는 비활성
- **본사 통합 모드 다른 지점 룸 변경 시도**: 권한자 외 차단
- **삭제 후 캘린더 잔여 데이터**: 룸 삭제는 soft delete, 과거 예약 이력은 보존

## 비즈니스 규칙

1. 룸 유형은 GX / PT / 스피닝 / 필라테스 / 기타 5종, 등록 시 단일 선택, 변경 가능(예약 영향 경고).
2. 룸명은 동일 지점 내 고유, 중복 등록 차단.
3. 정원은 1 이상 자연수, 캘린더 예약 시 동시 예약 인원 한도로 사용.
4. 게이트 정보는 옵션, 출입 안내·RFID 매핑(FAC-03)에 활용.
5. 운영 상태는 운영중(operating) / 점검중(maintenance) / 고장(broken) 3종 순환, 미사용 상태는 점검중에 포함.
6. 점검중·고장 상태 룸은 신규 예약 차단, 슬롯 바에 "예약 불가" 표시.
7. 점검중 → 고장 전환 시 진행 중 수업이 있으면 경고 + 강제 종료 옵션 제공.
8. 고장 상태는 빨강 + 사선 강조, 운영중으로 복구 시 수리 완료 기록 권장.
9. 운영 상태 전환은 ⚙ 버튼으로 순환되며, 변경 시 즉시 캘린더(SCR-C001) 및 모든 예약 시스템에 반영된다.
10. 룸 삭제는 사용 중인 일정(오늘 + 미래)이 0건일 때만 가능, soft delete로 과거 이력은 보존.
11. 룸 변경 이력(등록·수정·상태 전환·삭제)은 감사 로그(SCR-097)에 기록된다.
12. 예약 슬롯 바는 SCR-C001 캘린더의 룸별 예약 데이터를 실시간 반영(5초 폴링 또는 이벤트).
13. 슬롯 바 색상: 여유(예약/정원 < 50%) 초록, 혼잡(50~80%) 주황, 만석(80% 이상) 빨강, 빈 시간 회색.
14. 슬롯 바 표시 시간: 07:00~20:00 (테넌트 영업시간 정책으로 변경 가능).
15. 카드 보기 / 목록 보기 전환은 사용자 설정으로 저장 (다음 진입 시 유지).
16. 유형 필터 변경 시 URL 쿼리 동기화로 새로고침 시에도 유지.
17. 권한별 가시성: 슈퍼관리자 / 센터장은 등록·수정·삭제·상태 전환. 매니저는 상태 전환·수정. FC / 스태프 / 프런트는 상태 전환만. 트레이너 / readonly는 조회만.
18. 본사 통합 모드에서는 지점별 룸 분리 운영, 슈퍼관리자만 통합 조회.
19. 룸 정원 변경 후 기존 예약이 신정원 초과하면 운영자에게 경고 + 별도 조정 가이드.
20. 상태 전환 시 회원 알림: 진행 중 수업 강제 종료 시 회원에게 NFR-19 알림 자동 발송.
21. 룸 등록 직후 예약 가능 (캘린더 자동 반영, 별도 활성화 불필요).
22. 룸 삭제 후 같은 룸명 재등록은 허용 (soft delete 후 신규 등록).

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `FAC-04`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-053`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-053-001 룸등록수정, DLG-053-002 룸삭제확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
