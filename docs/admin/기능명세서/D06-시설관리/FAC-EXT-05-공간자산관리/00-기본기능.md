## 기능 목적

룸과 골프 타석 같은 공간 자산을 통합 운영하는 화면(SCR-059)이다. 운영자가 공간 자산의 사용 상태와 예약 상황을 카드 단위로 즉시 파악하고, 상태 변경·예약 현황을 한 곳에서 확인할 수 있다. 운동룸 관리(FAC-04)와 골프 타석 관리(FAC-05)의 상위 통합 뷰로 작동한다.

운영 맥락:
- **통합 자산 한 화면 조회**: 룸 + 타석을 한 화면 카드 그리드로 조회, 상태 색상 즉시 인식
- **운영자 빠른 상태 변경**: 카드 [상태 변경] → 사용중/대기/점검/고장 토글 + 사유 입력 → 캘린더 자동 반영
- **자산별 예약 현황 빠른 확인**: 자산 카드 클릭 → 우측 패널에 오늘 + 이번 주 예약 일정
- **점검 시 즉시 차단**: 점검·고장 전환 시 신규 예약 차단 + 회원 알림 (FAC-04·FAC-05 동기화)
- **전체 가동 현황 시각화**: 색상으로 자산 가동률 즉시 인지 (사용중·대기·점검·고장)
- **자산 등록 통합 인터페이스**: 룸 또는 타석 추가 등록 (각 도메인 등록 화면으로 라우팅)
- **본사 통합 모드 운영**: 지점별 자산 분리, 슈퍼관리자만 통합 조회
- **혼잡 시간대 분석**: 사용중 자산 비율 모니터링 → 추가 자산 도입 또는 시간대 조정 결정

상태 변경·등록·삭제 모두 SCR-097 감사 로그에 기록되며, 상태 변경은 FAC-04 운동룸 / FAC-05 골프 타석 / SCR-C001 캘린더에 즉시 동기화된다.

## 주요 UX 흐름

**기본 조회**
1. 사이드바 → "시설관리 > 공간 자산 관리" 진입
2. 자산 카드 그리드 한 화면 표시
3. 상태 색상으로 즉시 인식

**상태 변경**
1. 자산 카드 [상태 변경] 클릭
2. 상태 선택 → 사유 입력 → 저장
3. 캘린더(SCR-C001) 자동 반영

**예약 현황 확인**
1. 자산 카드 클릭 → 우측 패널
2. 오늘 + 이번 주 예약 일정 표시

### 분기·예외 흐름
- **사용중 자산 점검·고장 전환 시 진행 일정**: 경고 "현재 진행 중인 일정 N건이 있습니다. 강제 종료하시겠어요?" + [강제 종료] / [취소]
- **상태 변경 사유 미입력**: 인라인 "변경 사유를 입력해주세요" + 저장 차단
- **고장 → 사용중 복구 시 수리 미완료**: 경고 "수리 완료 기록이 없습니다" + 강행 옵션
- **자산 삭제는 본 화면에서 차단**: "자산 삭제는 운동룸 관리(FAC-04) 또는 골프 타석 관리(FAC-05)에서 처리하세요" 안내
- **자산 등록 라우팅**: 룸 → FAC-04 / 타석 → FAC-05 등록 화면으로 이동
- **권한 부족 상태 변경 시도**: 버튼 hidden 또는 비활성
- **본사 통합 모드 다른 지점 변경**: 권한자 외 차단
- **상태 변경 시 캘린더 동기화 실패**: 토스트 "캘린더 반영 실패, 재시도 중" + 자동 재시도
- **강제 종료 알림 발송 실패**: 종료는 성공, 알림은 NFR-19 재시도 큐 등록
- **예약 패널 데이터 로딩 실패**: "예약 정보를 불러올 수 없습니다" + 재시도

| 사용중 | 파랑 카드 |

## 비즈니스 규칙

1. 본 화면은 운동룸(FAC-04)과 골프 타석(FAC-05)의 상위 통합 뷰로 두 도메인 데이터를 모두 표시한다.
2. 자산 유형은 룸(GX/PT/스피닝/필라테스/기타) + 타석 (단일 카테고리), 카드에 유형 배지 표시.
3. 자산 상태는 사용중(in_use) / 대기(available) / 점검(maintenance) / 고장(broken) 4종 통일.
4. 상태 변경은 즉시 캘린더(SCR-C001) + 예약 시스템 + 원 도메인(FAC-04/FAC-05) 모두 동기화.
5. 점검·고장 상태 자산은 신규 예약을 받지 못한다.
6. 사용중 자산 점검·고장 전환 시 진행 중 일정 경고 + 강제 종료 옵션 (FAC-04와 동일 흐름).
7. 강제 종료 시 회원에게 NFR-19 알림 자동 발송.
8. 상태 변경 시 사유 입력 필수, 사유는 감사 로그에 기록.
9. 카드 단위에서 상태가 즉시 읽혀야 한다는 퍼블리싱 포인트를 따른다 (색상 구분 명확).
10. 자산 등록은 본 화면에서 시작, 유형(룸/타석) 선택 후 해당 도메인 등록 화면으로 라우팅.
11. 자산 삭제는 본 화면에서 차단, 원 도메인(FAC-04/FAC-05)에서만 처리.
12. 예약 현황 패널은 오늘 + 이번 주 일정 표시, SCR-C001 캘린더 데이터 실시간 반영(5초 폴링).
13. 권한별 가시성: 슈퍼관리자 / 센터장 / 매니저는 등록·상태 변경. FC / 스태프는 상태 변경(룸·타석 한정). 트레이너 / readonly는 조회만.
14. 본사 통합 모드는 지점별 자산 분리 운영, 슈퍼관리자만 통합 조회 가능.
15. 모든 등록·상태 변경 처리는 감사 로그(SCR-097)에 actor·asset_id·asset_type·before-after·reason 기록.
16. 카드 색상 우선순위: 고장 > 점검 > 사용중 > 대기.
17. 자산명·유형·상태 필터링 지원 (URL 쿼리 동기화로 새로고침 시 유지).
18. 자산 카드 클릭 vs 상태 변경 버튼 클릭 분리: 카드 = 예약 패널, [상태 변경] 버튼 = 모달.
19. 본 화면에서 변경된 상태는 FAC-04 / FAC-05에 반영되며 동시 편집 시 마지막 저장이 우선.
20. 가동률 표시 옵션: 카드 그리드 상단에 전체 가동률(사용중 / 전체) 카드 표시 (테넌트 정책).
21. 강제 종료 권한: 매니저+ 권한만 강제 종료 가능, 그 외는 일반 점검 토글만 가능.
22. 회원에게 영향 있는 상태 변경(점검·고장)은 진행 중 회원에게 자동 알림 발송.

- **API 기준**: `GET /api/space-assets` / `POST /api/space-assets/:id/status` / `GET /api/space-assets/:id/reservations` / `GET /api/space-assets/utilization` / `POST /api/space-assets/:id/force-end`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `FAC-EXT-05`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-059`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
