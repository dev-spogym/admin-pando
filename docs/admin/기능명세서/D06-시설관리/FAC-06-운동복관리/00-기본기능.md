## 기능 목적

센터에서 회원에게 대여하는 운동복의 재고 현황과 대여·반납·세탁·파손 상태를 관리하는 화면(SCR-055)이다. QR 코드 스캔으로 대여와 반납을 빠르게 처리할 수 있으며, 운동복별 현재 상태와 대여 이력을 한눈에 파악할 수 있다.

운영 맥락:
- **회원 입장 시 빠른 대여**: QR 스캐너로 운동복 코드 스캔 → 회원 검색 → [대여 확정] 1초 처리
- **회원 반납 시 자동 세탁 전환**: QR 스캔 반납 → 운동복 상태 자동 "세탁중" 전환
- **세탁 완료 후 재투입**: 세탁중 행 [세탁 완료] → 대기 상태로 즉시 전환
- **파손 운동복 격리**: 행 [파손] → 대여 차단, 후속 폐기 또는 [복구]로 재투입
- **회원 1인당 대여 한도**: 정책에 따라 1인당 동시 대여 1세트 또는 N세트 제한
- **반납 예정일 초과 회수**: 반납 예정일 경과 시 알림 + 운영자 안내
- **사이즈별 재고 부족**: 인기 사이즈(M·L) 재고 부족 시 발주 권유
- **운동복 신규 등록**: 신규 도입 시 번호·사이즈·타입 입력, QR 자동 생성
- **본사 통합 모드 운영**: 지점별 운동복 분리, 본사 슈퍼관리자만 통합 조회

대여·반납·상태 변경·등록·삭제 모두 SCR-097 감사 로그에 기록되며, 반납 예정일 초과·파손 처리는 NFR-19 알림으로 회원·운영자에게 자동 발송된다.

## 주요 구성요소

### 현황 요약 카드 (4개)

| 카드 | 내용 |
|------|------|
| 전체 운동복 수 | 합계 |
| 대기(사용 가능) | available |
| 대여중 | rented |
| 세탁중 | washing |

전체 / 대기 / 대여중 / 세탁중 / 파손 (각 탭 카운트 배지).

### 검색창

운동복 번호 또는 대여 회원명.

### 운동복 목록 테이블

| 컬럼 | 설명 |
|------|------|
| 번호 | 운동복 번호 |

| 타입 | 상의/하의/세트 |
| 상태 배지 | 대기/대여중/세탁중/파손 |

## 주요 UX 흐름

**QR 대여**
1. 사이드바 → "시설관리 > 운동복 관리" 진입
2. [QR 스캔] → 코드 입력
3. 빈 운동복 조회 → 회원 검색 → [대여 확정]

**QR 반납**
1. [QR 스캔] → 코드 입력
2. 대여중 운동복 → [반납 처리]

**상태 직접 변경**
1. 행 액션 버튼 클릭 → 즉시 상태 변경

**운동복 등록**
1. [운동복 등록] → 번호·사이즈·타입 입력
2. 저장 → 목록 추가

### 분기·예외 흐름
- **QR 코드 미인식**: "해당 QR 코드의 운동복을 찾을 수 없습니다" + 수동 검색 안내
- **이미 대여중인 운동복 QR 스캔(대여 시)**: "해당 운동복은 이미 [회원명]에게 대여 중입니다" + 차단
- **반납 시 대여중 아닌 운동복 QR 스캔**: "대여중 상태가 아닙니다 (현재: [상태])" + 반납 차단
- **파손 운동복 대여 시도**: 클릭 차단 + "파손 운동복은 대여 불가, 복구 후 사용하세요"
- **회원 1인당 대여 한도 초과**: "해당 회원은 이미 N세트 대여 중입니다 (한도 [N])" + 차단
- **회원 검색 0건**: "검색 결과가 없어요" + 회원 등록 안내
- **세탁중 → 대여 시도**: 세탁 완료 후에만 대여 가능, 클릭 시 안내
- **번호 중복 등록**: 인라인 "동일 번호가 이미 존재합니다" + 저장 차단
- **반납 예정일 초과 미반납**: 회원에게 알림 + 운영자 목록 상단 강조
- **상태 직접 변경 권한 부족**: 액션 버튼 hidden 또는 비활성
- **본사 통합 모드 다른 지점 변경**: 권한자 외 차단

## 비즈니스 규칙

1. 운동복 번호는 시스템 내 고유, 중복 등록 차단 (UNIQUE 제약).
2. QR 코드는 운동복별 고유값으로 등록 시 자동 생성, 인쇄 후 운동복 부착.
3. 사이즈는 S / M / L / XL / XXL 5종, 타입은 상의 / 하의 / 세트 3종.
4. 운동복 상태는 대기(available) / 대여중(rented) / 세탁중(washing) / 파손(damaged) 4종.
5. 대여 시 반납 예정일은 정책 기본값으로 자동 설정 (당일 22:00 또는 +1일), 변경 가능.
6. 반납 시 운동복 상태는 자동 "세탁중"으로 전환, 운영자 직접 [세탁 완료] 처리 시 대기로 복귀.
7. 파손 처리된 운동복은 [복구] 액션으로 재사용 가능, 폐기는 별도 삭제 처리.
8. 회원 1인당 동시 대여 개수: 1세트(기본) / N세트(테넌트 정책). 초과 시 대여 차단.
9. QR 스캔 대여: 빈 운동복 QR + 회원 검색 + [대여 확정] 트랜잭션 단건 처리.
10. QR 스캔 반납: 대여중 운동복 QR + [반납 처리] → 상태 자동 세탁중 전환.
11. 반납 예정일 초과 미반납 시 HQ-09 반납 초과 정책 step + 해당 지점 ON 상태 기준으로 회원에게 NFR-19 알림 발송.
12. 상태 변경 시 액션 버튼은 현재 상태에 맞는 옵션만 노출 (대기→[세탁]/[파손], 대여중→[반납]/[세탁], 세탁중→[세탁 완료], 파손→[복구]).
13. 권한별 가시성: 슈퍼관리자 / 센터장 / 매니저는 등록·삭제·QR·상태 모든 액션. FC / 스태프는 QR 대여·반납·상태 변경 가능, 등록 불가. 트레이너 / readonly는 조회만.
14. 본사 통합 모드는 지점별 운동복 분리 운영, 슈퍼관리자만 통합 조회.
15. 모든 대여·반납·상태 변경·등록·삭제 처리는 감사 로그(SCR-097)에 actor·clothing_id·member_id·before-after 기록.
16. 검색은 운동복 번호 정확 매치 또는 회원명 부분 매치, 디바운스 300ms.
17. 상태 탭 변경 시 즉시 결과 갱신, URL 쿼리 동기화.
18. 엑셀 다운로드: 현재 적용된 탭·검색 결과, 파일명 `운동복현황_지점_YYYYMMDD.xlsx`.
19. QR 스캐너 미연결 시 수동 번호 입력 가능, 상단에 스캐너 연결 상태 배지 노출.
20. 파손 처리 시 운영자에게 [폐기 처리] 옵션 안내 (폐기는 영구 삭제).
21. 사이즈별 재고 통계는 카드 또는 부가 패널로 노출, 부족 사이즈 알림.
22. 대여 이력은 운동복별로 보관(누가 언제 빌리고 반납했는지), 90일 이상 유지.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `FAC-06`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-055`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
