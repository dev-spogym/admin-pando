## 기능 목적

센터 내 운동 장비의 정기 점검 일정과 수리 이력을 관리하는 화면(SCR-056)이다. 장비별로 다음 점검 예정일을 설정하고, 점검 완료 후 결과를 기록하며, 고장·수리 접수부터 완료까지의 이력을 추적한다. 점검이 지연되거나 수리가 필요한 장비를 한눈에 파악해 시설 안전을 유지한다.

운영 맥락:
- **신규 장비 도입**: [장비 등록] → 장비명·유형·위치·점검 주기 입력 → 첫 점검 예정일 자동 설정
- **정기 점검 진행**: 점검 예정일 도래 시 운영자에게 알림 → [점검 등록] → 결과 기록
- **점검 완료 후 다음 예정일 자동 갱신**: 점검 주기에 따라 다음 예정일 자동 산정
- **회원 신고로 수리 접수**: 장비 고장 신고 → [수리 접수] → 증상·담당자·예상 완료일 입력
- **수리 완료 후 정상 복구**: 수리 완료 처리 → 정상 운영 상태 복귀
- **점검 기한 초과 강조**: 예정일 경과 장비 빨강 + 경고 강조, 즉시 조치 유도
- **고장 장비 사용 차단**: 고장 상태 장비는 회원에게 "사용 금지" 안내 표시
- **본사 통합 모드 운영**: 지점별 장비 분리, 슈퍼관리자만 통합 조회
- **운동룸 / 골프 타석 연계 고장**: FAC-04·FAC-05에서 고장 토글 시 수리 접수 자동 등록 옵션

장비 등록·점검·수리·삭제 모두 SCR-097 감사 로그에 기록되며, 점검 임박·기한 초과·수리 완료는 NFR-19 알림으로 운영자에게 자동 발송된다.

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin | 전체 장비 + 이력 | 등록·수정·삭제·점검·수리 |
| owner (센터장) | 전체 장비 + 이력 | 등록·수정·삭제·점검·수리 |
| manager | 전체 장비 + 이력 | 점검·수리 (삭제 불가) |
| fc / 스태프 | 장비 목록 + 이력 | 점검 완료 기록 |
| 트레이너 / readonly | 현황 조회 | 변경 불가 |

## 주요 UX 흐름

**기본 조회**
1. 사이드바 → "시설관리 > 장비 점검 일정" 진입
2. 다음 점검 예정일 기준 정렬
3. 임박 장비 우선 확인

**점검 등록**
1. 행 [점검 등록] → DLG-056-002
2. 점검 결과·다음 예정일 입력
3. 저장 → 상태 갱신

**수리 접수**
1. 행 [수리 접수] → DLG-056-003
2. 증상·담당자 입력 → 상태 "수리중"
3. 수리 완료 → 정상 복구

### 분기·예외 흐름
- **장비명 중복 등록**: 동일 지점·동일 위치 내 장비명 중복 시 인라인 "동일 장비명이 존재합니다" + 저장 차단
- **점검 주기 미선택**: 인라인 "점검 주기를 선택해주세요" + 저장 차단
- **다음 점검 예정일 과거 입력**: 인라인 "과거 일자 불가" + 저장 차단
- **수리중 장비 재수리 접수**: "이미 수리중 상태입니다" + 차단 또는 추가 메모 옵션
- **수리 완료 처리 시 미입력 필드**: 인라인 "수리 결과를 입력해주세요" + 저장 차단
- **점검 기한 초과 + 사용 차단 안내**: 회원 시설 이용 시 안내 + 운영자 알림
- **삭제 시 점검 이력 존재**: 삭제 가능, 이력은 영구 보존(soft delete)
- **점검 주기 변경 시 다음 예정일 영향**: 변경 시 다음 예정일 재산정 안내
- **수리 담당자 없음**: 담당자 검색 0건 시 "직원을 등록 후 다시 시도하세요" 안내
- **본사 통합 모드 다른 지점 변경**: 권한자 외 차단

## 비즈니스 규칙

1. 장비 상태는 정상(normal) / 점검 예정(due) / 수리중(repair) / 고장(broken) 4종.
2. 점검 주기는 월간 / 분기(3개월) / 반기(6개월) / 연간 4종, 등록 시 단일 선택.
3. 다음 점검 예정일이 7일 이내인 장비는 자동 "점검 예정" 상태로 표시 + 알림 발송.
4. 점검 기한 초과(예정일 < 오늘) 장비는 빨강 + "기한 초과" 경고 강조, 즉시 조치 유도.
5. 수리중·고장 장비는 회원 사용 차단 안내 표시 + 운영자에게 알림.
6. 점검 완료 시 다음 점검 예정일이 점검 주기에 따라 자동 갱신 (예: 월간 → +30일).
7. 점검 결과는 정상 / 경미한 이상 / 수리 필요 3종 + 자유 메모.
8. 수리 접수 시 증상·담당자·예상 완료일 필수 입력, 담당자는 직원 검색.
9. 수리 완료 처리 시 수리 결과·소요 시간·비용 입력 가능.
10. 장비명 + 위치(룸·층) 조합은 동일 지점 내 고유, 중복 등록 차단.
11. 점검·수리 이력은 영구 보관, 90일 초과 조회는 별도 분석 화면.
12. 장비 삭제는 manager+ 권한, soft delete로 이력 보존.
13. 점검 주기 변경 시 다음 예정일 재산정 안내, 운영자 확인 후 적용.
14. FAC-04 운동룸·FAC-05 골프 타석 고장 토글 시 수리 접수 자동 등록 옵션 (테넌트 정책).
15. 권한별 가시성: 슈퍼관리자 / 센터장은 등록·수정·삭제·점검·수리. 매니저는 점검·수리 가능, 삭제 불가. FC / 스태프는 점검 완료 기록만. 트레이너 / readonly는 조회만.
16. 본사 통합 모드는 지점별 장비 분리 운영, 슈퍼관리자만 통합 조회.
17. 모든 등록·수정·점검·수리·삭제 처리는 감사 로그(SCR-097)에 actor·equipment_id·before-after 기록.
18. 점검 임박 알림: 점검 예정일 D-7 / D-3 / D-1, 기한 초과 시 추가 알림.
19. 수리 완료 후 정상 복구 시 다음 점검 예정일은 기존 주기 유지 (수리는 점검과 별개).
20. 검색은 장비명·위치·점검자 다중 검색, 디바운스 300ms.
21. 강조 색상 우선순위: 고장 > 기한 초과 > 수리중 > 점검 예정 > 정상.
22. 엑셀 다운로드: 검색·필터 결과, 파일명 `장비점검현황_지점_YYYYMMDD.xlsx`.

- **연계 다이얼로그**: DLG-056-001 장비등록 / DLG-056-002 점검등록 / DLG-056-003 수리등록
- **API 기준**: `GET /api/equipment` / `POST /api/equipment` / `PUT /api/equipment/:id` / `DELETE /api/equipment/:id` / `POST /api/equipment/:id/inspection` / `POST /api/equipment/:id/repair` / `POST /api/equipment/:id/repair-complete` / `GET /api/equipment/:id/history` / `GET /api/equipment/export`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `FAC-EXT-02`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-056`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-056-001 장비등록, DLG-056-002 점검등록, DLG-056-003 수리등록`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
