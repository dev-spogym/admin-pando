## 기능 목적

회원이 실제 계약금·잔액·할부 등 계약상 납입 의무를 완료하지 못한 미수금을 추적하고 관리하는 화면이다. 미결제·일부결제·연체·완료 상태를 탭으로 구분해 현황을 파악하고, 납입이 이루어지면 상태를 직접 변경한다. 결제링크 발송만 된 건은 계약금이나 계약상 미수금이 아니므로 PAY-03 원장에 생성하지 않는다. 결제링크 결제 전 상태는 회원상세 결제내역과 PAY-06 결제링크 상태로만 표시한다.

운영 맥락:
- **카운터 매니저 일일 미수 회수**: 매일 출근 후 연체 탭 확인 → 회원 연락 → 납입처리 (DLG-S008)
- **FC 본인 담당 회원 미수 추적**: 회원명 검색 → 미수금 발생 유형 확인 → 계약금 잔액/수기 분할/정기 할부 미납이면 직접 결제 권유
- **센터장 월말 미수 점검**: 미수금 총액·본사 정책 기준 연체 알림 대상 건수 카드 확인 → HQ-09 미수/연체 운영자 알림 대상은 운영팀 회수 작업
- **본사 슈퍼관리자 지점별 회수율 모니터링**: 통합 모드에서 지점별 미수금 총액·회수율 비교 → 운영 점검
- **결제링크 후속 제외**: 결제링크 재발송·무효화·새 링크 생성은 회원상세 결제내역 또는 PAY-06에서 처리
- **수기 분할 납부 회원**: 매월 입금일에 매니저가 입금 확인 후 납입처리, 메모에 입금 일자/금액 기록
- **할부 미납 자동 동기화**: SAL-EXT-01 할부 회차 미납 → PAY-03에 자동 등록, 회수 시 양쪽 자동 갱신
- **연체 자동 독촉 (NFR-05)**: HQ-09 `결제기한 만료` 본사 정책 step + 지점 ON 상태 기준으로 자동 알림을 발송한다. 미수/연체 알림의 N일 기준, 반복 주기, 발송 시각, 기본 채널은 본사(superAdmin/primary)가 HQ-09 정책 세트에서 설정해 지점에 배포한다. 지점은 ON/OFF만 가능하고 지점 추가 step은 허용하지 않는다.
- **회원 연락 메모**: DLG-S005 메모 편집으로 독촉 통화 / 약속 일자 기록 → 다음 담당자에게 인수인계

HQ-09 미수/연체 운영자 알림 대상 건은 별도 집계 카드 + 빨강 강조로 즉시 식별된다.

### 미수금 최초 생성 기준

PAY-03 화면에서는 미수금 건을 직접 신규 생성하지 않는다. 최초 생성은 결제 처리(PAY-01)의 계약금 등록/잔액 발생, 수기 분할 선택, 할부 관리(SAL-EXT-01) 회차 미납 이벤트에서 자동 등록된다. 결제링크 발송만 된 건은 미수금으로 생성하지 않는다. `수기 분할`은 PAY-01 계약금 등록 시 잔액을 정기 할부 계획 없이 운영자가 직접 회수하기로 선택한 경우 생성되는 비정형 미수 유형이며, PAY-03에서는 납입처리·상태 변경·메모 관리만 수행한다.

### 상태 변경

현재 상태에 따라 전환 가능한 다음 상태만 노출 (미결제→일부결제·완료, 일부결제→완료, 연체→일부결제·완료, 완료→변경 불가).

### 메모 편집 (DLG-S005)

메모 버튼 클릭 → 모달 → 즉시 저장.

### 결제링크 후속 액션 제외

결제링크 발송만 된 건은 PAY-03 미수금 원장에 생성하지 않는다. 결제링크 재발송·무효화·새 링크 생성은 회원상세 결제내역 또는 PAY-06 결제링크 상태 영역에서 처리한다.

### 엑셀 내보내기

현재 탭/검색 조건 적용 목록 다운로드.

## 주요 UX 흐름

### 일일 미수 회수 흐름
1. 사이드바 "매출관리 > 미수금 관리" 진입
2. 상단 지표 카드로 미수 총액·연체 파악
3. 연체 탭 선택 → 본사 정책 기준 연체 알림 대상 회원 목록
4. 회원명 클릭 → 회원 카드(SCR-M004) 진입 → 연락
5. 납입 시 [납입처리] → DLG-S008 → 입금일·금액 입력
6. 상태 "일부결제" 또는 "완료"로 전환 + 메모 기록

### 결제링크 후속 흐름
1. PAY-03 미수금 원장에는 결제링크 발송 건을 표시하지 않는다.
2. 회원상세 결제내역에서 `미결제/발송됨` 결제링크 행을 확인한다.
3. 활성 링크는 [재발송] 또는 [결제링크 무효화]만 허용한다.
4. 만료/무효화 상태에서는 [결제링크 발송]으로 새 DLG-S016을 연다.
5. 회원 결제 완료 webhook → SCR-S001 반영 + 이용권 즉시 활성화

### 분기·예외 흐름
- **상태 전환 가능 목록 (현재 상태별)**: 미결제 → 일부결제·완료 / 일부결제 → 완료 / 연체 → 일부결제·완료 / 완료 → 변경 불가
- **납입처리 시 미수금 < 입금액**: "입금액이 미수금을 초과합니다" + 입금액 정정 안내
- **결제링크 활성 1개 제한**: 활성 링크 있을 때 새 링크 생성 시도 → "이미 발송된 결제링크가 있습니다" 안내 후 재발송 또는 무효화 안내
- **할부 미납 자동 등록**: SAL-EXT-01 회차 미납 → PAY-03에 자동 INSERT, 회수 시 양쪽 자동 갱신
- **결제기한 만료 정책 step 자동 알림**: NFR-05는 매일 04:00 대상 산출 후 HQ-09 본사 정책 step의 발송 시각에 알림을 발송한다. 미수/연체 알림 N일, 반복 주기, 발송 시각, 기본 채널은 본사 설정값을 따르며 지점별 발송 여부는 센터장(owner)이 SCR-072에서 ON/OFF한 상태를 따른다. 지점 추가 step은 제공하지 않는다.
- **HQ-09 미수/연체 운영자 알림**: HQ-09 결제기한 만료 본사 step에서 설정한 N일·발송 시각에 운영자에게 미수/연체 회원을 일괄 알림한다.
- **회원 탈퇴 후 미수**: 탈퇴 회원도 미수금은 유지 (회수 추진 가능), 단 회원 카드 진입 차단
- **본사 통합 모드**: 전 지점 미수금 통합 조회, 지점별 컬럼 추가
- **동시 납입처리 충돌**: row-level lock으로 이중 차감 방지

## 비즈니스 규칙

1. **발생 유형 3종 관리**: 계약금 잔액 / 수기 분할 / 정기 할부 미납을 미수금 원장으로 관리한다.
1-1. **신규 생성 위치**: PAY-03은 미수금 신규 등록 화면이 아니며, 최초 생성은 PAY-01 계약금 등록/잔액 발생, 수기 분할 선택, SAL-EXT-01 할부 회차 미납 이벤트에서만 자동 등록된다. 결제링크 발송만 된 건은 미수금으로 생성하지 않는다.
1-2. **수기 분할 정의**: `수기 분할`은 PAY-01에서 잔액을 정기 할부 계획 없이 직접 회수하기로 선택했을 때 생성되는 단일 미수 건이다. 회차는 별도 엔티티로 만들지 않고 메모에 기록한다.
2. **연체 정의**: 납입기한이 지난 미수금이며, 화면 경고·알림 대상 N일 기준은 HQ-09 `결제기한 만료` 본사 정책 step 값을 따른다. 별도 집계 + 경고 강조.
3. **상태 전환 규칙**: 미결제 → 일부결제·완료 / 일부결제 → 완료 / 연체 → 일부결제·완료 / 완료 → 변경 불가.
4. **납입처리 입금액 검증**: 입금액 ≤ 미수금 잔액. 초과 시 차단.
5. **부분 입금 시 상태**: 미수금 일부 입금 시 "일부결제" 자동 전환, 잔액 미수금 유지.
6. **결제링크 후속 분리**: 동일 결제 건의 활성 링크 1개 제한, 재발송, 무효화, 새 링크 생성은 PAY-06에서 처리한다. PAY-03은 결제링크 상태를 미수금으로 관리하지 않는다.
7. **결제기한 만료 정책 step 자동 알림 (NFR-05)**: 결제 기한 기준 D-N/D+N 알림일, 반복 주기, 발송 시각, 기본 채널은 HQ-09 `결제기한 만료` 본사 정책값을 따른다. 해당 지점에서 센터장(owner)이 ON으로 둔 step만 회원·운영자에게 발송한다. 결제기한 만료는 지점 추가 step을 허용하지 않는다.
7-1. **결제링크 예외**: 결제링크 발송 건은 PAY-03 미수금이 아니므로 결제기한 만료 정책 대상이 아니다. PAY-06 결제링크는 링크 7일 고정, D-3/D-1 고정 알림을 사용한다.
8. **HQ-09 미수/연체 운영자 알림**: HQ-09 결제기한 만료 본사 step에서 설정한 N일·발송 시각에 운영자에게 미수/연체 회원을 일괄 알림한다.
9. **할부 미납 동기화**: SAL-EXT-01 회차 미납 시 PAY-03에 자동 INSERT, 한쪽 회수 시 양쪽 자동 갱신.
10. **메모 변경 이력**: 메모 변경 이력은 감사 로그(SCR-097)에 기록.
11. **권한별 가시성**: FC는 담당 회원만, 트레이너·스태프는 조회만.
12. **본사 통합 모드**: 본사 슈퍼관리자만 전 지점 통합 조회.
13. **회원 탈퇴 후 미수**: 탈퇴 회원도 미수금은 유지, 회원 카드 진입 차단.
14. **납입처리 동시성 락**: 동일 미수 건에 대한 동시 납입처리는 row-level lock으로 직렬화.
15. **회수액 카드 갱신**: 이번 달 회수액은 매일 04:00 집계, 실시간 회수 시 즉시 추가.
16. **결제링크 재발송 유효성**: 결제링크 재발송은 회원상세/PAY-06에서 처리하며 만료일시 갱신 없이 동일 링크를 재전송한다.
17. **새 링크 생성 시 기존 무효화**: 새 링크 생성은 기존 활성 링크를 사유 입력 후 무효화한 뒤에만 가능하다.
18. **엑셀 다운로드**: 현재 탭/검색 조건 기준 전체 데이터, 30,000건 초과 시 비동기.
19. **감사 로그**: 상태 변경·납입처리·메모 편집 모두 SCR-097 기록.
20. **반복 미수 회원 알림**: 동일 회원 3회 이상 미수 발생 시 운영자에게 알림.
21. **수기 분할 회차 입력**: 수기 분할은 회차 정보 없이 단일 미수 건으로 관리, 메모에 회차 기록.
22. **회원 연락처 변경 시 링크 재발송**: 회원 연락처 변경 후 미발송 링크는 새 연락처로 자동 갱신.
23. **결제 기한 변경**: 결제 기한 연장은 운영자(센터장+) 권한, 변경 이력 감사 로그 기록.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-S008`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-S005 메모편집, DLG-S008 납입처리`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 표와 아래 API 기준을 같이 적용합니다.

- **연계 화면**: SCR-S001 / SCR-S009 할부 / SCR-S012 결제 취소 / PAY-06 결제링크 / SCR-M004 회원 카드 / SCR-097 감사 로그
- **연계 다이얼로그**: DLG-S005 / DLG-S008
- **API 기준**: `GET /api/unpaid` / `PUT /api/unpaid/:id/status` / `POST /api/unpaid/:id/payment` / `POST /api/payment-links/:id/resend` / `POST /api/payment-links/:id/expire` / `GET /api/unpaid/export`
