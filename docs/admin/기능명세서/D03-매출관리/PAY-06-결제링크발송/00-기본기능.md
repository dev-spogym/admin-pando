## 기능 목적

현장에서 확정한 상품·금액·할인 조건으로 회원이 직접 결제할 수 있는 결제링크를 발송하는 기능이다. 결제 처리 화면(SCR-S003)에서 수납 방식을 `결제링크 발송`으로 선택하면 DLG-S016 다이얼로그가 열리고, 운영자는 발송 채널·만료일을 확인한 후 SMS 또는 카카오톡으로 결제링크를 보낸다. 회원은 링크에서 결제수단만 선택할 수 있으며 금액·상품 구성은 수정할 수 없어 현장 합의 그대로 결제가 진행된다. 회원앱 측에서는 MA-140 결제링크 화면이 비편집 모드로 동작한다.

## 주요 구성요소

### 회원 정보 영역

| 항목 | 표시 |
|------|------|
| 수신 회원 이름 | 자동 채움 |
| 연락처 | 010 자동 포맷 |
| 앱 연결 여부 | "회원앱 설치됨" / "미설치" |

### 결제 요약 영역

| 항목 | 설명 |
|------|------|
| 상품명 | 현장 확정 상품 |
| 수량 | 단일 / 다중 |
| 정가 | 천 단위 콤마 |
| 할인 | 할인 금액 + 사유 |
| 최종 결제 금액 | 정가 - 할인 |
| 잔액 여부 | 계약금/잔액 안내 |

### 발송 채널 선택

| 채널 | 사용 조건 |
|------|----------|
| SMS | 연락처 유효 시 기본 |
| 카카오톡 | 카카오 채널 친구·앱 연결 시 활성 |

### 링크 만료일시

발송 시점 + 7일로 고정 표시. 만료일 이후 결제 불가.

### 내부 메모

상담 메모, 발송 사유, 특이사항 textarea. 내부 관리용으로 회원에게 노출되지 않음.

### 활성 링크 처리

동일 원결제 기준 활성 링크가 이미 있을 경우.

| 옵션 | 동작 |
|------|------|
| 같은 링크 재발송 | 기존 링크 그대로 재전송 |
| 강제 만료 후 새 링크 | 기존 링크 만료 → 새 링크 생성 |

### 발송 / 취소 버튼

- [발송]: 입력값 검증 → 채널 발송 → 상태 "발송됨" 갱신
- [취소]: 발송 없이 이전 화면(SCR-S003) 복귀

### 발송 결과 처리

| 결과 | 동작 |
|------|------|
| 발송 성공 | 토스트 + SCR-S003 복귀 + 상태 "발송됨" |
| 연락처 무효 | 인라인 에러 |
| 채널 사용 불가 | 다른 채널 자동 추천 |
| 발송 실패 | 토스트 + 재시도 |

## 주요 UX 흐름

**신규 결제링크 발송**
1. SCR-S003 결제 처리에서 상품·할인·금액 확정
2. 수납 방식 → "결제링크 발송" 선택
3. DLG-S016 다이얼로그 오픈
4. 회원 정보·결제 요약·만료일 확인
5. 채널 선택 (SMS / 카카오톡)
6. 내부 메모 입력 (선택)
7. [발송] → 검증 → 발송 → 상태 "발송됨"
8. SCR-S003 복귀

**활성 링크 재발송**
1. SCR-S003에서 "결제링크 발송" 재선택
2. DLG-S016 → 활성 링크 감지 안내
3. "같은 링크 재발송" 또는 "강제 만료 후 새 링크" 선택
4. [발송] → 처리

**회원 측 결제**
1. 회원이 SMS/카톡 링크 클릭
2. 회원앱 MA-140 결제링크 화면 (비편집)
3. 결제수단 선택 → PG 결제
4. 결제 완료 webhook → 매출 자동 반영

## 비즈니스 규칙

1. 링크 발송 후 상품·할인·최종 금액을 수정할 수 없다 (현장 합의 보호).
2. 동일 원결제 기준 활성 링크는 1개만 유지하며, 활성 링크가 있으면 같은 링크만 재발송할 수 있다.
3. 운영자는 활성 링크를 수동 만료 또는 취소할 수 있고, 그 이후에만 새 링크를 생성할 수 있다.
4. 링크 만료 후에는 새 링크를 발송해야 하며 만료된 링크는 재사용하지 않는다.
5. 회원 연락처가 없거나 유효하지 않으면 발송할 수 없다.
6. 만료일은 발송 시점 + 7일로 고정한다.
7. 회원앱 MA-140은 비편집 모드로 결제수단만 선택 가능하다.
8. 결제 완료 시 webhook을 통해 SCR-S001 매출현황·결제 건에 자동 반영되고 감사 로그에 기록된다.
9. 결제 미완료 상태에서 환불(SCR-S012)이 아닌 링크 취소로 처리한다.
