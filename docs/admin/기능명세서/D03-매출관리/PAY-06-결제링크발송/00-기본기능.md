## 기능 목적


현장에서 확정한 상품·금액·할인 조건으로 회원이 직접 전액 결제할 수 있는 결제링크를 발송하는 기능이다. 결제링크는 계약금/잔액/할부 수납에 사용하지 않는다. 결제 처리 화면(SCR-S003)에서 수납 방식을 `결제링크 발송`으로 선택하면 DLG-S016 다이얼로그가 열리고, 운영자는 발송 채널·만료일을 확인한 후 회원앱 Push 기본 또는 KakaoTalk fallback으로 결제링크를 보낸다. 회원은 링크에서 결제수단만 선택할 수 있으며 금액·상품 구성은 수정할 수 없어 현장 합의 그대로 결제가 진행된다. 회원앱 측에서는 MA-140 결제링크 화면이 비편집 모드로 동작한다.

운영 맥락:
- **카운터 매니저 비대면 회원 결제**: 상담 후 회원이 카드 미소지 → 결제링크 회원앱 Push 발송 → 회원 자가 결제
- **FC 외부 미팅 후 결제 위임**: 미팅 후 사무실 복귀 없이 결제링크 KakaoTalk fallback 발송 → 회원이 집에서 결제
- **전액 결제 링크 발송**: 금액·상품·할인 조건을 확정한 뒤 전액 결제 링크 발송 → 회원 자가 결제 → 결제완료 및 이용권 즉시 활성화
- **활성 링크 재발송**: 회원이 링크 분실 → 회원상세 결제내역/PAY-06에서 같은 링크 재발송, 만료 또는 무효화 시 새 링크 생성
- **활성 링크 무효화 + 신규**: 금액·상품 변경 필요 → 기존 링크 무효화 사유 입력 → 새 링크 생성
- **링크 만료 알림 (NFR-05)**: 결제링크는 발송일시 + 7일 고정 만료이며, 만료 D-3/D-1에 회원과 운영자에게 고정 알림을 발송한다. 지점 ON/OFF는 제공하지 않는다.
- **미결제 링크 환불 차단**: 미결제 결제링크는 환불 목록과 환불 버튼에 노출하지 않는다. URL 직접 접근 등 방어 케이스에서만 환불 진입을 차단하고 PAY-06 결제링크 무효화 안내를 표시한다.
- **회원앱/카카오 미연동 회원**: 결제링크 기본 발송은 회원앱 Push이며, 회원앱 미설치 또는 Push 실패 시 KakaoTalk fallback을 선택 설정한 경우에만 보조 발송한다. SMS로 자동 전환하지 않는다.
- **회원 PG 결제 webhook**: 회원 자가 전액 결제 완료 → webhook으로 매출 자동 반영 + 이용권 즉시 활성화

본 화면은 발송 + 활성 링크 관리만 담당하며 발송 후 결제 처리 자체는 회원앱 MA-140 + PG webhook 흐름으로 비동기 진행된다.

## 주요 구성요소

### 회원 정보 영역

| 항목 | 표시 |
|------|------|
| 수신 회원 이름 | 자동 채움 |
| 연락처 | 010 자동 포맷 |
| 앱 연결 여부 | "회원앱 설치됨" / "미설치" |

### 결제 요약 영역

| 항목 | 설명 |
|------|------|
| 상품명 | 현장 확정 상품 |
| 수량 | 단일 / 다중 |
| 정가 | 천 단위 콤마 |
| 할인 | 할인 금액 + 사유 |
| 최종 결제 금액 | 정가 - 할인 |
| 전액 결제 안내 | 계약금/잔액/할부 링크 불가 안내 |

### 발송 채널 선택

| 채널 | 사용 조건 |
|------|----------|
| 회원앱 Push | 기본 발송 채널 |
| KakaoTalk fallback | 지점이 fallback을 선택했고 채널 사용이 가능한 경우 보조 발송 |

### 링크 만료일시

발송 시점 + 7일로 고정 표시. 만료일 이후 결제 불가.

### 내부 메모

상담 메모, 발송 사유, 특이사항 textarea. 내부 관리용으로 회원에게 노출되지 않음.

### 활성 링크 처리

동일 원결제 기준 활성 링크가 이미 있을 경우.

| 옵션 | 동작 |
|------|------|
| 같은 링크 재발송 | 기존 링크 그대로 재전송 |
| 결제링크 무효화 후 새 링크 | 기존 링크 만료 → 새 링크 생성 |

### 발송 / 취소 버튼

- [발송]: 입력값 검증 → 채널 발송 → 상태 "발송됨" 갱신
- [취소]: 발송 없이 이전 화면(SCR-S003) 복귀

### 발송 결과 처리

| 결과 | 동작 |
|------|------|
| 발송 성공 | 토스트 + SCR-S003 복귀 + 상태 "발송됨" |
| 연락처 무효 | 인라인 에러 |
| 채널 사용 불가 | 다른 채널 자동 추천 |
| 발송 실패 | 토스트 + 재시도 |

## 주요 UX 흐름

### 신규 결제링크 발송
1. SCR-S003 결제 처리에서 상품·할인·금액 확정
2. 수납 방식 → "결제링크 발송" 선택
3. DLG-S016 다이얼로그 오픈
4. 회원 정보·결제 요약·만료일 확인
5. 채널 선택 (회원앱 Push / KakaoTalk fallback)
6. 내부 메모 입력 (선택)
7. [발송] → 검증 → 발송 → 상태 "발송됨"
8. SCR-S003 복귀

### 활성 링크 재발송
1. 회원상세 결제내역 또는 PAY-06에서 "결제링크 재발송"
2. DLG-S016 → 활성 링크 감지 안내
3. "같은 링크 재발송" 또는 "결제링크 무효화 후 새 링크" 선택
4. [발송] → 처리

### 회원 측 결제
1. 회원이 회원앱 Push/KakaoTalk fallback 링크 클릭
2. 회원앱 MA-140 결제링크 화면 (비편집)
3. 결제수단 선택 → PG 결제
4. 결제 완료 webhook → 매출 자동 반영 + 이용권 즉시 활성화

### 분기·예외 흐름
- **활성 링크 1개 제한**: 동일 원결제 기준 활성 링크는 1개만 유지, 재발송 또는 결제링크 무효화 후 신규 옵션
- **발송 후 수정 불가**: 링크 발송 후 상품·할인·최종 금액 수정 차단 (현장 합의 보호)
- **KakaoTalk fallback 불가 회원**: 카카오톡 채널 미연결 또는 템플릿 미승인 → SMS 자동 전환 없이 실패/제외 상태 기록 + 운영자 수동 안내 필요 표시
- **연락처 무효**: 인라인 에러 + 회원 정보 수정 안내
- **만료된 링크 재발송 시도**: "만료된 링크입니다" + 새 링크 생성 안내
- **회원 결제 완료 webhook**: PG 콜백 수신 → 결제 완료 처리 + SCR-S001 반영 + 이용권 즉시 활성화
- **회원 결제 실패 webhook**: 링크 상태 유지 + 회원에게 재시도 안내
- **링크 만료 알림 (NFR-05)**: 발송일시 + 7일 만료 기준 D-3/D-1에 회원과 운영자에게 고정 알림 발송. 지점 ON/OFF는 제공하지 않음
- **미결제 환불 시도**: 환불이 아닌 PAY-06 결제링크 무효화로 분기
- **회원 연락처 변경 시**: 미발송 링크는 새 연락처로 자동 갱신, 발송된 링크는 별도 재발송 필요

## 비즈니스 규칙

1. **발송 후 수정 불가**: 링크 발송 후 상품·할인·최종 금액 수정 차단 (현장 합의 보호).
2. **활성 링크 1개 제한**: 동일 원결제 기준 활성 링크는 1개만 유지.
3. **재발송 / 결제링크 무효화 옵션**: 활성 링크 있을 때 같은 링크 재발송 또는 결제링크 무효화 후 새 링크.
4. **만료 후 재사용 차단**: 만료된 링크는 재사용 불가, 새 링크 발송 필요.
5. **연락처 필수**: 회원 연락처가 없거나 무효하면 발송 차단.
6. **만료일 고정**: 발송 시점 + 7일 고정. 운영자와 지점은 만료일을 변경할 수 없다.
7. **회원앱 MA-140 비편집 모드**: 결제수단만 선택, 금액·상품 수정 불가.
8. **결제 완료 webhook 자동 반영**: SCR-S001 매출현황·결제 건에 자동 반영하고 이용권을 즉시 활성화하며 감사 로그를 기록한다.
9. **미완료 환불 차단**: 결제 미완료 시 환불(SCR-S012) 아닌 결제링크 무효화로 처리.
10. **발송 채널 fallback**: 회원앱 Push가 기본이며, 실패 시 지점이 선택한 KakaoTalk fallback만 사용한다. SMS로 자동 전환하지 않으며, 두 채널 모두 불가하면 발송 실패/제외로 기록한다.
11. **링크 만료 알림 (NFR-05)**: 링크 만료 기준 D-3/D-1 고정 알림을 회원·운영자에게 발송한다. 결제링크 만료 알림은 지점 ON/OFF를 제공하지 않는다.
12. **회원 결제 실패 시**: 링크 상태 "결제 실패" + 만료까지 재시도 가능.
13. **PG webhook 보안**: webhook 서명 검증 (HMAC), 위변조 차단.
14. **idempotency**: webhook 중복 수신 시 idempotency-key로 이중 처리 차단.
15. **연락처 변경 시 미발송 링크 갱신**: 회원 연락처 변경 후 미발송 링크는 새 연락처로 자동 갱신.
16. **활성 링크 1개 제한**: 동일 결제 건에는 `발송됨` 상태 링크 1개만 허용한다. 새 링크가 필요하면 기존 링크를 먼저 무효화해야 한다.
17. **권한별 발송**: FC도 담당 회원에게 발송 가능, 트레이너·스태프는 조회만.
18. **본사 통합 모드**: 본사 슈퍼관리자만 전 지점 통합 조회.
19. **링크 토큰 보안**: 링크 토큰은 1회용 + 7일 만료, 위변조 방지 서명 포함.
20. **링크 미사용 만료 시 미수금 미생성**: 링크 만료 후에도 PAY-03 미수금으로 생성하지 않음, 새 링크 발송 안내.
21. **감사 로그**: 발송·재발송·만료·무효화·결제 webhook 모두 SCR-097 기록. 무효화는 사유·actor·처리시각을 필수 기록한다.
22. **비정상 발송 알림**: 일별 50건 이상 발송 시 본사 슈퍼관리자 알림.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `PAY-06`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-S003`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-S016 결제링크발송`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
