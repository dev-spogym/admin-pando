## 기능 목적

POS 판매 화면(SCR-S002)에서 구성한 장바구니를 결제완료 상태로 확정하는 기능이다. 현장 판매에서는 CRM이 카드 PG 승인을 직접 수행하지 않는다. 인포데스크(FC)가 외부 POS 단말 또는 현금/계좌이체 수납으로 실제 결제를 먼저 완료하고, CRM에는 혼합결제 행, 포인트 사용액, 결제일시, 영수증 파일, VAN/POS 결과, 지점 귀속 필드를 등록한다. 등록이 성공하면 별도 매니저 승인 없이 결제완료와 회원/이용권 등록 완료가 즉시 반영된다.

비대면 고객을 위한 PAY-06 결제링크 발송은 유지한다. 결제링크 경로는 고객이 링크에서 직접 결제하고 webhook으로 매출과 미수금을 반영하는 별도 흐름이다.

운영 맥락:
- **카운터 매니저 일반 회원권 등록**: POS에서 1년 회원권 장바구니 구성 → 외부 POS 카드 결제 완료 → 영수증 첨부 → 회원권 즉시 활성
- **FC 신규 회원 PT 패키지 등록**: 상담 후 PT 패키지 판매 → 카드/현금/계좌이체 결제 영수증 첨부 + 포인트 사용액 입력 → 결제완료와 이용권 등록 완료
- **계약금만 받고 다음 달 잔액**: 당일 결제가격과 포인트 사용액 등록 → 즉시 개시 vs 완납 후 개시 선택 → 잔액은 PAY-03 미수금/SAL-EXT-01 할부 라우팅
- **링크 발송 결제 (DLG-S016)**: 회원이 비대면일 때 금액·할인 확정 후 SMS/카톡 발송 → 회원 직접 결제 → webhook으로 매출 자동 반영
- **포인트 사용 결제**: 회원 검색 → 보유 포인트 검증 → 사용액 입력 → 혼합결제 행 합계 + 포인트 사용액이 장바구니 합계와 일치해야 등록
- **혼합결제 결제**: 카드/현금/계좌이체를 복합 입력 → 각 수단별 영수증·승인정보 저장 → 단일 결제로 확정
- **법인/통합 회원권 결제**: 결제지점·이용지점·매출 귀속 지점·정산 지점·인센티브 귀속자 확인 후 저장
- **중복 결제 의심 (DLG-S004)**: 동일 회원·동일 금액·동일 상품이 5분 이내 다시 등록되면 경고 → 운영자가 의도 확인 후 진행
- **본사 슈퍼관리자 운영 모니터링**: 본사 통합 모드에서 지점 매출 실시간 집계, 비정상 등록 패턴(대량 환불·중복 등록) 알림 수신

영수증 파일 첨부는 현장 판매 결제 등록의 필수 조건이다. 첨부가 없으면 결제 완료 등록 버튼은 활성화되지 않는다.

## 주요 구성요소

### 결제 상품 목록 (좌측)

POS에서 담아온 상품명·수량·소계 + 하단 장바구니 최종 합계 큰 표시.

### 회원 검색 (좌측)

포인트 사용 또는 회원/이용권 등록 시 필수. 이름/전화번호 검색 → 보유 포인트 표시 → X 해제.

### 할인 입력

정가 / 할인 항목 / 할인 금액 입력 → 장바구니 최종 합계와 잔액 즉시 재계산.

### 수납 방식 선택

| 방식 | 설명 |
|------|------|
| 현장 전액 등록 | 외부 POS/현금 결제가 끝난 전체 금액을 영수증과 함께 등록 |
| 계약금 등록 | 당일 결제가격 + 포인트 사용액 등록, 잔액은 미수금/할부 |
| 잔액 등록 | 기존 계약 남은 잔액에 대한 현장 결제 영수증 등록 |
| 결제링크 발송 | 금액 확정 후 고객 직접 결제 링크 발송 |

### 현장 결제 등록 정보

| 필드 | 필수 | 검증 |
|---|---|---|
| 혼합결제 행 | 필수 | 1개 이상, 카드 / 현금 / 계좌이체 조합 허용 |
| 결제가격(행별 금액) | 필수 | 0원 이상, 수납 행 합산 검증 |
| 포인트 사용 여부/사용액 | 조건부 | 사용 시 회원 선택 및 보유 포인트 이내 |
| 결제일시 | 필수 | 영수증 기준 결제 완료 시각 |
| 영수증 파일 | 필수 | 이미지/PDF 첨부, 미첨부 시 등록 불가 |
| FC 메모 | 선택 | 현장 확인 내용, 특이사항 |
| VAN/POS 승인 결과 | 조건부 | 카드 결제 행이 있으면 승인번호/단말ID/응답결과 저장 가능 |
| 지점 귀속 필드 | 필수 | 결제지점 / 이용지점 / 매출 귀속 지점 / 정산 지점 / 인센티브 귀속자 |

### 금액 일치 검증

`혼합결제 행 합계 + 포인트 사용액 = 장바구니 최종 합계`가 정확히 일치해야 결제 완료 등록이 가능하다. 불일치하면 차액을 붉은색으로 표시하고 버튼을 비활성화한다.

### 잔액 요약 박스

정가 / 할인 / 당일 등록 금액 / 잔액 / 결제 경로 한 줄 표시.

### 이용권 개시 옵션 (계약금 등록 시)

`즉시 개시 / 완납 후 개시` 라디오.

### 결제링크 발송 버튼 (DLG-S016)

수납 방식 = 결제링크 발송 시 노출. 회원 연락처 + 만료일시 확인 후 발송.

### 결제 확인 모달 (DLG-S003)

상품 내역·장바구니 합계·결제수단·결제가격·포인트 사용액·결제일시·영수증 첨부 여부·선택 회원 최종 확인. "결제 완료 등록" 버튼 → 등록 중 상태.

### 중복 결제 경고 (DLG-S004)

동일 회원 동일 금액 최근 결제 감지 시 경고. "계속 진행" 또는 "취소".

### 결제 완료 화면

체크 아이콘 + 완료 메시지 + 영수증 파일 보기 / 문자 발송 / 계속 판매 / 매출 현황 이동. 이 상태는 결제완료와 회원/이용권 등록 완료가 모두 반영된 상태다.

## 주요 UX 흐름

### 현장 전액 등록 흐름

1. SCR-S002에서 [결제하기] → SCR-S003 진입
2. 좌측 상품 목록 + 장바구니 최종 합계 확인
3. 할인 입력 / 수납 방식 = 현장 전액 등록 선택
4. 인포데스크(FC)가 외부 POS 또는 현금 수납 완료
5. 혼합결제 행, 포인트 사용액, 결제일시, 영수증 파일, VAN/POS 결과, 귀속 필드 입력
6. `혼합결제 행 합계 + 포인트 사용액 = 장바구니 최종 합계` 검증 통과
7. [결제 등록] → DLG-S003 최종 확인 → [결제 완료 등록]
8. 완료 → 결제완료 + 회원/이용권 등록 완료 + 매출 현황 반영

### 계약금 등록 + 잔액 결제링크 흐름

1. 수납 방식 = 계약금 등록 → 당일 결제가격과 포인트 사용액 입력
2. 영수증 파일 첨부 및 결제일시 입력
3. 이용권 개시 옵션 (즉시 / 완납 후) 선택
4. 잔액 처리 = 결제링크 발송 (DLG-S016)
5. 회원 연락처 + 만료일시 확인 → 발송
6. 회원 직접 결제 → webhook → SCR-S001 반영 + 미수금 차감

### 분기·예외 흐름

- **영수증 파일 미첨부**: "영수증 파일을 첨부해주세요" 안내 + 결제 등록 버튼 비활성
- **결제 총액 불일치**: 혼합결제 행 합계 + 포인트 사용액과 장바구니 합계 차액 표시 + 결제 등록 버튼 비활성
- **포인트 사용 시 회원 미선택**: "포인트 사용은 회원 선택이 필요해요" 안내 + 회원 검색 영역 강조
- **포인트 보유 부족**: 부족액 빨강 표시 + 결제 등록 차단
- **DLG-S004 중복 결제 경고**: 동일 회원·금액 5분 이내 결제 감지 시 모달 → "계속 진행" 또는 "취소" 선택
- **결제링크 발송 후 SCR-S003 복귀**: 링크 상태 "발송됨"으로 잠금, 별도 현장 등록 재시도 차단
- **계약금 0원 입력**: "계약금은 1원 이상 입력해주세요" + 결제 차단
- **할인 금액이 정가 초과**: 할인 입력 빨강 + 결제 차단
- **카드 결제 행 승인번호 누락**: 저장은 가능하나 "승인정보 미입력" 경고 배지 표시
- **법인/홈&오피스/주말/통합 회원권 포함**: 지점 귀속 필드 검토를 완료해야 저장 가능

## 비즈니스 규칙

1. **영수증 첨부 필수**: 현장 결제 등록은 영수증 파일 첨부가 없으면 완료할 수 없다.
2. **현장 결제 총액 일치**: 혼합결제 행 합계 + 포인트 사용액은 장바구니 최종 합계와 정확히 일치해야 한다.
3. **CRM 직접 PG 제외**: 현장 판매의 카드/현금 결제 승인은 외부 POS 또는 현장 수납에서 완료하며 CRM은 승인 요청을 보내지 않는다.
4. **결제 완료 즉시 반영**: 결제 완료 등록 시 SCR-S001 매출 현황·회원 카드 이용권에 즉시 반영한다.
5. **회원/이용권 동시 완료**: 현장 결제 등록 성공은 결제완료와 회원/이용권 등록 완료를 동시에 의미한다.
6. **포인트 사용 회원 필수**: 포인트 사용은 회원 선택이 필수이며 보유 부족 시 결제를 차단한다.
7. **포인트 잔액 동시성**: 포인트 차감 시 row-level lock으로 잔액 동시 차감 충돌을 방지한다.
8. **중복 결제 감지 윈도우**: 동일 회원·동일 금액·동일 상품의 결제가 5분 이내 재등록되면 DLG-S004 경고.
9. **계약금 등록 이용권 개시**: 계약금 등록 시 이용권 개시 시점(즉시 / 완납 후) 명시 필수, 미선택 시 결제 차단.
10. **결제링크 만료**: 결제링크 발송 시 만료일시는 발송 시점 + 7일 고정. 만료 후 결제 불가.
11. **할인 한도**: 할인 금액은 정가의 100%를 초과할 수 없으며 무료 등록은 별도 권한자 승인.
12. **0원 현장 등록 차단**: 혼합결제 행 합계 + 포인트 사용액이 0원인 경우 결제 등록 차단, 별도 무료 등록 플로우로 분기.
13. **혼합결제 허용 범위**: 카드/현금/계좌이체는 3개 수단까지 동시 입력 가능하며 동일 수단 다중 행도 허용한다.
14. **카드 승인정보 저장**: 카드 결제 행은 `approvalNo`, `terminalId`, `externalTransactionId`, `approvedAt`, `vanResultCode`, `vanResultMessage`를 선택 저장할 수 있다.
15. **계좌이체 증빙 저장**: 계좌이체 행은 `depositorName`, `transferRef`, `transferredAt`, `bankName`을 저장한다.
16. **귀속 필드 분리 저장**: 모든 결제는 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId`를 함께 저장한다.
17. **다지점 회원권 처리**: 법인/홈&오피스/주말/통합 회원권은 이용 가능 지점과 귀속 필드를 단일 지점으로 축약하지 않는다.
18. **계약금 최소 금액**: 계약금은 총액의 10% 이상이어야 하며 정책에 따라 변경 가능.
19. **할부 자동 라우팅**: 계약금 등록 + 잔액이 있을 때 분납 회차 입력 시 SAL-EXT-01 할부 계약 자동 생성, 단순 미수는 PAY-03 미수금에 등록.
20. **잔액 수납 모드**: 기존 계약 잔액만 수납하는 경우 원결제 ID 필수 매핑.
21. **영수증 보관**: 영수증 파일은 결제 기록과 연결해 보관하며, 매출 상세와 감사 로그에서 조회 가능해야 한다.
22. **권한별 결제 한도**: FC는 1회 등록 최대 1000만원, 매니저는 무제한 (테넌트 정책 토글).
23. **결제 취소/환불**: 외부 POS 결제 취소는 현장 POS에서 선처리 후 CRM에서는 SAL-EXT-04 결제취소/부분환불로 기록한다.
24. **감사 로그**: 결제 등록 시도·성공·실패·취소 모두 SCR-097에 기록 (`payment_id`, `actor_id`, `amount`, `method`, `receipt_file_id`, `result`).
25. **중복 회원 검색 결과**: 회원 검색 결과 2명 이상 시 추가 식별 정보(생년월일·전화번호 끝자리) 입력 필수.
26. **회원 비활성/탈퇴 시**: 비활성 회원에게는 결제 차단(이용권 부여 불가), 탈퇴 회원은 검색 결과에서 제외.
27. **법인 회원 결제**: 법인 회원 결제 시 SAL-EXT-02 세금계산서 발행 알림 자동 노출 + 사업자 정보 자동 채움.
28. **부분 환불 기준 데이터 보존**: 원결제의 혼합결제 행은 환불 완료 후에도 immutable로 보존되며 SAL-EXT-04에서 행별 잔여 환불 가능액 계산의 기준이 된다.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-S003`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-S003 결제확인, DLG-S004 중복결제경고, DLG-S016 결제링크발송`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 표와 아래 API 기준을 같이 적용합니다.

- **연계 화면**: SCR-S002 / SCR-S001 / SCR-M004 / SCR-S008 미수금 / SCR-S009 할부 / SCR-S010 세금계산서 / SCR-097 감사 로그
- **연계 다이얼로그**: DLG-S003 / DLG-S004 / DLG-S016
- **API 기준**: `POST /api/payments/receipt-registration` / `POST /api/payment-receipts/upload` / `POST /api/payments/check-duplicate` / `POST /api/payment-links` / `POST /api/payments/webhook` (결제링크 콜백) / `POST /api/payments/:id/cancel`
