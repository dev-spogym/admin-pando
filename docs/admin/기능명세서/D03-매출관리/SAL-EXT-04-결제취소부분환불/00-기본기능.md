## 기능 목적

완료된 결제 건에 대해 전체 취소 또는 일부 금액 환불을 요청·승인·처리하는 화면이다. 단순 변심·결제 오류·서비스 불만 등의 사유로 환불 요청이 들어왔을 때 담당자가 해당 결제 건을 조회하고 전체 취소 또는 부분 환불 금액을 수기로 입력한다. 환불 자동 계산 산식은 현재 미확정이므로 기사용 차감금·위약금·기환불 누계·이번 환불 가능액·최종 환불액은 모두 수기 입력값과 조정 사유를 기준으로 기록한다. 실제 환불 실행은 지점장(owner) 승인 후 가능하며, 지점장 계정으로 로그인한 경우에는 승인대기 없이 즉시 환불 처리할 수 있다. 현장 영수증 첨부 등록 건은 외부 POS/현금 환불을 먼저 완료한 뒤 CRM에 환불 기록을 남기고, 결제링크 완료 건은 PG 환불/webhook 흐름으로 처리한다. 처리된 내역은 환불 관리 화면에 자동 반영되며 감사 로그에 기록된다.

운영 맥락:
- **카운터 매니저 당일 결제 취소 요청**: 결제 직후 회원 변심 → 결제 ID 검색 → 환불 항목 수기 입력 → 지점장 승인 요청
- **FC 휴원·이사 환불 요청**: 회원 요청 → 결제 검색 → 사용한 회차/일수 차감·위약금·환불 가능액 수기 입력 → 지점장 승인 요청
- **센터장 분쟁 환불 직접 처리**: 서비스 불만 → 환불 항목 수기 입력 → 승인대기 없이 처리 → 처리 내역 즉시 확인
- **고객센터 결제 오류 환불**: 중복 결제 / 금액 오류 → 결제 ID로 직접 조회 → 전체 취소
- **할부 진행 중 환불**: 잔여 미수금 상계 + 기납입액 환불 + 잔여 회차 일괄 취소 (SAL-EXT-01 연계)
- **부분 환불 후 잔여 환불 가능액**: 같은 결제 건 두 번째 부분 환불 시 기환불 누계 차감 후 가능액 갱신
- **미결제 결제링크 환불 진입 방어**: 미결제 결제링크는 환불 목록과 환불 버튼에 노출하지 않으며, 직접 접근 시 환불 진입 차단 + PAY-06 결제링크 무효화 안내로 처리
- **결제경로별 환불 처리**: 현장 영수증 등록 건은 외부 POS/현금 환불 증빙 확인, 결제링크 완료 건은 PG 환불 결과를 webhook으로 갱신
- **마이너스 세금계산서**: 법인 회원 환불 시 SAL-EXT-02에서 마이너스 세금계산서 발행 안내
- **본사 슈퍼관리자 비정상 환불 모니터링**: 대량/고액 환불 시 알림 수신 + 감사 로그 검토

환불 요청 담당자는 운영 판단에 따라 기사용 차감금·위약금·기환불 누계·이번 환불 가능액·최종 환불액을 모두 수기 입력하며 조정 사유를 반드시 기록한다. 클라이언트의 환불 자동 계산 산식이 확정되기 전까지 화면은 어떤 환불 가능액도 자동 산출값으로 단정하지 않는다. 추후 정책 확정 후 configurable policy 또는 정책 테이블 기반 자동 계산으로 대체할 수 있으나, 현재 정본 기준은 수기 입력 + 지점장 승인이다.

## 주요 구성요소

### 결제 건 검색

| 항목 | 입력 |
|------|------|
| 회원명 | 텍스트 (디바운스 300ms) |
| 상품명 | 텍스트 |
| 결제일 | 기간 범위 |
| 결제 ID | 직접 입력 |

### 결제 내역 확인

선택한 결제 건의 정보 카드.

| 항목 | 표시 |
|------|------|
| 결제일 | YYYY-MM-DD HH:mm |
| 상품명 | 멤버십/PT 등 |
| 결제 금액 | 천 단위 콤마 |
| 결제 수단 | 현장 카드/결제링크 카드/현금/계좌이체/마일리지(포인트) |
| 결제자 | 회원명 + 담당자 |

### 환불 계산 박스

| 항목 | 설명 |
|------|------|
| 원결제 금액 | 결제 시 수납액 |
| 기사용 차감금 | 이미 사용한 회차·일수에 대한 운영 판단 차감액. 수기 입력 |
| 위약금 | 약관 또는 협의 기준으로 운영자가 입력하는 위약금. 수기 입력 |
| 기환불 누계 | 이전 부분 환불 합계 확인값. 수기 입력/보정 가능 |
| 이번 환불 가능액 | 이번 처리에서 환불 가능한 금액. 수기 입력 |
| 최종 환불액 | 실제 반환할 금액. 수기 입력 (≤ 이번 환불 가능액) |

정책 미확정 상태의 1차 구현에서는 아래 항목을 수기 입력으로 받는다.

| 항목 | 수기 입력 목적 |
|------|------|
| 기사용 차감금 | 일할 계산, PT 사용 횟수, 기간권 사용일 등 클라이언트 정책 확정 전 운영 판단값 기록 |
| 위약금 | 정액/비율/상품별 예외 정책 확정 전 담당자 입력 |
| 기환불 누계 | 이전 부분 환불 금액 확인 전 수기 보정 |
| 이번 환불 가능액 | 자동 계산값이 아니라 운영자가 확정한 금액 입력 |
| 최종 환불액 | 실제 반환할 금액 입력 |
| 조정 사유 | 수기 입력 또는 조정 근거 필수 기록 |

### 혼합결제 환불 분해표

| 항목 | 설명 |
|------|------|
| 원수납 행 | 카드 / 현금 / 계좌이체 / 마일리지(포인트)별 원결제 행 |
| 기환불액 | 수단별 누적 환불액 |
| 이번 환불 배분액 | 이번 처리에서 각 수단에 배분되는 금액 |
| 잔여 가능액 | 수단별 남은 환불 가능액 |

### 처리 유형 선택

- **전체 취소**: 환불 가능액 전액 → 사유 입력 필수
- **부분 환불**: 직접 입력 (가능액 초과 불가) → 사유 입력 필수

### 환불 사유 입력

프리셋 사유 + 추가 의견.

| 사유 카테고리 | 예시 |
|---|---|
| 단순 변심 | 회원 변심 |
| 결제 오류 | 중복 결제 / 금액 오류 |
| 회원 요청 | 휴원·이사 |
| 서비스 불만 | 강사·시설 불만 |
| 기타 | 자유 입력 |

### 환불 수단 확인

원결제 수단에 따른 환불 방법 안내.

| 원결제 수단 | 환불 방법 |
|---|---|
| 현장 카드 | 외부 POS 환불 완료 후 CRM 기록 |
| 결제링크 카드 | PG 환불 후 webhook 상태 갱신 |
| 현금 | 현금/계좌 환불 완료 후 CRM 기록 |
| 계좌이체 | 계좌 이체 |
| 마일리지(포인트) | 환불 시 우선 복원 |

외부 연동 정책이 확정되기 전에는 환불 수단, 외부 처리 상태, POS/PG 승인번호 또는 증빙 메모를 수기로 기록한다.

### 승인/귀속 기록

| 항목 | 설명 |
|------|------|
| 처리 상태 | 요청 / 승인대기 / 완료 중 선택 |
| 승인자 | 환불 승인 지점장(owner). 지점장 직접 처리 시 현재 로그인 계정 |
| 승인 메모 | 환불 승인 사유와 특이사항 |
| 결제지점 | 원결제 발생 지점 |
| 이용지점 | 실제 이용 또는 수업 수행 지점 |
| 매출 귀속 지점 | 환불 차감 기준 지점 |
| 정산 지점 | 정산 반영 기준 지점 |
| 인센티브 귀속자 | 환불 시 환수 또는 차감 대상자 |

### 환불 처리 전 최종 확인

환불 실행 전에 환불 대상 결제, 환불 유형, 기사용 차감금, 위약금, 기환불 누계, 이번 환불 가능액, 최종 환불액, 환불 사유, 환불 수단, 외부 처리 증빙, 쿠폰/마일리지 복원 내역을 한 번 더 확인한다. 지점장(owner)은 [처리 완료]로 즉시 환불을 실행하고, manager/fc는 [승인 요청]으로 승인대기 상태를 생성한다. 승인대기 건은 지점장이 동일 확인 항목을 검토한 뒤 승인 또는 반려할 수 있다.

### 처리 완료 안내

환불 성공 후 환불번호, 환불금액, 처리일시, 처리자, 승인자, 쿠폰/마일리지 복원 결과를 표시한다. 사용자는 [환불 관리에서 확인] 버튼으로 환불 목록에서 방금 처리한 환불 건을 확인하거나, [계속 환불 처리] 버튼으로 현재 화면에 남아 다른 결제 건을 이어서 처리할 수 있다.

### 처리 이력

해당 결제 건에 대해 이전 부분 환불 이력이 있으면 하단 목록 표시.

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin | 전체 지점 결제 건 | 전체 취소·부분 환불 처리, 승인 이력 조회, 지점장 승인 대행 |
| owner (센터장) | 소속 지점 전체 | 승인대기 없이 전체 취소·부분 환불 처리, 승인대기 건 승인/반려, 위약금 면제 |

| fc | 담당 회원 결제 건 | 환불 요청 생성, 수기 계산 항목 입력, 승인대기 등록. 실제 환불 실행 불가 |
| 트레이너 / 스태프 | 매출 조회만 | 조회만 |
| readonly | ❌ | ❌ |

## 주요 UX 흐름

### 전체 취소 흐름
1. 사이드바 → "매출관리 > 결제 취소/부분 환불" 진입
2. 회원명·상품명·결제일·결제 ID로 결제 건 검색
3. 결제 내역 확인 + 환불 수기 입력 박스 검토
4. "전체 취소" 선택 → 사유 입력
5. manager/fc는 [승인 요청], owner는 [처리 확인] → 환불 처리 전 최종 확인 팝업 → [처리 완료]
6. 환불 완료 결과 안내 팝업 → [환불 관리에서 확인] 또는 [계속 환불 처리] 선택

### 부분 환불 흐름
1. 결제 건 선택 → 환불 수기 입력 박스 확인
2. "부분 환불" 선택 → 환불 금액 입력
3. 가능액 초과 시 경고
4. 사유·수단 확인 → [처리 확인]
5. 환불 처리 전 최종 확인 팝업 → 처리 완료 → 잔여 환불 가능액 갱신

### 위약금 / 기사용 차감 조정 흐름
1. 환불 계산 박스 → 위약금 / 기사용 차감 항목 클릭
2. 조정 입력 + 조정 사유 입력 (필수)
3. 이번 환불 가능액과 최종 환불액을 운영자가 수기 입력
4. manager/fc는 승인 요청, owner는 즉시 처리

### 분기·예외 흐름
- **이미 전액 환불 건**: "이미 전액 환불된 건입니다" + 처리 차단
- **미결제 결제링크**: "환불 진입 차단 + PAY-06 결제링크 무효화 안내" + PAY-06 안내
- **결제경로별 환불 처리**: 현장 카드/현금은 외부 POS/현금 환불 완료 후 CRM 기록, 결제링크 카드는 PG 환불 (영업일 3~5일)
- **할부 진행 중 환불**: 잔여 미수금 상계 + 기납입액 환불, 잔여 회차 일괄 취소 (SAL-EXT-01 연계)
- **마일리지(포인트) 환불**: 쿠폰보다 먼저 사용 마일리지(포인트)를 복원하고, 남은 환불액을 결제수단별로 처리. webhook 없음
- **결제링크 PG 환불 거절 webhook**: "처리 실패" 상태 + 운영자 알림, 익영업일 재시도
- **위약금 면제 권한 부족**: 면제 토글 hidden, 매니저 이상에게 요청 안내
- **부분 환불 가능액 0원**: 더 이상 환불 불가 안내
- **법인 회원 환불**: "마이너스 세금계산서 발행 필요" 알림 → SAL-EXT-02 진입 가능

## 비즈니스 규칙

1. **환불 계산 항목**: `기사용 차감금`, `위약금`, `기환불 누계`는 환불 상태가 아니라 환불 계산 항목.
2. **환불 자동 계산 미확정**: 환불 가능액 자동 산식은 현재 사용하지 않는다. 기사용 차감금·위약금·기환불 누계·이번 환불 가능액·최종 환불액은 모두 수기 입력하고 사유를 남긴다.
3. **할부/미수 상계 우선**: 할부/미수 진행 중 결제는 남은 미수금과 먼저 상계한 뒤 실제 환불액을 운영자가 수기 확정한다.
4. **미결제 결제링크**: 미결제 결제링크는 환불 목록과 환불 버튼에 노출하지 않는다. URL 직접 접근 등 방어 케이스에서만 "결제되지 않은 링크는 환불 대상이 아닙니다" 안내 후 차단하고 PAY-06 결제링크 무효화 안내로 보낸다.
5. **조정 권한 + 사유 기록**: 환불 요청 담당자는 수기 입력 항목을 작성할 수 있으며 조정 사유를 필수 기록한다. 실제 환불 실행은 owner 승인 후 가능하다.
6. **최종 환불액 한도**: 최종 환불액 ≤ 확정된 환불 가능액. 초과 차단.
7. **지점장 승인 필수**: manager/fc가 등록한 환불은 승인대기 상태가 되며, 지점장(owner) 승인 후에만 처리 완료할 수 있다. owner가 직접 로그인한 경우 승인자=처리자로 기록하고 즉시 처리 가능하다.
8. **자동 반영**: 처리 결과는 환불 관리 화면에 5초 이내 자동 반영, 감사 로그에 append-only로 기록.
9. **결제경로별 환불 처리**: 현장 카드/현금은 외부 POS/현금 환불 완료 후 CRM 기록, 결제링크 카드는 PG 환불 (영업일 3~5일)과 webhook 비동기 갱신.
10. **마일리지(포인트) 우선 복원**: 환불 시 결제에 사용한 마일리지(포인트)를 우선 복원한다. 복원 금액이 환불 대상 금액을 초과할 수 없으며, 잔여 금액만 카드/현금/계좌 등으로 처리한다.
11. **쿠폰 복원**: 환불 처리 시 해당 결제에 사용된 쿠폰은 미사용 상태로 복원한다. 쿠폰 유효기간이 이미 만료된 경우에도 복원 여부와 만료 상태를 이력에 표시한다.
12. **현금/계좌 환불**: 계좌 이체로 환불, 회원 환불 계좌 정보 필수.
13. **부분 환불 누적**: 같은 결제 건의 부분 환불은 누적 추적하며, 가능액은 운영자가 수기 확정한다.
14. **혼합결제 행 단위 잔액 관리**: 카드/현금/계좌이체/마일리지(포인트)별 잔여 환불 가능액을 별도로 관리하며, 부분 환불 시 각 행의 잔액을 차감한다.
15. **환불 귀속 유지**: 원결제의 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId`를 상속해 정산·KPI·인센티브 차감을 계산한다.
16. **이미 전액 환불 차단**: 이미 전액 환불 건은 추가 환불 차단.
17. **위약금 정책**: 자동 산식은 미확정이다. 위약금은 운영자가 수기 입력하고 근거를 메모로 남긴다.
18. **위약금 면제 권한**: 슈퍼관리자·센터장만 면제 가능, 면제 사유 필수.
19. **결제링크 PG 환불 거절 시 처리**: webhook 거절 응답 시 상태 "거절" + 운영자 알림, 익영업일 재시도.
20. **할부 환불 연계**: 할부 환불 시 SAL-EXT-01 잔여 회차 일괄 취소.
21. **법인 회원 환불**: 마이너스 세금계산서 발행 안내 (SAL-EXT-02 연계).
22. **권한별 가능 범위**: manager/fc는 환불 요청까지만 가능하고 실제 환불 실행은 owner 승인 또는 owner 직접 처리로 제한한다.
23. **idempotency**: 환불 요청은 idempotency-key로 중복 처리 차단.
24. **사유 카테고리**: 단순 변심 / 결제 오류 / 회원 요청 / 서비스 불만 / 기타 5종.
25. **부분 환불 최소 금액**: 1원 이상.
26. **선수익금 환불 영향**: 환불 시 SAL-04 선수익금 인식 차감.
27. **환불 이력 보관**: 5년 보관 (회계·세무).
28. **대량/고액 환불 알림**: 단일 환불 100만원 이상 또는 일별 10건 이상 시 본사 슈퍼관리자 알림.
29. **회원 탈퇴 후 환불**: 탈퇴 회원도 환불 가능 (회수 추진), 환불 계좌 필수.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SAL-EXT-04`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-S012`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-S013 환불처리, DLG-S014 환불상세결과, DLG-S015 환불요청`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
