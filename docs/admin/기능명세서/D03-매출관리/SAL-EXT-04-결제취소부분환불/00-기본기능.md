## 기능 목적

완료된 결제 건에 대해 전체 취소 또는 일부 금액 환불을 처리하는 화면이다. 단순 변심·결제 오류·서비스 불만 등의 사유로 환불 요청이 들어왔을 때 담당자가 해당 결제 건을 조회하고 전체 취소 또는 부분 환불 금액을 지정해 처리한다. 현장 영수증 첨부 등록 건은 외부 POS/현금 환불을 먼저 완료한 뒤 CRM에 환불 기록을 남기고, 결제링크 완료 건은 PG 환불/webhook 흐름으로 처리한다. 처리된 내역은 SCR-S007 환불 관리 화면에 자동 반영되며 감사 로그에 기록된다.

운영 맥락:
- **카운터 매니저 당일 결제 취소**: 결제 직후 회원 변심 → 결제 ID 검색 → 외부 POS/현금 환불 완료 → CRM 전체 취소 기록
- **FC 휴원·이사 환불 요청**: 회원 요청 → 결제 검색 → 부분 환불 (사용한 회차/일수 차감 + 위약금) → 환불 가능액 자동 계산
- **센터장 분쟁 환불 처리**: 서비스 불만 → DLG-S015 환불 요청 검토 → 위약금 면제 권한 사용 → 처리
- **고객센터 결제 오류 환불**: 중복 결제 / 금액 오류 → 결제 ID로 직접 조회 → 전체 취소
- **할부 진행 중 환불**: 잔여 미수금 상계 + 기납입액 환불 + 잔여 회차 일괄 취소 (SAL-EXT-01 연계)
- **부분 환불 후 잔여 환불 가능액**: 같은 결제 건 두 번째 부분 환불 시 기환불 누계 차감 후 가능액 갱신
- **결제링크 미완료 환불 시도 차단**: 미완료 링크는 환불 아닌 링크 취소(SCR-S016)로 분기
- **결제경로별 환불 처리**: 현장 영수증 등록 건은 외부 POS/현금 환불 증빙 확인, 결제링크 완료 건은 PG 환불 결과를 webhook으로 갱신
- **마이너스 세금계산서**: 법인 회원 환불 시 SAL-EXT-02에서 마이너스 세금계산서 발행 안내
- **본사 슈퍼관리자 비정상 환불 모니터링**: 대량/고액 환불 시 알림 수신 + 감사 로그 검토

환불 처리 담당자는 운영 판단에 따라 기사용 차감금·위약금·이번 환불 가능액을 조정할 수 있으며 조정 사유를 반드시 기록한다. 클라이언트 정책이 확정되지 않은 항목은 자동 계산으로 단정하지 않고 수기 입력값으로 먼저 기록하며, 추후 정책 확정 후 configurable policy 또는 정책 테이블 기반 자동 계산으로 대체한다.

## 주요 구성요소

### 결제 건 검색

| 항목 | 입력 |
|------|------|
| 회원명 | 텍스트 (디바운스 300ms) |
| 상품명 | 텍스트 |
| 결제일 | 기간 범위 |
| 결제 ID | 직접 입력 |

### 결제 내역 확인

선택한 결제 건의 정보 카드.

| 항목 | 표시 |
|------|------|
| 결제일 | YYYY-MM-DD HH:mm |
| 상품명 | 멤버십/PT 등 |
| 결제 금액 | 천 단위 콤마 |
| 결제 수단 | 현장 카드/결제링크 카드/현금/계좌이체/포인트 |
| 결제자 | 회원명 + 담당자 |

### 환불 계산 박스

| 항목 | 설명 |
|------|------|
| 원결제 금액 | 결제 시 수납액 |
| 기사용 차감금 | 이미 사용한 회차·일수 환산 |
| 위약금 | 약관 기반 위약금 |
| 기환불 누계 | 이전 부분 환불 합계 |
| 이번 환불 가능액 | 자동 계산 (조정 가능) |
| 최종 환불액 | 입력값 (≤ 가능액) |

정책 미확정 상태의 1차 구현에서는 아래 항목을 수기 입력으로 받는다.

| 항목 | 수기 입력 목적 |
|------|------|
| 기사용 차감금 | 일할 계산, PT 사용 횟수, 기간권 사용일 등 클라이언트 정책 확정 전 운영 판단값 기록 |
| 위약금 | 정액/비율/상품별 예외 정책 확정 전 담당자 입력 |
| 기환불 누계 | 이전 부분 환불 금액 확인 전 수기 보정 |
| 이번 환불 가능액 조정 | 계산값과 다른 운영 확정값 입력 |
| 조정 사유 | 수기 입력 또는 조정 근거 필수 기록 |

### 혼합결제 환불 분해표

| 항목 | 설명 |
|------|------|
| 원수납 행 | 카드 / 현금 / 계좌이체 / 포인트별 원결제 행 |
| 기환불액 | 수단별 누적 환불액 |
| 이번 환불 배분액 | 이번 처리에서 각 수단에 배분되는 금액 |
| 잔여 가능액 | 수단별 남은 환불 가능액 |

### 처리 유형 선택

- **전체 취소**: 환불 가능액 전액 → 사유 입력 필수
- **부분 환불**: 직접 입력 (가능액 초과 불가) → 사유 입력 필수

### 환불 사유 입력

프리셋 사유 + 추가 의견.

| 사유 카테고리 | 예시 |
|---|---|
| 단순 변심 | 회원 변심 |
| 결제 오류 | 중복 결제 / 금액 오류 |
| 회원 요청 | 휴원·이사 |
| 서비스 불만 | 강사·시설 불만 |
| 기타 | 자유 입력 |

### 환불 수단 확인

원결제 수단에 따른 환불 방법 안내.

| 원결제 수단 | 환불 방법 |
|---|---|
| 현장 카드 | 외부 POS 환불 완료 후 CRM 기록 |
| 결제링크 카드 | PG 환불 후 webhook 상태 갱신 |
| 현금 | 현금/계좌 환불 완료 후 CRM 기록 |
| 계좌이체 | 계좌 이체 |
| 포인트 | 즉시 회복 |

외부 연동 정책이 확정되기 전에는 환불 수단, 외부 처리 상태, POS/PG 승인번호 또는 증빙 메모를 수기로 기록한다.

### 승인/귀속 수기 기록

| 항목 | 설명 |
|------|------|
| 처리 상태 | 요청 / 승인대기 / 완료 중 선택 |
| 승인 메모 | 지점장 승인 필요 조건이 확정되기 전 수기 기록 |
| 결제지점 | 원결제 발생 지점 |
| 이용지점 | 실제 이용 또는 수업 수행 지점 |
| 매출 귀속 지점 | 환불 차감 기준 지점 |
| 정산 지점 | 정산 반영 기준 지점 |
| 인센티브 귀속자 | 환불 시 환수 또는 차감 대상자 |

### 처리 확인 모달 (DLG-S013)

환불 금액·사유·수단을 최종 확인 → [처리 완료] → 처리 중 비활성 → 결과 모달(DLG-S014).

### 처리 완료 안내

성공 메시지 + SCR-S007 환불 관리로 이동 CTA.

### 처리 이력

해당 결제 건에 대해 이전 부분 환불 이력이 있으면 하단 목록 표시.

## 주요 UX 흐름

### 전체 취소 흐름
1. 사이드바 → "매출관리 > 결제 취소/부분 환불" 진입
2. 회원명·상품명·결제일·결제 ID로 결제 건 검색
3. 결제 내역 확인 + 환불 계산 박스 검토
4. "전체 취소" 선택 → 사유 입력
5. [처리 확인] → DLG-S013 → [처리 완료]
6. DLG-S014 결과 모달 → SCR-S007 이동

### 부분 환불 흐름
1. 결제 건 선택 → 환불 계산 박스 확인
2. "부분 환불" 선택 → 환불 금액 입력
3. 가능액 초과 시 경고
4. 사유·수단 확인 → [처리 확인]
5. DLG-S013 → 처리 완료 → 잔여 환불 가능액 갱신

### 위약금 / 기사용 차감 조정 흐름
1. 환불 계산 박스 → 위약금 / 기사용 차감 항목 클릭
2. 조정 입력 + 조정 사유 입력 (필수)
3. 이번 환불 가능액 자동 재계산
4. 운영 판단으로 진행

### 분기·예외 흐름
- **이미 전액 환불 건**: "이미 전액 환불된 건입니다" + 처리 차단
- **결제링크 미완료**: "환불 아닌 링크 취소로 처리" + SCR-S016 안내
- **결제경로별 환불 처리**: 현장 카드/현금은 외부 POS/현금 환불 완료 후 CRM 기록, 결제링크 카드는 PG 환불 (영업일 3~5일)
- **할부 진행 중 환불**: 잔여 미수금 상계 + 기납입액 환불, 잔여 회차 일괄 취소 (SAL-EXT-01 연계)
- **포인트 환불**: 즉시 포인트 잔액 회복, webhook 없음
- **결제링크 PG 환불 거절 webhook**: "처리 실패" 상태 + 운영자 알림, 익영업일 재시도
- **위약금 면제 권한 부족**: 면제 토글 hidden, 매니저 이상에게 요청 안내
- **부분 환불 가능액 0원**: 더 이상 환불 불가 안내
- **법인 회원 환불**: "마이너스 세금계산서 발행 필요" 알림 → SAL-EXT-02 진입 가능

## 비즈니스 규칙

1. **환불 계산 항목**: `기사용 차감금`, `위약금`, `기환불 누계`는 환불 상태가 아니라 환불 계산 항목.
2. **할부/미수 상계 우선**: 할부/미수 진행 중 결제는 남은 미수금과 먼저 상계한 뒤 실제 환불액 계산.
3. **결제링크 미완료**: 결제 미완료 링크는 환불이 아닌 링크 취소(SCR-S016 / DLG-S016)로 처리.
4. **조정 권한 + 사유 기록**: 담당자는 기사용 차감금·위약금·이번 환불 가능액을 조정할 수 있으며 조정 사유 필수 기록.
5. **최종 환불액 한도**: 최종 환불액 ≤ 확정된 환불 가능액. 초과 차단.
6. **자동 반영**: 처리 결과는 SCR-S007 환불 관리에 5초 이내 자동 반영, 감사 로그(SCR-097) append-only.
7. **결제경로별 환불 처리**: 현장 카드/현금은 외부 POS/현금 환불 완료 후 CRM 기록, 결제링크 카드는 PG 환불 (영업일 3~5일)과 webhook 비동기 갱신.
8. **포인트 환불**: 즉시 포인트 잔액 회복, webhook 없음, row-level lock 동시성 보장.
9. **현금/계좌 환불**: 계좌 이체로 환불, 회원 환불 계좌 정보 필수.
10. **부분 환불 누적**: 같은 결제 건의 부분 환불은 누적 추적, 가능액 = 원결제 - 기환불 누계 - 위약금 - 기사용.
11. **혼합결제 행 단위 잔액 관리**: 카드/현금/계좌이체/포인트별 잔여 환불 가능액을 별도로 관리하며, 부분 환불 시 각 행의 잔액을 차감한다.
12. **환불 귀속 유지**: 원결제의 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId`를 상속해 정산·KPI·인센티브 차감을 계산한다.
13. **이미 전액 환불 차단**: 이미 전액 환불 건은 추가 환불 차단.
14. **위약금 정책 (기본)**: 7일 이내 0% / 30일 이내 30% / 30일 초과 50% (정책 세트 기준).
15. **위약금 면제 권한**: 슈퍼관리자·센터장만 면제 가능, 면제 사유 필수.
16. **결제링크 PG 환불 거절 시 처리**: webhook 거절 응답 시 상태 "거절" + 운영자 알림, 익영업일 재시도.
17. **할부 환불 연계**: 할부 환불 시 SAL-EXT-01 잔여 회차 일괄 취소.
18. **법인 회원 환불**: 마이너스 세금계산서 발행 안내 (SAL-EXT-02 연계).
19. **권한별 가능 범위**: FC도 환불 처리 가능, 매니저 위약금 면제 ❌.
20. **idempotency**: 환불 요청은 idempotency-key로 중복 처리 차단.
21. **사유 카테고리**: 단순 변심 / 결제 오류 / 회원 요청 / 서비스 불만 / 기타 5종.
22. **부분 환불 최소 금액**: 1원 이상.
23. **선수익금 환불 영향**: 환불 시 SAL-04 선수익금 인식 차감.
24. **환불 이력 보관**: 5년 보관 (회계·세무).
25. **대량/고액 환불 알림**: 단일 환불 100만원 이상 또는 일별 10건 이상 시 본사 슈퍼관리자 알림.
26. **회원 탈퇴 후 환불**: 탈퇴 회원도 환불 가능 (회수 추진), 환불 계좌 필수.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SAL-EXT-04`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-S012`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-S013 환불처리, DLG-S014 환불상세결과, DLG-S015 환불요청`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
