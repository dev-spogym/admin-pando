## 기능 목적

처리된 환불 내역과 승인대기 환불 요청을 조회하고 통계를 확인하는 화면이다. 이번 달 환불 총액·건수·평균 환불액·위약금 합계를 파악하고, 기간별로 환불 이력을 조회한다. 환불 사유와 처리 상태, 승인자, 원판매 담당자별 환불 책임 현황을 함께 확인할 수 있어 고객 불만 패턴 파악 및 환불 정책 점검에 활용한다. 현장 영수증 첨부 등록 건은 외부 POS/현금 환불 완료 후 CRM에 기록된 환불로 조회하며, 결제링크 완료 건은 PG 환불/webhook 상태를 함께 조회한다. 지점장(owner)은 승인대기 건을 이 화면에서 확인하고 승인/반려 또는 상세 처리 화면으로 이동할 수 있다.

운영 맥락:
- **센터장 환불 승인 및 월말 점검**: 승인대기 건 확인 → 승인/반려 또는 상세 처리 → 이번 달 환불 총액·건수·위약금 합계 확인
- **본사 슈퍼관리자 지점별 환불률 비교**: 통합 모드에서 지점별 환불 건수·금액·환불률 모니터링 → 운영 품질 점검
- **매니저 특정 회원 환불 이력 추적**: 회원명 검색으로 반복 환불 회원 식별 → 마케팅 / CS 대응
- **FC 본인 담당 환불 책임 확인**: 원판매 담당자별 책임 탭에서 본인 환불률 확인 → 영업 품질 자가 점검
- **회계 마감 환불 정산**: 월별 환불 총액·위약금 합계 엑셀 다운로드 → 회계팀 마감 자료
- **고객 분쟁 사유 패턴 분석**: 환불 사유 4종(단순 변심·결제 오류·서비스 불만·회원 요청) 비율로 운영 개선
- **위약금 회수 규모 파악**: 위약금 합계 카드로 환불 시 차감 매출 회수 규모 확인
- **환불 경로 점검**: 현장 영수증 등록 건은 외부 POS/현금 환불 증빙 확인, 결제링크 건은 PG 환불/webhook 상태 확인

본 화면은 조회·분석 중심이며 실제 환불 처리는 SAL-EXT-04 결제 취소·부분 환불에서 수행한다.

이번 달 / 지난 달 / 최근 3개월 프리셋 + 직접 입력 + [조회].

| 컬럼 | 표시 |
|------|------|
| No / 환불일 / 요청일 / 회원명 / 상품명 | - |

| 환불방법 / 결제경로 / 원결제ID | - |
| 결제지점 / 이용지점 / 매출 귀속 지점 / 정산 지점 / 인센티브 귀속자 | 원결제 기준 + 환불 조정분 |
| 사유 | 보조 텍스트 |

### 엑셀 내보내기

현재 조회 환불 내역 전체 엑셀 다운로드.

## 주요 UX 흐름

### 환불 현황 조회
1. 사이드바 "매출관리 > 환불 관리" 진입
2. 상단 지표 카드로 환불 현황 + 위약금 회수 규모 파악
3. 날짜 프리셋 또는 직접 입력 + [조회]
4. 테이블에서 환불 이력·사유·상태·승인자·쿠폰/마일리지 복원 여부 확인
5. 원판매 담당자별 책임 탭으로 특정 담당자 환불 집중 여부 확인
6. 엑셀로 내역 저장

### 환불 상세 진입 (DLG-S006)
1. 테이블 행 클릭 → DLG-S006 상세 모달
2. 결제 정보 / 환불 내역 / 처리 이력 확인
3. 원결제 ID → SAL-01 매출 상세 진입 가능

### 분기·예외 흐름
- **SAL-EXT-04에서 환불 처리 후 본 화면 자동 반영**: webhook 또는 폴링으로 5초 이내 반영
- **승인대기 건 존재**: 상태 배지 "승인대기" 표시, owner에게 [승인/반려] 또는 [상세 처리] 액션 노출
- **환불 처리 중 결제링크 PG 응답 지연**: 상태 배지 "처리중(노랑)" 유지, webhook 수신 시 "완료(초록)"
- **현장 환불 증빙 누락/결제링크 PG 실패**: 상태 "거절(빨강)" + 운영자 알림, 증빙 보완 또는 익영업일 재시도
- **위약금 정책 변경 (정책 세트 갱신)**: 신규 환불부터 신정책 적용, 기존 환불 이력은 원정책 보존
- **원판매 담당자 퇴사**: 담당자명에 "퇴사" 라벨 + 환불률 집계는 유지
- **미결제 결제링크 환불 시도**: 환불 아닌 환불 진입 차단 + PAY-06 결제링크 무효화 안내 (PAY-06)
- **본사 통합 모드 + 지점 필터 해제**: 전체 지점 합산, 지점별 컬럼 추가 노출
- **엑셀 다운로드 30,000건 초과**: 비동기 백그라운드 다운로드 + 완료 알림

| 상태 | 설명 |
|---|---|
| 로딩 중 | 테이블 로딩 |
| 정상 표시 | 지표 + 테이블 |

| 처리 중 환불 있음 | "처리중" 배지 노랑 |
| 현장 환불 증빙 누락 / 결제링크 PG 실패 | "거절" 배지 빨강 + 알림 |
| 권한 미달 | 환불 처리 버튼 hidden |
| 오류 | 토스트 알림 |

## 비즈니스 규칙

1. **환불 자동 계산 미확정**: 위약금, 사용분 차감금, 기환불 누계, 환불 가능액, 최종 환불액은 SAL-EXT-04에서 수기 입력된 값을 표시한다. 본 화면에서 자동 산식으로 재계산하지 않는다.
2. **지점장 승인 표시**: manager/fc가 요청한 환불은 승인대기 상태로 표시하고, owner 승인 후 완료 처리한다. owner가 직접 처리한 건은 승인자와 처리자가 동일하게 표시된다.
3. **SAL-EXT-04 자동 반영**: 환불 처리는 SAL-EXT-04에서 수행되며 본 화면에 5초 이내 자동 반영.
4. **원판매 담당자 환불률**: 원매출 대비 환불률로 계산, 담당자별 영업 품질 지표.
5. **환불 사유 4종 + 자유 입력**: 단순 변심·결제 오류·회원 요청·서비스 불만 + 추가 의견.
6. **처리자/일시 자동 기록**: 환불 처리 시 처리자·일시 자동 기록, 감사 로그 INSERT.
7. **미결제 링크 환불**: 미결제 결제링크는 환불 목록과 환불 버튼에 노출하지 않는다. 직접 접근 시 환불 진입을 차단하고 PAY-06 결제링크 무효화 안내를 표시한다.
8. **환불 가능 윈도우**: 현장 영수증 등록 건은 외부 POS/현금 환불 완료 확인, 결제링크 카드 결제는 익영업일 PG 환불(3~5일).
9. **현금 환불**: 현금/계좌이체 결제는 계좌 이체로 환불, 회원 환불 계좌 정보 필수.
10. **마일리지(포인트) 우선 복원**: 환불 처리 시 결제에 사용한 마일리지(포인트)를 우선 복원하고, 복원 내역을 목록과 상세에 표시한다.
11. **쿠폰 복원 표시**: 환불된 결제에 사용 쿠폰이 있으면 쿠폰을 미사용 상태로 복원하고, 복원 성공/실패/만료 상태를 표시한다.
12. **부분 환불 제한**: 부분 환불은 원결제 금액 한도 내에서만 가능, 누적 환불 금액 추적.
13. **혼합결제 환불 추적**: 카드/현금/계좌이체/마일리지(포인트)별 원수납액, 기환불액, 잔여 환불 가능액을 행 단위로 추적한다.
14. **환불 귀속 기준 유지**: 환불 리포트는 원결제의 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId`를 상속해 KPI·정산 차감을 계산한다.
15. **할부 진행 중 환불**: 할부 진행 중 환불은 미수금 상계 + 잔여 환불액 수기 입력값 기준으로 처리한다 (SAL-EXT-04 위임).
16. **환불 승인 권한**: 실제 환불 실행과 승인대기 건 승인/반려는 슈퍼관리자·센터장만 가능하다. manager/fc는 요청만 가능하다.
17. **본사 통합 모드 권한**: 본사 슈퍼관리자만 전 지점 환불 통합 조회.
18. **퇴사 담당자 처리**: 원판매 담당자가 퇴사한 경우 "퇴사" 라벨 + 환불률 집계 유지.
19. **엑셀 다운로드 한도**: 30,000건 초과 시 비동기 백그라운드 다운로드, 완료 알림 발송.
20. **환불 이력 보관**: 5년 보관 (회계·세무 신고 기간), 5년 후 익명화.
21. **감사 로그**: 환불 조회·처리·취소 모두 SCR-097 기록 (`refund_id`, `actor_id`, `amount`, `reason`).
22. **거절 사유 기록**: 외부 환불 증빙 누락, 결제링크 PG 거절, 시스템 오류 등 거절 시 사유 자동 기록.
23. **반복 환불 회원 알림**: 동일 회원 3회 이상 환불 시 운영자에게 알림 (NFR-19).
24. **환불률 임계값**: 지점 월 환불률 5% 초과 시 본사 슈퍼관리자에게 알림.
25. **세금계산서 연계 환불**: 법인 회원 환불 시 세금계산서 마이너스 발행 안내 (SAL-EXT-02).

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-S007`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-S006 환불상세, DLG-S013 환불처리, DLG-S014 환불상세결과, DLG-S015 환불요청`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 표와 아래 API 기준을 같이 적용합니다.

- **연계 화면**: SCR-S001 / SCR-S012 / SCR-S010 세금계산서 / SCR-097 감사 로그 / SCR-074 포인트
- **연계 다이얼로그**: DLG-S006 / DLG-S013 / DLG-S014 / DLG-S015
- **API 기준**: `GET /api/refunds` / `POST /api/refunds` / `GET /api/refunds/by-staff` / `GET /api/refunds/export` / `GET /api/refunds/:id`
