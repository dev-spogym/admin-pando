## 기능 목적

아직 회원으로 등록되지 않은 잠재 고객(문의·상담 대상)을 등록하고, 7단계 상담 파이프라인(신규 → 연락완료 → 상담예정 → 방문완료 → 등록완료 / 미전환 / 보류)별 진행 상황을 추적해 회원 전환율을 높이는 마케팅 도메인의 핵심 화면이다. FC는 담당 리드의 후속 상담을 관리하고, 매니저는 전체 리드 전환율을 모니터링하며, 센터장은 가입경로별 ROI를 분석해 마케팅 예산을 배분한다. 칸반 DnD로 상담 단계를 직관적으로 변경하고 상담 상세 패널에서 메모·후속 액션·이력을 한 화면에서 처리한다.

운영 맥락:
- **신규 문의 즉시 등록**: 문의 유형 4종과 가입경로 9종을 분류해 등록, 담당 FC 자동 할당
- **칸반 DnD 단계 변경**: FC가 상담 결과를 카드 이동만으로 단계 변경, 변경 이력 자동 기록
- **후속 상담 일정 관리**: 후속 예정일 알림으로 미수행 상담 0건 운영 (HQ-09 CRM 후속 상담 정책 step + 지점 ON 상태 기준 자동 알림)
- **회원 전환 (등록완료)**: 리드에서 회원 등록/결제 흐름으로 진입하고 첫 정상 결제가 완료되면 등록완료 확정 + 리드↔회원 매핑
- **가입경로 ROI 분석**: 9종 가입경로별 등록 전환율로 마케팅 채널 효과 분석
- **미전환 사유 관리**: 미전환 단계 이동 시 사유 입력 (가격·거리·시간·경쟁·기타) → 마케팅 전략 반영
- **장기 보류 리드 재활성**: 보류 30일 경과 시 재상담 후속 액션 자동 등록
- **외부 [신규DB] 연동**: C열 문의 유형, D/E열 가입경로, N/R/V열 1차·2차·3차 상담 방식 자동 임포트

요약 카드(전환율·미전환율) + 상태 분포(7종 컬럼) + 칸반 DnD + 상담 상세 패널을 한 화면에 통합해 FC 1명이 30~50건 리드를 실시간으로 관리할 수 있도록 설계되었다.

## 주요 구성요소

### 요약 지표 카드 (5개)

| 카드 | 내용 |
|------|------|
| 전체 리드 수 | 합계 |
| 등록 전환 수 | 등록완료 카운트 |
| 전환율 | 등록완료 / 전체 |
| 대기 중 | 신규 + 연락완료 |
| 미전환율 | 미전환 / 전체 |

### 상태별 분포 카드 (7종)

신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류. 0건 상태는 숨김.

### 필터

| 필터 | 옵션 |
|------|------|
| 상태 | 7종 (다중) |
| 가입경로 | 간판 / 블로그 / 인스타 / 당근 / 지역카페 / 현수막 / 전단지 / 회원소개 / 기타 |
| 문의 유형 | WI(방문) / TI(전화문의) / 체험 / 일일입장 |

### 뷰 전환

목록 뷰(테이블) ↔ 칸반 뷰(상태별 컬럼).

### 리드 목록 테이블

| 컬럼 | 설명 |
|------|------|
| 문의일 | YYYY-MM-DD |
| 이름 | 클릭 시 상세 패널 |
| 연락처 | 010 자동 |
| 가입경로 | 9종 |
| 상담 단계 | 7종 배지 |
| 담당 FC | 클릭 시 STF-02 |
| 후속 예정일 | YYYY-MM-DD |
| 메모 | 미리보기 |
| 액션 | [수정] / [삭제] |

### 상담 방식 컬럼

외부 `[신규DB]` N/R/V열의 1차·2차·3차 상담 방식. 값은 `대면`, `유선`, `부재` 제한.

### 칸반 뷰

상태 컬럼 배치 + DnD 단계 변경. 카드 이동 시 단계 변경 이력 자동 기록.

### 상담 상세 패널

리드 카드/행 클릭 → 우측 패널 슬라이드.

| 영역 | 기능 |
|------|------|
| 메모 | 작성·수정·삭제 |
| 후속 액션 등록 | 전화/방문/문자 예정 + 일정 |
| 단계 변경 이력 | 타임라인 |

### 리드 등록

[+ 리드 등록] → DLG-070-001.

## 주요 UX 흐름

### 정상 칸반 운영 흐름
1. 사이드바 → "마케팅 > 리드 관리" 진입
2. 요약 카드 5종(전체/등록/전환율/대기/미전환율) + 상태 분포 7종 카드로 현황 파악
3. 필터 적용(상태 다중·가입경로 9종·문의 유형 4종)
4. 칸반 뷰 전환 → 카드 DnD로 컬럼 간 이동 → 단계 변경
5. 단계 변경 즉시 변경 이력 자동 INSERT, 전환율 통계 자동 재계산
6. 카드 클릭 → 우측 상담 상세 패널 슬라이드 (메모·후속 액션·타임라인)

### 리드 등록 흐름
1. [+ 리드 등록] → DLG-070-001
2. 이름(필수) + 연락처(필수, 010 자동) + 가입경로(9종) + 문의 유형(WI/TI/체험/일일입장) + 담당 FC 지정 + 메모 입력
3. 저장 → 신규 단계로 추가 + 담당 FC에게 알림 발송 + 감사 로그 기록

### 상담 진행 흐름
1. 카드 클릭 → 상담 상세 패널 진입
2. 메모 작성·수정·삭제
3. 후속 액션 등록 (전화/방문/문자 + 예정 일시)
4. 단계 변경 (DnD 또는 패널 셀렉트)
5. 단계 변경 이력 타임라인 자동 갱신

### 등록완료(회원 전환) 흐름
1. 카드 → 등록완료 컬럼 DnD 또는 상담 상세 패널 [회원 등록/결제 진행] 클릭
2. "회원 등록 및 결제로 전환하시겠습니까?" 확인 모달
3. 확인 → 회원 등록 화면(SCR-M002)에 리드의 이름·연락처·문의 유형·가입경로를 전달
4. SCR-M002에서 첫 정상 결제가 완료되면 회원 등록이 확정되고 리드↔회원 매핑 저장
5. 등록 전환수 +1 + 전환율 자동 갱신, 회원 상세(SCR-M004)로 이동

### 분기·예외 흐름
- **연락처 중복 등록 시도**: "동일 연락처의 리드가 이미 존재합니다" + 기존 리드 카드 노출 + [기존 리드 보기] / [신규 등록 강행]
- **연락처가 기존 회원과 일치**: "이미 회원으로 등록된 번호입니다" + 회원 카드 노출 + 리드 등록 차단
- **등록완료 → 다른 단계 회귀 시도**: "이미 회원으로 전환된 리드입니다" 모달 + 회귀 차단 (단, 슈퍼관리자만 강행 가능)
- **미전환 단계로 이동 시 사유 미입력**: 사유 모달 표시(가격/거리/시간/경쟁/기타·텍스트) + 미입력 시 단계 변경 차단
- **보류 30일 경과 리드**: 카드 노랑 테두리 + "보류 30일 경과" 배지 + 후속 액션 자동 등록 권유
- **FC 권한으로 다른 FC 담당 리드 수정 시도**: 조회만 허용, [수정] 버튼 hidden, 단계 변경도 본인 담당만 (정책 모드에 따라 변경)
- **FC가 [삭제] 시도**: 버튼 hidden (삭제 권한 없음)
- **칸반 DnD 락 충돌 (동시 변경)**: "다른 운영자가 변경 중입니다, 새로고침 후 시도" 모달
- **외부 신규DB 엑셀 형식 오류**: C/D/E/N/R/V열 누락 시 "필수 컬럼이 누락되었습니다" + 미임포트
- **상담 방식 값 외 입력**: `대면`/`유선`/`부재` 외 값은 "잘못된 값입니다" + 미저장
- **후속 예정일 과거 입력**: "후속 예정일은 오늘 이후로 입력해주세요" 인라인 에러
- **가입경로 9종 외 신규 경로**: 운영자가 [기타] 선택 + 텍스트 메모로 보충
- **회원 전환 후 기존 리드 메모**: 회원 상세(SCR-M004) 내 메모 영역으로 자동 이관
- **타 지점 리드 (전사 모드 운영자만)**: 통합 모드에서 다른 지점 리드 조회 가능, 단 수정은 해당 지점 권한자만
- **삭제 후 복구 요청**: 30일 이내는 휴지통(soft delete)에서 복원 가능, 30일 경과 시 영구 삭제

| 칸반 열 비어있음 | "없음" |

## 비즈니스 규칙

1. **상담 단계 7종 고정**: 신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류. 변경 시 변경 이력 자동 기록.
2. **가입경로 9종**: 간판 / 블로그 / 인스타 / 당근 / 지역카페 / 현수막 / 전단지 / 회원소개 / 기타. 등록 시 필수 선택. 외부 `[신규DB]` D열 `상세 경로1`과 E열 `상세 경로2`는 CRM 내부에서 단일 가입경로로 통합 매핑한다. D/E열 값이 동시에 있으면 9종과 직접 매칭되는 더 구체적인 값을 우선 사용하고, 둘 다 매칭되지 않으면 `기타`로 집계한다.
3. **문의 유형 4종**: WI(방문) / TI(전화문의) / 체험 / 일일입장. 외부 `[신규DB]` C열 매핑 값으로 저장. 화면 라벨 `방문`은 `WI`, `전화문의`는 `TI`로 매핑.
4. **상담 방식 3종**: `대면`/`유선`/`부재`. 외부 `[신규DB]` N/R/V열 1차·2차·3차 상담 방식. 외 값 입력 시 차단.
5. **연락처 중복 검증**: 동일 연락처 리드 등록 시 기존 카드 노출 후 신규 등록 여부 확인. 기존 회원 번호와 일치하면 신규 리드 등록 차단.
6. **등록완료 회원 전환**: 첫 정상 결제 완료로 회원 등록이 확정될 때 등록완료 단계로 전환하고 리드↔회원 매핑(`lead_member_map`)을 저장한다. 결제 전에는 등록완료로 확정할 수 없으며 등록완료 회귀는 차단한다.
7. **미전환 사유 필수**: 미전환 단계 이동 시 사유 모달(가격/거리/시간/경쟁/기타) 필수 입력. 미입력 시 단계 변경 차단.
8. **DnD 단계 변경 락**: 동시 변경 시 optimistic lock으로 충돌 감지 → 후행 변경 차단 + 새로고침 안내.
9. **칸반 DnD 변경 이력**: `lead_stage_history`에 (lead_id, from_stage, to_stage, actor_id, ts, reason) append-only INSERT.
10. **전환율 자동 계산**: 등록완료 / 전체 리드 = 전환율. 카드 이동·등록·삭제 시 즉시 재계산. 5분 캐시.
11. **미전환율 자동 계산**: 미전환 / 전체. 동일 캐시 정책.
12. **FC 가시성**: 본인 담당 리드를 우선 표시하지만 소속 센터 전체 리드는 조회·수정 가능. 삭제 권한은 없음.
13. **FC 단계 변경 권한**: 본인 담당 리드만 단계 변경 가능 (정책 모드: `strict_owner` 또는 `branch_open`).
14. **삭제 권한**: 슈퍼관리자 / 센터장 / 매니저 가능. FC는 삭제 불가. 30일 휴지통 보관 후 영구 삭제 (soft delete).
15. **후속 예정일 정책**: 오늘 이후만 입력 가능. 알림 기준일은 HQ-09 CRM 후속 상담 정책 step 값을 따르며, 해당 지점에서 센터장(owner)이 ON으로 둔 step만 발송한다. 미수행 시 카드 빨강 표시.
16. **보류 30일 경과**: 자동 노랑 배지 + 후속 액션 등록 권유 알림. 60일 경과 시 자동 미전환 전환 옵션 (테넌트 정책).
17. **외부 신규DB 임포트**: 엑셀 업로드 시 C열(문의 유형) + D/E열(가입경로) + N/R/V열(상담 방식) 매핑. 필수 컬럼 누락 시 임포트 차단.
18. **가입경로 ROI 분석**: 가입경로별 전환율(등록완료 / 해당 가입경로 전체)을 일별·주별로 집계. 마케팅 예산 배분 근거.
19. **담당자 성과 분리**: 상담 성과 담당자는 리드의 담당 FC로 관리하고, 매출 성과 담당자는 첫 정상 결제 완료 시점의 판매 담당자/인센티브 귀속자로 관리한다. 가입경로는 유입 채널이며 직원을 구분하는 값으로 사용하지 않는다.
20. **이름 정책**: 1~30자, 특수문자 일부 허용 (이모지 차단).
21. **연락처 정책**: 010-XXXX-XXXX 형식 자동 포맷. 외국인 연락처는 +82 허용.
22. **권한별 가시성**:
    - 슈퍼관리자: 전 지점 리드 + 통합 모드
    - 센터장: 소속 지점 전체 리드 + 등록·수정·삭제·DnD
    - 매니저: 소속 지점 전체 리드 + 등록·수정·삭제·DnD
    - FC: 소속 지점 전체 조회 + 본인 담당 우선 표시 + 등록·수정·DnD (삭제 불가)
    - 트레이너 / 스태프: 마케팅 도메인 접근 불가
    - readonly: 차단
23. **감사 로그**: 등록·수정·삭제·단계 변경·후속 액션·회원 전환 모두 SCR-097 기록 (`actor_id`, `lead_id`, `action`, `old_value`, `new_value`).
24. **세그먼트 연계**: CRM 리드를 세그먼트 조건으로 사용 가능 (예: "30일 이상 보류 리드", "회원소개 가입경로 리드").
25. **메시지 발송 연계 (MKT-01)**: 리드 대상 그룹을 수신자로 선택 가능. 미전환 리드 재마케팅에 활용.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `CRM-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-070`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-070-001 리드등록수정, DLG-070-002 리드삭제확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
