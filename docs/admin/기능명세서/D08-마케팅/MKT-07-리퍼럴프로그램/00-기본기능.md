## 기능 목적

기존 회원이 지인을 추천해 새 회원을 유치하면 추천인·피추천인 양쪽에게 혜택(마일리지/쿠폰/할인)을 제공하는 리퍼럴 프로그램을 설정·실행·실적 관리하는 화면이다. 회원앱에서 회원별 고유 추천 코드를 자동 발급해 SNS·카톡으로 공유하고, 피추천인 등록 시 자동 매칭으로 양방향 혜택 자동 지급한다. 구전 마케팅을 체계화해 신규 회원 유치 비용(CAC)을 광고 대비 1/3~1/5 수준으로 절감한다.

운영 맥락:
- **이벤트 등록**: 추천인 5,000원 쿠폰 + 피추천인 10% 할인 양방향 혜택 설계
- **추천 코드 자동 발급**: 회원앱에서 회원별 고유 코드 (예: REF-홍길동-A1B2) 자동 생성
- **외부 공유**: 회원이 카톡·SNS·문자로 코드 공유
- **피추천인 등록 시 자동 매칭**: 등록 화면에 추천 코드 입력 → 매칭 → 양방향 혜택 자동 지급
- **1인당 추천 제한**: 1인당 {인원수}명 한도 (예: 1인 5명) 설정 가능
- **혜택 자동 지급**: 피추천인의 첫 정상 결제 완료로 등록완료가 확정되는 시점에 양쪽 마일리지/쿠폰 자동 지급
- **추천 이력**: 추천인↔피추천인 매핑 + 전환 여부 + 혜택 지급 상태 추적
- **MKT-06 캠페인 연동**: 캠페인에 리퍼럴 이벤트를 연결해 통합 운영
- **이벤트 종료 후 진행 중 추천 처리**: 종료 후 30일 이내 등록은 정상 매칭 (그레이스 기간 정책)
- **혜택 미지급 사유 추적**: 휴면·차단·정책 위반 등 미지급 사유 기록

이벤트 목록 + DLG-077-001 등록 + 실적 현황 + 추천 이력 + DLG-077-002 삭제 위자드로 구성된다.

## 주요 UX 흐름

### 이벤트 등록 흐름
1. 사이드바 → "마케팅 > 리퍼럴 프로그램" 진입
2. [이벤트 등록] → DLG-077-001
3. 이벤트명 + 추천인 혜택(마일리지/쿠폰/할인) + 피추천인 혜택 + 추천 코드 발급 방식(자동/수동) + 기간 + 1인 최대 추천 횟수 입력
4. 저장 → 준비 상태 + 시작일에 회원앱 코드 자동 발급

### 추천 코드 발급 흐름 (자동)
1. 시작일 도래 시 회원앱에 회원별 고유 코드 자동 생성 (예: REF-회원ID-랜덤)
2. 회원이 회원앱 추천 화면에서 코드 확인 + 카톡·SNS·문자 공유

### 매칭 흐름 (피추천인 등록)
1. 신규 회원 등록 화면에서 추천 코드 입력 (선택)
2. 코드 검증 (존재·유효 기간·1인 한도·휴면·블랙리스트)
3. 매칭 성공 → `referral_match` INSERT (추천인·피추천인·이벤트)
4. 첫 정상 결제 완료로 등록완료가 확정되는 시점에 양방향 혜택 자동 지급 (마일리지/쿠폰 발급)
5. 추천인·피추천인에게 알림 발송

### 실적 모니터링 흐름
1. 실적 카드 (전체 추천 건수 / 성공 전환 / 지급된 혜택 합계)
2. 추천 이력 목록 (추천인·피추천인·추천 일시·전환 여부·혜택 지급)
3. [지급 대기] 행 → 사유 확인 → 수동 지급 또는 정책 적용

### 분기·예외 흐름
- **추천 코드 입력 누락**: 매칭 없이 일반 등록만 진행
- **추천 코드 미유효 (오타·만료)**: "추천 코드가 유효하지 않습니다" 안내 + 매칭 실패
- **이벤트 종료 후 매칭 시도**: 그레이스 기간(7~30일) 내면 매칭 + 종료 후 진행 처리, 경과 시 매칭 차단
- **1인 추천 한도 도달**: "추천 한도 초과" 안내 + 매칭 차단
- **휴면 추천인**: "휴면 회원은 추천 불가" + 매칭 차단
- **블랙리스트 추천인 / 피추천인**: 매칭 차단 + 운영자 알림
- **본인이 본인 코드 사용**: "본인 추천 불가" 차단
- **가족 회원끼리 추천 (MBR-EXT-02)**: 정책에 따라 차단 또는 허용
- **이미 회원인 사람이 코드 사용**: "기존 회원은 피추천 불가" 차단 (재등록 회원은 정책에 따라)
- **부정 사용 의심 (동일 IP 반복)**: 자동 감지 + 매칭 보류 + 운영자 알림
- **혜택 지급 실패 (마일리지 적립 webhook 오류)**: 자동 재시도 3회 + 미지급 상태 유지
- **이벤트 삭제 시 진행 중 매칭**: 진행 중 매칭은 정상 처리, 신규 매칭은 차단
- **이벤트 수정 시 기존 매칭**: 기존 매칭은 기존 혜택 지급, 신규 매칭부터 변경 적용
- **추천 코드 발급 방식 (수동)**: 매니저가 회원에게 수동으로 코드 부여 (오프라인 캠페인용)
- **혜택 종류 변경 시도**: 진행 중 이벤트의 혜택 변경 차단 (신규 이벤트 등록 권유)
- **양방향 혜택 1개만 지급되는 경우**: 추천인 또는 피추천인 휴면·블랙리스트 시 한쪽만 지급 (정책)
- **회원 탈퇴 시 추천 이력**: 이력 보존, 미지급 혜택은 소멸
- **회원 병합 (MBR-EXT-01) 시 추천 이력**: 부 계정 추천 이력 → 주 계정으로 합산
- **본사 통합 vs 지점 이벤트 동시 운영**: 본사 우선 또는 둘 다 적용 (정책)
- **법정 한도 (사례비 100만원 한도)**: 정책에 따라 추천 보상 누적 100만원/년 제한 (세무 의무)

## 비즈니스 규칙

1. **추천 코드 발급**: 회원앱에서 회원별 고유 코드 자동 발급 (예: REF-회원ID-랜덤). 수동 발급 옵션 (오프라인 캠페인용).
2. **양방향 혜택**: 추천인·피추천인 각각 혜택 설계. 마일리지 / 쿠폰 / 할인 중 선택 (다중 가능).
3. **자동 매칭**: 피추천인 등록 시 추천 코드 입력 → 자동 매칭 → 첫 정상 결제 완료로 등록완료 확정 시 양방향 혜택 자동 지급.
4. **1인 추천 한도**: 1인당 {인원수}명 제한 (기본 5명, 정책으로 변경 가능). 도달 시 매칭 차단.
5. **이벤트 기간**: 시작 ≤ 종료. 종료 후 그레이스 기간(7~30일) 내 매칭은 정상 처리.
6. **본인 추천 차단**: 본인이 본인 코드 사용 차단.
7. **휴면 / 블랙리스트 차단**: 휴면 또는 블랙리스트 회원의 추천·피추천 차단.
8. **가족 회원 추천 차단 (MBR-EXT-02)**: 동일 가족 그룹 멤버끼리 추천 정책에 따라 차단 또는 허용.
9. **기존 회원 피추천 차단**: 이미 회원인 사람이 코드 사용 시 차단. 단, 재등록 회원은 정책에 따라.
10. **부정 사용 감지**: 동일 IP 반복 매칭 / 비정상 패턴 감지 → 매칭 보류 + 운영자 알림.
11. **상태 3종**: 준비 / 진행 / 종료. 시작일 자동 활성, 종료일 자동 종료.
12. **혜택 자동 지급**: 첫 정상 결제 완료로 등록완료가 확정되는 시점에 양방향 자동 지급. webhook 실패 시 재시도 3회 + 미지급 상태.
13. **혜택 지급 실패 처리**: 운영자가 추천 이력에서 [지급 대기] 행 클릭 → 사유 확인 → 수동 지급.
14. **회원 탈퇴 시 처리**: 이력 보존, 미지급 혜택은 소멸. 지급된 혜택은 정책에 따라 회수 또는 유지.
15. **회원 병합 (MBR-EXT-01)**: 부 계정 추천 이력 → 주 계정으로 합산.
16. **이벤트 삭제 정책**: 진행 전 hard delete. 진행 중 / 종료는 soft delete (이력 보존).
17. **이벤트 수정 정책**: 진행 전 전체 수정. 진행 중 혜택 종류·금액 변경 차단 (신규 이벤트 등록 권유).
18. **법정 한도**: 추천 보상 누적 100만원/년 제한 (세무 의무, 정책).
19. **본사 통합 이벤트**: 슈퍼관리자가 전 지점 일괄 등록. 지점 이벤트와 동시 운영 시 정책에 따라 충돌 처리.
20. **추천 코드 정책**: 영숫자 8~16자. 회원 ID 또는 이름 일부 포함 가능 (선택).
21. **권한별 가시성**:
    - 슈퍼관리자: 전 지점 이벤트 + 본사 통합
    - 센터장 / 매니저: 소속 지점 이벤트 + 등록·수정·삭제·실적
    - FC / 트레이너 / 스태프 / readonly: 차단
22. **추천 이력 영구 보존**: 이벤트 종료 후에도 영구 보존 (분석·세무 의무).
23. **MKT-06 캠페인 연동**: 캠페인에 리퍼럴 이벤트 연결 가능. 통합 ROI 분석.
24. **감사 로그**: 등록·수정·삭제·매칭·혜택 지급·미지급 사유 모두 SCR-097 기록.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MKT-07`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-077`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-077-001 리퍼럴등록, DLG-077-002 리퍼럴삭제`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
