## 기능 목적

할인 쿠폰을 생성·관리하고 특정 회원·그룹·등급에게 발급하는 화면이다. 정액(원 차감) / 정률(% 할인) 2종, 유효 기간 / 발급 수량 제한 / 1인 사용 제한 / 적용 상품 다중 선택으로 다양한 마케팅 시나리오를 지원한다. 매니저는 쿠폰별 발급 / 사용 / 사용률 통계로 마케팅 효과를 파악하고, 슈퍼관리자는 본사 통합 쿠폰 정책을 운영한다.

운영 맥락:
- **신규 회원 환영 쿠폰**: 등록 감사 알림과 함께 환영 쿠폰 자동 발급 (5,000원 정액)
- **재등록 권유 쿠폰**: 만료 회원에게 10% 정률 쿠폰 발급, 알림톡 동시 발송
- **VIP 등급 보상 쿠폰**: VIP 회원 그룹 일괄 발급 (월 1회)
- **이벤트 쿠폰**: 신년·생일·기념일 한정 쿠폰 (수량/기간 제한)
- **추천 보상 쿠폰**: 리퍼럴 프로그램(MKT-07)과 연동된 양방향 혜택
- **PT 패키지 한정 쿠폰**: 적용 상품을 PT 패키지로 제한
- **쿠폰 만료 자동 처리**: 유효 기간 종료 시 "만료" 상태 자동 전환, 신규 발급 차단
- **사용 중 쿠폰 보호**: 발급되었지만 미사용된 쿠폰은 삭제 차단 → "중단"으로 전환
- **사용률 분석**: 쿠폰별 사용률(사용/발급)로 효과 비교 → 마케팅 전략 조정

요약 카드(전체/발급/사용/평균 사용률) + 쿠폰 목록 + 쿠폰 사용률 통계 + 쿠폰 생성/수정 폼 + 쿠폰 발급 폼 + 쿠폰 삭제 확인 절차로 구성되어 있다. 쿠폰 사용률 통계는 발급 대비 실제 사용 현황을 보여주는 운영 지표이며, 별도 매출 ROI 산정·AI 추천·자동 마케팅 진단은 포함하지 않는다.

## 주요 구성요소

### 요약 지표 카드 (4개)

| 카드 | 내용 | 집계 기준 |
|------|------|------|
| 전체 쿠폰 수 | 조회 권한 범위 안에 등록된 쿠폰 수 | 활성 / 만료 / 중단 상태 쿠폰 포함, 삭제된 쿠폰 제외 |
| 발급 건수 | 회원에게 발급 완료된 쿠폰 누적 건수 | 현재 필터 조건의 쿠폰 발급 이력 합계. 중단 쿠폰도 이미 발급된 이력은 포함 |
| 사용 건수 | 결제에서 실제 사용 완료된 쿠폰 건수 | 현재 사용 완료 상태 기준. 환불로 미사용 복원된 쿠폰은 사용 건수에서 제외하고 사용 이력에는 남김 |
| 평균 사용률 | 발급 대비 실제 사용 비율 | 사용 건수 ÷ 발급 건수 × 100. 발급 건수 0건이면 0%로 표시 |

### 쿠폰 목록 테이블

| 컬럼 | 설명 |
|------|------|
| 쿠폰명 | 이름 |
| 할인 유형 | 정액 / 정률 |
| 할인 금액·율 | 원 또는 % |
| 유효 기간 | 시작 ~ 종료 |
| 발급 수 | 발급 카운트 |
| 사용 수 | 사용 카운트 |
| 사용률 | % |
| 상태 | 활성 / 만료 / 중단 |
| 액션 | [발급] / [수정] / [삭제] |

### 상태 필터

활성 / 만료 / 중단 필터.

### 쿠폰 사용률 통계

| 통계 항목 | 설명 |
|------|------|
| 발급 수 | 선택 기간 또는 현재 필터 기준으로 회원에게 발급 완료된 건수 |
| 사용 수 | 결제에서 실제 사용 완료된 건수. 환불로 미사용 복원된 건은 현재 사용 수에서 제외 |
| 미사용 수 | 발급 수 - 현재 사용 수 - 만료/중단으로 더 이상 사용 불가한 건수 |
| 환불 복원 수 | 환불 처리로 미사용 상태로 복원된 쿠폰 건수 |
| 사용률 | 사용 수 ÷ 발급 수 × 100. 발급 수 0건은 0% |

쿠폰별 통계는 쿠폰 목록 행 단위로 위 항목을 표시하고, 사용률 높은 순 / 낮은 순 정렬을 제공한다. 기간별 통계는 발급일 또는 사용일 기준으로 조회 기간을 선택해 같은 항목을 재집계한다. `효과 분석`은 사용률·미사용 수·환불 복원 수를 기준으로 쿠폰별 성과를 비교하는 단순 운영 분석이며, 매출 기여도·재구매 전환율·AI 추천은 개발 범위에 포함하지 않는다.

### 쿠폰 생성 / 수정 폼

| 항목 | 입력 |
|------|------|
| 쿠폰명 | 텍스트 (필수) |
| 할인 유형 | 정액 / 정률 |
| 할인 값 | 원 또는 % |
| 유효 기간 | 시작 ~ 종료 |
| 발급 수량 제한 | 무제한 / 숫자 |
| 1인 사용 제한 | 1회 / 무제한 |
| 적용 상품 | 다중 선택 |
| 활성 여부 | 토글 |

### 쿠폰 발급 폼

| 항목 | 입력 |
|------|------|
| 발급 대상 | 회원 검색 / 그룹 / 등급 |
| 발급 수량 | 자동 또는 수동 |
| 발급 안내 메시지 | 고객사 확인 필요. 쿠폰 발급 완료 후 회원에게 자동 메시지를 보낼지, 메시지를 입력한 경우에만 보낼지, 발송하지 않을지 확정 전까지 개발 대기 |

### 쿠폰 삭제 확인 / 중단 전환

쿠폰 삭제 버튼 클릭 시 삭제 가능 여부를 확인한다. 발급·사용 이력이 전혀 없는 쿠폰만 영구 삭제할 수 있다. 발급 이력 또는 사용 이력이 있는 쿠폰은 영구 삭제하지 않고 `중단` 상태로 전환해 신규 발급을 차단하며, 이미 발급된 쿠폰은 기존 정책에 따라 사용 가능 상태를 유지한다.

## 주요 UX 흐름

### 쿠폰 생성 흐름
1. 사이드바 → "마케팅 > 쿠폰 관리" 진입
2. [쿠폰 생성] 클릭 → 쿠폰 생성/수정 폼을 빈 상태로 열기
3. 쿠폰명(필수, 1~50자) + 할인 유형(정액/정률) + 할인 값 + 유효 기간 + 발급 수량 제한(무제한/N매) + 1인 사용 제한(1회/N회/무제한) + 적용 상품(다중 선택) + 활성 토글
4. 저장 → 목록 추가 + 활성 상태

### 쿠폰 발급 흐름
1. 행 [발급] 클릭 → 쿠폰 발급 폼 열기
2. 발급 대상 선택 (회원 검색 / 그룹 / 등급)
3. 발급 수량 (자동 또는 수동)
4. 발급 안내 메시지 자동 발송 여부는 고객사 확인 필요. 확정 전에는 메시지 입력/발송을 개발하지 않고 쿠폰 발급만 처리
5. 발급 → 발급 이력 기록 + 발급 카운트 갱신. 회원 알림 발송은 고객사 확정 후 적용

### 쿠폰 사용 흐름 (결제 시)
1. 결제 화면(SCR-S003)에서 회원 보유 쿠폰 목록
2. 적용 상품 검증 + 1인 사용 제한 검증 + 유효 기간 검증
3. 쿠폰 적용 → 결제 금액 차감 + 사용률 통계 +1

### 쿠폰 삭제 흐름
1. 행 [삭제] 클릭 → 쿠폰 삭제 확인 다이얼로그 열기
2. 발급·사용 이력 검사: 발급·사용 이력이 모두 없으면 영구 삭제 가능
3. 발급 이력 또는 사용 이력이 있으면 영구 삭제를 차단하고 "중단" 전환만 제공
4. 확인 텍스트 입력 → 영구 삭제 또는 중단 전환 확정

### 분기·예외 흐름
- **정률 쿠폰 0% 또는 100% 초과**: 인라인 "1~100% 범위로 입력해주세요" + 저장 차단
- **정액 쿠폰 0원 이하**: 인라인 "0원 초과로 입력해주세요" + 저장 차단
- **유효 기간 시작 > 종료**: "시작일이 종료일보다 늦을 수 없습니다" + 저장 차단
- **유효 기간 만료**: 자동 "만료" 상태 전환 + 발급 버튼 비활성
- **발급 수량 제한 도달**: "발급 한도 도달" + 발급 비활성
- **1인 사용 제한 도달 회원에게 발급**: 발급은 가능하나 결제 시 사용 차단 + 안내
- **적용 상품 외 결제 시도**: "이 쿠폰은 {상품명}에서만 사용 가능합니다" + 적용 차단
- **사용 중 쿠폰 삭제 시도**: 안내 모달 + "중단"으로 전환 옵션만 제공 (hard delete 차단)
- **만료 쿠폰 발급 시도**: 발급 버튼 비활성
- **중단 쿠폰**: 신규 발급 차단, 기존 발급분은 사용 가능 (정책)
- **회원 보유 쿠폰 중복 발급**: "이미 보유 중" 안내 + 중복 발급 차단 옵션 (또는 정책에 따라 허용)
- **결제 환불 시 쿠폰 처리**: 환불 처리 완료 시 사용된 쿠폰은 미사용 상태로 복원하고, 복원 이력을 남긴다.
- **발급 안내 메시지 발송 실패(확정 후 적용)**: 쿠폰 발급은 성공으로 유지하고, 메시지 실패 처리는 고객사 확정된 재시도 정책에 따름
- **FC 권한으로 쿠폰 생성 시도**: 버튼 hidden (FC는 발급만 가능)
- **다중 적용 상품 모두 단종**: 쿠폰 자동 비활성 + 운영자 알림
- **할인 금액 > 결제 금액**: 결제 금액 0원으로 처리, 차액 미환급
- **쿠폰 + 마일리지 동시 적용**: 결제 적용 순서는 상품/할인 정책을 따르되, 환불 복원은 마일리지 우선 복원 후 쿠폰 복원 순서로 처리한다.
- **쿠폰명 중복**: 동일 지점 내 중복 허용 (다른 캠페인일 수 있음)

## 비즈니스 규칙

1. **할인 유형 2종**: 정액(원 차감) / 정률(% 할인). 정액 0원 초과, 정률 1~100% 검증.
2. **유효 기간**: 시작일·종료일 입력. 시작일 ≤ 종료일 검증. 만료 시 자동 "만료" 상태 전환.
3. **발급 수량 제한**: 무제한 또는 N매. 도달 시 발급 차단.
4. **1인 사용 제한**: 1회 / N회 / 무제한. 결제 시 회원별 사용 카운트 검증.
5. **적용 상품 다중 선택**: 전체 상품 또는 특정 상품 다중 선택. 결제 시 적용 상품 검증.
6. **상태 4종**: 활성 / 만료 / 중단 / 비활성. 자동 전환 또는 운영자 수동.
7. **자동 사용률 계산**: 사용률 = 사용 수 ÷ 발급 수 × 100. 결제 사용·환불 복원·발급 취소 시 즉시 무효화하고 5분 캐시로 재집계한다. 환불로 미사용 복원된 쿠폰은 현재 사용 수에서 제외한다.
8. **삭제 정책**: 발급·사용 이력이 모두 없으면 hard delete. 발급 이력 또는 사용 이력이 있으면 "중단"으로 soft delete만 허용.
9. **쿠폰 사용 (결제)**: 결제 화면(SCR-S003)에서 보유 쿠폰 목록 표시. 자동 차감 + 사용률 통계 +1.
10. **할인 금액 > 결제 금액**: 결제 금액 0원 처리, 차액 미환급 (정책).
11. **쿠폰 + 마일리지 동시 적용**: 결제 시 적용 우선순위는 결제 정책을 따르며, 환불 시 복원 우선순위는 마일리지 우선 복원 후 쿠폰 복원이다.
12. **환불 시 쿠폰 복원**: 환불 처리 완료 시 해당 결제에 사용된 쿠폰은 미사용 상태로 복원한다. 이미 유효기간이 만료된 쿠폰도 복원 이력과 만료 상태를 함께 표시한다.
13. **발급 시 회원 알림**: 고객사 확인 필요. 쿠폰 발급 완료 후 회원에게 자동 메시지를 보낼지, 메시지를 입력한 경우에만 보낼지, 발송하지 않을지 확정 전까지 개발 대기. 확정 전에는 쿠폰 지급과 발급 이력만 처리한다.
14. **중복 발급 정책**: 동일 회원에게 동일 쿠폰 중복 발급 허용 / 차단 (정책).
15. **적용 상품 단종 시**: 모든 적용 상품 단종이면 쿠폰 자동 비활성 + 운영자 알림.
16. **권한별 가시성**:
    - 슈퍼관리자: 전 지점 쿠폰 + 본사 통합 정책
    - 센터장: 소속 지점 쿠폰 + 생성·수정·삭제·발급
    - 매니저: 소속 지점 쿠폰 + 생성·수정·발급 (삭제 권한은 정책에 따라)
    - FC: 쿠폰 목록 조회 + 발급 (생성·수정·삭제 불가)
    - 트레이너 / 스태프 / readonly: 차단
17. **쿠폰명 정책**: 1~50자. 동일 지점 내 중복 허용.
18. **발급 안내 메시지 정책**: 고객사 확정 후 적용. 입력형 메시지를 제공하는 경우 0~200자 제한을 기본안으로 둔다.
19. **쿠폰 코드 자동 생성**: 시스템 자동 생성 (영숫자 8~12자) 또는 수동 입력 (정책).
20. **외부 채널 발급 (이벤트 페이지)**: 외부 이벤트 페이지에서 코드 입력으로 발급 (선택 기능).
21. **감사 로그**: 생성·수정·삭제·발급·사용·중단 모두 SCR-097 기록 (`actor_id`, `coupon_id`, `member_id`, `action`).
22. **사용률 통계 캐시**: 5분 캐시. 발급/사용/환불 시 무효화.
23. **본사 통합 쿠폰**: 본사 슈퍼관리자가 전 지점 일괄 등록 가능 (`hq_owned=true`). 지점에서는 발급만 가능.
24. **만료 후 보존**: 만료 쿠폰은 90일 이상 보존 (사용 이력 추적용). 90일 후 자동 아카이브.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MKT-03`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-073`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 쿠폰 생성/수정 폼, 쿠폰 발급 폼, 쿠폰 삭제 확인 흐름을 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
