## 기능 목적

할인 쿠폰을 생성·관리하고 특정 회원·그룹·등급에게 발급하는 화면이다. 정액(원 차감) / 정률(% 할인) 2종, 유효 기간 / 발급 수량 제한 / 1인 사용 제한 / 적용 상품 다중 선택으로 다양한 마케팅 시나리오를 지원한다. 매니저는 쿠폰별 발급 / 사용 / 사용률 통계로 마케팅 효과를 파악하고, 슈퍼관리자는 본사 통합 쿠폰 정책을 운영한다.

운영 맥락:
- **신규 회원 환영 쿠폰**: 등록 감사 알림과 함께 환영 쿠폰 자동 발급 (5,000원 정액)
- **재등록 권유 쿠폰**: 만료 회원에게 10% 정률 쿠폰 발급, 알림톡 동시 발송
- **VIP 등급 보상 쿠폰**: VIP 회원 그룹 일괄 발급 (월 1회)
- **이벤트 쿠폰**: 신년·생일·기념일 한정 쿠폰 (수량/기간 제한)
- **추천 보상 쿠폰**: 리퍼럴 프로그램(MKT-07)과 연동된 양방향 혜택
- **PT 패키지 한정 쿠폰**: 적용 상품을 PT 패키지로 제한
- **쿠폰 만료 자동 처리**: 유효 기간 종료 시 "만료" 상태 자동 전환, 신규 발급 차단
- **사용 중 쿠폰 보호**: 발급되었지만 미사용된 쿠폰은 삭제 차단 → "중단"으로 전환
- **사용률 분석**: 쿠폰별 사용률(사용/발급)로 효과 비교 → 마케팅 전략 조정

요약 카드(전체/발급/사용/평균 사용률) + 쿠폰 목록 + DLG-073-001 생성/수정 + DLG-073-002 발급 + DLG-073-003 삭제 위자드로 구성되어 있다.

## 주요 UX 흐름

### 쿠폰 생성 흐름
1. 사이드바 → "마케팅 > 쿠폰 관리" 진입
2. [쿠폰 생성] → DLG-073-001
3. 쿠폰명(필수, 1~50자) + 할인 유형(정액/정률) + 할인 값 + 유효 기간 + 발급 수량 제한(무제한/N매) + 1인 사용 제한(1회/N회/무제한) + 적용 상품(다중 선택) + 활성 토글
4. 저장 → 목록 추가 + 활성 상태

### 쿠폰 발급 흐름
1. 행 [발급] → DLG-073-002
2. 발급 대상 선택 (회원 검색 / 그룹 / 등급)
3. 발급 수량 (자동 또는 수동)
4. 발급 메시지 입력 (선택, 알림톡/SMS 동시 발송 옵션)
5. 발급 → `coupon_issue_log` INSERT + 회원 알림 발송 + 발급 카운트 갱신

### 쿠폰 사용 흐름 (결제 시)
1. 결제 화면(SCR-S003)에서 회원 보유 쿠폰 목록
2. 적용 상품 검증 + 1인 사용 제한 검증 + 유효 기간 검증
3. 쿠폰 적용 → 결제 금액 차감 + 사용률 통계 +1

### 쿠폰 삭제 흐름
1. 행 [삭제] → DLG-073-003
2. 사용 이력 검사: 미사용 쿠폰만 hard delete, 사용 이력 있으면 "중단" 전환 (soft delete)
3. 확인 텍스트 입력 → 삭제

### 분기·예외 흐름
- **정률 쿠폰 0% 또는 100% 초과**: 인라인 "1~100% 범위로 입력해주세요" + 저장 차단
- **정액 쿠폰 0원 이하**: 인라인 "0원 초과로 입력해주세요" + 저장 차단
- **유효 기간 시작 > 종료**: "시작일이 종료일보다 늦을 수 없습니다" + 저장 차단
- **유효 기간 만료**: 자동 "만료" 상태 전환 + 발급 버튼 비활성
- **발급 수량 제한 도달**: "발급 한도 도달" + 발급 비활성
- **1인 사용 제한 도달 회원에게 발급**: 발급은 가능하나 결제 시 사용 차단 + 안내
- **적용 상품 외 결제 시도**: "이 쿠폰은 {상품명}에서만 사용 가능합니다" + 적용 차단
- **사용 중 쿠폰 삭제 시도**: 안내 모달 + "중단"으로 전환 옵션만 제공 (hard delete 차단)
- **만료 쿠폰 발급 시도**: 발급 버튼 비활성
- **중단 쿠폰**: 신규 발급 차단, 기존 발급분은 사용 가능 (정책)
- **회원 보유 쿠폰 중복 발급**: "이미 보유 중" 안내 + 중복 발급 차단 옵션 (또는 정책에 따라 허용)
- **결제 환불 시 쿠폰 처리**: 사용된 쿠폰은 환불 후 "사용 처리" 유지 또는 복원 (정책에 따라)
- **쿠폰 발급 메시지 발송 실패**: 쿠폰 발급은 성공, 메시지만 재시도 큐 등록
- **FC 권한으로 쿠폰 생성 시도**: 버튼 hidden (FC는 발급만 가능)
- **다중 적용 상품 모두 단종**: 쿠폰 자동 비활성 + 운영자 알림
- **할인 금액 > 결제 금액**: 결제 금액 0원으로 처리, 차액 미환급
- **쿠폰 + 마일리지 동시 적용**: 정책에 따라 허용 또는 1개만 (테넌트 설정)
- **쿠폰명 중복**: 동일 지점 내 중복 허용 (다른 캠페인일 수 있음)

## 비즈니스 규칙

1. **할인 유형 2종**: 정액(원 차감) / 정률(% 할인). 정액 0원 초과, 정률 1~100% 검증.
2. **유효 기간**: 시작일·종료일 입력. 시작일 ≤ 종료일 검증. 만료 시 자동 "만료" 상태 전환.
3. **발급 수량 제한**: 무제한 또는 N매. 도달 시 발급 차단.
4. **1인 사용 제한**: 1회 / N회 / 무제한. 결제 시 회원별 사용 카운트 검증.
5. **적용 상품 다중 선택**: 전체 상품 또는 특정 상품 다중 선택. 결제 시 적용 상품 검증.
6. **상태 4종**: 활성 / 만료 / 중단 / 비활성. 자동 전환 또는 운영자 수동.
7. **자동 사용률 계산**: 사용률 = 사용 / 발급. 결제·환불 시 즉시 갱신. 5분 캐시.
8. **삭제 정책**: 사용 이력 없으면 hard delete. 사용 이력 있으면 "중단"으로 soft delete만 허용.
9. **쿠폰 사용 (결제)**: 결제 화면(SCR-S003)에서 보유 쿠폰 목록 표시. 자동 차감 + 사용률 통계 +1.
10. **할인 금액 > 결제 금액**: 결제 금액 0원 처리, 차액 미환급 (정책).
11. **쿠폰 + 마일리지 동시 적용**: 테넌트 정책으로 허용 / 1개만 / 마일리지 우선 등 설정 가능.
12. **환불 시 쿠폰 복원**: 정책에 따라 사용 처리 유지 또는 미사용으로 복원 (테넌트 설정).
13. **발급 시 회원 알림**: 발급 메시지 입력 시 알림톡/SMS/푸시 동시 발송 (MKT-01 연계).
14. **중복 발급 정책**: 동일 회원에게 동일 쿠폰 중복 발급 허용 / 차단 (정책).
15. **적용 상품 단종 시**: 모든 적용 상품 단종이면 쿠폰 자동 비활성 + 운영자 알림.
16. **권한별 가시성**:
    - 슈퍼관리자: 전 지점 쿠폰 + 본사 통합 정책
    - 센터장: 소속 지점 쿠폰 + 생성·수정·삭제·발급
    - 매니저: 소속 지점 쿠폰 + 생성·수정·발급 (삭제 권한은 정책에 따라)
    - FC: 쿠폰 목록 조회 + 발급 (생성·수정·삭제 불가)
    - 트레이너 / 스태프 / readonly: 차단
17. **쿠폰명 정책**: 1~50자. 동일 지점 내 중복 허용.
18. **발급 메시지 정책**: 0~200자. 빈 값 시 알림 발송 안 함.
19. **쿠폰 코드 자동 생성**: 시스템 자동 생성 (영숫자 8~12자) 또는 수동 입력 (정책).
20. **외부 채널 발급 (이벤트 페이지)**: 외부 이벤트 페이지에서 코드 입력으로 발급 (선택 기능).
21. **감사 로그**: 생성·수정·삭제·발급·사용·중단 모두 SCR-097 기록 (`actor_id`, `coupon_id`, `member_id`, `action`).
22. **사용률 통계 캐시**: 5분 캐시. 발급/사용/환불 시 무효화.
23. **본사 통합 쿠폰**: 본사 슈퍼관리자가 전 지점 일괄 등록 가능 (`hq_owned=true`). 지점에서는 발급만 가능.
24. **만료 후 보존**: 만료 쿠폰은 90일 이상 보존 (사용 이력 추적용). 90일 후 자동 아카이브.

- **연계 다이얼로그**: DLG-073-001 쿠폰생성수정 / DLG-073-002 쿠폰발급 / DLG-073-003 쿠폰삭제확인
- **API 기준**: `GET /api/coupons` / `POST /api/coupons` / `PUT /api/coupons/:id` / `DELETE /api/coupons/:id` / `POST /api/coupons/:id/issue` / `GET /api/coupons/:id/stats`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MKT-03`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-073`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-073-001 쿠폰생성수정, DLG-073-002 쿠폰발급, DLG-073-003 쿠폰삭제확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
