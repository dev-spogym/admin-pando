## 기능 목적

회원·리드에게 SMS / LMS / 카카오 알림톡 / 앱 푸시 4종 채널 중 적합한 채널로 메시지를 직접 작성해 발송하고, 발송 이력을 관리하는 화면이다. 매니저는 이벤트 안내·재등록 권유 메시지를 일괄 발송하고, FC는 본인 담당 회원에게 1:1 케어 메시지를 보낸다. 메시지 플랫폼 API를 통해 발신 프로필·승인 템플릿·예상 비용·발송 가능 여부를 조회하고, 변수 치환(회원명·만료일·잔여횟수·담당FC)으로 개인화된 메시지를 효율적으로 전송한다.

운영 맥락:
- **이벤트 단발 발송**: 신년·생일·할인 이벤트 등 일회성 캠페인 메시지 일괄 발송 (전체 회원 / 활성 / 만료 그룹별)
- **재등록 권유**: 만료 회원만 필터 → 알림톡 발송 (저비용 채널 우선)
- **개별 회원 케어 메시지**: FC가 본인 담당 회원에게 PT 잔여횟수·운동 격려 1:1 메시지
- **리드 그룹 발송**: CRM-01 리드를 수신자로 선택해 미전환 리드 재마케팅
- **예약 발송**: 점심시간·퇴근 시간 등 발송 효율 시간대 예약
- **채널 선택 기준**: 운영자가 알림톡 / SMS·LMS / 앱 푸시 중 명시 선택한다. 자동 알림의 기본 채널은 회원앱 Push이며, 실패 또는 미설치 시 KakaoTalk fallback은 지점 설정이 켜진 경우에만 사용한다.
- **플랫폼 잔여 캐시 부족 차단**: 플랫폼 API 기준 잔여 캐시/크레딧 < 예상 비용이면 발송 차단 + 외부 플랫폼 충전 안내
- **법정 시간 차단**: 영업/광고성 메시지 21~08시 발송 차단(정보통신망법)

수신자 미리보기·플랫폼 API 기반 예상 비용 표시·DLG-071-002 발송 미리보기로 발송 전 검증을 지원해 오발송·과비용을 방지한다.

## 메시지 플랫폼 연동 원칙

- 알림톡/SMS 발송 관련 기준 정보의 진실 소스는 내부 단가 테이블이 아니라 연동된 메시지 플랫폼 API다. 단, 자동 알림의 채널 기본값은 회원앱 Push이며 SMS로 자동 전환하지 않는다.
- 화면에는 플랫폼에서 조회한 발신 프로필, 템플릿 승인 상태, 채널별 예상 비용, 잔여 캐시/크레딧, 최근 동기화 시각만 노출한다.
- 운영자는 관리자에서 발송 조건과 메시지 내용을 결정하지만, 과금 단가·실발송 상태·최종 청구 근거는 플랫폼 응답값을 우선한다.

## 주요 구성요소

### 탭 전환

메시지 전송 / 발송 이력.

### 플랫폼 발송 정보 표시

상단에 연동된 메시지 플랫폼, 발신 프로필, 잔여 캐시/크레딧, 최근 동기화 시각을 표시한다. 조회 실패 시 발송 기능 일부를 잠근다.

### 발신 설정

플랫폼 API에서 조회한 발신 번호/카카오 발신 프로필 목록 중 선택한다.

### 수신자 선택

| 옵션 | 설명 |
|------|------|
| 전체 회원 | 일괄 |
| 활성 회원 | active만 |
| 만료 회원 | expired만 |
| 개별 검색 | DLG-071-001 |
| 리드 그룹 | CRM-01 리드 |

### 발송 채널 선택

| 채널 | 비용 기준 |
|------|------|
| 알림톡 | 플랫폼 API 예상 비용 |
| SMS·LMS | 플랫폼 API 예상 비용 |
| 앱 푸시 | 무료 (앱 회원) |

### 예상 비용 안내

선택 수신자 수 × 채널·템플릿·글자수 조건을 플랫폼 API에 전달해 예상 비용을 실시간 표시한다.

### 메시지 작성

자유 텍스트 + 변수 삽입.

| 변수 | 설명 |
|------|------|
| {회원명} | 회원 이름 |
| {만료일} | 이용권 만료일 |
| {잔여횟수} | PT 잔여 횟수 |
| {담당FC} | 담당 FC |

### 발송 미리보기 (DLG-071-002)

수신자 화면 형태로 미리 확인.

### 발송 / 예약 발송

즉시 또는 원하는 일시에 예약.

### 발송 이력 테이블

| 컬럼 | 설명 |
|------|------|
| 발송 일시 | YYYY-MM-DD HH:mm |
| 채널 | 알림톡/SMS/푸시 |
| 수신자 수 | 카운트 |
| 내용 요약 | 첫 30자 |
| 발송 결과 | 성공/실패/일부 실패 |
| 액션 | [상세] |

## 주요 UX 흐름

### 정상 즉시 발송 흐름
1. 사이드바 → "마케팅 > 메시지 발송" 진입
2. 메시지 플랫폼 연결 상태·발신 프로필·잔여 캐시를 확인
3. 발신 번호 또는 카카오 발신 프로필 선택
4. 수신자 선택 (전체/활성/만료/개별 검색/리드 그룹)
5. 채널 선택 (알림톡/SMS·LMS/앱 푸시) → 플랫폼 API 기반 예상 비용 실시간 표시
6. 메시지 작성 + 변수 삽입 ({회원명}/{만료일}/{잔여횟수}/{담당FC})
7. 글자수 카운트 표시 (SMS 90byte / LMS 2000byte / 알림톡 1000자)
8. [미리보기] → DLG-071-002 (변수 치환된 첫 수신자 화면)
9. [발송] → 플랫폼 발송 요청 + 발송 큐 등록 → 발송 이력 탭으로 자동 이동
10. 플랫폼 webhook/결과 API로 발송 결과 실시간 갱신 (성공/실패/일부 실패)

### 예약 발송 흐름
1. 동일 흐름 + [예약 발송] 선택
2. 발송 일시 선택 (분 단위)
3. 예약 등록 → 예약 목록 표시
4. 예약 시점 자동 발송
5. 발송 5분 전까지 취소 가능

### 발송 이력 조회 흐름
1. "발송 이력" 탭 진입
2. 발송 일시·채널·수신자 수·내용 요약·결과 배지
3. [상세] 클릭 → 수신자별 성공/실패 + 사유
4. 실패 건 [재발송] 옵션

### 분기·예외 흐름
- **플랫폼 잔여 캐시/크레딧 < 예상 비용**: 빨강 경고 + 발송 비활성 + 외부 플랫폼 충전 링크
- **수신자 0명 (필터 결과 없음)**: 발송 비활성 + "수신자가 없습니다" 안내
- **카카오 알림톡 비친구 회원 포함**: "비친구 회원은 알림톡 발송 대상에서 제외됩니다" 안내. SMS는 운영자가 SMS·LMS 채널을 명시 선택한 경우에만 별도 발송한다.
- **앱 푸시 미설치 회원 포함**: "앱 미설치 회원은 발송 제외" 안내
- **변수 치환 실패 (회원 데이터 누락)**: 해당 회원 발송 제외 + "데이터 누락 {인원수}명 제외" 안내
- **발송 5분 전 예약 취소**: 즉시 취소 가능
- **발송 4분 전 예약 취소 시도**: "발송이 임박해 취소할 수 없습니다" 차단
- **법정 시간(21~08시) 영업/광고 발송**: "야간 광고성 메시지 발송 불가" 모달 + 차단 (정보·고객응대 메시지는 예외)
- **수신 거부(블랙리스트) 회원 포함**: 자동 제외 + "수신 거부 {인원수}명 제외" 안내
- **휴면 회원 포함**: 자동 제외 + 안내
- **발신 번호 미인증**: "발신 번호 인증이 필요합니다" + 시스템 설정 이동 안내
- **글자수 초과**: SMS는 LMS로 자동 전환 (단가 변경 안내) / 알림톡 1000자 초과 시 차단
- **금지어 포함 (도박·대출 등)**: "사전 등록된 금지어가 포함되었습니다" 차단
- **알림톡 미승인 템플릿**: "카카오 사전 승인 템플릿만 사용 가능" 안내
- **FC가 다른 FC 담당 회원 발송 시도**: 본인 담당 회원만 검색 결과 표시 (RLS)
- **발송 중 webhook 응답 지연**: 5분 후 "발송 결과 확인 중" 표시 + 별도 새로고침
- **발송 실패 (외부 API 오류)**: 자동 재시도 3회 + 최종 실패 시 알림 + 플랫폼 결과 재조회
- **예약 발송 시점 플랫폼 잔여 캐시 부족**: 발송 보류 + 운영자 알림

## 비즈니스 규칙

1. **플랫폼 기준 과금**: 예상 비용과 실제 과금 기준은 연동된 메시지 플랫폼 응답값을 따른다. 내부 단가 수기 관리 기능은 두지 않는다.
2. **채널 4종**: 알림톡 / SMS / LMS / 앱 푸시. SMS/알림톡/LMS 예상 비용은 플랫폼 API에서 조회한다.
3. **알림톡 친구 제한**: 카카오 채널 친구 회원에게만 발송 가능. 비친구는 자동 제외한다. SMS로 자동 전환하지 않으며, SMS·LMS 발송은 운영자가 해당 채널을 명시 선택한 경우에만 수행한다.
4. **알림톡 사전 승인 템플릿**: 카카오 정책에 따라 사전 승인된 템플릿만 발송 가능. 자유 텍스트는 SMS/LMS만 가능.
5. **SMS / LMS 자동 전환**: SMS 90byte 초과 시 LMS로 자동 전환 + 단가 변경 안내. LMS 2000byte 초과 시 차단.
6. **앱 푸시**: 회원앱 설치 + 푸시 동의 회원에게만 발송, 무료.
7. **변수 치환**: {회원명}/{만료일}/{잔여횟수}/{담당FC} 4종. 수신자별 자동 치환. 데이터 누락 회원은 발송 제외.
8. **예약 발송**: 분 단위 설정. 발송 5분 전까지 취소 가능, 4분 이내는 차단. 예약 시점 플랫폼 잔여 캐시 부족 시 보류.
9. **발신 번호 인증**: 사전 인증된 번호만 발신 가능. 미인증 번호는 시스템 설정에서 인증 필요.
10. **수신 거부 / 블랙리스트**: 회원이 수신 거부 등록한 경우 자동 제외. 휴면 회원도 자동 제외.
11. **법정 시간 차단**: 영업/광고성 메시지는 21:00~08:00 발송 차단(정보통신망법). 정보성·고객응대 메시지는 예외.
12. **금지어 차단**: 도박·대출·성인 등 사전 등록 금지어 포함 시 발송 차단.
13. **글자수 정책**: SMS 90byte (한글 45자) / LMS 2000byte / 알림톡 1000자. 실시간 카운트.
14. **FC 권한**: 본인 담당 회원에게만 발송 가능 (검색 시 본인 담당만 결과). 발신 설정 변경 불가.
15. **수신자 그룹**: 전체 회원 / 활성 / 만료 / 개별 검색 / 리드 그룹 (CRM-01). 다중 조합 가능.
16. **예상 비용 실시간**: 수신자 수·채널·글자수·템플릿 정보를 플랫폼 API에 전달해 즉시 갱신한다.
17. **발송 결과 동기화**: 외부 메시지 플랫폼 webhook 또는 결과 조회 API로 실시간 갱신한다 (성공/실패/일부 실패).
18. **자동 재시도**: 발송 실패 시 자동 재시도 3회 (1분/5분/30분 간격). 최종 실패 시 운영자 알림 + 플랫폼 결과 재조회.
19. **발송 이력 보관**: 발송 결과는 90일 이상 보관. 감사 로그에 기록 (`actor_id`, `recipient_count`, `channel`, `cost`, `result`).
20. **권한별 가시성**:
    - 슈퍼관리자: 전 지점 발송 + 이력
    - 센터장 / 매니저: 소속 지점 전체 발송 + 이력 + 발신 설정
    - FC: 메시지 전송만 (담당 회원), 발신 설정 변경 불가
    - 트레이너 / 스태프 / readonly: 차단
21. **개별 발송 미리보기 (DLG-071-002)**: 발송 전 변수 치환된 첫 수신자 화면 형태로 미리 표시.
22. **수신자 검색 (DLG-071-001)**: 이름·연락처 디바운스 300ms. 다중 선택 가능.
23. **가족 묶음 발송 (MBR-EXT-02)**: 가족 그룹 1명에게만 발송 옵션. 중복 발송 방지.

## 관련 화면 / 다이얼로그 / API

- **연계 화면**: SCR-071 / SCR-072 자동 알림 / SCR-078 SMS·카카오 대량 / SCR-M004 회원 / SCR-070 리드
- **연계 다이얼로그**: DLG-071-001 수신자검색 / DLG-071-002 발송미리보기
- **API 기준**: `POST /api/messages` / `POST /api/messages/schedule` / `GET /api/messages/history` / `GET /api/messages/recipients` / `GET /api/messages/cost-estimate` / `GET /api/messages/points`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MKT-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-071`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-071-001 수신자검색, DLG-071-002 발송미리보기`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
