## 기능 목적

본사 정책 세트로 내려온 만료 step(D-30/D-14/D-7/D-Day 등 본사가 정의한 기준일)과, 생일·장기 미방문·등록 감사·첫 방문 환영 등 자동 알림 엔진을 관리하는 화면이다. 본사는 HQ-09에서 `회원 이용권 만료`, `결제기한 만료`, `락커 만료` 정책을 분리해 기준일 step을 생성하고 지점에 배포한다. 지점은 본사 step 기준일을 수정하지 않지만, `회원 이용권 만료`와 `락커 만료` 정책에서는 센터장(owner)이 해당 지점 전용 추가 step을 생성·수정·삭제할 수 있다. `결제기한 만료`는 지점 추가 step을 허용하지 않고 본사 step ON/OFF만 변경한다. 각 지점의 센터장(owner)만 배포된 정책 또는 step의 ON/OFF를 변경할 수 있으며, manager/fc/staff/readonly는 ON/OFF와 지점 추가 step을 변경할 수 없다. 알림 채널은 Push / 카카오톡 / SMS 3종으로 고정한다. 자동 알림의 기본 채널은 회원앱 Push이며, 실패·미설치 시 카카오톡 fallback은 지점에서 선택 활성화한 경우에만 사용한다. SMS는 정책 step에서 명시 선택한 경우에만 발송하며 자동 fallback으로 전환하지 않는다. 채널·메시지·발송 시각 조정 권한은 지점 운영 설정에 따르되, 정책 사용 여부 토글 권한과 분리한다. 알림 채널의 발신 프로필·승인 템플릿·예상 비용·발송 가능 여부는 메시지 플랫폼 API를 조회해 판단한다.

## 메시지 플랫폼 연동 원칙

- 자동 알림 설정 화면은 메시지 플랫폼의 발신 프로필, 승인 템플릿, 테스트 발송 결과, 예상 비용 스냅샷을 조회해 보여준다.
- 지점은 플랫폼 과금 단가를 직접 입력하지 않는다. 예상 비용은 테스트 발송 또는 시뮬레이션 시 플랫폼 API 응답을 사용한다.

운영 맥락:
- **만료 정책별 본사 step 배포**: 회원 이용권 만료, 결제기한 만료, 락커 만료별로 본사가 HQ-09에서 정의한 step을 지점에 배포한다. 지점 본사 step 기준일 수정은 불가하고 센터장(owner)만 지점별 ON/OFF 가능
- **지점 추가 step**: 회원 이용권 만료와 락커 만료는 센터장(owner)이 지점 추가 step을 등록할 수 있다. 결제기한 만료는 지점 추가 step 불가
- **생일 축하**: 매년 생일 당일 09:00 자동 발송, 쿠폰 첨부 옵션
- **장기 미방문**: 30일/60일/90일 미방문 회원 자동 알림 (재방문 유도)
- **등록 감사**: 신규 등록 회원에게 환영 + 첫 방문 안내 즉시 발송
- **첫 방문 환영**: 첫 출석 트리거 시 격려 메시지 자동 발송
- **이용권 만료 당일/만료 후**: HQ-09 만료 정책 step의 D-Day·D+N 기준과 해당 지점 ON 상태에 따라 재등록 권유
- **홀딩 종료**: 자동 재개 시점에 회원 알림
- **결제 완료 / 환불 처리**: 즉시 영수증·환불 통보
- **SCR-072A 운영 현황**: 자동 알림 발송 통계·성공률·전환율 실시간 모니터링
- **본사 vs 지점 분리**: 본사 영역(기준일·정책·템플릿 기본값)은 읽기 전용, 지점 영역(ON/OFF, 채널·메시지·시각)은 권한에 따라 편집 가능. 단 ON/OFF는 센터장(owner) 전용

전체 ON/OFF 토글로 시스템 점검·이벤트 기간 일시 중단도 가능하다. 전체 ON/OFF 역시 센터장(owner)만 변경할 수 있으며, 매니저 이하는 현재 상태 조회와 운영 현황 확인만 가능하다.

## 자동 알림 범위 고정 원칙

계약서의 `자동 알림 13종 엔진`은 아래 목록을 설정·ON/OFF·자동 발송·이력 조회하는 범위로 한정한다. `고객 알림 목록`과 `상품 알림 목록`은 모든 고객/상품 관련 알림을 무제한 추가하는 기능이 아니며, 본 문서에 명시되지 않은 신규 알림은 별도 협의 또는 고객사 확인 대상으로 분리한다.

자동 알림의 기본 수신 주체는 `회원`이다. 운영자에게 보내는 내부 업무 알림은 NFR-19 알림센터 또는 운영자 알림으로 분리하며, MKT-02 회원 자동 발송 채널과 혼합하지 않는다. 채널은 Push / 카카오톡 / SMS 3종으로 고정한다. 기본은 회원앱 Push이고, 카카오톡은 지점이 fallback을 켠 경우에만 보조 발송한다. SMS는 규칙 상세 설정에서 명시 선택한 경우에만 발송하며 자동 fallback으로 전환하지 않는다.

MKT-04의 `마일리지 소멸 예정 알림`은 마일리지 자동 소멸 기능의 부속 알림이다. MKT-02는 해당 알림의 채널, 발송 이력, 재시도, 카카오톡 fallback 처리에 공통 발송 엔진만 제공하며, 이를 자동 알림 13종 목록을 무제한 확장하는 의미로 해석하지 않는다.

### 규칙별 토글 스위치

각 자동 알림 규칙 또는 step의 지점 적용 여부를 ON/OFF로 제어하는 스위치다. OFF 상태에서는 해당 지점에서 트리거 조건을 만족해도 자동 발송하지 않으며, 본사 정책 원본·기준일·기본 템플릿은 삭제하거나 변경하지 않는다. 토글 조작은 센터장(owner)만 가능하며 manager 이하 계정은 disabled 상태와 권한 안내 툴팁만 확인한다.

본사가 특정 규칙 또는 step을 `본사 필수`로 배포한 경우에는 지점 토글을 ON 고정으로 표시한다. 이 상태를 `본사 필수 규칙 OFF 차단`으로 정의하며, 센터장(owner)도 해당 규칙을 OFF로 변경할 수 없다. 화면에는 `본사 필수` 배지와 "본사 필수 알림은 지점에서 끌 수 없습니다" 안내를 표시하고, 상세 설정에서 허용된 채널·메시지·발송 시각만 조정 가능하다. 필수 여부 변경은 본사 정책 관리(HQ-09)에서만 가능하다.

### 상세 설정

| 영역 | 편집 가능 |
|------|---------|
| 본사 소유 기준일 | 읽기 전용 |
| 지점 추가 step 기준일 | 회원 이용권 만료·락커 만료에서 센터장(owner)만 편집 가능 |
| 정책/step ON/OFF | 센터장(owner)만 가능 |
| 채널 | Push / 카카오톡 / SMS. 기본은 회원앱 Push, 카카오톡 fallback은 선택 가능, SMS는 명시 선택 시에만 발송 |
| 메시지 내용 | 지점 조정 가능 |
| 발송 시각 | 지점 조정 가능 |
| 발송 옵션 | 지점 조정 가능 |

### 전체 자동 알림 ON/OFF

상단 토글로 모든 알림 일괄 활성/비활성. 센터장(owner)만 조작 가능.

## 주요 UX 흐름

### 만료 정책별 본사 step ON/OFF 및 채널·메시지 조정 흐름
1. 사이드바 → "마케팅 > 자동 알림 설정" 진입
2. 만료 정책 탭에서 회원 이용권 만료, 결제기한 만료, 락커 만료 중 정책별 step(D-30/D-14/D-7 등 정책별 기준일) 확인
3. step 상세 설정을 열어 현재 설정값 확인
4. 본사 영역(기준일·정책·기본 템플릿) 읽기 전용 표시
5. 센터장(owner)은 step ON/OFF를 변경할 수 있고, manager 이하는 토글 disabled 상태로 확인만 가능
6. 지점 영역 편집 (채널·메시지·발송 시각·발송 옵션)
7. 저장 → 해당 지점에 즉시 반영 + 감사 로그 기록

### 지점 추가 만료 step 등록 흐름
1. 센터장(owner)이 회원 이용권 만료 또는 락커 만료 탭에서 [지점 step 추가] 클릭
2. DLG-072-002에서 기준일 유형(만료 전/당일/후), 기준일 값, 발송 시각, 메시지, KakaoTalk fallback 사용 여부 입력
3. 동일 정책 안의 본사 step 또는 기존 지점 추가 step과 기준일이 중복되면 저장 차단
4. 저장하면 해당 지점에만 step이 추가되고 본사 정책 원본과 다른 지점에는 영향 없음
5. 결제기한 만료 탭에는 [지점 step 추가] 버튼을 노출하지 않음

### 지점 운영 알림 활성화 흐름
1. 센터장(owner)이 고객/상품 알림 목록에서 토글 ON
2. [상세 설정]을 눌러 알림 규칙 상세 설정 다이얼로그 열기
3. 채널·메시지·발송 시각 입력
4. 저장 → 다음 트리거 시점부터 자동 발송

### 전체 일시 중단 흐름
1. 센터장(owner)이 상단 전체 자동 알림 토글 OFF
2. 확인 모달: "이 지점의 자동 알림이 모두 중단됩니다. 본사 정책 원본은 변경되지 않습니다."
3. 사유 입력 후 확인 → 해당 지점 자동 알림 중단
4. manager 이하가 토글 클릭 시 권한 안내만 표시하고 변경하지 않음

### SCR-072A 운영 현황 진입 흐름
1. 화면 우측 [운영 현황] 또는 별도 사이드바
2. 알림 종류별 발송 건수·성공률·실패 사유·전환율 확인
3. 메시지 효과 비교 → 개선 포인트 도출

### 분기·예외 흐름
- **센터장 외 step 비활성 시도**: 토글 잠금 + "센터장만 자동 알림 사용 여부를 변경할 수 있습니다" 안내
- **본사 영역 편집 시도**: 읽기 전용 안내 + 입력 차단
- **자동 알림 발송 시점 플랫폼 잔여 캐시 부족**: 발송 보류 + 운영자 알림 + 플랫폼 충전 후 재시도
- **수신 거부 / 휴면 회원**: 자동 제외 + 발송 통계에 제외 카운트 기록
- **변수 데이터 누락**: 해당 회원 발송 제외 + 운영 현황에 누락 사유 기록
- **법정 시간(21~08시) 발송 시각 설정 시도**: 영업/광고 알림은 차단, 정보성(결제·환불·홀딩 종료)은 허용
- **금지어 포함 메시지**: 저장 차단 + 인라인 에러
- **알림톡 미승인 템플릿 채널 선택**: "사전 승인 템플릿이 필요합니다" 안내. fallback은 비활성 처리하고 기본 Push만 발송한다.
- **전체 OFF 후 처리**: 해당 지점의 자동 알림 발송 중단. 본사 정책 원본과 다른 지점에는 영향 없음
- **트리거 조건 충족인데 발송 실패**: 자동 재시도 3회 + 최종 실패 시 운영자 알림
- **동시 두 알림이 같은 회원에게 발송**: 우선순위 정책으로 1개만 발송 (예: D-Day > D-1 > D-3) 또는 모두 발송 (정책)
- **테스트 발송**: 운영자 본인 번호로 시범 발송 후 본 발송 옵션
- **메시지 변경 후 즉시 반영 vs 다음 트리거부터**: 다음 트리거부터 적용 (이미 큐 등록된 발송은 기존 메시지)
- **본사가 step 추가 시 지점에 자동 노출**: 신규 step은 본사 기본 활성값에 따라 노출되며, 센터장(owner)이 ON/OFF 변경 가능

## 비즈니스 규칙

1. **자동 알림 엔진 범위**: 자동 알림은 본 문서의 `고객 관련 알림 목록`과 `상품/결제 관련 알림 목록`에 명시된 항목만 포함한다. 목록에 없는 고객/상품/예약/출석/쿠폰/마일리지 알림은 MKT-02 기본 범위로 자동 포함하지 않고 별도 협의 또는 고객사 확인 대상으로 둔다. 단, MKT-04에 명시된 `마일리지 소멸 예정 알림`은 MKT-04 자동 소멸의 부속 알림으로 보며, MKT-02는 공통 발송 엔진만 제공한다.
2. **본사 step 배포 구조**: 만료 step의 기준일·트리거 조건·기본 템플릿은 HQ-09 본사 정책 세트에서 정의한다. 지점은 본사 기준일을 수정하지 않고 소속 지점 적용 여부만 ON/OFF한다.
2-1. **정책별 기준일**: 회원 이용권 만료는 회원 이용권 종료일, 결제기한 만료는 미수금·잔액·할부 납입기한, 락커 만료는 락커 이용 종료일을 기준으로 한다.
2-2. **지점 추가 step 허용**: 회원 이용권 만료와 락커 만료에서만 센터장(owner)이 지점 추가 step을 만들 수 있다. 결제기한 만료는 지점 추가 step을 만들 수 없다.
3. **ON/OFF 권한**: 정책/step별 ON/OFF와 전체 자동 알림 ON/OFF는 센터장(owner)만 변경 가능하다. manager/fc/trainer/staff/readonly는 토글을 변경할 수 없으며, UI에서는 disabled + 권한 안내 툴팁으로 표시한다.
3-1. **본사 필수 규칙 OFF 차단**: 본사가 `본사 필수`로 배포한 규칙/step은 지점에서 OFF할 수 없다. owner 계정에도 ON 고정 disabled 토글과 `본사 필수` 배지를 표시하며, OFF가 필요하면 HQ-09 본사 정책에서 필수 여부를 변경해야 한다.
4. **본사 영역 읽기 전용**: 본사 소유 기준일·트리거 조건은 지점에서 편집 불가. 지점 추가 step의 기준일은 회원 이용권 만료·락커 만료에서 owner만 편집 가능하다. 채널·메시지·발송 시각·발송 옵션은 지점 운영 권한에 따라 편집 가능하되 ON/OFF 권한과 분리한다.
5. **트리거 발송 시점**: 만료 step은 일배치 04:00에 대상 추출 + 설정 시각 발송. 결제·환불·홀딩 종료는 이벤트 즉시. 첫 방문은 출석 webhook 트리거.
6. **발송 결과 통합**: 자동 알림 발송 결과는 SCR-071 메시지 발송 이력에 통합 기록. SCR-072A 운영 현황에서 자동 알림만 별도 통계.
7. **변수 치환**: {회원명}/{만료일}/{잔여횟수}/{담당FC} 4종. 누락 회원 발송 제외 + 사유 기록.
8. **플랫폼 기준 발송 가능 여부**: 자동 알림도 일반 발송과 동일하게 플랫폼 잔여 캐시/발송 가능 여부를 확인한다. 부족 시 발송 보류 + 운영자 알림.
9. **자동 알림 기본 채널**: 회원앱 Push를 기본 채널로 사용한다. 회원앱 미설치, Push 수신 실패, 장기 미접속 등 보조 안내가 필요한 경우에만 지점이 KakaoTalk fallback을 선택 활성화할 수 있다. SMS로 자동 전환하지 않는다.
10. **수신 거부 / 휴면 자동 제외**: 회원 수신 거부 등록 또는 휴면 회원은 자동 제외.
11. **법정 시간 차단**: 영업/광고 알림(생일·미방문·등록 감사·첫 방문)은 21~08시 차단. 정보성(결제·환불·홀딩 종료·만료 D-Day)은 예외.
12. **금지어 차단**: 메시지에 사전 등록 금지어 포함 시 저장 차단.
13. **KakaoTalk fallback 사전 승인**: KakaoTalk fallback 선택 시 카카오 사전 승인 템플릿이 필요하다. 미승인 시 fallback을 사용하지 않고 Push만 발송하거나 저장을 차단한다.
14. **전체 ON/OFF**: 상단 토글 OFF 시 해당 지점의 모든 자동 알림이 중단된다. 본사 정책 원본과 다른 지점의 적용 상태에는 영향이 없다.
15. **자동 재시도**: Push 실패 시 1분/5분/30분 3회 재시도한다. 최종 실패 시 지점이 KakaoTalk fallback을 켠 규칙만 KakaoTalk로 1회 보조 발송하고, 그렇지 않으면 운영자 알림만 남긴다.
16. **우선순위 정책**: 동일 회원에게 같은 시점 여러 알림 트리거 시 우선순위 정의 (D-Day > D-1 > D-3 > D-7 > 기타) 또는 모두 발송 (테넌트 정책).
17. **메시지 변경 적용 시점**: 저장 후 다음 트리거부터 적용. 이미 큐 등록된 발송은 기존 메시지 유지.
18. **테스트 발송**: 운영자 본인 번호로 시범 발송 가능. 실제 회원 발송과 별도 카운트하며 플랫폼 API 응답으로 성공 여부를 확인한다.
19. **권한별 가시성**:
    - 슈퍼관리자: 본사 step 정의 + 전 지점 알림 정책
    - 센터장: 소속 지점 알림 활성/비활성·상세 설정
    - 매니저: 소속 지점 알림 조회·상세 설정, ON/OFF 변경 불가
    - FC / 트레이너 / 스태프: 접근 차단
    - readonly: 차단
20. **본사 step 추가 시**: 신규 step 자동 추가, 본사 기본 활성값에 따라 지점에 노출 + 알림.
21. **만료 step 트리거 정의**: 본사 step 기준일은 HQ-09 정책 세트의 값을 따른다. 예: D-30(만료 30일 전), D-14, D-7, D-Day, D+1. 지점 추가 step은 회원 이용권 만료·락커 만료 정책에서 해당 지점 전용으로만 동작한다. 각 step 발송 시각은 지점 설정값을 사용할 수 있다.
22. **장기 미방문 트리거**: 마지막 출석일 +30/60/90일 매일 04:00 배치로 대상 추출.
23. **생일 트리거**: 회원 생일 당일 09:00 (지점 설정 가능).
24. **첫 방문 환영 트리거**: 회원 첫 출석 (출석 카운트 1) webhook 즉시.
25. **결제·환불·홀딩 종료 트리거**: 이벤트 발생 즉시 (1분 이내).
26. **감사 로그**: 토글 변경·상세 설정 변경·전체 ON/OFF 모두 SCR-097 기록. 토글 변경 로그에는 actor_role이 owner인지 검증 결과를 포함한다.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MKT-02`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-072, SCR-072A`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 알림 규칙 상세 설정 다이얼로그를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
