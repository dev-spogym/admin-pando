## 기능 목적

본사 정책 세트로 내려온 만료 step(D-7/D-3/D-1/D-Day/D+1) 5종과, 생일·장기 미방문·등록 감사·첫 방문 환영 등 13종 자동 알림 엔진을 관리하는 화면이다. 본사가 정의한 필수 step은 지점에서 비활성화할 수 없으며, 채널·메시지·발송 시각만 지점 운영에 맞게 조정한다. 매니저는 일일 운영 부담 없이 회원 리텐션 알림을 자동화하고, 본사 슈퍼관리자는 정책 세트로 일관된 회원 경험을 유지한다.

운영 맥락:
- **본사 만료 step (필수)**: D-7/D-3/D-1/D-Day/D+1 5단계로 만료 임박 회원에게 자동 발송, 비활성화 차단
- **생일 축하**: 매년 생일 당일 09:00 자동 발송, 쿠폰 첨부 옵션
- **장기 미방문**: 30일/60일/90일 미방문 회원 자동 알림 (재방문 유도)
- **등록 감사**: 신규 등록 회원에게 환영 + 첫 방문 안내 즉시 발송
- **첫 방문 환영**: 첫 출석 트리거 시 격려 메시지 자동 발송
- **이용권 만료 당일**: D-Day 09:00 + 만료 후 D+1 재등록 권유
- **홀딩 종료**: 자동 재개 시점에 회원 알림
- **결제 완료 / 환불 처리**: 즉시 영수증·환불 통보
- **SCR-072A 운영 현황**: 자동 알림 발송 통계·성공률·전환율 실시간 모니터링
- **본사 vs 지점 분리**: 본사 영역(기준일·정책)은 읽기 전용, 지점 영역(채널·메시지·시각)은 편집 가능

전체 ON/OFF 토글로 시스템 점검·이벤트 기간 일시 중단도 가능하다(본사 필수 step 별도 처리).

## 주요 UX 흐름

### 본사 만료 step 채널·메시지 조정 흐름
1. 사이드바 → "마케팅 > 자동 알림 설정" 진입
2. 고객 알림 목록에서 만료 step (D-7/D-3/D-1/D-Day/D+1) 확인
3. step 클릭 → DLG-072-001
4. 본사 영역(기준일·정책) 읽기 전용 표시
5. 지점 영역 편집 (채널·메시지·발송 시각·발송 옵션)
6. 저장 → 즉시 반영 + 감사 로그 기록

### 지점 운영 알림 활성화 흐름
1. 고객/상품 알림 목록에서 토글 ON
2. [상세 설정] → DLG-072-001
3. 채널·메시지·발송 시각 입력
4. 저장 → 다음 트리거 시점부터 자동 발송

### 전체 일시 중단 흐름
1. 상단 전체 자동 알림 토글 OFF
2. 확인 모달: "본사 필수 step은 별도 처리됩니다"
3. 확인 → 모든 비필수 알림 중단
4. 본사 필수 step은 정책에 따라 계속 발송 또는 같이 중단

### SCR-072A 운영 현황 진입 흐름
1. 화면 우측 [운영 현황] 또는 별도 사이드바
2. 알림 종류별 발송 건수·성공률·실패 사유·전환율 확인
3. 메시지 효과 비교 → 개선 포인트 도출

### 분기·예외 흐름
- **본사 필수 step 비활성 시도**: 토글 잠금 + "본사 필수 step은 비활성화 불가" 모달
- **본사 영역 편집 시도**: 읽기 전용 안내 + 입력 차단
- **자동 알림 발송 시점 잔여 포인트 부족**: 발송 보류 + 운영자 알림 + 충전 후 재시도
- **수신 거부 / 휴면 회원**: 자동 제외 + 발송 통계에 제외 카운트 기록
- **변수 데이터 누락**: 해당 회원 발송 제외 + 운영 현황에 누락 사유 기록
- **법정 시간(21~08시) 발송 시각 설정 시도**: 영업/광고 알림은 차단, 정보성(결제·환불·홀딩 종료)은 허용
- **금지어 포함 메시지**: 저장 차단 + 인라인 에러
- **알림톡 미승인 템플릿 채널 선택**: "사전 승인 템플릿이 필요합니다" 안내 + SMS로 자동 변경 권유
- **전체 OFF 후 본사 필수 step 처리**: 정책에 따라 계속 발송 또는 같이 중단 (`hq_required_continue` 토글)
- **트리거 조건 충족인데 발송 실패**: 자동 재시도 3회 + 최종 실패 시 운영자 알림
- **동시 두 알림이 같은 회원에게 발송**: 우선순위 정책으로 1개만 발송 (예: D-Day > D-1 > D-3) 또는 모두 발송 (정책)
- **테스트 발송**: 운영자 본인 번호로 시범 발송 후 본 발송 옵션
- **메시지 변경 후 즉시 반영 vs 다음 트리거부터**: 다음 트리거부터 적용 (이미 큐 등록된 발송은 기존 메시지)
- **본사가 step 추가 시 지점에 자동 노출**: 신규 step은 비활성 상태로 노출 + 안내

| 상태 | 설명 |

| 알림 활성 | 토글 ON |
| 알림 비활성 | 토글 OFF, 회색 |

| 본사 필수 | 토글 잠금 |

## 비즈니스 규칙

1. **자동 알림 13종 엔진**: 만료 step (D-7/D-3/D-1/D-Day/D+1) + 생일 + 장기 미방문 (30/60/90) + 등록 감사 + 첫 방문 환영 + 이용권 만료 당일 + 홀딩 종료 + 결제 완료 + 환불 처리.
2. **본사 필수 step**: D-7/D-3/D-1/D-Day/D+1 만료 step은 본사 정책으로 비활성화 불가. 토글 잠금.
3. **본사 영역 읽기 전용**: 본사 소유 기준일·트리거 조건은 지점에서 편집 불가. 채널·메시지·발송 시각·발송 옵션만 지점에서 편집 가능.
4. **트리거 발송 시점**: 만료 step은 일배치 04:00에 대상 회원 추출 + 설정 시각 발송. 결제·환불·홀딩 종료는 이벤트 즉시. 첫 방문은 출석 webhook 트리거.
5. **발송 결과 통합**: 자동 알림 발송 결과는 SCR-071 메시지 발송 이력에 통합 기록. SCR-072A 운영 현황에서 자동 알림만 별도 통계.
6. **변수 치환**: {회원명}/{만료일}/{잔여횟수}/{담당FC} 4종. 누락 회원 발송 제외 + 사유 기록.
7. **포인트 차감**: 자동 알림도 일반 발송과 동일하게 포인트 차감. 부족 시 발송 보류 + 운영자 알림.
8. **수신 거부 / 휴면 자동 제외**: 회원 수신 거부 등록 또는 휴면 회원은 자동 제외.
9. **법정 시간 차단**: 영업/광고 알림(생일·미방문·등록 감사·첫 방문)은 21~08시 차단. 정보성(결제·환불·홀딩 종료·만료 D-Day)은 예외.
10. **금지어 차단**: 메시지에 사전 등록 금지어 포함 시 저장 차단.
11. **알림톡 사전 승인**: 알림톡 채널 선택 시 사전 승인 템플릿 필요. 미승인 시 SMS 자동 폴백 또는 차단.
12. **전체 ON/OFF**: 상단 토글 OFF 시 모든 비필수 알림 중단. 본사 필수 step은 `hq_required_continue` 정책에 따라 계속 발송 또는 같이 중단.
13. **자동 재시도**: 발송 실패 시 1분/5분/30분 3회 재시도 + 최종 실패 시 운영자 알림.
14. **우선순위 정책**: 동일 회원에게 같은 시점 여러 알림 트리거 시 우선순위 정의 (D-Day > D-1 > D-3 > D-7 > 기타) 또는 모두 발송 (테넌트 정책).
15. **메시지 변경 적용 시점**: 저장 후 다음 트리거부터 적용. 이미 큐 등록된 발송은 기존 메시지 유지.
16. **테스트 발송**: 운영자 본인 번호로 시범 발송 가능. 실제 회원 발송과 별도 카운트.
17. **권한별 가시성**:
    - 슈퍼관리자: 본사 step 정의 + 전 지점 알림 정책
    - 센터장 / 매니저: 소속 지점 알림 활성/비활성·상세 설정
    - FC / 트레이너 / 스태프: 접근 차단
    - readonly: 차단
18. **본사 step 추가 시**: 신규 step 자동 추가, 지점은 비활성 상태로 노출 + 알림.
19. **만료 step 트리거 정의**: D-7 (만료 7일 전), D-3 (3일 전), D-1 (1일 전), D-Day (당일), D+1 (만료 다음 날). 각 step 발송 시각 지점 설정.
20. **장기 미방문 트리거**: 마지막 출석일 +30/60/90일 매일 04:00 배치로 대상 추출.
21. **생일 트리거**: 회원 생일 당일 09:00 (지점 설정 가능).
22. **첫 방문 환영 트리거**: 회원 첫 출석 (출석 카운트 1) webhook 즉시.
23. **결제·환불·홀딩 종료 트리거**: 이벤트 발생 즉시 (1분 이내).
24. **감사 로그**: 토글 변경·상세 설정 변경·전체 ON/OFF 모두 SCR-097 기록.

## 자동화 / 배치 / 이벤트 연계

| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| 만료 step 일배치 | 매일 04:00 | D-7/D-3/D-1/D-Day/D+1 대상 추출 + 설정 시각 발송 |
| 생일 알림 일배치 | 매일 04:00 | 당일 생일 회원 추출 + 09:00 발송 (지점 설정) |
| 장기 미방문 일배치 | 매일 04:00 | 30/60/90일 미방문 회원 추출 |
| 등록 감사 이벤트 | 회원 등록 트리거 | 즉시 발송 (1분 이내) |
| 첫 방문 환영 이벤트 | 첫 출석 webhook | 즉시 발송 |
| 결제 완료 이벤트 | 결제 완료 webhook | 즉시 발송 (영수증) |
| 환불 처리 이벤트 | 환불 트랜잭션 | 즉시 발송 |
| 홀딩 종료 이벤트 | 자동 재개 트랜잭션 | 즉시 발송 |
| 이용권 만료 당일 이벤트 | 만료일 00:00 | 09:00 발송 (지점 설정) |
| SCR-097 히스토리 로그 | 토글 / 상세 설정 / 전체 ON/OFF 변경 | actor·rule_id·old/new INSERT |
| SCR-072A 운영 현황 집계 | 매시간 배치 | 발송 건수·성공률·실패 사유·전환율 집계 |
| MKT-01 메시지 발송 이력 통합 | 자동 알림 발송 시 | 동일 발송 이력 테이블에 기록 |
| 자동 재시도 큐 | 발송 실패 | 1분/5분/30분 3회 재시도 |
| 본사 step 정의 변경 | 슈퍼관리자 변경 | 전 지점 즉시 동기화 + 알림 |
| 잔여 포인트 부족 알림 | 발송 시점 부족 | 운영자 알림 발송 (NFR-19) |
| 우선순위 충돌 처리 | 동일 회원 다중 트리거 | 정책에 따라 1개 또는 모두 발송 |
