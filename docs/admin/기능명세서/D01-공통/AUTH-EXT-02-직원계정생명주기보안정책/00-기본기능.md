## 기능 목적

직원 관리, 로그인, 권한 설정, 퇴사 처리, 프로필/보안 설정에 공통으로 적용되는 `직원 계정 정책`의 기준 문서다. 본 시스템은 `직원 1명 = 로그인 계정 1개`를 기본 원칙으로 하며, 직원 정보와 로그인 자격은 운영 UX에서는 하나의 흐름으로 다루고 보안 정책은 계정 상태를 통해 제어한다.

이 문서는 다음 화면들의 상위 정책을 정의한다.

- SCR-061 직원 등록/수정
- SCR-062 직원 퇴사 처리
- SCR-081 권한 설정
- SCR-100 로그인
- SCR-105 프로필 / 계정 설정

## 핵심 원칙

1. 모든 재직 직원은 로그인 계정을 가진다.
2. 로그인 계정은 직원 1명당 1개만 허용한다.
3. 로그인 계정은 직원 단위로 생성·잠금·비활성화·재활성화된다.
4. 권한은 계정에 직접 부여하지 않고 `권한 템플릿`에 연결한다.
5. 퇴사·휴직·보안 사고 시 계정 상태가 직원 상태와 함께 움직인다.
6. 동일 계정의 공유 사용은 금지한다.

## 생명주기 상태

| 직원 상태 | 계정 상태 | 로그인 가능 | 설명 |
|---|---|---|---|
| ACTIVE | ACTIVE | 가능 | 정상 재직 상태 |
| ACTIVE | LOCKED | 불가 | 재직 중 보안 잠금, 사고 대응, 임시 차단 |
| ON_LEAVE | INACTIVE | 불가 | 휴직 중 로그인 차단 |
| RESIGNING | ACTIVE 또는 LOCKED | 정책 따름 | 인수인계 기간, 센터 정책에 따라 제한 |
| RESIGNED | INACTIVE | 불가 | 퇴사 확정, 세션 즉시 만료 |
| WITHDRAWN | INACTIVE | 불가 | 강제 탈퇴, 이력 보존 |

## 계정 생성 정책

### 신규 직원 등록

- 직원 저장과 동시에 로그인 계정을 생성한다.
- 필수 입력값:
  - 직원명
  - 로그인 ID
  - 이메일
  - 역할/직무
  - 소속 지점
  - 임시 비밀번호
- 기본 보안값:
  - `forcePasswordChange = true`
  - `loginFailCount = 0`
  - `isActive = true`
  - `lockedUntil = null`

### 본사 / 지점 공통 규칙

- 본사에서 직원 등록 시 해당 직원의 본사/지점 스코프에 맞는 계정을 함께 만든다.
- 지점에서 직원 등록 시 해당 지점 스코프의 계정을 함께 만든다.
- 지점 이동이 발생하면 직원 소속과 계정의 `branchId/current scope`를 함께 조정한다.

## 권한 연결 정책

### 역할과 직무의 분리

- `직무`는 인사/운영 분류값이다.
- `권한 템플릿`은 메뉴 접근 제어 값이다.
- 직원 등록 시 직무를 선택하되, 로그인 계정은 권한 템플릿에도 연결된다.

### 기본 연결 예시

| 직원 직무 | 기본 권한 템플릿 |
|---|---|
| 센터장 | owner |
| 매니저 | manager |
| FC | fc |
| 트레이너 | trainer 계열 직무 + fc 또는 별도 템플릿 정책 |
| 스태프 / 프런트 | staff |

> 트레이너/골프강사/프런트는 인사 직무와 화면 접근 권한이 완전히 같지 않을 수 있으므로, 실제 접근 권한은 SCR-081에서 최종 확정한다.

## 보안 정책

### 인증

- 로그인 ID + 비밀번호 기반 로그인
- 첫 로그인 시 비밀번호 변경 강제
- 2FA는 역할/정책에 따라 권장 또는 강제
- 비밀번호 재설정은 이메일 기반으로 수행

### 잠금

- 로그인 실패 5회 시 자동 잠금
- 보안 사고 시 관리자가 수동 잠금 가능
- 잠금 해제는 30분 경과 후 자동 처리되며, 긴급 수동 해제는 슈퍼관리자만 본인 확인 후 수행한다.

### 세션

- 퇴사 확정 시 모든 활성 세션을 즉시 만료한다.
- 계정 비활성화 시 refresh/access token 모두 폐기 대상으로 본다.
- 권한 변경 후 다음 화면 진입 또는 refresh 시점에 신규 권한이 적용된다.

### 추적

- 로그인 성공/실패
- 잠금/잠금 해제
- 비밀번호 변경
- 권한 변경
- 퇴사/휴직/복직으로 인한 계정 상태 변경

위 이벤트는 모두 감사로그(SCR-097) 대상이다.

## 운영 시나리오

| 시나리오 | 처리 정책 |
|---|---|
| 신규 직원 입사 | 직원 등록 + 계정 생성 + 임시 비밀번호 발급 |
| 직무 변경 | 직원 정보 수정 + 권한 템플릿 재매핑 검토 |
| 비밀번호 유출 의심 | 계정 즉시 LOCKED + 활성 세션 만료 + 재설정 유도 |
| 휴직 전환 | 직원 상태 ON_LEAVE + 계정 비활성화 |
| 복직 | 직원 상태 ACTIVE + 계정 재활성화 + 필요 시 비밀번호 재발급 |
| 퇴사 예정 등록 | 인수인계 기간 동안 정책에 따라 ACTIVE 또는 LOCKED |
| 퇴사 확정 | 직원 상태 RESIGNED + 계정 INACTIVE + 세션 만료 |
| 재입사 | 신규 직원 등록 플로우로 재생성, 기존 계정 재사용 금지 기본 |

## 예외 / 금지 규칙

- 공용 프런트 계정, 지점 공용 계정, 스케줄 전용 계정은 기본 정책에서 허용하지 않는다.
- 한 직원에게 여러 관리자 계정을 발급하지 않는다.
- 퇴사한 직원 계정을 다른 직원에게 재할당하지 않는다.
- 로그인 ID 중복은 허용하지 않는다.
- 계정 공유를 전제로 한 기획/퍼블리싱은 금지한다.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `AUTH-EXT-02`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-061`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
