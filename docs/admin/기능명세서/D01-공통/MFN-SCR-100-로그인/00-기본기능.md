## 기능 목적

CRM 시스템의 유일한 공개 진입점으로, 이메일과 비밀번호를 통해 관리자 본인을 확인하고 세션을 발급받는 화면이다. 단순 인증에 그치지 않고, 로그인 성공 직후 계정에 부여된 역할(role)을 판정해 해당 역할에 맞는 첫 화면으로 자동 이동시키는 분기 로직을 포함한다.

슈퍼관리자는 슈퍼 대시보드로, 본사 최고관리자·센터장·매니저·FC는 지점 대시보드로, 트레이너는 수업 캘린더로, 스태프는 출석 관리로 이동한다. 이미 유효한 세션이 존재하는 경우 로그인 화면을 거치지 않고 대시보드로 바로 진입한다. 보안 강화가 필요한 계정에는 2단계 인증(2FA) 추가 스텝이 삽입된다. 이 로그인 계정은 직원 등록 화면(SCR-061)에서 발급되는 직원 1:1 계정이다.

## 주요 구성요소

### 브랜드 헤더

- 서비스 로고 및 서비스명 표시
- 로그인 화면 전용 레이아웃 (사이드바·헤더 없음)

### 입력 폼

| 필드 | 속성 |
|------|------|
| 이메일 | type=email, autofocus, placeholder="이메일을 입력하세요" |
| 비밀번호 | type=password, 표시/숨김 토글 버튼 포함 |
| 로그인 상태 유지 | checkbox (remember me) — 체크 시 토큰 만료 연장 |

### 액션 버튼 및 링크

| 요소 | 동작 |
|------|------|
| 로그인 버튼 | 이메일+비밀번호 유효성 검사 후 API 호출 |
| 비밀번호 재설정 링크 | SCR-106 진입 |

### 2단계 인증(2FA) 스텝

2FA 활성 계정 전용으로, 기본 인증 성공 후 추가로 표시되는 입력 영역이다.

- 인증 코드 입력란 (6자리 숫자)
- 재발송 버튼 (30초 쿨다운)
- 완료 후 역할별 화면으로 이동

### 역할별 로그인 후 이동

| 계정 유형 | 로그인 후 이동 화면 |
|---|---|
| superAdmin (슈퍼관리자) | 슈퍼 대시보드 |
| primary (본사 최고관리자) | 지점 대시보드 |
| owner (센터장) | 지점 대시보드 |
| manager (매니저) | 지점 대시보드 |
| fc (피트니스코치) | 지점 대시보드 |
| staff (스태프) | 출석 관리 |
| trainer (트레이너) | 수업 캘린더 |

## 주요 이벤트 / 자동화

- **세션 만료 감지**: 기존 세션 토큰이 만료되면 어느 화면에서든 DLG-000이 자동으로 표시되며, 재로그인 후 이전 화면으로 복귀한다.
- **자동 리다이렉트**: 이미 로그인된 사용자가 `/login`에 접근하면 역할에 맞는 첫 화면으로 즉시 이동한다.
- **토큰 갱신 배치**: 로그인 상태 유지 옵션이 활성화된 경우, refresh token으로 access token을 자동 갱신한다 (백그라운드 처리).
- **계정 잠금 알림**: 5회 연속 로그인 실패 시 30분 자동 잠금 처리, 남은 시간 카운트다운 표시, 본인/관리자 이메일 알림 발송.
- **비활성 직원 차단**: 퇴사·휴직·수동 잠금 처리된 직원 계정은 로그인 단계에서 즉시 차단한다.

## 예외 / 에러 처리

| 케이스 | 처리 |
|---|---|
| 이메일 형식 오류 | 제출 전 인라인 유효성 안내 |
| 존재하지 않는 이메일 | "이메일 또는 비밀번호가 올바르지 않습니다" (계정 존재 여부 노출 차단) |
| 비밀번호 불일치 | 동일 메시지로 통일 처리 |
| 5회 연속 실패 | 30분 계정 잠금, 남은 시간 표시, "30분 후 다시 시도하거나 관리자에게 문의하세요" 안내 |
| 2FA 코드 만료 | "인증 코드가 만료되었습니다. 재발송해주세요" 안내 |
| 2FA 코드 불일치 | "인증 코드가 올바르지 않습니다" 안내 |
| 서버 오류 (5xx) | "일시적 오류가 발생했습니다. 잠시 후 다시 시도해주세요" |
| 서비스 점검 중 | 점검 안내 화면으로 대체 표시 |
| 네트워크 단절 | 오프라인 안내 + 재시도 버튼 |

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MFN-SCR-100`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-100`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-000-세션만료`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
