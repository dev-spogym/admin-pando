## 기능 목적

관리자(본사 슈퍼관리자 / primary / 센터장 owner / 매니저 / FC / 트레이너 / 스태프 / readonly)가 `직원 등록 시 발급된 로그인 ID/PW` + 보안 정책으로 어드민 시스템에 진입하고 JWT 세션을 발급받는 화면이다. 자동 로그아웃 타이머, 5회 실패 시 30분 자동 잠금, 첫 로그인 시 비밀번호 강제 변경, 90일 만료 정책, 2FA(선택), IP 화이트리스트(본사 정책), 디바이스 핑거프린트, 동시 세션 제한 등 다층 보안을 적용해 부정 접근·계정 탈취·무차별 대입을 차단한다. 본사 슈퍼관리자는 전 지점 RLS 우회, owner는 소속 지점, manager 이하는 권한 매트릭스에 따라 접근이 제한된다.

본 시스템은 `직원 1명 = 로그인 계정 1개`를 기본 원칙으로 하며, 직원 계정은 공개 가입이 아니라 SCR-061 직원 등록/수정에서만 발급된다.

운영 맥락:
- **본사 신임 슈퍼관리자 첫 로그인**: 임시 비밀번호 + 첫 로그인 시 강제 변경 + 2FA 등록 권장
- **센터장 출근 직후 로그인**: 자동 로그인 토글 ON 상태 + 단말 기억 → 즉시 지점 대시보드(SCR-090/DASH-01) 진입
- **매니저 비밀번호 분실**: 이메일 인증 → 재설정 링크 발송 → 새 비밀번호 설정 → 자동 로그인
- **5회 연속 실패 → 30분 잠금**: 부정 시도 차단 + 알림 센터로 본인·관리자에게 알림
- **장시간 자리 비움 후 자동 로그아웃**: 30분 무활동 감지 → 토큰 만료 → 로그인 화면 복귀, 작성 중 데이터 자동 임시저장
- **본사 슈퍼관리자 IP 화이트리스트 위반**: 본사 외부 IP에서 슈퍼 권한 로그인 차단 + 보안 알림
- **퇴사자 계정 비활성화**: 직원 관리(STF)에서 비활성화 → 즉시 모든 활성 세션 강제 만료 + 재로그인 차단
- **이중 로그인(다른 기기) 감지**: 동시 세션 제한 정책에 따라 이전 세션 강제 종료 또는 알림

### JWT 세션

발급 후 토큰을 헤더에 포함해 API 호출. 만료 시 자동 갱신 또는 재로그인.

### 감사 로그

로그인 성공/실패 모두 SCR-097에 기록.

## 계정별 차이 (RBAC)

| 계정 유형 | 접근 범위 |
|---|---|
| primary / superAdmin | 전 지점 접근, 본사 정책 화면 포함 (RLS 우회) |
| owner (센터장) | 소속 지점, 본사 화면 일부 차단 |
| manager | 소속 지점, 본사 정책·감사 로그 차단 |
| fc / 트레이너 / 스태프 | 본인 정보 + 권한 범위, 어드민 메뉴 제한 |
| readonly | 조회 권한만, 모든 변경 차단 |

## 운영 시나리오 (페르소나 × 트리거 × 결과)

| 페르소나 | 사용 맥락 | 행동 | 기대 결과 |
|---|---|---|---|
| 본사 신임 슈퍼관리자 | 첫 로그인 (임시 PW 발급) | 임시 비밀번호 입력 → 강제 변경 화면 → 새 비밀번호 + 2FA 등록 | 정식 슈퍼관리자 권한 부여 + 감사 로그 기록 |
| 센터장 (owner) | 매일 출근 직후 | 자동 로그인 토글 ON → 단말 기억 → 즉시 지점 대시보드(SCR-090/DASH-01) | 30분 무활동 시점까지 세션 유지, 출근 즉시 업무 시작 |
| 매니저 | 비밀번호 분실 | [비밀번호 찾기] → 이메일 인증 → 재설정 링크 → 새 비밀번호 | 즉시 재로그인 + 비밀번호 변경 이력 감사 로그 |
| FC | 외근 중 모바일 접근 | 신뢰하지 않는 단말로 로그인 → 디바이스 핑거프린트 변경 감지 → 추가 인증(이메일 OTP) | 본인 확인 후 세션 발급 + 보안 알림 |
| 본사 슈퍼관리자 | 회의실 외부 IP에서 슈퍼 권한 시도 | IP 화이트리스트 미허용 IP에서 로그인 시도 | 차단 + "허용된 네트워크에서 접속해주세요" + 알림 센터 |
| 직원 관리자 | 퇴사자 계정 비활성화 처리 | STF에서 비활성화 → 시스템이 활성 토큰 강제 만료 | 즉시 로그아웃 + 재로그인 시 "비활성 계정" 안내 |
| 슈퍼관리자 | 잠금 해제 운영 | 5회 실패 잠금 회원 ↔ 본인 확인 후 즉시 잠금 해제 | 카운트 초기화 + 감사 로그 기록 |
| 매니저 | 다른 기기 로그인 (PC + 모바일) | 동시 세션 정책 = 1세션이면 이전 세션 강제 종료 | "다른 기기에서 로그인되어 종료되었습니다" 모달 |

## 주요 UX 흐름

**일반 로그인**
1. 로그인 화면 진입
2. ID/PW 입력 → [로그인]
3. 검증 성공 → JWT 발급 → 메인 대시보드

**잠금**
1. 5회 연속 실패
2. "30분 후 다시 시도해주세요" 안내
3. 30분 후 자동 해제

**자동 로그아웃**
1. 30분 무활동 감지
2. 세션 만료 → 로그인 화면 복귀

**첫 로그인**
1. 임시 비밀번호로 로그인
2. 비밀번호 변경 강제 화면
3. 변경 후 메인 진입

### 분기·예외 흐름
- **ID 미존재**: "ID 또는 비밀번호가 일치하지 않습니다" (보안상 ID 존재 여부 노출 금지)
- **비밀번호 불일치**: 동일 메시지 + 실패 카운트 +1 + 남은 시도 횟수 안내(정책에 따라)
- **5회 연속 실패**: 30분 자동 잠금 + "30분 후 다시 시도해주세요" + 본인 이메일/관리자 알림
- **잠금 중 재시도**: 남은 잠금 시간 표시(분/초 카운트다운) + 시도 차단
- **계정 비활성**: "비활성화된 계정입니다" + 관리자 문의 안내
- **첫 로그인 임시 PW**: 강제 변경 화면 진입, 변경 전 본 화면 접근 차단
- **비밀번호 만료(90일)**: 로그인 시 "비밀번호 변경 필요" 안내 화면 진입
- **신규 디바이스/IP 접근**: 디바이스 핑거프린트 미일치 시 추가 인증(이메일 OTP/2FA) 요구
- **2FA 미등록 슈퍼관리자**: 로그인 후 "2FA 등록을 권장합니다" 배너 + 7일 후 강제 등록
- **IP 화이트리스트 위반(슈퍼)**: 로그인 차단 + 보안 알림 센터 기록
- **동시 세션 초과**: 정책에 따라 이전 세션 강제 종료 또는 신규 차단 + 모달 안내
- **JWT refresh 만료(7일)**: 재로그인 화면 자동 이동
- **자동 로그아웃 직전 경고**: 만료 1분 전 토스트 + 작성 중 데이터 자동 임시저장
- **비밀번호 정책 위반(8자/특문)**: 인라인 에러 + 저장 차단
- **이메일 재설정 링크 만료**: "링크가 만료되었습니다" + 다시 발송 안내
- **연락처 인증 실패(ID 찾기)**: "일치하는 계정을 찾을 수 없습니다" + 관리자 문의

## 비즈니스 규칙

1. **5회 연속 실패 잠금**: 30분 자동 잠금. 사용자 ID 기준 + IP 기준 동시 카운트(IP만 차단 시 합법 사용자 차단 위험).
2. **자동 로그아웃**: 마지막 활동 후 30분 무활동 시 access 토큰 만료, refresh도 폐기.
3. **JWT 이중 구조**: access(15분) + refresh(7일). access 만료 시 refresh로 자동 갱신.
4. **비밀번호 정책**: 최소 8자, 영문/숫자/특수문자 조합 필수. 사전 단어·연속 문자·과거 비밀번호 5개 재사용 차단.
5. **첫 로그인 강제 변경**: 임시 비밀번호로 로그인 시 변경 완료 전까지 다른 화면 접근 차단.
6. **비밀번호 만료**: 90일. 시스템 설정에서 30/60/90/180일로 변경 가능.
7. **감사 로그 필수**: 로그인 성공·실패·잠금·잠금 해제·비밀번호 변경·로그아웃 모두 SCR-097에 IP·디바이스·UA·결과 기록.
8. **민감 데이터 마스킹**: 비밀번호는 평문 저장 금지(bcrypt 등 해시), 로그·응답에 절대 노출 금지.
9. **IP 화이트리스트(슈퍼)**: superAdmin / primary 권한은 본사 정책에 등록된 IP 범위에서만 로그인 가능. 외부 IP 차단.
10. **2FA 권장**: 슈퍼관리자/센터장은 2FA(TOTP/이메일 OTP) 등록 권장. 정책에 따라 강제 가능.
11. **디바이스 핑거프린트**: 신규 단말 로그인 시 추가 인증(이메일 OTP). 기억 단말은 30일 유지.
12. **동시 세션 정책**: 기본 다중 허용. 정책에 따라 1세션 제한 시 이전 세션 강제 종료.
13. **계정 비활성화 즉시 로그아웃**: 직원 비활성화 시점에 모든 활성 토큰 강제 만료. 재로그인 시 차단.
14. **자동 로그인 토글**: refresh 토큰 7일 유지. ON 시 단말 기억, OFF 시 브라우저 종료 시 토큰 폐기.
15. **로그인 시도 속도 제한**: 동일 IP 1분당 N회 초과 시도 시 임시 차단(rate limit).
16. **비밀번호 재설정 링크**: 1회용, 1시간 유효. 사용 후 폐기.
17. **ID 찾기 시 정보 마스킹**: 일치 ID는 일부 마스킹(예: ad***@example.com).
18. **세션 만료 직전 경고**: 만료 1분 전 토스트 + 작성 중 폼 데이터 임시저장(localStorage).
19. **잠금 해제 권한**: 슈퍼관리자만 수동 해제 가능. 본인 확인 후 카운트 초기화.
20. **권한 변경 즉시 반영**: 세션 중 권한 변경 시 다음 API 호출에 반영(refresh 시점).
21. **로그인 성공 시 권한·지점 컨텍스트 로드**: 세션에 `tenant_id`, `branch_id(s)`, `role`, `permissions` 포함.
22. **로그인 화면 다국어**: 한국어 기본, 운영 정책에 따라 영어 추가 가능.

| 비밀번호 만료 | "비밀번호 변경이 필요합니다" 안내 화면 | 변경 후 본 화면 진입 |
| 비밀번호 정책 위반 | 인라인 에러(8자/조합/사전어/재사용) | 저장 차단 |
| 신규 디바이스 | 추가 인증(이메일 OTP) | 본인 확인 후 단말 기억 |
| 2FA 미등록 슈퍼 | 권장 배너 + 7일 후 강제 등록 | 등록 화면 진입 |
| IP 화이트리스트 위반 | "허용되지 않은 네트워크입니다" | 보안 알림 + 차단 |
| 동시 세션 초과 | "다른 기기에서 로그인되어 종료되었습니다" 모달 | 신규 세션만 활성 |
| JWT refresh 만료 | 재로그인 화면 자동 이동 | 작성 중 데이터 임시저장 |
| 자동 로그아웃 임박 | 1분 전 토스트 경고 | 활동 시 연장 |
| 이메일 재설정 링크 만료 | "링크가 만료되었습니다" | 다시 발송 안내 |
| 연락처 인증 실패 | "일치하는 계정을 찾을 수 없습니다" | 관리자 문의 |
| Rate limit 초과 | "잠시 후 다시 시도해주세요" | 일정 시간 후 재시도 |
| 서버 오류 | "일시적인 오류" + 재시도 버튼 | 로그 기록 |
| 토큰 위조/변조 감지 | 즉시 강제 로그아웃 + 보안 알림 | 슈퍼관리자 알림 |

## 자동화 / 배치 / 이벤트 연계

| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| SCR-097 감사 로그 | 로그인 성공/실패/잠금/해제/PW 변경/로그아웃 | actor·IP·디바이스·UA·결과 INSERT |
| 알림 센터(NFR-19) | 5회 실패 잠금 / IP 위반 / 신규 단말 / 동시 세션 종료 | 본인·관리자 알림 |
| 직원 비활성화 이벤트(STF) | 직원 비활성화 트랜잭션 | 활성 토큰 강제 만료 + 재로그인 차단 |
| 비밀번호 만료 배치 | 매일 03:00 | 90일 임박 사용자에게 7일/3일/1일 전 알림 |
| 잠금 자동 해제 배치 | 30분 경과 | 잠금 카운트 초기화 |
| Refresh 토큰 갱신 | access 만료 시 | 자동 갱신 (refresh 유효 시) |
| Refresh 만료 배치 | 7일 경과 | refresh 폐기 + 재로그인 요구 |
| 디바이스 기억 만료 | 30일 경과 | 신규 단말 처리 + 추가 인증 |
| Rate limit 캐시 | 동일 IP 1분당 N회 초과 | 임시 차단 + 알림 |
| 2FA 강제 등록 캐시 | 슈퍼 로그인 후 7일 경과 | 등록 화면 강제 진입 |

## 관련 화면 / 다이얼로그 / API

- **연계 화면**: 관리자 로그인 / SCR-090 지점 대시보드 / SCR-097 감사 로그 / 비밀번호 변경 화면 / 2FA 등록 화면
- **API 기준**: `POST /api/auth/login` / `POST /api/auth/logout` / `POST /api/auth/refresh` / `POST /api/auth/forgot-password` / `POST /api/auth/reset-password` / `POST /api/auth/change-password` / `POST /api/auth/2fa/enroll` / `POST /api/auth/2fa/verify` / `POST /api/auth/unlock` (슈퍼만)

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `AUTH-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-100`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
