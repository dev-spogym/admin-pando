## 기능 목적

로그인 이후 모든 화면에서 공통으로 표시되는 좌측 고정 메뉴 영역이다. 운영자가 현재 위치를 파악하면서 시스템의 주요 기능으로 빠르게 이동할 수 있도록 한다. 계정 역할(RBAC)에 따라 접근 가능한 메뉴 항목이 다르게 렌더링되어, 불필요한 메뉴를 노출하지 않고 각 역할에 최적화된 내비게이션 구조를 제공한다.

데스크톱에서는 펼침/접힘 두 가지 모드를 지원하며, 좁은 화면에서는 아이콘만 표시하는 접힘 모드로 전환된다. 모바일 환경에서는 햄버거 버튼으로 사이드바를 열고 닫는 오버레이 방식으로 전환된다.

## 주요 구성요소

### 상단 영역

| 요소 | 동작 |
|------|------|
| 브랜드 로고 | 클릭 시 대시보드(SCR-101) 이동 |
| 지점명 표시 | 현재 선택된 지점명 (슈퍼관리자는 선택 지점명) |

### 메뉴 항목 목록

| 메뉴 | 이동 화면 | 노출 제한 역할 |
|------|-----------|----------------|
| 대시보드 | 통합 대시보드 (SCR-101) | 전체 |
| 회원관리 | 회원 목록 | 전체 |
| 매출 | 매출 현황 / 결제 취소 / 부분 환불 / 환불 관리 | trainer, staff 일부 제한. FC는 결제 취소 / 부분 환불 승인 요청 경로만 노출 |
| 수업관리 | 수업 캘린더 | 전체 |
| 상품관리 | 상품 목록 | staff, trainer 제한 |
| 시설관리 | 락커 관리 | trainer 제한 |
| 직원관리 | 직원 목록 | trainer, staff, fc 제한 |
| 마케팅 | 리드 관리 | trainer, staff 제한 |
| 설정 | 센터 설정 | trainer, staff, fc 제한 |
| 본사관리 | 본사 대시보드 | superAdmin, primary만 노출 |

### 현재 위치 강조

- 활성 메뉴 항목 강조 표시 (배경색 + 텍스트 색상 변경)
- 서브메뉴가 있는 경우 펼쳐진 상태로 표시

### 접기/펼치기 버튼

| 모드 | 표시 방식 |
|------|-----------|
| 펼침 | 아이콘 + 메뉴명 텍스트 |
| 접힘 | 아이콘만 표시, hover 시 툴팁으로 메뉴명 표시 |

### 모바일 햄버거 버튼

- 상단 헤더에 위치
- 클릭 시 사이드바 전체화면 오버레이 표시
- 메뉴 선택 또는 바깥 클릭 시 닫힘

## 권한

| 역할 | 표시되지 않는 메뉴 |
|---|---|
| superAdmin | 없음 (전체 접근) |
| primary | 없음 (전체 접근) |
| owner | 본사관리 메뉴 일부 |
| manager | 본사관리 메뉴, 직원관리 일부 |
| fc | 매출 중 결제 취소 / 부분 환불 승인 요청 외 항목, 직원관리, 상품관리, 설정 |
| staff | 매출관리, 직원관리, 마케팅, 설정 일부 |
| trainer | 매출관리, 직원관리, 시설관리, 상품관리, 마케팅, 설정 |
| readonly | 조회 가능 메뉴만, 편집 진입 차단 |

## 주요 이벤트 / 자동화

- **현재 위치 자동 강조**: 라우터 경로 변경 시 사이드바 활성 항목이 자동으로 업데이트된다.
- **접힘 상태 유지**: 사용자가 설정한 접힘/펼침 상태는 localStorage에 저장되어 다음 로그인 시에도 유지된다.
- **지점 전환 반영**: 슈퍼관리자가 지점 필터를 변경하면 지점명 표시가 즉시 업데이트된다.

## 예외 / 에러 처리

| 케이스 | 처리 |
|---|---|
| 권한 없는 URL 직접 접근 | SCR-108 403 에러 페이지로 리다이렉트 |
| 역할 정보 미로드 | 메뉴 목록 로딩 스켈레톤, 역할 확인 후 렌더링 |
| 모바일 화면 회전 | 오버레이 상태 초기화, 현재 모드 재계산 |
| 세션 만료 중 메뉴 클릭 | DLG-000 세션 만료 다이얼로그 표시 |

## 연관 문서

- 화면설계서: SCR-102-사이드바네비게이션
- 관련 기능: SCR-101-대시보드통합 (로고 클릭 이동), SCR-108-에러페이지 (권한 없는 접근)

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MFN-SCR-102`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-102`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
