## 기능 목적

관리자가 ID/PW로 시스템에 로그인하고 JWT 세션을 발급받는 화면이다. 자동 로그아웃 타이머, 5회 실패 시 30분 잠금 등 보안 정책을 적용해 부정 접근을 차단한다. 슈퍼관리자는 전 지점 접근, 센터장·매니저·FC·스태프는 소속 지점 접근만 허용된다.

## 주요 구성요소

### 로그인 폼

| 항목 | 입력 |
|------|------|
| ID (이메일) | 텍스트 |
| 비밀번호 | 마스킹 |
| 자동 로그인 | 토글 (선택) |
| [로그인] | 처리 |

### 로그인 정책

| 정책 | 설정 |
|------|------|
| 5회 연속 실패 | 30분 자동 잠금 |
| 자동 로그아웃 타이머 | 30분 무활동 |
| 비밀번호 만료 | 90일 (정책) |
| 첫 로그인 | 임시 비밀번호 변경 강제 |

### 부가 액션

| 항목 | 동작 |
|------|------|
| 비밀번호 찾기 | 이메일 인증 → 재설정 링크 |
| ID 찾기 | 연락처 인증 |
| 회원가입 안내 | 직원 등록은 관리자만 가능 |

### JWT 세션

발급 후 토큰을 헤더에 포함해 API 호출. 만료 시 자동 갱신 또는 재로그인.

### 감사 로그

로그인 성공/실패 모두 SCR-097에 기록.

## 계정별 차이 (RBAC)

| 계정 유형 | 접근 범위 |
|---|---|
| primary / superAdmin | 전 지점 접근 |
| owner (센터장) | 소속 지점 |
| manager | 소속 지점 |
| fc / 트레이너 / 스태프 | 본인 정보 + 권한 범위 |
| readonly | 조회 권한만 |

## 주요 UX 흐름

**일반 로그인**
1. 로그인 화면 진입
2. ID/PW 입력 → [로그인]
3. 검증 성공 → JWT 발급 → 메인 대시보드

**잠금**
1. 5회 연속 실패
2. "30분 후 다시 시도해주세요" 안내
3. 30분 후 자동 해제

**자동 로그아웃**
1. 30분 무활동 감지
2. 세션 만료 → 로그인 화면 복귀

**첫 로그인**
1. 임시 비밀번호로 로그인
2. 비밀번호 변경 강제 화면
3. 변경 후 메인 진입

## 화면 상태

| 상태 | 설명 |
|---|---|
| 기본 | 빈 폼 |
| 입력 중 | 검증 표시 |
| 처리 중 | 버튼 로딩 |
| 인증 실패 | "ID 또는 비밀번호가 일치하지 않습니다" |
| 잠금 | "30분 후 다시 시도" |
| 첫 로그인 | 비밀번호 변경 화면 |

## 비즈니스 규칙

1. 5회 연속 로그인 실패 시 30분 자동 잠금된다.
2. 30분 무활동 시 자동 로그아웃된다.
3. 첫 로그인 시 임시 비밀번호 변경이 강제된다.
4. 비밀번호는 최소 8자, 영문/숫자/특수문자 조합 필수이다.
5. JWT 토큰은 access(15분) + refresh(7일) 이중 구조로 운영된다.
6. 로그인 성공·실패·잠금은 모두 감사 로그(SCR-097)에 IP·디바이스와 함께 기록된다.
7. 비밀번호 90일 만료 정책은 시스템 설정에서 변경 가능하다.

## 관련 화면 / 다이얼로그 / API

- **연계 화면**: 관리자 로그인 / SCR-090 본사 대시보드 / SCR-097 감사 로그 / 비밀번호 변경 화면
- **API 추정**: `POST /api/auth/login` / `POST /api/auth/logout` / `POST /api/auth/refresh` / `POST /api/auth/forgot-password` / `POST /api/auth/reset-password` / `POST /api/auth/change-password`
