## 기능 목적

오늘 처리해야 할 업무 목록을 관리하는 화면이다. 직원 개인별 또는 지점 공유 할 일을 등록·수정·완료 체크하여 일일 업무를 체계적으로 관리한다. KPI 센터(HQ-03) 액션 큐와 연동되어 자동 생성된 액션도 본 화면에서 처리한다. 수업 일정 요청(CLS-09)에서 발생한 미처리 요청은 SCR-098 Today Tasks(오늘의 할 일) 화면의 `일정 요청 미처리` 시스템 태스크로 표시한다.

운영 맥락:
- **owner(센터장) 일일 업무 지휘**: 오전 출근 후 Today Tasks 진입 → 자동 생성 7종 태스크와 이벤트 기반 `일정 요청 미처리` 태스크 확인 → 직원 배분
- **FC 당일 리드 처리**: 자동 생성된 "미수금·재상담·생일" 태스크 → 우선순위 확인 → 처리 완료 체크
- **트레이너 OT/노쇼 관리**: 자동 생성된 "노쇼·체성분" 태스크 → 회원 연락 → 완료 처리
- **본사 superAdmin 지점 업무 현황 점검**: 전체 지점 완료율 비교 → 처리율 낮은 지점 확인
- **수기 업무 추가**: 직원이 DLG-098-001로 임시 업무 등록 → 담당자 지정 → 공유 범위 설정
- **태스크 상태 변경 이력 추적**: 완료·미완료 전환 이력 → 감사 로그(SCR-097) 연계 → 책임 소재 파악
- **우선순위 기반 정렬**: 긴급→우선→일반 순 자동 정렬 → 수동 드래그 정렬 오버라이드

### 필터 탭

| 탭 | 표시 기준 | 건수 배지 |
|---|---|---|
| 전체 | 오늘 날짜의 모든 태스크를 표시한다. 완료/미완료를 모두 포함하며 화면 진입 시 기본 선택된다. | 오늘 전체 태스크 수 |
| 미완료 | 오늘 날짜 태스크 중 완료 체크가 되지 않은 항목만 표시한다. | 오늘 미완료 태스크 수 |
| 완료 | 오늘 날짜 태스크 중 완료 체크가 된 항목만 표시한다. | 오늘 완료 태스크 수 |

정합성 메모: HQ-06-03 필터 탭은 Today Tasks 목록의 완료 상태 필터(전체/미완료/완료)만 의미한다. 본사 비교·리포트 화면의 지점/권역/KPI 유형 필터 탭과 연결하지 않는다. 탭 전환은 목록 표시만 바꾸며 태스크 상태, 담당자, 우선순위, 마감 시각은 변경하지 않는다.

채워진 폼 + 수정.

### KPI 센터 액션 연동

KPI 센터(HQ-03)에서 자동 생성된 액션이 본 화면에 자동 추가됨.

### 일정 요청 미처리 태스크

| 항목 | 기준 |
|---|---|
| 태스크명 | 일정 요청 미처리 `N` |
| 출처 | CLS-09 일정 요청 처리 / SCR-C009 일정 요청 처리 |
| 생성·갱신 조건 | 처리 상태가 `대기`, `응답대기`인 요청이 있거나, 생성 후 24시간을 초과했으나 `수락/거절/만료`가 아닌 요청이 있을 때 |
| 건수 기준 | `대기`, `응답대기`, `24시간 초과 미처리` 요청의 합계. 동일 요청은 1건으로만 계산 |
| 우선순위 | 기본 `보통`, 24시간 초과 미처리 건이 1건 이상이면 `높음` |
| 담당자 | 소속 지점 owner(센터장)와 manager에게 노출 |
| 클릭 동작 | SCR-C009(`/schedule-requests?status=pending`)로 이동하고 기본 필터 `대기/응답대기/24시간 초과` 적용 |
| 해제 조건 | 대상 요청이 모두 `수락`, `거절`, `만료` 상태가 되면 Today Tasks에서 자동 숨김 |

정합성 메모: `일정 요청 미처리`는 매일 06:00에 생성되는 자동 태스크 7종에 포함하지 않는다. CLS-09 상태 변경에 따라 실시간 또는 주기 동기화로 생성·갱신되는 이벤트 기반 시스템 태스크다.

## 주요 UX 흐름

**할 일 조회**
1. 사이드바 → "본사관리 > Today Tasks" 진입

3. 진행 현황 요약 카드 확인

1. [+ 할 일 추가] → DLG-098-001

2. [삭제] → 확인 → 제거

## 비즈니스 규칙

1. 오늘 날짜가 변경되면 자동으로 새 할 일 목록이 표시된다.
2. 미완료 항목은 다음 날로 자동 이월되지 않으며 별도 알림으로 안내된다.
3. KPI 센터(HQ-03) 액션 큐에서 자동 생성된 액션은 우선순위 "높음"으로 자동 추가된다.
4. 매니저 이하는 본인이 담당자인 항목만 완료 처리 가능하다.
5. 공유 범위 "지점"으로 등록된 할 일은 같은 지점 직원 모두에게 표시된다.
6. 변경·완료 이력은 감사 로그에 기록된다.
7. 자동 생성 태스크 7가지 카테고리: 만료 예정·미수금·노쇼·생일·홀딩·재상담·체성분.
8. 자동 생성 태스크는 매일 06:00 배치로 생성되며 해당 대상이 없는 카테고리는 생략한다.
9. 자동 생성 태스크 우선순위: 만료·미수금 = 높음, 노쇼·재상담 = 보통, 생일·홀딩·체성분 = 낮음.
10. 완료 처리는 취소(미완료 복원) 가능하며 복원 이력도 감사 로그에 기록된다.
11. 태스크 삭제는 삭제 확인 모달 후 영구 삭제되며 복구 불가하다.
12. 수동 정렬(드래그앤드롭)은 우선순위 자동 정렬보다 우선 적용된다.
13. 필터 탭 "전체/미완료/완료"는 현재 날짜 기준 태스크만 대상으로 한다.
14. DLG-098-001 공유 범위 "개인"은 본인만 조회 가능, "지점"은 동일 지점 전 직원 조회 가능.
15. KPI 센터 큐 완료 처리와 Today Tasks 완료 처리는 양방향 동기화된다.
16. 진행 현황 요약 완료율 = 완료 항목 수 ÷ 전체 항목 수 × 100 (소수점 없음).
17. 마감 시각 미설정 태스크는 목록 하단에 표시된다.
18. owner/superAdmin은 전체 지점 태스크 조회 및 직원 담당자 지정 가능하다.
19. 태스크 상태 변경(완료·미완료·수정·삭제)은 모두 감사 로그(SCR-097)에 자동 기록된다.
20. 미완료 알림은 전날 23:50에 담당자에게 앱 푸시로 발송한다.
21. CLS-09 일정 요청 미처리 태스크는 `대기`, `응답대기`, `24시간 초과 미처리` 요청을 기준으로 생성·갱신하며, 대상 요청이 모두 처리되면 자동 숨김 처리한다.
22. CLS-09 일정 요청 미처리 태스크 클릭 시 SCR-C009로 이동하며 기본 필터는 `대기/응답대기/24시간 초과`다.

## 관련 화면 / 다이얼로그 / API

- **연계 화면**: SCR-098 / SCR-095 KPI 센터 / SCR-090 지점 대시보드 / SCR-C009 일정 요청 처리
- **연계 다이얼로그**: DLG-098-001 태스크추가 / DLG-098-002 태스크상세수정
- **API 기준**: `GET /api/today-tasks` / `POST /api/today-tasks` / `PUT /api/today-tasks/:id` / `DELETE /api/today-tasks/:id` / `POST /api/today-tasks/:id/complete`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `HQ-06`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-098`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-098-001 태스크추가, DLG-098-002 태스크상세수정`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
