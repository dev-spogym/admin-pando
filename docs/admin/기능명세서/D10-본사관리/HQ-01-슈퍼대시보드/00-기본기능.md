## 기능 목적

본사 슈퍼관리자(`superAdmin`/`primary`) 전용 화면(SCR-091)으로, 전 지점 통합 KPI 7종 + 지점별 현황 카드 + 최근 히스토리 로그를 한 화면에서 파악하는 본사 지휘 통제실(Command Center)이다. 전월 대비 매출/회원 증감, 전일 대비 출석 증감을 색상 코딩(양수 초록 ↑ / 음수 빨강 ↓)으로 즉시 위기 지점 식별이 가능하다. [지점 전환] 액션으로 RLS 우회 + 해당 지점 모드로 지점 대시보드(SCR-090) 진입, [지점 상세]로 운영 정보 페이지(SCR-092) 진입한다. 모든 지점 전환은 감사 로그(SCR-097)에 기록되어 본사 권한 행사 추적이 가능하다.

운영 맥락:
- **본사 임원 매일 아침 점검**: 슈퍼 로그인 → 자동 진입 → 7개 KPI + 지점별 카드 5분 내 점검 → 위기 지점 식별
- **위기 지점 즉시 대응**: 매출 -20% 이상 지점 카드 빨강 → [지점 전환] → 지점 대시보드 → 액션 큐 진입
- **본사 영업 회의 자료 준비**: 전월 대비 증감률 색상 코딩 → 화면 캡처 또는 KPI 대시보드(HQ-02) 이동
- **신규 오픈 지점 모니터링**: 운영 상태 `오픈 예정` 카드 → 운영 시작일 임박 점검
- **임시휴업 지점 관리**: 휴업 카드 → 진행 중 회원 영향 점검 → 환불 처리 추적
- **전사 통합 회원 흐름 분석**: 신규 회원·만료 회원·출석 → 본사 차원 마케팅 의사결정
- **이상 지점 감지**: 직원 수 0 또는 출석 급감 지점 → 알림 + 즉시 점검
- **지점 전환 후 복귀**: 지점 모드에서 다시 슈퍼 모드로 복귀 → 사이드바 또는 헤더 [본사로]

## 주요 UX 흐름

1. 슈퍼관리자 로그인 → 화면 진입
2. 전체 지점 데이터 자동 로드 → 스켈레톤 → 수치 전환 (5분 캐시)
3. KPI 카드(7종) + 지점별 카드 + 최근 히스토리 로그 확인
4. [지점 전환] 클릭 → 모드 변경 → 해당 지점 대시보드(SCR-090) 자동 이동 + 감사 로그
5. [지점 상세] → SCR-092 지점 관리 진입
6. 슈퍼관리자 외 접근 시 권한 안내 + 본사 대시보드 자동 이동

### 분기·예외 흐름
- **권한 부족 (owner/manager 등)**: "본 화면은 슈퍼관리자 전용입니다" 안내 + 본사 대시보드 자동 이동
- **지점 0개 (신규 본사)**: 빈 상태 + [지점 등록] CTA → SCR-092
- **KPI 데이터 없음 (신규)**: 모든 카드 0 + "데이터를 수집 중입니다"
- **지점 카드 데이터 부족**: 해당 지점 카드만 부분 데이터 + "데이터 수집 중" 배지
- **API 오류**: 카드별 재시도 버튼 + 토스트
- **5분 캐시 만료**: 자동 재조회. 수동 새로고침 즉시 갱신
- **지점 전환 후 모드 표시**: 헤더에 "현재 지점: XX점 (본사 모드 → 지점 모드)" 표시
- **지점 모드에서 본사 복귀**: 사이드바 [본사로] 또는 헤더 → 모드 복귀 + 슈퍼 대시보드 진입
- **임시휴업/폐점 지점**: 카드 흐림 + 상태 배지 + KPI 일부 표시 안 함
- **전월 대비 증감 N/A**: 신규 지점은 첫 달 "신규" 배지로 표시, 증감 미표시

## 비즈니스 규칙

1. **권한 제한**: 본 화면은 `superAdmin`/`primary`만 접근. 외 권한은 지점 대시보드(SCR-090)로 자동 이동.
2. **증감률 계산**: 매출·회원은 전월 대비, 출석은 전일 대비. 양수 초록 ↑ / 음수 빨강 ↓.
3. **신규 지점 증감**: 첫 달은 "신규" 배지로 표시, 증감 미표시.
4. **지점 전환 메커니즘**: 모드 변경 시 세션 컨텍스트에 `current_branch_id` 설정 → 해당 지점 대시보드로 이동 → 감사 로그 INSERT.
5. **지점 운영 상태 표시**: SCR-092에서 설정된 4종(`운영 중` / `오픈 예정` / `임시휴업` / `폐점`) 그대로 반영.
6. **데이터 캐시**: KPI는 5분 캐시. 수동 새로고침으로 즉시 갱신. 지점 카드도 동일.
7. **감사 로그 필수**: 지점 전환·새로고침은 actor·타깃 branch_id 기록.
8. **RLS 우회**: 슈퍼관리자는 모든 지점 데이터 조회 가능 (RLS 우회 권한).
9. **휴업/폐점 카드**: 흐림 처리 + 상태 배지. KPI는 휴업 시 부분 표시, 폐점 시 비표시.
10. **히스토리 로그 (최근 10건)**: 시스템 전체 액션 중 주요 이벤트 (등록·결제·환불·정책 변경)만. SCR-097 일부.
11. **지점 카드 정렬**: 매출 순 또는 가나다 순 기본. 토글 가능.
12. **운영 시작일 도래 자동 전환**: `오픈 예정` → `운영 중` 자동 (배치). 슈퍼 대시보드 자동 갱신.
13. **폐점 후 데이터 보관 기간**: 6개월 보관 후 아카이브 → 슈퍼 대시보드에서 제외.
14. **이상 감지**: 직원 수 0 또는 출석 전일 대비 -50% 초과 시 카드 빨강 강조 + 토스트.
15. **만료 회원 vs 만료 임박**: 분리 카드. 만료 임박 = 30일 이내, 만료 = 이미 만료.
16. **이번 달 신규 회원 카운트**: 1일 ~ 오늘까지 등록 회원 수. 환불·삭제 회원 제외.
17. **지점 전환 시 권한 컨텍스트**: 슈퍼는 그대로 유지. 일반 직원처럼 보지 않음(RLS 우회).
18. **본사 모드 복귀**: 헤더 [본사로] 또는 사이드바. 컨텍스트 초기화 + 슈퍼 대시보드.
19. **모바일 반응형**: 카드 1열 또는 2열로 자동 재배치.
20. **지점 수 제한**: 라이선스 한도 내. 초과 시 신규 등록 차단(SCR-092 정책).

2. 화면 동작은 연계 화면설계서 `SCR-091`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
