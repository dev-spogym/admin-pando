## 기능 목적

본사가 전사 자동화 정책 세트를 관리하는 화면이다. 만료 알림·운영 자동화 정책을 세트 단위로 생성·수정·중지하고, 정책별 스텝(기준일·채널·템플릿·필수 여부)을 라이브러리화하여 지점에 적용한다. 고정 D-day 대신 본사가 입력한 기준일 step 리스트 구조를 사용한다.

운영 맥락:
- **전사 표준 정책 배포**: 본사가 신규 만료 알림 정책 세트를 생성하면, 기본 정책으로 지정된 세트가 신규 지점 등록 시 자동 적용된다.
- **지점별 맞춤 채널 허용**: 지점 수정 허용 범위를 "채널만 변경 허용"으로 설정하여 지점별 선호 채널(SMS/카카오/앱푸시)을 유연하게 운영한다.
- **정책 충돌 사전 방지**: 동일 기준일 스텝이 중복될 경우 저장 전 경고를 노출하여, 회원이 동일 날짜에 중복 메시지를 받는 상황을 방지한다.
- **시뮬레이션으로 검증 후 배포**: 정책 세트 수정 전 시뮬레이션(가상 회원 적용)으로 스텝 발송 타이밍을 검증하고, 확인 후 전사 배포한다.
- **비활성 지점 선별 적용**: 특정 지점군(예: 신규 개설 지점, 지방 거점 지점)에만 적용 범위를 한정하여 정책 효과를 집중시킨다.
- **정책 롤백**: 수정 후 지점 VOC 증가·발송 오류 급증 시, 이전 정책 세트 버전으로 1클릭 롤백하여 운영 안정성을 즉시 복원한다.
- **감사 로그 추적**: 본사 컴플라이언스 담당자가 SCR-097에서 정책 수정 이력(누가, 언제, 어떤 스텝을 변경했는지)을 전수 조회한다.

## 분기·예외 흐름

- **스텝 0개로 저장 시도**: "스텝을 최소 1개 이상 추가해주세요" 인라인 오류, 저장 차단.
- **기준일 중복 스텝 입력**: 경고 배너("동일 기준일 스텝이 있어요") 표시, 사용자 확인 후 저장은 허용.
- **사용 중지 시 기존 지점 영향 고지**: "현재 {개수}개 지점에 적용 중입니다. 중지하면 신규 적용만 차단됩니다" 확인 다이얼로그 → 확정 시 중지.
- **기본 정책 중지 시도**: "기본 정책은 중지할 수 없습니다. 다른 세트를 기본으로 지정 후 중지해주세요" 차단.
- **정책 삭제 시 사용 중인 지점 존재**: 삭제 차단, "사용 중인 지점이 있어 삭제할 수 없습니다" 안내.
- **지점 수정 허용 범위 "변경 불가"인 스텝 편집 시도(지점 측)**: 편집 UI 비활성화, 잠금 아이콘 표시.
- **필수 스텝 삭제 시도**: "필수 스텝은 삭제할 수 없습니다" 차단, 선택 스텝으로 변경 후 삭제 가능.
- **정책 수정 후 저장 시 영향 범위 0개**: 별도 고지 없이 즉시 저장.
- **정책 수정 후 영향 범위 {개수}개**: "{개수}개 지점에 즉시 적용됩니다" 고지 다이얼로그 → 확정.
- **롤백 대상 버전 없음**: "롤백 가능한 이전 버전이 없습니다" 안내.
- **정책 복제 시 이름 중복**: "이미 같은 이름의 정책 세트가 있어요" 인라인 오류, 새 이름 입력 요구.
- **superAdmin 외 계정 접근**: 화면 진입 자체 차단, 403 처리.

**정책 세트 조회**
1. 사이드바 → "본사관리 > 자동화 정책 라이브러리" 진입
2. 정책 세트 카드 + 테이블 확인
3. 카드 또는 행 선택 → 우측 스텝 미리보기·사용 현황 패널 갱신

**정책 세트 신규 등록**
1. [+ 정책 세트] → DLG-H1001-001
2. 기본정보(이름·범위·사용 상태·기본 여부) 입력
3. 스텝 리스트 추가 (기준일·채널·템플릿·필수)
4. 지점 수정 허용 범위 설정
5. 저장 → 카드/테이블에 추가

**정책 수정**
1. 카드/테이블 [편집] → DLG-H1001-001 (기존 값 채워짐)
2. 정보·스텝 변경
3. 저장 → 영향 범위 고지 → 확정 시 적용

**사용 중지**
1. [중지] → 확인 다이얼로그
2. 신규 적용 차단 + 기존 사용 지점 영향 범위 고지
3. 확정 → 카드 상태 "중지"로 변경

## 비즈니스 규칙

1. 본 화면은 superAdmin / primary 계정만 접근 가능하다. 그 외 계정은 403으로 차단된다.
2. 고정 D-day 대신 본사가 입력한 기준일 step 리스트 구조를 사용한다. 기준일은 음수(이용권 만료 전 {기준일수}일)·양수(만료 후 {기준일수}일) 모두 허용한다.
3. 정책명은 필수이며 전사 중복 불가. 스텝은 최소 1개 이상 등록되어야 저장 가능하다.
4. 동일 정책 세트 내 기준일 중복 시 경고 표시 후 사용자 확인이 필요하다. 강제 저장은 허용하되 이중 발송 책임은 운영자에게 있다.
5. 사용 중지된 정책은 신규 적용만 차단되고 기존 사용 지점은 그대로 동작한다. 중지 전 영향 범위(지점 수) 고지가 필수이다.
6. **기본 정책 세트**: 전사에 1개만 지정 가능하다. 신규 지점 등록 시 자동 적용된다. 기본 정책은 중지·삭제 불가이며, 다른 세트를 기본으로 지정 후 변경해야 한다.
7. **지점 수정 허용 범위 3단계**: ① 스텝별 토글 허용(스텝 ON/OFF 가능) ② 채널만 변경 허용 ③ 변경 불가. 스텝별로 독립 설정 가능하다.
8. **필수 스텝 잠금**: 필수(required) 스텝은 지점에서 OFF 토글 불가. 필수 → 선택 변경 권한은 본사 superAdmin 전용이다.
9. **정책 버전 관리**: 수정 시 이전 버전 스냅샷을 보존하여 롤백 가능하다. 최대 보존 버전 수는 10개이다.
10. **롤백**: 이전 버전 선택 시 현재 정책을 해당 버전으로 즉시 교체. 영향 지점에 재적용 트리거 발생.
11. **시뮬레이션**: 실제 발송 없이 가상 회원(이용권 만료일 임의 설정)에 정책을 적용하여 스텝 발송 타이밍 미리보기. 결과는 화면 내 임시 표시, 저장 안 됨.
12. **정책 충돌 감지**: 동일 지점에 2개 이상의 정책 세트가 겹쳐 적용될 경우 충돌 경고를 노출한다. 충돌 해소 전까지 두 번째 정책 적용 차단.
13. **정책 복제**: 기존 세트 전체를 복사하여 새 이름으로 저장. 복제 직후 상태는 "중지"이며 명시적으로 활성화해야 한다.
14. **채널 가용성 검증**: 스텝 저장 시 선택 채널(SMS/카카오/앱푸시)이 테넌트 내 활성화된 채널인지 검증한다. 비활성 채널 선택 시 경고.
15. **정책명 정책**: 1~50자, 특수문자 허용(괄호·하이픈), 이모지 차단. 전사 중복 불가.
16. **SET-EXT-01 페어링**: 외부 연동 알림 세트(SET-EXT-01)와 본 정책 라이브러리가 동일 지점에 중복 적용 시, SET-EXT-01이 우선순위를 가진다. 충돌 표시 필수.
17. **감사 로그 필드**: 정책 세트 생성·수정·중지·복제·롤백 모두 SCR-097에 기록. `policy_set_id`, `actor_id`, `action`, `diff_snapshot`, `affected_branch_count` 저장.
18. **정책 삭제 조건**: 사용 중인 지점이 0개이고 기본 정책이 아닌 경우에만 삭제 가능. 삭제 시 버전 이력도 함께 삭제된다.
19. **스텝 채널 다중 선택**: 동일 기준일 스텝에 채널을 2개 이상 선택하면 동일 시점에 2개 채널로 발송된다. 중복 발송 의도 명시 팝업 표시.
20. **적용 범위 변경**: "전사 → 특정 지점군" 변경 시 기존 전사 적용 지점 중 범위 외 지점에는 자동 해제 알림 발송.
21. **스텝 순서**: 기준일 오름차순 자동 정렬. 동일 기준일 내 순서는 등록 순 유지.
22. **정책 내보내기**: 정책 세트 전체(스텝 목록 포함)를 PDF로 내보낼 수 있다. 헤더에 생성자·생성일·버전 번호 자동 삽입.

| 정책명 미입력 | 인라인 "정책명을 입력해주세요" | 저장 차단 |

| 스텝 0개 저장 시도 | 인라인 "스텝을 최소 1개 이상 추가해주세요" | 저장 차단 |
| 기준일 중복 스텝 | 경고 배너 "동일 기준일 스텝이 있어요" | 확인 후 저장 허용 |
| 기본 정책 중지 시도 | 모달 "기본 정책은 중지할 수 없습니다" | 다른 기본 정책 지정 후 재시도 안내 |
| 사용 중 정책 삭제 시도 | 모달 "사용 중인 지점이 있어 삭제할 수 없습니다" | 삭제 차단, 지점 목록 확인 유도 |
| 필수 스텝 삭제 시도 | 인라인 "필수 스텝은 삭제할 수 없습니다" | 선택 스텝 변경 후 삭제 안내 |
| 비활성 채널 선택 | 경고 "해당 채널은 현재 비활성 상태입니다" | 저장은 허용, 발송 시 실패 가능성 안내 |
| 롤백 가능 버전 없음 | "롤백 가능한 이전 버전이 없습니다" | 안내 토스트 |
| 정책 복제 이름 중복 | 인라인 "이미 같은 이름의 정책 세트가 있어요" | 새 이름 입력 요구 |
| SET-EXT-01 충돌 | 경고 배지 "외부 연동 세트와 충돌" + 충돌 상세 패널 | 충돌 해소 전 두 번째 정책 적용 차단 |
| 정책 수정 중 네트워크 오류 | 토스트 "저장에 실패했습니다. 다시 시도해주세요" | 편집 내용 로컬 임시 보존 |
| superAdmin 외 접근 시도 | 403 화면 | 접근 불가 안내 |
| 시뮬레이션 데이터 부족 | "시뮬레이션에 필요한 데이터가 부족합니다" | 최소 조건 안내 |
| 영향 지점 재적용 실패 | 관리자 알림 + 실패 지점 목록 노출 | 수동 재적용 버튼 제공 |

## 자동화 / 배치 / 이벤트 연계

| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| SCR-097 감사 로그 | 정책 세트 생성·수정·중지·복제·롤백 | `policy_set_id`, `actor_id`, `action`, `diff_snapshot`, `affected_branch_count` INSERT |
| 신규 지점 등록 이벤트 | 지점 생성 트랜잭션 | 기본 정책 세트 자동 적용 (SET-DEFAULT 트리거) |
| 정책 수정 배포 이벤트 | 저장 확정 시 | 영향 범위 내 지점 정책 캐시 무효화 + 재적용 배치 실행 |
| 정책 롤백 이벤트 | 롤백 확정 시 | 이전 버전 스냅샷 복원 + 영향 지점 재적용 트리거 |
| SET-EXT-01 충돌 감지 배치 | 정책 적용 범위 변경 시 | 충돌 지점 목록 생성 + 경고 배지 갱신 |
| 발송 실패 모니터링 | 스텝 발송 실행 후 | 실패율 임계값(30%) 초과 시 자동 알림 + 정책 일시 중단 고려 안내 |
| 버전 스냅샷 보존 배치 | 정책 수정 저장 시 | 이전 버전 스냅샷 DB 저장 (최대 10개 보존, FIFO 삭제) |
| NFR-19 알림 센터 | 정책 중지·충돌·배포 실패 | superAdmin 대상 인앱 알림 발송 |
| 시뮬레이션 처리 | [시뮬레이션 실행] 클릭 | 가상 회원 데이터 대입 → 스텝 타이밍 계산 → 결과 임시 렌더링 (DB 미저장) |
| 채널 가용성 검증 배치 | 스텝 저장 시 | 테넌트 활성 채널 목록과 대조, 비활성 채널 경고 플래그 설정 |
| 정책 내보내기 배치 | [PDF 내보내기] 클릭 | 정책 세트 + 스텝 목록 + 버전 정보 PDF 생성 후 다운로드 |

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `HQ-09`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-H1001`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-H1001-001 정책세트편집`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
