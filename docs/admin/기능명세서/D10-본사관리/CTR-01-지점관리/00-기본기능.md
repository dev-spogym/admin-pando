## 기능 목적

본사 슈퍼관리자가 가맹·직영 지점 전체의 현황을 조회하고, 신규 지점 등록 다이얼로그에서 지점 기본 정보와 초기 Owner(지점장)을 입력해 지점을 생성하거나 기존 지점의 운영 상태(운영 중 / 오픈 예정 / 임시휴업 / 폐점)를 변경하며, 지점 간 통합 성과를 비교하는 화면이다. 본사 차원의 인사·자원 배분, 정책 세트 적용, 신규 오픈 워크플로우, 폐점 정리, 위기 지점 식별 의사결정의 단일 진입점이다. 지점 등록 시 본사 표준 정책 세트(HQ-09)가 자동 적용되고, 모든 변경은 감사 로그(SCR-097)에 기록되며, 데이터 격리(`branch_id`/`tenant_id` 기반 RLS)를 위반하지 않도록 강제된다.

운영 맥락:
- **신규 지점 가맹 계약 후 시스템 등록**: 본사 슈퍼관리자가 신규 지점 등록 다이얼로그에서 지점명·지점 코드·주소·대표 연락처·운영 시작일·초기 Owner(지점장)을 입력 → 본사 표준 정책 세트 자동 적용 → 운영 시작일 도래 시 `운영 중` 활성
- **신규 오픈 전 준비 단계**: 운영 시작일 이전 = `오픈 예정` 상태 → 직원 등록·상품 세팅 가능, 회원 등록은 시작일 이후 활성
- **임시 휴업(리모델링·휴업 신고)**: 운영 상태 → `임시휴업`. 진행 중 회원 이용권 자동 홀딩(정책에 따라) + 신규 가입 차단
- **폐점 처리**: 운영 상태 → `폐점`. 활성 회원 자동 환불·이관 안내 → 데이터 {개수}개월 보관 후 아카이브
- **센터장 교체**: 지점 수정 → 신규 센터장 매핑 + 기존 센터장 권한 회수 → 감사 로그
- **본사 임원 통합 비교**: 통합 현황 비교 탭에서 지점별 매출·회원·출석·KPI 한눈 비교 → 위기 지점 식별 → HQ-04 지점 리포트 진입
- **폐점 후 데이터 복구 요청**: 아카이브 데이터 복원 (슈퍼관리자만, 별도 승인 워크플로우)
- **지점 합병 / 분할**: 회원·매출 데이터 이관(MBR-ADV-02) + 본사 합병 처리(별도 마이그레이션)

## 주요 구성요소

### 지점 목록

| 컬럼 | 설명 |
|------|------|
| 지점명 | 지점의 운영 표시명. 행 클릭 시 지점 상세 정보 패널 또는 상세 화면을 연다. |
| 지점 코드 | 본사가 지점을 식별하는 고유 코드. 자동 생성 또는 수동 입력값을 표시한다. |
| 주소 | 지점의 대표 주소. 검색 대상이며 긴 주소는 말줄임 처리 후 hover 또는 상세에서 전체 표시한다. |
| 연락처 | 지점 대표 연락처. 전화번호 형식으로 표시한다. |
| 회원 수 | 해당 지점의 활성 회원 수. 폐점 지점은 폐점 시점 기준 보존 수치를 표시한다. |
| 직원 수 | 해당 지점 소속 재직 직원 수. 휴직자는 포함하고 퇴사자는 제외한다. |
| 운영 상태 | `운영 중` / `오픈 예정` / `임시휴업` / `폐점` 4종 배지 중 하나를 표시한다. |
| 등록일 | 시스템에 지점이 등록된 날짜. `YYYY-MM-DD` 형식으로 표시한다. |
| 액션 | [수정] / [비활성화] 또는 상태별 가능한 액션을 표시한다. 권한이 없으면 hidden 또는 disabled 처리한다. |

### 검색 / 필터

- 지점명 / 주소 키워드
- 운영 상태 (전체 / 운영 중 / 오픈 예정 / 임시휴업 / 폐점)

### 신규 지점 등록 다이얼로그

| 항목 | 입력 |
|------|------|
| 지점명 | 텍스트 (필수) |
| 지점 코드 | 자동 또는 수동 |
| 주소 | 주소 검색 |
| 연락처 | 010 |
| 운영 시작일 | 캘린더 |
| 초기 Owner(지점장) 지정 | 기존 직원 검색 또는 신규 초대 이메일 입력 |
| 정책 세트 적용 | 본사 표준 정책 세트 자동 적용 |

### 비활성화 / 운영 상태 변경 확인 다이얼로그

운영 중인 지점을 `임시휴업` 또는 `폐점` 상태로 변경하기 전 영향 범위를 확인하고 최종 확정을 받는 다이얼로그다. 대상 지점명, 현재 운영 상태, 변경 후 운영 상태, 예정일, 사유, 영향 범위를 표시한다.

| 항목 | 입력/표시 |
|------|------|
| 대상 지점 | 변경 대상 지점명과 지점 코드 표시 |
| 현재 운영 상태 | 현재 상태 배지 표시 |
| 변경 후 운영 상태 | `임시휴업` 또는 `폐점` 선택/확인 |
| 적용 예정일 | 즉시 또는 날짜 지정 |
| 변경 사유 | 필수 입력 |
| 영향 안내 | 직원 계정 접근, 회원 앱 노출, 신규 가입·결제·예약 차단 여부, 진행 예약 수, 활성 회원 수 |
| 확인 액션 | [취소] / [운영 상태 변경] |

### 통합 현황 비교 탭

지점별 회원 수 / 매출 / 출석률을 기간(월간/주간/연간)으로 비교한다. CTR-01의 통합 비교는 지점 관리 화면 안에서 위기 지점과 우수 지점을 빠르게 식별하는 요약 기능이며, 상세 분석·내보내기·수업별 분석은 HQ-04 지점 성과 리포트로 이동해 확인한다.

#### 통합 비교 차트

| 차트 | 표시 기준 | 동작 |
|---|---|---|
| 지점별 총매출 비교 막대 차트 | 선택 기간의 지점별 총매출. 매출 집계 기준은 SCR-S004 매출통계 기준을 따르며 환불은 차감한다. | 기본 정렬은 총매출 높은 순. 막대 hover 시 지점명, 총매출, 기간을 표시한다. |
| 지점별 활성 회원 수 비교 막대 차트 | 선택 기간 종료일 기준 활성 회원 수. 폐점 지점은 기본 비교에서 제외한다. | 막대 hover 시 지점명, 활성 회원 수, 기간을 표시한다. |
| 지점별 출석률 비교 막대 차트 | 선택 기간의 실제 출석 인원 합계 / 예약 인원 합계 × 100. 취소 예약은 분모에서 제외하고 노쇼는 출석에서 제외한다. | 막대 hover 시 지점명, 출석률, 출석 인원, 예약 인원을 표시한다. |

#### 통합 비교 테이블

| 컬럼 | 표시 기준 |
|---|---|
| 순위 | 기본 정렬 기준인 총매출 순위. 정렬 변경 시 화면 순번으로 갱신한다. |
| 지점명 | 지점 이름. 행 클릭 시 HQ-04 지점 성과 리포트로 이동한다. |
| 운영 상태 | `운영 중` / `오픈 예정` / `임시휴업` / `폐점` 배지. 비교 기본값은 `운영 중` 지점이다. |
| 총매출 | 선택 기간의 총매출. 환불 차감 후 금액으로 표시한다. |
| 활성 회원 수 | 선택 기간 종료일 기준 활성 회원 수. |
| 출석 수 | 선택 기간의 실제 출석 인원 합계. |
| 출석률 | 실제 출석 인원 합계 / 예약 인원 합계 × 100. |
| 매출 증감률 | 직전 동일 기간 대비 총매출 증감률. 데이터가 없으면 `-`로 표시한다. |
| 상세 | [상세 보기] 버튼. 선택 지점과 기간을 유지한 상태로 HQ-04 지점 성과 리포트에 진입한다. |

테이블은 총매출, 활성 회원 수, 출석률, 매출 증감률 컬럼 정렬을 지원한다. 차트 막대를 클릭하면 같은 지점의 테이블 행을 강조하고, 테이블 행 또는 [상세 보기]를 클릭하면 HQ-04로 이동한다.

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin | 전체 지점 | 등록·수정·비활성·비교·폐점·정책 적용·복원 |
| owner (센터장) | 소속 지점 | 소속 지점 정보 수정(연락처·주소 등 제한 항목만), 운영 상태 변경 불가 |
| manager 이하 | 접근 불가 | ❌ |
| readonly | ❌ | ❌ |

## 운영 시나리오 (페르소나 × 트리거 × 결과)

| 페르소나 | 사용 맥락 | 행동 | 기대 결과 |
|---|---|---|---|
| 본사 슈퍼관리자 | 신규 가맹 지점 등록 | 신규 지점 등록 다이얼로그에서 지점명·주소·운영 시작일·초기 Owner(지점장)·정책 적용 기준 입력 | 지점 등록 + 표준 정책 자동 적용 + Owner(지점장) 권한 부여 + 감사 로그 |
| 본사 슈퍼관리자 | 임시 휴업 처리 | 비활성화/운영 상태 변경 확인 다이얼로그에서 진행 중 회원·예약 영향 확인 → 확정 | 운영 상태 = `임시휴업`, 회원 이용권 자동 홀딩(정책 토글), 신규 가입 차단 |
| 본사 슈퍼관리자 | 폐점 처리 | 운영 상태 → `폐점` → 환불 안내 → 활성 회원 이관 처리(MBR-ADV-02) | 폐점 + {개수}개월 데이터 보관 후 아카이브 |
| 본사 슈퍼관리자 | 위기 지점 식별 | 통합 비교 탭 → 매출 하위·이탈 상위 지점 식별 → HQ-04 지점 리포트 진입 | 본사 차원 지원 의사결정 |
| 본사 슈퍼관리자 | 센터장 교체 | 지점 수정 → 신규 센터장 매핑 → 기존 센터장 비활성 처리 | 권한 즉시 이관 + 감사 로그 |
| 센터장 (owner) | 지점 연락처·주소 변경 | 지점 수정 → 연락처·주소 일부 항목만 변경 가능 | 본사 승인 없이 즉시 반영, 감사 로그 |
| 본사 임원 | 신규 오픈 일정 점검 | 지점 목록 → `오픈 예정` 필터 → 운영 시작일 임박 지점 확인 | 사전 점검 액션 트리거 |
| 본사 슈퍼관리자 | 폐점 데이터 복원 요청 | 아카이브된 폐점 지점 복원 → 운영 상태 = `운영 중` | 회원·매출·이용권 데이터 복구 + 감사 로그 |

## 주요 UX 흐름

**지점 조회**
1. 사이드바 → "본사관리 > 지점 관리" 진입
2. 전체 지점 목록 자동 로드
3. 검색·필터로 좁히기 (지점명·주소·운영 상태)

**신규 등록**
1. [신규 지점 등록] 클릭 → 신규 지점 등록 다이얼로그 표시
2. 지점명·코드(자동/수동)·주소(검색)·연락처·운영 시작일 입력
3. 초기 Owner(지점장)을 기존 직원 검색 또는 신규 초대 이메일로 지정
4. 본사 표준 정책 세트 자동 적용 기준 확인
5. 저장 → 목록 추가 → Owner(지점장) 권한 부여 → 자동 감사 로그

**비활성화**
1. [비활성화] 또는 운영 상태 변경 액션 클릭 → 비활성화/운영 상태 변경 확인 다이얼로그 표시
2. 변경 후 상태(`임시휴업` 또는 `폐점`), 적용 예정일, 변경 사유 입력
3. 진행 중 회원·직원·예약·이용권 영향 안내 확인 (정량 표시: "활성 회원 {활성회원수}명, 진행 예약 {진행예약수}건")
4. 확인 → 운영 상태 변경 → 자동 알림 (직원·회원 정책에 따라) → 감사 로그 기록

**통합 비교**
1. "통합 현황 비교" 탭
2. 기간 선택 (월간/주간/연간)
3. 총매출, 활성 회원 수, 출석률 비교 차트와 지점별 종합 비교 테이블 표시
4. 차트 막대 클릭 → 같은 지점 테이블 행 강조
5. 테이블 행 또는 [상세 보기] 클릭 → 선택 지점과 기간을 유지한 상태로 HQ-04 지점 성과 리포트 진입

### 분기·예외 흐름
- **지점 코드 중복**: 인라인 "이미 사용 중인 코드입니다" + 자동 생성 권장
- **운영 시작일 과거 입력**: 경고 + "오픈 예정" 상태로 자동 전환되지 않음(즉시 운영 중)
- **초기 센터장 미선택**: 저장 차단 + "초기 센터장은 필수입니다"
- **초기 센터장 다른 지점 소속**: "다른 지점 소속 직원입니다, 이동하시겠습니까?" 확인 모달
- **폐점 처리 시 활성 회원 존재**: "활성 회원 {활성회원수}명에 대한 환불·이관이 필요합니다" + [환불 처리] / [이관 처리]
- **임시휴업 처리 시 진행 예약**: 예약 자동 취소 또는 유지 정책 선택
- **본사 정책 세트 미설정**: 신규 지점 등록 시 "본사 표준 정책이 없습니다" + 정책 라이브러리(HQ-09) 진입
- **owner가 운영 상태 변경 시도**: 버튼 hidden 또는 "권한이 부족합니다" 안내
- **폐점된 지점 회원 등록 시도**: 차단 + "폐점된 지점입니다"
- **아카이브 복원**: 별도 슈퍼 승인 워크플로우 + 감사 로그

## 비즈니스 규칙

1. **지점 코드 고유성**: 시스템 내 unique. 자동 생성(예: BR0001) 또는 수동 입력. 중복 시 차단.
2. **운영 상태 4종**: `운영 중` / `오픈 예정`(운영 시작일 이전) / `임시휴업` / `폐점`. 기본은 `운영 중`.
3. **임시휴업 정책**: 진행 중 회원·이용권은 유지되며 신규 가입·결제·예약만 차단. 회원 이용권 자동 홀딩 토글 가능.
4. **폐점 처리**: 데이터는 {개수}개월(기본 6개월) 보관 후 아카이브. 활성 회원 존재 시 환불·이관(MBR-ADV-02) 강제.
5. **초기 센터장 매핑**: 직원관리(STF)에서 등록된 직원만 가능. 다른 지점 소속이면 이동 확인 모달.
6. **정책 세트 자동 적용**: 본사 표준(HQ-09 기본 정책)이 기본. 신규 등록 시 자동 적용. 지점별 커스터마이징은 SCR-080A에서 수행.
7. **운영 시작일**: 캘린더 입력. 미래일 = `오픈 예정`, 도래 시 자동 `운영 중` 전환(배치).
8. **owner 수정 권한 제한**: owner는 연락처·주소·운영 시간 등 일부 항목만 수정 가능. 운영 상태·코드·센터장 매핑 등은 슈퍼만.
9. **감사 로그 필수**: 지점 등록·수정·비활성화·폐점·복원·센터장 변경 모두 SCR-097에 기록(actor·branch_id·전·후 값).
10. **매니저 이하 접근 차단**: 지점 관리 화면 진입 자체를 차단(권한 매트릭스).
11. **비교 탭 데이터 격리**: owner는 소속 지점만, 슈퍼는 전 지점. RLS 우회는 슈퍼만.
12. **지점 코드 변경 금지**: 등록 후 코드 변경 불가(데이터 무결성). 변경 필요 시 신규 등록 + 이관.
13. **연락처 정책**: 010-XXXX-XXXX 자동 포맷. 02-XXXX-XXXX 등 일반 전화 허용.
14. **주소 검색**: 다음 우편번호 또는 카카오 주소 API 사용. 위경도 자동 저장(매장 지도용).
15. **운영 시간**: 지점별 영업 시간 등록(요일별). 회원 출입·예약 가능 시간 기준.
16. **휴무일**: 정기 휴무 + 특별 휴무(설/추석 등). 자동 차단 처리.
17. **폐점 데이터 복원**: 아카이브 데이터를 슈퍼관리자 승인 워크플로우로 복원 가능. 감사 로그 필수.
18. **신규 지점 등록 직후 자동 트리거**: 정책 세트 자동 적용 + 본사 표준 알림 템플릿 활성 + 기본 KPI 목표(0) 설정.
19. **지점 수 한도**: 본사 라이선스 정책에 따라 최대 등록 가능 지점 수 제한. 초과 시 등록 차단.
20. **폐점 시 직원 처리**: 직원은 다른 지점 이동 또는 비활성화 선택. 자동 비활성화는 안 함(수동 의사결정).

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `CTR-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-092`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-092-001 신규지점등록, DLG-092-002 비활성화확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
