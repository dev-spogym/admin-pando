## 기능 목적

센터 운영 데이터의 백업 주기를 설정하고, 수동 백업을 실행하며, 이전 백업 시점으로 복원하는 화면이다. 데이터 손실 사고에 대비한 안전망으로 운영되며, 복원 이력을 통해 과거 복원 내역을 추적할 수 있다.

운영 맥락:
- **시스템 마이그레이션 전 수동 백업**: 서버 이전·대규모 업데이트 전 즉시 수동 백업 실행 → 이상 발생 시 즉시 복원 대비
- **자동 백업 스케줄 설정**: 매일 새벽 3시 자동 백업 + 90일 보관 → 평상시 운영 데이터 안전망 확보
- **사고 후 시점 복원**: 잘못된 대량 삭제·데이터 오염 발생 시 가장 가까운 정상 백업 시점으로 복원
- **백업 파일 외부 보관**: 백업 파일 다운로드 → 외부 스토리지(NAS, 클라우드)에 추가 보관
- **보관 기간 정책 변경**: 법적 요건 또는 비용 절감 목적으로 보관 기간 변경 → 기존 백업 파일 소급 삭제 여부 확인
- **복원 권한 관리**: 복원은 슈퍼관리자 전용 또는 센터장이 슈퍼관리자 승인 요청 후 실행 → 오작동 방지
- **트랜잭션 점검 모드**: 복원 실행 전 진행 중인 결제·예약 트랜잭션 종료 여부 확인 → 데이터 정합성 보장

## 주요 구성요소

### 자동 백업 설정

| 항목 | 옵션 |
|------|------|
| 자동 백업 활성 | 토글 |
| 백업 주기 | 매일 / 매주 / 매월 |
| 백업 실행 시각 | HH:mm |
| 보관 기간 | 30일 / 90일 / 180일 / 무제한 |
| 액션 | [백업 설정] → DLG-089-002 |

브랜드 3사 운영 기준에서 자동 백업이 필수 기능으로 확정되지 않은 경우 v1은 수동 백업·복원 이력 조회를 우선 구현한다. 자동 백업 스케줄 설정은 후순위 옵션으로 둔다.

### 수동 백업

| 항목 | 동작 |
|------|------|
| 지금 백업 실행 | 즉시 백업 |
| 마지막 백업 일시 | YYYY-MM-DD HH:mm |
| 최신 백업 다운로드 | 파일 |

백업 파일 다운로드는 슈퍼관리자 전용이며 파일 암호화, 서명 URL 만료, 감사 로그 기록 정책이 확정된 뒤 활성화한다.

### 백업 이력

| 컬럼 | 설명 |
|------|------|
| 백업 일시 | YYYY-MM-DD HH:mm |
| 데이터 크기 | MB/GB |
| 백업 방식 | 자동 / 수동 |
| 상태 | 성공 / 실패 / 진행 중 |
| 암호화 여부 | 암호화 / 미암호화 배지 |
| 액션 | [복원] / [다운로드] |

기간 필터: 오늘 / 이번 주 / 이번 달 / 사용자 지정.

### 복원 이력

| 컬럼 | 설명 |
|------|------|
| 복원 일시 | YYYY-MM-DD HH:mm |
| 복원 백업 시점 | YYYY-MM-DD |
| 실행자 | 직원명 |
| 복원 사유 | 텍스트 |
| 복원 결과 | 성공 / 실패 |

기간 필터: 동일 4종.

### 데이터 복원 확인 (DLG-089-001)

복원 최종 확인 + 영향 안내 + 진행 중 트랜잭션 경고 + 사유 입력.

### 백업 설정 (DLG-089-002)

자동 백업 상세 설정 (주기·시각·보관 기간·암호화 옵션).

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin | 전체 설정·이력 | 백업·복원·다운로드·설정 변경 |
| owner (센터장) | 소속 지점 백업 이력 | 수동 백업·다운로드 (복원은 슈퍼관리자 승인 필요) |

| readonly | 없음 | 없음 |

## 주요 UX 흐름

**자동 백업 설정**
1. 사이드바 → "설정 > 데이터 백업·복원" 진입
2. [백업 설정] → DLG-089-002
3. 주기·시각·보관 기간·암호화 입력
4. 저장 → 자동 실행 시작

**수동 백업**
1. [지금 백업 실행]
2. 진행 표시 → 완료 → 이력 추가

**시점 복원**
1. 이력 행 [복원] → DLG-089-001
2. 영향 안내 + 진행 중 트랜잭션 경고 + 사유 입력 확인
3. 복원 시작 → 시스템 재시작 → 선택 시점 데이터로 전환

**다운로드**
1. 행 [다운로드] → 권한 검증
2. 백업 파일 다운로드 (링크 유효 1시간)

### 분기·예외 흐름

- **복원 시 진행 중 트랜잭션 존재**: DLG-089-001에서 "현재 N건의 결제·예약이 진행 중입니다. 복원 시 이 트랜잭션은 취소됩니다" 경고 + 강제 진행 or 취소 선택
- **보관 기간 단축 시 기존 백업 소급 삭제**: "{보관일수}일 초과 백업 {대상건수}건이 즉시 삭제됩니다" 확인 모달, 취소 가능
- **자동 백업 OFF 시 경고**: "자동 백업을 끄면 데이터 손실 위험이 높아집니다. 계속하시겠습니까?" 확인 모달
- **수동 백업 중 자동 백업 동시 실행**: 수동 백업 완료 후 자동 백업 대기, 동시 실행 방지 (락 메커니즘)
- **복원 실패 (디스크 오류·파일 손상)**: "복원에 실패했습니다. 파일 상태를 확인하거나 다른 백업 시점을 선택해주세요" 모달, 시스템 재시작 없이 이전 상태 유지
- **다운로드 링크 만료 (1시간 초과)**: "다운로드 링크가 만료되었습니다. 다시 요청해주세요" 안내 + 재요청 버튼
- **센터장의 복원 시도**: "복원은 슈퍼관리자 권한이 필요합니다. 승인을 요청하시겠습니까?" 안내 → 승인 요청 워크플로
- **백업 파일 손상 감지**: 무결성 체크(checksum) 실패 시 이력에 "손상" 배지 + [복원] 버튼 disabled + "다른 백업 시점 사용 권장" 안내
- **복원 후 시스템 재시작 소요 시간 안내**: DLG-089-001에서 "복원 완료까지 약 N분이 소요됩니다. 이 시간 동안 서비스가 중단됩니다" 안내
- **무제한 보관 설정 시 스토리지 경고**: 백업 파일 누적 크기가 일정 임계값(예: 100GB) 초과 시 "스토리지 용량 경고" 배너 노출
- **복원 사유 미입력**: DLG-089-001에서 사유 필드 미입력 시 "복원 사유를 입력해주세요" 인라인 에러, 복원 차단

## 화면 상태

| 상태 | 설명 |
|---|---|
| 기본 | 자동 설정 + 이력 |
| 백업 진행 중 | 진행 표시 + 버튼 비활성 |
| 백업 완료 | 메시지 + 이력 갱신 |
| 복원 진행 중 | 화면 전체 처리 중 + 서비스 중단 안내 |
| 이력 없음 | 안내 |
| 백업 파일 손상 | 손상 배지 + 복원 비활성 |
| 스토리지 경고 | 용량 초과 배너 |

## 비즈니스 규칙

1. 자동 백업은 후순위 옵션이다. 활성화된 경우 설정된 주기·시각에 자동 실행되며 보관 기간 경과 시 자동 삭제된다.
2. 수동 백업은 즉시 실행되며 자동 백업과 별도 보관된다.
3. 복원은 슈퍼관리자 권한 또는 센터장의 슈퍼관리자 승인 후 실행 가능하다 (오작동 방지).
4. 복원 시 시스템이 재시작되며 진행 중인 작업이 중단될 수 있다.
5. 백업 파일은 암호화되어 저장되며 다운로드 시에도 권한 검증이 필요하다.
6. 모든 백업·복원 이력은 감사 로그에 기록된다.
7. **암호화**: 백업 파일은 AES-256 암호화 적용. 다운로드 파일도 동일 암호화 유지.
8. **무결성 검증**: 백업 완료 후 checksum(SHA-256) 생성·저장. 복원 전 checksum 재검증, 불일치 시 손상 처리.
9. **다운로드 링크 유효 기간**: 다운로드 요청 후 서명된 URL 생성, 유효 시간 1시간. 만료 후 재요청 필요.
10. **복원 사유 필수 입력**: DLG-089-001에서 복원 사유 텍스트 필수 입력. 감사 로그에 사유 포함.
11. **트랜잭션 점검**: 복원 전 진행 중 결제·예약 트랜잭션 카운트 표시, 복원 시 해당 트랜잭션 취소 안내.
12. **보관 기간 단축 소급 삭제**: 보관 기간을 짧게 변경 시 기존 초과 파일 즉시 삭제. 변경 전 확인 모달 필수.
13. **자동 백업과 수동 백업 동시 실행 방지**: 백업 진행 중 다른 백업 요청 시 큐에 대기, 완료 후 순차 실행.
14. **복원 후 복원 시점 이후 데이터 손실**: 복원 시점 이후 생성·수정된 데이터는 복원 완료 후 모두 손실됨을 DLG-089-001에서 명시.
15. **센터장 복원 승인 워크플로**: 센터장이 복원 요청 시 슈퍼관리자에게 승인 요청 알림 발송, 슈퍼관리자 승인 후 자동 복원 실행.
16. **자동 백업 실패 재시도**: 자동 백업 실패 시 30분 후 1회 재시도. 재시도도 실패 시 운영자에게 알림.
17. **스토리지 용량 임계 경고**: 누적 백업 크기 100GB 초과 시 경고 배너. 무제한 보관 정책 재검토 유도.
18. **백업 이력 영구 보관**: 백업 파일 자체는 보관 기간 후 삭제되나 이력 메타데이터(일시·크기·방식·상태)는 영구 보관.
19. **복원 이력 영구 보관**: 복원 실행 이력(일시·시점·실행자·사유·결과)은 영구 삭제 불가, 감사 목적.
20. **자동 백업 OFF 강제 경고**: 자동 백업 기능을 사용하는 지점에서 비활성화 시 데이터 손실 위험 경고 모달 필수 표시, 확인 후에만 OFF 전환.
21. **슈퍼관리자 전용 복원 접근**: 복원 버튼은 슈퍼관리자에게만 활성. 센터장은 회색 처리 + "승인 요청" 버튼 표시.
22. **백업 실행 시각 서버 기준**: 백업 실행 시각은 서버 UTC 기준으로 저장, UI에서는 설정 타임존(SET-05)으로 변환 표시.

## 자동화 / 배치 / 이벤트 연계

| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| 자동 백업 배치 | 설정된 주기·실행 시각 | 전체 DB 스냅샷 생성 → S3/Object Storage 암호화 저장 → 이력 INSERT |
| 자동 백업 실패 재시도 | 자동 백업 실패 이벤트 | 30분 후 1회 재시도. 재실패 시 운영자 알림 발송 |
| 백업 파일 만료 삭제 배치 | 매일 04:00 | 보관 기간 초과 파일 삭제, 이력 메타데이터는 유지 |
| 무결성 검증 배치 | 백업 완료 이벤트 | checksum 계산 → 저장 → 이력 레코드에 checksum 업데이트 |
| 자동 백업 실패 알림 | 자동 백업 2회 연속 실패 | 슈퍼관리자에게 이메일·앱 알림 |
| 스토리지 용량 모니터링 배치 | 매일 06:00 | 누적 백업 크기 집계, 100GB 초과 시 경고 배너 활성 |
| 센터장 복원 승인 요청 이벤트 | 센터장 [승인 요청] 클릭 | 슈퍼관리자에게 승인 요청 알림, 승인 시 복원 자동 실행 |
| SCR-097 감사 로그 | 백업 실행·복원 실행·설정 변경 이벤트 | actor·type·backup_id·timestamp·사유 INSERT |
| 다운로드 URL 생성 이벤트 | [다운로드] 클릭 | 서명된 임시 URL 생성 (유효 1시간), 다운로드 요청 로그 INSERT |
| 복원 완료 후 시스템 재시작 이벤트 | 복원 DB 교체 완료 | 애플리케이션 서버 재시작 → 사용자 세션 초기화 → 로그인 화면 리디렉션 |
| 타임존 기반 실행 시각 표시 (SET-05) | 백업 이력 조회 | 저장된 UTC 시각을 설정 타임존으로 변환 표시 |

- **API 기준**: `GET /api/backup/settings` / `PUT /api/backup/settings` / `POST /api/backup/run` / `GET /api/backup/history` / `POST /api/backup/:id/restore` / `GET /api/backup/:id/download` / `GET /api/backup/restore-history` / `POST /api/backup/restore-approval-request`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SET-EXT-03`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-089`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-089-001 데이터복원확인, DLG-089-002 백업설정`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
