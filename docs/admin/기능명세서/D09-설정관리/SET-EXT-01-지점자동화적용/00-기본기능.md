## 기능 목적

지점이 본사에서 등록한 정책 세트를 적용받고 지점별 활성 상태를 관리하는 화면이다. 만료 정책은 회원 이용권 만료, 결제기한 만료, 락커 만료로 분리해 보여준다. 지점은 새 본사 정책 세트를 만들지 않고 본사 표준 정책을 따르며, 본사 step의 D-30/D-14/D-7 같은 날짜 기준·스텝 순서·트리거 조건은 수정하지 않는다. 각 지점의 센터장(owner)만 정책 또는 스텝의 ON/OFF를 변경할 수 있고, 회원 이용권 만료와 락커 만료 정책에 한해 해당 지점 전용 추가 step을 생성·수정·삭제할 수 있다. 결제기한 만료 정책은 지점 추가 step을 허용하지 않는다. manager 이하는 현재 적용 상태와 상세 설정을 확인하되 사용 여부 토글과 지점 추가 step은 변경할 수 없다. 단순 토글 목록이 아니라 현재 적용 중인 정책 요약을 먼저 보여주어 운영자가 즉시 상황을 파악할 수 있도록 한다.

운영 맥락:
- **신규 지점 오픈 온보딩**: 본사 표준 정책 세트 자동 적용 → 센터장(owner)이 필요 없는 스텝만 OFF → 회원 이용권 만료·락커 만료는 필요한 지점 추가 step 등록 → 테스트 발송 후 운영 시작
- **프랜차이즈 전국 통일 정책 배포**: superAdmin이 모든 지점에 동일 정책 세트 배포 → 각 지점장은 지점별 ON/OFF만 조정
- **계절별 정책 전환**: 성수기·비수기마다 본사 정책 세트 전환 → 지점은 본사 날짜 기준을 수정하지 않고 사용 여부만 조정. 회원 이용권 만료·락커 만료의 지점 추가 step은 유지 여부를 owner가 확인
- **권한 충돌 차단**: manager 이하가 정책/스텝 ON/OFF를 시도하면 변경을 차단하고 센터장 권한 필요 안내 표시
- **시뮬레이션으로 사전 검증**: 지점 ON/OFF 저장 전 "시뮬레이션" 모드로 발송 대상 회원 수·발송 예상 시각·플랫폼 예상 비용 미리 확인
- **ON/OFF 변경 후 롤백**: 잘못된 지점 ON/OFF 저장 시 이전 ON/OFF 상태로 즉시 롤백 (24시간 이내)
- **감사 목적 정책 이력 조회**: 본사 배포 이력과 지점 ON/OFF 변경 이력(언제·누가·어느 step을 변경)을 감사 로그에서 추적

## 메시지 플랫폼 연동 원칙

- 시뮬레이션과 테스트 발송은 내부 계산값이 아니라 메시지 플랫폼 API에서 조회한 예상 비용·발신 프로필·승인 템플릿 상태를 사용한다.
- 지점은 본사 정책 적용 상태 화면에서 SMS/알림톡 단가를 수정하지 않으며, 비용 정보는 참고용 조회값으로만 노출한다.

## 주요 구성요소

### 정책 요약 카드 (PolicySummaryCards)

현재 적용 중인 정책 세트를 정책 유형별로 요약 표시. 회원 이용권 만료, 결제기한 만료, 락커 만료가 별도 카드로 보여야 한다.

### 정책 유형 탭 (PolicyTypeTabs)

회원 이용권 만료 / 결제기한 만료 / 락커 만료로 분리한다. 결제링크 만료 알림은 PAY-06 고정 정책이므로 이 탭에 포함하지 않는다.

### 적용 정책 표시 (AppliedPolicySummary)

본사에서 배포한 정책 세트를 읽기 전용으로 표시한다. 지점에서는 정책 세트를 직접 교체하지 않으며, 변경 필요 시 본사에 요청한다.

### 스텝 테이블 (StepTable)

정책 유형 × 스텝 × 채널 3단 구조. 본사 step과 지점 추가 step은 배지로 구분한다.

| 컬럼 | 설명 |
|------|------|
| 스텝 | 본사 HQ-09 정책값 또는 지점 추가 step (예: D-30 / D-14 / D-7 / D-Day / D+1) |
| 소유 구분 | 본사 step / 지점 추가 step |
| 채널 | 회원앱 Push 기본 / KakaoTalk fallback 선택 |
| 활성 | 토글 (센터장(owner)만 변경 가능, manager 이하는 disabled) |
| 발송 시각 | 본사 기본값 또는 지점 상세 설정값 |
| 메시지 미리보기 | 본사 템플릿 |
| 테스트 발송 | [발송] |

### 지점 추가 step 관리

| 정책 유형 | 지점 추가 step | 권한 |
|---|---|---|
| 회원 이용권 만료 | 가능 | 센터장(owner)만 생성·수정·삭제 |
| 결제기한 만료 | 불가 | 본사 step ON/OFF만 가능 |
| 락커 만료 | 가능 | 센터장(owner)만 생성·수정·삭제 |

### 시뮬레이션 패널

지점 ON/OFF 저장 전 발송 대상 회원 수·발송 예상 시각·플랫폼 예상 비용 미리보기.

### ON/OFF 변경 롤백 버튼

마지막 지점 ON/OFF 변경 후 24시간 이내 이전 ON/OFF 상태로 즉시 복구.

### 액션 푸터 (ActionFooter)

[시뮬레이션] / [ON/OFF 저장] / [취소] 버튼.

### ON/OFF 변경 확인 (DLG-080A-001)

저장 시 영향 범위(대상 회원 수·스텝 수·채널) 확인.

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin | 전체 + 본사 정책 | 정책 세트 등록·지점 적용·강제 배포 |
| owner (센터장) | 본사 정책 + 지점 적용 | 정책/스텝 ON/OFF, 회원 이용권 만료·락커 만료 지점 추가 step 관리, 테스트, 시뮬레이션, 저장 |
| manager | 본사 정책 + 지점 적용 | 조회, 테스트, 시뮬레이션. 정책/스텝 ON/OFF, 지점 추가 step 관리 및 저장 불가 |
| fc / 트레이너 / 스태프 | 접근 불가 | 없음 |
| readonly | 없음 | 없음 |

## 주요 UX 흐름

1. 사이드바 → "설정 > 지점 자동화 적용" 진입
2. 정책 요약 카드로 현재 적용 정책 즉시 파악
3. 정책 유형 탭 선택 → 회원 이용권 만료, 결제기한 만료, 락커 만료별 본사 배포 정책 세트 확인
4. 센터장(owner)은 스텝 테이블에서 정책/스텝 ON/OFF를 조정하고, 회원 이용권 만료·락커 만료는 지점 추가 step을 관리
5. [테스트 발송]으로 메시지 미리보기
6. [시뮬레이션]으로 발송 대상 사전 확인
7. [ON/OFF 저장] → DLG-080A-001 → 지점 ON/OFF 상태 즉시 반영

### 분기·예외 흐름

- **센터장 외 스텝 OFF 시도**: 해당 토글 disabled + 자물쇠 아이콘 표시, 호버 시 "센터장만 자동 알림 사용 여부를 변경할 수 있습니다" 툴팁
- **정책 세트 0개 (본사 미등록)**: 정책 표시 영역 비활성 + "본사에서 등록된 정책 세트가 없습니다. 본사 관리자에게 문의해주세요" 안내
- **본사 기준일 편집 시도**: 기준일·트리거 조건 입력은 읽기 전용으로 유지하고 "본사 정책값은 지점에서 수정할 수 없습니다" 안내
- **결제기한 만료 지점 step 추가 시도**: [지점 step 추가] 버튼 미노출. URL 직접 접근 등 방어 케이스에서는 "결제기한 만료는 본사 정책 step만 사용할 수 있습니다" 안내 후 차단
- **지점 추가 step 기준일 중복**: 같은 지점·같은 정책 내 본사 step 또는 기존 지점 추가 step과 동일 기준일이면 저장 차단
- **테스트 발송 실패 (채널 오류)**: "테스트 발송에 실패했습니다. 채널 설정을 확인해주세요" 토스트 + 플랫폼 연동 상태 링크
- **시뮬레이션 결과 0명**: "발송 대상 회원이 없습니다. 정책 조건을 확인해주세요" 안내
- **ON/OFF 저장 중 네트워크 오류**: "저장에 실패했습니다. 재시도해주세요" 토스트, 저장 전 상태 유지
- **롤백 24시간 초과**: 롤백 버튼 비활성 + "롤백 가능 시간(24시간)이 초과되었습니다" 툴팁
- **superAdmin 전체 지점 강제 배포 후 개별 지점 조정**: 강제 배포 후 허용된 스텝 범위 내에서 개별 지점 재조정 가능. 강제 배포로 초기화된 항목은 배포 기록에 표시
- **동시 설정 변경 충돌 (두 관리자 동시 접근)**: 최종 저장자 우선 반영, 이전 사용자에게 "설정이 변경되었습니다. 새로고침 후 재시도" 알림
- **정책 세트 본사 업데이트 시 지점 적용 정책과 불일치**: "적용 중인 정책 세트가 업데이트되었습니다. 재검토 후 다시 적용해주세요" 배너 노출

| 저장 중 | 버튼 비활성 |
| 저장 완료 | 즉시 반영 + 롤백 버튼 활성 (24시간) |
| 권한 잠금 | owner가 아닌 계정은 정책/스텝 ON/OFF disabled |
| 본사 정책 세트 없음 | 적용 정책 표시 영역 비활성 + 안내 |

## 비즈니스 규칙

1. 지점은 새 본사 정책 세트를 만들거나 정책 세트를 직접 교체하지 않으며, 본사에서 배포한 세트를 적용받는다.
2. 지점은 본사 HQ-09에서 배포한 정책/스텝을 적용받으며, 본사 기준일·스텝 순서·트리거 조건을 수정할 수 없다.
2-1. 만료 정책은 회원 이용권 만료, 결제기한 만료, 락커 만료로 분리한다.
2-2. 회원 이용권 만료와 락커 만료 정책은 센터장(owner)이 지점 추가 step을 생성·수정·삭제할 수 있다. 지점 추가 step은 해당 지점에만 적용된다.
2-3. 결제기한 만료 정책은 지점 추가 step을 만들 수 없고 본사 step ON/OFF만 가능하다.
2-4. PAY-06 결제링크 만료 알림은 D-3/D-1 고정으로 별도 관리되며 결제기한 만료 정책에 포함하지 않는다.
3. 정책/스텝 ON/OFF와 지점 추가 step 변경은 각 지점의 센터장(owner)만 변경할 수 있다. manager/fc/trainer/staff/readonly는 토글 변경 불가.
4. 지점은 정책 템플릿 기본값을 수정하지 않으며, 허용된 경우 채널·발송 시각·지점 메시지만 조정 가능하다.
5. 정책 요약은 토글 목록보다 먼저 표시되어 운영자가 현재 상태를 즉시 파악할 수 있어야 한다.
6. 정책 유형·스텝·채널·발송 시각의 구조가 명확히 읽혀야 한다.
7. 지점 ON/OFF 저장은 즉시 반영되며 자동 알림(MKT-02)에 반영된다.
8. 변경 이력은 감사 로그에 기록된다.
9. **권한 잠금**: owner가 아닌 계정의 정책/스텝 ON/OFF는 토글 disabled + 자물쇠 아이콘으로 표시한다.
10. **시뮬레이션 모드**: 적용 전 발송 대상 회원 수·채널별 발송 건수·예상 발송 시각·플랫폼 예상 비용 미리보기. 실제 발송 없음.
11. **테스트 발송**: 운영자 본인 계정(등록 전화번호·카톡·이메일)으로만 발송. 실제 회원 발송 아님.
12. **롤백 정책**: 지점 ON/OFF 저장 후 24시간 이내에만 이전 ON/OFF 상태로 즉시 롤백 가능. 24시간 초과 시 신규 변경으로 다시 저장해야 함.
13. **superAdmin 강제 배포**: superAdmin은 모든 지점에 동일 정책 세트 강제 배포 가능. 배포 후 지점별 ON/OFF 상태는 본사 기본 활성값으로 초기화될 수 있으며, 각 지점 센터장(owner)이 다시 ON/OFF 조정 가능.
14. **정책 세트 본사 업데이트**: 본사가 적용 중인 정책 세트 내용 업데이트 시 지점 화면에 "정책 세트 업데이트됨" 배너 노출, 재확인 및 재적용 유도.
15. **발송 채널 비용**: SMS·카톡 채널은 발송 건당 비용이 발생한다. 시뮬레이션 화면에는 플랫폼 API 기준 예상 발송 건수·비용을 표시한다.
16. **저장 즉시 반영 범위**: 지점 ON/OFF 저장 즉시 이후 발생하는 만료·결제 이벤트부터 적용. 이미 큐에 들어간 발송 건은 저장 전 상태 유지.
17. **감사 로그 기록 항목**: 지점 ID, 변경 전 정책 세트 ID, 변경 후 정책 세트 ID, 스텝 ON/OFF 변경 내역, actor, timestamp.
18. **정책 세트 없음 처리**: 본사 등록 정책 세트가 0개일 때 지점은 적용 정책 없음 상태로 표시한다. 자동화 알림 미발송 상태 유지.
19. **동시 접근 제어**: 동일 지점 설정을 두 관리자가 동시 수정 시 최종 저장자 우선, 선행 편집자에게 경고.
20. **채널 발송 실패 재시도**: 발송 실패 시 30분 간격 최대 3회 재시도. 3회 모두 실패 시 운영자에게 발송 실패 알림.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SET-EXT-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-080A`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-080A-001 정책적용확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
