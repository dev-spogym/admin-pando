## 기능 목적

기본 제공 8종 역할(superAdmin/primary/owner/manager/fc/trainer/staff/readonly) 외에 센터 운영 특성에 맞는 맞춤형 역할을 생성·관리하는 화면(SCR-087)이다. 역할 이름·설명을 정의하고 SCR-081과 동일한 9개 메뉴 그룹 × 5종 권한 매트릭스로 권한 조합을 직접 구성한다. 기본 역할로 표현하기 어려운 운영 시나리오(보조 매니저, 시간제 강사, 야간 매니저, 신입 인턴, 프로젝트 PM 등)를 반영한다. 역할 삭제 시 배정 직원이 있으면 DLG-087-001로 재배정을 강제해 권한 공백을 방지한다.

운영 맥락:
- **보조 매니저 신규 도입**: manager 권한 복사 후 환불·급여 권한 회수 → "보조 매니저" 생성
- **시간제 강사 역할**: trainer 복사 후 수업·출석만 활성 → 재무 정보 차단
- **야간 매니저 (제한 권한)**: owner 복사 후 회원 영구 삭제·매출 수정 거부 → 야간 운영 안전망
- **신입 인턴 한정 권한**: 기본 매트릭스에서 [조회]만 활성 → 1개월 후 정식 역할로 전환
- **프로젝트 PM (한시적)**: 메시지·공지만 활성 → 프로젝트 종료 시 역할 삭제 + 직원 재배정
- **본사 정책 변경 후 일괄 권한 조정**: 커스텀 역할 권한 매트릭스 일괄 회수 → SCR-081에서 즉시 반영
- **역할 사용 종료**: 역할 삭제 → DLG-087-001 → 배정 8명 일괄 재배정 → 권한 공백 방지
- **이름 충돌 방지**: 기본 역할명 중복 차단 + 동일 지점 내 커스텀 역할명 unique

커스텀 역할은 SCR-081 권한 설정과 단일 source-of-truth로 운영되며 양 화면에서 동일하게 편집된다. 모든 변경은 SCR-097 감사 로그에 기록된다.

### 역할 배정 현황

해당 역할 배정 직원 목록 미리보기 (이름·소속 지점·직무).

### 역할 삭제 재배정 (DLG-087-001)

삭제 시 배정 직원 ≥ 1명이면 다른 역할로 일괄 재배정.

### 영향 분석 안내

SET-04-06 영향 분석은 SCR-081/DLG-081-006과 동일한 저장 전 확인 안내다. 역할 삭제 또는 권한 변경 시 배정 직원 수, 담당 회원 합계, before/after 권한 차이만 표시하며 별도 예측 리포트나 시뮬레이션 기능으로 확장하지 않는다.

## 주요 UX 흐름

### 새 역할 생성 흐름
1. 사이드바 → "설정 > 커스텀 역할 생성" 진입 → 역할 목록 표시
2. [+ 새 역할 만들기] 클릭
3. 역할 이름 (필수, 1~30자, 기본 역할명 중복 차단) + 설명 (선택)
4. 복사 베이스 선택 (선택, 선택 시 권한 매트릭스 자동 로드)
5. 매트릭스 9그룹 × 5권한 편집 → 저장
6. 목록 추가 + SCR-081 좌측 패널에 즉시 노출 + 메시지

### 역할 수정 흐름
1. 행 [수정] → 채워진 폼
2. 권한 변경 → 저장 → 배정 직원 ≥ 1명이면 영향 분석 안내
3. 즉시 반영 + 감사 로그 INSERT

### 역할 삭제 흐름
1. 행 [삭제] → DLG-087-001
2. 배정 직원 ≥ 1명이면 재배정 역할 선택 강제
3. 재배정 + 삭제 → 목록에서 제거

### 분기·예외 흐름
- **이름 중복 (기본 역할명)**: "기본 역할명과 중복됩니다" 인라인 + 저장 차단
- **이름 중복 (지점 내 커스텀 역할명)**: "이미 사용 중인 이름입니다" 인라인 + 저장 차단
- **이름 30자 초과**: "30자 이내" 인라인 + 저장 차단
- **이름 빈값**: "역할 이름은 필수입니다" + 저장 차단
- **복사 베이스 선택 후 변경 시**: 매트릭스 재로드 (현재 편집 내용 폐기 경고)
- **삭제 시 배정 직원 ≥ 1명**: DLG-087-001 재배정 역할 선택 강제, 미선택 시 [삭제] 비활성
- **삭제 시 배정 직원 0명**: 즉시 삭제 확인 후 처리
- **owner가 다른 지점 커스텀 역할 접근**: 행 hidden (RLS branchId)
- **수정 중 다른 운영자 동시 편집**: 30초 lock + 사용자명 표시
- **저장 중 페이지 이탈**: 미저장 경고 모달

## 비즈니스 규칙

1. 커스텀 역할 이름은 1~30자, 빈값 차단, 기본 7종 역할명(superAdmin/primary/owner/manager/fc/staff/readonly) 및 한글 표기와 중복 불가하다.
2. 동일 지점 내 커스텀 역할명은 unique이며 다른 지점은 허용된다.
3. 권한 복사 베이스 선택 시 선택 역할의 9그룹·5권한 매트릭스가 자동 로드된다.
4. 역할 삭제 시 배정 직원 ≥ 1명이면 DLG-087-001 재배정이 강제된다.
5. 커스텀 역할은 SCR-081 권한 설정과 단일 source-of-truth로 운영되며 양 화면에서 동일하게 편집된다.
6. 권한 변경 시 배정 직원 ≥ 1명이면 배정 직원 수·담당 회원 합계·before/after 권한 차이를 보여주는 영향 분석 안내가 표시된다.
7. 변경 이력은 SCR-097 감사 로그에 actor·역할 ID·변경 전후 스냅샷으로 INSERT 된다.
8. owner는 소속 지점 커스텀 역할만 생성·수정·삭제 가능하다 (RLS branchId).
9. **역할 설명**: 200자 이내, 선택 항목.
10. **6종 민감 기능 포함 시**: SCR-081과 동일하게 강조 표시 + 저장 시 추가 확인.
11. **권한 매트릭스 공통**: SCR-081과 동일한 9그룹(회원·수업·매출·상품·직원·급여·시설·메시지·설정) × 5권한(접근·조회·생성·수정·삭제).
12. **역할 삭제 후 직원 재배정 정책**: DLG-087-001에서 선택한 역할로 일괄 재배정, 다른 역할 선택 시 차단.
13. **재배정 후 직원 활성 세션**: 다음 페이지 로드부터 신규 역할 권한 적용 (JWT refresh).
14. **삭제 시 담당 회원 영향**: 직원 재배정 후에도 담당 회원 매핑은 유지.
15. **역할명 변경**: 기존 배정 직원 권한은 유지 (역할 ID 기준).
16. **역할 생성 후 권한 미설정 (전체 거부)**: 허용되나 배정 시 직원이 권한 없음 상태가 됨 → 경고.
17. **동시 편집 lock**: 같은 역할을 다른 운영자가 편집 중이면 30초 lock + 사용자명 표시.
18. **수정 중 페이지 이탈**: 미저장 변경 경고 모달 (저장/이탈/취소).
19. **인라인 검증**: 이름·설명 입력 시 실시간 검증 (글자 수·중복).
20. **역할 수정 시 자기 자신 영향**: 본인이 해당 역할 배정이면 권한 회수 시 본인 권한도 박탈됨 경고.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SET-04`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-087`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-087-001 역할삭제재배정`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
