## 기능 목적

회원의 출석을 인정하는 기준과 자동 처리 규칙을 설정하는 화면이다. 출석 인정 시간대, 지각 판단 기준, 자동 출석 처리 조건 등을 센터 운영 방침에 맞게 구성한다. IoT 출입 기록과 연동해 자동 출석 인정도 가능하다. QR 출석은 독립 QR 발급/검증 기능이 아니라 출석 수단 중 하나로 사용하는지와 화면에 노출할지를 설정하는 항목으로 한정한다.

운영 맥락:
- **IoT 출입 기록 기반 자동 출석**: IoT(SCR-083) 연동 완료 후 자동 출석 ON → 직원 수동 체크인 없이 출입 태그로 자동 인정
- **QR 코드 출석 센터**: IoT 미사용 센터에서 QR 출석 수단 사용 → QR 출석 사용 여부와 키오스크 QR 표시 여부를 설정하고, 출석 수단 안내 문구를 운영자에게 노출
- **지각 다발 클래스 관리**: 특정 시간대 지각자 누적 시 지각 임계 N분 조정 → 회원·관리자 동시 알림 발송
- **자유 이용 회원 출석 처리**: PT·GX 수업 외 자유 이용 회원의 입장 기록을 별도 출석으로 인정
- **OFFLINE 키오스크 동기화**: 키오스크 네트워크 단절 시 로컬 출석 기록 → 네트워크 복구 후 서버 동기화 정책 설정
- **출석 정정 권한 관리**: 정정 가능 권한을 센터장·매니저 중 어느 역할까지 허용할지 정책 설정
- **주말·공휴일 출석 정책**: 주말 운영 여부에 따라 해당일 출석 자동 처리 ON/OFF

## 주요 구성요소

### 출석 인정 시간 설정

| 항목 | 입력 |
|------|------|
| 출석 인정 시작 | 수업 시작 N분 전부터 |
| 출석 인정 마감 | 수업 시작 N분 후까지 |
| 주말/공휴일 출석 | 토글 |

### 지각 기준 설정

| 항목 | 입력 |
|------|------|
| 지각 판단 시간 | 수업 시작 후 N분 |
| 지각 누적 알림 | N회 초과 시 |
| 노쇼 판단 시간 | 출석 인정 마감 후 미입장 |

### QR 출석 설정

| 항목 | 입력 |
|------|------|
| QR 출석 사용 | 토글 |
| 키오스크 QR 표시 | 토글 |
| 출석 수단 안내 | QR / 키오스크 / IoT / 수동 출석의 사용 범위와 설정 위치 안내. QR 발급·검증 상세는 출석 처리 화면에서 다룸 |

### 자동 출석 규칙

| 항목 | 입력 |
|------|------|
| 자동 출석 처리 | 토글 (IoT 기반) |
| 자유 이용 출석 | 토글 |
| 동일 회원 중복 처리 | 첫 입장만 / 매 입장 |
| OFFLINE 키오스크 동기화 | 즉시 / 지연 허용 N분 |

### 출석 정정 권한

| 항목 | 입력 |
|------|------|
| 정정 허용 역할 | 센터장만 / 센터장+매니저 |
| 정정 가능 기간 | 출석일 기준 기본 7일 이내 |

### 출석 기록 보관

| 항목 | 입력 |
|------|------|
| 보관 기간 | 개월 단위 (법정 최소 12개월) |

## 주요 UX 흐름

1. 사이드바 → "설정 > 출석 관리 설정" 진입
2. 저장된 설정값 표시
3. 항목 변경 → 저장 활성
4. 자동 출석 활성 시 IoT 연동 안내
5. [저장] → 즉시 반영
6. 미저장 + 이탈 → DLG-080-001

### 분기·예외 흐름

- **IoT 미연결 상태에서 자동 출석 활성 시도**: "IoT 장치가 연결되어 있지 않습니다. SCR-083에서 장치를 연결해주세요" 인라인 경고, 토글은 ON 허용하되 실제 자동 처리는 IoT 연결 후 동작
- **출석 인정 시작 시간이 마감 시간보다 늦은 경우**: "인정 마감 시간은 인정 시작 시간보다 커야 합니다" 인라인 에러, 저장 차단
- **지각 판단 시간이 출석 인정 마감보다 긴 경우**: "지각 판단 시간은 출석 인정 마감 시간 이내여야 합니다" 경고 (논리 오류 방지)
- **출석 정정 기간 초과 후 정정 시도**: "정정 가능 기간(기본 7일)이 초과되었습니다. 센터장 승인이 필요합니다" 안내
- **OFFLINE 키오스크 동기화 충돌**: 서버 기록과 OFFLINE 기록 시각 중복 시 서버 기록 우선, OFFLINE 기록은 "중복 의심" 표시 후 관리자 확인
- **보관 기간 법정 최소(12개월) 미만 설정 시도**: "출석 기록 보관 기간은 최소 12개월이어야 합니다" 인라인 에러, 저장 차단
- **QR 출석 OFF 상태에서 키오스크 QR 표시 ON 시도**: "QR 출석 사용을 먼저 켜주세요" 인라인 안내, 키오스크 QR 표시 토글 비활성
- **동일 회원 당일 중복 입장 (매 입장 모드)**: 중복 입장 기록 모두 저장, 출석 횟수는 1회로 집계 (입장 이력은 별도 유지)
- **노쇼 자동 처리 후 회원이 출석 이의 제기**: 관리자 정정 권한 내에서 수동 정정 처리, 정정 이력 감사 로그 기록
- **예외 출석 (외부 행사 참석 인정)**: 운영자가 수동으로 출석 처리 시 "예외 출석" 사유 입력 필수
- **설정 변경 즉시 소급 적용 여부**: 설정 저장 시 "오늘부터 적용" 또는 "다음 영업일부터 적용" 선택 제공 (소급 불가 안내)

## 비즈니스 규칙

1. 출석 인정 시작은 수업 시작 N분 전부터 적용된다 (운영 정책).
2. 자동 출석은 IoT 출입 기록 기반이며 IoT(SCR-083) 미연결 시 경고 배너 표시, 자동 처리는 미동작.
3. 동일 회원 중복 처리 방식은 "첫 입장만" 또는 "매 입장마다" 선택 가능하다.
4. 출석 이력 보관 기간은 법정 최소 12개월 이상이어야 한다. 미만 설정 차단.
5. 지각 누적 알림은 회원·관리자 양측에 발송된다.
6. 변경 이력은 감사 로그에 기록된다.
7. **QR 출석**: 본 설정에서는 QR을 출석 수단으로 사용할지와 키오스크에 노출할지만 관리한다. QR 출석 사용이 ON일 때만 키오스크 QR 표시를 켤 수 있으며, QR 생성·토큰 만료·서버 검증·스캔 처리 로직은 출석 처리 화면/구현 영역에서 다룬다.
8. **노쇼 판단**: 출석 인정 마감 시간까지 미입장 시 "노쇼"로 자동 기록. 노쇼 횟수 N회 초과 시 회원에게 알림.
9. **출석 정정 권한**: 정정 허용 역할(센터장만 or 센터장+매니저)과 정정 가능 기간(출석일 기준 기본 7일)을 설정으로 관리. 기간 초과 정정은 슈퍼관리자 승인 필요.
10. **OFFLINE 키오스크 동기화**: 네트워크 단절 시 키오스크 로컬 DB에 출석 기록 임시 저장. 복구 후 정책 시간(즉시 또는 지연 허용 N분) 내 동기화. 중복 충돌 시 서버 우선.
11. **예외 출석**: 운영자가 수동으로 입력하는 예외 출석은 사유 필수 입력, "예외" 태그 부착, 감사 로그 필수.
12. **주말·공휴일 출석**: 토글 OFF 시 해당일 자동 출석 처리 미동작. 수동 정정은 권한 내에서 가능.
13. **설정 변경 적용 시점**: 저장 즉시 이후 수업부터 적용. 과거 출석 데이터 소급 변경 불가.
14. **자유 이용 출석**: 이용권 타입이 "자유 이용"인 회원의 입장 기록을 출석으로 인정. 수업 연동 없이 단독 출석 이력 생성.
15. **지각 임계 시간**: 지각 판단 시간은 출석 인정 마감 시간 이내로 제한 (논리 오류 방지).
16. **보관 기간 초과 데이터 자동 삭제**: 보관 기간 경과 출석 기록은 매월 1일 배치로 자동 삭제. 삭제 7일 전 운영자 알림.
17. **감사 로그**: 설정 변경 시 변경 전·후 값, actor, timestamp 기록. 출석 정정 시 정정자·정정 사유·원본값 별도 기록.

## 예외 / 에러 처리

| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| IoT 미연결 + 자동 출석 활성 | 경고 배너 "IoT 미연결" + SCR-083 링크 | 토글 ON 허용, 실제 동작은 IoT 연결 후 |
| 인정 시간 역순 (마감 < 시작) | "인정 마감 > 시작 이어야 합니다" 인라인 에러 | 저장 차단 |

| 보관 기간 12개월 미만 | "법정 최소 12개월" 인라인 에러 | 저장 차단 |
| QR 출석 OFF + 키오스크 QR 표시 ON | "QR 출석 사용을 먼저 켜주세요" 인라인 안내 | 키오스크 QR 표시 토글 비활성 |
| 정정 기간 초과 후 정정 시도 | "정정 기간 초과 — 슈퍼관리자 승인 필요" | 승인 요청 워크플로 안내 |
| OFFLINE 동기화 충돌 | 중복 의심 건에 "중복 의심" 태그 + 관리자 확인 요청 | 관리자 수동 확인 |
| 예외 출석 사유 미입력 | "사유를 입력해주세요" 인라인 에러 | 저장 차단 |
| 설정 저장 중 네트워크 오류 | "저장에 실패했습니다. 다시 시도해주세요" 토스트 | 재시도 |
| 미저장 상태 이탈 | DLG-080-001 미저장 경고 | 저장 or 취소 선택 |

## 관련 화면 / 다이얼로그 / API

- **연계 화면**: SCR-086 / SCR-083 IoT / SCR-C014 출석 QR / SCR-C011 유효 수업
- **연계 다이얼로그**: DLG-080-001 미저장경고
- **API 기준**: `GET /api/settings/attendance` / `PUT /api/settings/attendance` / `POST /api/attendance/manual` / `PATCH /api/attendance/:id/correct` / `POST /api/attendance/offline-sync`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SET-EXT-05`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-086`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-080-001 미저장경고`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
