## 기능 목적

센터에 설치된 IoT 출입 장치(스마트 밴드 RFID·QR 스캐너·얼굴 인식 카메라·핀번호 패드)를 등록·관리하고 출입 방식·중복 방지·이력 보관·알림 정책을 설정하는 화면(SCR-083)이다. 4종 출입 수단 활성화 토글, 동일 회원 재입장 어뷰징 방지(중복 출입 방지 시간), 비정상 출입 시도(미등록 카드·만료 회원·얼굴 미일치 등) 자동 알림으로 보안을 강화한다. 기기 연결 상태 3종(정상/오프라인/오류) 배지로 운영자가 즉시 상황을 파악하며, 오프라인 기기는 자동 재연결 + 일정 시간 지속 시 운영자 알림된다.

운영 맥락:
- **신규 IoT 게이트 설치**: [+ 새 기기 등록] → 기기 코드·설치 위치 입력 → 연결 시도 → 정상 배지 → 즉시 운영
- **오프라인 기기 응급 복구**: 행 [재연결] 클릭 → MQTT 재시도 → 실패 시 현장 점검 안내
- **출입 어뷰징 방지**: 중복 출입 방지 시간 30분으로 상향 → 같은 회원 30분 내 재입장 차단
- **비정상 출입 시도 추적**: 미등록 카드 알림 → SCR-093 출입 이력 → 시간대·기기 위치 분석
- **얼굴 인식 활성 → 키오스크 출석 연동**: SCR-083 얼굴 인식 ON + SET-IOT-01 키오스크에서 얼굴 인식 출석 활성
- **법정 보관 기간 준수**: 출입 이력 90일 보관 정책 적용 → 자동 삭제 배치
- **회원앱 입장/퇴장 푸시 ON**: 회원이 본인 출입 이력을 즉시 확인 가능
- **출입 수단 전체 비활성 시도 차단**: 4종 모두 OFF 시 "최소 1개 활성 필수" 차단
- **기기 펌웨어 업데이트**: 본사에서 기기 OTA 푸시 → 기기 일시 오프라인 → 자동 재연결 후 복구

연결 기기 현황은 5분 헬스체크 기반이며 N분 이상 오프라인 지속 시 NFR-19 알림 센터로 운영자에게 즉시 알림된다. 출입 이력은 SCR-093에서 별도 조회·필터·내보내기 가능하다.

## 주요 UX 흐름

### 기본 운영 흐름
1. 사이드바 → "설정 > IoT 출입 관리" 진입 → 기기 목록 + 연결 상태 자동 로드 (5분 헬스체크)
2. 오프라인/오류 기기 식별 → 행 [재연결] 시도
3. 출입 방식·중복 방지·보관 기간 변경 → 저장 → 즉시 push
4. 미저장 + 이탈 → DLG-080-001

### 기기 등록 흐름
1. [+ 새 기기 등록]
2. 기기 코드 (제조사 발급) + 설치 위치 입력
3. 연결 시도 → 성공 시 목록 추가 + 정상 배지
4. 실패 시 사유 표시 + 재시도

### 출입 방식 변경 흐름
1. 4종 수단 토글 + 중복 방지 시간 + 보관 기간 변경
2. 알림 토글 (입장·퇴장·비정상)
3. [저장] → 모든 기기 push + DB 저장

### 분기·예외 흐름
- **출입 수단 0개**: "최소 1개 활성 필수" + 저장 차단
- **얼굴 인식 활성·카메라 미등록**: 카메라 등록 안내 + 저장 후 fallback 동작
- **기기 코드 중복 등록**: "이미 등록된 기기" + 차단
- **기기 코드 형식 오류**: 인라인 검증 + 차단
- **재연결 시도 실패**: "기기 응답 없음" + 현장 점검 안내
- **N분 이상 오프라인 (테넌트 정책 5분)**: NFR-19 알림 + 배지 변경
- **법정 보관 기간 미달 설정**: 30일 미만 선택 차단
- **저장 push 부분 실패**: 실패 기기 목록 + 재시도
- **저장 push 전체 실패**: 트랜잭션 롤백 + 안내
- **owner가 타 지점 기기 접근**: 행 hidden (RLS branchId)

## 비즈니스 규칙

1. 출입 수단은 최소 1개 활성 필수이며 모두 비활성 저장 차단된다.
2. 중복 출입 방지 시간은 동일 회원의 연속 입장을 차단해 어뷰징을 방지한다 (5/10/30/60분 옵션).
3. 출입 이력 보관 기간은 법정 최소(30일) 이상 필수, 30일 미만 선택 차단.
4. 비정상 출입 시도(미등록 카드·만료 회원·얼굴 미일치·시간외 시도)는 관리자에게 즉시 알림된다 (NFR-19).
5. 오프라인 기기는 5분 헬스체크 기반 자동 재연결 시도되며 N분(테넌트 정책) 이상 지속 시 관리자 알림된다.
6. 변경 이력은 SCR-097 감사 로그에 기록된다.
7. **기기 코드 정책**: 제조사 발급 unique 코드, 등록 시 형식 검증·중복 차단.
8. **연결 상태 3종**: 정상(통신 정상)·오프라인(N분 무응답)·오류(인증 실패·하드웨어 오류).
9. **얼굴 인식 활성 조건**: 얼굴 인식 카메라 ≥ 1대 등록·정상 상태 필수, 미충족 시 저장은 가능하나 동작 시 fallback.
10. **회원앱 푸시 정책**: 입장·퇴장 알림 ON 시 회원에게 본인 출입 이력 푸시 발송 (NFR-19 알림 채널).
11. **비정상 출입 시도 알림 정책**: 알림 ON 시 운영자(owner/manager)에게 NFR-19 알림 + 회원앱 본인에게 보안 알림.
12. **권한 정책**: 매니저는 기기 연결 상태 조회만, owner는 소속 지점 RLS branchId 필터, primary/superAdmin은 전 지점.
13. **저장 시점 동기화 트랜잭션**: DB 저장 + 기기 MQTT push 동시 처리, 부분 실패 시 실패 기기 목록 + 재시도.
14. **출입 이력 보관 정책 변경 영향**: 보관 기간 단축 시 즉시 영향 안내 + 확인 후 적용 (자동 삭제 배치).
15. **DLG-080-001 미저장 경고**: 기기 등록·설정 변경 미저장 + 페이지 이탈 시 강제 표시.
16. **기기 등록 시 위치 표기**: 자유 텍스트 (예: "1층 입구·B1 출구·여성 탈의실"), 50자 이내.
17. **기기 펌웨어 업데이트**: 본사 OTA 푸시로 일시 오프라인 → 자동 재연결, 운영자 별도 조작 불필요.
18. **출입 이력 별도 화면**: SCR-093에서 조회·필터(회원·기기·기간·정상/비정상)·CSV 내보내기.
19. **법정 보관 정책**: 개인정보보호법에 따라 출입 이력은 최소 30일 보관 + 보관 기간 경과 자동 삭제.
20. **MQTT/WebSocket 채널**: 출입 정책 변경 시 모든 기기에 신호 push, 미연결 기기는 connect 시점 동기화.
21. **기기 삭제**: 기기 행 [삭제]는 별도 액션 (본 문서에서는 등록·재연결만 다룸, 삭제는 SCR-083 V2).

| 기기 펌웨어 업데이트 중 | 일시 오프라인 배지 | 자동 재연결 |
| 권한 부족 (스태프) | 화면 접근 차단 | 사이드바 hidden |
