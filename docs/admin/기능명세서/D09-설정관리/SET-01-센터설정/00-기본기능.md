## 기능 목적

센터 운영에 필요한 기본 정보를 한 곳에서 관리하는 설정 허브 화면(SCR-080)이다. 4개 탭(기본정보·알림설정·테마설정·물품 관리)으로 구분되어 센터명·사업자번호·운영시간 같은 핵심 메타데이터, 채널별 알림 발송 정책, 화면 모드·컬러 테마, 수건·운동복 재고 관리를 단일 진입점에서 처리한다. 각 탭은 미저장 변경 사항을 감지해 탭 전환 시 DLG-080-001로 손실을 방지한다.

운영 맥락:
- **신규 오픈 센터 초기 정보 등록**: 로고·센터명·사업자번호·연락처·주소 일괄 입력 → 저장 → 운영 시작
- **운영시간 변경 (계절·휴일)**: 평일·주말 운영시간 임시 조정 → 저장 → 회원앱·키오스크 즉시 반영
- **사업자등록증 변경**: 사업자번호 변경 → 10자리 형식 검증 → 저장 → 세금계산서 발행 정합화
- **알림 채널별 정밀 제어**: 앱 푸시 5종 / 이메일 2종 / 카카오톡 fallback 항목별 토글 + 메시지 플랫폼 연동 정보 확인 → 마케팅·운영 알림 분리
- **다크 테마 전환**: 화면 모드 다크 → 저장 → 모든 운영자 화면 즉시 적용
- **수건 재고 일일 카운트**: 수건 대 50개·소 80개 입력 → 1일 발급 한도 100개 → 잔여 자동 갱신
- **본사 표준 컬러 적용**: 본사 정책으로 메인·보조 컬러 변경 → 모든 지점 적용 안내
- **알림 채널 변경 후 즉시 적용**: 알림 토글은 저장 후 적용 (변경 즉시 발송 차단)
- **매니저 알림 설정 조회 권한**: 매니저는 알림설정 탭만 조회 가능 (수정 불가)
- **미저장 변경 + 탭 전환**: DLG-080-001로 손실 방지

기본정보 탭의 사업자번호·로고·운영시간은 회원앱·키오스크·세금계산서·홈페이지에 노출되므로 변경 시 영향 범위가 넓다. 모든 변경은 SCR-097 감사 로그에 기록된다.

## 주요 구성요소

### 기본정보 탭

| 항목 | 입력 |
|------|------|
| 센터 로고 | 이미지 업로드 (PNG/JPG ≤ 5MB) |
| 센터명 | 텍스트 (필수, 1~50자) |
| 사업자등록번호 | 10자리 숫자 |
| 센터 소개 | textarea (500자) |
| 대표 연락처 | 010 자동 포맷 |
| 주소 | 주소 검색 버튼 (도로명 + 우편번호) |
| 업종 | 11종 다중. 노출 순서: 헬스 / 필라테스 / PT샵 / 골프 / 요가 / 크로스핏 / 복싱 / 수영 / 태권도 / 스피닝 / 기타 |
| 평일 운영시간 | 오픈~마감 (HH:mm) |
| 주말 운영시간 | 오픈~마감 (HH:mm) |
| VAT 설정 | 부가세 포함/별도 |

### 알림설정 탭

| 채널 | 항목 |
|------|------|
| 앱 푸시 | 입장 알림·만료 임박·결제 완료·수업 예약·수업 취소 (5종) |
| 이메일 | 주간 리포트·만료 예정 안내 (2종) |
| 카카오톡 fallback | 회원앱 푸시 실패 시 선택 fallback, 결제 완료·만료 임박 등 |

### 메시지 플랫폼 연동 요약

| 항목 | 설명 |
|------|------|
| 연동 플랫폼 | 사용 중인 알림톡/SMS provider |
| 발신 프로필 | SMS 발신 번호 / 카카오 발신 프로필 |
| 승인 템플릿 수 | 알림톡 발송 가능 템플릿 개수 |
| 예상 비용 기준 | 플랫폼 API 응답 기준 |
| 최근 동기화 | 마지막 조회 시각 |

### 테마설정 탭

| 항목 | 옵션 |
|------|------|
| 화면 모드 | 라이트 / 다크 / 시스템 |
| 메인 컬러 | 색상 선택 (HEX) |
| 보조 컬러 | 색상 선택 (HEX) |
| 글자 크기 | 작게 / 기본 / 크게 |

### 물품 관리 탭

| 항목 | 입력 |
|------|------|
| 수건 대·소 | 재고 수량 |
| 운동복 상·하의 | 재고 수량 |
| 1일 발급 한도 | 숫자 |
| 잔여 수량 | 자동 (재고 - 오늘 발급) |

### 저장 버튼

변경 사항이 있을 때만 활성화. 미저장 + 탭 이동 시 DLG-080-001.

## 주요 UX 흐름

### 기본 정보 변경 흐름
1. 사이드바 → "설정 > 센터 설정" 진입 → 기본정보 탭 자동 활성
2. 저장값 표시 + 항목 변경
3. 저장 버튼 활성 + "저장되지 않은 변경사항" 배지
4. [저장] → 메시지(3초) + 회원앱·키오스크 push
5. 미저장 + 탭 이동 → DLG-080-001 (저장/이탈/취소)

### 알림 변경 흐름
1. 알림설정 탭 진입 → 9종 토글 상태 표시
2. 토글 변경 → 저장 활성
3. [저장] → 알림 정책 즉시 적용
4. 매니저는 토글 비활성 (조회만)

### 분기·예외 흐름
- **센터명 빈값**: "센터명은 필수입니다" 인라인 + 저장 차단
- **센터명 50자 초과**: 인라인 카운터 + 저장 차단
- **사업자번호 10자리 미달/형식 오류**: "사업자등록번호 형식 오류" + 저장 차단
- **사업자번호 검증 API 실패 (외부)**: 형식 검증만 수행 + 경고
- **로고 5MB 초과/형식 불일치**: "PNG/JPG ≤ 5MB" + 업로드 차단
- **운영시간 마감 < 오픈**: "마감 시각이 오픈보다 이르거나 동일합니다" + 저장 차단 (단 24시간 운영은 00:00~24:00 허용)
- **업종 미선택**: "업종 1개 이상 선택" + 저장 차단
- **메인·보조 컬러 동일**: 경고 + 진행 가능
- **수건 발급 한도 > 재고**: "한도가 재고를 초과합니다" + 경고
- **미저장 + 탭 이동**: DLG-080-001 강제
- **owner 다른 지점 설정**: 화면 자체 RLS branchId 필터로 차단
- **매니저가 알림설정 외 탭 직접 URL**: 권한 부족 안내

## 비즈니스 규칙

1. 센터명은 필수이며 1~50자, 빈 값 저장 불가하다.
2. 사업자등록번호는 10자리 숫자 형식 검증 후 저장된다.
3. 미저장 변경 사항이 있을 때 탭 이동 시 DLG-080-001 경고가 표시된다.
4. 알림 토글 변경은 저장 후 적용된다 (즉시 발송 차단).
5. 매니저는 알림설정 탭만 조회 가능하며 수정 불가하다.
6. 변경 이력은 SCR-097 감사 로그에 기록된다.
7. **로고 정책**: PNG/JPG ≤ 5MB, 권장 정사각 또는 가로형, 회원앱·키오스크·홈페이지에 노출.
8. **업종 다중 선택**: 11종(헬스/필라테스/PT샵/골프/요가/크로스핏/복싱/수영/태권도/스피닝/기타) 중 최소 1개 필수.
9. **운영시간 정책**: HH:mm 형식, 마감 ≥ 오픈, 24시간 운영은 00:00~24:00 표기.
10. **VAT 설정**: 부가세 포함/별도 토글, 결제·매출·세금계산서 화면 표시 형식에만 영향, 저장 데이터는 변경 없음.
11. **자동 알림 기본 채널**: 회원 대상 운영 알림의 기본 채널은 회원앱 푸시다. 카카오톡은 지점이 선택한 경우에만 푸시 실패 fallback으로 사용한다.
12. **메시지 플랫폼 정보는 조회 전용**: 카카오톡 예상 비용, 발신 프로필, 템플릿 승인 상태는 플랫폼 API로 조회만 하며 관리자에서 단가를 직접 수정하지 않는다.
13. **테마 변경 영향**: 화면 모드·컬러·글자 크기는 운영자 본인 또는 전 운영자 적용 (테넌트 정책 토글).
14. **메인·보조 컬러**: HEX 색상, 동일 색상 시 가독성 경고.
15. **물품 관리 정책**: 수건 대·소·운동복 상·하의 4종, 1일 발급 한도 ≤ 재고, 잔여 = 재고 - 오늘 발급(자동 계산).
16. **owner RLS branchId**: 자기 지점 설정만 편집 가능, 본사 슈퍼관리자/primary는 전 지점.
17. **DLG-080-001 미저장 경고**: 저장/이탈/취소 3 옵션, 탭 이동·페이지 이탈 둘 다 트리거.
18. **저장 후 회원앱·키오스크 push**: 센터명·로고·운영시간 변경 시 즉시 동기화.
19. **사업자번호 검증**: 외부 API 검증 (선택, 실패 시 형식 검증만).
20. **주소 검색**: 외부 우편번호 API 연동, 도로명·우편번호 자동 입력.
21. **알림 토글 즉시 차단 정책**: 변경 후 [저장] 전에는 발송 정책 미적용 (실수 방지).
22. **물품 잔여 0개 시 알림**: 1일 발급 한도 도달 또는 잔여 0개 시 운영자 알림.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `SET-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-080`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-080-001 미저장경고`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
