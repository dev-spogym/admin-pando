## 기능 목적

직원 목록(SCR-060)에서 직원명 클릭 시 표시되는 상세 패널/화면이다. 선택한 직원의 담당 회원·스케줄·실적·근태·인사 메모·계정 보안 상태를 한 화면에서 확인해 운영 관리자가 인사·실적·보안 의사결정을 빠르게 내릴 수 있도록 한다. 매니저·센터장은 모든 직원의 상세 정보를 조회하고 인사 메모를 작성·조회할 수 있으며, 직원 본인은 본인 정보·실적·근태만 보고 인사 메모는 비공개 처리된다. FC/트레이너/스태프는 동료 직원의 상세 접근이 차단된다.

운영 맥락:
- **트레이너 월간 평가 리뷰**: 매니저가 트레이너 상세 → 실적 카드(수업 진행·신규 매출·NPS) + 근태 요약을 한 화면에서 검토
- **OT 진행 현황 점검**: 신규 회원 OT1·OT2 완료 수 분리 카운트로 OT 미완료 회원 즉시 식별
- **담당 회원 인계 사전 검토**: 퇴사 예정 직원의 담당 회원 목록 → STF-04 인계 작업 전 회원 규모 파악
- **수업 캘린더 직원 필터 진입**: 담당 스케줄의 [캘린더 보기] 버튼을 누르면 선택 직원 기준으로 필터링된 수업 캘린더를 열어 이번 주·다음 주 수업을 확인
- **인사 메모 누적 (비공개)**: 매니저·센터장이 1:1 면담·근태 이슈·민원 발생 시 메모 작성, 직원에게 비공개
- **NPS 기반 코칭 결정**: 수업 후기 평균 NPS가 임계치 미만이면 매니저가 트레이너 코칭·재배정 검토
- **본인 마이페이지 진입**: FC/트레이너 본인이 본인 상세 → 본인 실적·근태 확인 (인사 메모는 hidden)
- **회원 상세 확인 경로**: 담당 회원 카드 또는 회원명을 클릭하면 선택 회원의 상세 화면을 열어 기본 정보, 이용권 상태, 결제·출석 이력, 상담/메모를 확인하고 뒤로가기 시 직원 상세로 복귀

상세 화면은 모바일에서 풀스크린 슬라이드로 전환되며, 카드별 스켈레톤 로딩으로 부분 데이터부터 표시한다.

## 주요 구성요소

### 담당 회원 목록

해당 직원이 담당 FC 또는 트레이너로 지정된 회원 목록.

| 표시 정보 | 설명 |
|---|---|
| 회원명 | 클릭 시 선택 회원의 상세 화면을 열어 기본 정보, 이용권 상태, 결제·출석 이력, 상담/메모 확인 |
| 연락처 | 010 자동 포맷 |
| 이용권 상태 | 활성/만료/홀딩 배지 |
| 마지막 출석일 | 상대 시간 (예: "3일 전") |

### 담당 스케줄

이번 주 / 다음 주 수업 캘린더 데이터를 직원 단위로 필터링.

- 이번 주 수업 카드 (요일별 그룹)
- 다음 주 수업 카드
- [캘린더 보기] 버튼 클릭 시 선택 직원 기준 수업 캘린더 열기

### 실적 요약 카드

| 지표 | 설명 |
|---|---|
| 이번 달 수업 진행 건수 | PT/GX/필라테스 합계 |
| 신규 매출 | 이번 달 신규 등록 매출 (담당자 귀속) |
| 재등록 매출 | 이번 달 재등록 매출 |
| OT 1·2 완료 수 | OT1 / OT2 분리 카운트 |
| NPS 평균 점수 | 수업 후기 데이터 기준 자동 집계 |

> 매출 집계 기준은 `매출관리.md` 담당자별 집계 정의를 따른다.

### 근태 요약 카드

SCR-063 근태 관리 데이터에서 이번 달 출근일·결근·지각 횟수.

| 항목 | 표시 |
|---|---|
| 출근일 | {출근일수}일 (이번 달 영업일 대비) |
| 결근 | N회 |
| 지각 | N회 |
| 출근율 | 자동 계산 % |

### 인사 메모

매니저·센터장만 볼 수 있는 비공개 메모.

- 작성 / 수정 / 삭제
- 작성자 + 일시 자동 기록
- 직원 본인 영역에서는 hidden
- 메모별 카테고리(근태/면담/민원/기타) 선택

### 계정 / 보안 카드

직원과 1:1로 연결된 로그인 계정 상태를 운영자가 바로 확인하는 영역이다. 이 카드는 직원 계정의 기본 상태 확인과 잠금/해제, 임시 비밀번호 재발급을 다루며, 접속 기기 목록 조회·활성 세션 수 표시·개별 세션 강제 로그아웃 같은 별도 세션 관리 기능은 제공하지 않는다.

| 항목 | 설명 |
|---|---|
| 로그인 ID | 현재 사용 중인 계정 식별자 |
| 권한 템플릿 | owner / manager / fc / staff / readonly 등 연결 역할 |
| 계정 상태 | ACTIVE / LOCKED / INACTIVE |
| 마지막 로그인 시각 | 최근 성공 로그인 일시 |
| 비밀번호 변경 필요 여부 | force password change 플래그 |

헤더 또는 카드 액션:

- [계정 잠금]
- [잠금 해제]
- [임시 비밀번호 재발급]
- [권한 설정으로 이동]

### 헤더 액션 버튼

| 버튼 | 동작 | 권한 |
|------|------|------|
| 수정 | 선택 직원의 기존 정보가 채워진 직원 등록/수정 폼을 열어 기본 정보, 직무, 연락처, 계정 상태, 권한 템플릿, 급여 기본 정보를 수정 | manager+ |
| 퇴사 처리 | 퇴사일, 퇴사 사유, 담당 회원·수업 인수인계, 계정 비활성화 여부를 입력하는 퇴사 처리 흐름 시작 | owner+ |
| 메시지 보내기 | 선택 직원을 수신자로 지정한 메시지 작성 화면을 열어 공지/알림 작성 | manager+ |

## 권한 분기 (RBAC)

| 역할 | 동료 상세 | 본인 상세 | 인사 메모 | 헤더 액션 |
|---|:---:|:---:|:---:|:---:|
| primary / superAdmin | O | O | O 작성·조회 | O |
| owner (센터장) | O | O | O | O (수정·퇴사·메시지) |
| manager | O | O | O | O (수정·메시지), 퇴사 처리 불가 |
| fc / 트레이너 / 스태프 | X | O (본인만) | X | X |
| readonly | X | X | X | X |

계정 / 보안 카드 액션 권한:

- `owner+`: 잠금 / 잠금 해제 / 임시 비밀번호 재발급
- `manager`: 조회만 가능, 보안 액션은 정책에 따라 제한 가능
- `직원 본인`: 본인 계정 상태만 조회, 잠금 해제/재발급 직접 실행 불가

## 주요 UX 흐름

### 정상 조회 흐름
1. SCR-060 직원 목록 → 직원명 클릭
2. 상세 패널 슬라이드 (모바일 풀스크린)
3. 담당 회원 / 스케줄 / 실적 / 근태 4개 카드 확인
4. 인사 메모 작성 (매니저·센터장 한정)
5. 헤더 [수정] 클릭 시 직원 등록/수정 폼을 열고, [퇴사 처리] 클릭 시 퇴사 처리 흐름을 시작하며, [메시지] 클릭 시 선택 직원을 수신자로 지정한 메시지 작성 화면을 연다
6. 패널 닫기 또는 뒤로가기 시 직원 목록의 검색어, 필터, 페이지 상태를 유지한 채 복귀

### 분기·예외 흐름
- **담당 회원 0건**: "담당 회원이 없어요" 빈 상태 + 회원 배정 안내 (매니저+ 권한)
- **이번 주 수업 0건**: "이번 주 수업이 없어요" + [캘린더 보기] CTA
- **실적 카드 부분 로드 실패**: 카드별 스켈레톤 유지 + 실패 카드만 [재시도] 버튼 노출
- **NPS 후기 0건**: "후기 데이터 없음" + 회색 처리 (집계 불가)
- **근태 카드 (이번 달 영업일 0)**: 신규 입사자(이번 달 입사) 출근율 N/A 표시
- **인사 메모 (직원 본인 진입)**: 메모 섹션 자체 hidden, 권한 안내 없음 (메모 존재 자체 비공개)
- **인사 메모 작성 권한 부족**: 메모 섹션 read-only + 작성 버튼 hidden
- **계정 잠금 상태**: 상세 헤더에 "잠금" 배지 + 보안 경고 카드 노출
- **비밀번호 변경 강제 상태**: "첫 로그인 후 비밀번호 변경 필요" 배지 + 재발급 CTA
- **퇴사 처리된 직원 상세 진입**: 모든 카드 read-only + "퇴사 직원" 배지 + 헤더 액션 [수정] hidden, [퇴사 취소]는 센터장만
- **휴직 직원 상세 진입**: "휴직 중" 배지 + 실적·근태 카드 회색 처리 (현재 데이터 없음)
- **본사 통합 모드 직원 상세**: 지점 라벨 헤더 표시 + 데이터는 직원 소속 지점 기준
- **모바일 풀스크린 진입**: 사이드 패널 → 풀스크린 전환 + 뒤로가기로 복귀
- **동시 메모 편집 충돌**: 다른 운영자 동시 수정 시 "다른 사용자가 수정 중" 토스트 + 새로고침 안내
- **메모 30일 자동 알림 (선택 정책)**: 30일 이상 미열람 메모는 매니저 인앱 알림으로 표시
- **담당 회원 카드 클릭**: 선택 회원의 상세 화면을 열어 기본 정보, 이용권 상태, 결제·출석 이력, 상담/메모를 확인하고 뒤로가기 시 직원 상세로 복귀

### 매니저 인앱 알림 기준

매니저 인앱 알림은 `manager` 권한 계정으로 로그인한 사용자에게 관리자 웹 내부 화면에서 알림 배너, 토스트, 알림 패널 형태로 표시되는 시스템 알림을 의미한다. 특정 대시보드 화면(SCR-090/SCR-098)에 고정 노출되는 의미가 아니며, 운영자는 알림을 클릭해 관련 직원 상세 또는 연결 화면으로 이동한다.

| 알림 | 발생 기준 | 수신자 | 클릭 후 이동 |
|---|---|---|---|
| 메모 30일 미열람 | 인사 메모 작성 후 30일 이상 미열람 | 해당 지점 manager 이상 | STF-02 직원 상세 > 인사 메모 |
| OT1 14일 미완료 | 회원 첫 정상 결제 완료일로부터 14일 내 OT1 미완료 | 해당 지점 manager 이상 | STF-02 직원 상세 > OT 진행 현황 |
| NPS 4.0 미만 | 트레이너 NPS 평균 4.0 미만 | 해당 지점 manager 이상 | 직원 상세의 NPS 카드 또는 수업 후기 목록 |

## 비즈니스 규칙

1. 인사 메모는 매니저·센터장만 작성·조회 가능하며 직원 본인에게는 노출되지 않는다 (섹션 자체 hidden, 메모 존재 자체 비공개).
2. 실적 요약의 매출 집계는 `매출관리.md`의 담당자별 집계 기준을 그대로 사용한다.
3. NPS는 수업 후기 데이터에서 자동 집계된 값이다. 후기 0건이면 N/A.
4. 본인 조회 모드에서도 동료 직원의 데이터에는 접근할 수 없다.
5. 담당 스케줄은 수업 캘린더 데이터를 직원 단위로 필터링해 표시한다.
6. 근태 요약은 SCR-063 데이터를 기반으로 이번 달 합산한다. 신규 입사자는 입사일 기준 영업일만 집계.
7. **카드별 스켈레톤 로딩**: 5개 카드(담당 회원/스케줄/실적/근태/메모)는 독립 API 호출, 부분 데이터부터 표시한다.
8. **인사 메모 카테고리**: 근태 / 면담 / 민원 / 기타. 단일 선택. 카테고리별 필터·통계 가능.
9. **인사 메모 작성자 자동 기록**: 작성자(actor_id), 작성 일시, 마지막 수정 일시. 작성자 본인 또는 센터장만 수정 가능.
10. **메모 삭제 정책**: 작성자 본인 또는 센터장만 삭제 가능. 삭제 시 soft-delete + 감사 로그.
11. **헤더 액션 권한 차이**: 수정(매니저+) / 퇴사 처리(owner+) / 퇴사 취소·정산 미완료 강제 확정(센터장+) / 메시지(매니저+). 매니저 이하에게 [퇴사 처리] 버튼은 hidden 처리하고 퇴사 처리 화면 직접 접근도 차단한다.
11-1. **계정 보안 액션 권한 차이**: 잠금/잠금 해제/임시 비밀번호 재발급은 owner 이상 또는 정책상 허용된 보안관리자만 가능하다.
11-2. **세션 관리 제외**: STF-02 직원 상세에서는 활성 세션 수, 접속 기기 목록, 세션별 강제 로그아웃 기능을 제공하지 않는다. 퇴사 처리나 계정 비활성화 시 기존 로그인 차단은 인증 공통 보안 정책으로 처리하며, 직원 상세의 별도 기능으로 보지 않는다.
12. **퇴사 직원 상세**: 모든 카드 read-only, [수정]·[퇴사 처리] hidden, [퇴사 취소]는 센터장만.
13. **휴직 직원 상세**: 실적·근태 카드 회색 처리 + "휴직 중" 라벨. 휴직 기간 데이터는 0 또는 hidden.
14. **OT 카운트 분리**: OT1(첫 트레이닝)과 OT2(2차 트레이닝) 각각 카운트. 회원 첫 정상 결제 완료일로부터 14일 내 OT1 미완료 시 매니저 알림.
15. **NPS 임계치 알림**: 트레이너 NPS 평균 4.0 미만 (5점 만점) 시 매니저 인앱 알림으로 표시 (테넌트 정책).
16. **담당 회원 정렬**: 마지막 출석일 내림차순 기본. 이용권 만료 임박 회원 상단 우선.
17. **모바일 풀스크린**: 768px 미만 화면에서 패널 → 풀스크린 자동 전환.
18. **본사 통합 모드 가시성**: 직원 상세 진입 시 지점 라벨 헤더 표시, 데이터는 직원 소속 지점 기준.
19. **감사 로그**: 인사 메모 생성·수정·삭제, 헤더 액션 실행 이력은 히스토리 로그에 기록한다. `actor_id`, `staff_id`, `action_type`, `memo_id` 저장.
19-1. **보안 감사 로그**: 계정 잠금/해제/재발급/권한 이동도 SCR-097에 기록한다.
20. **상세 패널 캐시**: 30초 캐시. [새로고침] 버튼으로 강제 갱신.
21. **메시지 보내기**: 헤더 [메시지] 클릭 시 선택 직원을 수신자로 지정한 단일 메시지 작성 화면을 연다.
22. **본인 조회 모드 헤더 액션**: [수정] hidden (관리자 권한 필요), [퇴사 처리] hidden, [메시지] hidden.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `STF-02`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-060 상세`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
