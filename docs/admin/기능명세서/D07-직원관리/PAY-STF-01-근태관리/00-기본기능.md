## 기능 목적

직원별 출퇴근 기록을 조회하고 지각·결근·초과근무 현황을 파악하는 화면(SCR-063)이다. 월별·직원별로 근무 시간을 집계해 급여 산정의 기초 데이터로 활용하며, 관리자가 출퇴근 기록을 수동으로 보정할 수 있다. 모든 보정 이력은 감사 로그에 기록된다. 직원 본인은 자신의 근태만 조회할 수 있고 수정은 불가하다.

운영 맥락:
- **자동 수집 우선**: 키오스크(SCR-082) 또는 IoT 출입(SCR-083)에서 자동 수집된 데이터가 우선 적용
- **월말 급여 산정 대비**: 매니저가 월말 직원별 근태 집계 → 보정 → 급여 화면(PAY-STF-02)으로 데이터 자동 연동
- **누락 기록 수동 추가**: 키오스크 미사용·IoT 미연동 환경에서 매니저가 출근/퇴근 직접 입력
- **시각 보정 (지각 인정)**: 회의·외근 등 정당 사유 지각 시 매니저가 출근 시각 보정 + 사유 기록
- **초과근무 신청·승인**: 직원 신청 → 매니저 승인 → 근태 시간에 초과 시간 추가 (정책에 따라 별도 모듈)
- **휴가·연차 관리**: 별도 휴가 관리 모듈에서 처리, 근태 화면은 표시만 (출근일에서 자동 제외)
- **외근·재택**: 별도 카테고리로 처리, 근무 시간 인정 (정책 따라)
- **본인 근태 조회 (모바일)**: 직원 앱·웹에서 본인 출퇴근 기록 + 월 출근율 확인
- **본사 슈퍼관리자 전 지점 근태 조회**: 통합 모드에서 지점 비교, 평균 출근율 분석
- **노무사 제출 자료**: 월별 근태 엑셀 다운로드, 임금 정산 자료로 활용

근태 데이터는 PAY-STF-02 급여 관리에 자동 연동되어 시급제·건별 직원의 급여 자동 계산에 핵심 입력으로 활용된다.

## 주요 구성요소

### 조회 기간 선택

월 단위 또는 특정 날짜 범위를 선택해 해당 기간의 근태 데이터 조회. 기본값은 당월.

### 직원 선택 필터

특정 직원 또는 전체 직원 선택. 직무 필터(PT트레이너/GX강사/골프강사/FC/매니저/스태프) 보조 제공.

### 요약 지표 카드

| 지표 | 설명 |
|------|------|
| 정상 출근 일수 | 지각·결근·조퇴 제외 |
| 지각 횟수 | 출근 시각 기준 초과 |
| 결근 횟수 | 영업일 미출근 |
| 총 근무 시간 | 합계 |
| 평균 출근율 | (정상 + 지각) / 영업일 % |

### 근태 목록 테이블

| 컬럼 | 설명 |
|------|------|
| 날짜 | YYYY-MM-DD (요일 표시) |
| 직원명 | - |
| 출근 시각 | HH:MM |
| 퇴근 시각 | HH:MM |
| 근무 시간 | 자동 계산 |
| 상태 | 정상 / 지각 / 결근 / 조퇴 / 외근 / 휴가 배지 |
| 출처 | 키오스크 / IoT / 수동 보정 / 누락 추가 |
| 보정 이력 | 보정 횟수 + hover 시 상세 |

### 수동 보정 기능

관리자가 출퇴근 시각을 직접 수정하거나 누락된 기록을 추가. 보정 사유 필수, 이력 기록.

### 누락 기록 추가 다이얼로그

일자·출근/퇴근 시각·사유 입력. 매니저+ 권한 필요.

### 월별 집계 요약

직원별 월 총 근무 시간과 출근율을 한눈에 비교하는 요약 뷰.

### 엑셀 내보내기

조회 결과를 엑셀 파일로 다운로드. 노무사 제출 양식 옵션.

## 주요 UX 흐름

### 정상 조회 흐름
1. 사이드바 "직원 관리 > 근태 관리" 진입
2. 조회 기간(월/날짜 범위) + 대상 직원 선택
3. 근태 목록에서 일자별 출퇴근 기록 확인
4. 요약 카드로 지각·결근 현황 파악
5. 오류 기록이 있으면 [수정] 또는 [누락 추가] → 사유 입력 → 저장
6. 급여 계산 시 월별 집계 요약 데이터 활용

### 본인 모드 흐름
1. 직원 앱·웹에서 근태 메뉴 진입
2. 본인 데이터만 표시 (보정/추가 영역 hidden)
3. 월 출근율·지각·결근 확인
4. 잘못된 기록 발견 시 매니저에게 메시지 (직접 보정 불가)

### 분기·예외 흐름
- **데이터 0건 (신규 입사자)**: "기록이 없습니다" + 입사일 안내
- **자동 수집 데이터 + 수동 보정 충돌**: 수동 보정 우선 적용 + "수동 보정됨" 배지
- **보정 사유 미입력**: 인라인 에러 "보정 사유는 필수입니다" + 저장 비활성
- **보정 권한 부족 (직원 본인)**: 수정 버튼 hidden + read-only 모드
- **누락 기록 시각 불일치 (퇴근 < 출근)**: 인라인 에러 "퇴근 시각이 출근 시각보다 빠릅니다"
- **누락 기록 미래 일자**: 인라인 에러 "미래 날짜는 입력할 수 없습니다"
- **누락 기록 영업일 외 (휴무일)**: 경고 모달 "영업일이 아닙니다, 진행하시겠습니까?"
- **이미 자동 수집된 일자에 누락 추가**: 경고 모달 "이미 기록이 있습니다, 덮어쓰시겠습니까?"
- **휴가·외근 일자 보정 시도**: 경고 + 휴가 모듈에서 처리 안내
- **본사 통합 모드 권한 부족**: 통합 토글 hidden
- **엑셀 다운로드 대용량 (전 지점 + 1년)**: 백그라운드 잡 + 알림 센터 링크
- **신규 입사자 출근율 N/A**: 입사일 이전은 영업일 미카운트
- **퇴사 직원 근태 조회**: 퇴사 확정일까지 표시, 이후 데이터 없음
- **조퇴 처리**: 퇴근 시각이 정규 시간 미만 시 "조퇴" 자동 분류
- **24시간 초과 출근 (야간 근무)**: 다음 날 일자로 분리 또는 합산 (정책)
- **모바일 풀스크린 진입**: 테이블 → 카드 리스트 자동 전환

## 비즈니스 규칙

1. 출퇴근 기록의 수동 보정은 매니저+ 권한자만 가능하며, 보정 이력이 반드시 기록된다.
2. 직원 본인은 본인 기록만 조회할 수 있으며 수정·추가는 불가능하다.
3. 출근율은 (정상 출근 + 지각) / 총 영업일로 계산한다.
4. 키오스크(SCR-082) 또는 IoT 출입(SCR-083)에서 자동 수집된 데이터가 우선이다.
5. 보정 사유는 필수 입력이며 감사 로그(SCR-097)에 기록된다.
6. 근태 데이터는 PAY-STF-02 급여 관리에 자동 연동된다.
7. **상태 6종**: 정상 / 지각 / 결근 / 조퇴 / 외근 / 휴가. 자동 분류 + 수동 변경 가능.
8. **출처 4종**: 키오스크 / IoT / 수동 보정 / 누락 추가. 출처 배지로 구분.
9. **수동 보정 우선**: 자동 수집 + 수동 보정 충돌 시 수동 우선 적용 + "수동 보정됨" 배지.
10. **누락 기록 검증**: 퇴근 시각 > 출근 시각 필수, 미래 일자 차단, 휴무일 경고.
11. **누락 기록 덮어쓰기**: 이미 자동 수집된 일자에 누락 추가 시 경고 모달, 운영자 확인 후 덮어쓰기.
12. **직원 지각 기준**: 고정값을 사용하지 않고 D09 `SCR-086 출석 관리 설정 > 직원 근태 기준 설정`의 지점별 직원 지각 허용 N분을 따른다. 출근 시각이 `정규 출근 시각 + 직원 지각 허용 N분`을 초과하면 지각으로 자동 분류한다.
12-1. **수업 지각 기준과 분리**: 수업/회원 출석의 지각·노쇼 기준은 직원 출퇴근 자동 분류에 재사용하지 않는다.
13. **조퇴 기준**: 퇴근 시각이 정규 퇴근 시각 미만. 자동 분류.
14. **결근 기준**: 영업일 + 출근 기록 없음 + 휴가/외근 미등록. 자동 분류.
15. **24시간 초과 야간 근무**: 다음 날 일자로 분리 (기본) 또는 합산 (정책).
16. **휴가·외근 자동 제외**: 출근일 카운트에서 자동 제외, 출근율 분모에 영향 없음.
17. **신규 입사자**: 입사일 이전 영업일 미카운트, 입사일 = 첫 출근일 기준.
18. **퇴사 직원**: 퇴사 확정일까지 데이터 보존·조회 가능, 이후 신규 데이터 없음.
19. **본사 슈퍼관리자 통합 모드**: 전 지점 근태 합산 + 지점별 비교, 매니저+ 만 가능.
20. **엑셀 노무사 양식**: 노무사 제출 양식(월별·직원별·근무시간·휴가·결근) 컬럼 매핑 옵션 제공.
21. **엑셀 파일명 규칙**: `yyyymm_지점_근태.xlsx` (통합 모드는 `yyyymm_전체_근태.xlsx`).
22. **대용량 다운로드**: 전 지점 + 1년 데이터는 백그라운드 잡 처리 + 알림 센터 링크.
23. **감사 로그**: 보정·누락 추가·상태 변경 모두 SCR-097에 기록. `actor_id`, `staff_id`, `date`, `before`, `after`, `reason` 저장.
24. **보정 이력 hover**: 보정 이력 컬럼 hover 시 작성자·일시·사유 상세 표시. 매니저+ 만 노출.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `PAY-STF-01`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-063`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
