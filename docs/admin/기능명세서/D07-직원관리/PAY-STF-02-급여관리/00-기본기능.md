## 기능 목적

직원별 당월 급여를 계산하고 수당·공제 내역을 검토한 뒤 최종 급여를 확정하는 화면(SCR-064)이다. 근태 데이터(PAY-STF-01)와 연동되어 기본급에 각종 수당이 자동 반영되며, 관리자가 항목을 수동으로 편집한 후 일괄 확정할 수 있다. 급여 편집은 매니저 이상이 가능하지만, 최종 확정은 센터장만 가능하다. 확정된 급여는 PAY-STF-03 급여 명세서에서 조회 가능해진다.

운영 맥락:
- **월말 정기 급여 산정**: 매니저가 근태 데이터 마감 후 급여 자동 계산 → 수당·공제 검토 → 센터장이 일괄 확정
- **수당 수동 조정 (성과급)**: 매출 우수자에게 추가 성과 수당 → DLG-064-001에서 항목 추가 → 변경 사유 기록
- **공제 수동 조정 (지각·결근)**: 근태 페널티 → 공제 항목 추가 → 사유 기록
- **트레이너 수업 수당 자동 계산**: 진행 수업 건수 × 단가 → 자동 합산 (정책 토글)
- **확정 후 오류 발견 → 당월 재편집**: 확정 취소 → DLG-064-001 재편집 → 재확정 (당월 한정)
- **전월 급여 조회 (read-only)**: 전월 이전은 잠금, 조회만 가능
- **본사 슈퍼관리자 전 지점 급여 통합 조회**: 통합 모드에서 지점별 합산, 본사 차원 인건비 분석
- **이전 월 대비 증감**: 요약 카드에서 전월 대비 ±% 표시, 비정상 증감 자동 알림
- **노무사 임금 정산 자료**: 엑셀 다운로드 → 노무사 시스템 입력 자료
- **시급제 직원 자동 계산**: 근태 시간 × 시급 → 자동 합산
- **건별 직원 자동 계산**: 진행 건수 × 단가 → 자동 합산

급여 계산 공식: **실지급액 = 기본급 + 수당 합계 − 공제 합계 + 수업/건별 수수료**.

## 주요 구성요소

### 지급 월 선택

급여를 처리할 대상 월 선택. 기본값은 당월. 전월 이전은 read-only 잠금.

### 요약 지표 카드

| 지표 | 설명 |
|------|------|
| 전체 지급 예정 금액 | 합계 |
| 확정 완료 인원 | {인원수}명 |
| 미확정 인원 | {인원수}명 |
| 이전 월 대비 증감 | + / − % 표시 |

### 직원별 급여 테이블

| 컬럼 | 설명 |
|------|------|
| 직원명 | - |
| 역할 | 직무 배지 |
| 급여 형태 | 월급/시급/건별 |
| 기본급 | 자동 계산 |
| 수당 합계 | 근태 연동 + 수동 편집 합산 |
| 공제 합계 | 4대 보험 + 추가 공제 |
| 수수료 | 수업 건수 × 단가 (트레이너) |
| 실지급액 | 자동 계산 |
| 확정 상태 | 미확정 / 확정 배지 |
| 액션 | 편집 / 확정 / 확정 취소 |

### 직군별 산식 정책

| 직군 | 주요 산식 |
|------|-----------|
| FC | 기본급 + 신규 등록 커미션 + 재등록 커미션 + 상품추가 커미션 - 환불 차감 |
| PT | 기본급 또는 시급 + 수업단가 + 수업매출 정률 + 타지점 수업 귀속 조정 |
| GX | 클래스당 고정수당 또는 시급 + 출석 인원 보너스 + 결강/대체수업 조정 |
| 공통 | 지각·결근 공제, 4대 보험, 수기 수당/공제, 퇴사 일할 계산 |

### 수당·공제 편집 (DLG-064-001)

각 직원 행의 [편집] 클릭 시 다이얼로그 열림. 항목별 금액 수동 조정 + 실지급액 미리보기 + 변경 사유 입력.

### 급여 확정 (DLG-064-002)

개별 또는 전체 직원의 급여를 확정. 확정 전 확인 다이얼로그 표시 (인원/총액 요약).

### 확정 취소

이미 확정된 급여도 당월 내에는 확정 취소 후 재편집 가능. 전월 이전은 잠금.

### 엑셀 내보내기

당월 급여 내역 전체를 엑셀 파일로 다운로드. 노무사 양식 옵션.

## 주요 UX 흐름

### 정상 처리 흐름
1. 사이드바 "직원 관리 > 급여 관리" 진입
2. 지급 월 선택 → 직원별 급여 데이터 자동 로드
3. 근태 데이터 기반 기본급 + 수당 자동 계산 + 시급/건별 자동 산출
4. 수정이 필요한 직원 [편집] → DLG-064-001에서 항목 조정 + 사유 기록
5. 검토 후 [급여 확정] → DLG-064-002 확인 → 최종 실행
6. 확정 후 PAY-STF-03 명세서에서 조회 가능

### 확정 취소 + 재편집 흐름
1. 확정된 직원 행 → [확정 취소]
2. 권한 확인 (센터장만)
3. 발송된 명세서 자동 무효 처리 + 재발송 안내
4. DLG-064-001 재편집 가능
5. 재확정 시 명세서 새로 생성

### 분기·예외 흐름
- **재직 직원 0건**: "재직 직원이 없습니다" 빈 상태
- **자동 계산 실패 (근태 데이터 부재)**: 해당 직원 행에 경고 + "근태 데이터 확인 필요"
- **시급제 + 근태 0시간**: 기본급 0 + 경고 표시
- **건별 + 진행 건수 0건**: 수수료 0 + 경고 표시
- **수당 마이너스 입력**: 인라인 에러 "수당은 0 이상이어야 합니다"
- **공제가 기본급+수당 초과**: 경고 모달 "실지급액이 음수가 됩니다, 확인하시겠습니까?"
- **변경 사유 미입력 (편집 시)**: 인라인 에러 "변경 사유는 필수입니다"
- **확정 권한 부족 (매니저)**: [확정] 버튼 hidden + 편집만 가능
- **확정 후 [편집] 시도**: read-only + "확정 취소 후 편집하세요"
- **전월 이전 급여 편집·확정 시도**: 잠금 + "이전 월은 수정할 수 없습니다"
- **확정 취소 권한 부족**: [확정 취소] hidden
- **확정 취소 시 발송된 명세서 처리**: 자동 무효 + 재발송 알림
- **전월 대비 증감 50% 이상**: 요약 카드 빨강 알림 + 매니저 점검 안내
- **이미 확정된 급여 일괄 확정 시도**: 자동 제외 + 미확정만 처리
- **본사 통합 모드 권한 부족**: 토글 hidden
- **엑셀 다운로드 대용량**: 백그라운드 잡 + 알림 센터 링크
- **트레이너 수업 수당 정책 OFF**: 수수료 컬럼 hidden 또는 0
- **퇴사 직원 당월 급여**: 퇴사 확정일까지 일할 계산 + 일할 안내
- **휴직 직원**: 급여 미산정 (기본급 0) + "휴직 중" 배지

## 비즈니스 규칙

1. 급여 편집은 매니저 이상이 가능하지만, 최종 확정은 센터장만 가능하다.
2. 확정된 급여만 PAY-STF-03 급여 명세서에서 조회 가능하다.
3. 당월 내에는 확정 취소 후 재편집이 가능하다 (전월 이전은 잠금).
4. 근태 데이터(PAY-STF-01)는 자동 연동되어 수당이 계산된다.
5. 수당·공제 편집 시 변경 사유가 기록된다.
6. 확정 처리는 감사 로그(SCR-097)에 기록된다.
7. **계산 공식**: 실지급액 = 기본급 + 수당 합계 − 공제 합계 + 수수료.
8. **급여 형태 4종**: 고정급제 / 시급제 / 정률제 / 혼합제. 각 형태별 자동 계산 로직을 분리한다.
9. **FC 산식**: 기본급 + 신규 등록 커미션 + 재등록 커미션 + 상품추가 커미션 − 환불 확정 차감.
10. **PT 산식**: 기본급 또는 시급 + 수업단가 + 수업매출 정률 + 타지점 수업 귀속 조정.
11. **GX 산식**: 클래스당 고정수당 또는 시급 + 출석 인원 보너스 + 결강/대체수업 조정.
12. **시급제 자동 계산**: 근태 총 근무 시간 × 시급. 야간/휴일 가산 정책 (1.5배 등) 적용.
13. **건별 자동 계산 (트레이너)**: 진행 수업 건수 × 단가. 수업 종류별 단가 분리.
14. **지각·결근 자동 공제**: 근태 페널티 정책에 따라 자동 산출 (테넌트 정책 토글).
15. **확정 권한 (센터장만)**: 매니저는 편집만 가능, [확정] 버튼 hidden.
16. **확정 취소 권한 (센터장만, 당월 한정)**: 매니저 hidden, 전월 이전은 잠금.
17. **확정 취소 시 명세서 처리**: 발송된 명세서 자동 무효 + 직원에게 재발송 알림.
18. **전월 이전 잠금**: 전월 이전 급여는 read-only. 수정 불가, 조회만 가능.
19. **변경 사유 필수**: 편집 시 변경 사유 필수 입력. 감사 로그에 기록.
20. **마이너스 실지급액 경고**: 공제가 기본급+수당 초과 시 경고 모달, 확인 시 진행.
21. **전월 대비 증감 알림**: ±50% 이상 변동 시 요약 카드 빨강 알림 + 매니저 점검 유도.
22. **이미 확정된 급여 일괄 확정 자동 제외**: 미확정 인원만 대상.
23. **퇴사 직원 일할 계산**: 퇴사 확정일까지 일할 계산 (월급제), 시급/건별은 실 근무 기준.
24. **휴직 직원**: 휴직 기간 급여 미산정 (기본급 0), "휴직 중" 배지.
25. **타지점 강습 귀속 규칙**: 다른 지점 수업은 정책에 따라 수행 지점 / 판매 지점 / 정산 지점 중 하나를 급여 실적 기준으로 선택한다.
26. **환불 차감 규칙**: 환불 확정 건은 커미션 지급 대상에서 제외하거나 이전 지급분을 차감할 수 있으며, 정책별 차감 비율을 저장한다.
27. **본사 슈퍼관리자 통합 모드**: 전 지점 합산 + 지점별 비교, 매니저+ 가능.
28. **엑셀 노무사 양식 옵션**: 노무사 제출 양식 컬럼 매핑 자동 변환.
29. **엑셀 파일명 규칙**: `yyyymm_지점_급여.xlsx` (통합은 `yyyymm_전체_급여.xlsx`).
30. **감사 로그**: 편집·확정·확정취소 모두 SCR-097에 기록. `actor_id`, `staff_id`, `month`, `before`, `after`, `reason` 저장.
31. **세무·4대 보험 외부 처리 안내**: 급여 화면에 "세무 신고·4대 보험은 외부 시스템에서 진행하세요" 안내 박스.

## 자동화 / 배치 / 이벤트 연계

| 연계 대상 | 트리거 | 영향 |
|---|---|---|
| SCR-097 히스토리 로그 | 편집·확정·확정취소 | actor·staff_id·month·before·after INSERT |
| PAY-STF-01 근태 자동 연동 | 지급월 변경 + 근태 마감 | 시급/건별 자동 계산 |
| 시급제 자동 계산 | 근태 총 시간 × 시급 | 기본급 자동 산출 |
| 건별 자동 계산 | 진행 건수 × 단가 | 수수료 자동 산출 |
| 지각·결근 공제 자동 | 근태 페널티 정책 | 공제 항목 자동 추가 |
| PAY-STF-03 명세서 생성 | 확정 완료 | 명세서 자동 생성 |
| 명세서 자동 무효 | 확정 취소 | 발송된 명세서 무효 + 재발송 알림 |
| 전월 이전 잠금 | 매월 1일 00:00 | 전월 read-only 전환 |
| 전월 대비 증감 알림 | ±50% 이상 | 매니저 알림 (NFR-19) |
| 퇴사 직원 일할 계산 | 퇴사 확정 + 당월 | 일할 자동 산출 |
| 휴직 직원 미산정 | 휴직 상태 | 기본급 0 자동 |
| 본사 통합 합산 | 통합 모드 | 지점별 합산 + 비교 |
| 노무사 양식 변환 | 엑셀 옵션 | 양식 매핑 |
| 대용량 엑셀 잡 | 전 지점 + 1년 | 백그라운드 + 알림 |
| 4대 보험 외부 안내 | 모든 지급 | 외부 처리 안내 표시 |
| 세무 신고 외부 안내 | 모든 지급 | 외부 처리 안내 |

## 관련 화면 / API

- **연계 화면**: PAY-STF-01 근태 / PAY-STF-03 명세서 / SCR-097 감사 로그 / NFR-19 알림 / SCR-064
- **연계 다이얼로그**: DLG-064-001 / DLG-064-002
- **API 기준**: `GET /api/payroll/:month` / `PUT /api/payroll/:id` / `POST /api/payroll/:id/confirm` / `POST /api/payroll/:id/cancel-confirm` / `POST /api/payroll/bulk-confirm` / `GET /api/payroll/export` / `GET /api/payroll/summary`

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `PAY-STF-02`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-064`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-064-001, DLG-064-002`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
