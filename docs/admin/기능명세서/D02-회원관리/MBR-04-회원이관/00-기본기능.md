## 기능 목적

회원을 현재 소속 지점에서 다른 지점으로 이관하는 화면이다. 이관 전 미납금·락커·홀딩·PT 잔여·쿠폰·마일리지 6종 체크리스트를 자동 점검하여 차단(block) / 주의(warn) / 안내(info) 등급으로 결과를 표시한다. 이관 유형 3종(잔여 이용권 유지 / 환불 후 신규 / 소진 후 이관)을 선택하고 사유를 입력해 최종 이관을 실행한다.

## 주요 구성요소

### 대상 회원 정보 표시

이관 대상 회원의 이름, 연락처, 현재 지점, 상태, 이용권 종류, 만료일.

### 이관 전 체크리스트 (6종 자동 점검)

| 항목 | 등급 | 처리 |
|------|------|------|
| 미납금 | block | 해결 전 이관 불가 |
| 락커 | block | 회수 후 이관 |
| 홀딩 진행 중 | warn | 확인 후 진행 가능 |
| PT 잔여 | warn | 처리 방식 선택 |
| 쿠폰 보유 | info | 지점 한정 시 소멸 안내 |
| 마일리지 | info | 테넌트 전체 공유 (이관 후 유지) |

### 이관 설정

| 항목 | 입력 |
|------|------|
| 이관할 지점 | 드롭다운 (현재 지점 제외) |
| 이관 유형 | 라디오 (잔여 유지 / 환불 후 신규 / 소진 후 이관) |
| 사유 | textarea |

### 이관 확인 모달 (DLG-M023)

최종 확인 화면에서 이관 대상과 유형을 재확인 후 실행.

## 계정별 차이 (RBAC)

| 역할 | 이관 가능 |
|---|:---:|
| primary / superAdmin | ✅ 모든 지점 간 이관 |
| owner (센터장) | ✅ 본인 지점 → 타 지점 |
| manager / fc / staff / 트레이너 / readonly | ❌ 접근 불가 |

## 주요 UX 흐름

1. SCR-M001 행별 [이관] 또는 단일 선택 [지점이관] 또는 SCR-M004 헤더 [지점이관]
2. SCR-M005 진입 → 대상 회원 정보 + 체크리스트 자동 점검
3. block 항목 있으면 "해결 후 진행" 안내, warn은 확인 후 진행 가능
4. 이관 지점 / 유형 / 사유 입력
5. [이관 실행] → DLG-M023 확인 모달
6. 최종 확인 → 처리 → SCR-M001 복귀

## 화면 상태

| 상태 | 설명 |
|---|---|
| 정상 (이관 가능) | 모든 입력 활성 + 실행 버튼 활성 |
| block 항목 있음 | 실행 버튼 비활성 + 해결 안내 |
| warn 항목 있음 | 경고 표시, 실행 가능 |
| 처리 중 | 로딩 + 중복 클릭 방지 |
| 처리 완료 | 토스트 + SCR-M001 복귀 |
| 처리 실패 | 에러 토스트 + 재시도 |

## 비즈니스 규칙

1. 미납금이 있거나 락커를 보유한 경우 이관이 차단된다 (block).
2. 홀딩 중이거나 PT 잔여 횟수가 있어도 이관 자체는 가능하지만 담당자가 확인 후 진행한다 (warn).
3. 쿠폰은 지점 한정인 경우 이관 시 소멸될 수 있음을 사전에 안내한다.
4. 마일리지는 테넌트 전체 공유이므로 이관 후에도 그대로 유지된다.
5. 이관 실행은 되돌릴 수 없다.
6. 본사 통합 모드에서 이관하더라도 원 지점은 회원의 실제 소속 지점(`members.branchId`)으로 기록한다.
7. 현재 소속 지점과 동일한 지점으로는 이관할 수 없다.
8. 이관 사유는 감사 로그(SCR-097)에 기록된다.
