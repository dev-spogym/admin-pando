## 기능 목적

새로운 회원을 시스템에 등록(SCR-M002)하거나 기존 회원의 정보를 수정(SCR-M003)하는 화면이다. 필수 정보(Step 1 — 인적사항·관리정보)와 추가 정보(Step 2 — 추가 연락·메모)를 단계별로 입력받아 "빠른 카운터 등록"과 "상세 프로파일링"을 분리한다. 등록 완료 후 5초간 [바로 결제] 버튼을 노출해 신규 회원의 이용권 결제(SCR-S003)로 자연스럽게 연결하며, 결제 완료까지 끊김 없는 단일 흐름을 유지한다.

운영 맥락:
- **스태프/프런트가 카운터에서 신규 방문자 대면 등록 시**: Step 1만 빠르게 입력 → 저장 → 바로 결제로 직행 (체류 시간 최소화)
- **매니저가 콜·온라인 사전 등록 처리 시**: Step 1 + Step 2 전체 입력으로 마케팅·CRM 분석에 필요한 유입경로·운동목적·광고 동의까지 확보
- **센터장이 법인 회원(기명/무기명) 일괄 등록 시**: 회사명 + 출석번호 사전 발급 + 법인 결제 흐름 연동
- **회원 본인 정보 변경 요청 처리 (수정 모드)**: 연락처 변경 시 중복 검증 + 기존 인증 정보 무효화 + 알림 동의 재확인까지 처리

SCR-M003 수정 모드는 동일 컴포넌트를 재사용하되 기존 정보가 자동 채움되며, "변경된 필드"만 PATCH 요청으로 전송하고 모든 변경은 SCR-097 히스토리 로그에 before/after로 기록된다.

## 주요 구성요소

### 단계 표시기 + 프로필 사진

- **Step 표시**: Step 1 / Step 2 진행 단계 상단 표시. Step 1 완료 후 Step 2 이동 가능
- **프로필 사진 업로더**: 원형 영역 클릭 → 사진 등록. 미등록 시 이니셜 아바타 자동 생성

### Step 1 — 기본 인적 사항 (필수)

| 항목 | 입력 | 검증 |
|------|------|------|
| 이름 | 텍스트 | 필수, 한/영/한자 2~20자 |
| 성별 | 토글 (남/여) | 필수 |
| 연락처 | 010 자동 포맷 + [중복 확인] | 필수, 중복 시 DLG-M006 경고 |
| 회원구분 | 일반 / 기명법인 / 무기명법인 | 필수 |
| 법인 회사명 | 회원구분=법인 시 추가 노출 | - |
| 생년월일 | 캘린더 | 미래 날짜 차단 |
| 키 (cm) | 숫자 | - |

### Step 1 — 관리 정보

담당 FC / 담당 트레이너 / 방문경로 / 유입경로 / 운동 목적 (모두 선택)

### Step 2 — 추가 연락 정보

별칭·닉네임 / 이메일 / 주소(DLG-M027 주소 검색) / 상세 주소 / 회사명 / 출석번호

### Step 2 — 기타 설정

- 광고성 정보 수신 동의 체크박스
- 메모 입력란 (최대 500자, 글자 수 표시)

### 하단 고정 버튼

- Step 1: [취소] [다음]
- Step 2: [이전] [저장]
- [초기화]: 입력한 내용이 있을 때만 활성, 확인 후 전체 초기화 (DLG-M008)

## 주요 UX 흐름

### 정상 등록 흐름
1. SCR-M001의 [회원 추가] 버튼 → SCR-M002 진입
2. Step 1: 이름·성별·연락처·회원구분 입력 + [중복 확인] 버튼 클릭
3. 중복 없음 → 초록 체크 표시 → [다음] 활성화
4. [다음] → Step 2 (필수 미입력 또는 중복 미완료 시 이동 불가, 미입력 필드 빨강 강조)
5. Step 2 추가 정보 선택적 입력 → [저장]
6. 성공 시 SCR-M004 회원 상세로 이동, 우측 상단에 [바로 결제] 버튼 5초 카운트다운 노출 → 클릭 시 SCR-S003 진입
7. 5초 경과 후 버튼 사라짐, 회원 상세 정상 노출

### 수정 (SCR-M003) 흐름
1. SCR-M004 헤더 [수정] 또는 SCR-M001 행별 메뉴 진입
2. 기존 정보 자동 채움 + Step 1/2 모두 진입 가능 (단계 잠금 없음)
3. 변경된 필드만 dirty 마크 → 저장 시 PATCH로 변경 필드만 전송
4. 연락처 변경 시 중복 재검증 필수 + 기존 SMS/카카오 인증 토큰 무효화
5. 저장 → SCR-M004 복귀 + 변경 알림 토스트 ("3개 항목이 수정되었어요")

### 분기·예외 흐름
- **연락처 중복 시 (DLG-M006)**: 동일 연락처가 활성 회원에 존재 → 모달에 기존 회원 카드(이름·이용권 상태) 표시 + [기존 회원으로 이동] / [강제 등록(법인 동일 번호 등)] / [닫기] 3선택지
- **연락처 중복 시 — 탈퇴/삭제 회원**: 동일 연락처가 탈퇴/삭제 회원에 존재 → "복구" 옵션 우선 안내 + 신규 등록 시 별도 회원 ID 부여
- **연락처 중복 확인 후 다른 필드 수정한 경우**: 연락처 자체는 변경 안 했는데 다른 값 수정 후 30초 경과 → 중복 확인 만료 → 재확인 요구
- **이미지 업로드 도중 페이지 이탈**: 진행 중 업로드 취소 안내 + 임시 S3 객체 자동 정리
- **Step 1 → Step 2 → Step 1 되돌아간 경우**: Step 2 입력값 보존, 다시 Step 2 진입 시 그대로 표시
- **저장 도중 네트워크 끊김**: 클라이언트에서 입력값 임시 저장(localStorage 30분 TTL) + 재진입 시 "이전에 작성 중이던 내용을 불러올까요?" 모달
- **출석번호 중복 자동 생성**: 시스템 자동 발급 시 동일 지점 내 충돌 시 +1 증가 재시도, 3회 실패 시 운영자에게 수동 입력 요청
- **법인 회원 모드 → 일반 회원 변경**: 회사명 입력값 자동 비움 + 사용자에게 "법인 정보가 초기화됩니다" 사전 경고
- **수정 도중 회원이 다른 운영자에 의해 탈퇴 처리됨**: 저장 시도 시 409 Conflict → "회원 상태가 변경되었어요" 모달 + 새로고침 안내

## 비즈니스 규칙

1. 연락처는 중복 확인을 완료해야 다음 단계로 진행할 수 있다. 중복 확인 결과는 30초간 유효하며 이후 재확인 필요.
2. 생년월일에 미래 날짜는 입력할 수 없으며, 만 14세 미만은 법정 대리인 동의 체크박스 필수(개인정보보호법).
3. 이름은 한/영/한자 2~20자. 특수문자·이모지 차단(검색 정합성). 단, 외국인 회원의 경우 영문 미들네임 공백 허용.
4. 메모는 500자 초과 불가, 줄바꿈 포함. 민감정보(주민번호 패턴) 입력 시 정규식 검출 후 저장 차단 + 경고.
5. 출석번호 미입력 시 시스템 자동 생성(지점 내 유일, 4~6자리 숫자). 동일 지점 내 중복 충돌 시 +1 재시도.
6. 법인 회원은 기명/무기명 구분, 회사명 추가 입력 필수. 무기명 법인은 연락처 중복 검증 우회 가능(DLG-M006에서 [강제 등록] 선택).
7. 등록 완료 후 5초간 [바로 결제] 버튼이 단축 진입으로 노출. 5초 카운트다운은 회원 상세 진입 직후 시작.
8. **연락처 중복 정책**: 활성 상태 회원과 중복은 [강제 등록] 권한자(매니저+) 외 차단. 탈퇴/삭제 회원과 중복은 "복구" 우선 안내 후 신규 등록 허용.
9. **연락처 변경 시 인증 무효화**: 수정 모드에서 연락처를 변경하면 기존 SMS/카카오 인증 토큰, 패스워드 리셋 토큰을 즉시 무효화하고 신규 인증을 유도.
10. **branchId 변경 차단**: 수정 모드에서 `branchId` 직접 변경은 불가. 지점 변경은 SCR-M005 회원 이관 화면을 통해서만 가능.
11. **광고성 정보 수신 동의**: 등록 시 동의 → `marketing_agreed_at` 타임스탬프 저장. 동의 철회는 회원 본인이 모바일 앱에서만 가능(전자문서법).
12. **이미지 업로드 검증**: 5MB 이내, JPEG/PNG/WebP만 허용. EXIF GPS 정보 자동 제거(개인정보보호).
13. **부분 저장(드래프트)**: Step 1 입력 중 페이지 이탈 시 localStorage 30분 TTL로 임시 보관. 재진입 시 사용자 확인 후 복원.
14. **수정 이력 로그**: SCR-M003 수정 시 변경된 필드별 before/after를 SCR-097 히스토리 로그에 INSERT. 메모 변경은 본문 diff 형태로 기록.
15. **권한별 수정 가능 필드**: 매니저는 회원구분(일반↔법인) 변경 불가. 슈퍼관리자만 모든 필드 수정 가능. FC/트레이너는 메모·운동목적 외 수정 불가.
16. **동시성 제어**: 수정 모드에서 회원의 `version` 컬럼 기반 optimistic lock. 다른 운영자가 동시 수정한 경우 409 Conflict로 재시도 요구.
17. **출석번호 변경 정책**: 한번 발급된 출석번호는 변경 불가(이력 추적). 변경 필요 시 슈퍼관리자만 사유 입력 후 가능.
18. **개인정보 입력 최소화**: 미입력 가능 필드(이메일/주소/회사명 등)는 강제하지 않음. PII 최소수집 원칙 준수.
