## 기능 목적

회원을 현재 소속 지점에서 다른 지점으로 이관하는 화면(SCR-M005)이다. 이관 전 미납금·락커·홀딩·PT 잔여·쿠폰·마일리지 6종 체크리스트를 자동 점검하여 차단(block) / 주의(warn) / 안내(info) 등급으로 결과를 표시하고, 이관 유형 3종(잔여 이용권 유지 / 환불 후 신규 / 소진 후 이관)을 선택해 최종 이관을 실행한다. 이관은 되돌릴 수 없는 작업이며 회원의 소속·담당자·정산 흐름 전체에 영향을 미치므로, 사전 검증과 명시적 확인 단계를 거친다.

운영 맥락:
- **회원 거주지 이전 / 직장 이동에 따른 자발적 이관**: 잔여 이용권 유지 유형 선택, 새 지점에서 그대로 사용 (가장 많은 케이스)
- **회원 본인 환불 후 신규 시작 요청**: 기존 이용권 환불 → 새 지점에서 신규 결제 (회원·지점 모두 깔끔한 정산)
- **회원이 잔여 횟수 다 쓰고 이관 결정**: 소진 후 이관 — 만료일까지 현재 지점 사용, 만료 후 새 지점에서 신규 시작
- **본사 가맹점 정책 변경에 따른 일괄 이관**: 폐점·합병 시 슈퍼관리자가 다수 회원 이관 (CSV 일괄 미지원, 1명씩 진행)
- **가족 회원 동반 이관**: 가족 연결 회원 중 1명 이관 시 가족 그룹은 자동 분리되지 않으며 별도 조정 필요
- **본사 통합 모드 진입**: 회원의 실제 `branchId` 기준으로 원 지점 확정, 통합 모드에서도 이관 가능

## 주요 구성요소

### 대상 회원 정보 표시

이관 대상 회원의 이름, 연락처, 현재 지점, 상태, 이용권 종류, 만료일.

| 홀딩 진행 중 | warn | 확인 후 진행 가능 |

| 마일리지 | info | 테넌트 전체 공유 (이관 후 유지) |

| 항목 | 입력 |

## 운영 시나리오 (페르소나 × 트리거 × 결과)

| 페르소나 | 사용 맥락 | 행동 | 기대 결과 |
|---|---|---|---|
| 센터장 (owner) | 회원 거주지 이전 요청 | 잔여 유지 유형 선택 → 사유 "거주지 이전" → 실행 | 새 지점에서 잔여 횟수 그대로 사용, 정산은 이관 시점에 양 지점 분배 |
| 센터장 | 회원 본인 환불 + 신규 결제 요청 | 환불 후 신규 유형 선택 → 환불 처리(DLG-M013) 자동 진입 | 기존 이용권 환불 + 새 지점에서 신규 결제 흐름 |
| 본사 슈퍼관리자 | 가맹점 폐점에 따른 다수 회원 이관 | 1명씩 순차 처리 (CSV 일괄 미지원) | 회원 동의 받은 인원만 이관, 미동의자는 환불 후 탈퇴 |
| 매니저 | 회원 양도 / 가족 분리 후 이관 | 양도 처리 후 양수자 회원에 대해 이관 진행 | 양도 + 이관 2단계 처리, 감사 로그에 양도 → 이관 순차 기록 |
| FC | 담당 회원 이관 시 후속 인계 | 이관 완료 후 새 지점 담당 FC에게 인수인계 메모 | 새 지점 FC에게 알림 push (NFR-19) + 상담메모 자동 이전 |

## 주요 UX 흐름

### 정상 이관 흐름
1. SCR-M001 행별 [이관] 또는 단일 선택 [지점이관] 또는 SCR-M004 헤더 [지점이관]
2. SCR-M005 진입 → 대상 회원 정보 + 6종 체크리스트 자동 점검 (병렬 호출)
3. block 항목 있으면 "해결 후 진행" 안내 (실행 버튼 비활성), warn은 확인 후 진행 가능
4. 이관 지점 드롭다운 (현재 지점 제외, 슈퍼관리자=전 지점, 센터장=소속 브랜드 지점)
5. 이관 유형 선택 (잔여 유지 / 환불 후 신규 / 소진 후 이관)
6. 사유 입력 (10자 이상 권장, 감사 로그 필수 필드)
7. [이관 실행] → DLG-M023 확인 모달 → 회원명 입력 일치 시 활성
8. 최종 확인 → 처리 (트랜잭션 시작) → 처리 완료 토스트 → SCR-M001 복귀

### 분기·예외 흐름
- **block 항목 발생 시**: 미납금 → SCR-S004 미수금 정산 화면 진입 안내, 락커 → MBR-02 락커 회수 안내, 실행 버튼 영구 비활성
- **warn 항목 발생 시**: 홀딩 중 → "이관 시 홀딩 자동 해제됩니다" 사전 경고, PT 잔여 → "유형 선택에 따라 처리 방식이 달라집니다" 안내
- **이관 유형 = 환불 후 신규**: 실행 시 환불 처리(DLG-M013)가 자동 호출되며 환불 완료 후 이관 트랜잭션 진행 (2단계 트랜잭션, 환불 실패 시 이관 전체 롤백)
- **이관 유형 = 소진 후 이관**: 즉시 이관하지 않고 만료 예약 등록 → 만료 도래 시 배치(NFR-05)가 자동 이관 실행
- **이관 유형 = 잔여 유지 + 정산 분배**: 잔여 가치 = 잔여 횟수 × 단가, 양 지점 회계 분배 처리 (본사 정산 정책에 따라)
- **이관 직전 회원 상태 변경**: 다른 운영자가 동시에 탈퇴/홀딩 처리한 경우 stale 데이터 → 409 Conflict 모달
- **쿠폰 지점 한정 손실**: info 알림에 "쿠폰 N건 소멸 예정" 명시, 회원에게 사전 동의 필수
- **마일리지 처리**: 테넌트 전체 공유이므로 이관 후 그대로 유지, info 알림에 명시
- **가족 회원 이관**: 가족 그룹 자동 분리 안 됨, "가족 그룹은 유지됩니다" 안내 + 필요 시 가족 회원 화면(MBR-EXT-02)에서 별도 조정
- **이관 처리 도중 네트워크 끊김**: 트랜잭션 롤백 + 운영자에게 "이관이 완료되지 않았습니다" 토스트 + 자동 재시도 1회
- **이관 후 새 지점 정원 초과**: 본사 정책에 따라 정원 제한이 있는 지점은 이관 차단 (실행 시 422)

## 비즈니스 규칙

1. 미납금이 있거나 락커를 보유한 경우 이관이 차단된다 (block). 락커는 회원이 락커 키 반납 + 시스템에서 락커 해제 처리 후 이관 가능.
2. 홀딩 중이거나 PT 잔여 횟수가 있어도 이관 자체는 가능하지만 담당자가 확인 후 진행한다 (warn). 홀딩 중 이관 시 홀딩 자동 해제 + 만료일 즉시 적용.
3. 쿠폰은 지점 한정인 경우 이관 시 소멸될 수 있음을 사전에 안내한다. 회원 동의 없는 소멸은 클레임 사유가 되므로 사유에 명시 필수.
4. 마일리지는 테넌트 전체 공유이므로 이관 후에도 그대로 유지된다. 단, 본사 정책 세트에서 별도 정의 시 마일리지 분배 가능.
5. 이관 실행은 되돌릴 수 없다. 잘못된 이관은 새 지점에서 재이관(원 지점으로 복귀) 처리해야 하며, 이때도 새 트랜잭션으로 기록.
6. 본사 통합 모드에서 이관하더라도 원 지점은 회원의 실제 소속 지점(`members.branchId`)으로 기록한다. 화면 컨텍스트 지점이 아닌 데이터 기준.
7. 현재 소속 지점과 동일한 지점으로는 이관할 수 없다. 드롭다운에서 자동 제외 + API에서도 422 거부.
8. 이관 사유는 감사 로그(SCR-097)에 기록된다. 사유 10자 미만 시 경고, 50자 이상 권장.
9. **이관 유형별 처리**:
   - **잔여 유지**: 이용권 잔여 횟수·기간 그대로 새 지점 사용. 회계 정산은 본사 정산 정책에 따라 양 지점 분배.
   - **환불 후 신규**: 환불 처리(DLG-M013) 자동 호출 → 환불 성공 → 새 지점 신규 결제 안내 (이관 자체는 회원 정보만 이전).
   - **소진 후 이관**: 즉시 이관 안 함, 만료 예약 등록. 만료 도래 시 배치(NFR-05)가 자동 이관 트리거.
10. **이관 권한**: 슈퍼관리자(전 지점), 센터장(소속 브랜드 지점), 그 외 권한 차단. 매니저/FC/스태프 모두 이관 불가.
11. **이관 후 자동 효과**: 회원 `branchId` 변경, 담당 FC/트레이너 자동 해제(새 지점에서 재배정 필수), 알림센터에 양 지점 운영자 push.
12. **새 지점 정원 제한**: 본사 정책에서 지점 정원이 정의된 경우, 정원 초과 지점으로의 이관은 차단(422).
13. **이관 트랜잭션 원자성**: 회원 정보 변경 + 정산 분배 + 락커/홀딩 해제 + 알림 발송이 단일 트랜잭션. 1개 실패 시 전체 롤백.
14. **결제이력·출석이력은 이전 안 함**: 모든 이력 데이터는 그대로 유지되어 새 지점에서도 조회 가능. `branchId`는 데이터 행의 발생 시점 지점 그대로 보존.
15. **상담메모 / 운동프로그램 / 종합평가 이전**: 회원에 종속된 데이터는 그대로 따라감. 단, 새 지점 담당자에게 인수인계 알림 발송.
16. **가족 그룹 미분리**: 가족 회원 1명만 이관해도 그룹은 유지. 분리 필요 시 MBR-EXT-02에서 별도 처리.
17. **이관 사유 카테고리화** (선택): 거주지 이전 / 직장 이동 / 가맹점 폐점 / 본사 정책 / 기타 — BI 분석용 코드값.
18. **DLG-M023 회원명 입력 일치**: 최종 확인 모달에서 회원명 정확 입력해야 [실행] 활성. 오타 방지.
19. **동시성 제어**: 이관 트랜잭션은 회원 row에 대해 PostgreSQL `SELECT FOR UPDATE` lock. 동시 이관 시도 시 후행 요청 대기 후 stale 검증.
20. **본사 정산**: 이관 시점의 잔여 가치(잔여 횟수 × 단가)는 본사 정산 정책 세트의 분배 비율에 따라 양 지점 회계 처리.

| PT 잔여 (warn) | 노랑 박스 + 유형별 처리 방식 안내 | 진행 가능 |
| 쿠폰 지점 한정 (info) | 파랑 박스 + "N건 소멸 예정" 명시 | 회원 동의 + 사유 명시 |
| 마일리지 보유 (info) | 파랑 박스 + "이관 후 유지" 안내 | - |
| 동일 지점 선택 시도 | 드롭다운 자동 제외, API 422 | UI에서 미노출 |
| 새 지점 정원 초과 | "선택 지점이 정원에 도달했어요" 모달 | 다른 지점 선택 안내 |
| 환불 후 신규 — 환불 실패 | 외부 결제사 API 실패 → 트랜잭션 롤백 | "이관이 취소되었습니다" + 재시도 |
| 소진 후 이관 — 만료 도래 후 자동 처리 실패 | 배치 알림 + 운영자 수동 처리 안내 | NFR-05 배치 재시도 |
| 이관 도중 네트워크 끊김 | 트랜잭션 롤백 + 자동 재시도 1회 | 사용자에게 명시적 안내 |
| 권한 부족 진입 | 접근 제한 화면 | 대시보드로 이동 |
| 동시 이관 시도 (lock 대기) | "잠시 후 다시 시도해주세요" | 재시도 |
| stale 데이터 (다른 운영자 동시 처리) | 409 Conflict 모달 | 새로고침 후 재시도 |
| 사유 10자 미만 입력 | "사유를 10자 이상 입력해주세요" | 진행 가능하나 경고 |
| DLG-M023 회원명 오타 | 빨강 강조 + [실행] 비활성 | 정확 입력 시 활성 |
| 가족 회원 이관 시 그룹 영향 | 안내 모달 "가족 그룹은 유지됩니다" | 진행 가능 |
