## 기능 목적

특정 회원의 모든 정보를 하나의 화면에서 15개 탭(회원정보/이용권/출석이력/결제이력/결제내역/예약내역/상세내역/체성분/상담메모/레슨/신체정보/종합평가/상담이력/운동프로그램/운동이력)으로 구분해 조회·관리하는 회원관리 도메인의 중심 화면이다. 프로필 헤더에 핵심 요약과 6개 액션(수동출석/수정/구매/메시지/이관/탈퇴)을 고정 노출하며, 만료 정책 결과·홀딩·탈퇴·삭제·복구·정지·복원까지 회원의 전체 라이프사이클을 단일 페이지에서 관리한다. 본사 정책 세트 기반 만료 알림 배너가 상태 배너보다 우선 노출되어 운영자가 즉시 액션을 취할 수 있다.

운영 맥락:
- **FC가 D-7 만료 임박 회원에게 리텐션 상담 시**: 만료 배너 + 결제이력 탭 + 상담이력 탭 + 메시지 액션을 한 화면에서 수행
- **매니저가 회원 클레임 응대 시**: 결제내역(미수·환불·링크 상태) + 출석이력 + 상담메모를 즉시 조회해 사실관계 파악
- **트레이너가 PT 세션 시작 전**: 체성분 추이 + 종합평가 + 운동프로그램 + 운동이력 탭으로 회원 컨디션 종합 판단
- **센터장이 환불 / 양도 / 이관 결재 시**: 헤더 액션 + 상세내역(홀딩·연장·양도·쿠폰·마일리지) 5서브탭으로 결재 근거 확인
- **본사 최고관리자가 정책 위반 의심 회원 감사 시**: SCR-097 히스토리 로그 진입 직전 회원 상세에서 모든 변경 이력의 단서를 종합
- **회원 본인 사망·중대 사고 시**: 탈퇴 처리 → 회원 데이터 보존 + PII 마스킹(X11) 90일 카운트 시작

### 만료 알림 배너 (조건부)

본사 정책 세트의 step 결과가 있는 경우 상단 표시. 강조 색상은 지점 적용 정책의 긴급도 기준 (D-14 info / D-7 warning / D-1 danger).

### 추가 액션

- **홀딩 처리** (DLG-M003/M004) — 기간/사유 입력, 만료일 자동 연장
- **탈퇴 처리** (DLG-M005) — 사유 입력, status=WITHDRAWN
- **회원 삭제** — 회원명 직접 입력 2차 확인 (소프트 삭제)
- **회원 복구** — 삭제·탈퇴 회원 헤더 [복구] (DLG-M005 역연계)

## 주요 UX 흐름

### 정상 진입 흐름
1. SCR-M001 회원 목록 → 회원명 클릭 → SCR-M004 진입 (URL: `/members/:id`)
2. 헤더 프로필 요약 + 만료/홀딩/정지 배너 + 6액션 즉시 노출
3. 15개 탭 중 사용 맥락에 맞는 탭 클릭으로 상세 정보 확인 (탭 전환은 deep link 지원)
4. 헤더 액션 또는 탭 내부 액션으로 작업 수행

### 분기·예외 흐름
- **만료 D-day 회원 진입**: 빨강 배너 강조 + [상품구매] 버튼 강조 색상 변경, 수동출석·이관 비활성
- **홀딩 중 회원 진입**: 보라색 배너 + 홀딩 기간/사유 표시 + [홀딩 해제(DLG-M004)] 버튼, 일부 액션 차단
- **정지 회원 진입**: 주황 배너 + 사유 표시, 권한자에게만 [정지 해제] 버튼 노출
- **탈퇴/삭제 회원 진입**: 회색 배너 + 읽기 전용, 권한자에게만 [복구(DLG-M005 역연계)] 버튼
- **삭제 90일 경과 회원**: PII 자동 마스킹, 본사 권한자 외 이름·연락처 비식별
- **회원 정보 동시 수정 충돌**: optimistic lock(`version`) 위반 시 409 → "다른 운영자가 동시에 수정했어요" 모달 + 새로고침 안내
- **15개 탭 중 일부 데이터 로드 실패**: 해당 탭만 에러 상태(나머지 탭은 정상), 탭 진입 시 [다시 시도] 버튼
- **결제이력 탭 — 결제링크 만료**: 권한자에게 [재발송] 버튼 + 만료 사유 (24시간 경과/취소)
- **레슨 탭 — 모바일 서명 미완료**: in_progress 상태 표시 + 회원에게 서명 요청 푸시 재발송 버튼
- **체성분 탭 — 측정 0건**: "측정 기록이 없어요" + DLG-M015 진입 CTA
- **상담이력 탭 — 수정 시**: 변경 후 메시지에 `상담 이력 수정됨` 자동 prefix 추가하여 히스토리 로그 INSERT
- **위험 구역 — 회원 삭제**: 회원명 직접 입력 2차 확인 + 권한 검증 + 소프트 삭제(즉시 hard delete 아님)
- **위험 구역 — 회원 복구 시 동명이인 충돌**: 동일 연락처 신규 회원 존재 시 회원 병합(MBR-EXT-01) 진입 권유

## 비즈니스 규칙

1. 만료 알림 배너는 본사 정책 세트 결과가 있는 경우에만 표시한다. 배너 우선순위: 만료 D-1 (danger) > 정지 (suspended) > 홀딩 (holding) > 만료 D-7 (warning) > 만료 D-14 (info).
2. 홀딩 처리 시 만료일이 홀딩 일수만큼 자동 연장된다. 홀딩 기간 중 출석·이용권 사용은 차단되며, 결제·예약은 가능.
3. 홀딩 중복 등록 차단: 활성 홀딩이 1건 이상이면 새 홀딩 등록 불가. 기존 홀딩 해제 후 등록 가능.
4. 탈퇴는 status=WITHDRAWN으로 변경하며 데이터는 보존된다. 미수금·미사용 이용권은 환불 정산 후 탈퇴 처리(미정산 시 경고).
5. 삭제는 논리적 삭제(soft delete)이며 회원 목록에서 보이지 않는다. hard delete는 본사 슈퍼관리자만 수행 가능하며 백업 후 처리.
6. 회원 복구는 센터장·매니저·슈퍼관리자에 한정한다 (DLG-M005 역연계). 동일 연락처 신규 회원 존재 시 회원 병합(MBR-EXT-01) 권유.
7. 레슨 탭 데이터는 모바일 레슨 완료/서명과 동일 레코드를 공유한다. 서명 없으면 `in_progress`, 있으면 `completed`.
8. 상담 이력은 Supabase `consultations`의 `memberId`/`branchId`/`scheduledAt`/`completedAt`/`channel` 기준 저장. 수정 시 히스토리 로그에 `상담 이력 수정됨` 문구 필수.
9. 회원 정보 수정 이력은 모두 히스토리 로그(SCR-097)에 기록된다. 변경 필드별 before/after + actor + reason 저장.
10. **권한별 가시성**: FC는 결제내역 탭 조회만 가능(수정 불가), 스태프는 결제내역 탭 hidden, readonly는 모든 탭 조회만.
11. **이관 후 즉시 효과**: 지점 이관 완료 시 현재 헤더에서 즉시 사라지고, 통합 모드 운영자는 새 지점 컨텍스트로 재진입.
12. **체성분 탭 = MBR-ADV-03 동일 데이터**: 회원 상세 체성분 탭과 SCR-M006 체성분 관리는 동일 데이터 소스(`body_composition`)를 공유.
13. **거래 귀속 우선 원칙**: 회원 헤더의 기본 귀속값은 기본값이며, 결제이력·결제내역·수업·환불 화면은 각 레코드의 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId`를 우선 표시한다.
14. **예외 회원권 표시**: 법인 회원권, 홈&오피스, 주말 이용권, 통합 회원권은 이용권 카드에 운영 정책 배지와 이용 가능 지점 요약을 함께 노출한다.
15. **결제내역 탭 통합 표시**: POS·결제링크·수기 입력 모든 결제 채널이 하나의 타임라인에 노출. 미수금은 누적 합산.
16. **결제링크 재발송 권한**: 본사 슈퍼관리자/센터장/매니저/FC만 재발송 가능. 발송 횟수 제한 일 3회.
17. **위험 구역 — 회원 삭제 2차 검증**: 회원명 직접 입력 + 사유 입력 + [삭제] 버튼 5초 카운트다운 후 활성화.
18. **이관 가능 조건**: 만료/정지 회원은 이관 차단 (SCR-M005 화면 상태 규칙과 동일). 미수금·락커 보유 시 차단(MBR-ADV-02 비즈룰).
19. **메시지 발송 채널 fallback**: 카카오 알림톡 실패 시 SMS 자동 fallback (NFR-19 정책).
20. **15개 탭 lazy loading**: 회원 정보 탭만 즉시 로드, 나머지는 탭 클릭 시 lazy fetch (네트워크 트래픽 최적화).
21. **PII 마스킹 시점**: 탈퇴/삭제 후 90일 경과 시 X11 배치가 이름·연락처·이메일을 마스킹. 본사 권한자가 사유 입력 시 일시 해제.
22. **레슨/상담/메모 작성자 권한**: 작성자 본인 + 상위 권한자만 수정·삭제 가능. FC가 작성한 상담은 매니저+가 수정 가능.
23. **헤더 액션 활성 조건**: 만료 회원 → 수동출석/이관 비활성, 홀딩 회원 → 수동출석 비활성, 정지 회원 → 모든 액션 비활성(권한자만 정지 해제).
24. **동시성 제어**: 회원 정보 수정·홀딩 등록·탈퇴 처리는 모두 optimistic lock(`version`). 동시 처리 시 후행 요청 409 거부.
25. **이용권 탭 — 잔여 횟수 0건 + 만료**: PT 0회 + 이용권 만료 동시 발생 시 "재계약 또는 이관 권유" CTA 강조.
26. **종합평가(DLG-M024) 입력 주기**: 분기당 최소 1회 권장. 미입력 회원은 세그먼트 "관심 필요" 자동 라벨.

## 예외 / 에러 처리

| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| 회원 ID 잘못된 URL | "회원을 찾을 수 없습니다" + 목록으로 이동 | 자동 redirect (3초) |
| 회원 삭제됨 / 권한 부족 | 접근 제한 화면 | 대시보드로 이동 |
| 만료 D-day 진입 시 | 빨강 배너 강조 + 상품구매 강조 | 재계약 유도 |
| 홀딩 처리 시 미수금 존재 | "미수금이 있어요. 정산 후 홀딩하세요" | 결제 화면 진입 안내 |
| 탈퇴 처리 시 미수금/이용권 잔여 | 경고 모달 + 강제 탈퇴/정산 후 탈퇴 선택 | 권한자만 강제 탈퇴 가능 |
| 삭제 시 회원명 입력 불일치 | "회원명이 일치하지 않아요" | 삭제 차단 |
| 삭제 권한 부족 | 위험 구역 자체 hidden | - |
| 결제링크 재발송 일 한도 초과 | "오늘 발송 한도(3회)를 초과했어요" | 내일 재시도 안내 |
| 레슨 서명 푸시 발송 실패 | "푸시 발송 실패. SMS로 재시도할까요?" | SMS fallback 옵션 |
| 상담이력 수정 권한 부족 | "본인 작성 상담만 수정 가능" | 수정 차단 |
| 동시 편집 충돌 (409) | "다른 운영자가 동시에 편집했어요" | 새로고침 후 재시도 |
| 탭 데이터 로드 실패 | 해당 탭에만 에러 + [다시 시도] | 다른 탭은 정상 |
| 환불 처리 시 결제 채널 외부 API 실패 | "결제사 API 응답이 없어요" + 재시도 | 트랜잭션 롤백 + 운영자 알림 |
| 본사 통합 모드 + 이관 차단 회원 | [지점이관] 버튼 비활성 + 사유 툴팁 | "미수금/락커/만료 상태" 안내 |
| 만료 90일 경과 + PII 마스킹 회원 | 이름·연락처 마스킹 표시 (***) | 본사 권한자 사유 입력 시 일시 해제 |
| 정지 해제 권한 부족 | 버튼 hidden | - |
| 종합평가 입력 시 5카테고리 미완 | "5개 카테고리 모두 입력해주세요" | 저장 차단 |
| 양도 처리 시 양수자 미선택 | "양수자를 선택해주세요" | 저장 차단 |
| 운동프로그램 배정 시 트레이너 매칭 실패 | "지점 내 트레이너가 없어요" | 트레이너 등록 안내 |
