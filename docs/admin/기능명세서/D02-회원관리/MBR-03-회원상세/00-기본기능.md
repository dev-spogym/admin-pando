## 기능 목적

특정 회원의 모든 정보를 하나의 화면에서 15개 탭(회원정보/이용권/출석이력/결제이력/결제내역/예약내역/상세내역/체성분/상담메모/레슨/신체정보/종합평가/상담이력/운동프로그램/운동이력)으로 구분해 조회·관리한다. 프로필 헤더에 핵심 요약과 6개 액션(수동출석/수정/구매/메시지/이관/탈퇴)을 고정 노출하며, 만료 정책 결과·홀딩·탈퇴·삭제·복구도 한 화면에서 처리한다. 본사 정책 세트 기반 만료 알림 배너가 우선 노출된다.

## 주요 구성요소

### 프로필 헤더 (고정)

| 표시 | 설명 |
|------|------|
| 이름 / 등급 배지 / 상태 | 활성/만료/홀딩/탈퇴 |
| 만료일까지 남은 일수 | D-day |
| 연락처 / 이메일 | 010 자동 포맷 |
| 마일리지 / 미수금 | 잔액 |
| 계약 건수 / 락커 정보 | - |

### 만료 알림 배너 (조건부)

본사 정책 세트의 step 결과가 있는 경우 상단 표시. 강조 색상은 지점 적용 정책의 긴급도 기준 (D-14 info / D-7 warning / D-1 danger).

### 헤더 6액션 버튼

| 버튼 | 동작 | 권한 |
|------|------|------|
| 수동출석 | DLG-M022 | staff+ |
| 수정 | SCR-M003 진입 | manager+ |
| 상품구매 | SCR-S003 진입 | staff+ |
| 메시지 | SCR-071 진입 | fc+ |
| 지점이관 | SCR-M005 진입 | owner+ |
| 탈퇴 | DLG-M005 | manager+ |

### 15개 탭

| 번호 | 탭명 | 핵심 내용 |
|------|------|----------|
| 1 | 회원정보 | 인적사항/가입일/이용권 기간/운영 정보/특이사항/메모 |
| 2 | 이용권 | 보유 계약 카드 + [신규 이용권 / 상품 구매] |
| 3 | 출석이력 | 6개월 히트맵 + 최근 20회 체크인 |
| 4 | 결제이력 | 간략 목록 + 결제 상세 팝업 + 환불 진입 |
| 5 | 결제내역 | 누적 요약 카드 + 정가/판매/할인/미수 컬럼 |
| 6 | 예약내역 | 월 캘린더 + 테이블 + SHOW/NOSHOW/미처리 |
| 7 | 상세내역 | 홀딩/연장/양도/쿠폰/마일리지 5서브탭 |
| 8 | 체성분 | 라인 차트 + 측정 추가 (DLG-M015) |
| 9 | 상담메모 | 카테고리별 자유 메모 (DLG-M009/M010) |
| 10 | 레슨 | PT/GX 기록 + 모바일 서명 동기화 |
| 11 | 신체정보 | 키/몸무게/혈압/심박 + 추이 차트 |
| 12 | 종합평가 | 5카테고리 1~10점 (DLG-M024) |
| 13 | 상담이력 | 일정/결과/후속/전환율 (DLG-M011/M012) |
| 14 | 운동프로그램 | 배정/해제 (DLG-M025) |
| 15 | 운동이력 | 일별 종목/세트/횟수 (DLG-M026) |

### 추가 액션

- **홀딩 처리** (DLG-M003/M004) — 기간/사유 입력, 만료일 자동 연장
- **탈퇴 처리** (DLG-M005) — 사유 입력, status=WITHDRAWN
- **회원 삭제** — 회원명 직접 입력 2차 확인 (소프트 삭제)
- **회원 복구** — 삭제·탈퇴 회원 헤더 [복구] (DLG-M005 역연계)

## 주요 UX 흐름

1. SCR-M001 → 회원명 클릭 → SCR-M004 진입
2. 헤더 요약 + 6액션 즉시 사용
3. 15개 탭 클릭으로 상세 정보 확인
4. 홀딩/탈퇴/삭제/복구 처리
5. 만료 임박 회원의 경우 상단 배너 + 재등록 권유

## 화면 상태

| 상태 | 설명 |
|---|---|
| 정상 활성 | 모든 탭 + 헤더 액션 |
| 만료 D-day | 알림 배너 강조 |
| 홀딩 중 | 헤더 "홀딩" 칩 |
| 탈퇴/삭제 | 비활성 표시, 헤더 [복구] 버튼 |
| 권한 부족 | 일부 탭/액션 hidden |
| 로딩 | 탭 스켈레톤 |

## 비즈니스 규칙

1. 만료 알림 배너는 본사 정책 세트 결과가 있는 경우에만 표시한다.
2. 홀딩 처리 시 만료일이 홀딩 일수만큼 자동 연장된다.
3. 탈퇴는 status=WITHDRAWN으로 변경하며 데이터는 보존된다.
4. 삭제는 논리적 삭제(soft delete)이며 회원 목록에서 보이지 않는다.
5. 회원 복구는 센터장·매니저·슈퍼관리자에 한정한다 (DLG-M005 역연계).
6. 레슨 탭 데이터는 모바일 레슨 완료/서명과 동일 레코드를 공유한다.
7. 상담 이력은 Supabase `consultations`의 `memberId`/`branchId`/`scheduledAt`/`completedAt`/`channel` 기준 저장.
8. 회원 정보 수정 이력은 모두 히스토리 로그(SCR-097)에 기록된다.
