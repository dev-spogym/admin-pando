## 기능 목적

공통된 특성이나 행동 패턴을 가진 회원들을 그룹(세그먼트)으로 묶어 타겟 마케팅과 맞춤 관리에 활용하는 화면(SCR-M010)이다. "30일 이상 방문/출석이 없는 활성 회원", "본사/지점 만료 알림 step 대상 회원", "첫 정상 결제 완료일로부터 30일 이내 회원", "골드 등급 + 가족 그룹 보유" 등 다양한 조건 조합으로 세그먼트를 생성하고, 해당 그룹에 메시지 발송이나 혜택 제공 등의 액션을 연결한다.

자동 분류 세그먼트 7종(신규 / 만료후미등록 / 이탈위험 / 만료임박 / 관심필요 / 충성 / 활발)은 시스템이 자동 산출한다. `충성`을 제외한 자동 라벨은 우선순위 기반으로 회원당 기본 라벨 1개가 부여되며, `충성`은 조건을 만족하면 다른 자동 라벨과 함께 보조 라벨로 중복 표시될 수 있다. 운영자 정의 커스텀 세그먼트는 추가 라벨 형태로 제공된다.

운영 맥락:
- **매니저가 월말 캠페인 — 이탈 위험 회원에게 일괄 메시지**: "30일 방문/출석 없음 + 활성 + 회원 이용권 만료 step 대상" 세그먼트 → 메시지 발송
- **FC가 일일 콜 리스트 작성**: "오늘 만료" + "충성" 세그먼트 결합 → 우선 콜 대상
- **본사 슈퍼관리자가 분기 마케팅 캠페인**: "이번 분기 첫 결제 완료 + 첫 방문 X" 세그먼트 → 첫 방문 유도 혜택
- **센터장이 지점 KPI 분석**: "활발" 세그먼트 비율 추이 → 운영 효과 측정
- **자동 갱신 vs 수동 새로고침**: 매일 04:00 배치 자동 갱신, 운영자가 [지금 재계산] 버튼으로 즉시 재계산 가능
- **세그먼트 → 메시지 / 혜택 자동 연결**: 카드에서 [메시지 발송(SCR-071)] 또는 [이용권 혜택 적용(SCR-073)] 원클릭

세그먼트는 회원 검색 조건의 확장이자 마케팅 대상 정의 도구로 활용되며, 등급(MBR-EXT-03)·가족(MBR-EXT-02)·결제 이력·출석 패턴을 모두 조건으로 사용 가능하다.

## 주요 구성요소

### 세그먼트 목록

생성된 세그먼트를 카드 형태로 표시. 각 카드: 이름·설명·해당 회원 수·생성일·마지막 업데이트.

### 세그먼트 생성 + 조건 빌더

AND / OR 조합으로 여러 조건 추가:

| 조건 | 옵션 |
|------|------|
| 회원 상태 | 활성 / 홀딩 / 만료 / 미등록 |
| 최근 방문일 | 예: 30일 이상 방문/출석 없음 |
| 이용권 만료일 | HQ-09 `회원 이용권 만료` 본사 step 또는 지점 추가 step 대상 + 해당 지점 ON 상태 |
| 첫 결제일 | 예: 첫 정상 결제 완료일로부터 최근 30일 이내 |
| 성별 / 연령대 / 회원구분 / 유입경로 | - |
| 누적 결제 금액 범위 | min~max |

### 미리보기

조건 설정 중 [미리보기] → 현재 조건 해당 회원 수 + 샘플 명단.

### 자동 갱신 설정

매일 / 주간 / 월간 자동 재계산.

### 세그먼트 액션 연결

세그먼트 카드에서 [메시지 발송] / [이용권 혜택 적용] 버튼.

### 수정·삭제

기존 세그먼트의 조건/이름 변경, 삭제.

## 주요 UX 흐름

### 정상 세그먼트 생성 흐름
1. 사이드바 "회원관리 > 세그먼트 관리" 진입
2. 기존 세그먼트 목록 (카드 그리드) 확인 또는 [새 세그먼트 만들기]
3. 이름·설명 입력 (이름 필수, 30자 이내)
4. 조건 빌더 진입 — AND/OR 조합으로 다중 조건 추가
5. 조건 항목: 회원 상태 / 최근 방문일 / 이용권 만료일 / 등록일 / 성별·연령대·회원구분·유입경로 / 누적 결제 금액 / 등급(MBR-EXT-03) / 가족 그룹 / 세그먼트 라벨 (자동 7종)
6. [미리보기] → 현재 조건 해당 회원 수 + 샘플 명단 10명 표시 (실시간 쿼리)
7. 자동 갱신 주기 선택 (실시간 / 매일 / 주간 / 월간)
8. [저장] → 카드 그리드에 새 카드 추가 + 첫 번째 재계산 즉시 실행

### 액션 연결 흐름
1. 세그먼트 카드 → [메시지 발송] → SCR-071 진입, 대상자 자동 선택
2. 세그먼트 카드 → [이용권 혜택 적용] → SCR-073 쿠폰 발급 진입, 대상자 자동 선택
3. 세그먼트 카드 → [회원 목록으로 보기] → SCR-M001 + 세그먼트 필터 자동 적용

### 분기·예외 흐름
- **조건 빌더 — 충돌 조건**: "활성 + 탈퇴" 같은 모순 조합 시 미리보기 결과 0건 + 경고 안내
- **조건 변경 후 미리보기 안 한 채 저장**: "미리보기 없이 저장됩니다. 회원 수 미확정" 노랑 경고 → 진행 가능
- **저장 직후 재계산 시간 소요**: 회원 1만+ 시 백그라운드 처리 + 카드에 "계산 중" 라벨, 완료 시 알림
- **세그먼트 회원 수 0건**: 카드에 "0명" 표시 + [메시지 발송] 비활성
- **자동 7종 세그먼트는 수정·삭제 불가**: 시스템 정의, 운영자는 조회만 가능
- **자동 갱신 진행 중 동시 수정**: 갱신 완료 후 재시도 안내
- **자동 갱신 = 실시간 선택 시**: 회원 상태 변경 이벤트마다 즉시 재계산. 부하 큰 세그먼트는 권장 안 함 (경고)
- **세그먼트 삭제 시 의존 액션 처리**: 진행 중 메시지 발송 작업이 있으면 발송 완료까지 삭제 보류
- **세그먼트 라벨 변경 (기본 자동 라벨)**: 우선순위 기반 자동 결정, 운영자 수동 지정 불가. 단, `충성`은 조건을 만족하면 보조 라벨로 함께 노출
- **권한 부족**: FC는 메시지 발송만 가능, 트레이너/스태프는 화면 진입 차단
- **본사 통합 모드**: 전 지점 세그먼트 가능, 단 지점 한정 조건은 명시적으로 추가
- **샘플 명단 PII 마스킹**: 90일 경과 탈퇴 회원은 마스킹 표시 (X11)

## 비즈니스 규칙

1. 자동 7종 세그먼트는 시스템 정의이며 운영자는 조회만 가능하다. 운영자는 자동 7종의 조건·우선순위·라벨명을 수정하거나 삭제할 수 없다.
2. 자동 라벨 산출은 `기본 자동 라벨`과 `충성 보조 라벨`을 분리한다.
   - 기본 자동 라벨은 회원당 1개만 부여한다.
   - `충성`은 조건을 만족하면 기본 자동 라벨과 함께 보조 라벨로 중복 표시한다.
   - 다른 기본 자동 라벨 조건을 만족하지 않고 `충성` 조건만 만족하면 기본 자동 라벨도 `충성`으로 표시한다.
3. 기본 자동 라벨 우선순위는 `이탈위험 > 만료임박 > 신규 > 활발 > 관심필요 > 만료후미등록` 순서다. `충성`은 이 우선순위에서 제외하고 보조 라벨로 별도 판정한다.
4. 방문/출석 판정은 키오스크 입장, 수업 출석, PT/GX 참여, 수동 출석을 모두 포함한다. 동일 회원의 2시간 이내 중복 입장은 1회 방문으로 집계한다.
5. 7종 자동 세그먼트 정의:

| 라벨 | 판정 기준 | 추가 기준 |
|---|---|---|
| 신규 | 첫 정상 결제 완료일로부터 30일 이내 | 결제 없이 회원 등록은 불가하므로 등록일이 아니라 첫 결제 완료일을 기준으로 한다. |
| 만료후미등록 | 마지막 회원 이용권 만료일로부터 60일 경과 + 만료 후 재등록 결제 없음 | 회원 이용권 재등록 결제가 발생하면 제외한다. |
| 이탈위험 | 최근 30일 이상 방문/출석 없음 + 활성 상태 | 방문/출석 없음은 키오스크, 수업 출석, PT/GX 참여, 수동 출석 모두 없는 상태를 의미한다. |
| 만료임박 | HQ-09 `회원 이용권 만료` 본사 step 또는 지점 추가 step 중 해당 지점에서 ON인 만료 전 step 대상 | 기준일은 HQ-09 정책값 또는 지점 추가 step 값이며 고정 D-day를 문서에 박지 않는다. |
| 관심필요 | 최근 90일 이내 종합평가 기록이 없거나 상담 기록이 없는 회원 | 지속적인 관심이 필요한 회원을 놓치지 않기 위한 운영 라벨이다. 둘 중 하나라도 없으면 후보에 포함한다. |
| 충성 | 누적 결제 기간 12개월 이상 + 골드 이상 등급 | 누적 결제 기간은 결제된 이용권 기간 합산 기준이며 홀딩 기간은 제외한다. 지점 이관 시 이전 지점 이용기간도 포함한다. 다른 라벨과 중복 표시 가능하다. |
| 활발 | 최근 30일 이내 방문/출석 8회 이상 | 방문/출석 판정은 키오스크, 수업 출석, PT/GX 참여, 수동 출석 모두 포함하고 2시간 이내 중복 입장은 1회로 본다. |

6. 만료임박 기준일은 HQ-09 `회원 이용권 만료` 본사 step 또는 지점 추가 step 값을 따르며, 지점별 포함 여부는 SCR-072의 센터장(owner) ON/OFF 상태를 따른다.
4. 커스텀 세그먼트 기준 변경은 본사 슈퍼관리자·센터장만. 매니저는 생성·수정만, 삭제는 센터장+.
5. 세그먼트는 실시간 또는 자동 주기로 재계산. 자동 주기: 매일 04:00 / 주간 월요일 04:00 / 월간 1일 04:00.
6. 메시지 발송 액션은 SCR-071 / 혜택 적용은 SCR-073(쿠폰)/SCR-074(마일리지)와 연동.
7. 본사 통합 모드에서는 전 지점 세그먼트 생성 가능. 단 지점 한정 조건 (예: 특정 지점 락커 보유)은 명시적 추가 필요.
8. **조건 빌더 AND/OR 중첩**: 최대 3단계 중첩 ((A AND B) OR (C AND D)). 더 깊은 중첩은 UI 차단.
9. **조건 항목 13종**: 회원 상태 / 최근 방문일 / 이용권 만료일 / 등록일 / 성별 / 연령대 / 회원구분 / 유입경로 / 누적 결제 금액 / 등급(MBR-EXT-03) / 가족 그룹(MBR-EXT-02) / 자동 세그먼트 라벨 / 운동프로그램 보유.
10. **미리보기 결과**: 회원 수 + 샘플 10명 (이름·연락처·등급). 90일 경과 탈퇴 회원은 PII 마스킹.
11. **자동 갱신 = 실시간**: 회원 상태 변경 / 결제 / 출석 이벤트 발생 시 즉시 재계산. 부하 큰 세그먼트는 비권장 (경고).
12. **세그먼트 카드 정보**: 이름·설명·해당 회원 수·생성일·마지막 업데이트·자동 갱신 주기·생성자.
13. **세그먼트 회원 수 0건**: 카드에 "0명" 표시 + [메시지 발송] 비활성. 조건 변경 안내.
14. **메시지 발송 시 가족 묶음 옵션**: SCR-071에서 가족 그룹 1명만 발송 옵션 제공 (중복 방지).
15. **세그먼트 삭제 시 의존성**: 진행 중 메시지 발송 / 쿠폰 발급 작업이 있으면 완료까지 삭제 보류.
16. **세그먼트 이름 정책**: 1~30자, 동일 지점 내 중복 차단.
17. **세그먼트 권한별 가시성**:
    - 슈퍼관리자: 전 브랜드 세그먼트
    - 센터장: 소속 지점 세그먼트
    - 매니저: 소속 지점 세그먼트 (생성·수정·액션 실행, 삭제 불가)
    - FC: 소속 지점 세그먼트 조회 + 메시지 발송만
    - 트레이너 / 스태프: 화면 진입 차단
18. **자동 갱신 진행 상태 표시**: 카드에 "계산 중" / "최종 갱신 N분 전" 표시.
19. **샘플 명단 PII 마스킹**: 탈퇴/삭제 90일 경과 회원은 X11 정책에 따라 마스킹.
20. **감사 로그**: 세그먼트 생성·수정·삭제·액션 실행 SCR-097 INSERT.
21. **세그먼트 → 회원 목록 진입**: 카드 클릭 → SCR-M001 + 세그먼트 필터 자동 적용. 그 화면에서 추가 필터 결합 가능.
22. **자동 갱신 부하 제한**: 동일 세그먼트 1분 내 중복 재계산 요청 시 제한 (스로틀링).
23. **세그먼트 결과 캐시**: 자동 주기 = 매일/주간/월간 세그먼트는 결과 캐시 24시간. [지금 재계산] 버튼으로 강제 재계산.
24. **마케팅 동의 회원 필터링**: 메시지 발송 시 광고 동의(`marketing_agreed_at`) 회원만 자동 필터.
25. **세그먼트 import/export (선택)**: JSON 형태로 세그먼트 정의 export/import (현재 미구현, 후속 단계).
26. **회원 라벨 변경 시 알림 안 함**: 세그먼트 라벨은 시각적 분류일 뿐, 회원에게 알림 발송 안 함 (단 액션 트리거 시 알림 발송).

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `MBR-EXT-04`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-M010`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `해당 없음`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
