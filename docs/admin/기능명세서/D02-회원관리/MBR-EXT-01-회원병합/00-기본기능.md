## 기능 목적

동일인으로 판단되는 중복 회원 계정 두 개를 하나로 합치는 화면(SCR-M007)이다. 연락처 변경, 회원 재등록, 시스템 마이그레이션, 가맹점 합병 등의 사유로 같은 회원이 중복 등록된 경우, 양쪽 데이터를 하나의 주 계정으로 통합한다. 출석 이력·결제 이력·상담 메모·체성분 기록·이용권·마일리지·운동프로그램 등 모든 이력 데이터는 병합 후에도 유지되며, 부 계정은 즉시 삭제되지 않고 비활성 처리되어 일정 기간(90일) 동안 복구 가능 상태로 보존된다.

운영 맥락:
- **연락처 변경 후 재등록 회원**: 회원이 번호 분실로 새 번호로 다시 등록한 경우 → 이전 이력 + 신규 이력 통합
- **결제 시스템 마이그레이션 중복**: 구 시스템 → Pando 이전 시 동일 회원이 양쪽에 존재 → 하나로 통합
- **가맹점 합병 시 동일 회원 중복**: A지점 회원이 B지점에도 등록된 경우(가맹점 합병 케이스) → 합병 후 단일 계정으로 통합
- **본인 인증 실수로 신규 등록**: 매니저가 회원 본인을 못 알아보고 신규 등록한 경우 → 빠르게 병합으로 정리
- **무기명 법인 → 기명 법인 전환**: 법인 회원의 회원 정보가 명확해지면 무기명 → 기명으로 통합
- **본인 사망 / 가족 양도 후 정리**: 양도 처리된 이용권이 양수자 계정에 자동 합산되지 않아 운영자가 수동 병합

병합은 매우 민감한 작업으로 되돌리기 어렵기 때문에 "병합" 텍스트 입력 + 권한 검증 + 비교 화면 + 단계별 확인을 통해 실수를 방지한다.

## 주요 구성요소

### 중복 회원 검색

이름·연락처·생년월일로 중복이 의심되는 회원 검색.

### 주 계정 / 부 계정 지정

- **주 계정** = 병합 후 남길 계정
- **부 계정** = 병합 후 비활성될 계정

### 병합 전 정보 비교 화면

주 계정과 부 계정의 주요 정보(이름·연락처·이용권·등록일·최근 방문일)를 나란히 표시.

### 병합 항목 선택

이름, 연락처, 프로필 사진 등 일부 항목에서 어느 쪽 계정 값을 채택할지 선택.

### 병합 후 처리 안내

- 부 계정의 출석/결제/상담 메모/체성분 기록은 주 계정으로 이전
- 부 계정은 비활성 상태로 전환 (즉시 삭제 아님)

### 최종 확인 다이얼로그 (DLG-M028)

병합은 되돌리기 어려운 작업임을 명시하고 "병합" 입력 확인 후 처리.

## 주요 UX 흐름

### 정상 병합 흐름
1. 회원 목록 또는 회원 상세 메뉴 → "회원 병합" 진입 (또는 사이드바)
2. 중복 의심 회원 검색 (이름·연락처·생년월일 OR 매칭)
3. 검색 결과 카드에서 주 계정 선택 → 부 계정 선택 (동일 회원 동시 선택 불가)
4. 비교 화면: 두 계정 정보를 좌우로 나란히 표시 (이름·연락처·이용권·등록일·최근 방문일·마일리지·결제 누적·세그먼트)
5. 병합 항목 선택: 이름·연락처·프로필 사진 등에서 어느 쪽 값을 채택할지 라디오 선택
6. 병합 후 처리 안내 박스 (이력 이전 / 부 계정 비활성 / 되돌리기 어려움)
7. [병합] 버튼 클릭 → DLG-M028 최종 확인
8. "병합" 텍스트 입력 → [실행] 활성 → 트랜잭션 처리 → 주 계정 SCR-M004 진입

### 분기·예외 흐름
- **검색 결과 0건**: "검색 결과가 없습니다" + 검색 조건 확장 안내 (이름·연락처·생년월일 중 1개라도)
- **동일 회원 선택 시도**: 부 계정 선택 시 주 계정과 같으면 빨강 강조 + "다른 계정을 선택해주세요"
- **두 계정의 이용권 모두 활성**: 경고 박스 + "양 계정 모두 활성 이용권이 있어요. 잔여 횟수가 합산됩니다" 안내
- **두 계정의 결제 누적이 모두 큰 경우**: 등급 재산정 안내 (MBR-EXT-03 등급 갱신 트리거)
- **두 계정의 가족 그룹이 서로 다름**: 경고 박스 + "주 계정의 가족 그룹이 유지되며 부 계정의 가족 연결은 해제됩니다"
- **두 계정의 세그먼트 라벨이 다름**: D+1 배치에서 자동 재계산
- **부 계정에 미수금 존재**: 미수금이 주 계정으로 자동 이전 (회원 채무 보존)
- **부 계정에 환불 진행 중 결제 존재**: 환불 완료 전 병합 차단
- **부 계정에 진행 중 홀딩 / 정지 / 탈퇴**: 주 계정 상태로 통합 (주 계정 우선)
- **지점 간 병합**: 본사 권한자만 가능, 일반 센터장은 동일 지점 회원 간만 병합
- **병합 도중 한쪽 회원 탈퇴 처리됨 (동시성)**: 트랜잭션 롤백 + "회원 상태가 변경되었습니다" 모달
- **DLG-M028 텍스트 오타**: 빨강 강조 + [실행] 비활성, 정확 입력 시 활성
- **병합 성공 후 5분 이내 취소 가능 (선택)**: 별도 [최근 병합 취소] 메뉴 제공 (정책에 따라 활성)

## 화면 상태

| 상태 | 설명 |
|---|---|
| 초기 검색 | 두 계정 모두 미선택, 검색 안내 |
| 주 계정만 선택 | 부 계정 선택 대기 |
| 두 계정 모두 선택 | 비교 화면 + 병합 버튼 활성 |
| 처리 중 | 버튼 비활성 + 로딩 |
| 병합 완료 | 주 계정 상세 페이지 이동 |

## 비즈니스 규칙

1. 병합은 되돌릴 수 없는 작업이며 DLG-M028에서 "병합" 텍스트 입력 후 최종 확인 필수.
2. 부 계정의 모든 이력(출석·결제·상담메모·체성분·이용권·예약·운동프로그램·운동이력·종합평가·레슨)은 주 계정으로 이전. `member_id` 외래키 일괄 UPDATE.
3. 부 계정은 즉시 삭제되지 않고 비활성(`status=MERGED_INACTIVE`) 처리된다. 90일 보관 후 X11 PII 마스킹, 1년 후 hard delete (정책에 따라).
4. 동일 회원은 주/부 계정으로 동시 지정 불가. UI 차단 + API 422.
5. 지점 간 병합은 본사 슈퍼관리자만 가능. 일반 센터장은 동일 지점 회원 간만 병합 (RBAC 강화).
6. 처리 이력은 감사 로그(SCR-097)에 기록. `merged_at`, `primary_id`, `secondary_id`, `actor_id`, `field_choices[]` 저장.
7. **병합 항목 선택 정책**: 이름·연락처·프로필 사진·생년월일·이메일·주소는 주/부 중 선택, 그 외 필드는 주 계정 우선 (자동).
8. **이용권 통합**: 양 계정의 활성 이용권은 모두 주 계정으로 이전, 잔여 횟수·기간 합산. 동일 상품의 경우 합산, 다른 상품은 각각 유지.
9. **마일리지 합산**: 부 계정 마일리지는 주 계정에 더해짐. 만료된 마일리지는 이전하지 않음.
10. **결제 누적 합산**: 등급(MBR-EXT-03) 산정 기준이 되는 누적 결제 금액·이용 기간·방문 횟수는 합산 후 등급 재산정 트리거.
11. **세그먼트 재계산**: 병합 후 D+1 배치에서 주 계정 세그먼트 라벨 갱신.
12. **가족 그룹 처리**: 주 계정의 가족 그룹이 유지되며, 부 계정의 가족 연결은 해제. 부 계정이 다른 그룹의 대표였다면 그룹 자동 해체 + 운영자 알림.
13. **미수금·환불·홀딩 처리**:
   - 부 계정 미수금 → 주 계정으로 이전 (회원 채무 보존)
   - 부 계정에 환불 진행 중 결제 → 병합 차단 (환불 완료 후 재시도)
   - 부 계정 홀딩/정지/탈퇴 상태 → 주 계정 상태가 우선
14. **권한 정책**: 본사 슈퍼관리자(전 지점 + 지점 간), 센터장(소속 지점 내), 그 외 모든 권한 차단.
15. **DLG-M028 입력 일치**: "병합" 정확 입력 시에만 [실행] 활성. 한글/영문 구분 엄격.
16. **트랜잭션 원자성**: 회원 정보 통합 + 이력 외래키 UPDATE + 가족 분리 + 등급 재산정 트리거 + 알림 발송이 단일 트랜잭션. 1개 실패 시 전체 롤백.
17. **외래키 cascade 처리**: `consultations`, `payments`, `attendance`, `body_composition`, `classes`, `family_members`, `coupons`, `mileage` 등 모든 회원 관련 테이블의 `member_id`를 부 계정 → 주 계정으로 일괄 UPDATE.
18. **알림 발송**: 회원 본인에게 카카오 알림톡으로 "회원 정보가 통합되었어요" 발송 (양 계정 등록 연락처 모두 발송).
19. **검색 조건**: 이름 + 연락처 + 생년월일 OR 매칭. 최소 1개 조건 필요.
20. **중복 자동 추천 (선택)**: 시스템이 검출한 중복 의심 회원 리스트를 별도 화면에서 제공 가능 (현재 미구현, 후속 단계).
21. **병합 취소 정책**: 5분 이내에 한해 [최근 병합 취소] 가능 (정책에 따라 활성). 그 이후는 hard rollback 불가, 새 회원 등록으로 분리해야 함.
22. **본인 사망 / 미성년자 보호자 대리**: 사망 / 보호자 대리 케이스는 본사 슈퍼관리자만 처리, 사망확인서·동의서 등 증빙 첨부 (별도 시스템).
23. **PII 정합성**: 병합 후 부 계정의 이름·연락처는 주 계정으로 통합되거나 부 계정에 그대로 남아 PII 마스킹 정책(X11) 대상.
24. **감사 로그 상세도**: 병합 사유 / 선택한 필드 값 / 양 계정 ID / 통합 후 회원 ID / 운영자 / 시각 모두 기록.

## 예외 / 에러 처리

| 케이스 | 표시 | 후속 조치 |
|---|---|---|
| 검색 결과 0건 | "검색 결과가 없어요" + 조건 확장 안내 | 이름·연락처·생년월일 중 1개만 입력 권장 |
| 동일 회원 선택 시도 | 빨강 강조 + "다른 계정을 선택해주세요" | 부 계정 선택 차단 |
| 양 계정 활성 이용권 존재 | 노랑 경고 + 합산 안내 | 진행 가능 |
| 부 계정 환불 진행 중 | 빨강 박스 + "환불 완료 후 재시도" | 병합 차단 |
| 부 계정 홀딩/정지/탈퇴 | 노랑 경고 + 주 계정 상태 우선 안내 | 진행 가능 |
| 가족 그룹 충돌 | 노랑 경고 + 주 계정 그룹 유지 안내 | 진행 가능, 부 계정 그룹 자동 해체 |
| 부 계정이 가족 그룹 대표 | 빨강 경고 + "그룹이 해체됩니다" | 그룹 운영 정책 확인 후 진행 |
| 권한 부족 (지점 간 병합 시도) | 접근 제한 + "지점 간 병합은 본사 권한자만 가능" | 본사에 요청 안내 |
| 본사 통합 모드 미사용 + 지점 간 병합 시도 | 검색 결과에서 타 지점 회원 미노출 | UI에서 미노출 |
| 병합 도중 회원 상태 변경 (동시성) | 409 Conflict + 새로고침 안내 | 재시도 |
| DLG-M028 텍스트 오타 | 빨강 강조 + [실행] 비활성 | 정확 입력 안내 |
| 트랜잭션 도중 외래키 cascade 실패 | 전체 롤백 + 운영자 알림 | 재시도 또는 본사 문의 |
| 회원 알림톡 발송 실패 | 병합 자체는 성공, 알림 실패 토스트 | 운영자가 수동 안내 |
| 미성년자 / 사망 케이스 비권한자 시도 | 빨강 + "본사 권한자만 처리 가능" | 본사 문의 |
| 5분 경과 후 취소 시도 | "취소 가능 시간이 지났어요" | 새 회원 등록으로 분리 안내 |
| 네트워크 끊김 (저장 도중) | 트랜잭션 롤백 + 자동 재시도 1회 | 명시적 안내 |

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-M007`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-M028 회원병합확인`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 표와 아래 API 기준을 같이 적용합니다.

- **연계 화면**: SCR-M001 / SCR-M004 / SCR-M007 / SCR-097 / SCR-M008 가족 회원
- **연계 다이얼로그**: DLG-M028
- **API 기준**: `POST /api/members/merge` / `GET /api/members/duplicates` / `GET /api/members/merge/preview` / `POST /api/members/merge/cancel`
