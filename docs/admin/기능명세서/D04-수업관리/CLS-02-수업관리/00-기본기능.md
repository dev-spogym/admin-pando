## 기능 목적

등록된 수업 전체를 목록으로 조회하고 상태별로 필터링하는 화면이다. 개별 수업의 출석 현황을 확인하고 수업 정보를 수정하거나 취소 처리할 수 있다. 캘린더 뷰(SCR-C001)의 보조 화면으로, 목록 기반의 정밀한 수업 관리가 필요할 때 사용한다. 강습 세션은 KPI 집계를 위해 PT / 필라테스 / 스트레칭 / 테라피 세션 유형을 함께 표시한다.

정합성 메모: 드래그앤드롭 일정 이동, 시간 리사이즈, 캘린더 셀 충돌 검사는 CLS-01 수업 캘린더의 동작이다. CLS-02는 목록 기반 조회·등록·수정·취소·출석 처리 화면으로 정의한다.

운영 맥락:
- **매니저 일·주간 정산**: 완료 상태 필터로 특정 강사 수업의 출석·노쇼 카운트 확인 → 급여(SCR-064) 정산 자료.
- **트레이너 본인 수업 정정**: 출석 누락 발견 → 행 클릭 → DLG-C003에서 출석/노쇼 정정 + 사유 기록.
- **FC 회원 문의 대응**: 회원 이름 검색으로 예약 이력 추적 → 취소 사유·재예약 안내.
- **센터장 분쟁 대응**: DLG-C005 수업 기록 상세 + DLG-C006 서명 이미지 확인 → 회원 분쟁 증빙.
- **본사 KPI 검증**: 강습 세션 유형(4종) 필터로 KPI 원천 데이터 정합성 확인.
- **수업 일괄 취소(휴관일)**: 캘린더(SCR-C001) 일괄 변경과 별도로 행 단위 정밀 취소 + 사유 입력 → 회원 알림.
- **노쇼 자동 페널티 검증**: 노쇼 컬럼 카운트 vs 페널티 관리(SCR-C008) 일치 확인.

캘린더 vs 수업 관리 분리 원칙: 캘린더는 시각적 시간 운영, 수업 관리는 행 단위 정밀 관리·정정·기록 확인이 주된 역할이다.

## 주요 UX 흐름

**수업 조회 + 수정**
1. SCR-C001 → "수업 관리" 탭 또는 `/lessons` 직접 진입
2. 강사·장소·세션 유형 필터 + 상태 버튼(전체/예정/진행중/완료/취소)으로 좁히기
3. 수업 행 클릭 → DLG-C003 정보 확인·수정
4. 변경 시 강사·장소 충돌 검증 통과 → 저장 → 토스트 + 목록 갱신
5. 완료 행은 DLG-C005 + DLG-C006 서명으로 분기

**출석/노쇼 처리**
1. 행 → 출석 / 노쇼 버튼 클릭
2. 출석: PT 횟수 자동 차감(CLS-07) + 서명 요청 옵션(DLG-C006)
3. 노쇼: 자동 페널티 정책(CLS-08) 적용 + 회원 알림
4. 처리 결과 즉시 상태 배지 갱신

**수업 취소**
1. 행 → [취소] → 사유 입력 (필수) → 확인
2. 예약 회원 자동 알림 + PT 횟수 자동 복구
3. 결제 미완 수업이면 결제 환불 화면 안내

**완료 수업 기록 확인**
1. 완료 상태 행 클릭 → DLG-C005
2. 출석·서명·메모·QR 로그 확인 → 분쟁 증빙

### 분기 · 예외 · 롤백
- **이미 완료된 수업 수정 시도**: 정보 변경 차단, 출석 정정만 허용 (사유 필수)
- **취소 후 환불 미수행**: 결제 화면 자동 이동 안내 + 환불 처리 여부 체크
- **PT 횟수 차감 실패 (이용권 만료)**: 출석 처리는 수행 + 차감 실패 알림 → 운영자가 횟수 조정(CLS-07) 필요
- **트레이너가 타 강사 수업 수정 시도**: 행 클릭 시 DLG-C003은 read-only 모드
- **노쇼 처리 후 자동 페널티 발생 → 부당 노쇼 정정**: 출석으로 정정 시 자동 페널티 자동 해제 + 알림
- **동시 수정 충돌 (낙관적 락)**: "다른 사용자가 먼저 수정했어요" + 최신 값 다시 로드
- **취소 사유 미입력**: 인라인 에러 + 저장 차단

## 비즈니스 규칙

1. `수업 유형`은 화면 운영 분류이며, `강습 세션 유형`은 KPI 산출용 세부 분류이다.
2. 강습 세션 유형은 PT / 필라테스 / 스트레칭 / 테라피 4종으로 고정하며, 본사 KPI 대시보드의 강습세션수 집계 원천이다.
3. 수업 완료(출석) 시 회원의 PT 횟수가 자동 차감된다 (CLS-07 횟수 관리 연동, append-only 이력).
4. 수업 취소 시 회원에게 알림이 자동 발송되고 PT 횟수는 자동 복구된다.
5. **취소 사유 필수**: 모든 취소는 사유 텍스트(최소 5자) 입력 필수 + 감사 로그 기록.
6. 노쇼 처리는 자동 페널티 정책(CLS-08)에 따라 페널티가 부과될 수 있다.
7. **노쇼 → 출석 정정**: 정정 시 자동 페널티가 자동 해제되며 회원 알림 발송.
8. **출석 정정 권한**: manager+만 정정 가능, 트레이너는 본인 담당만 정정.
9. **서명 정책**: PT 수업 완료 시 회원 서명 필수 (테넌트 정책에 따라 GX는 선택). 미수령 시 노랑 배지.
10. 트레이너는 본인 담당 수업만 수정 가능하며 타 강사 수업은 read-only.
11. **상태 전이**: 예정 → 진행중(자동) → 완료(출석/노쇼 처리 시) → 취소는 모든 단계에서 가능하나 완료 후 취소는 운영자 권한.
12. **정원 검증**: 정원 변경 시 예약 인원 < 새 정원이면 차단 (대기열로 옮기거나 취소 후 변경).
13. **결제 환불 연동**: 결제 완료된 1회권 수업 취소 시 결제 환불 자동 안내 (SCR-S007).
14. **낙관적 락**: 수업 동시 수정 시 last-write-wins + 충돌 감지 시 최신 값 재로드.
15. **본사 통합 모드**: superAdmin/primary는 지점 컬럼 노출 + 전 지점 합산.
16. **엑셀 내보내기**: 현재 필터·검색 적용된 결과만 다운로드 (최대 10,000행).
17. **감사 로그**: 등록·수정·취소·출석/노쇼 처리·서명·정정 모두 SCR-097 기록 (actor·lesson_id·before·after).
18. **자동 진행중 전이**: 시작 시간 도달 + 출석 1건 이상 → 자동 "진행중", 예정 + 미처리는 종료 시간 경과 후 주황 강조.
19. **수업 기록 보관 기간**: DLG-C005 기록은 최소 5년 보관 (분쟁 대응).
20. **회원 마지막 방문일**: 출석 처리 시 회원의 last_visit_at 자동 갱신 (SCR-M004).

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `CLS-02`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-C002`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-C003 수업등록수정_관리, DLG-C005 수업기록상세, DLG-C006 서명`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
