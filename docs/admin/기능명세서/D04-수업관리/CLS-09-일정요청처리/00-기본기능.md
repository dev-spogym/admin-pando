## 기능 목적

회원이 회원앱에서 요청한 수업 변경·취소 요청을 관리자가 검토하고 수락 또는 거절하는 화면이다. 회원이 직접 수업을 취소하거나 다른 일정으로 변경하고 싶을 때 요청을 보내면, 센터 관리자가 이 화면에서 일괄 처리한다. 취소 요청에 대해서는 대안 일정을 제시해 회원 만족도와 매출을 모두 지킬 수 있다.

운영 맥락:
- **매니저 일일 미처리 요청 정리**: 출근 직후 대기 요청 일괄 처리 (수락/거절/대안 제시) → 회원 응답 시간 단축.
- **트레이너 본인 담당 요청 처리**: 본인 수업 변경 요청만 노출 → 직접 수락/거절.
- **취소 요청 → 대안 제시 (DLG-C016)**: 취소 대신 다른 시간·강사 제안 → 매출 보호 + 회원 만족.
- **노쇼/취소 정책 위반 거절**: DLG-C007 정책상 시작 2시간 전 이내 취소는 거절 + 페널티.
- **회원 분쟁 대응**: 처리자·처리일시 + 거절 사유 → 분쟁 증빙.
- **Today Tasks 미처리 알림**: SCR-098 Today Tasks(오늘의 할 일) 화면에 `일정 요청 미처리 N` 태스크를 표시해 누락을 방지.
- **회원앱 응답 동기화**: 회원이 대안 일정 수락/거절 → 자동 일정 변경 또는 취소.
- **변경 요청 → 충돌 검증**: 회원 희망 일시에 강사·장소 충돌 여부 자동 확인 + 알림.

## 주요 구성요소

### 요청 목록 테이블

| 컬럼 | 설명 |
|------|------|
| 요청 유형 | 변경 / 취소 배지. 변경=파랑, 취소=주황 |
| 회원명 | 클릭 시 SCR-M004 |
| 연락처 | 010 자동 |
| 원래 수업 | 수업명·일시·강사 |
| 요청 내용 | 변경: 희망 일시 / 취소: 사유 |
| 요청 일시 | YYYY-MM-DD HH:mm |
| 처리 상태 | 대기 / 수락 / 거절 / 대안제시 / 응답대기 / 만료 배지 |
| 액션 | [수락] / [거절] / [대안] |

### 필터

| 필터 | 설명 |
|------|------|
| 요청 유형 | 전체 / 변경 / 취소 |
| 처리 상태 | 전체 / 대기 / 처리 완료 |
| 기간 | 요청일 범위 |

### 수락 버튼

요청 수락 → 수업 일정 자동 변경(변경 요청) 또는 취소 처리(취소 요청) → 회원 알림 발송.

### 거절 버튼

거절 사유 입력 → 회원에게 거절 안내 알림 발송.

### 대안 일정 제시 (DLG-C016)

취소 요청 시 [대안 제시] 버튼으로 대안 일정 제안 다이얼로그.

| 항목 | 입력 |
|------|------|
| 대안 일시 | 캘린더 + 시간 (최대 3개) |
| 대안 강사 | 동일 또는 다른 강사 |
| 메시지 | 회원 안내 메시지 |

### 미처리 배지

SCR-C009 상단 탭 내비게이션과 SCR-098 Today Tasks(오늘의 할 일)에 미처리 요청 건수를 표시한다.

| 표시 위치 | 표시명 | 건수 기준 | 클릭 동작 |
|---|---|---|---|
| SCR-C009 상단 탭 | 미처리 `N` | 처리 상태가 `대기`, `응답대기`이고 요청 생성 후 24시간이 지나지 않은 건수 | SCR-C009 현재 화면에서 처리 상태=`대기/응답대기` 필터 적용 |
| SCR-098 Today Tasks | 일정 요청 미처리 `N` | 처리 상태가 `대기`, `응답대기`, 또는 24시간 초과 미처리인 전체 건수 | `/schedule-requests?status=pending`으로 이동, 기본 필터 `대기/응답대기/24시간 초과` 적용 |
| SCR-098 Today Tasks 긴급 카드 | 일정 요청 SLA 초과 `N` | 요청 생성 후 24시간을 초과했으나 `수락/거절/만료`가 아닌 건수 | `/schedule-requests?sla=overdue`로 이동, 24시간 초과 미처리 필터 적용 |

요청 유형 배지:

| 값 | 표시 |
|---|---|
| 변경 | 파랑 배지 |
| 취소 | 주황 배지 |

처리 상태 배지:

| 값 | 의미 | 표시 |
|---|---|---|
| 대기 | 운영자 검토 전 | 빨강 배지 |
| 수락 | 요청 수락 완료 | 초록 배지 |
| 거절 | 요청 거절 완료 | 회색 배지 |
| 대안제시 | 운영자가 대안 일정을 발송함 | 파랑 배지 |
| 응답대기 | 회원이 대안 일정에 아직 응답하지 않음 | 보라 배지 |
| 만료 | 24시간 응답 만료로 자동 취소됨 | 회색 배지 |

## 주요 UX 흐름

**일반 처리**
1. 사이드바 → "수업관리 > 일정 요청 처리" 진입
2. 대기 요청 필터로 미처리 우선 확인 + 미처리 건수 배지
3. 요청 내용 검토 (변경: 희망 일시 / 취소: 사유) → [수락] / [거절] / [대안]
4. **수락 (변경)**: 희망 일시 충돌 검증 → 통과 시 일정 자동 변경 → 회원 알림
5. **수락 (취소)**: 일정 취소 + PT 횟수 자동 복구 + 회원 알림
6. **거절**: 거절 사유 입력 (필수) → 회원 알림
7. 처리 완료 후 처리 상태·처리자·처리일시 기록

**대안 제시 (DLG-C016)**
1. 취소 요청 행 → [대안] → DLG-C016
2. 대안 일시 (최대 3개) + 대안 강사 + 안내 메시지 입력
3. 회원에게 발송 → 응답 대기 (회원앱 알림)
4. 회원 수락 시 자동 일정 변경, 거절 시 자동 취소 처리

### 분기 · 예외 · 롤백
- **변경 요청 희망 일시 충돌**: 강사·장소·회원 충돌 → 자동 거절 추천 + 사유 안내
- **트레이너 권한**: 본인 담당만 처리 가능, 타 강사 요청은 hidden
- **거절 사유 미입력**: 차단
- **수락 후 회원 결제 미수금**: 결제 화면 안내 + 처리 보류
- **대안 일정 회원 응답 만료 (24시간)**: 자동 취소 처리 + 알림
- **수락 후 일정 변경 도중 충돌**: 트랜잭션 롤백 + "다른 예약과 충돌이 발생했어요"
- **노쇼/취소 정책 위반 (DLG-C007)**: 자동 거절 추천 + 페널티 부과 옵션

## 화면 상태

| 상태 | 설명 |
|---|---|
| 대기 요청 있음 | 상단 건수 배지 + 빨강 강조 |
| 대기 요청 없음 | "처리할 요청이 없어요" |
| 처리 완료 목록 | 수락·거절 이력 + 처리자·시각 |
| 처리 중 | 행 액션 비활성 + 스피너 |
| 충돌 감지 | 빨강 강조 + 자동 거절 추천 |
| 정책 위반 (DLG-C007) | 노랑 경고 + 페널티 부과 옵션 |
| 대안 회원 응답 대기 | "회원 응답 대기 중" 배지 |
| 대안 회원 수락 | 자동 일정 변경 + 토스트 |
| 대안 만료 (24시간) | 자동 취소 + 회색 배지 |
| 트레이너 본인 외 | 카드 hidden |

## 비즈니스 규칙

1. 수락 시 수업 일정이 즉시 변경 또는 취소되며 강사 캘린더에 자동 반영된다.
2. 거절 시 거절 사유 입력은 필수이며 회원에게 알림이 발송된다.
3. 대안 일정 제시는 취소 요청에 한해 제공되며 회원이 수락·거절을 선택할 수 있다.
4. 트레이너는 본인 담당 수업 요청만 처리할 수 있다.
5. 수업 시작 전 변경/취소 가능 시간은 노쇼/취소 정책(DLG-C007)을 따른다.
6. 처리 결과는 감사 로그(SCR-097)에 기록된다.
7. **변경 요청 충돌 검증**: 희망 일시에 강사·장소·회원 충돌 시 자동 거절 추천.
8. **거절 사유 필수 + 5자 이상**: 인라인 검증.
9. **대안 일정 최대 3개**: 회원이 1개 선택 또는 모두 거절.
10. **대안 회원 응답 시한 (24시간)**: 미응답 시 자동 취소 처리 + 알림.
11. **수락 시 PT 횟수 처리**: 변경은 영향 없음, 취소는 자동 복구.
12. **결제 미수금 수업 처리**: 환불 화면(SCR-S007) 안내 + 처리 보류 옵션.
13. **권한**: manager+ 전체, 트레이너 본인 담당만, FC 조회만.
14. **정책 위반 자동 거절 추천**: DLG-C007 정책 위반 (예: 시작 2시간 전 이내) 시 자동 거절 + 페널티 부과 옵션.
15. **미처리 SLA**: 24시간 초과 미처리 시 owner+에게 알림.
16. **본사 통합 모드**: 지점 컬럼 + 전 지점 합산.
17. **회원앱 동기화**: 처리 결과 회원앱 즉시 반영, 회원 응답도 즉시 동기화.
18. **Today Tasks 알림 (NFR-19)**: SCR-098 Today Tasks(오늘의 할 일)에 `일정 요청 미처리 N` 시스템 태스크를 표시하고, 클릭 시 SCR-C009로 진입한다. 기본 필터는 `대기/응답대기/24시간 초과`다.
19. **트랜잭션 보장**: 수락 시 일정 변경·횟수 복구·알림 발송 모두 트랜잭션, 일부 실패 시 롤백.
20. **이력 보관**: 처리 이력 영구 보관 (분쟁 대응).

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `CLS-09`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-C009`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-C016 대안일정제시`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
