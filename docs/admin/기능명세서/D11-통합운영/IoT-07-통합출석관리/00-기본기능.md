## 기능 목적

회원·직원·게스트의 출석 현황을 단일 화면(SCR-I001)에서 실시간으로 통합 조회·관리한다. 키오스크 QR / RFID / 얼굴인식 / 회원앱 QR / 수동 입력 등 5종 채널에서 발생한 출석 이벤트를 동일한 데이터 모델로 집계하여 운영자가 입장·퇴실·실패·중복·미배정 락커를 한눈에 파악하도록 한다. 본 화면은 통합 운영 도메인의 첫 진입점으로, 출석 그 자체뿐만 아니라 출석 후 후속 처리(옷 락커 배정·퇴실 처리·실패 사유 점검)까지 한 화면에서 흐름이 끊기지 않도록 설계되었다.

운영 맥락:
- **러시아워 프런트 모니터링**: 06:00~09:00 / 18:00~22:00 피크 타임에 키오스크·앱 QR 출석이 동시 폭주하는 상황에서 미배정 락커·실패 건을 실시간 감지하여 대응
- **얼굴인식 실패 회원 안내**: 키오스크 KIO-103에서 얼굴인식 실패가 반복되는 회원을 프런트에서 즉시 식별하여 수동 등록·재등록 안내
- **중복 출석 진위 확인**: 키오스크 정책 "중복 출석 방지 시간(기본 10분)"에 걸려 실패로 기록된 회원이 실제 재방문인지 단순 재시도인지 비고로 구분
- **만료 회원 출석 재결제 유도**: 만료된 회원이 키오스크에서 실패 처리되면 프런트가 즉시 회원 상세 이동 → 재결제 안내
- **PT 강사 출퇴근 관리**: 직원 채널 필터로 강사 출퇴근 현황 즉시 확인, 무단 결근 / 지각 즉시 식별
- **퇴실 미처리 정리**: 마감 시간 임박 시 "현재 센터 내" 카드 클릭 → 입장 후 미퇴실 회원 일괄 식별 → 수동 퇴실 처리
- **본사 통합 모드 출석 BI**: 본사 운영자가 전 지점 동일 시각 출석 추이를 비교, 지점 운영 인사이트 도출
- **수동 출석(DLG-I001) 보완 운용**: 키오스크 장애·QR 인식 실패·게스트 방문 시 프런트가 즉시 수동 등록으로 보완
- **출석 후 락커 자동 배정 미적용 후속**: 키오스크 설정 "자동 배정 시도" 실패 시 본 화면 미배정 락커 카드에서 즉시 수동 배정(DLG-I002)
- **회원 도용·미수금 대응**: 키오스크에서 미수금 차단으로 실패한 회원을 프런트가 즉시 식별하여 결제 유도

상단 통계 카드(오늘 총 출석 / 현재 센터 내 / 미배정 락커 / 실패 건수)는 운영 KPI 대시보드 역할을 동시에 수행하여, 카드 클릭만으로 해당 필터가 자동 적용되는 즉시 액션 인터랙션을 제공한다.

## 주요 구성요소

### 상단 통계 카드

| 카드 | 표시 | 클릭 액션 |
|------|------|------|
| 오늘 총 출석 | 회원 + 직원 + 게스트 합산 입장 수 | 결과=전체·기간=오늘 필터 |
| 현재 센터 내 | 입장 후 퇴실 미처리 인원 수 | 결과=성공·미퇴실 필터 |
| 미배정 락커 | 출석 완료 + 옷 락커 미배정 인원 수 | 락커=미배정 필터 + 회원 패널 자동 열기 |
| 실패 건수 | 금일 출석 실패(만료·중복·미등록·미수금) | 결과=실패 필터 |

### 필터 영역

| 필터 | 옵션 |
|------|------|
| 기간 | 오늘(기본) / 이번 주 / 이번 달 / 직접 선택 |
| 구분 | 전체 / 회원 / 직원 / 게스트 |
| 결과 | 전체 / 성공 / 실패 / 중복 / 퇴실 |
| 채널 | 앱 QR / 키오스크 QR / 키오스크 RFID / 얼굴인식 / 키오스크 바코드 / 키오스크 전화번호 / 수동 |
| 락커 상태 | 전체 / 미배정 / 수동배정 / 자동배정 / 대상 아님 |
| 검색 | 이름·연락처·회원번호·사번 |

### 출석 테이블

| 컬럼 | 표시 |
|------|------|
| 시간 | 입장 시각 (HH:mm:ss) |
| 구분 | 회원 / 직원 / 게스트 배지 |
| 이름 | 이름 + 회원번호 또는 사번 |
| 채널 | 앱 QR / 키오스크 QR / 키오스크 RFID / 얼굴인식 / 키오스크 바코드 / 키오스크 전화번호 / 수동 |
| 결과 | 성공 / 실패 / 중복 / 퇴실 |
| 옷 락커 | 미배정 / 수동배정(번호) / 자동배정(번호) / 대상 아님 |
| 고정 락커 | 보유 시 락커 번호, 없으면 '-' |
| 비고 | 실패 사유 또는 운영 메모 |

### 실시간 출석 확인 카드

SCR-101 대시보드 통합과 동일한 FC 확인용 카드 위젯을 일별 뷰 상단에 배치한다.

| 항목 | 표시 / 동작 |
|------|-------------|
| 이벤트 원천 | 키오스크 QR, 앱 QR, RFID/밴드, 얼굴인식, 수동 출석 |
| 카드 수 | 데스크톱 기준 최대 10개 유지 |
| 초과 처리 | 가장 먼저 출석한 카드부터 제거 |
| 중복 처리 | 동일 회원 첫 출석 후 2시간 이내 재출석은 새 카드 생성 안 함 |
| 회원 정보 | 사진/기본 아바타, 이름, 회원번호, 성별/나이, 이용권, 만료일, 출석 시각, 출석 채널 |
| 주의 태그 | 만료, 만료 임박, 미수금, 중복, 이용권 없음, 사진 필요 |
| 만료 기준 | 본사 자동화 정책 또는 지점 키오스크 출입 규칙에서 적용 중인 만료 안내 기준일 |
| 신규 이벤트 알림 | 카드 4~5초 강조 + 알림음 + 토스트 |
| 사진 미등록 | 기본 아바타 표시 + FC에게 현장 사진 촬영 필요 토스트 |
| 클릭 동작 | 회원 상세(SCR-M004) 기본정보 탭 이동 |

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin (본사) | 전 지점 출석 현황 (지점 선택) | 조회 전용 (수동 등록·퇴실은 해당 지점) |
| owner (센터장) | 소속 지점 출석 현황 | 회원·직원 수동 등록·퇴실·락커 배정 |
| manager (프런트) | 소속 지점 출석 현황 | 회원 수동 등록·퇴실·락커 배정 (직원 수동 등록은 owner 승인) |
| 강사 | 소속 지점 출석 조회 | 조회만 (담당 회원만 강조) |
| readonly | 조회 | 조회만 |

## 주요 UX 흐름

### 출석 현황 모니터링 (정상)
1. 사이드바 → "통합운영 > 통합 출석 관리(/attendance)" 진입
2. 기본값: 기간=오늘 / 구분=전체 / 결과=전체
3. WebSocket 스트림 수신 → 키오스크·앱·얼굴인식 출석 발생 → 테이블 상단 즉시 반영 + 신규 행 노란색 1.5초 하이라이트
4. 통계 카드 수치 실시간 카운트업

### 미배정 락커 처리
1. "미배정 락커" 카드 클릭 → 락커=미배정 필터 자동 적용 + 우측 회원 패널 자동 펼침
2. 행 [락커 배정] 또는 회원 카드 [배정] → DLG-I002 → 빈 락커 클릭 → [배정]
3. 그리드 + 출석 테이블 즉시 갱신, 옷 락커 컬럼 "수동배정(번호)"로 전환

### 수동 출석 등록 (DLG-I001)
1. [수동 출석 등록] → 모달 오버레이
2. 구분(회원/직원) → 이름/번호 검색 → 자동완성 결과 선택
3. 출석 시각 확인·수정 → 비고 입력 → [등록]
4. 성공 시 토스트 "출석이 등록되었습니다." + 목록 즉시 갱신
5. 실패 시 인라인 오류 메시지 (검색 결과 없음·미래 시각·중복 출석)

### 퇴실 처리
1. 결과=성공 / 미퇴실 행 [퇴실] → 확인 모달 → 결과 "퇴실"로 전환
2. 일괄 퇴실: 마감 시간 임박 시 "현재 센터 내" 카드 → 다중 선택 → [선택 퇴실]

### 분기·예외 흐름
- **만료 회원 키오스크 출석 시도**: 키오스크 KIO-201 실패 화면 7초 + 본 화면 결과=실패·비고="이용권 만료"로 즉시 적재 + 프런트 안내 토스트(정책 ON 시)
- **중복 출석 (10분 내 재시도)**: 키오스크 실패 화면 + 본 화면 결과=중복으로 분리 적재 (실패와 별도 카운트), 비고에 "이전 체크인 후 X분 경과"
- **미등록 회원 키오스크 출석 시도**: 결과=실패·비고="미등록", 회원 상세 이동 불가, [수동 출석 등록]으로 안내
- **미수금 회원 출석 시도**: 키오스크 설정 정책에 따라 경고/차단 분기, 본 화면 비고에 미수금 금액 표시 + 결제 유도
- **직원 출석 허용 OFF인데 직원 키오스크 시도**: 결과=실패·비고="직원 출석 불가", 키오스크 설정에서 토글 활성 안내
- **얼굴인식 정지 판정 미충족**: 키오스크 설정 ka.face.stillSec 미충족 → 본 화면 결과=실패·비고="얼굴인식 시간 초과"
- **수동 등록 시 미래 시각 입력**: 인라인 "현재 시각 이후로는 등록할 수 없습니다" + [등록] 차단
- **수동 등록 시 동일 시각 중복**: "이미 같은 시각에 출석 데이터가 있습니다" + 결과=중복으로 저장
- **WebSocket 연결 끊김**: 화면 상단 노란 배너 "실시간 연결 끊김 - 새로고침 후 재시도" + 폴링(30초)으로 fallback
- **키오스크 모니터 패널 사이드 슬라이드**: 최근 5분 키오스크 이벤트(KIO-201 결과 분기) 노출, 클릭 시 해당 행 하이라이트
- **본사 통합 모드 + 수동 등록 시도**: "지점 선택 후 등록 가능합니다" 안내 + 차단
- **마감 시간 후 출석 시도**: 출입 허용 시간 외 → 결과=실패·비고="허용 시간 외"
- **퇴실 처리 후 재방문**: 동일 일자 두 번째 입장 → 결과=성공으로 별도 행 적재 (중복 아님, 재입장)
- **게스트 출석**: 회원/직원 외 게스트 출석 (정책 ON 시) → 구분=게스트, 락커=대상 아님
- **검색 0건**: "검색 결과가 없습니다" + [수동 출석 등록] CTA

## 비즈니스 규칙

1. 회원·직원·게스트 출석은 동일 테이블에서 통합 표시되되 구분 컬럼·필터로 식별된다.
2. 키오스크 QR / RFID / 얼굴인식 / 바코드 / 전화번호 / 앱 QR / 수동 7종 채널이 모두 동일한 출석 레코드 모델로 통합되며 채널 컬럼으로만 구분된다.
3. 키오스크 설정(SCR-I002)의 출석 후 락커 처리 정책(출석만 / 수동 배정 대기 / 자동 배정 시도)이 본 화면 락커 컬럼에 그대로 반영된다.
4. **만료 회원**: 키오스크 설정 "만료 회원 허용" OFF 상태에서 출석 시도 시 실패로 기록되며 비고="이용권 만료" 자동 부여.
5. **중복 출석 방지 시간**: 키오스크 설정의 중복 방지 시간(기본 10분) 내 동일 회원 재체크인은 결과=중복으로 별도 분류 (실패 카운트와 분리).
6. **미수금 정책**: 키오스크 설정 "미수금 처리"가 차단이면 결과=실패, 경고면 결과=성공·비고에 미수금 금액 표시.
7. **직원 출석 허용**: 키오스크 설정 "직원 출석 허용" OFF 시 직원 키오스크 출석 시도는 결과=실패·비고="직원 출석 불가".
8. **수동 출석 등록 권한**: manager는 회원 수동 등록만 가능, 직원 수동 등록은 owner 이상.
9. **수동 등록 미래 시각 차단**: 출석 시각은 현재 시각 이후 입력 불가.
10. **수동 등록 동일 시각 중복**: 동일 회원·동일 분 단위 시각 중복 시 결과=중복으로 저장하고 안내 토스트 표시.
11. **퇴실 처리 권한**: manager 이상에서 처리 가능. 강사·readonly는 불가.
12. **퇴실 후 재입장**: 동일 일자 두 번째 입장은 별도 행으로 적재 (중복 아님, 결과=성공).
13. **본사 통합 모드 조회**: 본사 계정은 지점 선택 드롭다운으로 단일 지점 조회. 수동 등록·퇴실 등 변경 액션은 해당 지점 관리자에게 위임.
14. **실시간 스트림**: 출석 발생 시 WebSocket으로 즉시 push, 끊김 시 30초 폴링 fallback.
15. **통계 카드 실시간**: 통계 카드 수치는 출석 이벤트 push 시 즉시 카운트업, 5초 디바운스로 깜빡임 방지.
16. **카드 클릭 필터 연동**: 통계 카드 4종 모두 클릭 시 해당 필터 자동 적용 + 페이지 1로 리셋.
17. **회원앱 데이터 공유**: 키오스크·관리자 출석 이벤트는 회원앱 SCR-MA-111 출석 이력에도 즉시 노출 (단일 데이터 원천).
18. **감사 로그**: 모든 수동 등록·퇴실·락커 배정은 SCR-097 감사 로그에 actor·target·timestamp 기록.
19. **게스트 출석**: 게스트 채널은 정책 ON 지점에 한해 노출, 락커=대상 아님 고정.
20. **키오스크 모니터 패널**: 최근 5분 키오스크 이벤트(KIO-201 결과)를 사이드 슬라이드로 노출, 새로고침 5초 주기.
21. **검색 자동완성**: 이름·연락처·회원번호·사번 통합 검색, 최소 2자 입력부터 동작, 디바운스 300ms.
22. **데이터 보관**: 출석 레코드는 영구 보관 (감사·BI 목적), 결과=실패 데이터도 동일 기간 보관.
23. **시간대 정렬**: 기본 정렬은 시간 내림차순(최신 상단), 사용자 정렬 변경 가능.

## 개발 추적 기준

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `IoT-07`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.
2. 화면 동작은 연계 화면설계서 `SCR-I001`를 기준으로 확인합니다.
3. 팝업·확인·입력 흐름은 연계 다이얼로그 `DLG-I001 수동출석등록, DLG-I002 옷락커배정`를 함께 확인합니다.
4. 상태 변경, 배치, 알림, 감사 로그는 `자동화 / 배치 / 이벤트 연계` 또는 본문 내 연계 표를 같이 적용합니다.
5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
