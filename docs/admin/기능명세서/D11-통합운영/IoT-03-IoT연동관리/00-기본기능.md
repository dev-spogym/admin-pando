## 기능 목적

지점에 설치된 IoT 장비(출입 게이트, 키오스크, 락커 컨트롤러, InBody 측정기)의 연결 상태를 한 화면(SCR-I003)에서 통합 모니터링·관리한다. 본 화면은 5개 탭(게이트 관리 / IoT 기기 / 출입 로그 / 출입 규칙 / 자동 전원)으로 구성되어, 기기 등록·삭제·연결 테스트·원격 게이트 제어·출입 로그 조회·출입 허용 규칙 설정·자동 전원 스케줄까지 IoT 운영의 전 라이프사이클을 처리한다. heartbeat 기반 실시간 상태 감지(MQTT/WebSocket), 펌웨어 버전 추적, 원격 명령(게이트 강제 개방·기기 재시작) 실행 결과를 감사 로그로 일관 관리하여, 본사·지점 운영자가 IoT 장애를 즉시 인지하고 대응할 수 있게 한다.

운영 맥락:
- **신규 단말 도입 시 등록 절차**: 지점 owner가 [기기 추가] → 유형·이름·IP·포트 입력 → 자동 연결 테스트 → 온라인 배지 확인
- **출입문 비상 개방**: 응급 환자 발생·소방 점검·VIP 안내 시 owner가 원격 게이트 개방 + 자동 히스토리 로그
- **InBody 장비 오프라인 감지**: heartbeat 미수신 시 자동 오프라인 전환 → 체성분 통합 관리(SCR-I006) 검수 대기 안내
- **키오스크 펌웨어 버전 추적**: 본사가 전 지점 펌웨어 분포 조회 → 노후 단말 업데이트 권고
- **새벽 자동 전원 스케줄**: 키오스크 OFF 23:00 / ON 05:30 자동 전원 제어로 전기료 절감 + 24시간 운영 지점은 ON 유지
- **휴무일 출입 규칙 일시 차단**: 명절·휴무일에 게이트별 출입 시간 규칙 임시 변경 → 무단 진입 차단
- **이상 출입 감지**: 출입 로그 결과=예외 필터로 비정상 출입(연속 실패·심야 시도) 식별
- **본사 통합 운영**: 본사가 전 지점 IoT 기기 상태 조회 → 장애 일괄 식별 → 해당 지점 owner에게 즉시 통보
- **MQTT/WebSocket 통신 장애 복구**: 통신 끊김 시 자동 재시도(3회) → 실패 시 NFR-19 알림 → owner 대응
- **InBody 채널 3종 분리**: 수기·파일 업로드·실시간 API 채널별 상태 배지로 통합 모니터링

상단 헤더의 [전체 동기화] 버튼은 모든 등록 기기에 ping을 일괄 발송하여 상태 배지를 갱신한다. 기기 5종(게이트 / 키오스크 / 락커 컨트롤러 / InBody / 카드 리더)은 동일한 데이터 모델로 등록되며, 유형 컬럼으로만 구분된다.

## 주요 구성요소

### 탭 구조

| 탭 | 설명 |
|----|------|
| 게이트 관리 | 출입문 목록, 실시간 연결 상태, 원격 개방 |
| IoT 기기 | 지점 전체 기기 목록 + 상태 배지 + 펌웨어 버전 |
| 출입 로그 | 출입 성공/실패/예외 이벤트 이력 |
| 출입 규칙 | 시간대·요일·게이트별 출입 허용 규칙 |
| 자동 전원 | 키오스크/기기 전원 ON·OFF 스케줄 |

### IoT 기기 탭

| 컬럼 | 표시 |
|------|------|
| 기기명 | 장비 식별 이름 |
| 유형 | 게이트 / 키오스크 / 락커 컨트롤러 / InBody / 카드 리더 |
| IP/포트 | 네트워크 연결 정보 |
| 상태 | 온라인 / 오프라인 / 오류 / 점검 중 |
| 마지막 통신 | 최근 heartbeat 시각 |
| 펌웨어 버전 | 설치 펌웨어 버전 |
| 액션 | [연결 테스트] / [상세] / [삭제] |

### InBody 채널 상태 배지

| 채널 | 설명 |
|------|------|
| 수기 | 직원 수동 입력 (DLG-I003) |
| 파일 업로드 | 장비 CSV/XLSX 파일 업로드 |
| 실시간 API | InBody 직접 전송 (TCP/HTTP) |

### 게이트 관리 탭

| 컬럼 | 표시 |
|------|------|
| 게이트명 | 출입문 식별 이름 |
| 위치 | 1층 정문·지하 비상문 등 |
| 연결 상태 | 온라인 / 오프라인 |
| 원격 개방 | [개방] 버튼 (예외 상황) |
| 마지막 이벤트 | 최근 출입 이벤트 시각 + 결과 |

### 출입 로그 탭

| 필터 | 옵션 |
|------|------|
| 기간 | 직접 선택 |
| 게이트 | 단일/다중 |
| 결과 | 성공 / 실패 / 예외 |
| 회원/직원/외부인 | 구분 |

| 컬럼 | 표시 |
|------|------|
| 시각 | 출입 시각 |
| 게이트 | 게이트명 |
| 회원 | 이름 + 회원번호 |
| 결과 | 성공 / 실패 / 예외 |
| 사유 | 실패 사유 |

### 출입 규칙 탭

| 항목 | 입력 |
|------|------|
| 규칙명 | 텍스트 |
| 요일 | 월~일 다중 선택 |
| 시간 범위 | 시작·종료 시각 |
| 게이트 | 단일/다중 |
| 우선순위 | 낮음 / 보통 / 높음 |

### 자동 전원 탭

| 항목 | 입력 |
|------|------|
| 대상 기기 | 키오스크 / 게이트 / 락커 컨트롤러 (다중 선택) |
| ON 시각 | HH:mm |
| OFF 시각 | HH:mm |
| 적용 요일 | 월~일 |
| 휴무일 예외 | ON / OFF |

| 버튼 | 동작 |

## 계정별 차이 (RBAC)

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| primary / superAdmin (본사) | 전 지점 기기 현황 | 조회만 (제어는 지점 owner) |
| owner (센터장) | 소속 지점 기기 | 등록·삭제·원격 제어·규칙·전원 스케줄 |
| manager (프런트) | 소속 지점 출입 로그 | 출입 로그 조회만 |
| 강사 | 접근 불가 | — |
| readonly | 접근 불가 | — |

| 페르소나 | 사용 맥락 | 행동 | 기대 결과 |
|---|---|---|---|
| 센터장 | 신규 키오스크 단말 도입 | [기기 추가] → 유형=키오스크·IP·포트·펌웨어 → 저장 → 자동 연결 테스트 | 온라인 배지 + SCR-I002 단말 목록에도 노출 |
| 센터장 | 응급 환자 발생 비상 개방 | 게이트 관리 탭 → 정문 [원격 개방] → 확인 → 즉시 개방 + 히스토리 | 5초 개방 + actor·timestamp 기록 |
| 센터장 | InBody 장비 오프라인 의심 | IoT 기기 탭 → InBody 행 [연결 테스트] → 오프라인 확인 → 현장 점검 | SCR-I006 검수 대기 안내 |
| 본사 슈퍼관리자 | 펌웨어 분포 점검 | 지점 선택 → IoT 기기 탭 → 펌웨어 컬럼 정렬 → 노후 단말 식별 | 업데이트 권고 |
| 센터장 | 새벽 자동 전원 도입 | 자동 전원 탭 → 키오스크 ON 05:30·OFF 23:00·평일 → 저장 | 전기료 절감 + 출입 시간 외 자동 차단 |
| 센터장 | 명절 휴무일 출입 차단 | 출입 규칙 탭 → 휴무일 규칙 추가 (요일 미지정·날짜 지정) → 우선순위 높음 | 명절 무단 진입 차단 |
| 매니저 | 이상 출입 감지 후 점검 | 출입 로그 탭 → 결과=예외·기간=어제 → 패턴 식별 | 보안 점검 보고 |
| 본사 슈퍼관리자 | 다지점 게이트 일괄 점검 | [전체 동기화] → 전 지점 기기 상태 새로고침 → 오프라인 단말 일괄 식별 | 장애 즉시 통보 |

## 주요 UX 흐름

### 기기 등록 (정상)
1. 사이드바 → "통합운영 > IoT 연동 관리(/settings/iot)" 진입
2. IoT 기기 탭 → [기기 추가] → 모달
3. 유형(게이트/키오스크/락커 컨트롤러/InBody/카드 리더) → 이름 → IP → 포트 → 펌웨어 버전 입력
4. [저장] → 자동 연결 테스트 (5초 timeout) → 상태 배지 표시
5. SCR-I002 단말 목록에도 자동 노출 (키오스크 유형인 경우)

### 원격 게이트 개방
1. 게이트 관리 탭 → 게이트 행 [원격 개방]
2. 확인 모달 "정문을 5초간 개방합니다. 계속하시겠습니까?" + [개방] / [취소]
3. [개방] → 명령 전송 → 결과 토스트
4. 히스토리 로그 자동 생성 (actor·gate_id·timestamp·reason)

### 출입 규칙 설정
1. 출입 규칙 탭 → [규칙 추가]
2. 요일·시간·게이트·우선순위 입력 → [저장]
3. 우선순위 높은 규칙이 먼저 적용 (예: 명절 휴무 규칙 > 일반 영업 시간)
4. 키오스크 설정과 연동 (SCR-I002 출입 허용 시간과 합쳐서 적용)

### 자동 전원 스케줄
1. 자동 전원 탭 → [스케줄 추가]
2. 대상 기기 다중 선택 → ON/OFF 시각 → 요일 → 휴무일 예외
3. [저장] → 시스템 스케줄러 등록

### 원격 재시작
1. IoT 기기 탭 → 기기 행 [원격 재시작]
2. 확인 모달 "기기를 재기동합니다. 약 30초간 오프라인 상태가 됩니다." + [재시작]
3. 명령 전송 → 30초 후 자동 [연결 테스트] → 결과 배지 갱신

### 분기·예외 흐름
- **IP 중복 입력**: "이미 등록된 IP입니다" + [저장] 차단
- **포트 범위 외 (1~65535)**: "유효 포트 1~65535" + [저장] 차단
- **연결 테스트 timeout (10초)**: 상태 오프라인으로 등록 + 노란 배너
- **heartbeat 미수신 임계 초과**: 자동 오프라인 전환 + NFR-19 알림 → owner에게 푸시
- **원격 게이트 개방 실패 (단말 오프라인)**: "단말 오프라인 - 명령 전송 실패" + 현장 수동 개방 안내
- **출입 규칙 충돌 (동일 시간·동일 게이트 다중 규칙)**: 우선순위 높은 규칙 적용 + 노란 안내
- **자동 전원 ON/OFF 시각 동일**: "ON과 OFF 시각이 같음" + [저장] 차단
- **휴무일 예외 ON인데 휴무일 캘린더 미설정**: "휴무일 캘린더를 먼저 설정하세요" + 안내
- **기기 삭제 시도 (활성 사용 중)**: "현재 사용 중 - 비활성 후 삭제" + 차단
- **펌웨어 버전 형식 오류**: "x.y.z 형식" + 인라인 안내
- **카드 리더 등록 시 SCR-052 매핑 미설정**: "카드매핑 화면에서 매핑 필요" + SCR-052 이동 링크
- **출입 로그 30일 초과 조회**: "30일 초과 조회 - 데이터 적재 시간 길어짐" 노랑 안내 + 진행
- **본사 통합 모드에서 원격 제어 시도**: "지점 owner에 위임" + 차단
- **매니저 기기 추가/삭제 시도**: 버튼 hidden 또는 비활성
- **MQTT/WebSocket 끊김**: 화면 상단 빨간 배너 + 30초 폴링 fallback + 재연결 시도
- **InBody 실시간 API 인증 실패**: 채널 배지 빨강 + 토큰 재발급 안내
- **펌웨어 업데이트 중 단말**: 상태=점검 중 + 업데이트 진행률 표시 (펌웨어 OTA)
- **삭제 후 복구 기간**: 30일 내 복구 가능, 이후 영구 삭제

## 비즈니스 규칙

1. **권한**: 기기 등록·삭제·원격 제어·규칙·자동 전원은 owner(센터장) 이상. 매니저는 출입 로그 조회만.
2. **본사 통합 모드**: 본사 계정은 전 지점 조회만, 제어는 해당 지점 owner.
3. **원격 게이트 개방**: 확인 모달 후 실행, 히스토리 로그(actor·gate_id·timestamp·reason) 자동 생성.
4. **heartbeat 임계**: 단말은 60초 주기로 heartbeat를 송신하며, 서버가 5분 초과 미수신으로 판정하면 자동 "오프라인" 전환. 임계 초과 시 NFR-19 알림 → owner 푸시.
5. **InBody 채널 3종**: 수기·파일 업로드·실시간 API 모두 지원, 채널별 상태 배지로 구분.
6. **출입 규칙 우선순위**: 동일 시간·게이트 다중 규칙 충돌 시 우선순위 높은 규칙 적용. 동일 우선순위면 최신 규칙 적용.
7. **자동 전원 스케줄**: 시스템 스케줄러에 의해 자동 처리, 실행 결과는 출입 로그에 기록.
8. **휴무일 예외**: 자동 전원 / 출입 규칙에 휴무일 예외 ON 시 회사 휴무일 캘린더 적용. 캘린더 미설정 시 차단.
9. **기기 삭제**: 활성 사용 중 단말은 [비활성] 후 [삭제]. 삭제 후 30일 복구 가능, 이후 영구 삭제.
10. **IP/포트 중복**: 동일 지점 내 IP+포트 조합 중복 금지.
11. **펌웨어 버전 형식**: x.y.z (예: 1.2.3) 강제. 형식 오류 시 [저장] 차단.
12. **카드 리더 의존**: 카드 리더 등록 시 SCR-052 카드매핑 화면 매핑 필수. 미설정 시 안내.
13. **MQTT/WebSocket 통신**: 끊김 시 자동 재시도(3회) + 30초 폴링 fallback. 끊김 지속 시 빨간 배너.
14. **출입 로그 보관**: 1년 영구 보관, 30일 초과 조회 시 데이터 적재 시간 길어짐 안내.
15. **펌웨어 OTA 업데이트**: 진행 중 단말은 상태=점검 중, 진행률 표시. 실패 시 자동 롤백.
16. **원격 재시작**: 30초 오프라인 + 자동 [연결 테스트] 재실행으로 복구 확인.
17. **InBody 실시간 API**: 토큰 기반 인증, 인증 실패 시 채널 배지 빨강 + 토큰 재발급 안내.
18. **기기 5종**: 게이트·키오스크·락커 컨트롤러·InBody·카드 리더. 동일 데이터 모델, 유형 컬럼으로 구분.
19. **자동 전원 ON/OFF 동시 시각 차단**: 동일 시각 입력 시 [저장] 차단.
20. **감사 로그**: 모든 등록·삭제·원격 제어·규칙 변경은 SCR-097에 기록.
21. **출입 규칙 + 키오스크 설정 합산**: SCR-I002 출입 허용 시간 ∩ SCR-I003 출입 규칙 = 실제 허용 시간.
22. **기기 그룹화**: 다수 단말 일괄 명령 시 기기 그룹(예: "정문 게이트 그룹") 기능으로 효율화 (옵션).
23. **원격 명령 실패 fallback**: 단말 오프라인이면 명령 큐에 적재 후 단말 온라인 시 자동 재시도.
24. **펌웨어 노후 알림**: 펌웨어 6개월 이상 미업데이트 시 본사 슈퍼관리자에게 NFR-19 알림.

개발자는 이 기능을 구현할 때 아래 순서로 문서를 따라갑니다.

1. 본 기능명세서 `IoT-03`의 Lv2/Lv3, 비즈니스 규칙, 예외/에러 처리 기준을 먼저 확인합니다.

5. API가 본문에 명시된 경우 해당 `API 기준`을 우선 적용하고, 명시가 없으면 화면 액션 단위로 API를 설계합니다.
