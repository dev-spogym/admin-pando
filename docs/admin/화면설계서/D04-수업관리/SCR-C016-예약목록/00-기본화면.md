## 화면 목적

전체 수업 예약을 예약 1건 단위로 조회·검색·필터링하는 예약 원장 화면입니다. 관리자는 회원 문의, 예약 취소 확인, 출석·노쇼 처리 현황을 한 화면에서 확인하고 필요한 후속 처리를 수행합니다.

## 주요 구성요소

- **요약 카드**: 전체 예약, 예약완료, 출석완료, 취소·노쇼, 대기 건수
- **필터 바**:
  - 기간: 수업일 기준 기본, 예약일 기준 전환 가능
  - 수업: 수업명 또는 수업 유형 선택
  - 강사: 담당 강사 선택
  - 상태: 전체 / 예약완료 / 출석완료 / 취소 / 노쇼 / 대기
  - 지점: 전체 지점(통합) 권한일 때만 노출
- **검색 입력**: 회원명 또는 연락처 검색. 연락처는 하이픈 제거 후 비교한다.
- **예약 목록 테이블**:
  - 예약일시
  - 수업일시
  - 수업명
  - 수업 유형
  - 강습 세션 유형
  - 강사
  - 회원명
  - 연락처
  - 지점
  - 상태
  - 취소 사유
  - 처리자 / 처리일시
- **행 액션**: 회원 상세 보기, 수업 상세 보기, 예약 취소, 출석 처리, 노쇼 처리
- **다운로드**: 현재 필터·검색 조건을 적용한 엑셀 다운로드

## 계정별 차이

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 본사 / 센터장 / 매니저 | 권한 범위 내 전체 예약 | 예약 조회, 취소, 출석·노쇼 처리, 다운로드 |
| 트레이너 | 본인 담당 수업 예약 | 출석·노쇼 처리, 회원 상세 확인 |
| FC / 스태프 | 소속 지점 예약 | 예약 조회, 예약 취소 접수, 회원 상세 확인 |
| readonly | 예약 목록 | 조회만 가능 |

## 주요 UX 흐름

1. 사이드바 > 수업관리 > 예약 목록 진입
2. 기본값으로 오늘부터 7일간의 수업일 기준 예약을 표시
3. 기간, 수업, 강사, 상태 필터를 조합해 목록을 좁힘
4. 회원명 또는 연락처로 특정 회원 예약을 검색
5. 예약 행에서 회원 상세 또는 수업 상세로 이동
6. 권한이 있는 사용자는 예약 취소, 출석 처리, 노쇼 처리를 수행
7. 상태 변경 결과는 목록에 즉시 반영되고 히스토리 로그에 기록

## 화면 상태

| 상태 | 설명 |
|---|---|
| 로딩 | 예약 목록 조회 중 스켈레톤 표시 |
| 예약 있음 | 필터 조건에 맞는 예약 테이블 표시 |
| 결과 없음 | 조건에 맞는 예약이 없다는 안내와 필터 초기화 버튼 표시 |
| 조회 실패 | 재시도 버튼과 오류 안내 표시 |
| 처리 중 | 상태 변경 액션 수행 중 해당 행 버튼 비활성화 |

## 데이터 및 필터 규칙

- 기준 행은 예약 1건이며, 수업 1개에 여러 회원이 예약된 경우 회원 수만큼 행을 표시한다.
- 예약 원천은 `lesson_bookings` 또는 동등한 예약 원장 테이블이다.
- 수업 정보는 `classes`, 회원 정보는 `members`, 강사 정보는 `staff`, 지점 정보는 `branches`와 연결해 표시한다.
- 기간 필터는 기본적으로 수업 시작일시를 기준으로 적용한다.
- 예약일 기준 조회로 전환하면 예약 생성일시를 기준으로 필터링한다.
- 연락처 검색은 숫자만 남긴 값으로 비교해 `01012345678`과 `010-1234-5678`을 동일하게 처리한다.
- 전체 지점(통합) 권한에서는 모든 지점 예약을 표시하고 지점 컬럼을 필수 노출한다.
- 단일 지점 권한에서는 사용자의 소속 지점 예약만 조회한다.

## 비즈니스 규칙

- 예약 상태는 `예약완료`, `출석완료`, `취소`, `노쇼`, `대기`를 기본으로 사용한다.
- 예약 취소 시 취소 사유 입력은 필수다.
- 출석완료 또는 노쇼 상태의 예약은 일반 취소가 불가하며, 권한이 있는 사용자의 상태 정정 플로우로만 변경한다.
- 동일 회원이 동일 수업에 중복 예약된 경우 정상 행 1건 외 중복 의심 건에 경고 배지를 표시한다.
- 예약 취소, 출석 처리, 노쇼 처리, 상태 정정은 히스토리 로그에 처리자와 처리일시를 포함해 기록한다.
