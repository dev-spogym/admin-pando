## 화면 목적

개별 회원의 모든 정보를 15개 탭으로 분류해 조회하고 관리하는 회원관리 도메인의 중심 화면입니다. 화면 상단의 회원 프로필 요약과 주요 액션 버튼이 스크롤 중에도 고정되어 어느 탭에서든 즉시 접근 가능합니다. 회원 상태(정상이용 / 홀딩 / 만료 / 정지 / 비활성)에 따라 표시되는 배너, 활성화되는 버튼, 안내 메시지가 완전히 달라지며, 회원의 전체 라이프사이클을 단일 페이지에서 관리합니다.

## 주요 구성요소

- **이동 경로 표시**: 화면 상단에 "회원 목록 > 회원명 상세"로 현재 위치 안내.
- **만료 알림 배너**: HQ-09 `회원 이용권 만료` 정책의 본사 step 또는 해당 지점의 지점 추가 step 결과가 존재하고 해당 지점에서 해당 step이 ON일 때 상단에 고정 표시. 색상과 강조 수준은 step 긴급도 기준을 따르며, D-30/D-14/D-7 같은 기준일은 본사 정책값 또는 지점 추가 step 값을 그대로 표시합니다.
- **회원 프로필 요약 (고정 영역)**: 프로필 사진 / 관심회원 별표 / 회원명 / 등급 배지 / 상태 배지 / 만료일까지 남은 일수 / 연락처 / 이메일. 하단에 미수금·마일리지·이용권 계약 수·락커 번호 요약 표시.
- **지점·귀속 요약 카드**: 프로필 요약 하단에 `소속지점 / 기본 이용지점 / 담당 상담자(FC) / 담당 트레이너 / 기본 매출 귀속 지점 / 기본 인센티브 귀속자`를 별도 카드로 표시합니다.
- **운영 코크핏**: 프로필 바로 아래에 `지금 바로 처리할 운영 이슈` 영역을 배치합니다. 만료 임박, 미수금 존재, 장기 미방문, 홀딩 상태, 이용 정지 같은 리스크를 우선순위 순으로 카드형 경보로 노출합니다.
- **추천 액션 큐**: 운영 코크핏 우측에 재등록 안내 발송, 미수 결제 처리, 추가 상품 제안, 홀딩 처리/해제, 상담이력 확인 같은 다음 액션 버튼을 문맥에 따라 다르게 배치합니다.
- **최근 신호 요약**: 마지막 방문일, 최근 30일 결제금액, 활성 계약 수를 별도 요약 블록으로 표시해 운영자가 탭 이동 없이 현재 회원의 건강도를 파악할 수 있게 합니다.
- **주요 액션 버튼**: 수동출석 / 수정 / 상품구매 / 메시지 / 지점이관 / 탈퇴. 회원 상태와 계정 권한에 따라 버튼 활성/비활성이 결정됩니다.
- 헤더 6액션은 위 6개로 고정합니다. 상담 등록은 상담이력/상담메모 탭에서, 결제/이용권 등록은 상품구매 액션(SCR-S003) 진입 후 처리합니다.
- **15개 탭**: 회원정보 · 이용권 · 출석이력 · 결제이력 · 결제내역 · 예약내역 · 상세내역 · 체성분 · 상담메모 · 레슨 · 신체정보 · 종합평가 · 상담이력 · 운동프로그램 · 운동이력
  - 결제이력 / 결제내역 탭에서는 결제경로(POS·링크·수기), 미수잔액, 결제링크 상태, 링크 재발송·무효화 가능 여부를 함께 확인합니다.
  - 결제링크 발송 건은 실제 계약금·잔액·할부 계약이 아니므로 미수금으로 집계하지 않습니다. 결제 완료 전에는 회원상세 결제내역에만 `미결제 / 발송됨` 행으로 표시하고, 환불 버튼은 표시하지 않습니다.
  - 결제이력 / 결제내역 탭에서는 `결제지점 / 이용지점 / 매출 귀속 지점 / 정산 지점 / 인센티브 귀속자 / 판매 담당자 / 승인번호`까지 함께 확인합니다.
  - 이용권 탭에서는 상품별 `운영 정책 구분(단일지점/법인/홈&오피스/주말/통합)`과 `이용 가능 지점` 요약을 함께 표시합니다.
- **계약 정보 탭 카드 보드**: 이용권/락커/운동복 상품을 카드형으로 노출합니다. 각 카드에는 상태 배지(사용중/홀딩/만료임박), 상품명, 기간, 판매 담당자, 계약일, 더보기 메뉴가 표시됩니다.
- **계약 액션 버튼 묶음**: 계약 정보 탭 상단에 업그레이드 / 양도 / 환불 / 기간정지 / 기간정지 종료 / 기간정지 취소 버튼을 배치합니다. 회원 상태와 상품 상태에 따라 버튼 활성 조건이 달라집니다.
- **유효한 상품만 토글**: 계약 정보 탭에서 활성 상품만 빠르게 보도록 토글 필터를 제공합니다.
- **계약 내역 원장 테이블**: 하단에 계약일 / 유형 / 계약 / 계약금액 / 합계 / 결제금액 / 미납 / 할인내역 / 메모 / 메뉴 컬럼을 제공합니다. 카드 뷰와 원장 테이블은 동일 계약ID를 공유합니다.
- **레슨 탭**: 회원별 레슨 기록을 `classes` 기준으로 조회·추가한다. 기록 추가 시 회원 ID/회원명, 수업명, 트레이너, 운동 메모, 서명 상태를 저장하며 모바일 레슨 완료 서명과 같은 `signature_url`, `signature_at`, `completed_at` 컬럼을 공유한다.
- **상담이력 탭**: 상담 일시, 유형, 채널, 담당자, 상태, 결과, 연결 매출, 후속조치, 내용을 `consultations`에 저장한다. 수정 시 히스토리 로그에 `상담 이력 수정됨` 문구가 남아야 한다.
- **회원 상태 관리 영역**: 정상이용 중이면 "홀딩 처리" 버튼, 홀딩 중이면 "홀딩 해제" 버튼, 정지 상태이면 권한자에게만 "정지 해제" 버튼 표시.
- **위험 구역**: 권한이 있는 계정에게만 화면 최하단에 표시. 회원 삭제 버튼 포함. 삭제는 되돌릴 수 없음을 명시.

## 계정별 차이

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 슈퍼관리자 / 본사 최고관리자 | 전체 탭 + 전체 버튼 + 위험 구역 | 수정·이관·탈퇴·삭제·홀딩·정지해제 등 모든 기능, 결제링크 재발송·무효화 |
| 센터장 (owner) | 전체 탭 + 전체 버튼 + 위험 구역 | 모든 기능 + 정지 해제 + 결제링크 재발송·무효화 |
| 매니저 | 전체 탭 | 수동출석·수정·상품구매·메시지·탈퇴·홀딩, 결제링크 재발송·무효화 (이관·삭제·정지해제 불가) |
| FC (피트니스 코치) | 전체 탭 (결제내역 조회 및 결제링크 처리 가능) | 수동출석·상품구매·메시지·관심회원, 결제링크 재발송·무효화 (수정·이관·탈퇴 불가) |
| 스태프 | 대부분 탭 (결제내역 제외) | 수동출석·수정·상품구매·메시지 (이관·탈퇴·삭제·홀딩 불가) |
| 트레이너 / 스태프 / 조회전용 | 접근 불가 | 이 화면 진입 차단 |

## 주요 UX 흐름

1. 회원 목록(SCR-M001)에서 회원명을 클릭하거나, 대시보드 위젯에서 특정 회원을 선택해 진입합니다.
2. 회원 프로필 요약과 상태 배너로 현재 상황을 파악합니다.
3. 운영 코크핏에서 만료 임박, 미수금, 장기 미방문 등 우선 대응 이슈를 먼저 확인합니다. 만료 임박 배너는 지점장(owner)이 SCR-072에서 ON 처리한 회원 이용권 만료 본사 step과 해당 지점 추가 step만 노출합니다.
4. 추천 액션 큐에서 재등록 안내, 미수 결제 처리, 홀딩 처리 같은 다음 작업을 즉시 실행합니다.
5. 탭을 선택해 이용권 현황, 출석 이력, 결제 내역 등 원하는 정보를 확인합니다.
6. 계약 정보 탭에서는 카드 보드에서 활성 상품을 빠르게 확인하고, 필요 시 "유효한 상품만" 토글로 만료 상품을 숨깁니다.
7. 상품 카드 상단 액션 또는 탭 상단 버튼으로 업그레이드·양도·환불·기간정지를 수행합니다.
8. 결제이력 또는 결제내역 탭에서 결제경로, 미수잔액, 결제링크 상태를 확인합니다.
9. 미결제 결제링크 행에는 [재발송]과 [결제링크 무효화] 버튼을 표시합니다. 무효화 시 사유 입력은 필수이며, 무효화 처리자와 처리 시각을 히스토리에 기록합니다.
10. 링크 미결제 건이 만료 또는 무효화된 상태라면 권한자에게 [결제링크 발송] 버튼이 표시되어 새 링크를 만들 수 있습니다. 단, 발송됨 상태의 활성 링크가 있으면 새 링크 생성은 차단하고 기존 링크 재발송 또는 무효화만 허용합니다.
11. 필요한 액션 버튼(수동출석·메시지·상품구매 등)을 클릭해 작업을 수행합니다.
12. 홀딩이나 탈퇴 등 상태 변경은 해당 버튼을 클릭하면 확인 다이얼로그가 나타나 처리합니다.
13. 레슨 탭에서 레슨 기록을 추가하면 Supabase `classes`에 저장되고, 서명이 없으면 모바일 서명 대기 상태로 남아 모바일 완료 서명과 연결됩니다.
14. 상담이력 탭에서 상담을 추가·수정하면 Supabase `consultations`에 저장되고, 수정 건은 히스토리 로그에서 변경 이력을 확인할 수 있습니다.

## 화면 상태

| 상태 | 설명 |
|---|---|
| 로딩 중 | 회원 정보를 불러오는 동안 스켈레톤 화면 표시 |
| 정상이용 중 (ACTIVE) | 만료 배너 없음, 모든 액션 버튼 활성, "홀딩 처리" 버튼 표시 |
| 홀딩 중 (HOLDING) | 보라색 배너로 홀딩 기간 및 사유 표시, "홀딩 해제" 버튼 표시 |
| 기간정지 상품 보유 | 계약 카드에 정지 시작일/종료일/정지 포함 여부 표시, "기간정지 종료" 또는 "취소" 버튼 노출 |
| 만료 (EXPIRED) | 빨간색 재등록 유도 배너 표시, 상품구매 버튼 강조, 수동출석·이관 불가 |
| 이용 정지 (SUSPENDED) | 주황색 정지 사유 배너 표시, 대부분 액션 차단, 권한자에게만 "정지 해제" 버튼 |
| 비활성 (INACTIVE) | 회색 배너로 읽기 전용 안내, 권한자에게 "복구" 버튼 표시 |
| 회원 없음 | 잘못된 접근이거나 삭제된 회원일 때 "회원을 찾을 수 없습니다" + 목록으로 이동 버튼 |

## 데이터 및 로그 규칙

- 레슨 기록 저장소는 `classes`이며 `member_id`, `member_name`, `lesson_status`, `signature_url`, `signature_at`, `completed_at`, `memo`를 사용한다.
- 레슨 기록에 서명이 포함되면 즉시 `completed` 상태로 저장하고, 서명이 없으면 `in_progress` 상태로 저장해 모바일 완료 서명을 받을 수 있게 한다.
- 레슨 등록, 레슨 상태 변경, 완료 서명 저장, 예약/출석/횟수 차감 등 레슨 관련 주요 변경은 히스토리 로그에 남긴다.
- 상담 이력 저장소는 `consultations`이며 `memberId`, `branchId`, `scheduledAt`, `completedAt`, `channel`을 사용한다.
- 상담 이력을 수정하면 히스토리 로그의 상세 메시지 또는 변경 후 값에 `상담 이력 수정됨` 문구가 포함되어야 한다.
- 회원 기본 귀속 필드는 `homeBranchId(소속지점)`, `defaultUsageBranchId(기본 이용지점)`, `defaultSalesAttributionBranchId(기본 매출 귀속 지점)`, `defaultIncentiveOwnerId(기본 인센티브 귀속자)`, `assignedConsultantId`, `assignedTrainerId`로 관리한다.
- 거래·계약 단위 귀속 필드는 회원 기본값과 분리해 저장하며, 결제/환불/수업/정산/KPI는 계약 또는 결제 레코드에 저장된 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId`를 우선 참조한다.
- 만료 알림 배너는 HQ-09 회원 이용권 만료 본사 step 결과, 회원 이용권 만료 지점 추가 step 결과, 지점별 ON/OFF 상태를 함께 참조한다. 본사 정책 기준일은 화면에서 수정할 수 없고, 지점별 ON/OFF와 지점 추가 step 관리는 SCR-072에서 센터장(owner)만 변경한다.
