## 화면 목적

환불 요청이 접수된 건에 대해 환불 금액과 사유를 확정하고 처리를 완료하거나 승인 요청으로 저장합니다. 전체 환불 또는 부분 환불을 선택할 수 있으며, 처리 내용은 이력으로 저장됩니다. 환불 자동 계산 산식은 현재 미확정이므로 SCR-S012와 동일하게 기사용 차감금·위약금·기환불 누계·이번 환불 가능액·최종 환불액을 수기 입력·조정 사유 기록 방식으로 처리합니다. 지점장(owner)은 이 다이얼로그에서 바로 환불을 완료할 수 있고, manager/fc는 승인 요청만 할 수 있습니다.

## 주요 구성요소

| 구성요소 | 내용 |
|---|---|
| 원 매출 정보 | 환불 대상 매출 번호, 결제일, 상품명, 결제 금액 (읽기 전용) |
| 환불 수기 입력 요약 | 기사용 차감금, 위약금, 기환불 누계, 이번 환불 가능액, 최종 환불액 |
| 환불 가능액 입력 | 처리 담당자가 이번 환불 가능액을 수기 입력하고 사유를 기록 |
| 정책 미확정 수기 입력 | 기사용 차감금, 위약금, 기환불 누계, 최종 환불액, 외부 처리 상태, 승인 메모를 수기로 기록 |
| 환불 유형 선택 | 전체 환불 또는 부분 환불 중 선택 |
| 환불 금액 입력 | 부분 환불 선택 시 환불할 금액 직접 입력 (전체 환불 시 자동 입력) |
| 환불 사유 선택 | 사전 정의된 사유 목록에서 선택 (고객 변심, 서비스 불만, 중복 결제 등) |
| 사유 직접 입력 | 목록에 없는 경우 직접 입력 가능 |
| 환불 수단 | 환불 방법 선택 (원결제 수단 환불, 현금, 마일리지(포인트) 등) |
| 쿠폰/마일리지 복원 | 사용 마일리지 우선 복원, 사용 쿠폰 미사용 복원 대상 표시 |
| 처리 확인 버튼 | owner에게만 노출. 입력 내용으로 환불 처리 실행 |
| 승인 요청 버튼 | manager/fc에게 노출. 입력 내용을 승인대기 상태로 저장 |
| 취소 버튼 | 처리를 중단하고 이전 화면으로 복귀 |

## 언제 표시되나요

- DLG-S015(환불 요청)에서 처리 담당자가 승인 후 환불 처리로 진행할 때
- SCR-S007(환불 관리) 목록에서 미처리 건의 처리 버튼을 클릭했을 때
- DLG-S001(매출 상세)에서 환불 버튼을 클릭했을 때

## 주요 UX 흐름

1. 환불 대상 매출 건을 선택하고 환불 처리 버튼을 누릅니다.
2. 환불 처리 다이얼로그가 열리며 원 매출 정보가 표시됩니다.
3. SCR-S012와 동일하게 환불 수기 입력 요약을 확인하고 필요한 금액을 입력합니다.
4. 환불 유형(전체/부분)을 선택합니다.
5. 환불 금액, 사유, 환불 수단을 입력합니다.
6. 쿠폰/마일리지 복원 내역을 확인합니다. 마일리지(포인트)를 먼저 복원하고, 사용 쿠폰은 미사용 상태로 복원합니다.
7. owner는 처리 확인 버튼을 눌러 환불을 완료합니다. manager/fc는 승인 요청 버튼으로 승인대기 상태를 생성합니다.
8. 처리 완료 후 DLG-S014(환불 상세 결과)가 자동으로 표시됩니다.

## 비즈니스 규칙

- 자동 계산 로직은 사용하지 않습니다. 이 다이얼로그는 SCR-S012의 환불 수기 입력 기준을 참조합니다.
- 환불 요청 담당자는 환불 가능액을 수기 입력할 수 있으며, 조정 사유를 반드시 남깁니다.
- 최종 환불 금액은 확정된 환불 가능액을 초과할 수 없습니다.
- `INSTALLMENT` 건은 남은 미수금 상계 후 최종 환불액을 확정합니다.
- 사용분 차감 기준, 위약금 산식, 혼합결제 환불 순서, 귀속 차감 기준이 확정되지 않은 경우 자동 계산으로 단정하지 않고 수기 입력값과 메모를 이력에 남깁니다.
- 환불 실행은 지점장(owner) 승인 후 가능합니다. owner가 직접 처리하는 경우 승인자와 처리자를 동일 계정으로 기록하고 즉시 완료합니다.
- 환불 시 마일리지(포인트)를 우선 복원하고, 사용 쿠폰은 미사용 상태로 복원합니다.

## 화면 상태

| 상태 | 설명 |
|---|---|
| 기본 표시 | 부모 화면에서 선택한 대상의 최신 값을 불러와 표시합니다. |
| 입력/수정 중 | 필수값 누락, 형식 오류, 권한 제한을 인라인 메시지로 표시합니다. |
| 저장/처리 중 | 주요 버튼을 비활성화하고 중복 요청을 막습니다. |
| 완료 | 저장 또는 처리 성공 후 부모 화면 데이터를 갱신하고 다이얼로그를 닫습니다. |
| 실패 | 실패 사유를 토스트 또는 인라인 메시지로 안내하고 입력값은 유지합니다. |

## 계정별 차이

| 계정 | 동작 기준 |
|---|---|
| owner | 조회·입력·저장·처리 완료·승인/반려를 할 수 있습니다. |
| manager / fc | 담당 업무 범위에서 조회·입력·승인 요청을 할 수 있습니다. 처리 완료는 불가합니다. |
| trainer / staff | 담당 업무 범위에 포함된 데이터만 조회하며, 수정 권한은 부모 화면 정책을 따릅니다. |
| readonly | 조회만 가능하며 저장·삭제·확정 같은 변경 액션은 숨기거나 비활성화합니다. |
| 권한 없음 | 다이얼로그 진입을 차단하고 부모 화면에서 권한 안내를 표시합니다. |
