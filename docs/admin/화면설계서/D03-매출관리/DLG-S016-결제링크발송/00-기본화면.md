## 화면 목적

현장에서 확정한 상품·금액·할인 조건으로 고객이 직접 결제할 수 있는 링크를 발송합니다. 발송 후 고객은 결제수단만 선택할 수 있으며 금액·상품 구성은 수정할 수 없습니다.

## 주요 구성요소

| 구성요소 | 내용 |
|---|---|
| 회원 정보 | 수신 대상 회원 이름, 연락처, 앱 연결 여부 |
| 결제 요약 | 상품명, 수량, 정가, 할인, 최종 결제 금액, 잔액 여부 |
| 발송 채널 | SMS / 카카오톡 중 사용 가능한 채널 선택 |
| 링크 만료일시 | 결제 가능한 마지막 시각. 발송 시점 + 7일로 고정 |
| 내부 메모 | 상담 메모, 발송 사유, 특이사항 기록 |
| 발송 버튼 | 입력값 검증 후 결제링크 발송 |
| 취소 버튼 | 발송 없이 이전 화면으로 복귀 |

## 언제 표시되나요

- SCR-S003(결제 처리)에서 수납 방식을 `결제링크 발송`으로 선택했을 때
- 기존 활성 링크를 같은 링크로 다시 보내거나, 만료/취소 후 새 링크를 생성해야 할 때

## 주요 UX 흐름

1. 결제 처리 화면에서 상품, 할인, 확정 금액을 고정합니다.
2. 결제링크 발송 다이얼로그가 열립니다.
3. 수신 연락처와 발송 채널, 만료일시를 확인합니다.
4. 활성 링크가 있으면 같은 링크를 재발송할지, 강제 만료 후 새 링크를 만들지 선택합니다.
5. 발송 버튼을 누르면 같은 링크가 재발송되거나 새 링크가 생성되어 고객에게 발송됩니다.
6. 발송 완료 후 원화면으로 돌아가며 링크 상태가 `발송됨`으로 갱신됩니다.

## 비즈니스 규칙

- 링크 발송 후 상품, 할인, 최종 금액을 수정할 수 없습니다.
- 동일 원결제 기준 활성 링크는 1개만 유지합니다. 활성 링크가 있으면 같은 링크만 재발송할 수 있습니다.
- 운영자는 활성 링크를 수동 만료 또는 취소할 수 있고, 그 이후에만 새 링크를 생성할 수 있습니다.
- 링크 만료 후에는 새 링크를 발송해야 하며 만료된 링크를 재사용하지 않습니다.
- 회원 연락처가 없거나 유효하지 않으면 발송할 수 없습니다.

## 화면 상태

| 상태 | 설명 |
|---|---|
| 기본 표시 | 부모 화면에서 선택한 대상의 최신 값을 불러와 표시합니다. |
| 입력/수정 중 | 필수값 누락, 형식 오류, 권한 제한을 인라인 메시지로 표시합니다. |
| 저장/처리 중 | 주요 버튼을 비활성화하고 중복 요청을 막습니다. |
| 완료 | 저장 또는 처리 성공 후 부모 화면 데이터를 갱신하고 다이얼로그를 닫습니다. |
| 실패 | 실패 사유를 토스트 또는 인라인 메시지로 안내하고 입력값은 유지합니다. |

## 계정별 차이

| 계정 | 동작 기준 |
|---|---|
| owner / manager | 부모 화면에서 허용된 경우 조회·입력·저장할 수 있습니다. |
| trainer / fc / staff | 담당 업무 범위에 포함된 데이터만 조회하며, 수정 권한은 부모 화면 정책을 따릅니다. |
| readonly | 조회만 가능하며 저장·삭제·확정 같은 변경 액션은 숨기거나 비활성화합니다. |
| 권한 없음 | 다이얼로그 진입을 차단하고 부모 화면에서 권한 안내를 표시합니다. |
