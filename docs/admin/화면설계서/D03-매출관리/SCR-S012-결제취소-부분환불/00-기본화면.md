> **퍼블리싱 현황**: 퍼블리싱 보강 완료 / 1차 Supabase 연동. 완료 결제 건 조회와 환불 기록 생성은 동작하며, 클라이언트 정책 확정이 필요한 계산 항목은 수기 입력·조정 사유 기록 방식으로 우선 처리합니다.

## 화면 목적

완료된 결제 건에 대해 전체 취소 또는 일부 금액 환불을 처리하는 화면입니다. 단순 변심·결제 오류·서비스 불만 등의 사유로 환불 요청이 들어왔을 때, 담당자가 해당 결제 건을 조회하고 전체 취소 또는 부분 환불 금액을 지정해 처리합니다. 현장 영수증 첨부로 등록된 결제는 외부 POS/현금 환불을 먼저 완료한 뒤 CRM에 환불 기록을 남기며, 결제링크로 결제된 건은 링크 결제 webhook/PG 환불 흐름을 따릅니다. 처리된 내역은 환불 관리 화면(SCR-S007)에 자동으로 반영됩니다.

## 주요 구성요소

- **결제 건 검색**: 회원명·상품명·결제일로 환불 처리할 결제 건을 조회합니다.
- **결제 내역 확인**: 선택한 결제 건의 결제일·상품명·결제금액·결제수단·결제자 정보를 확인합니다.
- **환불 계산 박스**: 원결제금액 / 기사용 차감금 / 위약금 / 기환불 누계 / 이번 환불 가능액 / 최종 환불액을 표시합니다. 클라이언트 정책 확정 전에는 기사용 차감금·위약금·기환불 누계·이번 환불 가능액을 담당자가 수기 입력할 수 있습니다.
- **정책 미확정 항목 수기 입력**: 사용분 차감 기준, 위약금, 기환불 누계, 환불 가능액 조정, 조정 사유를 입력합니다. 자동 계산식이 확정되기 전까지 운영 판단 값을 기록하는 임시 정책 입력 영역입니다.
- **혼합결제 환불 분해표**: 카드/현금/계좌이체/포인트별 원수납액, 기환불액, 이번 환불 배분액, 잔여 환불 가능액을 행 단위로 보여줍니다. 수단별 자동 분해 정책 확정 전에는 환불 수단과 배분 메모를 수기로 기록합니다.
- **처리 유형 선택**: "전체 취소"와 "부분 환불" 중 하나를 선택합니다.
  - **전체 취소**: 이번 환불 가능액 전액을 환불 처리합니다. 사유 입력이 필요합니다.
  - **부분 환불**: 환불할 금액을 직접 입력합니다. 이번 환불 가능액을 초과할 수 없습니다. 사유 입력이 필요합니다.
- **환불 사유 입력**: 단순 변심·결제 오류·회원 요청·중복 결제·서비스 불만 등 프리셋 사유를 선택하거나 직접 입력합니다.
- **환불 수단 확인**: 원래 결제수단과 결제경로(현장 영수증 등록 / 결제링크)에 따라 환불 방법을 안내합니다. 현장 등록 건은 외부 POS/현금 환불 완료 증빙을 확인하고, 결제링크 건은 PG 환불 상태를 확인합니다. 외부 처리 상태와 영수증/증빙 메모는 수기로 입력할 수 있습니다.
- **귀속 영향 요약**: 결제지점, 이용지점, 매출 귀속 지점, 정산 지점, 인센티브 귀속자에 대한 환불 차감 영향을 요약 표시합니다. 다중 귀속 정책 확정 전에는 각 항목을 수기 메모로 남깁니다.
- **승인 상태 입력**: 처리 상태를 요청 / 승인대기 / 완료로 기록합니다. 지점장 승인 기준이 확정되기 전에는 승인 필요 여부와 승인 메모를 수기로 남깁니다.
- **처리 확인 모달**: 환불 금액·사유·수단을 최종 확인하고 "처리 완료" 버튼으로 확정합니다.
- **처리 완료 안내**: 환불 처리가 완료되면 완료 메시지와 함께 환불 관리 화면으로 이동하는 버튼을 제공합니다.
- **처리 이력**: 해당 결제 건에 대해 이전에 처리된 환불 이력이 있으면 하단에 목록으로 표시합니다.

## 계정별 차이

| 계정 유형 | 볼 수 있는 것 | 할 수 있는 것 |
|---|---|---|
| 슈퍼관리자 / 본사 최고관리자 | 전체 지점 매출 조회·분석 가능 | 전체 취소·부분 환불 처리, 결제 건 조회 |
| 센터장 / 매니저 | 소속 지점 매출 전체 | 전체 취소·부분 환불 처리, 결제 건 조회 |
| FC | 담당 회원 결제 처리 가능 | 담당 회원 결제 건 조회, 전체 취소·부분 환불 처리, 환불 가능액 조정 |
| 트레이너 / 스태프 | 매출 조회만 (처리 불가) | 조회만 가능 |

## 주요 UX 흐름

1. 사이드바에서 "매출관리 > 결제 취소 / 부분 환불"을 클릭해 진입합니다.
2. 회원명·상품명·결제일로 환불 처리할 결제 건을 검색합니다.
3. 해당 결제 건을 선택해 결제 내역(금액·수단·일자)을 확인합니다.
4. 환불 계산 박스에서 기사용 차감금, 위약금, 기환불 누계가 반영된 환불 가능액을 확인합니다. 자동 정책이 미확정된 경우 담당자가 해당 값을 수기로 입력합니다.
5. "전체 취소" 또는 "부분 환불"을 선택합니다.
6. 부분 환불의 경우 환불 금액을 직접 입력합니다.
7. 조정 사유, 환불 사유, 환불 수단, 외부 처리 상태, 영수증/증빙 메모를 입력합니다.
8. 매출/정산 귀속이 분리되어야 하는 경우 결제지점, 이용지점, 매출 귀속 지점, 정산 지점, 인센티브 귀속자를 수기로 입력합니다.
9. 처리 상태를 요청 / 승인대기 / 완료 중 선택하고 "처리 확인" 버튼을 누릅니다.
10. 최종 확인 모달에서 내역을 검토하고 "처리 완료" 또는 "승인대기 기록"을 누릅니다.
11. 완료 후 환불 관리 화면(SCR-S007)으로 이동하거나 계속 처리합니다.

## 화면 상태

| 상태 | 설명 |
|---|---|
| 초기 상태 | 결제 건이 선택되지 않은 상태. 검색 영역만 활성화됩니다. |
| 결제 건 선택됨 | 결제 내역이 표시되고 처리 유형·사유 입력 영역이 활성화됩니다. |
| 전체 취소 선택 | 최종 환불액이 이번 환불 가능액 전액으로 자동 입력됩니다. |
| 부분 환불 선택 | 환불 금액 입력란이 활성화됩니다. 이번 환불 가능액 초과 입력 시 경고를 표시합니다. |
| 처리 확인 모달 열림 | 최종 내역 확인 모달이 표시됩니다. 처리 중에는 버튼이 비활성화됩니다. |
| 요청 / 승인대기 기록 | 정책 또는 승인 확인이 필요한 건은 완료 처리하지 않고 요청/승인대기 상태로 기록합니다. |
| 처리 완료 | 완료 메시지와 후속 이동 버튼이 표시됩니다. |
| 이미 취소된 건 | 이미 전액 환불된 결제 건 선택 시 "이미 취소된 결제 건입니다" 안내를 표시합니다. |
| 오류 | 처리 실패 시 오류 메시지 알림(토스트)을 표시합니다. |

## 비즈니스 규칙

- `기사용 차감금`, `위약금`, `기환불 누계`는 환불 상태가 아니라 환불 계산 항목입니다.
- 할부/미수 진행 중(`INSTALLMENT`) 결제는 남은 미수금과 먼저 상계한 뒤 실제 환불액을 계산합니다.
- 아직 결제가 완료되지 않은 결제링크 건은 환불이 아니라 링크 취소로 처리합니다.
- 현장 영수증 첨부 등록 건은 CRM에서 카드 PG 취소를 직접 호출하지 않습니다. 외부 POS 또는 현금 환불 완료 후 CRM에는 환불 금액, 환불일시, 환불 증빙/메모를 기록합니다.
- 결제링크로 완료된 건만 PG 환불 또는 webhook 상태 갱신을 환불 처리 기준으로 사용합니다.
- 환불 처리 담당자는 `기사용 차감금`, `위약금`, `이번 환불 가능액`을 운영 판단에 따라 조정할 수 있으며, 조정 사유를 반드시 기록합니다.
- 최종 환불액은 확정된 환불 가능액을 초과할 수 없습니다.
- 혼합결제 건의 부분 환불은 원결제 수납 행 기준으로 추적하며, 카드/현금/계좌이체/포인트별 잔여 환불 가능액을 각각 관리합니다.
- 환불 완료 시 `paymentBranchId`, `usageBranchId`, `salesAttributionBranchId`, `settlementBranchId`, `incentiveOwnerId` 기준으로 KPI·정산·인센티브 차감을 반영합니다.
- 클라이언트 정책이 확정되기 전에는 사용분 차감 기준, 위약금 산식, 부분 환불 가능 범위, 혼합결제 환불 순서, 세금계산서/현금영수증 취소 처리, 지점장 승인 조건, 매출 귀속 차감 기준, 트레이너/FC 인센티브 환수 여부를 수기 입력값과 메모로 기록합니다.
- 수기 입력값은 최종 자동 계산 정책이 아니라 운영 기록입니다. 정책 확정 후에는 동일 필드를 정책 엔진 또는 설정값 기반 계산 결과로 대체합니다.
