# DLG-H1001-001 정책 세트 편집 — 기본화면

## 화면 목적

- 본사가 자동화 정책 세트를 생성하거나 수정하는 다이얼로그입니다.
- D-30, D-14, D-7, D-Day, D+1처럼 날짜 기준이 필요한 알림 정책은 이 다이얼로그의 step 리스트에서 정의합니다.
- 만료 알림 정책은 `회원 이용권 만료`, `결제기한 만료`, `락커 만료`로 분리해 생성합니다.
- 지점은 본사 step의 기준일을 직접 수정할 수 없습니다. 다만 `회원 이용권 만료`와 `락커 만료` 정책은 지점 센터장(owner)이 해당 지점 전용 추가 step을 만들 수 있도록 허용합니다.

## 주요 구성요소

### 기본정보

| 필드 | 입력/선택 | 필수 | 설명 |
|---|---|:---:|---|
| 정책명 | 텍스트 1~50자 | Y | 전사 중복 불가 |
| 정책 유형 | 회원 이용권 만료 / 결제기한 만료 / 락커 만료 / 운영 자동화 | Y | D-day step이 필요한 정책 유형 선택 |
| 설명 | 텍스트 | N | 지점 운영자가 이해할 수 있는 정책 설명 |
| 사용 상태 | 사용중 / 중지 | Y | 중지 시 신규 적용 차단 |
| 기본 정책 여부 | 토글 | N | 신규 지점 생성 시 자동 적용되는 기본 세트 |
| 지점 추가 step 허용 | 자동 표시 | Y | 회원 이용권 만료·락커 만료는 허용, 결제기한 만료는 불가. 운영 자동화는 정책별 별도 판단 |

### 적용 범위

| 필드 | 입력/선택 | 설명 |
|---|---|---|
| 적용 범위 | 전사 / 특정 지점군 / 특정 지점 | 정책을 배포할 지점 범위 |
| 지점군 선택 | 멀티 셀렉트 | 특정 지점군 선택 시 필수 |
| 제외 지점 | 멀티 셀렉트 | 전사 배포 중 제외할 지점이 있을 때 사용 |
| 적용 시점 | 즉시 / 예약 | 예약 시 날짜·시간 필수 |

### Step 리스트

| 필드 | 입력/선택 | 필수 | 설명 |
|---|---|:---:|---|
| 기준일 유형 | 만료 전 / 만료 당일 / 만료 후 | Y | D-숫자, D-Day, D+숫자 표시 기준 |
| 기준일 값 | 숫자 또는 D-Day | Y | 예: 30 입력 시 D-30, 14 입력 시 D-14 |
| 발송 시각 | HH:mm | Y | 지점 기본 발송 시각 |
| 기본 채널 | 회원앱 Push / KakaoTalk fallback | Y | 회원앱 Push가 기본. KakaoTalk fallback은 지점에서 선택 활성화한 경우만 사용 |
| 템플릿 | 템플릿 검색/선택 | Y | 메시지 템플릿 연결 |
| 기본 활성값 | ON / OFF | Y | 신규 배포 시 지점에 내려갈 기본 상태 |
| 지점장 ON/OFF | 항상 허용 | Y | 센터장(owner)만 SCR-072에서 변경 가능 |
| 지점 추가 step 허용 여부 | 자동 표시 | Y | 회원 이용권 만료·락커 만료는 허용, 결제기한 만료는 불가 |

### 버튼

| 버튼 | 동작 |
|---|---|
| Step 추가 | 빈 step 행 추가 |
| Step 삭제 | 해당 step 삭제. 사용 중인 정책 수정 시 영향 범위 고지 |
| 시뮬레이션 | 가상 만료일 기준 발송 예정일 미리보기 |
| 저장 | 검증 통과 시 정책 저장 또는 새 버전 생성 |
| 취소 | 변경 내용이 있으면 이탈 확인 후 닫기 |

## 3. 검증 규칙

- 정책명 필수
- 스텝 최소 1개 이상
- 기준일 중복 경고
- 기준일 값은 만료 전/후 1~365일 범위만 허용, D-Day는 한 정책 내 1개만 허용
- 기준일, step 순서, 템플릿 기본값은 본사만 수정 가능하며 지점 수정 필드로 내려가지 않음
- 지점 ON/OFF 변경 권한은 항상 센터장(owner)으로 고정하며 본사에서 manager 이하로 완화할 수 없음
- 회원 이용권 만료·락커 만료 정책은 지점 추가 step을 허용하되, 같은 지점·같은 정책 안에서 동일 기준일 중복과 D-Day 중복은 차단한다
- 결제기한 만료 정책은 지점 추가 step 생성 버튼이 노출되지 않으며, 본사 step의 ON/OFF만 허용한다
- 결제기한 만료는 미수금·잔액·할부 납입기한 기준이다. PAY-06 결제링크 만료 알림(D-3/D-1 고정)은 이 정책 유형으로 편집하지 않는다
- 템플릿 미선택, 발송 시각 미입력, 비활성 채널 선택 시 저장 차단 또는 경고 표시

## 4. 퍼블리싱 포인트

- 스텝 편집은 표 편집보다 카드 리스트와 인라인 편집 조합이 적합하다.

## 주요 UX 흐름

1. SCR-H1001에서 [+ 정책 세트] 또는 [편집]을 클릭하면 다이얼로그를 엽니다.
2. 생성 모드에서는 빈 기본정보와 step 리스트를 표시하고, 편집 모드에서는 기존 정책 버전을 불러옵니다.
3. 본사 담당자가 정책명, 유형, 적용 범위, step 기준일·채널·템플릿·기본 활성값을 입력합니다.
4. [시뮬레이션]을 실행하면 정책 유형별 기준일(회원 이용권 종료일/결제 납입기한/락커 이용 종료일)에 대해 정책 step별 발송 예정일을 미리 보여줍니다.
5. [저장] 클릭 시 필수값, 기준일 중복, 적용 범위, 채널 가용성, 영향 지점 수를 검증합니다.
6. 영향 지점이 있으면 "N개 지점에 새 정책 버전이 배포됩니다" 확인 후 저장합니다.
7. 저장 완료 시 부모 화면 카드/테이블/사용 현황 패널을 갱신하고 다이얼로그를 닫습니다.

## 화면 상태

| 상태 | 설명 |
|---|---|
| 기본 표시 | 부모 화면에서 선택한 대상의 최신 값을 불러와 표시합니다. |
| 입력/수정 중 | 필수값 누락, 형식 오류, 권한 제한을 인라인 메시지로 표시합니다. |
| 저장/처리 중 | 주요 버튼을 비활성화하고 중복 요청을 막습니다. |
| 완료 | 저장 또는 처리 성공 후 부모 화면 데이터를 갱신하고 다이얼로그를 닫습니다. |
| 실패 | 실패 사유를 토스트 또는 인라인 메시지로 안내하고 입력값은 유지합니다. |

## 계정별 차이

| 계정 | 동작 기준 |
|---|---|
| superAdmin / primary | 정책 세트 생성·수정·시뮬레이션·저장 가능 |
| owner / manager / trainer / fc / staff / readonly | 다이얼로그 진입 불가. 지점별 ON/OFF는 SCR-072에서 owner만 가능 |
| 권한 없음 | 다이얼로그 진입을 차단하고 부모 화면에서 권한 안내를 표시합니다. |
