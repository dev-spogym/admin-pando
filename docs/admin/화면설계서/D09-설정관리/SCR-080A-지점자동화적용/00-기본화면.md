# SCR-080A 지점 자동화 적용 — 기본화면


## 화면 목적

- 지점이 본사 HQ-09 정책 세트 적용 상태를 확인하고, 센터장(owner)이 지점별 정책/스텝 ON/OFF를 관리하는 화면이다.
- 만료 정책은 회원 이용권 만료, 결제기한 만료, 락커 만료로 분리해 표시한다.
- 본사 step의 D-30/D-14/D-7 같은 날짜 기준·트리거 조건은 본사 정책값으로 읽기 전용 표시된다.
- 회원 이용권 만료와 락커 만료 정책은 센터장(owner)이 해당 지점 전용 추가 step을 생성·수정·삭제할 수 있다.
- 결제기한 만료 정책은 지점 추가 step을 제공하지 않으며 본사 step의 ON/OFF만 허용한다.

## 주요 구성요소

- 정책 유형별 본사 배포 정책 세트 확인: 회원 이용권 만료 / 결제기한 만료 / 락커 만료
- 스텝별 활성/비활성(owner 전용)
- 회원 이용권 만료·락커 만료 지점 추가 step 관리(owner 전용)
- 테스트 발송
- 시뮬레이션 시 플랫폼 예상 비용 확인
- ON/OFF 저장

## 4. 운영 규칙

- 지점은 새 본사 정책 세트를 만들거나 교체하지 않는다.
- 지점은 본사 기준일·스텝 순서·트리거 조건을 수정하지 않는다.
- 회원 이용권 만료와 락커 만료 정책은 센터장(owner)이 지점 추가 step을 만들 수 있다. 지점 추가 step은 해당 지점에만 적용되며 본사 원본을 변경하지 않는다.
- 결제기한 만료 정책은 지점 추가 step을 만들 수 없다. 지점은 본사 step ON/OFF만 변경한다.
- 정책/스텝 ON/OFF와 지점 추가 step 생성·수정·삭제는 각 지점 센터장(owner)만 변경한다.
- manager 이하는 정책 상태 조회와 테스트·시뮬레이션만 가능하며 ON/OFF와 저장은 비활성화한다.
- 지점은 정책 템플릿 본문을 수정하지 않는다.
- SMS/알림톡 비용 정보는 플랫폼 API 조회값만 참고용으로 노출한다.

## 주요 UX 흐름

1. 사용자가 메뉴 또는 직접 URL로 화면에 진입합니다.
2. 기본 필터와 요약 영역을 먼저 확인합니다.
3. 정책 유형 탭에서 회원 이용권 만료, 결제기한 만료, 락커 만료 중 대상 항목을 선택합니다.
4. 센터장(owner)이 정책/스텝 ON/OFF를 변경하거나 회원 이용권 만료·락커 만료 지점 추가 step을 조정하면 DLG-080A-001에서 변경 요약을 확인합니다.
5. 저장 후 지점 ON/OFF 상태와 지점 추가 step 목록을 갱신하고 결과를 토스트로 안내합니다.

| 상태 | 설명 |

## 계정별 차이

| 계정 | 동작 기준 |
|---|---|
| owner | 지점 전체 정책 적용 상태를 조회하고 정책/스텝 ON/OFF, 회원 이용권 만료·락커 만료 지점 추가 step 관리, 테스트, 시뮬레이션, 저장을 수행할 수 있습니다. |
| manager | 지점 전체 정책 적용 상태를 조회하고 테스트·시뮬레이션을 수행할 수 있습니다. 정책/스텝 ON/OFF, 지점 추가 step 관리, 저장은 비활성화합니다. |
| trainer / fc / staff | 화면 접근을 차단합니다. |
| readonly | 조회 전용 접근만 허용하며 ON/OFF·저장·확정 액션은 숨기거나 비활성화합니다. |
| 권한 없음 | 메뉴와 직접 URL 접근을 차단하고 권한 안내 화면으로 전환합니다. |
