# Admin ↔ Kiosk 연동매트릭스

> 문서 버전: v0.2
> 작성일: 2026-05-14
> 목적: `admin-pando` 관리자웹의 어떤 화면/기능이 `kiosk-pando`(헬스장 입구 키오스크)와 데이터/정책으로 연동되는지 정리한다. 키오스크 단말은 admin 정책의 **현장 실행 채널**이며, 데이터 원천은 admin 단일이다.

> 키오스크 측 대응 문서: `../kiosk/KIOSK-기획연계정의서.md`

---

## 1. 채널 관계 요약

| 흐름 | 방향 | 의미 |
|---|---|---|
| 정책/설정 | admin → kiosk | 출석/락커/골프/주차/메뉴 토글 등 운영 규칙 전달 |
| 마스터 데이터 | admin → kiosk | 회원/이용권/예약/카드 매핑 등 조회용 |
| 이벤트 | kiosk → admin | 출석 기록, 직원 출퇴근, 결제, 골프 예약, 감사 로그 |
| 상태 보고 | kiosk → admin | 기기 정보, 온라인 상태, 장비 점검 결과 |

키오스크는 자체 영구 저장소를 두지 않는다. 일시 단절 시 로컬 큐만 보유, 복구 즉시 admin 원천에 반영한다.

## 2. 화면 단위 연동 매트릭스 (admin → kiosk)

### 2.1 D11-통합운영

| Admin 화면 | 책임 | 키오스크 영향 화면 | 연동 데이터 |
|---|---|---|---|
| `SCR-I001-통합출석관리` | 출석 정책 원천 (성공/실패/락커 후처리/타이머) | KIO-001, KIO-101 ~ KIO-105, KIO-201 | 출석 처리 규칙, 결과 모달 정보 |
| `SCR-I002-키오스크설정` | 키오스크 단말 설정 (얼굴 인식/락커 전달/메뉴 토글/주차/공지) | 모든 KIO 화면의 노출/동작 분기 | KSET-01 ~ KSET-05 전 영역 |
| `SCR-I008-키오스크운영현황` | 단말 운영 모니터링 (본사 통합) | KIO-402 (관리자 패널) ↔ 양방향 | 기기 정보, 온라인 상태, 감사 로그 |
| `DLG-I001-수동출석등록` | 수동 출석 (관리자 화면) | 키오스크 출석 실패 후 fallback | 회원 식별, 출석 기록 |
| `DLG-I002-옷락커배정` | 옷락커 수동 배정 다이얼로그 | KIO-201 락커 후처리 분기 | 락커 풀 상태 |

### 2.2 D06-시설관리

| Admin 화면 | 책임 | 키오스크 영향 화면 | 연동 데이터 |
|---|---|---|---|
| `SCR-050-락커관리` | 락커 풀 운영 (자동 배정 존, 가용 락커, 유효기한) | KIO-201, KIO-202, KIO-204, KIO-304 | 락커 번호, 존, 유효기한 |
| `SCR-051-사물함배정관리` | 사물함 배정 정책 | KIO-201 자동 배정 시도 분기 | 배정 룰 |
| `SCR-052-밴드카드관리` | RFID 카드/밴드 매핑 | KIO-102, KIO-204 | 카드 ↔ 회원 매핑, 밴드 재고 |
| `SCR-054-골프타석관리` | 타석 운영 (시간/타석/대기 정책) | KIO-501 ~ KIO-504 | 타석 상태, 가용 슬롯, 대기열 |

### 2.3 D03-매출관리 / D05-상품관리

| Admin 화면 | 책임 | 키오스크 영향 화면 | 연동 데이터 |
|---|---|---|---|
| `SCR-S002-POS판매` | 현장 판매 상품/구매자/장바구니 구성 | KIO-701, KIO-702 | 상품/가격/장바구니 |
| `SCR-S003-결제처리` | 외부 POS/현금/계좌이체 수납 결과와 영수증 첨부 결제 확정 | KIO-702 | 결제수단, 결제금액, 영수증, 결제 원장 |
| `SCR-S012-결제취소-부분환불` | 결제 취소/환불 | KIO-702 결제 결과 후 admin 처리 | 결제 트랜잭션 |
| `SCR-M004-회원상세` | 회원별 이용권/잔여회차 조회 원천 | KIO-302 | 이용권 상태/만료/잔여 |
| `SCR-P001-상품관리` | 상품 마스터 (매점 포함) | KIO-701 | 상품/가격/카테고리 |

### 2.4 D04-수업관리

| Admin 화면 | 책임 | 키오스크 영향 화면 | 연동 데이터 |
|---|---|---|---|
| `SCR-C002-수업관리` | 일반 수업 마스터와 수업 상태 원천 | KIO-303 (예약 조회) | 수업명, 유형, 강사, 장소, 일시, 상태 |
| `SCR-C016-예약목록` | 회원별 일반 수업 예약 원장 | KIO-303 (예약 조회) | 예약 상태, 출석/노쇼/취소, 회원별 예약 행 |

KIO-303은 일반 수업 예약과 골프 예약 요약을 함께 보여주지만, 일반 수업 예약을 키오스크에서 생성/변경하지 않는다. 일반 수업 정보는 `SCR-C002`와 `SCR-C016`을 기준으로 읽기 전용 표시하고, 골프 타석 예약 생성/대기 등록은 `SCR-054-골프타석관리`를 기준으로 KIO-501 ~ KIO-504에서만 처리한다.

## 3. 이벤트 단위 연동 (kiosk → admin)

| 이벤트 | 키오스크 발생 화면 | admin 적재 위치 |
|---|---|---|
| 회원 출석 성공 | KIO-201 | `SCR-I001-통합출석관리`, 출석 이력 테이블 |
| 회원 출석 실패 | KIO-201 (실패) | 운영 로그 |
| 직원 출퇴근 | KIO-104 → KIO-201 | `SCR-063-직원근태관리`, `staffAttendance` |
| 락커 자동 배정 | KIO-201 → KIO-202/204 | `SCR-050-락커관리` 락커 풀 갱신 |
| 락커 번호 앱 발송 | KIO-203 | 알림 채널(클라이언트) + admin 발송 로그 |
| 골프 예약 확정 | KIO-503 → KIO-504 | `SCR-054-골프타석관리` |
| 골프 대기 등록 | KIO-503 → KIO-504 | `SCR-054-골프타석관리` 대기열 |
| 매점 결제 | KIO-702 | `SCR-S002-POS판매` 장바구니 원장 + `SCR-S003-결제처리` 결제 원장 |
| 관리자 액션 (문열기/새로고침/TTS) | KIO-402 | 감사 로그 |
| 기기 상태 변경 | KIO-402 | `SCR-I008-키오스크운영현황` |

## 4. 새로 추가되어야 할 admin 항목

키오스크 기획에서 신규로 정의한 정책 중, admin 화면에 신규 설정 키 또는 화면 영역으로 반영되어야 하는 항목.

| 키오스크 기능 | 필요 admin 추가 사항 | 우선순위 |
|---|---|---|
| 락커 번호 영수증 출력 (ATT-04-03) | `SCR-I002` 영수증 토글, 출력 문구, 재출력 정책 | P1 |
| 락커 번호 앱 발송 (ATT-04-04) | `SCR-I002` 앱 발송 토글, 안내 문구, 미연동 회원 예외 | P1 |
| 신발장 밴드 수령 (ATT-04-05) | `SCR-I002` 신발장 토글, 동일번호 정책 사용 여부 + `SCR-052` 밴드 분실 정책 | P1 |
| 얼굴 인식 정지 판정 시간 (KSET-02-01) | `SCR-I002` 1~3초 슬라이더 또는 입력 | P0 |
| 골프 예약 키오스크 활성 (KSET-03-01) | `SCR-I002` 골프 키오스크 채널 토글 | P2 |
| 주차 등록 정책 (KSET-04) | `SCR-I002` 주차 토글, 처리 방식, 외부 링크, 안내 문구 | P3 |
| 매점 키오스크 활성 (KSET-01-02) | `SCR-I002` 매점 메뉴 토글 | P5 |

위 항목은 admin 측 화면 추가/보강이 완료될 때 `관리자문서_통합_ID대응표.md`에서 ID를 부여한다.

## 6. 동기화 원칙

1. **데이터 원천 단일화**: 같은 회원/예약/이용권은 admin DB 단일 원천을 사용. 키오스크는 별도 원천을 만들지 않는다.
2. **정책은 admin 우선**: 출석/락커/골프 운영 규칙은 admin 정책이 우선. 키오스크는 표시/입력만 담당.
3. **신규 설정 키 합의**: 키오스크가 새로 요구하는 설정은 admin `SCR-I002`에 명시 후 키오스크가 수신.
4. **이력은 admin으로 적재**: 출석/예약/결제/관리자 액션 모두 admin 운영 로그로 적재.
5. **오프라인 큐**: 일시 단절 시 키오스크가 로컬 큐를 보유할 수 있으나, 복구 즉시 admin 원천에 반영.
