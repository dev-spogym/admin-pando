# Admin TC Guide

## 상태 코드
- `Ready`: 문서상 기대 결과가 충분히 명시되어 바로 테스트 가능
- `Need-Design`: 상태값, 분기, 문구, 담당자 정책이 비어 있음
- `Need-Data`: 샘플 데이터, 마스터 코드, 연계값이 필요함
- `Need-Impl`: 화면은 있으나 실제 동작/로그/연계 구현이 없을 가능성이 큼

## 분류 코드
- `FLW`: 화면 진입, 다음 단계 이동, 완료 흐름
- `UI`: 컴포넌트 렌더링, 문구, 버튼 상태, 토스트
- `DATA`: 조회 조건, 저장 반영, 후속 시스템 갱신
- `STA`: 상태 배지, 빈 상태, 로딩, 완료/실패 분기
- `RBAC`: 역할, 읽기전용, 차단, 숨김
- `ERR`: 유효성 실패, 외부 연동 오류, 동시성 충돌, 복구
- `LINK`: 모달/상세/다른 화면 연결

## E2E 전환 규칙
- 화면 TC 전부를 곧바로 자동화하지 않는다.
- 같은 화면에서 `FLW + DATA + STA + RBAC + ERR`가 모두 `Ready`이면 그때 E2E 후보로 승격한다.
- 시나리오 문서의 happy path는 최소 1개 E2E, 고위험 분기는 Playwright 수동-반자동 조합으로 가져간다.

## 공통 확인 포인트
- 날짜/센터/지점 컨텍스트가 바뀐 뒤 목록과 KPI가 함께 갱신되는가
- 저장/삭제/발송 후 상세, 목록, 대시보드, 로그에 동일하게 반영되는가
- 읽기전용 역할에서 비활성 버튼, 숨김 버튼, 직접 URL 접근 차단이 모두 일치하는가
- 실패 후 재시도, 이전 화면 복귀, 문의/로그 경로가 존재하는가
