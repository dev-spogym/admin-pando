# FitGenie Client(회원앱) ↔ Kiosk 연동매트릭스

> 문서 버전: v0.1
> 작성일: 2026-05-04
> 목적: `client-pando` 회원앱과 `kiosk-pando` 키오스크가 어디에서 만나는지 정리한다. 두 채널은 FitGenie의 동일 데이터 원천(admin)을 다른 UX로 노출하며, 일부 흐름에서는 직접 데이터를 주고받는다.

> 키오스크 측 대응 문서: `../kiosk/KIOSK-기획연계정의서.md`

---

## 1. 채널 관계 요약

| 흐름 | 방향 | 의미 |
|---|---|---|
| 회원 발급 QR | client → kiosk | 회원앱이 발급한 QR을 키오스크 카메라가 스캔 |
| 락커 번호 안내 | kiosk → client | 출석 후 배정된 락커 번호를 회원 앱으로 발송 (앱 발송 방식) |
| 골프 예약 결과 알림 | kiosk → client | 키오스크에서 예약 확정/대기 등록 시 회원앱 알림 |
| 출석 이력 공유 | admin 경유 | 키오스크 출석 결과는 회원앱 출석이력에서도 조회 가능 |
| 이용권/예약/결제 데이터 | admin 단일 원천 | 두 채널이 같은 데이터를 다른 UX로 표시 |

회원앱은 데이터 원천이 아니다. 회원앱과 키오스크는 모두 admin DB를 바라본다.

## 2. 회원앱 화면 단위 연동

### 2.1 직접 연동 (회원앱 ↔ 키오스크 데이터 흐름이 명시적)

| 회원앱 화면 | MFN/MA ID | 키오스크 영향 화면 | 연동 내용 |
|---|---|---|---|
| QR 입장 | `MFN-102` / `SCR-MA-110-QR체크인` | KIO-101 (QR 스캔) | 회원앱 발급 QR 코드 → 키오스크 스캔 → 출석 |
| 알림 센터 | `MFN-119` / `SCR-MA-150-알림센터` | KIO-203 (락커 앱 발송 결과) | 키오스크 출석 후 락커 번호 푸시/인앱 메시지 수신 |
| 알림 센터 | 위와 동일 | KIO-504 (골프 예약 완료) | 키오스크 예약 확정 알림 수신 |
| 골프 예약 상세 | `SCR-MA-123-골프예약상세` | KIO-501 ~ KIO-504 | 동일 데이터, 다른 UX. 회원이 두 채널 어디에서나 예약 가능 |
| 대기 예약 관리 | `SCR-MA-124-대기예약관리` | KIO-503/504 | 키오스크에서 대기 등록 시 본 화면에서 관리 |

### 2.2 데이터 공유 (admin 경유, 동일 정보 표시)

| 회원앱 화면 | 키오스크 영향 화면 | 데이터 |
|---|---|---|
| `SCR-MA-111-출석이력` | KIO-201 출석 결과 | 회원앱이 키오스크 출석 결과를 동일하게 표시 |
| `SCR-MA-122-내예약수업이력` | KIO-303 예약 조회 | 같은 예약 목록 |
| `SCR-MA-131-이용권잔여회차` | KIO-302 이용권 조회 | 같은 이용권 상태 |

## 3. QR 입장 흐름 상세

```
[회원앱 SCR-MA-110]
   ↓ QR 코드 발급 (시간 제한 토큰)
[회원이 키오스크 KIO-101 카메라에 노출]
   ↓ 스캔 + 토큰 검증
[admin → 회원 식별 + 출석 처리]
   ↓
[KIO-201 출석 결과 모달]
   ↓
[회원앱 SCR-MA-111 출석이력에 즉시 반영]
```

키오스크 KIO-101 화면에서 회원앱 발급 QR을 받기 위해 다음 사항이 필요하다.

| 항목 | 필요 사항 |
|---|---|
| QR 토큰 형식 | 회원앱과 키오스크가 동일 디코딩 룰을 공유 |
| 토큰 유효시간 | 보안상 짧게 (예: 60초) |
| 재발급 정책 | 회원앱에서 자동 재발급 |
| 오프라인 키오스크 | 토큰 검증 불가 시 실패 안내 |

## 4. 락커 번호 앱 발송 흐름 상세

```
[KIO-201 출석 성공]
   ↓ 락커 자동 배정
[락커 번호 결정]
   ↓ 전달 방식 = 'app'인 경우
[admin 알림 채널 트리거]
   ↓
[client SCR-MA-150 알림센터에 푸시 + 인앱 메시지]
   ↓
[회원이 앱에서 락커 번호 확인]
   ↓
[키오스크는 KIO-203에 "앱에서 확인해주세요" 표시]
```

본 흐름에서 회원앱(`SCR-MA-150`) 측에 필요한 항목:

| 항목 | 내용 |
|---|---|
| 락커 번호 표시 | 큰 글자로 한 화면 |
| 유효 시간 | 출석 시각 + 운영시간 |
| 사용 안내 | 어디 위치인지, 어떻게 사용하는지 |
| 앱 미연동 회원 처리 | 해당 회원은 이 방식 기본값 사용 불가 |
| 전송 실패 시 | 키오스크가 즉시 영수증 또는 프런트 안내로 전환 |

## 5. 골프 예약 — 키오스크/회원앱 동시 흐름

회원이 골프 예약을 두 채널에서 모두 할 수 있어야 한다. 한쪽에서 예약하면 다른 쪽에 즉시 반영된다. 예약 확정, 대기 등록, 중복 차단은 admin의 단일 검증 결과를 기준으로 하며 키오스크와 회원앱은 같은 타석/예약 원천을 바라본다.

| 시나리오 | 처리 |
|---|---|
| 회원앱에서 예약 → 키오스크 KIO-303에서 조회 | 즉시 반영 |
| 키오스크에서 예약 → 회원앱 SCR-MA-123에서 조회 | 즉시 반영 + 알림 푸시 |
| 회원앱에서 취소 → 키오스크 다음 진입 시 반영 | OK |
| 키오스크 대기 등록 → 자동 승격 발생 → 회원앱 알림 | OK |

키오스크와 회원앱이 동시 시도하지 않도록 admin 측에서 단일 검증을 수행한다.

## 8. 동기화 원칙

1. 회원앱은 데이터 원천이 아니다. 모든 데이터는 admin 단일 원천을 거친다.
2. 키오스크 → 회원앱 직접 통신은 없다. admin 알림 채널을 경유한다.
3. 회원앱 → 키오스크는 QR 토큰 형태로만 직접 노출 (스캔 시점만).
4. 동일 회원이 두 채널에서 동시 시도해도 admin 단일 검증으로 결과가 일관되어야 한다.
