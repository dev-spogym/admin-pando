# Client TC Guide

## 상태 코드
- `Ready`: 기획 문서 기준으로 바로 검증 가능한 항목
- `Need-Design`: 문구, 상태값, 우선순위, 분기 기준 추가 정의 필요
- `Need-Data`: 샘플 데이터나 마스터 코드가 있어야 판정 가능한 항목
- `Need-Impl`: 문서상 필요하지만 현재 구현/로그/연동 확인이 어려운 항목

## 분류 코드
- `FLW`: 진입, 이동, 완료 흐름
- `UI`: 화면 구성, 카드, 버튼, 배지, 토스트
- `LINK`: 상세 이동, 외부 링크, 횡단 연결
- `STA`: 상태 분기, 빈 상태, 만료, 승인대기
- `DATA`: 조회값, 저장값, 후속 반영, 동기화
- `RBAC`: 계정/역할별 접근 및 노출 차이
- `ERR`: 실패, 복구, 중복 방지, 차단

## E2E 전환 규칙
- 화면별 TC를 먼저 통과 기준으로 정리한다.
- 시나리오/상태전이/연동 TC가 모두 맞춰진 뒤 핵심 happy path만 자동화한다.
- 정책이 흔들리는 화면은 바로 E2E로 내리지 않는다.
