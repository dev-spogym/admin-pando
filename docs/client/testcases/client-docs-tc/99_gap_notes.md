# Gap Notes

## 목적

- TC를 작성하면서 드러난 `기획 구멍`, `정책 불명확`, `실행 기준 미정` 항목을 따로 모은다.
- 이 파일의 항목은 E2E 자동화 전에 먼저 정리하는 것이 안전하다.

## 확인 필요 항목

| ID | 영역 | 이슈 | 왜 문제인지 | 권장 정리 방식 |
|---|---|---|---|---|
| GAP-01 | 회원가입/연동 | 앱 가입 시 인증 수단, 실패 재시도, 중복 연동 해제 규칙이 상세하지 않다 | 회원 전환 실패 시 예외 TC가 확정되지 않음 | 인증 성공/실패/만료/재전송 기준 문서화 |
| GAP-02 | QR 체크인 | 성공/실패/중복/이용권 없음/오프라인 상태별 화면 정의가 약하다 | 출석은 운영 리스크가 커서 상태 TC가 중요함 | QR 상태 매트릭스 추가 |
| GAP-03 | 예약 취소 | `취소 마감 시간`은 있으나 UI에서 마감 후 어떻게 보일지 세부 문구/버튼 상태가 약하다 | 동일 기능이 화면마다 다르게 구현될 수 있음 | enabled/disabled/message 규칙 고정 |
| GAP-04 | 대기열 자동 확정 | 자동 확정 시 회원/트레이너/알림/이력 동시 반영 기준이 명시 수준이 낮다 | E2E에서 기대결과가 흔들림 | 대기→확정 시퀀스 표 추가 |
| GAP-05 | OT1/OT2 | OT1/OT2의 데이터 모델, 완료 조건, 재예약 규칙이 화면보다 정책에 더 치우쳐 있다 | 회원/트레이너 양쪽 구현이 엇갈릴 수 있음 | OT1/OT2 상태전이도 추가 |
| GAP-06 | 골프 쌍방서명 | 대면/원격/만료/재요청/회원 미응답 상태 UI가 충분히 세분화되지 않았다 | 고가 레슨 증빙 핵심인데 상태 누락 위험 큼 | 서명 상태별 화면 스펙 추가 |
| GAP-07 | FC 상담 | `후속 조치 필수`는 있으나 어떤 결과값에서 필수인지, 수정 시점 제약이 더 필요하다 | 저장 검증 로직이 흔들릴 수 있음 | 결과값별 validation 표 추가 |
| GAP-08 | 스태프 수동 출석 | 권한 범위와 감사로그 표시 기준이 약하다 | 오남용 방지 검증이 어려움 | 수행자/사유/중복 처리 기준 추가 |
| GAP-09 | 마켓 메신저 | 1:1 톡의 읽음, 차단, 첨부 제한, 비로그인 진입 기준이 부족하다 | 메신저는 예외가 많아 구현 편차 큼 | 메신저 정책서 별도 분리 |
| GAP-10 | 결제/주문 | `주문`과 `결제내역`과 `영수증`의 상태 소유권이 문서마다 조금 다르게 읽힌다 | 주문상태/결제상태 정합성 테스트가 어렵다 | 상태 용어 사전 단일화 |
| GAP-11 | 환불 | 부분 환불 계산식, 사용 쿠폰/마일리지 환원 규칙이 명확하지 않다 | 금액 검증 TC를 확정할 수 없음 | 계산 예시 3~5개 추가 |
| GAP-12 | 건강 데이터 연동 | Android 지원 외 iOS, 웹, 권한 거부 후 복귀 흐름의 제품 정책이 더 필요하다 | 플랫폼별 TC 분리가 어렵다 | 지원 플랫폼 매트릭스 추가 |
| GAP-13 | 알림 설정 | 카테고리 ON인데 채널 0개일 때 저장 허용 여부가 불명확하다 | 저장 validation 기준 필요 | 채널 최소 조건 확정 |
| GAP-14 | 커뮤니티 Q&A | 공개 범위, 익명 규칙, 수정/삭제 가능 시간 기준이 부분 정의 상태다 | 운영 정책과 신고 정책이 연결되지 않음 | 게시 정책 표 추가 |
| GAP-15 | 시스템 공통 | 서버 점검, 네트워크 오류, 강제 업데이트의 우선순위가 정리되지 않았다 | 예외 상황에서 어떤 화면을 우선 노출할지 불명확 | 시스템 예외 우선순위 정의 |
