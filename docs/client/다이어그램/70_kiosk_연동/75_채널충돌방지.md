# 채널 충돌 방지 (회원앱 vs 키오스크)

> 작성일: 2026-05-04
> 같은 회원이 회원앱과 키오스크에서 동시에 시도할 때 admin 단일 검증으로 일관성 보장

## 1. 충돌 가능 시나리오

| 시나리오 | 발생 가능? | 처리 |
|---|---|---|
| 같은 시간/타석 골프 예약 | ✅ 가능 | admin 단일 검증, 선착순 |
| 같은 회원 출석 (10분 내 중복) | ✅ 가능 | 키오스크 중복 차단 |
| 같은 이용권 다중 차감 | ✅ 가능 | admin 트랜잭션으로 차단 |
| 같은 락커 동시 배정 | ❌ | 락커는 키오스크에서만 배정 |
| 결제 동시 처리 | 거의 없음 | 매점은 키오스크에서만 |

## 2. 골프 예약 동시 시도

```mermaid
sequenceDiagram
    actor 회원
    participant clientapp as 회원앱 SCR-MA-123
    participant kiosk as 키오스크 KIO-503
    participant admin

    par 동시
        회원->>clientapp: 타석 5번 / 14:00 예약
        clientapp->>admin: 예약 확정 요청
    and
        회원->>kiosk: 같은 타석 5번 / 14:00 예약
        kiosk->>admin: 예약 확정 요청
    end

    Note over admin: 트랜잭션 단일 처리
    admin->>admin: 먼저 도달한 요청만 확정

    alt 회원앱 먼저 도달
        admin-->>clientapp: 예약 ID
        admin-->>kiosk: 중복 차단 + "이미 예약된 타석"
        kiosk->>회원: KIO-503 갱신 + 다른 타석 선택 안내
    else 키오스크 먼저 도달
        admin-->>kiosk: 예약 ID
        admin-->>clientapp: 중복 차단
        clientapp-->>회원: "이미 예약된 타석" 안내
    end
```

## 3. 출석 중복 방지 (10분)

```mermaid
flowchart TD
    A[회원이 키오스크에서 출석 → 즉시 회원앱에서 다른 인증 시도] --> B[admin 출석 이력 조회]
    B --> C{최근 10분 내?}
    C -->|Y| D[중복 차단 안내]
    C -->|N| E[정상 처리]
```

회원앱은 직접 출석 입력을 하지 않지만, QR 토큰 발급 후 키오스크 두 번 스캔 시도 같은 경우 두 번째는 중복으로 차단된다.

## 4. 이용권 차감 일관성

```mermaid
flowchart LR
    A[키오스크 골프 예약 - 이용권 차감] --> ADMIN
    B[회원앱 결제 - 이용권 차감] --> ADMIN
    ADMIN[admin 트랜잭션] --> DB[(잔여 회차 갱신)]
    DB --> C[양 채널 모두 동일 잔여 표시]
```

같은 이용권을 두 채널에서 동시에 차감 시도해도 admin 트랜잭션 단일 처리로 잔여가 마이너스가 되지 않는다.

## 5. 사용자 경험 측면 — 차단된 채널의 처리

| 차단 채널 | 안내 문구 |
|---|---|
| 회원앱 차단 | "이미 다른 곳에서 처리되었습니다. 잠시 후 새로고침해주세요." |
| 키오스크 차단 | "이미 예약된 타석입니다. 다른 타석을 선택해주세요." |

회원이 자신이 다른 채널에서 동시에 한 행동임을 알 수 있도록 안내 문구를 명확히 한다.

## 6. 단일 원천 원칙 재확인

```mermaid
flowchart TD
    DB[admin DB - 단일 원천] --> CL[회원앱 client 캐시]
    DB --> KO[키오스크 kiosk 캐시]
    CL -.쓰기 시.-> DB
    KO -.쓰기 시.-> DB
    DB -.트랜잭션 단일 검증.-> ALL[모든 쓰기는 단일 검증]
```
