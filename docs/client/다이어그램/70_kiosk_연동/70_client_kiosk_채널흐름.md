# 회원앱 ↔ kiosk 전체 채널 흐름

> 작성일: 2026-05-04
> 회원앱 시점에서 키오스크와 만나는 모든 흐름

## 1. 채널 관계

```mermaid
flowchart LR
    subgraph clientapp[회원앱 client-pando]
        C110[SCR-MA-110 QR 체크인]
        C111[SCR-MA-111 출석이력]
        C122[SCR-MA-122 내예약수업이력]
        C123[SCR-MA-123 골프예약상세]
        C124[SCR-MA-124 대기예약관리]
        C131[SCR-MA-131 이용권잔여회차]
        C133[SCR-MA-133 결제내역]
        C150[SCR-MA-150 알림센터]
    end

    subgraph admin[admin / 알림 채널]
        A[admin DB]
        N[알림 채널]
    end

    subgraph kiosk[kiosk-pando]
        K101[KIO-101 QR 체크인]
        K201[KIO-201 출석 결과]
        K203[KIO-203 앱 확인]
        K302[KIO-302 이용권]
        K303[KIO-303 예약]
        K501[KIO-501~504 골프]
        K702[KIO-702 결제]
    end

    %% 회원앱 → 키오스크 (직접 노출)
    C110 -->|QR 토큰 시각 노출| K101

    %% 회원앱 ↔ admin
    C110 -.토큰 발급.-> A
    A -.출석 이력.-> C111
    A -.예약 데이터.-> C122
    A -.예약 데이터.-> C123
    A -.대기열.-> C124
    A -.이용권.-> C131
    A -.결제 내역.-> C133

    %% 키오스크 ↔ admin
    K201 -->|출석 이벤트| A
    K203 -->|락커 알림 트리거| A
    K501 -->|골프 예약/대기| A
    K702 -->|결제| A
    A -.이용권.-> K302
    A -.예약 목록.-> K303

    %% admin → 회원앱 (알림 채널)
    A --> N
    N -->|푸시/인앱| C150
```

## 2. 채널 책임

| 책임 | 회원앱(client) | 키오스크(kiosk) | admin |
|---|---|---|---|
| 데이터 원천 | ❌ 캐시 | ❌ 캐시 | ✅ 단일 |
| QR 토큰 발급 | ✅ 시각 노출 | ❌ | ✅ 토큰 발급/검증 |
| 출석 입력 | ❌ (인증 채널만) | ✅ 단말 | ❌ |
| 예약 입력 | ✅ 셀프 | ✅ 셀프 | ✅ 운영자 |
| 알림 수신 | ✅ 푸시/인앱 | ❌ | ✅ 발송 |
| 이력 표시 | ✅ 회원 시점 | ❌ (조회만) | ✅ 운영 시점 |

## 3. 회원이 두 채널을 동시에 쓰는 경우

```mermaid
flowchart TD
    A[회원이 같은 시점에 회원앱/키오스크 동시 사용] --> B{무엇을?}
    B -->|예약| C[admin 단일 검증으로 한 쪽만 성공]
    B -->|출석| D[키오스크에서만 출석 가능. 회원앱은 인증/QR 채널]
    B -->|이용권 조회| E[양쪽 모두 같은 정보. 충돌 없음]
    B -->|결제 내역 조회| F[양쪽 모두 같은 정보. 충돌 없음]
```

## 4. 직접 통신 vs admin 경유

| 흐름 | 방식 | 이유 |
|---|---|---|
| 회원앱 QR → 키오스크 카메라 | 직접 시각 노출 | 화면 표시만 |
| 키오스크 → 회원앱 락커 알림 | admin 알림 채널 경유 | 회원앱 푸시 토큰 관리는 admin |
| 키오스크 → 회원앱 골프 알림 | admin 알림 채널 경유 | 동일 |
| 회원앱 데이터 ↔ 키오스크 데이터 | admin DB 단일 원천 | 일관성 |

회원앱과 키오스크 사이 직접 네트워크 통신은 없다.
