# E5. 잔여 회차 / 마일리지 / 결제 부족 예외

> PT/OT 잔여 회차 0 시 예약 차단, 마일리지 부족 시 결제 화면에서 안내, 결제 실패 시 재시도 흐름.

```mermaid
flowchart TD
    Action[회원 액션] --> Type{유형}
    Type -->|예약 시도| ChkCount[잔여 회차 점검]
    Type -->|마일리지 사용| ChkMileage[마일리지 잔액 점검]
    Type -->|결제| ChkPayment[PG 결제 점검]

    ChkCount -->|충분| Allow[정상 예약]
    ChkCount -->|0회| ShowReset["잔여 회차가 없어요" + MA-138 재등록 추천 CTA]

    ChkMileage -->|충분| Apply[마일리지 차감 적용]
    ChkMileage -->|부족| ShowMile["보유 마일리지보다 많이 입력했어요" 인라인 에러]

    ChkPayment -->|승인| Done[결제 완료]
    ChkPayment -->|실패| ShowFail[결제 실패 안내 + 재시도]
```

## 잔여 회차 0 / 부족

```mermaid
sequenceDiagram
    actor Member
    participant App
    participant API

    Member->>App: MA-121 → "예약하기" (PT)
    App->>API: PT 잔여 조회
    API-->>App: 잔여 0회
    App-->>Member: "잔여 회차가 없어요" + "재등록 추천" CTA
    Member->>App: 재등록 추천 → MA-138
    App->>API: AI 추천 플랜 산정
    API-->>App: 3종 플랜
    App-->>Member: MA-138 + 추천 플랜 카드
    Member->>App: 카드 선택 → MA-140 결제
```

## 마일리지 부족 / 잘못된 입력

| 입력 상황 | 처리 |
|---|---|
| 보유 마일리지보다 많이 입력 | 입력 즉시 인라인 에러 + 자동 보정 (보유액으로 fallback) |
| 100P 단위 미만 입력 | "100P 단위로 입력해주세요" 안내 |
| 최소 결제액 미달로 인한 마일리지 차감 부족 | 결제 합계와 함께 안내 + 결제 CTA 비활성 |

## 결제 실패 시나리오

```mermaid
sequenceDiagram
    actor Member
    participant App
    participant PG as 토스페이먼츠
    participant API

    Member->>App: 결제 동의 + "결제하기"
    App->>PG: 결제 요청
    PG->>PG: 카드사 승인 시도
    PG-->>App: 실패 응답 (사유 코드)

    alt 한도 초과
        App-->>Member: "카드 한도를 확인해 주세요" + 재시도
    else 정지 카드
        App-->>Member: "사용할 수 없는 카드입니다" + 다른 결제수단 선택
    else 일시 오류
        App-->>Member: "잠시 후 다시 시도해주세요"
    else 회원 취소
        App-->>Member: 결제 화면 유지 (재시도 가능)
    end

    Note over App,API: 결제 실패 시 마일리지/쿠폰 적용 미차감
```

## 쿠폰 최소 결제액 미달

| 상황 | 처리 |
|---|---|
| 쿠폰 최소 결제액 30,000원, 합계 25,000원 | 쿠폰 카드 회색 + "5,000원 더 결제 시 적용" 안내 |
| 쿠폰 최소 결제액 충족 | 쿠폰 자동 적용 + 합계 즉시 갱신 |

## OT2 진입 시 OT1 미완료

| 상황 | 처리 |
|---|---|
| OT2 라디오 선택 + OT1 미완료 | "1차 OT를 먼저 진행해주세요" + OT1 예약 CTA (MA-121) |
| OT1 / OT2 모두 잔여 0 | "OT 추가권 구매가 필요해요" + MA-134 진입 CTA |
