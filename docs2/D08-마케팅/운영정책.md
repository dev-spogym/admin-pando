# D08-마케팅 마케팅 — 운영정책

> 개발사용 운영정책입니다. 이 파일만으로 해당 도메인의 운영 기준, 정책값, 예외 기준을 확인할 수 있도록 재구성했습니다.

## 1. 핵심 원칙
- 리드 유입부터 회원 등록, 회원 상세 운영까지의 기준을 하나로 묶는다.
- FC, 매니저, 지점 운영자가 가장 자주 쓰는 흐름을 우선 정의한다.
- 리드 관리
- 회원 목록
- 회원 등록/수정
- 회원 상세
- 회원 이관
- 상담/메모
- 외부 신규 DB 엑셀은 `docs/03_템플릿/지점파일템플릿/2025년 12월 광화문점 신규통합 DB.xlsx`의 `신규통합DB` 시트 형식을 기준으로 한다. 이 파일은 지점/월별 신규 리드 임포트 템플릿 예시이며, 실제 운영 임포트 파일도 같은 컬럼 구조를 사용해야 한다.
- 외부 신규 DB 컬럼 매핑: `경로` 필드는 문의 유형(방문(WI) / 전화문의(TI) / 체험 / 일일입장)으로 매핑하고, `상세 경로1`과 `상세 경로2`는 `가입경로` 단일 필드로 통합 매핑한다. 가입경로 9종은 간판 / 블로그 / 인스타 / 당근 / 지역카페 / 현수막 / 전단지 / 회원소개 / 기타로 고정한다.
- `상세 경로1`과 `상세 경로2` 값이 동시에 들어온 경우 9종 가입경로와 직접 매칭되는 더 구체적인 값을 우선 사용한다. 둘 다 매칭되지 않으면 `기타`로 집계한다. CRM 화면에는 원천 상세경로를 별도 필드로 나누어 노출하지 않고 `가입경로` 하나만 노출한다.
- 외부 신규 DB의 `1차 상담 방식`, `2차 상담 방식`, `3차 상담 방식` 값은 대면 / 유선 / 부재 3종만 허용한다.
- 리드 단계의 가입경로와 실제 첫 정상 결제 완료 회원의 가입경로는 다를 수 있으므로, 첫 정상 결제 완료 기준 가입경로 분포를 별도 표시한다. 가입경로 집계는 간판 / 블로그 / 인스타 / 당근 / 지역카페 / 현수막 / 전단지 / 회원소개 / 기타 9종을 기준으로 한다.
- 상담 성과 담당자는 리드의 `상담 담당자(FC)`로 관리하고, 매출 성과 담당자는 첫 정상 결제 완료 시점의 `판매 담당자/인센티브 귀속자`로 관리한다. 가입경로는 유입 채널이며 직원을 구분하는 용도로 사용하지 않는다.
- 리드는 전화번호를 기준으로 중복 여부를 먼저 확인한다.
- 이미 회원으로 존재하는 전화번호는 신규 리드 생성보다 "기존 회원 연결"을 우선 제안한다.
- 리드 담당자는 FC를 기본으로 하되, 지점 매니저가 재배정할 수 있다.
- `등록완료`는 첫 정상 결제 완료 시점에만 전환되며, 이때 회원 생성 또는 기존 회원 연결이 반드시 발생해야 한다. 칸반에서 `등록완료` 컬럼으로 이동하는 동작은 상태 저장이 아니라 회원 등록/결제 흐름 시작 트리거다.
- `미전환`은 종료 상태이며, 동일 연락처 재유입 시 기존 리드 재활성화를 기본값으로 한다. 새 리드는 연락처가 다르거나 권한자가 중복 강행 사유를 입력한 경우에만 생성한다.
- TI 문의는 전화 응대에서 끝났는지, 실제 대면 상담으로 이어졌는지를 분리해서 본다.
- WI 문의는 현장 방문 고객의 즉시 등록 전환 성과로 본다.
- `미등록`은 온보딩 미완료 상태이며 `비활성`과 합치지 않는다.

## 2. 상태 / 운영 정의
- **장기 보류 리드 재활성**: 보류 30일 경과 시 재상담 후속 액션 자동 등록
- 요약 카드(전환율·미전환율) + 상태 분포 카드 + 칸반 DnD + 상담 상세 패널을 한 화면에 통합해 FC 1명이 30~50건 리드를 실시간으로 관리할 수 있도록 설계되었다.
- 상태별 분포 카드 7종: 신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류. 0건 상태는 숨김.
- **리드 상태**: 신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류 7종을 사용하며, 화면에서는 다중 상태 분포로 표시한다.
- **이벤트 단발 발송**: 신년·생일·할인 이벤트 등 일회성 캠페인 메시지 일괄 발송 (전체 회원 / 활성 / 만료 그룹별)
- **재등록 권유**: 만료 회원만 필터 → 알림톡 발송 (저비용 채널 우선)
- **알림 채널**: Push / 카카오톡 / SMS 3종으로 고정한다. 자동 알림은 회원앱 Push를 기본으로 사용하고, 지점이 카카오톡 fallback을 켠 경우에만 Push 실패·회원앱 미설치 대상에게 카카오톡 보조 발송을 시도한다. SMS는 정책 step에서 명시 선택한 경우에만 발송하며 자동 fallback으로 전환하지 않는다.
- 화면에는 플랫폼에서 조회한 발신 프로필, 템플릿 승인 상태, 채널별 예상 비용, 잔여 캐시/크레딧, 최근 동기화 시각만 노출한다.
- 운영자는 관리자에서 발송 조건과 메시지 내용을 결정하지만, 과금 단가·실발송 상태·최종 청구 근거는 플랫폼 응답값을 우선한다.
- **만료 정책 분리**: HQ-09에서 `회원 이용권 만료`, `결제기한 만료`, `락커 만료`를 서로 다른 정책으로 생성·배포한다.
- **지점 사용 방식**: 각 지점은 본사 step을 받아 사용하며, Owner(지점장)만 지점별 ON/OFF를 변경할 수 있다.
- **지점 추가 step**: `회원 이용권 만료`와 `락커 만료`는 Owner(지점장)이 해당 지점 전용 step을 추가·수정·삭제할 수 있다. `결제기한 만료`는 지점 추가 step을 허용하지 않는다.
- **이용권 만료 당일**: D-Day 09:00 + 만료 후 D+1 재등록 권유
- **만료 step**: HQ-09 / `D10-본사관리/본사관리.md:894` 정책값을 사용한다. 회원 이용권 만료·락커 만료는 본사 step과 지점 추가 step을 함께 사용하고, 결제기한 만료는 본사 step만 사용한다.
- **이용권 만료 당일**: D-Day로 표시한다.
- 각 규칙 활성/비활성 토글. 본사 기준일 step은 지점에서 날짜를 수정할 수 없고, Owner(지점장)만 해당 지점의 ON/OFF를 변경 가능. OFF 시 해당 지점에서만 자동 발송이 중단되며 본사 정책 원본은 유지된다. 본사가 `본사 필수`로 배포한 규칙/step은 ON 고정 disabled + `본사 필수` 배지로 표시하고 지점에서 OFF할 수 없다. 지점 추가 step은 회원 이용권 만료·락커 만료에 한해 Owner(지점장)만 관리한다.
- **재등록 권유 쿠폰**: 만료 회원에게 10% 정률 쿠폰 발급, 알림톡 동시 발송
- **쿠폰 만료 자동 처리**: 유효 기간 종료 시 "만료" 상태 자동 전환, 신규 발급 차단
- **쿠폰 상태**: 활성 / 만료 / 중단 3개 상태로 표시한다.
- ### 상태 필터
- 활성 / 만료 / 중단 필터.

## 3. 권한·책임 분리
- 본사 권한자는 통합 모드에서 전 지점 조회·정책 관리를 수행한다.
- 지점 권한자는 소속 지점 데이터의 일상 운영 처리를 수행한다.
- 변경·삭제·복구·정산·권한 변경은 화면별 최소 권한을 따른다.
- 공통 권한 기준은 `_공통/권한매트릭스.md`를 우선 참조하고, 화면별 차이는 도메인 문서에 따로 표기한다.
