# 정책 미확정 확인 필요

이 문서는 `docs2` 기준으로 개발 착수 전 고객사 또는 판도 운영 판단이 필요한 정책값만 모은 목록입니다. API/DB 설계 방식이 아니라 화면·기능·UX·운영정책 기준에서 확정이 필요한 항목입니다.

| 구분 | 확인 필요 항목 | 영향 범위 | 확정 필요 이유 |
|---|---|---|---|
| 환불/취소 계산 | 향후 자동 계산 산식, 사용분 차감 기준, 위약금 산식 | 결제취소/환불, 미수금, 매출 통계 | 현재 v1 기준은 모든 금액 수기 입력 + Owner(지점장) 승인으로 확정. 향후 자동화 산식만 별도 확정 필요 |
| 지점 운영 임계값 | 미수 알림 N일 등 아직 확정되지 않은 운영 알림 기본값 | 운영 포커스, 자동 알림 | 화면 배지·필터·자동화 조건이 동일 값을 써야 함. 단, 이탈위험은 최근 30일 이상 미방문, 만료후미등록은 마지막 회원 이용권 만료일 +60일 경과로 확정 고정값이다 |
| 결제링크 정책 | 판도 내부 기준안 고객사 확인 대기: 전액 결제 전용, 링크 7일 고정, 만료 전 D-3/D-1 고정 알림, 활성 링크 1개만 허용, Owner(지점장)/manager/fc 무효화 가능, 사유 입력 필수, 결제 완료 즉시 이용권 활성화 | D03 결제처리, D03 PAY-06 결제링크, D02 회원상세 결제내역 | 고객사 최종 답변 전까지는 미확정 기준안이며 개발 대기 항목이다. 확정 전에는 자동 만료·자동 알림·활성 링크 제한·PG 결제 완료 webhook을 구현하지 않는다. 결제링크는 계약금·잔액·할부·미수금 수납에 사용하지 않는다. 미결제 링크는 환불 대상이 아니며 회원상세 결제내역의 `미결제/발송됨` 복합 표시로만 구분한다. 결제 완료된 링크 결제의 환불은 PAY-06 확정 후 D03 환불 기준안으로 처리한다 |
| 결제 자동 적용정책(후속) | v1 개발 기준에서는 제외. 할인 정책은 D05에서 등록·수정·삭제·조회까지만 가능하며, D03 결제 화면은 자동 적용 없이 할인 후보만 표시한다. 후속 확인 기준안: 쿠폰/마일리지는 자동 적용하지 않고 사용자 선택 시에만 적용, 직원 수동 임의 변경 불가, 마일리지는 다른 혜택과 중복 가능, 마일리지를 제외한 할인/쿠폰/시즌특가/등급할인은 중복 불가, 시즌특가와 등급할인이 동시에 걸리면 더 큰 할인 1개만 적용 | D05 할인설정, D05 상품비교, D05 시즌가격, D03 결제처리, D02 회원상세 결제내역 | v1에서는 자동 적용, 중복 적용, 우선순위, 직원 수동 변경 허용 여부를 개발하지 않는다. 결제 화면에는 적용 가능한 후보와 조건만 보여주고, 실제 할인 금액은 운영자가 수동 입력·확정한다 |
| 마케팅 선택형 자동화 | 보류 60일 자동 미전환, 생일 쿠폰 자동 발급은 정책 활성 시 실행하는 방향만 확정. 실제 사용 여부, 기본값, 쿠폰 혜택 기준은 고객사 확인 필요 | D08 CRM 리드, D08 쿠폰/혜택, D08 자동 알림 | 고객사 확인 전까지 개발 대기 항목이다. 화면에는 정책 활성 시 동작 후보로 표시할 수 있으나 자동 실행 구현 기준으로 삼지 않는다 |
| 출석 N회 달성 알림 | 출석 N회 달성 트리거의 N값 | D08 자동 알림, D11/D04 출석 이벤트 연동 | 고객사가 N회를 확정하지 않아 개발 대기 항목이다. 트리거 목록에는 노출 가능하지만, 조건 입력·자동 발송은 확정 후 개발한다 |
| 폐점 데이터 보관 기간 | 지점 폐점 후 데이터 보관 N개월 | D10 본사관리 폐점 처리, D10 운영정책 | 고객사가 N개월을 확정해야 한다. 확정 전에는 폐점 상태 전환, 활성 회원 자동 환불·이관 안내까지만 개발 기준으로 삼고, 보관 기간 만료 후 자동 아카이브 실행은 개발 대기 항목으로 둔다 |
