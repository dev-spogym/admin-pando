# docs4 vs docs/admin 기획·정책 포함량 비교

작성일: 2026-05-29

## 비교 기준

- `docs4`: 0529 정본 범위로 지정된 `V1`, `V2`, `_공통`, `_개발사_전달사항.md`, `_정책확인필요.md`, `핏지니_정책.md`, README/INDEX만 포함했다.
- `docs/admin`: 현재 개발 기준으로 사용된 관리자 문서 중 `testcases`를 제외한 Markdown만 포함했다.
- TC는 별도 후속 검수 대상이므로 이번 비교에서 제외했다.

## 해석

정량 기준으로는 `docs/admin`이 기획·정책·세부 기능을 더 많이 포함한다. 특히 현재 개발에 필요한 화면설계서와 기능명세서가 화면/기능 단위로 쪼개져 있어, 화면 ID와 세부 기능 코드 수가 `docs4`보다 훨씬 많다.

다만 `docs/admin`이 더 많다는 것은 최신 정본이라는 뜻은 아니다. `docs/admin`에는 기존 `기획자`, `기획자2`, 회원앱 보조 참조, 키오스크/운영용 문서, 재번호화 정보가 함께 들어 있어 개발 상세 기준으로는 풍부하지만, 0529 기준의 V1/V2 범위 분리와 최신 정책 판단은 `docs4`가 더 명확하다.

## docs4가 더 강한 부분

- 0529 기준 V1/V2 범위가 명확하다.
- V1에서 개발할 항목과 V2/후속으로 둘 항목이 분리되어 있다.
- 정책 미확정, 후속 확인, 확정 파라미터 구분이 명확하다.
- 개발사 전달 기준과 개발 대기/제외 해석이 별도 문서로 정리되어 있다.
- `IOT-01~IOT-07`, `PAY-01-13~15`, `PAY-03-09` 같은 일부 최신 코드/정책은 `docs4`에만 보인다.

## docs/admin이 더 강한 부분

- 화면설계서와 기능명세서가 화면/기능 단위로 상세하게 분리되어 있다.
- `docs4`에 있는 화면 ID 239개를 모두 포함하고, 추가 화면 ID 40개를 더 갖고 있다.
- 세부 기능 코드가 훨씬 많아 개발 구현 단위 추적에는 유리하다.
- 운영용 기획문서와 기능명세서에 정책성 세부 항목이 많이 남아 있다.
- 현재 개발이 이 문서를 기준으로 진행된 만큼, 구현된 화면/코드와의 연결성은 `docs/admin` 쪽이 높을 가능성이 크다.

## 주의할 차이

`docs/admin`의 추가 40개 화면 ID는 전부 최신 V1 범위라고 보면 안 된다. 예를 들어 일부는 기존 화면 ID 대응표, 회원앱 D12 보조 참조, 키오스크 이관/제외, 기존 `기획자2` 재번호화 항목이다.

`docs/admin`에만 있는 2,144개 기능 코드도 전부 누락 기능으로 보면 안 된다. 많은 항목은 세부 하위 코드 또는 과거 기능명세서의 더 촘촘한 분해 코드다. 반대로 `docs4`에만 있는 53개 기능 코드는 실제 최신 정책 보강일 가능성이 있으므로 개발 문서와 대조가 필요하다.

## 결론

- **양적으로 더 많은 기획·정책·세부 구현 정보는 `docs/admin`에 있다.**
- **최신 0529 정본, V1/V2 범위 판단, 정책 미확정/후속/확정 기준은 `docs4`가 우선이다.**
- 개발 검수에서는 `docs/admin`으로 개발된 화면이 `docs4`의 V1 기준과 충돌하지 않는지 확인해야 한다.
- 충돌 시 판단 우선순위는 `docs4`가 맞다.

## 권장 작업

1. `docs4` V1 화면/기능 239개를 기준으로 `docs/admin` 개발 화면과 매핑한다.
2. `docs/admin`에만 있는 40개 화면 ID는 `V1 포함`, `V2/후속`, `회원앱/키오스크`, `구버전/중복`, `확인 필요`로 재분류한다.
3. `docs4`에만 있는 `IOT`, `PAY` 최신 코드 53개는 현재 개발 문서와 구현에 반영되어 있는지 별도 확인한다.
4. 정책 충돌은 `docs4/_정책확인필요.md`, `docs4/핏지니_정책.md`, `docs4/_개발사_전달사항.md` 기준으로 정리한다.
