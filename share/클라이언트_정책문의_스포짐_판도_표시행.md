# 클라이언트 운영 정책 문의 정리

대상 시트: `개발사 계약 및 상세 기능리스트_제로스트 피드백_260518` > `3.CRM (admin)_제로스트_0518논의`

확인 범위: T:W 열 범례에 `스포짐`, `판도`, `스포짐 판도`가 표시된 행

## 작성 기준

이 문서는 기능 구현 여부를 묻는 문서가 아닙니다. 기능 구조와 화면은 `docs2` 기획 기준으로 판도에서 정의한 것으로 보고, 스포짐 운영자가 실제로 사용할 때 필요한 정책값만 질문합니다.

클라이언트 전달 방식:
- 기획 코드명은 내부 추적용입니다. 클라이언트에게는 각 항목의 `기능 배경`을 먼저 설명한 뒤 질문합니다.
- `현재 임시 기획 기준`은 확정 정책이 아니라, 판도에서 우선 잡아둔 기준안입니다.
- 스포짐 답변이 현재 기준과 다르면 docs2 정책/화면/자동화 기준을 수정해야 합니다.

질문에서 제외한 것:
- 기능을 넣을지 말지 묻는 질문
- 버튼, 화면, 탭, 차트 등 UI 구성 자체를 되묻는 질문
- 우리가 이미 기획한 발송 채널, 화면 동작, 데이터 표시 방식을 다시 확인하는 질문

질문에 포함한 것:
- 운영자가 어떤 기준으로 판단해야 하는지
- 누가 승인/처리/수정할 수 있는지
- 자동 처리와 수동 처리의 경계가 어디인지
- 예외 상황에서 어떤 운영 원칙을 적용해야 하는지
- 기존 운영 데이터나 고객사 정책이 있어야만 확정 가능한 기준값

## 1. HQ-03-04 액션 큐 우선순위 정책

시트 행: 117  
대상: 스포짐  
관련 docs2: `docs2/D10-본사관리/본사관리.md` 액션 큐

기능 배경:
- 액션 큐는 운영자가 오늘 먼저 처리해야 할 일을 모아 보여주는 업무 목록입니다.
- 예를 들어 상담 미처리, 방문 후 미등록, 만료 대상 재등록 상담 같은 업무가 여기에 올라옵니다.

현재 임시 기획 기준:
- 액션 큐는 운영자가 오늘 처리해야 할 업무를 `긴급 / 우선 / 일반 / 완료가능`으로 구분해 보여줍니다.
- 상담, OT, 재등록, 만료 알림 대상 등 운영 후속 조치가 액션 큐에 노출됩니다.

스포짐에 확인할 질문:
1. `긴급 / 우선 / 일반 / 완료가능`을 나누는 스포짐 운영 기준은 무엇인가요?
   - 예: 만료 D-day, 미처리 경과 시간, 상담 예정일, 등록 가능성, 매출 규모, 고객 등급
2. 전화 문의 후 미방문, 방문 후 미등록, 상담 결과 미기입, 재등록 상담 대상은 각각 며칠까지 미처리되면 상위 우선순위로 올려야 하나요?
3. 액션 큐 우선순위는 전 지점 공통 기준인가요, 지점장이 지점별로 조정할 수 있어야 하나요?
4. 액션 큐 항목을 완료 처리할 수 있는 운영 권한은 누구에게 있나요?
   - 예: 담당자 본인만, 지점장/매니저 대리 처리 가능, 본사는 조회만 가능
5. 완료 처리 시 사유 또는 메모를 필수로 남겨야 하는 항목이 있나요?

스포짐 정책 미확정 시 현재 기획 처리:
- 액션 큐는 표시하되, 자동 우선순위 산정은 기본 임시 기준으로 두고 스포짐 확정 후 조정합니다.

## 2. CLS-09-06 일정 요청 미처리 기준

시트 행: 362  
대상: 스포짐

기능 배경:
- 일정 요청 미처리 기준은 회원/직원/강사의 요청이 일정 시간 이상 처리되지 않았을 때 운영자에게 경고하는 기준입니다.
- 이 기준이 있어야 미처리 배지, 오늘의 처리 업무, 담당자 책임자를 정할 수 있습니다.

현재 임시 기획 기준:
- 일정 요청 처리 화면에는 미처리 배지와 SLA 초과 배지가 표시됩니다.
- Today Tasks에는 일정 요청 미처리 항목이 운영 태스크로 표시됩니다.

스포짐에 확인할 질문:
1. 일정 요청은 몇 시간 이상 처리되지 않으면 SLA 초과로 보나요?
   - 현재 기획 임시값: 24시간
2. SLA 초과 시 실제 운영 책임자는 누구인가요?
   - 예: 담당 강사, 지점장, 매니저, 본사 운영 담당
3. 담당자가 휴무/퇴사/권한 없음 상태일 때 미처리 요청은 누구에게 이관해야 하나요?
4. 요청자가 회원인 경우와 직원/강사인 경우의 처리 기한이 달라야 하나요?
5. SLA 초과 이력은 운영 평가나 담당자 성과에 반영하나요?

스포짐 정책 미확정 시 현재 기획 처리:
- 미처리 배지와 Today Tasks 표시는 유지하고, SLA 기준과 책임자 이관 정책은 확정 전까지 기본값으로 둡니다.

## 3. SAL-03-03 매출 통계 집계 운영 기준

시트 행: 413  
대상: 스포짐  
관련 docs2: `docs2/D03-매출관리/매출관리.md` 매출 통계

기능 배경:
- 매출 통계는 결제 데이터를 상품, 종목, 결제수단, 담당자, 법인권 등으로 나누어 보는 기능입니다.
- 분류 기준이 없으면 같은 매출도 지점/담당자/상품 통계에서 다르게 집계될 수 있습니다.

현재 임시 기획 기준:
- 매출 통계는 상품별, 상품타입별, 결제수단별, 종목별, 개월별, GX종목별, 법인권 기준으로 집계합니다.
- 화면/차트 구성은 docs2 기준으로 정의되어 있습니다.

스포짐에 확인할 질문:
1. 매출 통계에서 `법인권`으로 분류할 운영 기준은 무엇인가요?
   - 예: 월매출 자료의 `구분=법인권`, 특정 상품 코드, 결제 담당자 수기 분류
2. `GX종목별` 집계에서 스포짐이 실제로 사용하는 종목 분류명을 확정해 주세요.
   - 현재 기획 임시값: 요가, 필라테스, 스피닝, 줌바, GX 기타
3. 담당자별 매출에서 매출 귀속 기준은 무엇인가요?
   - 예: 결제 등록자, 상담 담당자, 인센티브 귀속자, 수업 담당자
4. 환불/취소 건은 매출 통계에서 어느 시점 기준으로 차감하나요?
   - 예: 결제일 기준 차감, 환불일 기준 차감, 월마감 후 별도 조정
5. 월마감 이후 매출 수정이 발생하면 과거 통계를 재계산하나요, 조정분으로 별도 표시하나요?

스포짐 정책 미확정 시 현재 기획 처리:
- 통계 화면은 유지하되, 법인권/GX/담당자 귀속/환불 반영 기준은 스포짐 운영 기준 확정 후 최종 고정합니다.

## 5. STF-04-04 퇴사 인수인계 정책

시트 행: 489  
대상: 스포짐  
관련 docs2: `docs2/D07-직원관리/직원관리.md` 직원 퇴사 처리

기능 배경:
- 퇴사 인수인계는 퇴사 직원이 맡고 있던 회원, 상담, 수업, 계약, 미수금 등을 다른 담당자에게 넘기는 절차입니다.
- 인수인계 기준이 없으면 퇴사 이후 담당자 공백이나 성과 귀속 문제가 생길 수 있습니다.

현재 임시 기획 기준:
- 퇴사 처리 시 담당 회원, 예약 수업, 진행 중 계약 등 운영 중인 업무를 인수인계합니다.
- 시스템은 인계자를 자동 선택하지 않고 운영자가 지정합니다.

스포짐에 확인할 질문:
1. 퇴사 시 반드시 인수인계해야 하는 대상 범위를 확정해 주세요.
   - 예: 담당 회원, 상담 리드, 예약 수업, PT/강습, 진행 중 계약, 미수금, 급여/정산, 마케팅 캠페인
2. 직무별로 인수인계 대상이 다른가요?
   - 예: FC, 트레이너, 골프 프로, 매니저, 스태프
3. 인계자를 지정하지 않은 항목이 있으면 퇴사 처리를 차단해야 하나요?
4. 퇴사일 이후 남아 있는 예약 수업/상담/계약은 자동 이관해야 하나요, 지점장이 수동 배정해야 하나요?
5. 퇴사 후 발생한 매출/재등록/상담 성과는 기존 담당자와 신규 인계자 중 누구에게 귀속하나요?
6. 퇴사 처리 후 기존 직원 계정은 즉시 잠금인가요, 퇴사일 도래 시 자동 잠금인가요?

스포짐 정책 미확정 시 현재 기획 처리:
- 인수인계 대상은 표시하되, 차단 조건과 성과 귀속은 스포짐 정책 확정 전까지 보류합니다.

현재 임시 기획 기준:
- 전자계약은 계약서 작성, 서명, 이력 조회, 재발송 흐름을 포함합니다.

4. 서명 완료 후 계약은 자동 확정인가요, 운영자 최종 확인 후 확정인가요?
5. 계약서 작성 후 서명 전에 전문 미리보기를 반드시 거쳐야 하나요?
6. 원격 서명 링크의 유효기간은 며칠인가요?
7. 원격 서명 링크 재발송은 횟수 제한이 필요한가요?
8. 완료된 계약서는 수정 불가인가요, 취소/재작성만 가능한가요?
9. 계약 해지, 계약 취소, 재작성 이력을 어떤 기준으로 남겨야 하나요?
10. 미성년자 회원 계약 시 보호자 동의/서명이 필요한 기준은 무엇인가요?

스포짐 정책 미확정 시 현재 기획 처리:
- 전자계약 화면 구조는 유지하되, 계약서 종류/수정 가능 항목/확정/재발송/해지 정책은 스포짐 확정 전까지 임시값으로 둡니다.

기능 배경:
- 예측 인사이트는 이탈 위험 회원이나 운영 리스크를 시스템이 계산해 운영자에게 참고 정보로 보여주는 기능입니다.
- 위험도 기준과 후속 조치 기준이 있어야 단순 정보인지, 실제 업무 지시인지 정할 수 있습니다.

현재 임시 기획 기준:
- 예측 인사이트는 시스템이 자동 생성하고 운영자는 결과를 확인한 뒤 수동 후속 조치를 진행합니다.
- 자동 메시지 발송, 자동 할인 적용, 자동 회원 상태 변경은 하지 않습니다.

스포짐에 확인할 질문:
1. 이탈 위험 회원으로 분류할 위험도 기준값은 얼마로 둘까요?
   - 현재 기획 임시값: 0.7 이상
2. 위험도 등급을 나눈다면 몇 단계로 운영하나요?
   - 예: 관심, 주의, 고위험
3. 위험 회원에게 권장할 후속 조치 목록을 확정해 주세요.
   - 예: 전화 상담, 재등록 안내, 담당자 케어 배정, 쿠폰 지급 검토
4. 권장 조치를 실행했는지 여부를 누가 완료 처리하나요?
5. 권장 조치 미처리 상태가 며칠 이상 지속되면 상위 관리자에게 노출해야 하나요?
6. 예측 인사이트를 운영 KPI나 담당자 평가에 반영하나요, 참고 정보로만 사용하나요?

스포짐 정책 미확정 시 현재 기획 처리:
- 인사이트는 참고 정보로 표시하고, 위험도 기준/권장 조치/완료 처리 정책은 확정 후 반영합니다.

## 8. MKT-03 쿠폰 운영 정책

시트 행: 662, 664~666  
대상: 스포짐 판도  
관련 docs2: `docs2/D08-마케팅/마케팅.md` 쿠폰 관리, `docs2/_정책미확정_확인필요.md`

기능 배경:
- 쿠폰은 재등록 권유, 생일 혜택, 이벤트, 리퍼럴 보상 등에 사용할 수 있는 회원 혜택입니다.
- 발급 후 메시지, 삭제/중단, 환불 시 복원 기준이 정해져야 결제/마케팅 정책이 충돌하지 않습니다.

현재 임시 기획 기준:
- 쿠폰 생성, 발급, 수정, 삭제/중단 전환, 사용률 통계를 관리합니다.
- 쿠폰 발급 후 안내 메시지 정책은 미확정입니다.

스포짐에 확인할 질문:
1. 쿠폰 발급 후 회원에게 안내 메시지를 항상 보내야 하나요, 특정 쿠폰/상황에서만 보내야 하나요?
2. 쿠폰 안내 메시지가 필요한 경우 기본 문구는 본사 공통인가요, 지점별 수정이 가능한가요?
3. 쿠폰 발급 메시지 발송 실패 시 쿠폰 발급은 성공으로 유지하나요, 발급도 실패 처리하나요?
4. 쿠폰 발급 대상 그룹의 기본 운영 분류를 확정해 주세요.
   - 예: 전체 회원, 활성 회원, 만료 회원, 특정 등급, 장기 미방문 회원
5. 발급/사용 이력이 있는 쿠폰은 영구 삭제하지 않고 `중단` 상태로 전환하는 정책으로 확정해도 되나요?
6. 쿠폰 사용률 통계에서 환불로 복원된 쿠폰은 사용 수에서 제외하는 기준으로 확정해도 되나요?
7. 쿠폰 발급/중단/삭제 권한은 누가 가지나요?
   - 예: 본사만, 지점장, 매니저

스포짐 정책 미확정 시 현재 기획 처리:
- 쿠폰 발급 자체는 가능하게 두고, 안내 메시지/권한/삭제 정책은 확정 전까지 보수적으로 제한합니다.

## 9. MKT-08 SMS/카카오 대량 발송 운영 정책

시트 행: 680~682, 685~687  
대상: 스포짐  
관련 docs2: `docs2/D08-마케팅/마케팅.md` SMS/카카오 대량 발송

기능 배경:
- 대량 발송은 이벤트, 재등록 권유, 만료 안내처럼 여러 회원에게 한 번에 메시지를 보내는 기능입니다.
- 승인 권한, 발송 한도, 비용 귀속, 실패 처리 기준이 없으면 오발송/과금/민원 리스크가 생깁니다.

현재 임시 기획 기준:
- 대량 발송은 운영자가 대상과 채널을 선택해 발송하고, 결과와 비용을 이력으로 관리합니다.
- 카카오 실패/비친구/미수신 대상은 SMS로 자동 전환하지 않는 기준입니다.

스포짐에 확인할 질문:
1. 대량 발송 승인 권한은 누구에게 있나요?
   - 예: 본사만, 지점장, 매니저
2. 발송 가능 시간 제한이 필요한가요?
   - 예: 야간/휴일 광고성 발송 제한, 특정 시간대만 허용
3. 지점별 월 발송 한도 또는 비용 한도가 있나요?
4. 발송 비용은 본사 부담인가요, 지점별 비용으로 귀속하나요?
5. 카카오 실패/비친구/미수신 대상은 SMS 자동 전환 없이 실패/제외로 처리하는 정책으로 확정해도 되나요?
6. 대량 발송 대상에서 반드시 제외해야 하는 회원 조건은 무엇인가요?
   - 예: 수신 거부, 휴면, 탈퇴, 미성년자, 특정 민감 상태
7. 발송 이력과 실패 사유는 얼마 동안 보관해야 하나요?
8. 발송 전 승인 또는 2인 확인 절차가 필요한 발송 조건이 있나요?
   - 예: 특정 인원수 이상, 특정 비용 이상, 전체 회원 대상

스포짐 정책 미확정 시 현재 기획 처리:
- 대량 발송 화면 구조는 유지하되, 실제 발송 승인/한도/비용/제외 조건은 스포짐 운영 정책 확정 후 적용합니다.

- 원천 데이터와 필수 필드, 매핑/검수 기준이 있어야 이관 후 회원 잔여횟수와 수업 이력이 맞게 표시됩니다.

현재 임시 기획 기준:
- 회원 상세 레슨 탭은 회원별 레슨 기록을 조회/추가하고, 서명/완료/메모 정보를 함께 관리합니다.

스포짐에 확인할 질문:
1. 마이그레이션해야 하는 원천 데이터는 무엇인가요?
   - 예: 기존 센터 운영 엑셀, 기존 시스템 DB, 모바일 임시 저장 데이터, 기타 수기 자료
2. 반드시 이전해야 하는 필수 필드를 확정해 주세요.
   - 예: 회원명, 회원 ID, 담당 강사, 수업명, 수업일시, 상태, 서명 URL, 완료일시, 메모
3. 기존 데이터에 회원/강사 식별자가 없거나 불일치하면 어떤 기준으로 매칭하나요?
4. 중복 레슨 기록은 어떤 기준으로 중복 판단하나요?
5. 미서명/서명 완료/진행 중 상태는 어떤 기준으로 매핑하나요?
6. 과거 수정 이력까지 이전해야 하나요, 최종 상태만 이전하면 되나요?
7. 마이그레이션 후 스포짐이 검수해야 하는 리포트 항목은 무엇인가요?
   - 예: 전체 건수, 성공/실패 건수, 누락 필드, 중복 제거 건수, 수동 확인 대상

스포짐 정책 미확정 시 현재 기획 처리:
- 신규 레슨 기록 관리 기능과 데이터 이전 작업을 분리하고, 이전 정책 확정 전까지 마이그레이션은 별도 협의 항목으로 둡니다.
