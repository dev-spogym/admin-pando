# MA-110 QR 입장 페이지

## 1. 화면 메타 정보

| 항목 | 값 |
|---|---|
| 작성일 / 버전 / 상태 | 2026-05-23 / v1.0 / 정합화 완료 |
| 도메인 | C01 공통-회원 |
| 화면 ID | MA-110 |
| 화면명 | QR 입장 |
| 화면 유형 | 풀스크린 (가로 모드 자동 전환 옵션) |
| 라우트 | `fitgenie://qr` (탭바 QR 또는 홈 카드) |
| 우선순위 | P0 (출시 필수) |
| 기능코드 | MFN-110 |
| 연계 화면 | MA-100 홈, MA-111 출석 이력, CRM 키오스크/게이트 |
| 호출 모달 | DLG 없음 (전체 풀스크린 QR) |

## 2. 화면 개요와 목적

회원이 본인 고유 QR 코드를 풀스크린으로 표시하여 센터 키오스크·출입 게이트에 스캔해 자동 출석 처리하는 화면입니다. QR 코드는 회원 ID + 타임스탬프 + 회전 토큰으로 구성되며 7일마다 자동 갱신되어 보안을 유지합니다.

이 화면이 다루는 운영 흐름은 회원이 헬스장에 도착해 키오스크 또는 게이트 앞에서 본 화면을 열고 QR을 스캔시키는 단순한 시나리오이며, CRM 출석 시스템과 자동 연동되어 PT 횟수 차감(CLS-07)·회원 last_visit_at 갱신·자동 노쇼 해제 같은 후속 처리가 트리거됩니다.

## 3. 진입 경로와 인접 화면

진입 경로: 탭바의 QR 버튼, 홈(MA-100)의 오늘 수업 카드 [QR 입장] 버튼, 푸시 알림 "곧 수업 시작" 클릭 시 딥링크 `fitgenie://qr`.

빠져나가는 인접 화면: 닫기 X 또는 5분 무동작 시 자동 복귀 (이전 화면). QR 스캔 성공 후 키오스크 측 처리 → 회원 앱에는 출석 알림 푸시. 화면 자체는 닫혀도 출석은 CRM에 기록됩니다.

## 4. 레이아웃과 UI 구성

- **풀스크린 QR 코드**: 화면 가로 폭 80% 정사각형, 흰 배경 (스캐너 인식률), 검은 QR
- **시스템 밝기 자동 100%**: 화면 진입 시 OS 밝기 최대화
- **회원명·이용권 정보**: QR 아래 작은 글씨 ("{회원명} / {이용권} {잔여}")
- **남은 갱신 시간**: "QR 갱신까지 N일" 작게 표시
- **새로고침 버튼**: QR 만료 시 활성, 수동 갱신
- **닫기 X**: 우상단 (다크 배경 위 흰색)

## 5. 탭 구성과 탭별 동작

탭은 없습니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

- **닫기 X**: 풀스크린 닫고 OS 밝기 복원, 이전 화면으로 복귀
- **새로고침 버튼**: `POST /api/member/qr-refresh` → 새 토큰 발급 + 화면 갱신
- **5분 무동작**: 자동으로 화면 닫힘 + OS 밝기 복원 (보안)
- **백그라운드 진입**: 30초 후 자동 닫힘

## 7. 호출되는 모달 동작

본 화면은 모달을 호출하지 않습니다. 출석 결과는 키오스크 측에서 처리되며 회원 앱에는 푸시 알림으로 결과 통보됩니다.

## 8. 토스트와 확인 팝업과 알럿

성공 토스트 (스캔 후 푸시 알림): "출석 완료!"(녹색).

실패 토스트 (스캔 후 푸시): "이용권을 확인해주세요"(만료), "오늘 이미 출석했어요"(중복), "예약 제한 중입니다"(페널티).

인라인 안내: QR 갱신 임박(D-1) 시 "곧 QR이 갱신됩니다", QR 만료 시 "QR이 만료됐어요. 새로고침해주세요".

## 9. 데이터 흐름과 외부 연동

**QR 생성 API**: `GET /api/member/qr` → 회원 ID + 타임스탬프 + 회전 토큰 + 만료일. 7일 캐시.

**QR 갱신 잡**: 매일 자정 백엔드 배치가 7일 경과 QR 자동 갱신. 회원 앱은 다음 진입 시 자동 갱신된 토큰 사용.

**키오스크 스캔 처리** (회원앱 외부): 키오스크가 QR을 스캔하면 `POST /api/attendance/checkin` → CRM 출석 시스템 → 결과 3종 분류(성공/실패/중복).

**자동 횟수 차감**: PT 수업 출석 시 docs2 CLS-07 멱등성 키 적용 + 자동 차감.

**자동 노쇼 해제**: 예약된 수업에 출석 시 자동 노쇼 페널티 자동 해제(A05 정합).

**위변조 보안**: QR 토큰은 백엔드 서명 + 디바이스 시각 검증으로 위변조 방지. 위변조 시도는 owner+ 보안 알림.

**오프라인 큐잉**: 네트워크 단절 시 스캔 결과 키오스크 측에 큐잉되어 복구 후 동기화.

## 10. 화면 상태와 예외 처리

| 상태 | 설명 |
|---|---|
| 정상 | QR 표시 + 밝기 100% |
| QR 만료 (7일) | "만료됐어요" + 새로고침 버튼 활성 |
| 자동 갱신 | "갱신됨" 토스트 (드물게 발생) |
| 회원 비활성 | "이용권을 확인해주세요" + QR 표시 차단 |
| 정지 플래그 | "이용 제한 중입니다" 안내 (QR 자체는 표시 가능, 출석은 키오스크에서 차단) |
| 페널티 적용 중 | "예약 제한 중입니다" 안내 (출석은 가능, 예약은 차단) |
| 네트워크 단절 | 마지막 캐시 QR 표시 (7일 이내) + 오프라인 배지 |
| 백그라운드 30초 | 자동 닫힘 (보안) |

예외: 이용권 만료 회원의 출석은 키오스크에서 차단되고 토스트 안내. QR 위변조 시도(서명 검증 실패)는 보안 로그 + 즉시 차단. 디바이스 시각 변조 감지 시 QR 표시 차단. 같은 날 중복 체크인은 키오스크 측에서 차단되고 결과=중복으로 별도 카운트.

## 11. 권한별 처리

`member` role만 본인 QR 표시 가능합니다. 다른 role(`trainer`, `golf_trainer`, `fc`, `staff`)은 QR 본인 표시가 아닌 수동 출석(MA-520) 또는 강사 본인 식별 화면을 사용합니다.

## 14. 핵심 디자인 요청사항

- 풀스크린 QR은 흰 배경 + 검은 QR (스캐너 인식률)
- 화면 진입 시 OS 밝기 100% 강제 (밝은 환경에서도 인식)
- QR 코드 크기는 가로 폭 80% 정사각형
- 닫기 X는 다크 배경 위 흰색 아이콘
- 회원명·이용권 정보는 작게 (QR 인식 방해 방지)
- 다크 모드에서도 QR 영역은 흰 배경 고정
- 가로 모드 전환 옵션 (가로 키오스크 사용 시)
- 5분 무동작 자동 닫힘은 부드러운 fade-out

## 15. 운영 정책 (이 화면에 연결된 부분)

**QR 갱신 정책**은 회원별 QR이 7일마다 자동 갱신된다는 것입니다. 매일 자정 백엔드 배치가 만료된 QR을 자동 갱신하고, 회원 앱은 다음 진입 시 갱신된 토큰을 받아옵니다. 회원이 수동으로 새로고침할 수도 있습니다.

**자동 출석 정책**은 QR 스캔 즉시 CRM 출석 시스템에 INSERT되며 결과 3종(성공/실패/중복) 중 하나로 분류된다는 것입니다. docs2 _공통/상태전이.md 정본을 따릅니다.

**자동 횟수 차감 정책**은 PT 수업 출석 시 docs2 CLS-07 멱등성 키 적용으로 자동 차감된다는 것입니다. 동일 회원·동일 수업 중복 차감을 방지합니다.

**자동 노쇼 해제 정책**은 예약된 수업에 출석 시 자동 노쇼 페널티가 자동 해제된다는 것입니다 (A05 정합).

**보안 정책**은 QR 토큰이 백엔드 서명 + 디바이스 시각 검증으로 위변조를 방지한다는 것입니다. 위변조 시도(서명 실패, 시각 변조)는 보안 로그에 기록되고 owner+ 알림이 발송됩니다.

**5분 무동작 자동 닫힘 정책**은 QR 화면이 5분 동안 사용자 입력 없으면 자동 닫히고 OS 밝기가 복원된다는 것입니다. 보안과 배터리를 위한 정책입니다.

**중복 체크인 정책**은 동일 회원이 10분 이내 재시도하면 결과=중복으로 별도 카운트되며 실패 건수에 합산되지 않는다는 것입니다(docs2 _공통/상태전이.md 정본).

**이용권 검증 정책**은 만료 회원·정지 회원·페널티 회원의 출석은 키오스크 측에서 차단되며 회원 앱에는 푸시로 사유가 안내된다는 것입니다. QR 표시 자체는 가능하지만 출석은 거부됩니다.

**오프라인 큐잉 정책**은 키오스크 측 네트워크 단절 시 스캔 결과를 로컬 큐에 저장하고 복구 후 동기화한다는 것입니다. 회원은 화면에 마지막 캐시 QR(7일 이내)을 표시받습니다.

**감사 로그 정책**은 모든 출석 시도(성공/실패/중복)와 위변조 의심 이벤트가 docs2 SCR-097 감사 로그에 비동기 INSERT된다는 것입니다.

이상의 모든 정책은 이 화면을 구현·운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다.
