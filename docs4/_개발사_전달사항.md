# 개발사 전달사항

작성일: 2026-05-29

`docs4`는 개발사가 도메인별 본문 MD와 운영정책 MD를 기준으로 구현할 수 있도록 정리한 개발 전달 문서입니다. 정책 미확정 또는 고객사/판도 확인 전 개발 대기 항목을 제외하면, 현재 확정 범위는 `docs4`만 보고 개발 착수가 가능합니다.

단, 문서에 언급된 모든 후속 자동화, PG 결제링크, 외부 Google Spreadsheet 산식 기반 자동 집계까지 전부 확정 개발 범위로 해석하면 안 됩니다. 해당 항목은 `docs4/_정책확인필요.md` 또는 각 도메인 본문에서 개발 대기/후속 확인으로 분리되어 있습니다.

## 1. 개발 기준

- `docs4/V1`: V1 개발 기준입니다. V1 구현자는 먼저 해당 도메인의 본문 MD와 `운영정책.md`를 확인합니다.
- `docs4/V2`: V2 또는 후속 범위 기준입니다. V1 개발 중 V2 문서만 보고 기능을 확장하지 않습니다.
- `docs4/_공통`: 권한, 알림, KPI, NFR, 외부연동, 자동화처럼 V1/V2가 함께 쓰는 기준입니다. V1 개발 시에는 V1 도메인 문서에서 참조한 공통 기준만 V1 구현 기준으로 봅니다.
- `docs4/_정책확인필요.md`: 고객사/판도 확인 또는 외부 자료 제공이 필요한 항목입니다. 확인 전에는 최종 완료 기준으로 보지 않습니다.
- `docs4/_scope`, `docs4/registry`, `docs4/reports`, `docs4/정합성체크`: 검증/내부 관리 산출물입니다. 개발 구현 본문으로 보지 않습니다.

## 2. 구현 가능 판단

현재 검증 기준으로 `docs4`는 확정 범위 개발 기준으로 사용할 수 있습니다.

| 도메인 | 판단 | 개발 기준 |
|---|---|---|
| D01 공통 | 가능 | 공통 화면, 세션, 오류, 네비게이션 기준을 따른다. |
| D02 회원관리 | 가능 | 회원 상태, 상세, 결제내역 연계 기준을 따른다. 단 결제링크 관련 버튼은 PAY-06 확정 후 적용한다. |
| D03 매출관리 | 조건부 가능 | 현장 결제, 수기 수납, 분할 수납, 미수금 전환은 개발 가능하다. PG 결제링크, webhook, 자동 만료/알림은 개발 대기다. |
| D04 수업관리 | 가능 | 수업 유형, 예약, 출석, 차감, 노쇼 기준을 따른다. |
| D05 상품관리 | 조건부 가능 | 상품, 가격, 할인 관리 화면은 개발 가능하다. 할인/쿠폰/마일리지/시즌특가 자동 적용 우선순위는 후속 확인 항목이다. |
| D06 시설관리 | 가능 | 락커, 사물함, 운동복, 장비 상태와 자동 회수 정책 연계를 따른다. |
| D07 직원관리 | 가능 | 근태, 급여, 명세서, 퇴사 처리 기준을 따른다. |
| D08 마케팅 | 조건부 가능 | 리드, 메시지, 쿠폰, 마일리지 기본 기능은 개발 가능하다. A/B 테스트, 쿠폰 발급 안내 자동 메시지 등은 고객사 확인 후 개발한다. |
| D09 설정관리 | 가능 | 권한, 키오스크/IoT 설정, 공지, 백업 기준을 따른다. |
| D10 본사관리 | 조건부 가능 | 지점, 정책, 본사 운영 화면은 개발 가능하다. 외부 Google Spreadsheet 산식 기반 자동 집계는 자료 제공 후 확정한다. |
| D11 통합운영 | 가능 | 통합 출석, 락커, 건강 연동 기준을 따른다. |

## 3. 개발 대기 / 제외 기준

아래 항목은 개발 누락이 아니라 확인 전 개발 대기 또는 후속 범위입니다.

- PG 결제링크, webhook, 자동 만료, 자동 알림, 활성 링크 제한
- 할인/쿠폰/마일리지/시즌특가/등급할인 자동 적용 우선순위
- 쿠폰 발급 안내 메시지 자동 발송 정책
- A/B 테스트 자동 분배, 우수안 채택, 캠페인 연동 자동화
- 폐점 데이터 보관 기간 만료 후 자동 아카이브
- 외부 Google Spreadsheet 산식 기반 매출, OT, 보고 지표 자동 집계
- 환불/취소 자동 계산 산식

확인 답변 또는 원천 자료가 오면 해당 도메인 본문 MD와 `운영정책.md`에 확정값을 반영한 뒤 개발 기준으로 전환합니다.

## 4. 미확정으로 보지 않는 항목

다음은 `N` 또는 조건값이 있어도 미확정 정책이 아닙니다.

- 기본값이 문서에 명시된 항목
- 본사 정책 세트에서 관리하는 `HQ-09`, `NFR-05` 계열 N일/D-N 기준
- 설정 화면에서 운영자가 변경하는 정책 파라미터
- `docs4/_정책확인필요.md`의 "미확정 아님" 섹션에 정리된 항목

이 항목은 문서에 명시된 기본값 또는 설정 위치를 기준으로 구현합니다.

## 5. 검증 결과

2026-05-29 기준 검증 결과는 다음과 같습니다.

| 검증 | 결과 |
|---|---|
| `docs_fact_check` | `ERROR=0`, `WARN=0` |
| docs4 내부 정의 충돌 | `conflict_groups=0` |
| 수량 표현 리뷰 후보 | `count_mismatches=26` |
| V1 참조/기능 무결성 | `reference_issues=0`, `feature_link_issues=0`, `definition_set_issues=0` |
| V2 정책 링크 무결성 | `policy_headings=103`, `linked_codes=239`, `index_rows=239`, `errors=0` |

`count_mismatches=26`은 실제 값 충돌이 아니라 숫자가 포함된 문장을 자동 추출한 리뷰 후보입니다. 현재 값 집합 충돌은 발견되지 않았습니다.

## 6. 전달 문구

개발사에는 아래 기준으로 전달합니다.

> `docs4`는 확정 범위 개발 기준으로 사용할 수 있습니다. 단, `docs4/_정책확인필요.md` 및 각 도메인 본문에 "고객사 확인 전 개발 대기", "후속 확인", "확정 후 개발"로 명시된 항목은 현재 구현 완료 범위에서 제외합니다. 기본값이 정해졌거나 본사 정책 세트/설정 화면에서 관리하는 N값은 미확정 정책이 아니라 구현 가능한 정책 파라미터로 봅니다.
