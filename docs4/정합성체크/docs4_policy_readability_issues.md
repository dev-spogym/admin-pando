# docs4 운영정책 가독성 점검 리포트

작성일: 2026-05-28

## 정리 기준

- 각 도메인의 본문 `md`가 화면·다이얼로그 구현 순서의 기준이다.
- 각 도메인의 `운영정책.md`는 본문 순서를 따라 읽을 수 있어야 한다.
- 운영정책의 `자동화 정책`, `운영 예외 처리` 표는 마지막 `연결 기능` 앵커의 본문 등장 순서를 기준으로 정렬한다.
- 정책 미확정 또는 자료 제공 필요 항목은 `docs4/_정책확인필요.md`에서만 관리한다.

## 이번에 보정한 문제

| 구분 | 대상 | 조치 |
|---|---|---|
| 운영정책 순서 | V1/V2 도메인 운영정책 14개 파일 | `연결 기능` 앵커 기준으로 자동화/예외 표 행을 본문 등장 순서에 맞게 재정렬 |
| 다중 처리 UX | V1 D07 `SCR-062 직원 퇴사 처리` | 단수 직원 기준 표현을 1명 이상 직원 기준으로 수정하고, 직원별 퇴사일/사유 override, 직원별 인수인계, 일부 실패 처리 기준을 본문에 명시 |
| 진입/확정 단계 구분 | V1 D07 `DLG-060-002 직원 삭제(퇴사 처리) 확인` | 최종 퇴사 실행 다이얼로그가 아니라 SCR-062 진입 전 사전 확인 단계임을 명시 |
| 라인 앵커 오해 | V1 D07 운영정책 `PAY-STF-03-01`, `PAY-STF-03-06` | `01`이 경로 뒤 숫자로 읽히지 않도록 기능 suffix를 앞에 배치하고, 자기 참조형 정책 설명을 일반 문장으로 정리 |
| V2 읽기 기준 | `docs4/V2_INDEX.md` | V2가 V1 기준선을 대체하는 독립 완전본이 아니라 V1 상속 + V2 변경/추가 문서임을 명시 |
| 외부 연동 DB 산식 | `docs4/_정책확인필요.md` | 판도에 확인할 원천 시트·컬럼·산식·집계 단위·스냅샷 저장 여부 질문을 추가 |

## 남은 주의점

| 이슈 | 판단 |
|---|---|
| V2 문서의 V1 참조가 많음 | V2는 V1 기준선 위의 변경 범위 문서이므로 의도된 구조다. 단, V2 개발자에게는 `V2_INDEX.md`의 상속 기준을 반드시 함께 전달해야 한다. |
| 외부 Google Spreadsheet/운영 DB 산식 | 개발사가 추정하면 매출, OT, 주간/월간 보고 집계가 틀어질 수 있다. 판도에서 원천 산식과 컬럼 정의를 제공하기 전에는 자동 집계 확정으로 보지 않는다. |
| 본문 전체를 정책 순서로 재작성하는 방식 | 문서 diff와 라인 앵커 drift가 커지므로 이번에는 운영정책 표 행 정렬과 실제 혼동 구간 보강으로 제한했다. |
