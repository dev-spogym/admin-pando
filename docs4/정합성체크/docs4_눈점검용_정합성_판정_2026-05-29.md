# docs4 눈점검용 정합성 판정표

작성일: 2026-05-29  
검토 범위: `docs4` 내부 문서만 확인  
작성 목적: 사용자가 원본 체크리스트를 눈으로 다시 검수할 수 있도록, 각 항목이 현재 `docs4` 문서의 실제 문제인지 판정한다.

반영 기준 추가: `docs4/_개발사_전달사항.md` 확인 결과, 후속 자동화·PG 결제링크·외부 Google Spreadsheet 산식 기반 자동 집계·환불/취소 자동 계산 등은 개발 대기 또는 후속 범위로 명시되어 있다. 따라서 해당 범주는 "정책 자체 오류"가 아니라 "도메인 본문/운영정책의 로컬 표기 보강 필요"로 판정한다.

## 판정 기준

| 판정 | 의미 |
|---|---|
| ✅ 유효 | `docs4` 내부에서 실제 문제로 확인됨 |
| 🟨 부분 유효 | 문제 방향은 맞지만, 라인 번호·설명·심각도·범위를 보정해야 함 |
| ⚠️ 재검토 | 현재 `docs4` 기준으로 문제성이 약하거나 이미 일부 정리되어 있음 |
| ⏸ 보류 | 추가 원문 대조 또는 별도 판단 필요 |

> 주의: 원본 체크리스트의 라인 번호는 일부 이동되어 있을 수 있다. 눈점검 시에는 라인 번호만 보지 말고 `파일 경로 + 코드 heading + 주변 본문` 기준으로 확인한다.

---

## 전체 결론

원본 체크리스트의 상당수는 `docs4` 문서 자체의 정합성 문제로 볼 수 있다.

다만 `docs4/_개발사_전달사항.md`를 함께 보면, 일부 항목은 이미 전역 기준에서 "개발 대기/후속 범위"로 분리되어 있다. 이 경우에는 기능 정책이 잘못 확정된 것이 아니라, 각 도메인 본문이나 `운영정책.md` 안에서도 같은 단서가 보이도록 보강하는 문제로 보는 것이 맞다.

특히 아래 유형은 실제 문제가 맞다.

- V1/V2 경로 오매핑
- ID 매핑 누락 또는 잘못된 앵커
- 운영정책 절 제목과 본문 내용 불일치
- 다른 화면/다이얼로그에서 복사된 예외처리 잔존
- V1 범위에 미확정 또는 후속 기능이 확정처럼 보이는 로컬 표현이 남아 있음
- 상태값, 권한, 자동화 기준 불일치
- 기능 코드 정의 누락 또는 dangling 참조
- 구현 전에 정책 기준을 더 명확히 해야 하는 항목

다만 일부 항목은 그대로 수정 대상으로 삼기 전에 `부분 유효`, `재검토`, `보류`로 조정하는 것이 맞다.
