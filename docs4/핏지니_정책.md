# docs4 확정 정책집

작성일: 2026-05-28
확정 정책 소스: `docs4/V1`, `docs4/_공통`
제외 대조 소스: `docs4/_정책확인필요.md`

이 문서는 `docs4` 안에서 개발 기준으로 이미 닫힌 운영 정책만 모은 확정 정책집입니다. 점검 결과, 문의 문장, 후보안, 고객사 확인 전 개발 대기 항목은 본문 정책으로 섞지 않습니다.

## 0. 적용 원칙

- V1 개발 기준은 `docs4/V1`의 도메인 문서를 우선한다.
- `_공통` 문서는 권한, 상태, 알림, NFR, 외부연동, 자동화처럼 여러 도메인이 공유하는 기준으로 사용한다.
- `_공통`에 V2 경로 또는 후속 항목이 함께 있어도 V1 구현 지시로 보지 않는다.
- 동일 ID가 V1/V2 양쪽에 있으면 V1 문서의 경로와 정의를 우선한다.
- API endpoint, DB table, queue, RLS, 백엔드 내부 구현 방식은 본 정책집의 범위가 아니라 개발사 설계 범위다.
- 이 문서 하단의 "V1 확정 제외 / 개발 대기 항목"은 V1 개발 범위에서 제외하거나 확정 전 구현하지 않는 기준이다.

## 1. 권한 / 역할 정책

- 관리자 웹 표준 역할 코드는 `superAdmin`, `primary`, `owner`, `manager`, `fc`, `trainer`, `staff`, `readonly` 8종으로 고정한다.
- `owner`의 화면 표시명은 `Owner(지점장)`으로 통일한다.
- `trainer`는 관리자 웹 기본 역할이다. PT트레이너, GX강사, 골프강사는 직원 직무값이며 기본 권한 템플릿은 `trainer`로 지정한다.
- 카운터/현장 지원 담당자는 별도 역할을 만들지 않고 `staff` 역할로 통일한다.
- 직무값은 인사/운영 분류이고, 역할값은 메뉴 접근과 기능 권한을 제어하는 값이다.
- 본사 권한자는 통합 모드에서 전 지점 조회와 정책 관리를 수행한다.
- 지점 권한자는 소속 지점 데이터의 일상 운영 처리를 수행한다.
- 권한 부족 액션은 기본적으로 버튼을 숨긴다.
- 직접 URL 진입 권한이 없으면 접근 제한 화면으로 처리한다.
- 변경, 삭제, 복구, 정산, 권한 변경, 정책 저장, 백업/복원 등 민감 액션은 히스토리 로그 기록 대상이다.

## 2. 인증 / 계정 / 세션 정책

- 직원 1명은 로그인 계정 1개를 기본 원칙으로 한다.
- 직원 상태와 로그인 계정 상태는 함께 관리한다.
- 계정 상태는 `ACTIVE`, `LOCKED`, `INACTIVE`를 사용한다.
- 5회 연속 로그인 실패 시 계정은 30분 동안 자동 잠금 처리한다.
- 잠금 중에는 남은 시간을 표시하고, 잠금 중 추가 시도는 실패 카운트를 증가시키지 않는다.
- 30분 경과 후 자동 해제하거나 `superAdmin`, `primary`, `Owner(지점장)`이 수동 해제한다. Owner는 소속 지점 직원 계정만 해제할 수 있다.
- 장시간 자리 비움은 30분 무활동 기준으로 자동 로그아웃 처리한다.
- 퇴사자 계정 비활성화 시 모든 활성 세션을 즉시 강제 만료하고 재로그인을 차단한다.
- 첫 로그인 임시 비밀번호 계정은 비밀번호 변경 전 다른 화면 진입을 차단한다.
- 2FA 활성 계정은 기본 인증 성공 후 추가 인증 입력 영역을 표시한다.
- 비밀번호 만료 배치는 매일 03:00에 실행하고, 90일 임박 사용자에게 7일/3일/1일 전 알림을 발송한다.
- Refresh token은 access token 만료 시 자동 갱신하되, refresh 만료 7일 경과 시 폐기하고 재로그인을 요구한다.
- 디바이스 기억은 30일 경과 시 만료되며 신규 단말 처리와 추가 인증을 요구한다.

## 3. 공통 상태 / 에러 / 토스트 정책

- 데이터 로드 상태는 로딩, 정상, 빈 상태, 오류를 사용한다.
- 권한 상태는 허용, 읽기 전용, 차단을 사용한다.
- 작업 상태는 대기, 처리 중, 성공, 부분 실패, 실패를 사용한다.
- 지점 상태는 운영 중, 오픈 예정, 임시휴업, 폐점을 사용한다.
- 기기 상태는 OK, 불안정, 오류, 점검 중을 사용한다.
- 출석 결과는 성공, 실패, 중복을 사용한다. 중복은 실패 건수에 합산하지 않고 별도 집계한다.
- 빈 목록은 "데이터가 없습니다" 계열 빈 상태로 표시하고, 등록 CTA는 권한이 있을 때만 표시한다.
- 401/세션 만료는 로그인 화면 이동으로 처리하고, 작성 중 데이터는 가능한 범위에서 임시저장한다.
- 403/권한 부족은 접근 제한 안내 후 대시보드 또는 이전 화면으로 이동한다.
- 409/동시 수정은 최신 데이터 새로고침 안내 후 후행 요청을 차단한다.
- 422/필수값 오류는 필드 인라인 에러를 표시하고 저장을 차단한다.
- 5xx/timeout은 재시도 토스트와 재시도 버튼을 제공하고, 자동 재시도 1회 후 사용자 액션을 기다린다.
- 토스트는 1문장으로 작성한다. 다음 행동이 필요하면 버튼 또는 링크로 제공한다.

## 4. 본사 / 지점 운영 책임 정책

- 본사는 정책, 템플릿, 표준, 기본값을 관리한다.
- 지점은 본사가 허용한 범위 안에서 정책을 적용하고 운영한다.
- 지점이 전사 기준을 새로 만드는 구조는 피한다.
- 본사 정책 범위에는 전사 권한 템플릿, 공통 상품 마스터, 자동화 정책 세트, 알림 템플릿, 공지 템플릿, KPI 및 감사 기준이 포함된다.
- 지점 운영 범위에는 회원/리드 실제 운영, 현장 결제와 미수금 처리, 수업 개설과 스케줄 운영, 시설 배정, 본사 정책 범위 안에서의 적용 설정이 포함된다.
- 지점 운영 상태 배지는 `운영 중`, `오픈 예정`, `임시휴업`, `폐점` 4종으로 고정한다.
- 신규 지점은 운영 시작일 이전에는 `오픈 예정` 상태이며, 직원 등록과 상품 세팅은 가능하지만 회원 등록은 운영 시작일 이후 활성화한다.
- 운영 시작일 도래 배치는 매일 00:00에 실행하며 `오픈 예정` 지점을 `운영 중`으로 자동 전환한다.
- 임시휴업 기간에는 진행 중 회원 이용권을 자동 홀딩하고, 휴업 종료 시 동일 기간만큼 만료일을 자동 연장한다.
- 임시휴업 기간 신규 가입은 차단하고, 휴업 기간 내 진행 예약은 자동 취소 후 회원에게 알림을 발송한다.
- 폐점 처리 시 활성 회원의 환불 또는 이관 안내까지 실행한다. 보관 기간 만료 후 자동 아카이브는 고객사 보관 기간 확정 전까지 실행하지 않는다.

## 5. 회원 / 리드 정책

- 회원 실제 상태값은 `ACTIVE(활성)`, `EXPIRED(만료)`, `SCHEDULED(예정)`, `EXPIRING(임박)`, `HOLDING(홀딩)`, `UNREGISTERED(미등록)`, `WITHDRAWN(탈퇴)`를 사용한다.
- `정지`는 실제 회원 상태값이 아니라 현재 회원 상태 위에 추가되는 이용 제한 플래그다.
- 회원 목록 상태 필터는 전체, 활성, 만료, 예정, 임박, 홀딩, 미등록, 탈퇴 총 8개 탭으로 운영한다. `전체`는 집계 탭이고 나머지 7개는 실제 회원 상태값이다.
- 리드 상담 단계는 신규, 연락완료, 상담예정, 방문완료, 등록완료, 미전환, 보류 7종을 사용한다.
- 리드 `등록완료`는 첫 정상 결제 완료 이벤트로만 확정되는 시스템 단계다. 칸반에서 등록완료 컬럼으로 이동하는 동작은 상태 저장이 아니라 회원 등록/결제 흐름 시작 트리거다.
- `미전환`은 종료 상태이며, 동일 연락처 재유입 시 기존 리드 재활성화를 기본값으로 한다.
- 새 리드는 연락처가 다르거나 권한자가 중복 강행 사유를 입력한 경우에만 생성한다.
- 리드는 전화번호를 기준으로 중복 여부를 먼저 확인한다.
- 이미 회원으로 존재하는 전화번호는 신규 리드 생성보다 기존 회원 연결을 우선 제안한다.
- 리드 담당자는 FC를 기본으로 하되, 지점 매니저가 재배정할 수 있다.
- TI 문의는 전화 응대에서 끝났는지 실제 대면 상담으로 이어졌는지를 분리해서 본다.
- WI 문의는 현장 방문 고객의 즉시 등록 전환 성과로 본다.
- 외부 신규 DB 엑셀은 `신규통합DB` 시트 형식을 기준으로 한다.
- 외부 신규 DB의 `경로` 필드는 문의 유형(방문(WI), 전화문의(TI), 체험, 일일입장)으로 매핑한다.
- 외부 신규 DB의 `상세 경로1`, `상세 경로2`는 `가입경로` 단일 필드로 통합한다.
- 가입경로는 간판, 블로그, 인스타, 당근, 지역카페, 현수막, 전단지, 회원소개, 기타 9종으로 고정한다.
- `상세 경로1`, `상세 경로2`가 동시에 들어오면 9종 가입경로와 직접 매칭되는 더 구체적인 값을 우선 사용한다. 둘 다 매칭되지 않으면 기타로 집계한다.
- 외부 신규 DB의 1차/2차/3차 상담 방식 값은 대면, 유선, 부재 3종만 허용한다.
- 상담 성과 담당자는 리드의 상담 담당자(FC)로 관리한다.
- 매출 성과 담당자는 첫 정상 결제 완료 시점의 판매 담당자 또는 인센티브 귀속자로 관리한다.
- 회원 이관은 회원 동의를 받은 인원만 진행한다.
- 본사 슈퍼관리자는 가맹점 폐점에 따른 다수 회원 이관을 처리할 수 있으나, V1에서는 CSV 일괄 이관을 지원하지 않고 1명씩 순차 처리한다.
- 미동의자는 환불 후 탈퇴 처리한다.

## 6. 회원 세그먼트 정책

- 자동 세그먼트는 신규, 만료후미등록, 이탈위험, 만료임박, 관심필요, 충성, 활발 7종을 사용한다.
- 신규는 첫 정상 결제 완료일로부터 30일 이내 회원이다.
- 만료후미등록은 마지막 회원 이용권 만료일 +60일 경과 후 재등록 결제가 없는 회원이다.
- 이탈위험은 활성 회원이 최근 30일 이상 방문 또는 출석이 없는 경우다.
- 만료임박은 HQ-09 회원 이용권 만료 본사 step 또는 지점 추가 step 중 ON 상태인 step 대상이다.
- 관심필요는 최근 90일 이내 종합평가 기록이 없거나 상담 기록이 없는 회원이다.
- 충성은 누적 결제 기간 12개월 이상이고 골드 이상 등급인 회원이다.
- 활발은 최근 30일 이내 방문 또는 출석 8회 이상인 회원이다.
- 출석 집계에는 키오스크 입장, 수업 출석, PT/GX 참여, 수동 출석을 포함한다.
- 2시간 이내 중복 입장은 1회로 처리한다.
- 기본 자동 라벨 우선순위는 `이탈위험 > 만료임박 > 신규 > 활발 > 관심필요 > 만료후미등록`이다.
- `충성`은 보조 라벨로 별도 판정하며 다른 기본 자동 라벨과 동시에 표시할 수 있다.
- 세그먼트 관리, 회원 목록 배지, 회원 상세 헤더, 본사 통합 KPI는 동일한 판정 기준을 사용한다.
- 자동 7종 세그먼트 갱신 배치는 매일 04:00에 실행하고, 회원 상태/결제/출석 이벤트는 실시간 반영한다.

## 7. 상품 / 결제 / 매출 정책

- 상품 판매부터 계약, 결제, 이용권 생성, 환불까지를 하나의 운영 흐름으로 본다.
- 상품 유형은 회원권, 수강권, 락커, 운동복, 일반 상품을 기준으로 한다.
- 수강권은 PT, GX, 골프, 기타 수강권을 세부 유형으로 가진다.
- GX 수강권과 GX 상품은 2단계 세부종목을 필수로 가진다.
- 패키지는 상품 대분류가 아니라 상품 구성 또는 판매 옵션으로 표시한다.
- 현장 카드 승인은 외부 POS/VAN에서 처리한다. CRM은 현장 카드 PG 승인을 직접 수행하지 않는다.
- 외부 POS, 현금, 계좌이체 수납 완료 후 CRM에 CRM 내부 승인번호 1개, 결제수단별 수납 행, 상품별 배분, 영수증 파일, 승인번호, 단말 ID, 외부 거래번호, 계좌이체 입금자명, 현금영수증 처리 여부, 승인 결과를 등록한다.
- 영수증 파일 첨부는 현장 판매 결제 등록의 필수 조건이다. 첨부가 없으면 결제 완료 등록 버튼을 활성화하지 않는다.
- 현장 전액 등록, 계약금 등록, 잔액 등록을 지원한다.
- 혼합 결제는 카드+현금, 카드+계좌이체, 현금+계좌이체, 카드+현금+계좌이체 조합을 허용한다.
- `혼합결제 행 합계 + 포인트 사용액 = 장바구니 최종 합계`가 정확히 일치해야 결제 완료 등록이 가능하다.
- 하나의 장바구니 결제 등록에는 CRM 내부 승인번호 1개를 자동 부여한다. 카드 2~3개, 현금, 계좌이체로 나뉜 수납 행은 내부 승인번호 아래 하위 행으로 관리한다.
- 상품별 분할 계산을 지원한다. 각 상품은 최종 상품금액, 포인트 배분액, 수납행별 배분액, 미수 잔액을 가진다.
- 계좌이체 수납 행에는 입금자명 입력이 필수다. 입금자명은 회원명과 달라도 허용하며 직원이 확인한 실제 입금자명을 저장한다.
- 결제수단 합계가 불일치하면 차액을 붉은색으로 표시하고 결제 완료 등록 버튼을 비활성화한다.
- 상품별 배분 합계가 수납행 금액 또는 상품별 최종금액과 맞지 않으면 결제 완료 등록 버튼을 비활성화한다.
- 결제 완료 등록 후 매출 현황의 카드와 리스트는 5초 이내 갱신한다.
- 이용권 상품 결제 완료 시 회원 카드의 이용권은 즉시 활성화하거나, 잔액 완납 시 자동 개시 대기 상태로 둔다.
- 계약금 등록 후 잔액이 발생하고 수기 분할을 선택하면 단일 미수금을 자동 등록한다.
- 분납 회차 입력 시 할부 계약과 회차 일정을 자동 생성한다.
- 미수/연체 알림은 HQ-09 결제기한 만료 본사 정책 step에서 관리하며, 지점 추가 step은 허용하지 않는다.
- 환불/취소 상태 배지는 요청, 승인대기, 완료, 반려·거절을 사용한다.
- V1 환불/취소는 자동 산식으로 확정하지 않고, 기사용 차감금, 위약금, 기환불 누계, 최종 환불액, 외부 처리 상태, 승인 메모를 수기로 입력한다.
- Owner(지점장)은 환불을 바로 완료할 수 있고, manager/fc는 승인 요청만 할 수 있다.
- 외부 POS/현금/계좌이체 환불 완료 후 CRM에 환불 수단, 외부 처리 상태, 승인번호 또는 증빙 메모를 기록한다.
- 수납행 취소와 상품 환불/계약 취소는 분리한다. 결제수단 일부 또는 전체를 취소하되 상품 계약을 유지하는 경우 취소 배분액은 즉시 상품별 미수금으로 전환하고, 재결제 시 완납 처리한다.
- 카드 승인 건은 기본적으로 외부 승인금액 단위 전체 취소를 원칙으로 본다. 상품 일부 취소나 결제수단 일부 변경은 취소 대상 수납행과 상품 배분을 기록하고 비는 금액을 미수금으로 남긴 뒤 새 수납행으로 재결제한다.
- 상품 자체를 해지하거나 이용권을 환불하는 경우에는 매출과 계약을 줄이는 환불로 처리하며, 상품을 계속 유지하는 수납행 취소처럼 자동 미수금을 만들지 않는다.
- 환불 자동 산식이 확정되기 전까지 시스템은 수기 입력값을 자동 재계산하지 않는다.
- 매출 현황과 매출 통계의 개인정보성 매출 데이터는 5년 경과 시 월 1회 PII 마스킹한다.
- 엑셀 30,000건 이상 또는 CSV 30,000행 이상 다운로드는 백그라운드 큐로 처리하고 완료 알림과 다운로드 링크를 제공한다.

## 8. 수업 / 예약 / 출석 정책

- 수업 유형은 PT, GX, 골프, 기타 4종으로 고정한다.
- 강습 세션 유형은 PT, GX, 골프, 기타 4종으로 고정한다.
- 강습 세션 유형의 기본값은 수업 유형과 동일하게 설정한다.
- 강습 세션 유형은 강습세션수 KPI의 월간·주차별 집계 축으로 사용한다.
- GX 세부종목은 요가, 필라테스, 스피닝, 줌바, GX 기타 5종으로 고정한다.
- GX 세부종목은 상품, 매출, 수업 세부 분포 축이며 수업 유형 또는 강습 세션 유형과 섞지 않는다.
- 수업은 일정 단위, 예약은 좌석 단위, 출석은 실제 이용 단위다.
- V1 기준 모든 예약형 수업의 횟수 차감은 출석 확정 후 1회 차감으로 통일한다.
- 예약 시에는 잔여 횟수 보유 여부와 이용권 유효 상태를 검증한다.
- 잔여 0회 또는 이용권 만료 상태이면 예약과 출석을 차단한다.
- 수업 상태 배지는 예정, 진행중, 완료, 취소를 사용한다.
- 수업 템플릿은 활성 상태인 템플릿만 선택 가능하다.
- 템플릿은 수업명, 유형, 정원, 기본 장소, 색상 등을 반복 입력 없이 자동 완성하는 기준으로 사용한다.
- 본사 시간표 일괄 등록은 본사 통합 모드에서 지점을 다중 선택하고, D10 수업 운영 자동화 정책이 ON인 지점에 동시 등록한다.
- 시작일이 종료일보다 늦으면 인라인 에러를 표시하고 미리보기를 비활성화한다.
- 템플릿 미선택 시 미리보기를 비활성화하고 강사·정원 자동 채움을 차단한다.
- 자동 노쇼는 출석 인정 마감 + 지점 노쇼 유예 N분 기준으로 처리한다.
- 노쇼 유예 기본값은 30분이다.
- 노쇼 유예 N분이 미설정이면 자동 노쇼를 보류하고 수동 처리 대상으로 남긴다.
- 노쇼 처리된 예약 회차는 해당 예약 회차 사용 처리와 페널티 부과 대상이 된다.
- 취소 요청 거절만으로는 페널티를 부과하지 않는다.
- 낮은 평점 1~2점 등록 시 Owner(지점장)+에게 즉시 알림을 보낸다.

## 9. 시설 / 락커 / 기기 정책

- 시설자산은 자산 마스터, 현재 상태, 배정 대상, 이력으로 관리한다.
- 회원 이용권과 연결되는 자산은 만료일과 연동해 운영한다.
- 배정형 자산은 언제 누구에게 연결되었는지 이력을 남긴다.
- 락커는 회원 부가 이용권 또는 옵션 상품과 연결한다.
- 락커 상태는 사용가능, 사용중, 만료임박, 만료, 고장, 비활성 기준으로 본다.
- 만료임박 판정은 HQ-09 락커 만료 정책 step 기준을 따른다.
- 락커 배정과 해제는 회원 상세에서도 진입 가능해야 한다.
- 카드 자체 상태와 회원 매핑 상태는 분리한다.
- 카드 분실, 재발급, 비활성 처리는 이력 중심으로 남긴다.
- CRM에서 고정으로 인식하는 기기 종류는 출입 게이트, 키오스크, 락커 컨트롤러, InBody 측정기 4종이다.
- 카드 리더, 얼굴인식 카메라, RFID/밴드, QR은 별도 기기 종류가 아니라 출입 게이트 또는 키오스크의 인증 수단 또는 부속 모듈이다.
- 기기 헬스체크 기본 주기는 5분이다.
- 본사(primary/superAdmin)만 기기 헬스체크 전역 기준을 변경할 수 있고, 지점은 임의 변경하지 않는다.
- 정상 응답은 OK, 미응답·응답 지연·부분 응답은 불안정, 인증 실패·하드웨어 오류는 오류로 표시한다.
- 불안정 또는 오류 감지 시 운영자에게 즉시 알림을 보낸다.
- 키오스크 화면 구성, TTS, 체크인 수단, 출입 규칙, 기기 등록은 D09 설정관리에서 처리한다.
- D11 통합운영은 키오스크 출석 이벤트, 실패 사유, 마지막 수신 시각, 상태 배지만 표시한다.
- D11에는 키오스크 운영 콘솔, 원격 재시작, 로그 다운로드, 단말 관리자 패널을 만들지 않는다.
- InBody는 측정 사용자, 측정 시각, 체성분 값만 CRM으로 수신한다.
- CRM은 InBody 장비 연결 테스트, 측정 시작, 장비 설정, 파일 업로드를 제공하지 않는다.
- InBody 회원 매칭 실패, 중복 의심, 수신 지연은 운영자가 직접 매칭, 무시, 확정 처리한다.

## 10. 알림 / 마케팅 / 쿠폰 / 마일리지 정책

- 알림 채널은 회원앱 Push, 카카오톡 fallback/알림톡, SMS/LMS/MMS를 사용한다.
- 회원 대상 자동 알림의 기본 채널은 회원앱 Push다.
- 카카오톡 fallback은 지점 설정이 켜져 있고 회원앱 Push 실패 또는 미설치인 경우에만 보조 발송으로 사용한다.
- SMS는 정책 step 또는 화면에서 명시된 경우에만 사용한다.
- 회원앱 Push 또는 카카오톡 실패 시 SMS로 임의 자동 전환하지 않는다.
- 회원앱 Push와 카카오톡 fallback은 별도 기준이 없으면 30분 간격 최대 3회 재시도한다.
- 최종 실패 시 운영자에게 실패 건 목록을 알린다.
- 메시지 발송 화면에는 플랫폼에서 조회한 발신 프로필, 템플릿 승인 상태, 채널별 예상 비용, 잔여 캐시/크레딧, 최근 동기화 시각을 노출한다.
- 과금 단가, 실발송 상태, 최종 청구 근거는 플랫폼 응답값을 우선한다.
- 후속 예정일이 경과했는데 미처리 상태이면 리드 카드를 빨강 표시하고 일일 알림을 보낸다.
- 보류 리드 30일 경과 시 매일 04:00 배치로 보류 리드 노랑 배지와 후속 액션 권유를 표시한다.
- 쿠폰 상태는 활성, 만료, 중단만 사용한다.
- 쿠폰 유효 기간 종료 시 매일 04:00 배치로 만료 상태로 전환하고 신규 발급을 차단한다.
- 쿠폰 정률 할인은 1~100% 범위만 허용한다.
- 쿠폰 정액 금액은 0원 초과만 허용한다.
- 쿠폰 유효 기간 시작일이 종료일보다 늦으면 저장을 차단한다.
- 마일리지 잔액 부족 차감은 차단한다. 마이너스 잔액은 허용하지 않는다.
- 마일리지 조정 사유는 필수다.
- 마일리지 금액은 0보다 큰 금액만 허용한다.
- 마일리지 자동 소멸 배치는 매일 04:00에 실행하고, 적립일 + 설정 개월 경과분을 FIFO 기준으로 소멸한다.

## 11. 직원 / 근태 / 급여 정책

- 직원 목록의 역할과 직무 표시는 `역할` 컬럼과 `직무 배지`로 나누어 표시한다.
- 역할은 권한 템플릿이고, 직무 배지는 PT트레이너, GX강사, 골프강사 등 실제 업무 구분이다.
- 직원 근태 상태 배지는 정상, 지각, 결근, 조퇴, 외근, 휴가를 사용한다.
- 근태 기록 출처 배지는 키오스크, IoT, 수동 보정, 누락 추가를 사용한다.
- 직원 지각 기준은 D09 출석 관리 설정의 지점별 직원 지각 허용 시간을 따른다.
- 직원 지각 허용 시간 기본값은 10분이다.
- 정규 출근 시각 + 10분까지는 정상, 10분 초과 출근부터 지각으로 분류한다.
- 직원 근태 지각 기준은 수업/회원 출석의 지각·노쇼 기준과 별도 정책값이다.
- 자동 수집 데이터와 수동 보정이 충돌하면 수동 보정을 우선 적용하고 "수동 보정됨" 배지를 표시한다.
- 근태 보정 시 보정 사유와 보정 이력을 반드시 남긴다.
- 보정 이력에는 변경 전/후 시각, 변경 상태, 보정 사유, 보정자, 보정 일시를 남긴다.
- 결근 자동 분류 배치는 다음날 00:00에 실행하며, 영업일 + 미출근 + 휴가 미등록이면 결근으로 분류한다.
- 조퇴 자동 분류는 퇴근 시각이 정규 퇴근 시각보다 빠른 경우 적용한다.
- 급여 처리 대상 월 기본값은 시스템 날짜 기준 당월이다.
- 미래 월은 선택할 수 없다.
- 전월 이전 월은 마감 월로 잠그고 read-only로 제공한다.
- 급여 확정 상태 배지는 미확정과 확정만 사용한다.
- 이미 확정된 급여도 당월 내에는 확정 취소 후 재편집 가능하다.
- 전월 이전 급여는 편집, 확정, 확정 취소, 자동 재계산, 급여 정책 재적용을 차단한다.
- 수당/공제 편집은 당월 미확정 급여에서만 가능하다.
- 자동 생성된 기본급, 자동 수당, 자동 공제, 수수료 원본 항목은 직접 덮어쓰지 않는다.
- 보정이 필요하면 수동 수당 또는 수동 공제 항목으로 추가한다.
- 수동 수당 항목은 식대, 교통비, 특별 수당, 성과 수당, 기타 수당을 사용한다.
- 수동 공제 항목은 지각·결근 공제, 4대 보험 안내 항목, 선지급·가불 차감, 기타 공제를 사용한다.
- 수동 수당/공제 저장 시 항목명, 금액, 변경 사유는 필수다.
- 급여 확정 취소 시 기존 급여 명세서는 CRM 내부 `무효` 상태로 전환한다.
- 무효 명세서는 발송, 재발송, PDF 저장, 인쇄를 차단한다.
- 재확정 시 기존 무효 명세서는 보존하고 새 명세서를 별도 생성한다.
- 새 명세서 발송은 자동 실행하지 않고 운영자가 [발송] 또는 [일괄 발송]으로 실행한다.
- 급여 명세서 발송 상태 배지는 미발송, 발송완료, 무효 3종으로 고정한다.
- 수신 확인은 발송 전 `-`, 발송 후 `미열람`, 직원 열람 시 `열람완료`, 무효 명세서·만료 링크·추적 불가 채널은 `확인불가`로 표시한다.
- 발송 일시는 마지막 성공 발송 일시를 표시한다.
- 재발송 시 마지막 발송 일시는 갱신하되 발송 이력은 누적 보존한다.
- 퇴사 처리 실행과 확정은 Owner(지점장)+만 가능하다. manager 이하는 버튼과 직접 진입을 제공하지 않는다.

## 12. HQ-09 / 만료·기한 정책

- HQ-09는 본사 표준 정책 세트를 관리하는 기준이다.

- NFR-05는 만료일, 납입기한, 사용기한처럼 날짜 기준으로 조치 대상을 산출하는 공통 배치다.
- NFR-05 결과는 대상자/대상 항목 목록, 화면 배지/카드 카운트, 화면 배너, 알림 큐, 동기화 결과를 함께 만든다.
- 회원 이용권 만료 정책은 본사 step과 지점 추가 step을 함께 사용할 수 있다.
- 회원 이용권 만료 대상자는 D02가 매일 03:00 산출한다.
- 회원 이용권 만료는 지점 추가 step 생성이 가능하고, 지점 ON/OFF가 가능하다.
- 결제기한 만료 정책은 본사 step만 사용한다.
- 결제기한 만료는 지점 추가 step을 허용하지 않고, 지점은 ON/OFF만 할 수 있다.
- 결제기한 만료 대상자는 D03가 매일 04:00 산출한다.
- 미수 알림 N일, 연체 D+N 알림, 반복 알림 주기, 발송 시각, 기본 채널은 HQ-09 결제기한 만료 본사 정책 step에 포함한다.
- 락커 만료 정책은 본사 step과 지점 추가 step을 함께 사용할 수 있다.
- 락커 만료는 지점 추가 step 생성이 가능하고, 지점 ON/OFF가 가능하다.
- D06/D11은 매일 00:30에 락커 만료 임박 상태를 산출한다.
- 락커 만료 경과 자동 회수 기본값은 OFF다.
- Owner(지점장)가 자동 회수를 ON으로 설정한 경우에만 매일 02:00에 실행한다.
- 일일 사물함 22:00 상태 갱신은 ON 고정이고, 실제 일괄 회수는 별도 정책 ON일 때만 실행한다.

## 14. V1 확정 외부연동 정책

- 회원앱 Push는 V1 확정 연동이다. CRM은 발송 이벤트, 대상, 메시지, 이동 대상, 실패 상태를 생성·표시하고 회원앱은 Push 수신과 화면 이동을 처리한다.
- 카카오톡 fallback/알림톡은 V1 확정 연동이다. CRM은 지점 설정 ON 여부, 승인 템플릿, 실패/제외 건수, 예상 비용을 표시하고 카카오 채널은 실제 발송과 템플릿 승인/비친구 판정을 담당한다.
- SMS/LMS/MMS는 V1 확정 연동이다. CRM은 발송 요청, 글자수, 비용, 실패 사유를 표시하고 SMS 사업자가 실제 발송을 처리한다.
- 외부 POS/VAN은 V1 확정 연동이다. 실제 카드 승인과 카드 취소는 외부 POS/VAN에서 처리하고 CRM은 내부 승인번호, 수납행, 상품별 배분, 증빙과 결과를 저장한다.
- 키오스크는 V1 확정 연동이다. CRM은 설정 저장, 기기 동기화 상태 표시, 실패 알림을 담당하고 키오스크는 단말 화면 표시와 출석 이벤트 전송을 담당한다.
- 출입 게이트는 V1 확정 연동이다. CRM은 출입 성공/실패 이벤트와 기기 상태 배지를 표시하고 게이트는 인증과 통과/실패 이벤트를 전송한다.
- 락커 컨트롤러는 V1 확정 연동이다. CRM은 락커 상태와 잠금 결과를 표시하고 컨트롤러는 잠금/해제 수행 결과를 전송한다.
- InBody 측정기는 V1 확정 연동이다. CRM은 측정 사용자, 측정 시각, 체성분 값을 수신해 조회·검수·확정하고 수기 등록을 보조한다.
- 회원앱 연동은 V1 확정 연동이다. CRM은 회원앱에 표시될 알림, 예약/대기 상태, 수업 변경, 운동 기록, 상품/카탈로그 상태, 락커/출석 결과를 생성하거나 갱신한다.
- Health Connect는 V1 조회 전용 연동이다. admin은 연결 상태와 요약값만 조회하고, 연결/해제/권한 변경은 회원앱에서 회원 본인이 수행한다.
- Health Connect V1 반영값은 걸음수, 이동 거리, 활동 kcal, 운동 세션 요약이다.
- Health Connect에서 심박수, 수면, 의료 데이터, 체성분 원천 데이터는 제외한다.
- Excel/CSV/PDF 내보내기는 V1 확정 파일 산출 기능이다. 실시간 외부 시스템 연동이 아니라 운영자가 파일을 내려받아 사용하는 기능이다.
