# 정책 확인 필요

작성일: 2026-05-29
통합 전 문서: V1 정책 확인 필요, 정책 미확정 확인 필요

이 문서는 `docs4` 기준으로 고객사 또는 판도 측 확인이 필요한 항목만 한 곳에서 관리하는 목록입니다. 개발사는 이 문서에 있는 항목을 확인 전 최종 완료 기준으로 해석하지 않습니다.

## 0. 분류 원칙

- 기본값이 문서에 명시된 항목은 미확정 정책으로 보지 않는다. 구현은 기본값으로 시작하고, 설정 화면이 있는 경우 운영자가 값을 변경할 수 있게 처리한다.
- `HQ-09`, `NFR-05`, `D09 출석 관리 설정`처럼 본사 정책 세트 또는 설정 화면에서 관리하는 `N`값은 미확정이 아니라 정책 파라미터다.
- V1 제외 또는 V2 이관 항목은 미확정 정책이 아니라 개발 범위 제외 또는 후속 개발 대기 항목으로 관리한다.
- API endpoint, DB table, queue, RLS 같은 백엔드 내부 설계 방식은 이 문서의 확인 대상이 아니다.
- 확인 답변이 오면 해당 도메인 문서와 운영정책 문서에 확정값을 직접 반영하고, 이 문서에서는 제거하거나 상태를 `확정 반영 완료`로 바꾼다.
- 확정 정책만 모아 볼 때는 `docs4/핏지니_정책.md`를 기준으로 한다.
- 개발사 전달 범위와 개발 대기/제외 해석은 `docs4/_개발사_전달사항.md`를 기준으로 한다.

## 1. V1 기준 확인 필요

아래 항목은 V1 문서 안에 후보 또는 보류 상태로 남아 있으며, 고객사 또는 판도 측 답변이 있어야 개발 완료 기준으로 확정할 수 있다.

|---|---|---|---|
| POL-01 | 자동 알림 13종 명칭 | 계약서에 예시형으로 적힌 자동 알림 13종의 정확한 명칭, 수신 주체, 채널, 발송 시점 | 문서에 명시된 후보 목록만 관리한다. 목록 밖 예약/출석/쿠폰/마일리지/상품 변경 알림은 자동 포함하지 않는다. |

| POL-06 | 현금영수증 처리 정책 | 현금 및 계좌이체 수납 시 현금영수증 발행 대상, 필수 여부, 발행 유형(소득공제/지출증빙), 식별번호 입력 범위, 취소 시 처리 기준 | V1 화면에는 현금영수증 처리 여부, 발행 유형, 식별번호, 발행 승인번호, 발행일시, 발행/취소 상태를 입력·조회할 수 있는 필드를 둔다. 다만 어떤 경우 발행을 필수로 강제할지는 고객사/세무 운영 기준 확인 후 확정한다. |

## 2. 후속 범위 확인 필요

아래 항목은 V1 개발을 막는 미확정 정책이 아니라, 후속 개발 범위가 확정될 때 별도 확인이 필요한 항목이다.

| 항목 | 현재 처리 기준 | 후속 확인 내용 |
|---|---|---|
| 결제링크 정책 | V1 확정 구현 범위로 보지 않는다. 고객사 확정 전에는 자동 만료, 자동 알림, 활성 링크 제한, PG 결제 완료 webhook, 결제 완료 자동 활성화를 구현하지 않는다. 미결제 링크는 환불 대상이 아니며 회원상세 결제내역에 `미결제` 상태로만 표시한다. | 전액 결제 전용 여부, 링크 7일 고정, D-3/D-1 만료 전 알림, 활성 링크 1개 제한, 무효화 권한과 사유 입력, 결제 완료 즉시 이용권 활성화 여부 |
| 결제 자동 적용정책 | V1에서는 자동 적용, 후보 조회, 중복 적용, 우선순위, 직원 수동 변경 제한을 개발하지 않는다. 결제 화면에는 운영자가 수동 확정한 할인 항목과 할인 금액만 입력·표시한다. | 쿠폰/마일리지 자동 적용 여부, 중복 가능 범위, 시즌특가와 등급할인 우선순위, 직원 수정 가능 여부 |
| 마케팅 선택형 자동화 | 보류 30일 경과 알림은 V1 기준으로 사용한다. 보류 60일 자동 미전환, 생일 쿠폰 자동 발급은 고객사 확인 전까지 자동 실행 기준으로 보지 않는다. | 실제 사용 여부, 기본값, 쿠폰 혜택 기준, 발송 채널 |
| 캠페인 A/B 테스트 | V1 제외, V2 이관. V1에서는 목록, 등록, 삭제, 자동 분배, 승리안 채택, 동시 적용 우선순위 자동 계산을 개발하지 않는다. | V2 개발 시 A/B 테스트 운영 방식과 우선순위 기준 |
| 환불/취소 자동 계산 | V1 기준은 기사용 차감금, 위약금, 기환불 누계, 최종 환불액, 외부 처리 상태, 승인 메모 수기 입력 + Owner(지점장) 승인이다. | 후속 자동화 시 사용분 차감 기준, 위약금 산식, 환불 자동 재계산 기준 |

## 3. 정책 확인이 아니라 자료 제공 필요

아래 항목은 고객사 운영 정책의 미확정이라기보다, 기존 운영 원천 자료를 개발사에 제공해야 자동 집계 기준으로 확정되는 항목이다.

| 항목 | 필요 자료 | 제공 전 개발 기준 |
|---|---|---|
| 외부 Google Spreadsheet 산식 | `[매출종합]`, `[월매출]`, `[OT관리-강습/골프]`, `[OT관리-강습]`, `[강습업무보고]`, `[주간월간보고]` 등 운영 시트의 컬럼 정의, 산식, 집계 기준 | 화면 표시 항목과 수기/임시 입력 기준만 개발한다. 자동 집계 산식은 판도에서 원천 정의를 제공한 뒤 확정한다. |

### 판도 확인 질문: 외부 연동 DB 산식

아래 항목은 정책 미확정이 아니라 기존 운영 원천 자료 제공 요청이다. 판도에 확인할 때는 "외부 연동 DB에 저장해야 하는 계산 결과와 원천 산식"을 기준으로 답변을 요청한다.

- 외부 Google Spreadsheet 또는 기존 운영 DB에서 CRM DB로 가져와야 하는 계산 결과 항목은 무엇인가?
- 각 계산 결과의 원천 시트, 원천 컬럼, 산식, 집계 단위(지점/직원/회원/상품/수업/일/월)는 무엇인가?
- `[매출종합]`, `[월매출]`의 매출, 환불, 미수, 정산, 인센티브 귀속 산식과 제외 조건은 무엇인가?
- `[OT관리-강습/골프]`, `[OT관리-강습]`의 OT 잔여, 차감, 노쇼, 보강, 강사 귀속 산식은 무엇인가?
- `[강습업무보고]`, `[주간월간보고]`의 보고 지표 산식, 기간 기준, 마감 기준, 반올림/절사 기준은 무엇인가?
- 외부 연동 DB에는 원천값만 저장할지, 계산 결과값까지 저장할지, 또는 원천값+계산 스냅샷을 함께 저장할지 결정이 필요한가?
- 산식 변경 시 과거 데이터 재계산 여부, 재계산 가능 기간, 수기 보정 권한, 변경 이력 보존 기준은 무엇인가?
- 판도 제공 전까지 CRM은 원천값 수기/임시 입력과 화면 표시만 지원하고, 자동 집계 산식·자동 정산·자동 인센티브 확정은 개발 완료 기준으로 보지 않는다.

## 4. 미확정 아님

아래 항목은 `N` 또는 조건값이 보이더라도 미확정 정책으로 보지 않는다. 기본값이 있거나, 본사 정책 세트/설정 화면에서 운영자가 관리하는 정책 파라미터다.

| 항목 | 확정 처리 기준 | 이유 |
|---|---|---|
| 미수/연체 알림 N일 | `HQ-09 결제기한 만료` 본사 정책 step에서 기준일(D+N), 반복 주기, 발송 시각, 기본 채널을 설정한다. 지점은 ON/OFF만 가능하며 지점 추가 step은 허용하지 않는다. | 고객사별 고정 답변을 받아야 하는 항목이 아니라 본사 정책 세트의 설정값이다. |
| 회원 이용권 만료 D-N 알림 | `HQ-09 회원 이용권 만료` 본사 step과 지점 추가 step 기준을 따른다. | 본사 정책 세트에서 step으로 관리하는 항목이다. |
| 락커 만료 D-N 알림 | `HQ-09 락커 만료` 본사 step과 지점 추가 step 기준을 따른다. | 본사 정책 세트에서 step으로 관리하는 항목이다. |
| 자동 노쇼 유예 N분 | `D09 출석 관리 설정`에서 관리하며 기본값은 30분이다. | 기본값과 설정 위치가 이미 정해진 정책 파라미터다. |
| 직원 지각 허용 시간 | `D09 출석 관리 설정`에서 지점별로 관리하며 기본값은 10분이다. | 기본값과 설정 위치가 이미 정해진 정책 파라미터다. |
| 회원 세그먼트 운영 임계값 | 신규은 첫 정상 결제 완료일로부터 30일 이내, 이탈위험은 최근 30일 이상 미방문, 만료후미등록은 마지막 이용권 만료일 +60일 경과로 본다. | `docs4`에서 고정값으로 확정된 기준이다. |
| 재등록 우대 후보의 만료 후 N일 | V1 핵심 결제 자동 적용 기준으로 보지 않는다. 후속 후보 조건으로만 관리하며 기본 기준은 30일이다. | V1 완료 기준을 막는 미확정 정책이 아니다. |
| 할인/쿠폰/시즌/등급 자동 우선순위 | V1 제외다. 운영자가 수동 확정한 할인 항목과 금액만 결제 화면에 입력·표시한다. | 현재 범위에서 구현하지 않는 후속 정책이다. |
| 계좌이체 입금자명 | D03 결제 처리의 계좌이체 수납 행에서 필수 입력한다. 회원명과 다르면 직원이 확인한 실제 입금자명을 저장한다. | 사용자 요구로 확정된 CRM 입력 필드이며 미확정 정책이 아니다. |
| CRM 내부 승인번호 | 하나의 장바구니 결제 등록마다 내부 승인번호 1개를 자동 생성한다. 여러 카드, 현금, 계좌이체 수납 행은 내부 승인번호 아래 하위 행으로 관리한다. | 개발 기준이 확정된 식별 정책이다. |
| 수납행 취소 후 미수금 전환 | 상품 계약을 유지한 채 결제수단 일부 또는 전체를 취소하면 취소 수납금액을 즉시 상품별 미수금으로 전환하고, 재결제 시 완납 처리한다. | 개발 기준이 확정된 결제 변경 정책이다. |

## 5. 전달 기준

- 개발사 전달 시 이 문서를 “정책 미확정 전체 목록”이 아니라 “확인 또는 자료 제공이 필요한 항목 목록”으로 설명한다.
- `N`값이 보인다는 이유만으로 미확정으로 분류하지 않는다. 기본값이 있거나 본사 정책 세트에서 관리하면 개발 가능한 정책 파라미터로 본다.
- V1 제외/V2 이관 항목은 개발 누락이 아니라 범위 제외로 설명한다.
- 확정 정책만 모아 볼 때는 `docs4/핏지니_정책.md`를 기준으로 한다.
- 개발사가 구현 범위를 확인할 때는 `docs4/_개발사_전달사항.md`의 개발 대기/제외 기준을 함께 전달한다.
