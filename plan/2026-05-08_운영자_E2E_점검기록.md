## 수정 반영 및 재검증

1. 로그인 `비밀번호 찾기`
조치: `/reset-password` 라우팅 연결
재검증: PASS

2. 회원 상세 `수동출석`
조치: 즉시 저장형을 `수동 출석 처리` 모달형으로 변경, 날짜/시간/사유 입력 가능하게 수정, 히스토리 로그 detail 기록 추가
재검증: PASS

3. 회원 상세 `최근 방문일`
조치: 상단 카드가 `registeredAt` 대신 `lastVisitAt`를 사용하도록 수정
재검증: PASS

4. 회원 등록 `바로 결제`
조치: `회원 등록 → POS`로 라우팅 수정, POS 화면에서 `memberId`로 구매자 자동 선택되도록 수정
재검증: PASS

5. 회원 목록 `운영 저장 뷰 탭`
조치: `상담내역 / 상담예약 / 재등록대상 / (구)고객관리` 탭을 추가하고 운영 문맥별 빠른 전환이 가능하도록 수정
재검증: PASS

6. 회원 목록 `출석시 상세 팝업`
조치: 토글을 추가하고, ON 상태에서는 행 클릭 시 우측 `Quick Member View` 패널이 열리고 OFF 상태에서는 회원 상세로 직접 이동하도록 수정
재검증: PASS

7. 회원 목록 `선택 행 일괄 액션 기준`
조치: 저장 뷰/정렬 변경 후에도 현재 화면에 보이는 행 기준으로 상태 변경, 메시지 발송, 수동 출석, 관심회원, 지점이관이 처리되도록 수정
재검증: PASS

선행조건: 결제 건 선택
수행 절차: 선택된 결제 요약 영역 확인
기대결과: 결제번호, 결제일, 결제수단, 담당자 등 최소 운영 확인 정보가 보여야 함
실제결과: 최초 점검 시 회원명/상품/금액만 노출
판단: UX 개선 필요

4. 테스트 항목: 환불 계산 요약
선행조건: 결제 건 선택
수행 절차: 처리 폼 관찰
기대결과: 환불 가능액/최종 환불액 등 계산 근거가 보여야 함
실제결과: 최초 점검 시 계산 요약 영역 없음
판단: 퍼블리싱 수정 필요 / 문서 불일치

5. 테스트 항목: 부분 환불 금액 초과 입력
선행조건: 결제 건 선택 후 `부분 환불` 선택
수행 절차: 결제 금액보다 큰 수 입력
기대결과: 경고 문구 노출 및 제출 차단
실제결과: `결제 금액을 초과할 수 없습니다.` 노출
판단: PASS

## 4차 수정 반영 및 재검증

1. 결제 취소 / 부분 환불 `처리 확인 단계`
조치: 공통 `ConfirmDialog`를 연결해 `환불 처리 확인` 모달에서 처리 유형, 환불 금액, 환불 수단, 취소 사유를 최종 검토하도록 변경
재검증: PASS (`21-cancel-refund-confirm.png`, dialog count 1 확인)

2. 결제 취소 / 부분 환불 `처리 완료 후 후속 행동`
조치: 성공 영역에 `환불 관리로 이동`, `계속 처리` 버튼 추가
재검증: PASS (`환불 관리로 이동`, `계속 처리` 버튼 노출 확인)

3. 결제 취소 / 부분 환불 `선택 결제 정보 확인성`
조치: 선택된 결제 요약에 결제번호, 결제일, 결제수단, 담당자 추가
재검증: PASS

4. 결제 취소 / 부분 환불 `환불 계산 요약`
조치: 현재 퍼블리싱 가능한 범위에서 `원결제금액`, `이번 환불 가능액`, `최종 환불액` 박스를 추가하고, 상세 계산식이 아직 없다는 점을 안내 문구로 명시
재검증: PASS

5. 공통 확인 모달 접근성
조치: `src/components/ui/ConfirmDialog.tsx`에 `role="dialog"`와 `aria-modal="true"` 추가
재검증: PASS

6. 결제 취소 / 부분 환불 `문서 대비 잔여 누락`
실제결과: 문서상 `회원명·상품명·결제일` 외 `결제일 직접 검색`, `사유 직접 입력`, `기환불 누계`, `기사용 차감금`, `위약금 조정`, `이미 취소된 건 안내`까지 필요하지만 현재 퍼블리싱은 미반영
판단: 문서 불일치 / 추가 퍼블리싱 필요
메모: 이번 라운드는 운영 사고를 줄이는 확인 단계와 후속 흐름 복구를 우선 처리
