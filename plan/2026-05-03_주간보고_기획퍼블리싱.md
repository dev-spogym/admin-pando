## 3. 주요 진행 내용

### 3.1 관리자 문서 구조 및 정본 기준 재정리

- 관리자 문서를 `docs/admin` 기준으로 재편하고, 기능명세서·화면설계서·다이어그램의 역할을 분리했습니다.
- 화면설계서는 화면 단위 정본으로 유지하고, 기능명세서는 고객사 검토용 요약 문서로 정리하는 흐름을 고정했습니다.
- Cmd+/ 기획 오버레이가 실제 route와 화면설계서를 참조하도록 경로를 동기화했습니다.
- 현재 관리자 화면설계서 마스터는 273개이며, 검증 기준으로 screen 118개, dialog 155개가 frontmatter 적용 상태입니다.

### 3.2 관리자 KPI / 지표 기획 정합화

- KPI 센터, 통합 대시보드, 매출 통계, 온보딩, 수업/강사 현황에서 중복되거나 미확정이던 지표를 정리했습니다.
- WI/TI 상담, TI 방문 전환율, WI/TI 등록률, 체험→등록, 일일입장→회원, 회원소개 유입, 가입경로 분포를 온보딩·마케팅·KPI 문서에 반영했습니다.
- OT 관련 지표는 강습/골프 OT를 분리하고, OT 등록 전환율·거부율·이월률·체험→등록률·트레이너별 OT 배정/완료 기준을 문서화했습니다.
- 매출 지표는 VAT 제외 매출, 법인권 매출, 개월별 판매 비율, GX 세부 종목 분포, 담당자별 환불 책임 기준을 추가했습니다.
- 제외 지표도 명시했습니다. 환불→재결제 복귀율, 취소재결제 건수, 매입사별 수수료, 만료일별 D-7/D-14/D-30 분포 위젯은 현재 기획 범위에서 제외로 기록했습니다.

### 3.3 관리자 퍼블리싱 route 정합화 및 누락 화면 보완

- 화면설계서 route를 정본으로 보고 실제 화면 route와 사이드바, Cmd+/ 오버레이 매핑을 맞췄습니다.
- 기존에 `미구현`으로 남아 있었지만 실제 UI가 존재하던 화면은 `퍼블리싱 완료 / 데이터 미연동` 상태로 정리했습니다.
- 신규 또는 보강된 화면 범위에는 자동화 정책 라이브러리, 지점 자동화 적용, 키오스크 운영 현황, 상품 상세 패널, 예약 목록이 포함됩니다.
- route 정본화 대상에는 QR 체크인, 장비 점검, 캠페인, 리퍼럴, SMS/카카오, A/B 테스트, 커스텀 대시보드, 예측 분석, 시즌 가격, 커스텀 역할, 회원 건강 연동 요약 등이 포함됩니다.

### 3.4 관리자 운영 데이터 기준 보강

- 상품관리에서 상품 등록/수정, 상품 그룹 매칭, GX 6종 세부종목 기준을 보강했습니다.
- 회원 상세의 상담 이력 저장, 수정 시 히스토리 로그 기록, 레슨 기록과 모바일 레슨 완료 서명 연동 기준을 보강했습니다.
- 본사 계정의 전체 지점(통합) 선택 시 전 지점 직원 조회가 가능하도록 지점 소속 기준을 정리했습니다.
- 히스토리 로그 명칭을 고객사 표현에 맞게 정리하고, 주요 변경 이력이 히스토리 로그에 남도록 보강했습니다.
- 수업관리에는 신규 `예약 목록` 화면을 추가해 기간, 수업, 강사, 상태 필터와 회원명·연락처 검색이 가능하도록 구현했습니다.

### 3.5 관리자 수업관리 예약 목록 신규 정의

- `수업 캘린더`는 일정 중심, `그룹 수업 현황`은 수업별 집계 중심, `예약 목록`은 예약 1건 단위 원장 화면으로 역할을 분리했습니다.
- 예약 목록은 `/class-reservations` route로 정의했고, 수업관리 메뉴에 추가했습니다.
- 예약 원장은 `lesson_bookings`를 기준으로 `classes`, `members`, `branches` 정보를 연결해 표시합니다.
- 예약 상태는 예약완료, 출석완료, 취소, 노쇼, 대기 기준으로 표시하고, 출석·노쇼·취소 처리 시 히스토리 로그가 남도록 했습니다.
- 예약 취소 시 취소 사유 입력을 필수로 두었습니다.

### 3.6 회원앱 디자인 시스템 전면 개편

- 회원앱 전체 visual language를 BODY SWITCH 청록 테마 기준으로 정리했습니다.
- Avatar, Badge, Brand, Button, Card, Chip, EmptyState, Input, ListItem, PageHeader, PriceTag, ProductCard, SearchBar, SectionHeader, Tag 등 공용 UI 컴포넌트 기준을 확장했습니다.
- 기존 75개 화면을 신규 디자인 시스템 기준으로 마이그레이션했습니다.
- 회원, FC, 스태프, 트레이너 4개 역할별 하단 탭바를 동일한 기준으로 정리했습니다.
- 전체 화면의 타이포그래피 위계를 토큰 기준으로 맞추고, 브랜드 명칭을 FitGenie 기준으로 통일했습니다.

### 3.7 회원앱 멀티센터 마켓플레이스 퍼블리싱

- 회원앱 마켓플레이스 화면을 신규 확장했습니다.
- 회원용 마켓 범위에는 탐색 홈, 센터 탐색, 센터 상세, 센터 지도, 카테고리 검색, 리뷰 목록/작성, 트레이너 탐색, 트레이너 상세, 찜 목록, 메신저 허브/대화방이 포함됩니다.
- 트레이너 마켓 범위에는 트레이너 마켓 프로필, 트레이너 메신저, 트레이너 대화방이 포함됩니다.
- 직원 메신저, 마켓 프로필, KPI 차트 등 역할별 부가 화면도 함께 정리했습니다.
- 하단 탭바는 홈, 예약, 센터, 강사, MY 5개 구조로 재정리했고, `스크랩` 표현은 고객 친화적인 `찜`으로 통일했습니다.

### 3.8 회원앱 결제·주문·리워드·커뮤니티 화면 확장

- 결제/주문 범위에는 장바구니, 결제 옵션, 주문 목록, 주문 상세, 결제수단, 환불 화면을 추가했습니다.
- 리워드/멤버십 범위에는 멤버십 등급, 리퍼럴, 활동 내역, 베스트 랭킹을 추가했습니다.
- 커뮤니티/고객지원 범위에는 이벤트, 이벤트 상세, FAQ, Q&A 목록/상세, 신고 내역을 추가했습니다.
- 시스템 상태 범위에는 네트워크 없음, 서버 점검, 온보딩 웰컴 화면을 추가했습니다.
- 공유, 로그인 유도, 확인 다이얼로그, 푸시 토스트 등 공용 인터랙션 UI도 함께 보강했습니다.

### 3.9 회원앱 UX / 일관성 정리

- 모바일 프레임을 벗어나는 화면 영역을 정리했습니다.
- 헤더 safe-area-top 기준을 맞추고, 일부 화면의 헤더 중복 노출을 제거했습니다.
- 알림센터는 제목과 시간을 한 줄에 배치하고 본문은 2줄 제한으로 정리했습니다.
- 수업 목록의 종목 표현 범위를 확장했습니다.
- 브랜드 표기는 `FitGenie` 기준으로 통일했습니다.

### 3.10 검증 및 안정화

- 문서 frontmatter 검증을 통과했습니다. 현재 오류는 0건이며, 남은 경고는 기존 문서의 권장 필드 미작성 항목입니다.
- 관리자웹 프로덕션 빌드를 통과했습니다.
- 예약 목록 화면은 브라우저 기준으로 조회 오류를 재현·수정했고, Supabase 400 오류 없이 목록이 표시되는 것을 확인했습니다.
- 주요 사용자 시나리오 검증을 위한 E2E 시나리오 파일을 33개 범위로 정리했습니다.

## 5. 현재 정리 결과

- 관리자웹은 화면설계서 기준 route와 실제 퍼블리싱 route가 대부분 정합화된 상태입니다.
- 기획 문서에서는 고객사 검토가 필요한 산식, 원천 데이터, 제외 지표를 별도로 구분했습니다.
- 퍼블리싱 화면 중 데이터 미연동이던 주요 운영 화면은 실데이터 연동 범위로 순차 전환 중입니다.
- KPI 센터와 통합 대시보드는 유사하지만, KPI 센터는 담당자·지표별 성과 관리 화면, 통합 대시보드는 운영 현황 요약 화면으로 역할을 분리해 설명할 수 있는 상태입니다.
- 수업관리에는 예약 목록이 신규 정의되어, 고객사 요청 사항인 기간·수업·강사·상태 필터와 회원명·연락처 검색 기준이 반영된 상태입니다.
- 회원앱은 마켓플레이스, 결제/주문, 리워드, 커뮤니티, 시스템 상태 화면까지 확장되어 플랫폼형 앱 구조로 진입한 상태입니다.

## 6. 클라이언트 확인 필요 항목

- OT 등록 전환율의 최종 분모를 `OT 진행`으로 고정할지, 기존 월간보고의 `등록 / 신규` 구조와 병행할지 확인이 필요합니다.
- OT 이월률 분모를 `OT배정 인원`, `OT 진행`, `신규등록` 중 어떤 기준으로 볼지 확정이 필요합니다.
- 예약 목록의 상태 처리 권한을 트레이너, FC, 스태프에게 어느 범위까지 허용할지 최종 확인이 필요합니다.
- 예약 취소 사유의 필수 항목과 표준 사유 목록을 둘지 확인이 필요합니다.
- 상품 GX 세부종목 6종 명칭을 요가·필라테스·스피닝·줌바·에어로빅·GX 기타로 고정할지 확인이 필요합니다.
- 회원앱 마켓플레이스의 센터/트레이너 노출 정책과 정렬 기준 확정이 필요합니다.
- 회원앱 결제/주문/환불 화면의 실제 백엔드 API 스펙 확정이 필요합니다.
- 회원앱 메신저의 실시간 통신 범위와 알림 정책 확정이 필요합니다.
