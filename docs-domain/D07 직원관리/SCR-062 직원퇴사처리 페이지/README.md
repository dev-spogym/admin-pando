## 2. 화면 개요와 목적

직원 퇴사 처리 페이지는 퇴사 예정인 직원의 퇴사일을 설정하고, 해당 직원이 담당하던 미완료 업무·회원·수업·계약을 인수인계한 뒤 시스템 계정을 비활성화하는 4단계 위자드 화면입니다. 본 시스템은 `직원 1명 = 로그인 계정 1개` 정책을 따르므로 퇴사 처리는 직원 상태 변경과 로그인 계정 비활성화를 동시에 수행합니다. 퇴사 처리가 완료되면 해당 직원은 재직 상태에서 제외되고 이후 로그인이 차단되며, 활성 세션도 즉시 만료됩니다. "퇴사처리" 텍스트를 직접 입력해야 최종 버튼이 활성화되는 이중 확인 절차(DLG-060-002)로 실수를 방지합니다.

이 화면이 다루는 운영 흐름은 다음과 같습니다. 자발 퇴사(이직)는 직원 통보 → 퇴사 예정일 등록 → 인수인계 단계별 진행 → 퇴사 확정일 도래 시 자동 처리 흐름을 따릅니다. 권고 퇴사(계약 위반)는 즉시 퇴사로 처리되어 계정이 즉시 비활성화되고 캘린더 일정도 즉시 정리됩니다. 계약 만료는 계약 종료일 = 퇴사 확정일로 D-30 사전 알림을 통해 인수인계가 준비됩니다. 휴직 후 미복귀 퇴사는 휴직 상태에서 직접 퇴사 처리되며, 인계는 휴직 시 사전 정리되어 있다는 전제 하에 진행됩니다. FC와 트레이너를 겸직하는 직원의 경우 회원은 다른 FC, 수업은 다른 트레이너로 분리 인계됩니다. 본사 슈퍼관리자는 통합 모드에서 다른 지점 직원도 퇴사 처리할 수 있으며, 이때 인계자는 해당 지점 직원 중에서만 선택 가능합니다.

따라서 이 화면은 단순한 퇴사 처리 폼이 아니라, 인사·인수인계·계정 보안·캘린더 정리·급여 일할 계산·노무 외부 처리까지 모두 다루는 멀티 도메인 위자드로 동작해야 합니다.

## 3. 진입 경로와 인접 화면

이 화면에 진입하는 경로는 세 가지입니다.

첫 번째 경로는 직원 목록(SCR-060)의 일괄 퇴사 처리입니다. SCR-060에서 한 명 이상의 직원을 체크박스로 선택한 뒤 [퇴사 처리] 버튼을 누르면 DLG-060-002가 호출되고, "퇴사처리" 텍스트 입력을 통과한 다음 이 화면으로 진입합니다. 일괄 선택에 이미 퇴사된 직원이 포함되어 있으면 자동 제외되며, 위자드 상단에 "총 N명 일괄 퇴사 처리"라는 카운트가 표시됩니다.

두 번째 경로는 직원 상세 패널의 헤더 [퇴사 처리] 버튼입니다. SCR-060의 상세 패널 또는 STF-02 상세 화면에서 헤더 액션의 [퇴사 처리]를 누르면 그 직원 한 명을 대상으로 이 화면이 열립니다. 단일 퇴사 처리의 경우 위자드 상단에 직원 이름이 강조 표시됩니다.

세 번째 경로는 더보기 메뉴입니다. SCR-060 테이블 행의 더보기 메뉴에서 [퇴사 처리] 항목을 누르면 그 직원 한 명을 대상으로 진입합니다.

이 화면에서 빠져나가는 인접 화면으로는, 처리 완료 후 자동 복귀하는 직원 목록(SCR-060), 인계자 검색 시 후보가 표시되는 직원 목록의 데이터 풀(`GET /api/staff/:id/handover-targets`), 인계 결과가 즉시 반영되는 수업 캘린더(SCR-C001)와 회원 상세(SCR-M004), 일할 계산이 반영되는 급여 관리(SCR-064), 그리고 모든 퇴사 처리·취소 이벤트가 기록되는 감사 로그(SCR-097)가 있습니다. 임금 정산과 4대 보험 상실 신고는 외부 노무사 시스템에서 별도 처리되며, 이 화면에서는 안내 박스만 표시됩니다.

## 4. 레이아웃과 UI 구성

화면은 위에서 아래로 단계별 진행 표시기와 본문, 그리고 하단 액션 바가 차곡차곡 쌓이는 위자드 레이아웃입니다. 데스크톱·태블릿에서는 좌측에 단계 진행 사이드바(1·2·3·4 단계 라벨과 현재 단계 강조)가 표시되고, 우측에 본문이 펼쳐집니다. 모바일에서는 단계 진행 표시기가 화면 상단에 가로 막대 형태로 표시되며, 본문은 단계별 풀스크린 슬라이드로 자동 전환됩니다.

화면 최상단에는 페이지 헤더가 있습니다. 좌측에는 "직원 퇴사 처리"라는 페이지 타이틀과 함께 대상 직원 수(예: "1명 선택" 또는 "5명 선택")가 표시되고, 우측에는 페이지 닫기(X) 아이콘이 있어 위자드를 중단하고 SCR-060으로 복귀할 수 있습니다. 닫기 클릭 시 폼이 dirty 상태이면 확인 모달이 호출됩니다.

페이지 헤더 아래에는 단계 진행 표시기가 있습니다. 1단계 퇴사 정보 → 2단계 인수인계 → 3단계 스케줄 정리 → 4단계 최종 확인 순서로 표시되며, 현재 단계는 강조 색으로, 통과한 단계는 체크 아이콘으로, 남은 단계는 회색 톤으로 표시됩니다. 인계 대상이 없는 직원의 경우 2단계는 자동 skip되어 "담당 업무 없음"으로 표시됩니다.

### 4-1. 1단계 - 퇴사 정보 입력

1단계 본문은 퇴사 대상 직원 정보 카드와 퇴사 정보 입력 폼으로 구성됩니다. 퇴사 대상 직원 정보 카드에는 직원 이름·직무·입사일·재직 기간·담당 회원 수·예약 수업 수·진행 중 계약 수가 요약 표시되어, 운영자가 인계 대상의 규모를 사전에 인지할 수 있게 합니다. 일괄 모드에서는 카드가 직원 수만큼 펼쳐지거나 "총 N명" 형태로 압축 표시됩니다.

퇴사 정보 입력 폼은 퇴사 확정일(캘린더 필수), 퇴사 예정일(캘린더 선택), 퇴사 사유 카테고리(라디오 - 자발/권고/계약 만료/기타), 추가 의견(textarea, 내부 메모)으로 구성됩니다. 퇴사 확정일이 오늘 또는 과거이면 "즉시 퇴사 처리됩니다" 인라인 안내가 표시되며, 계정 즉시 비활성화와 세션 만료 정책이 4단계에서 다시 강조됩니다. 미래 확정일은 "퇴사 예정 상태로 등록됩니다. 확정일 도래 시 자동 비활성화됩니다"로 안내되고, 1년 이상 미래는 인라인 경고가 표시되지만 진행은 가능합니다.

### 4-2. 2단계 - 미완료 업무 인수인계

2단계 본문은 인수인계 대상 카테고리 4종(담당 회원·예약된 수업·진행 중인 계약·OT 진행 중 회원)이 카드 또는 섹션으로 분리되어 표시됩니다. 각 카테고리는 처음에 접혀 있다가 클릭으로 펼쳐지며, 펼치면 해당 직원의 인계 대상 목록과 인계자 선택 영역이 노출됩니다.

인계자 선택은 같은 지점 내 같은 직무 직원이 우선 노출되는 드롭다운 또는 검색 인풋이 사용됩니다. 본인을 인계자로 선택하려고 하면 인라인 에러 "본인은 인계자가 될 수 없습니다"가 표시되고, 휴직·퇴사 직원도 차단됩니다. 다른 직무 인계 시(FC를 트레이너에게 등) 정책 토글에 따라 경고 또는 진행 차단이 표시됩니다. 본사 통합 모드에서 다른 지점 직원으로의 인계는 테넌트 정책에 따라 차단 또는 허용되며, 차단 정책에서는 같은 지점 직원만 검색됩니다.

일괄 또는 회원별 분배 토글이 있어, 담당 회원을 한 명에게 일괄 인계하거나 회원별로 나눠 인계할 수 있습니다. OT 진행 중 회원은 자동으로 잔여 OT가 인계 트레이너에게 이전되며, 인계자 미지정 시 진행 차단됩니다.

인계 대상이 0건인 직원의 경우 이 단계 자체가 자동 skip되며, "담당 업무 없음" 안내와 함께 다음 단계로 넘어갑니다.

### 4-3. 3단계 - 스케줄 정리 미리보기

3단계 본문은 퇴사 확정일 이후 자동 정리될 일정 미리보기가 표시됩니다. 회원과의 예약 수업은 인계자 일정으로 자동 이동되며, 휴가·외근 일정은 자동 삭제됩니다. 미리보기에는 일정 종류(수업/휴가/외근)·일자·시간·인계자(수업의 경우)가 카드 리스트로 표시되어, 운영자가 정리 결과를 사전에 확인할 수 있게 합니다. 인계자가 지정되지 않은 일정은 빨강 라벨로 강조 표시되며, 2단계로 돌아가 인계자를 지정해야 합니다.

자동 정리 대상이 많은 경우에는 카테고리별 카운트(예: "수업 23건 인계, 휴가 5건 삭제, 외근 2건 삭제")로 요약 표시되고, [상세 보기] 클릭 시 전체 목록이 펼쳐집니다.

### 4-4. 4단계 - 계정 비활성화 안내 및 최종 확인

4단계 본문은 계정 비활성화 안내 박스와 데이터 보존 정책 안내, 임금 정산·4대 보험 외부 처리 안내 박스, 그리고 최종 [처리 완료] / [취소] 버튼으로 구성됩니다. 안내 박스는 다음 내용을 포함합니다.

- 즉시 퇴사(확정일 = 오늘 또는 과거): "퇴사 처리 즉시 로그인 계정이 비활성화되고 활성 세션이 만료됩니다"
- 예약 퇴사(확정일 = 미래): "퇴사 확정일({날짜}) 도래 시 자동으로 로그인 계정이 비활성화됩니다"
- 데이터 보존: "퇴사 직원의 인사·실적·근태·급여·메모 데이터는 영구 보존됩니다"
- 본인 데이터 접근: "퇴사 직원 본인은 본인 급여 명세서를 5년간 이메일 링크로 조회할 수 있습니다"
- 임금 정산: "임금 정산은 별도 노무사 시스템에서 진행하세요"
- 4대 보험: 권고 퇴사·계약 만료 시 "4대 보험 상실 신고는 외부 시스템에서 진행하세요"

[처리 완료] 버튼은 강조 색(빨강 계열)으로 표시되며, 클릭 시 DLG-060-002가 한 번 더 호출됩니다. "퇴사처리" 텍스트를 정확히 입력하고 [퇴사 처리] 버튼을 눌러야 최종 실행됩니다. [취소] 버튼은 위자드를 중단하고 SCR-060으로 복귀하며, dirty 상태이면 확인 모달이 호출됩니다.

## 5. 단계별 동작과 분기

각 단계는 다음 단계로 넘어가기 전에 단계별 검증을 통과해야 합니다.

1단계는 퇴사 확정일이 입력되어 있어야 다음 단계로 넘어갈 수 있습니다. 퇴사 사유 카테고리는 통계용으로 필수이며, 미선택 시 인라인 에러가 표시됩니다. 추가 의견은 선택입니다. 과거 확정일은 경고 모달을 통과해야 진행되며, 이는 Owner(지점장)+ 권한에만 허용됩니다(매니저는 과거일 즉시 퇴사 강행이 차단됨).

2단계는 인계자 지정이 필수입니다. 인계 대상이 0건이면 자동 skip되어 3단계로 넘어가지만, 인계 대상이 있는데 인계자가 한 명이라도 미지정이면 [다음] 버튼이 비활성화되고 미지정 항목이 빨강 라벨로 강조됩니다. 인계자 본인 선택, 휴직/퇴사 직원 인계자 지정은 모두 차단됩니다.

3단계는 정리 미리보기를 확인만 하면 다음 단계로 넘어갈 수 있습니다. 단, 인계자 미지정 일정이 발견되면 2단계로 돌아가도록 안내가 표시됩니다.

4단계에서 [처리 완료]를 누르면 DLG-060-002가 호출되고, "퇴사처리" 텍스트 입력을 통과해야 최종 실행됩니다. 일괄 모드에서는 처리 가능 직원과 차단 직원(이미 퇴사·정산 미완료·권한 부족 등)이 분리되어 표시되며, 차단 직원은 처리 대상에서 자동 제외됩니다.

위자드 도중 단계 진행 사이드바의 이전 단계를 누르면 그 단계로 즉시 돌아갈 수 있으며, 입력된 값은 보존됩니다. 단계를 건너뛰는 것은 불가하며, 인계 대상 없음으로 인한 2단계 자동 skip만 허용됩니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

페이지 헤더 우측의 [X 닫기] 아이콘은 위자드를 중단하고 SCR-060으로 복귀합니다. 폼이 dirty 상태이면 "작성 중인 내용이 있습니다. 정말 중단하시겠습니까?" 확인 모달이 호출됩니다.

단계 진행 사이드바의 각 단계 라벨은 클릭 시 해당 단계로 이동합니다. 이전 단계는 자유롭게 이동 가능하고, 다음 단계는 현재 단계의 검증을 통과해야 이동 가능합니다.

본문 하단의 [이전] / [다음] 버튼은 단계 간 이동에 사용됩니다. 1단계에서는 [이전] 버튼이 비활성화되고, 4단계에서는 [다음] 대신 [처리 완료] 버튼이 표시됩니다.

2단계 인계자 검색 인풋은 디바운스 300ms로 같은 지점 직원(또는 본사 통합 모드에서 같은 지점 직원만)을 자동 검색합니다. 검색 결과 카드에는 이름·직무·현재 담당 회원 수가 표시되어, 인계자가 적절한지 즉시 판단할 수 있게 합니다.

2단계의 [일괄 인계] 버튼은 모든 회원을 한 명에게 인계하며, [회원별 분배] 버튼은 회원별로 인계자를 따로 지정합니다. 토글로 전환 가능합니다.

3단계의 [상세 보기] 버튼은 정리 대상 일정의 전체 목록을 펼쳐 보여줍니다. 다시 누르면 카운트 요약으로 접힙니다.

4단계의 [처리 완료] 버튼은 DLG-060-002를 호출합니다. 이중 확인 텍스트를 통과하면 백엔드로 `POST /api/staff/:id/resign` 요청이 전송되며, 일괄 모드에서는 `POST /api/staff/bulk-resign` 또는 직원별 반복 호출로 처리됩니다. 처리 중 버튼은 로딩 상태로 전환되어 중복 클릭이 차단됩니다.

[취소] 버튼은 SCR-060으로 복귀하며, dirty 상태이면 확인 모달이 호출됩니다.

위자드 처리 완료 후 SCR-060 상세 패널의 [퇴사 취소] 버튼은 Owner(지점장)+ 권한자에게만 노출되며, 퇴사 처리 후 24시간 이내·인계 데이터 미변경 상태에서만 활성화됩니다. 누르면 `POST /api/staff/:id/cancel-resign` 요청이 전송되어 재직 상태로 복귀하고 인계 데이터가 원래 직원에게 복원됩니다. 24시간 초과 시 버튼이 자동 hidden되며, 인계 데이터가 변경된 후에는 "인계 작업이 진행되어 취소할 수 없습니다" 안내가 표시됩니다.

모든 버튼은 클릭 후 응답이 돌아오기 전까지 비활성화되어 중복 요청이 차단됩니다.

## 7. 호출되는 모달 동작

### 7-1. DLG-060-002 직원 삭제(퇴사) 확인 다이얼로그

이 화면의 4단계에서 [처리 완료] 버튼을 클릭하면 호출됩니다. SCR-060에서 위자드 진입 전 한 번 호출되었지만, 위자드 마지막 단계에서 다시 한 번 호출되는 이중 안전 장치 구조입니다. 모달 상단에는 "직원 퇴사 처리"라는 제목이 표시되고, 그 아래에 "선택한 {인원수}명의 직원을 퇴사 처리하시겠습니까? 퇴사 처리 시 해당 직원의 계정 접근이 제한됩니다"라는 안내가 표시됩니다. 모달 가운데에는 "퇴사처리" 텍스트를 직접 타이핑해야만 활성화되는 확인 입력 필드가 있고, 텍스트가 정확히 일치할 때만 빨강 계열의 [퇴사 처리] 버튼이 활성화됩니다. [취소] 버튼은 모달을 닫고 위자드 4단계로 복귀합니다.

[퇴사 처리] 확정 후에는 직원 상태가 `WITHDRAWN`(퇴사)으로 전환되고 계정이 즉시 비활성화되며 활성 세션이 강제 만료됩니다. 인계 회원·수업·계약·OT는 지정된 인계자에게 자동 이전되고, 휴가·외근 일정은 자동 삭제됩니다. SCR-060으로 자동 복귀하면서 "n명의 퇴사 처리가 완료되었어요" 성공 토스트가 표시됩니다. 일괄 모드에서 부분 실패가 발생하면 결과 카드가 표시되고 실패 직원의 사유가 함께 노출됩니다.

### 7-2. 즉시 퇴사 확인 모달 (확정일 과거 입력 시)

1단계에서 퇴사 확정일을 오늘 또는 과거로 선택하면 "퇴사 확정일이 오늘 또는 과거입니다. 즉시 퇴사 처리되어 계정이 즉시 비활성화됩니다. 진행하시겠습니까?" 경고 모달이 호출됩니다. 확인을 누르면 1단계가 통과되고 즉시 퇴사 컨텍스트가 위자드에 적용됩니다. 취소를 누르면 확정일이 미입력 상태로 돌아갑니다. 과거일 즉시 퇴사 강행은 Owner(지점장)+ 권한만 가능하며, 매니저는 이 모달이 호출되지 않고 인라인 에러로 차단됩니다.

### 7-3. 위자드 중단 확인 모달

페이지 헤더의 [X 닫기] 또는 [취소] 버튼을 dirty 상태에서 누르면 "작성 중인 내용이 있습니다. 정말 중단하시겠습니까? 입력한 내용이 저장되지 않습니다" 모달이 호출됩니다. [중단]을 누르면 위자드 데이터가 폐기되고 SCR-060으로 복귀하며, [계속 작성]을 누르면 모달이 닫히고 위자드가 유지됩니다.

## 8. 토스트와 확인 팝업과 알럿

성공 토스트는 우측 상단에 녹색 계열로 5초 동안 표시됩니다. "n명의 퇴사 처리가 완료되었어요", "퇴사 취소가 완료되었어요"가 대표적입니다.

실패 토스트는 우측 상단에 빨강 계열로 표시되며, "퇴사 처리에 실패했습니다", "다른 사용자가 처리 중입니다", "인계 자동 이전이 일부 실패했어요"가 대표적입니다.

부분 결과 알림은 일괄 퇴사 처리에서 일부 직원만 실패했을 때 결과 카드 형태로 표시됩니다. "성공 4명 / 실패 1명"처럼 두 가지 숫자가 동시에 표시되며, 실패 사유(이미 퇴사·정산 미완료·권한 부족·인계 race condition 등)가 직원별로 분리 표시됩니다. 실패 리포트 CSV 다운로드 링크가 함께 제공되어 사후 정리 자료로 활용됩니다.

확인 팝업은 즉시 퇴사 확인, 위자드 중단 확인, 인계자 직무 불일치 경고 등 별도 모달로 호출됩니다.

알럿은 권한 없는 계정이 직접 URL로 접근했을 때 표시됩니다. 페이지 본문이 전부 가려지고 "이 화면에 접근할 권한이 없습니다" 메시지와 함께 3초 카운트다운 후 대시보드로 자동 이동됩니다.

## 9. 데이터 흐름과 외부 연동

이 화면의 데이터 흐름은 여러 외부 시스템과 자동 동기화됩니다.

위자드 진입 시점에는 대상 직원의 인계 요약 정보를 조회하는 API(`GET /api/staff/:id/handover-summary`)가 호출되어 1단계 카드에 표시됩니다. 일괄 모드에서는 직원별로 순회 호출되며, 인계 대상 카운트가 합산되어 위자드 상단에 표시됩니다.

2단계 인계자 검색은 `GET /api/staff/:id/handover-targets`로 같은 지점(또는 정책에 따라 다른 지점)의 활성 직원만 검색합니다. 검색은 디바운스 300ms로 동작하며, 휴직·퇴사 직원·본인은 결과에서 자동 제외됩니다.

3단계 정리 미리보기는 `GET /api/staff/:id/cleanup-preview`로 캘린더·수업·휴가·외근 데이터를 종합 조회해 카운트와 카드 리스트로 표시합니다.

4단계 [처리 완료] 실행은 트랜잭션으로 처리됩니다. `POST /api/staff/:id/resign` 또는 일괄 `POST /api/staff/bulk-resign`이 호출되며, 다음 작업이 동시에 일어납니다.

1. 직원 상태를 `WITHDRAWN`으로 변경.
2. 로그인 계정을 deactivate(Supabase Auth `action: "deactivate"`).
3. 활성 세션을 강제 만료.
4. 인계 대상(회원·수업·계약·OT)을 지정된 인계자에게 자동 이전.
5. 자동 삭제 대상(휴가·외근)을 캘린더에서 제거.
6. 퇴사 D-30·D-7 알림 큐를 정리(이미 등록되어 있던 경우).
7. 퇴사 직원 본인에게 본인 명세서 5년 보존 이메일 링크 발송.
8. 임금 정산·4대 보험 외부 처리 안내 발송(권고/계약 만료 시).
9. 감사 로그(SCR-097)에 비동기 INSERT.

위자드 처리 중 인계 자동 이전이 일부 실패하면(race condition 등) 부분 성공 + 실패 항목 결과 카드가 표시됩니다. 실패 항목은 수동 재배정으로 안내됩니다.

퇴사 D-30 사전 알림은 NFR-19 알림 센터로 매니저+에게 발송되어 인수인계 준비를 유도합니다. 퇴사 D-7 시점에 인계자 미지정 상태이면 매니저에게 재알림이 발송됩니다. 이는 퇴사 처리 누락을 방지하기 위한 정책입니다.

퇴사 취소(`POST /api/staff/:id/cancel-resign`)는 Owner(지점장)만 24시간 이내·인계 미진행 상태에서 실행 가능합니다. 인계된 회원·수업·계약·OT가 모두 원래 직원에게 복원되고, 자동 삭제된 휴가·외근 일정도 복원됩니다. 계정도 다시 활성화됩니다. 인계 데이터가 한 건이라도 변경되면 취소 불가하며, 별도 처리 안내가 표시됩니다.

본사 슈퍼관리자 통합 모드에서는 다른 지점 직원도 퇴사 처리할 수 있으며, 인계자는 해당 지점 직원만 검색되어 잘못된 지점으로 인계되지 않도록 보장합니다.

캘린더 자동 정리는 퇴사 확정일이 미래인 경우 예정 상태로만 등록되고, 확정일 도래 시 매일 새벽 4시 배치가 자동으로 직원 상태를 `WITHDRAWN`으로 전환하고 캘린더·계정 처리를 수행합니다.

화면에서 호출하는 주요 API는 다음과 같습니다. 인계 요약 조회 `GET /api/staff/:id/handover-summary`, 인계자 검색 `GET /api/staff/:id/handover-targets`, 정리 미리보기 `GET /api/staff/:id/cleanup-preview`, 퇴사 처리 `POST /api/staff/:id/resign`, 일괄 퇴사 처리 `POST /api/staff/bulk-resign`, 퇴사 취소 `POST /api/staff/:id/cancel-resign`, 인계 이전 `POST /api/staff/:id/handover`, 감사 로그 `POST /api/audit-log`.

## 10. 화면 상태와 예외 처리

이 화면은 다음 상태들을 가집니다.

1단계 정상 상태는 퇴사 정보 입력 폼이 표시된 일반 상태입니다. 확정일·사유 카테고리·추가 의견 입력이 진행됩니다.

2단계 인계 대상 있음 상태는 인수인계 섹션이 활성화되어 카테고리별 인계자 선택이 가능합니다. 인계자 미지정 항목은 빨강 라벨로 강조됩니다.

2단계 인계 대상 없음 상태는 "담당 업무 없음"이 표시되고 자동 skip되어 3단계로 넘어갑니다.

3단계 정상 상태는 정리 미리보기가 표시되어 운영자가 확인할 수 있습니다. 인계자 미지정 일정이 있으면 빨강 라벨로 강조되고 2단계로 돌아가도록 안내가 표시됩니다.

4단계 보안 확인 상태는 계정 비활성 안내·데이터 보존 정책·외부 처리 안내 박스가 표시됩니다.

처리 중 상태는 [처리 완료] 클릭 후 백엔드 응답을 기다리는 동안 표시되며, 모든 버튼이 비활성화되고 로딩 스피너가 노출됩니다.

처리 완료 상태는 성공 토스트와 함께 SCR-060으로 복귀합니다.

즉시 퇴사 상태는 확정일이 오늘 또는 과거인 경우 4단계에 "즉시 퇴사 처리 - 계정 즉시 차단" 강조 안내가 표시됩니다.

예약 퇴사 상태는 확정일이 미래인 경우 4단계에 "확정일({날짜}) 도래 시 자동 처리" 안내가 표시됩니다.

동시 처리 차단 상태는 같은 직원에 대해 다른 운영자가 동시에 퇴사 처리를 진행 중인 경우 "다른 사용자가 처리 중입니다" 모달이 표시되고 위자드 진행이 차단됩니다.

모바일 위자드 상태는 단계별 풀스크린 슬라이드로 자동 전환됩니다.

퇴사 취소 가능 상태는 24시간 이내·인계 미진행 상태에서 SCR-060 상세 패널의 [퇴사 취소] 버튼이 Owner(지점장)에게 노출됩니다.

퇴사 취소 불가 상태는 24시간 초과 또는 인계 데이터 변경 발생 후에 버튼이 hidden되거나 안내 메시지로 대체됩니다.

예외 케이스별 처리는 다음과 같습니다.

담당 회원 0건 + 예약 수업 0건 + 계약 0건 + OT 0건이면 2단계가 자동 skip되며 "담당 업무 없음" 안내가 표시됩니다.

인계자 미지정 상태에서 [다음] 클릭 시 인라인 에러 "인계자를 지정해주세요"와 함께 미지정 항목이 빨강 라벨로 강조되며 진행이 차단됩니다.

인계자가 본인이거나 휴직·퇴사 직원이면 인라인 에러가 표시되고 인계자 드롭다운에서 자동 제외됩니다.

인계 직무 불일치(FC를 트레이너에게 등)는 정책 토글에 따라 경고 모달 또는 진행 차단으로 처리됩니다.

본사 통합 모드에서 다른 지점 직원으로의 인계는 정책 토글에 따라 차단 또는 허용되며, 차단 정책에서는 같은 지점 직원만 검색 노출됩니다.

퇴사 확정일이 과거이면 즉시 퇴사 확인 모달이 호출되고, Owner(지점장)+ 권한에만 진행이 허용됩니다.

퇴사 확정일이 1년+ 미래이면 인라인 경고 "확정일이 1년 이상 미래입니다"가 표시되지만 진행은 가능합니다.

DLG-060-002 텍스트 불일치 시 최종 버튼은 비활성 유지되며, 사용자가 정확히 "퇴사처리"를 입력해야 합니다.

다른 사용자가 동시에 같은 직원을 퇴사 처리 중이면 "다른 사용자가 처리 중입니다" 모달이 표시되고 진행이 차단됩니다.

처리 중 네트워크 오류가 발생하면 토스트 안내와 함께 위자드 상태가 유지되어 [다시 시도]가 가능합니다.

퇴사 취소 시 24시간 초과 또는 인계 데이터 변경 발생 후에는 취소 불가 안내가 표시됩니다.

퇴사 처리 후 본인 로그인 시도 시 "비활성 계정입니다" 안내와 함께 로그인이 차단되고, 본인 명세서 5년 이메일 링크는 별도로 유효합니다.

자동 정리된 휴가·외근 일정은 3단계 미리보기에서 명시적으로 표시되어 사용자가 사전에 확인할 수 있습니다.

인계 자동 이전이 race condition으로 일부 실패하면 부분 성공 + 실패 항목 결과 카드가 표시되고 수동 재배정 안내가 함께 제공됩니다.

모바일 풀스크린 슬라이드에서는 단계 간 좌우 스와이프로 이동도 가능하지만, 검증 통과 전에는 다음 단계로 스와이프되지 않습니다.

권고 퇴사·계약 만료 시 4대 보험 상실 신고 외부 처리 안내 박스가 4단계에 추가로 표시됩니다.

## 11. 권한별 처리

이 화면은 권한이 단계적으로 제한됩니다.

본사 슈퍼관리자(superAdmin)·본사 최고관리자(primary)는 전 지점 퇴사 처리·통합 모드 처리·퇴사 취소 모두 가능합니다.

Owner(지점장)은 소속 지점 퇴사 처리 전체 폼을 사용할 수 있으며, 추가로 퇴사 취소(24h 내·인계 미진행)·정산 미완료 강제 확정·과거일 즉시 퇴사 강행이 허용됩니다.

매니저(manager)는 퇴사 처리 폼을 사용해 퇴사 처리 생성·진행이 가능합니다. 단, 퇴사 취소·정산 미완료 강제 확정·과거일 즉시 퇴사 강행은 차단되며, 과거일 확정일 입력 시 인라인 에러로 진행이 막힙니다.

기타 직원(FC·트레이너·스태프·프런트·readonly·직원 본인)은 이 화면에 접근할 수 없습니다. SCR-060에서 [퇴사 처리] 버튼 자체가 hidden이며, 직접 URL로 접근하면 권한 차단 페이지가 표시되고 3초 후 대시보드로 자동 이동됩니다.

권한이 부족해 액션이 차단된 경우의 사용자 경험은 일관됩니다. 1차 진입점(SCR-060의 [퇴사 처리] 버튼)에서 버튼이 hidden되고, 화면 내부의 권한 차단은 백엔드 응답이 403이 되어 토스트로 안내됩니다. 모든 권한 차단 이벤트는 감사 로그에 기록됩니다.

## 14. 핵심 디자인 요청사항

위자드의 단계 진행 명확성이 가장 중요한 화면이므로, 다음 디자인 원칙이 시각적으로 명확히 드러나야 합니다.

단계 진행 표시기는 현재 단계와 통과한 단계, 남은 단계가 색상과 아이콘으로 강하게 구분됩니다. 현재 단계는 강조 색(파랑 또는 녹색)으로, 통과한 단계는 체크 아이콘과 옅은 녹색으로, 남은 단계는 회색 톤으로 표시됩니다. 자동 skip된 2단계는 별도 라벨("담당 업무 없음")로 표시됩니다.

[처리 완료] 버튼은 빨강 계열로 표시되어 위험한 액션임을 시각적으로 강조합니다. 단순 [다음] 버튼과는 명확히 구분되며, 클릭 직전에 한 번 더 시각적 경고가 들어옵니다.

인계자 미지정 항목은 빨강 라벨과 함께 카드 테두리가 빨강 톤으로 변해, 운영자가 어떤 항목을 더 채워야 하는지 즉시 인지할 수 있습니다.

자동 정리 미리보기 카드는 일정 종류별로 아이콘(수업: 일정 아이콘, 휴가: 휴식 아이콘, 외근: 이동 아이콘)이 표시되어 카테고리가 시각적으로 구분됩니다. 인계자가 지정된 일정은 인계자 이름과 함께 옅은 녹색 톤으로, 자동 삭제 일정은 옅은 빨강 톤으로 표시됩니다.

계정 비활성화 안내 박스는 강조 톤(주황 또는 빨강 인포 박스)으로 표시되며, 즉시 퇴사 vs 예약 퇴사가 색상과 라벨로 명확히 구분됩니다. 데이터 보존 정책과 외부 처리 안내는 회색 톤 인포 박스로 분리되어, 정보 우선순위가 시각적으로 드러납니다.

위자드 중단·취소·이동 시 호출되는 모달은 모두 일관된 톤(노랑 경고 + 회색 본문)으로 통일되어, 사용자가 같은 패턴으로 인식할 수 있게 합니다.

모바일 위자드는 단계별 풀스크린 슬라이드 전환 애니메이션을 사용하며, 좌측에 [이전] 화살표와 우측에 [다음] 또는 [처리 완료] 버튼이 고정 배치됩니다.

일괄 모드에서 직원별 카드는 카드 헤더에 직원명·직무 배지가 표시되어, 운영자가 어떤 직원의 인계를 진행 중인지 한눈에 알 수 있습니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

이 화면은 단순한 처리 폼이 아니라 퇴사·인수인계·계정 보안·데이터 보존·외부 노무 처리까지 모두 다루는 운영 정책의 결합점입니다.

직원 1명 = 로그인 계정 1개 원칙에 따라 퇴사 처리는 직원 상태 변경과 로그인 계정 비활성화를 동시에 수행합니다. 활성 세션도 즉시 강제 만료되며, 이후 로그인은 차단됩니다. 이는 보안 정책의 핵심이며, 어떤 예외도 허용되지 않습니다.

퇴사 권한은 단계적으로 제한됩니다. 일반 퇴사 처리 생성·진행은 매니저+가 가능하지만, 퇴사 취소(24h 내·인계 미진행 한정)·정산 미완료 강제 확정·과거일 즉시 퇴사 강행은 Owner(지점장)+에게만 허용됩니다. 이는 운영 실수의 위험이 큰 액션을 추가 권한자에게만 허용해 사고를 방지하기 위한 정책입니다.

이중 확인 절차(DLG-060-002 + "퇴사처리" 텍스트 입력)는 모든 퇴사 처리에 강제 적용됩니다. SCR-060 진입 시 한 번, 위자드 4단계 [처리 완료] 클릭 시 한 번 더 호출되어 총 두 번의 확인을 거칩니다. 이는 실수로 인한 잘못된 퇴사 처리를 방지하기 위한 안전 장치입니다.

위자드 4단계 강제 진행 정책은 1→2→3→4 순차 진행만 허용되며, 단계 건너뛰기는 불가합니다. 단, 인계 대상이 없는 직원의 경우 2단계는 자동 skip되어 3단계로 넘어갑니다. 이는 운영자가 인계 대상을 빠뜨리지 않도록 강제하는 정책입니다.

인계자 선택 정책은 같은 지점 내 같은 직무 직원을 우선 노출합니다. 본인·휴직·퇴사 직원은 인계자에서 자동 차단되며, 다른 직무 인계는 테넌트 정책에 따라 경고 또는 차단됩니다. 본사 통합 모드에서 다른 지점 직원으로의 인계는 정책에 따라 차단되거나 허용됩니다.

OT 잔여 자동 이전 정책은 OT1·OT2 미완료 회원의 잔여 OT를 인계 트레이너에게 자동 부여합니다. 이는 회원 운영 연속성을 보장하기 위한 정책이며, 별도 수동 처리가 필요하지 않습니다.

자동 캘린더 정리 정책은 퇴사 확정일 이후 모든 본인 일정을 자동 정리합니다. 회원과의 예약 수업은 인계자에게 이동되고, 휴가·외근은 자동 삭제됩니다. 이는 캘린더의 무결성과 운영 연속성을 위한 정책입니다.

퇴사 D-30 사전 알림과 D-7 인수인계 미완료 알림은 매니저+에게 NFR-19 알림 센터로 발송됩니다. 이는 퇴사 준비 누락을 방지하기 위한 정책이며, 인계자 미지정 상태로 D-7에 도달하면 매니저에게 재알림이 발송됩니다.

퇴사 취소(당일 한정) 정책은 Owner(지점장)만 퇴사 처리 후 24시간 이내·인계 데이터 미변경 상태에서 가능합니다. 인계된 회원·수업·계약·OT가 모두 원래 직원에게 복원되고, 캘린더 일정도 복원되며, 계정도 다시 활성화됩니다. 인계 데이터가 한 건이라도 변경되면 취소가 불가하며, 별도의 수동 정리 절차가 필요합니다.

데이터 보존 정책은 퇴사 직원의 인사·실적·근태·급여·메모 데이터를 영구 보존합니다. 이는 감사·노무·법령 준수 목적이며, 익명화·아카이브는 정책에 따라 적용됩니다. 퇴사 직원 본인은 본인 급여 명세서를 5년간 이메일 링크로 조회할 수 있으며, 그 외 시스템 접근은 차단됩니다.

본인 데이터 접근 정책은 퇴사 직원 본인이 본인의 급여 명세서·근로 증명서를 5년간 이메일 링크로 받아볼 수 있도록 보장합니다. 이는 직원 권리 보호와 법령 준수 목적이며, 퇴사 시점에 5년 유효 토큰이 발급됩니다.

본사 슈퍼관리자 통합 모드 정책은 다른 지점 직원의 퇴사 처리도 가능하지만, 인계자는 해당 지점 직원만 선택되도록 자동 제한됩니다. 이는 잘못된 지점으로 회원이 인계되어 데이터 무결성이 깨지지 않도록 하는 정책입니다.

퇴사 사유 비공개 정책은 직원 본인이 퇴사 사유 메모를 열람할 수 없도록 합니다. 사유 카테고리(자발/권고/계약 만료/기타)와 추가 의견은 관리자 전용이며, 본인에게는 단순한 퇴사 처리 안내만 발송됩니다.

임금 정산 외부 처리 안내는 모든 퇴사 처리에 표시됩니다. 시스템은 임금 계산까지만 담당하고, 실제 정산은 외부 노무사 시스템에서 진행됩니다. 4대 보험 상실 신고도 마찬가지로 외부 처리되며, 권고 퇴사·계약 만료 시 별도 안내 박스가 추가 표시됩니다.

휴직 → 직접 퇴사 정책은 휴직 상태의 직원을 즉시 퇴사 처리할 수 있도록 허용합니다. 인계는 휴직 시 사전 정리되어 있다는 전제 하에 진행되며, 휴직 종료를 기다리지 않고 곧장 퇴사 처리가 가능합니다.

퇴사 후 재입사 정책은 신규 등록(STF-EXT-01)으로 처리됩니다. 기존 직원 ID는 유지되지 않고 새 레코드가 생성되며, 인사 파일은 검색으로 연결 가능합니다.

감사 로그는 모든 퇴사 처리·취소·인계 이전 이벤트를 SCR-097에 비동기로 기록합니다. 기록 필드는 `actor_id`, `staff_id`, `reason`, `handover_to`, `branch_id`, `timestamp`이며, append-only로 영구 보존됩니다.

이상의 모든 정책은 이 화면을 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다. 정책이 바뀌면 이 문서가 함께 갱신되어야 하며, 코드 변경과 정책 변경은 항상 짝지어 진행됩니다.
