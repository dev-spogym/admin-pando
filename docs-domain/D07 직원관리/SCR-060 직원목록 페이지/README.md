## 2. 화면 개요와 목적

직원 목록 페이지는 센터에 소속된 모든 직원의 현황을 한눈에 파악하고, 직무·재직 상태·소속 지점별로 빠르게 찾아 상세 패널로 이동하거나, 여러 직원을 한 번에 묶어 메시지를 보내고 상태를 일괄 변경하며, 퇴사 처리를 진행하는 직원관리 도메인의 핵심 허브 화면입니다. 사이드바의 직원 관리 메뉴를 누르거나 대시보드의 인력 지표 카드를 누르면 가장 먼저 진입하는 화면이며, 본사 관계자가 상단에서 "전체 지점(통합)" 모드를 선택한 경우에는 모든 지점의 직원이 함께 조회되며 각 직원이 어느 지점 소속인지가 목록과 엑셀 내보내기 결과에 그대로 표시됩니다.

이 화면이 다루는 운영 흐름은 매우 다양합니다. Owner(지점장)은 월초에 4종 요약 카드로 재직·휴직·퇴사 인원을 한 번에 확인해 휴직 복귀 예정자를 미리 파악하고, 매니저는 직무 필터로 트레이너만 골라 전체 선택 후 단체 공지 메시지를 보냅니다. 본사 슈퍼관리자는 통합 모드에서 지점별 트레이너·FC 격차를 살펴 본사 회의 자료를 만들고, 본사 최고관리자는 모든 필터를 해제한 상태에서 명단을 다운로드해 노무사·세무사에게 제출합니다. 신규 트레이너 채용이 확정되면 우측 상단의 직원 등록 버튼으로 곧장 SCR-061로 진입해 등록하며, 계약 만료 직원 5명을 동시에 퇴사 처리해야 할 때는 다중 선택 후 퇴사 처리 버튼을 눌러 DLG-060-002 확인을 거친 다음 SCR-062 위자드로 이동합니다. 매니저는 메모 컬럼 미리보기로 직원별 인사 이슈를 즉시 인지하고 직원명을 눌러 상세 패널에서 전체 메모를 확인합니다.

따라서 이 화면은 단순한 테이블이 아니라, 인사 권한 분리·계정 생명주기·근태/급여 자동 연동·본사 통합 모드·감사 로그까지 모두 반영된 운영 허브로 동작해야 합니다.

## 3. 진입 경로와 인접 화면

직원 목록 페이지에 진입하는 경로는 다음과 같이 여러 가지가 있고, 각 경로마다 진입 직후 화면의 초기 상태가 달라집니다.

첫 번째 경로는 사이드바입니다. 좌측 사이드바의 "직원 관리" 메뉴 아래 "직원 목록" 항목을 클릭하면 진입합니다. 이 경우 URL은 단순히 `/staff`가 되고, 화면은 기본 필터 상태(재직 상태 필터: 재직 기본, 직무 필터: 전체, 페이지 1, 페이지당 10건, 입사일 내림차순 정렬)로 시작합니다. 직전에 이 화면을 사용했다면 세션 스토리지에 5분 TTL로 저장된 필터·검색·페이지 상태가 자동 복원되어, 같은 운영 흐름을 이어서 진행할 수 있습니다.

두 번째 경로는 대시보드(SCR-101)의 인력 지표 카드 클릭입니다. 대시보드에서 "재직 인원", "휴직 인원", "퇴사 인원" 같은 지표 카드를 클릭하면 직원 목록 페이지로 이동하면서 그 지표에 대응하는 필터가 URL 쿼리 파라미터로 자동 적용된 상태로 진입합니다. 예를 들어 휴직 인원 카드를 누르면 `/staff?status=onLeave` 형태로 열립니다.

세 번째 경로는 글로벌 검색(SCR-103) 또는 알림 센터(SCR-104)에서의 클릭입니다. 글로벌 검색에서 직원명을 검색해 결과로 직원이 잡히면 곧장 직원 상세 패널이 열린 상태로 진입할 수 있고, "퇴사 D-30 직원 N명" 같은 직원군 알림은 목록 페이지로 이동하면서 해당 회원군 필터가 자동 적용됩니다.

네 번째 경로는 외부 도구에서 공유받은 북마크·딥링크입니다. URL 쿼리 파라미터로 필터·검색·페이지 상태가 모두 보존되므로, 매니저가 "트레이너 + 휴직" 같은 자주 쓰는 필터 조합을 북마크해 두고 매일 같은 URL로 진입할 수 있습니다.

다섯 번째 경로는 다른 도메인 화면에서의 역참조입니다. 회원 상세(SCR-M004)에서 담당 FC·트레이너 카드를 누르면 그 직원의 상세 패널로 곧장 들어오고, 수업 캘린더(SCR-C001)에서 직원 필터로 좁힌 뒤 직원명을 누르면 마찬가지로 직원 상세 패널이 열립니다.

이 화면에서 빠져나가는 인접 화면으로는, 직원명 클릭으로 진입하는 직원 상세 패널(같은 화면 내 우측 슬라이드 또는 모바일 풀스크린), 우측 상단 "직원 등록" 버튼으로 진입하는 직원 등록(SCR-061), 더보기 메뉴와 일괄 작업의 퇴사 처리로 진입하는 퇴사 처리(SCR-062), 일괄 작업의 메시지 전송으로 진입하는 메시지 발송(SCR-071), 상세 패널의 캘린더 진입 CTA로 가는 수업 캘린더(SCR-C001), 상세 패널의 담당 회원 카드로 가는 회원 상세(SCR-M004), 상세 패널의 NPS 후기 카드로 가는 수업 후기(SCR-C013), 그리고 모든 일괄 작업과 권한 변경 이벤트가 기록되는 감사 로그(SCR-097)가 있습니다.

## 4. 레이아웃과 UI 구성

직원 목록 페이지는 위에서 아래로 차곡차곡 쌓이는 세로형 단일 컬럼 레이아웃을 기본으로 합니다. 데스크톱에서는 가로 폭이 충분하므로 우측 상세 패널이 슬라이드 인 될 때 본문 가로폭이 자동으로 약 65% 정도로 축소되고, 태블릿에서는 본문 가로폭을 유지하면서 상세 패널이 우측 오버레이로 뜨며, 모바일(768px 미만)에서는 직원명을 누르면 풀스크린 슬라이드로 상세가 진입합니다. 화면은 위에서부터 다음 영역들이 순서대로 배치됩니다.

가장 위에는 페이지 헤더가 있습니다. 헤더 좌측에는 "직원 목록"이라는 페이지 타이틀과 함께, 현재 조회 중인 지점이 "전체 지점(통합)"인지 특정 지점인지를 알려주는 지점 컨텍스트 배지가 따라옵니다. 본사 권한자에 한해서만 본사 통합 모드 토글이 표시되며, 일반 지점 사용자에게는 토글 자체가 보이지 않습니다. 헤더 우측 끝에는 "직원 등록" 버튼이 있어 신규 등록 화면(SCR-061)으로 이동합니다. 이 버튼은 Owner(지점장)·매니저·본사 권한자에게만 보이며, FC·트레이너·스태프·프런트에게는 표시되지 않습니다.

페이지 헤더 바로 아래에는 요약 지표 카드 4개가 가로로 배치됩니다. 첫 번째 카드는 "전체 직원 수"로 등록된 모든 직원의 합계를 보여주며, 클릭하면 재직 상태 필터가 전체로 자동 적용됩니다. 두 번째 카드는 "재직 중 인원"으로 status=active인 직원만 카운트되며, 클릭 시 재직 필터가 자동 적용됩니다. 세 번째 카드는 "휴직 중 인원"으로 status=onLeave 카운트이며, 클릭 시 휴직 필터가 적용됩니다. 네 번째 카드는 "퇴사 인원"으로 status=resigned 카운트이며, 클릭 시 퇴사 필터가 적용됩니다. 본사 통합 모드에서는 모든 카드의 숫자가 전 지점 합산으로 표시되고, 카드 아래 작은 글씨로 "전 지점 합산"이라는 주석이 붙습니다. 카드 카운트는 매일 새벽 4시 KPI 배치와 실시간 업데이트(5분 TTL 캐시)로 갱신됩니다.

요약 카드 아래에는 검색 및 필터 바가 있습니다. 가장 왼쪽에는 통합 검색창이 있고, 직원 이름과 연락처를 동시에 OR 조건으로 검색할 수 있습니다. 검색은 입력 후 300ms 디바운스가 적용되어 타이핑이 끝나면 자동으로 결과가 갱신되며, 디바운스 도중 추가 입력이 들어오면 이전 요청은 cancel 처리됩니다. 연락처 검색은 하이픈 유무와 무관하게 매칭됩니다. 검색창 우측에는 직무 필터(Owner(지점장)·매니저·FC·트레이너·스태프·프런트·골프프로 7종, 멀티 선택), 본사 통합 모드 한정 소속 지점 필터, 재직 상태 필터(재직·휴직·퇴사 단일 선택)가 배치됩니다. 적용된 필터는 검색 바 아래에 칩 형태로 나란히 표시되며, 각 칩의 X 버튼을 누르면 해당 필터만 제거되고 "전체 해제" 링크를 누르면 모든 필터가 한 번에 초기화됩니다.

필터 바 아래에는 상단 액션 바가 있습니다. 좌측에는 "선택된 직원 n/N" 형식으로 현재 선택된 직원 수와 전체 직원 수가 표시되고, 우측에는 메시지 전송 / 상태 변경 / 퇴사 처리 / 명단 다운로드 버튼이 일렬로 놓입니다. 회원을 한 명도 선택하지 않은 상태에서는 메시지 전송·상태 변경·퇴사 처리 버튼이 비활성화 상태로 표시되어 누를 수 없으며, 명단 다운로드 버튼은 권한이 없는 계정(FC·스태프·프런트)에서는 아예 화면에 나타나지 않습니다.

상단 액션 바 아래에 직원 목록 테이블이 있습니다. 테이블의 컬럼은 좌측부터 선택 체크박스, 번호(No), 직원명(클릭 시 상세 패널 진입), 소속 지점(본사 통합 모드 한정), 직무 배지, 연락처, 입사일, 재직 상태 배지, 메모 미리보기(매니저+ 한정), 더보기 메뉴 순서로 배치됩니다. 직무 배지는 7종 직무에 따라 색상이 분기되어 멀리서 봐도 직무가 구분되어 보입니다. 재직 상태 배지는 재직은 success(녹색) 톤, 휴직은 warning(주황) 톤, 퇴사는 neutral(회색) 톤으로 표시됩니다. 메모 미리보기는 최대 30자에 말줄임이 적용되며, 매니저 미만 권한자에게는 컬럼 자체가 hidden 처리되어 overflow 영향이 없습니다. 퇴사 직원의 체크박스는 disabled 상태로 표시되며 hover 시 "이미 퇴사 처리된 직원입니다" 툴팁이 뜹니다. 직원명을 클릭하면 우측에 상세 패널이 슬라이드 인 되며, 모바일에서는 풀스크린으로 전환됩니다. 더보기 메뉴는 수정 / 메시지 / 퇴사 처리 항목을 권한에 따라 노출합니다.

테이블 아래에는 일괄 작업 활성 안내 바가 있습니다. 평소에는 단순한 카운트와 액션 버튼만 노출되지만, 직원을 1명 이상 체크박스로 선택하면 선택 수가 강조되고 일괄 액션 버튼이 활성화됩니다. 본사 통합 모드에서 일괄 작업을 수행하면 직원의 실제 `branchId` 기준으로 분기 처리되며, 트랜잭션은 지점별로 묶입니다.

페이지 가장 아래에는 페이지네이션 영역이 있습니다. 좌측에는 페이지당 표시 건수(기본 10건), 가운데에는 페이지 번호 이동 컨트롤(이전·다음·페이지 번호 직접 입력), 우측에는 "총 N건"이라는 합계가 표시됩니다. 마지막 페이지를 넘어서는 페이지 번호를 입력하면 1페이지로 자동 이동됩니다.

마지막으로, 직원명을 클릭한 상태에서는 본문 우측에 직원 상세 패널이 슬라이드 인 됩니다. 이 패널에는 5개의 카드가 카드별 스켈레톤 로딩으로 부분 데이터부터 표시되며, 카드 하나가 실패해도 다른 카드는 정상 표시됩니다. 카드는 위에서부터 담당 회원 목록(이름·연락처·이용권 상태·마지막 출석일, 클릭 시 SCR-M004 진입), 담당 스케줄(이번 주/다음 주 수업 카드와 캘린더 진입 CTA), 실적 요약(이번 달 수업 진행 건수·신규 매출·재등록 매출·OT1·OT2 완료 수·NPS 평균 점수), 근태 요약(출근일·결근·지각·출근율 자동 계산), 인사 메모(매니저·Owner(지점장) 한정 비공개 메모, 카테고리·작성자·일시 기록), 그리고 계정/보안 카드(로그인 ID·권한 템플릿·계정 상태·마지막 로그인·비밀번호 변경 필요 여부·활성 세션 수·잠금/해제/임시비밀번호 재발급/권한 설정 진입 액션) 순서로 배치됩니다. 헤더 액션 버튼은 수정(SCR-061) / 퇴사 처리(SCR-062) / 메시지 보내기(SCR-071) 세 가지이며, 각각 매니저+ 권한이 필요합니다. 상세 패널은 30초 캐시되며, 헤더의 [새로고침] 버튼으로 강제 갱신할 수 있습니다.

## 5. 탭 구성과 탭별 동작

직원 목록 페이지는 회원 목록과 달리 운영 보기 탭·저장 뷰 탭의 중첩 구조를 가지지 않습니다. 분류는 단일 계층의 재직 상태 필터(재직·휴직·퇴사)와 직무 필터(7종 멀티)로만 이루어지며, 이는 직원의 분류 기준이 회원보다 훨씬 안정적이고 단순하기 때문입니다. 재직 상태 필터는 기본값이 "재직"이며, 퇴사자는 명시적으로 "퇴사" 필터를 선택해야만 노출됩니다. 즉 재직 상태 미선택 또는 다른 상태 선택 시에는 퇴사자가 자동 제외되며, 이는 운영자가 실수로 퇴사자에게 메시지를 보내거나 일괄 작업을 수행하는 것을 방지하기 위한 정책입니다.

직무 필터는 멀티 선택을 지원합니다. "트레이너"와 "FC"를 함께 선택하면 두 직무에 해당하는 직원이 OR 조건으로 모두 표시됩니다. 직무 필터를 바꾸면 페이지는 1페이지로 리셋되지만, 검색어와 재직 상태 필터는 그대로 유지됩니다. 직무는 인사·운영 분류값이며, 실제 관리자웹 메뉴 접근 권한은 SCR-081 권한 설정에서 별도로 매핑되므로 직무를 바꾸면 SCR-081의 권한 매핑이 자동 재평가됩니다.

본사 통합 모드 토글은 본사 권한자(슈퍼관리자·본사 최고관리자)에게만 표시되는 또 하나의 분기 축입니다. 통합 모드를 켜면 소속 지점 필터가 노출되고 테이블에 소속 지점 컬럼이 자동으로 추가되며, 요약 카드의 카운트가 전 지점 합산으로 바뀝니다. 통합 모드를 끄면 본인의 기본 지점만 보이는 일반 모드로 돌아갑니다. 통합 모드 상태와 소속 지점 필터값도 URL 쿼리 파라미터로 보존되어, 페이지 새로고침이나 북마크 진입 시 같은 상태가 복원됩니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

이 화면에 등장하는 모든 클릭 가능한 요소를 빠짐없이 정의합니다.

요약 지표 카드 4개는 각각 클릭 가능합니다. 전체 직원 수 카드를 누르면 재직 상태 필터가 전체로, 재직 중 인원 카드는 재직으로, 휴직 중 인원 카드는 휴직으로, 퇴사 인원 카드는 퇴사로 자동 변경됩니다. 어느 카드를 누르든 페이지는 1페이지로 리셋되고 체크박스 선택은 해제됩니다. 본사 통합 모드에서는 카드의 카운트가 전 지점 합산이 적용된 결과로 필터링됩니다.

검색창은 디바운스 300ms를 거쳐 자동 재조회되며, X 버튼으로 검색어를 즉시 초기화할 수 있습니다. 직무 필터·소속 지점 필터·재직 상태 필터는 변경 즉시 재조회되고, 적용된 필터 칩 옆의 X 버튼으로 개별 해제, 우측 "전체 해제" 링크로 일괄 해제됩니다.

상단 액션 바의 메시지 전송 버튼은 선택된 직원이 한 명 이상이고 권한이 매니저+ 일 때 활성화되며, 누르면 선택된 직원의 ID 배열을 쿼리 파라미터로 전달하면서 메시지 발송 화면(SCR-071)으로 이동합니다. 본사 통합 모드에서는 지점별 메시지 발송 권한이 자동 검증되어, 권한 없는 지점 직원은 발송 대상에서 자동 제외되고 안내 토스트가 표시됩니다. 상태 변경 버튼은 매니저+ 일 때 활성화되며, 누르면 재직 ↔ 휴직 일괄 전환을 위한 미니 폼이 열립니다. 일괄 상태 변경은 재직 ↔ 휴직 사이에서만 가능하며, 퇴사로의 일괄 변경은 SCR-062 위자드를 거치는 단계별 처리만 허용되어 별도의 "퇴사 처리" 버튼으로 분리되어 있습니다.

상단 액션 바의 퇴사 처리 버튼은 매니저+ 권한자에게만 보이며, 한 명 이상 선택했을 때 활성화됩니다. 누르면 DLG-060-002 퇴사 확인 다이얼로그가 열리고, "퇴사처리" 텍스트 입력을 통과한 뒤 SCR-062 4단계 위자드로 이동합니다. 단, 일괄 선택에 이미 퇴사된 직원이 포함되어 있으면 자동 제외되며 안내 토스트가 표시됩니다.

상단 액션 바의 명단 다운로드 버튼은 권한이 있는 계정에서만 표시되며, 매니저+는 본인 지점에 한정해 다운로드할 수 있고 본사 통합 모드 다운로드는 슈퍼관리자·본사 최고관리자만 가능합니다. 클릭 시 현재 필터·검색·정렬을 그대로 적용한 결과 또는 전체 데이터(권한·모드에 따라)를 엑셀로 내려받으며, 파일명은 `yyyymmdd_지점명_직원목록.xlsx` 규칙을 따르고 통합 모드는 `yyyymmdd_전체_직원목록.xlsx`이 됩니다. 다운로드 대상이 1,000명을 초과하면 즉시 "다운로드 준비 중" 토스트가 뜨고 백그라운드 잡으로 전환되며, 완료 시 알림 센터(SCR-104)로 다운로드 링크가 푸시됩니다.

직원 목록 테이블의 직원명 클릭은 우측 상세 패널을 슬라이드 인 시킵니다(모바일은 풀스크린 전환). 더보기 메뉴 안의 수정 항목은 SCR-061 수정 모드로, 메시지 항목은 SCR-071 단일 발송 모드로, 퇴사 처리 항목은 DLG-060-002를 거쳐 SCR-062로 이동합니다. 더보기 메뉴 항목은 권한에 따라 자동으로 노출/숨김 처리됩니다.

페이지 헤더의 직원 등록 버튼은 SCR-061 빈 폼으로 이동하며, FC·트레이너·스태프·프런트에게는 표시되지 않습니다. 본사 통합 모드 토글은 본사 권한자에게만 보이고, 누르면 통합 모드와 일반 모드를 전환합니다.

직원 상세 패널 내부의 액션도 모두 클릭 가능합니다. 담당 회원 카드 클릭은 SCR-M004 회원 상세로 이동(브라우저 뒤로가기로 이 화면 복귀), 캘린더 진입 CTA는 SCR-C001 수업 캘린더로 직원 필터 자동 적용 진입, NPS 카드 클릭은 SCR-C013 수업 후기로 이동, 인사 메모 작성/수정/삭제는 매니저·Owner(지점장)만 가능하며 작성자 또는 Owner(지점장)만 수정·삭제할 수 있습니다. 계정/보안 카드의 잠금/잠금 해제/임시 비밀번호 재발급/권한 설정으로 이동 액션은 owner+ 또는 정책상 허용된 보안관리자만 사용 가능하며, 모든 보안 액션은 감사 로그에 기록됩니다. 헤더 액션의 수정·퇴사 처리·메시지 보내기는 각각 SCR-061, SCR-062, SCR-071로 이동합니다. 본인 조회 모드에서는 헤더 액션이 모두 hidden되고 인사 메모 섹션 자체가 숨겨집니다.

모든 버튼은 클릭 후 응답이 돌아오기 전까지 자동으로 비활성화되어 더블클릭 중복 요청이 차단됩니다. 일괄 작업 진행 중에는 진행 스피너가 표시되고 다른 일괄 액션 버튼이 모두 비활성화됩니다. 권한이 부족해 버튼이 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 1차 진입점(사이드바·직원 등록 버튼·명단 다운로드 버튼)에서는 메뉴 자체가 숨겨지고, 화면 내부의 버튼은 권한이 부족하면 hidden 또는 비활성화되며, 직접 URL 접근으로 모달까지 도달한 경우에는 백엔드 응답이 403이 되어 "권한이 없어요" 토스트가 표시되고 감사 로그에 권한 차단 이벤트가 기록됩니다.

## 7. 호출되는 모달 동작

이 화면에서 호출되는 모달은 두 가지입니다. 각각 어떤 트리거로 열리고, 어떤 입력을 받고, 확인/취소를 누르면 부모 화면에서 어떤 변화가 일어나는지를 모두 풀어 씁니다.

### 7-1. DLG-060-001 등록/수정 취소 확인 다이얼로그

DLG-060-001은 직원 목록 화면 안에서 인라인으로 펼쳐지는 등록·수정 폼(SCR-061의 가벼운 인라인 변형 또는 더보기 메뉴의 빠른 수정 시나리오)에서 "취소" 버튼을 눌렀을 때 호출되는 이탈 확인 모달입니다. 본격적인 SCR-061 전용 폼에서 발생하는 이탈 확인은 DLG-061-001이 담당하며, 둘은 동일 패턴이지만 호출 위치와 부모 화면이 다릅니다. 모달 상단에는 "작성 중인 내용이 있습니다"라는 제목이 표시되고, 그 아래에 "취소하면 입력한 내용이 저장되지 않습니다. 정말 취소하시겠습니까?"라는 안내가 따라옵니다. 하단에는 [계속 작성] 버튼과 [취소 확인] 버튼이 있습니다. 계속 작성을 누르면 모달이 닫히고 폼이 그대로 유지되며, 취소 확인을 누르면 폼이 닫히고 직원 목록 화면으로 복귀합니다. 폼에 아무 입력이 없는 깨끗한 상태에서 취소를 누르면 이 다이얼로그가 표시되지 않고 즉시 닫힙니다. ESC 키 또는 배경 클릭도 [계속 작성]과 동일하게 동작하지만, dirty 상태에서는 한 번 더 확인합니다.

### 7-2. DLG-060-002 직원 삭제(퇴사) 확인 다이얼로그

DLG-060-002는 직원 목록의 퇴사 처리 버튼 또는 더보기 메뉴의 퇴사 처리 항목을 클릭했을 때 SCR-062 위자드 진입 전 안전 장치로 동작합니다. 모달 상단에는 "직원 퇴사 처리"라는 제목이 표시되고, 그 아래에 "선택한 {인원수}명의 직원을 퇴사 처리하시겠습니까? 퇴사 처리 시 해당 직원의 계정 접근이 제한됩니다"라는 안내가 표시됩니다. 모달 가운데에는 "퇴사처리" 텍스트를 직접 타이핑해야만 활성화되는 확인 입력 필드가 있고, 텍스트가 정확히 일치할 때만 빨강 계열의 [퇴사 처리] 버튼이 활성화됩니다. 일치하지 않으면 버튼이 비활성화 상태를 유지합니다. [취소] 버튼은 언제나 활성화되어 있고, 누르면 모달이 닫히고 아무 처리도 일어나지 않습니다.

퇴사 처리 버튼을 누르면 모달은 SCR-062 4단계 위자드로의 진입을 위한 컨텍스트(선택된 직원 ID 배열)를 들고 이동합니다. SCR-062에서 위자드를 모두 통과하고 다시 같은 다이얼로그가 4단계 마지막에 한 번 더 호출되며, 그때 비로소 직원 상태가 "퇴사"로 전환되고 계정이 비활성화됩니다. 다이얼로그는 매니저+ 권한자에게만 호출 가능하며, FC·트레이너·스태프·프런트에게는 부모 화면의 퇴사 처리 버튼 자체가 숨겨지므로 이 모달에 진입할 수 없습니다. 일괄 선택에 이미 퇴사된 직원이 포함되어 있으면 부모 화면에서 자동 제외 처리가 선행되며, 모달 안에서는 "총 N명 선택"이라는 카운트가 처리 가능 인원만 반영합니다.

## 8. 토스트와 확인 팝업과 알럿

직원 목록 페이지에서 발생하는 모든 알림성 UI는 일관된 패턴으로 동작합니다.

성공 토스트는 우측 상단에 녹색 계열로 5초 동안 표시되며, "n명의 상태를 변경했어요", "n명에게 메시지를 발송했어요", "n명의 퇴사 처리를 시작합니다", "명단 다운로드가 시작되었어요" 같은 짧은 문구로 결과를 알려줍니다. 백그라운드 다운로드는 시작 토스트만 표시되고 완료는 알림 센터로 푸시되어, 운영자가 다른 업무로 넘어가도 결과를 놓치지 않습니다.

실패 토스트는 우측 상단에 빨강 계열로 표시되며, "데이터를 불러오지 못했어요", "권한이 없어요", "다른 사용자가 처리 중입니다", "데이터가 너무 많아요. 필터를 좁혀주세요" 같은 문구와 함께 "다시 시도" 같은 보조 액션 버튼이 따라옵니다. 네트워크 오류는 1회까지 자동 재시도된 후 사용자 액션을 기다립니다.

부분 결과 알림은 일괄 작업이 완료되었을 때 토스트가 아니라 결과 카드 형태로 화면 중앙 하단에 머무릅니다. "성공 8건 / 실패 2건"처럼 두 가지 숫자가 동시에 표시되며, 본사 통합 모드 일괄 작업에서는 지점별 성공/실패가 분리 표시되고 실패 리포트 CSV 다운로드 링크가 함께 제공됩니다.

확인 팝업은 별도 다이얼로그가 아닌 단순한 yes/no 형태입니다. 필터·검색 변경 시에는 별도 확인 없이 즉시 재조회되고, "전체 해제" 링크도 즉시 초기화됩니다. 다만 일괄 작업 처리 중에 다른 페이지로 이동하려고 하면 "처리 중인 작업이 있습니다. 이동하면 결과를 확인할 수 없습니다"라는 yes/no 확인이 뜹니다.

알럿은 시스템 메시지에 가까운 차단형 안내로, 권한 없는 계정이 직접 URL로 접근했을 때 페이지 본문이 전부 사라지고 "이 화면에 접근할 권한이 없습니다. 본인 정보만 표시됩니다"라는 메시지와 함께 본인 카드 1건만 표시됩니다(직원 본인 모드). readonly나 비로그인 상태는 대시보드로 자동 이동됩니다.

## 9. 데이터 흐름과 외부 연동

이 화면은 여러 데이터 소스와 외부 연동에 의존합니다.

화면 진입 시점에는 직원 목록 조회 API(`GET /api/staff`)가 호출됩니다. 요청에는 현재 활성화된 직무 필터·소속 지점 필터·재직 상태 필터·검색어·페이지 번호·페이지당 건수·정렬 기준이 모두 쿼리 파라미터로 들어갑니다. 본사 통합 모드일 때는 `branchId` 파라미터가 빠지거나 `all`로 전달되어 전체 지점의 직원이 합산 조회됩니다. 응답으로는 직원 배열, 총 건수, 페이지 정보, 그리고 4개 요약 카드의 카운트가 함께 내려옵니다. 카드 카운트는 같은 필터 조건을 기준으로 계산되되 페이지네이션은 적용하지 않은 전체 합계입니다.

직원의 직무·재직 상태는 변경 즉시 반영되지만, 요약 카드 카운트는 매일 새벽 4시 KPI 배치와 5분 TTL 캐시로 갱신됩니다. 따라서 직원의 직무를 바꾼 직후 카드 카운트가 한 박자 늦게 갱신될 수 있으며, 운영자에게는 카드 옆 작은 글씨로 "04:12 갱신" 같은 캐시 시각이 표시됩니다.

상세 패널은 5개 카드 각각에 대해 독립 API를 호출합니다. 담당 회원 목록 `GET /api/staff/:id/members`, 담당 스케줄 `GET /api/staff/:id/schedule`, 실적 요약 `GET /api/staff/:id/performance`, 근태 요약 `GET /api/staff/:id/attendance`, 인사 메모 `GET /api/staff/:id/memos`, 계정/보안 `GET /api/staff/:id/account`. 카드별 스켈레톤 로딩으로 부분 데이터부터 표시되며, 한 카드가 실패해도 다른 카드는 정상 표시됩니다. 실패한 카드만 별도 [재시도] 버튼이 노출됩니다. 패널 전체는 30초 캐시되며, 헤더의 [새로고침] 버튼으로 강제 갱신할 수 있습니다.

실적 요약의 매출 집계 기준은 `매출관리.md`의 담당자별 집계 정의를 따릅니다. 트레이너 매출은 트레이너 본인 귀속이며, FC 매출은 FC 본인 귀속입니다. 환불 책임 지표는 처리자가 아닌 원판매 담당자 기준으로 계산됩니다. NPS는 수업 후기(SCR-C013)에서 자동 집계된 값을 가져오며, 후기 0건이면 N/A(회색)로 표시되고 4.0 미만이면 매니저 대시보드에 코칭 알림이 발송됩니다(테넌트 정책).

근태 요약은 SCR-063 근태 관리의 데이터를 이번 달 합산해 표시하며, 5분 TTL 캐시를 사용합니다. 출근율은 (정상 출근 + 지각) ÷ 총 영업일로 계산하고, 신규 입사자는 입사일 기준 영업일만 집계해 입사일 이전 일자가 분모에 들어가지 않도록 합니다.

급여는 PAY-STF-02(SCR-064)와 연동되어, 직원 등록·퇴사 이벤트가 발생하면 다음 월 급여 계산 대상 풀이 자동 갱신됩니다. 캘린더 색상은 직원 등록 시 시스템이 지점 내 사용 빈도가 낮은 색상을 자동 배정해 SCR-C001에 즉시 반영됩니다.

계정/보안 카드는 `users` 테이블과 Supabase Auth 사용자(email = `${username}@spogym.local`)를 동기화하는 `POST /api/staff/account` 엔드포인트와 연결됩니다. `action: "upsert" | "deactivate"`로 호출되며, 서버 환경변수 `SUPABASE_SERVICE_ROLE_KEY` 미설정 시 users 테이블 동기화는 진행되지만 Auth 동기화는 건너뛰고 UI에 경고 토스트가 노출됩니다. 퇴사 처리 완료 시 계정은 즉시 deactivate되어 로그인이 차단되고 활성 세션이 강제 만료됩니다.

본사 통합 모드의 일괄 작업은 직원의 실제 `branchId` 기준으로 분기 처리되어, 트랜잭션이 지점별로 묶입니다. 따라서 한 지점의 트랜잭션이 실패해도 다른 지점은 정상 처리되며, 결과 카드에 지점별 성공/실패가 분리되어 표시됩니다.

모든 일괄 작업(상태 변경·메시지 발송·퇴사 처리·복구·명단 다운로드)은 감사 로그 시스템(SCR-097)에 비동기 INSERT됩니다. 기록 필드는 `actor_id`, `staff_ids[]`, `action_type`, `branch_id`, `before`, `after`, `reason`, `timestamp`이며, 감사 로그 INSERT는 작업 응답이 사용자에게 돌아간 후 5초 안에 보장됩니다.

휴직 자동 복귀 알림은 NFR-19 알림 센터로 휴직 종료일 D-3 시점에 매니저에게 발송되고, 퇴사 D-30 사전 알림은 매니저+에게 인수인계 준비를 유도하기 위해 발송됩니다. OT1 14일 미완료 알림과 NPS 4.0 미만 알림, 메모 30일 미열람 알림(매주 월요일)은 매니저 대시보드와 알림 센터에 동시에 표시됩니다.

세션 상태(필터·페이지·검색어)는 페이지 이탈 시 세션 스토리지에 5분 TTL로 저장되어, 같은 운영 흐름을 복귀 후에도 이어서 진행할 수 있습니다.

화면에서 호출하는 주요 API는 다음과 같습니다. 직원 목록 조회 `GET /api/staff`, 일괄 작업 처리 `POST /api/staff/bulk-action`, 일괄 상태 변경 `POST /api/staff/bulk-status`, 명단 엑셀 내보내기 `GET /api/staff/export`, 요약 카드 `GET /api/staff/summary`, 상세 패널 API 묶음 `GET /api/staff/:id/*`, 인사 메모 CRUD `POST/PATCH/DELETE /api/staff/:id/memo`, 계정 동기화 `POST /api/staff/account`.

## 10. 화면 상태와 예외 처리

직원 목록 페이지는 다음 상태들을 가질 수 있고, 각 상태마다 사용자에게 보이는 모습이 달라집니다.

로딩 중 상태에서는 테이블 자리에 행 모양의 스켈레톤이 표시되고, 요약 카드 자리에도 숫자 대신 스켈레톤이 표시됩니다. 헤더의 토글·필터 바는 미리 렌더되지만 상호작용은 잠시 막혀 있습니다.

정상 목록 상태는 200 응답과 함께 직원이 한 명 이상 존재할 때 표시되는 가장 일반적인 상태입니다. 테이블에 직원 행이 채워지고 페이지네이션이 활성화되며, 모든 버튼이 권한에 맞게 활성/비활성으로 동작합니다.

검색 결과 없음 상태는 필터나 검색을 적용한 결과가 0건일 때 표시됩니다. 테이블 자리에 "직원 데이터가 없습니다" 안내와 함께 검색 조건 조정 가이드 문구가 표시되고, 적용된 필터 칩은 그대로 노출되어 사용자가 X 버튼으로 좁힘을 풀 수 있습니다.

전체 직원 없음 상태는 어떤 필터도 적용되지 않은 상태에서 직원 자체가 0건인 경우입니다. 신규 개업 지점에서 흔히 보이며, 빈 상태 일러스트와 함께 "[직원 등록] 버튼으로 첫 직원을 등록해 보세요"라는 CTA가 강조 표시됩니다.

오류 상태는 서버에서 5xx 응답이 오거나 네트워크 타임아웃이 발생했을 때 표시됩니다. 화면 중앙에 에러 아이콘과 "데이터를 불러오지 못했어요" 메시지, 그리고 [다시 시도] 버튼이 표시됩니다. 자동 재시도가 1회 백그라운드에서 일어나고, 그래도 실패하면 사용자의 액션을 기다립니다.

본사 통합 모드 상태에서는 본사 권한자에게만 통합 토글이 켜진 상태로 표시되며, 소속 지점 컬럼이 자동으로 노출되고 요약 카드의 카운트가 전 지점 합산이 됩니다. 통합 모드 권한이 없는 사용자에게는 토글 자체가 hidden입니다.

권한 부족 상태(FC·트레이너·스태프·프런트)에서는 동료 목록이 노출되지 않고 본인 카드 1건만 표시됩니다. "관리자 권한이 필요합니다"라는 안내가 함께 표시되며, 회원 등록 버튼·명단 다운로드 버튼·메모 컬럼·일괄 작업 버튼은 모두 hidden입니다.

일괄 작업 활성 상태는 직원을 1명 이상 선택한 상태입니다. 선택 카운트 배지가 강조되고 일괄 액션 버튼이 활성화되며, 본사 통합 모드에서는 선택된 직원이 어느 지점들에 분포하는지가 작은 부제로 표시됩니다.

다운로드 준비 중 상태는 명단 다운로드를 트리거한 직후입니다. 대상 인원이 1,000명을 넘으면 백그라운드 잡으로 전환되고 "다운로드 준비 중" 토스트가 표시되며, 완료 시 알림 센터로 다운로드 링크가 푸시됩니다.

상세 패널 열림 상태는 직원명을 클릭해 우측 패널이 슬라이드 인 된 상태입니다. 본문 가로폭이 약 65%로 축소되며, 패널 내부 5개 카드가 카드별 스켈레톤으로 부분 로딩됩니다. 카드 하나가 실패해도 다른 카드는 정상 표시되고, 실패 카드만 [재시도] 버튼이 노출됩니다. 모바일에서는 풀스크린으로 전환됩니다.

휴직 직원 상세 상태에서는 패널 헤더에 "휴직 중" 배지가 표시되고 실적·근태 카드가 회색 처리됩니다. 휴직 기간의 데이터는 0 또는 hidden 처리되며, 헤더 액션의 수정·퇴사 처리는 정상 동작합니다.

퇴사 직원 상세 상태에서는 헤더에 "퇴사" 배지가 표시되고 모든 카드가 read-only가 됩니다. 헤더 액션의 수정·퇴사 처리 버튼은 hidden이며, 24시간 이내·인계 미진행 상태일 때만 [퇴사 취소] 버튼이 Owner(지점장)에게 노출됩니다.

예외 케이스별 처리는 다음과 같이 정의됩니다.

네트워크 오류(5xx 또는 timeout)가 발생하면 "데이터를 불러오지 못했어요" 토스트와 다시 시도 버튼이 표시됩니다. 자동 재시도 1회 후 사용자 액션을 기다립니다.

권한 없는 계정(FC·트레이너·스태프·프런트)이 직접 URL로 접근하면 본인 카드 1건만 표시되고 동료 데이터에는 RLS로 차단됩니다. readonly는 사이드바에서도 메뉴가 숨겨지고 직접 URL 접근 시 대시보드로 자동 이동됩니다.

일괄 작업의 부분 실패가 발생하면 성공 N건 / 실패 M건 결과 카드와 실패 리포트 CSV 다운로드 링크가 제공됩니다. 본사 통합 모드에서는 지점별로 결과가 분리 표시됩니다.

동일 직원에 대한 동시 편집(optimistic lock 위반)이 발생하면 "다른 사용자가 처리 중입니다" 모달이 표시되고, 사용자는 최신 데이터를 새로고침한 뒤 다시 시도해야 합니다.

명단 다운로드 권한이 없는 계정(FC·스태프·프런트)에서는 다운로드 버튼이 아예 화면에 표시되지 않습니다.

명단 다운로드 데이터가 1,000명을 초과하면 백그라운드 잡으로 전환되어 알림 센터로 결과가 전달됩니다.

본사 통합 모드 메시지 발송 시 권한 없는 지점 직원은 발송 대상에서 자동 제외되고 안내 토스트가 표시됩니다.

이미 퇴사된 직원을 일괄 선택에 포함시키면 자동 제외되고 체크박스 자체가 disabled로 표시됩니다.

휴직 → 재직 일괄 전환 시 일부 직원의 캘린더에 충돌이 있으면 충돌 직원은 제외되고 부분 성공 토스트가 표시됩니다.

상세 패널의 카드별 부분 로드 실패는 카드 단위로 [재시도] 버튼이 노출되어 부분 데이터를 유지한 채 실패 카드만 재요청할 수 있게 합니다.

모바일 768px 미만에서 테이블은 카드형 리스트로 자동 전환되고, 상세 패널은 풀스크린 슬라이드로 진입합니다.

페이지네이션 마지막 페이지를 넘는 페이지 번호 입력은 1페이지로 자동 이동됩니다.

세션 만료가 발생하면 자동 임시 저장 후 로그인 페이지로 리디렉션되며, 복귀 시 세션 스토리지 상태가 5분 TTL 안에 있으면 자동 복원됩니다.

## 11. 권한별 처리

이 화면은 권한에 따라 진입 가능 여부, 보이는 영역, 가능한 액션이 모두 달라집니다.

본사 슈퍼관리자(superAdmin)와 본사 최고관리자(primary)는 모든 기능을 사용할 수 있습니다. 본사 통합 모드 토글이 노출되어 전 지점 직원을 합산 조회할 수 있고, 소속 지점 컬럼이 자동으로 표시됩니다. 직원 등록·상태 변경·퇴사 처리·메시지 전송·명단 다운로드(통합 다운로드 포함)·인사 메모 작성·계정 잠금·임시 비밀번호 재발급·권한 설정 이동까지 모두 가능합니다.

Owner(지점장)은 자기 지점의 직원 전체를 조회할 수 있습니다. 본사 통합 모드 토글은 표시되지 않거나 비활성화되며, 자기 지점에 한정해 직원 등록·상태 변경·퇴사 처리·메시지 전송·명단 다운로드를 수행할 수 있습니다. 추가로 퇴사 취소(24시간 이내·인계 미진행 한정)·정산 미완료 강제 확정·과거일 즉시 퇴사 강행·급여 확정은 Owner(지점장)에게만 허용됩니다. 인사 메모도 작성·조회 가능하며, 계정 보안 액션(잠금·해제·임시 비밀번호 재발급)도 정책에 따라 사용할 수 있습니다.

매니저(manager)는 자기 지점의 직원 전체를 조회할 수 있고, 직원 등록·상태 변경·메시지 전송·명단 다운로드(본인 지점)를 수행할 수 있습니다. 퇴사 처리도 생성·진행할 수 있지만, 퇴사 취소·정산 미완료 강제 확정·과거일 즉시 퇴사 강행은 차단됩니다. 인사 메모는 작성·조회 가능하지만 계정 보안 액션은 owner+ 정책에 따라 제한될 수 있습니다.

FC(fc)·트레이너(trainer)·스태프(staff)·프런트(front)는 동료 직원의 목록을 볼 수 없고 본인 정보만 조회 가능합니다. 화면 진입 시 본인 카드 1건만 표시되며, "관리자 권한이 필요합니다" 안내가 함께 표시됩니다. 직원 등록·일괄 작업·명단 다운로드·메모 컬럼·상세 패널의 인사 메모 섹션·헤더 액션은 모두 hidden 또는 비활성화됩니다. 본인 상세에서는 본인의 실적·근태만 표시되고, 인사 메모는 섹션 자체가 hidden 처리되어 메모 존재 자체가 비공개됩니다.

직원 본인 모드(자기 자신의 상세 패널 진입)에서는 본인 프로필·실적·근태·급여 명세서만 표시되며, 직접 수정은 불가능합니다. 잠금 해제·임시 비밀번호 재발급도 본인이 직접 실행할 수 없고 관리자에게 요청해야 합니다.

읽기 전용(readonly)은 이 화면 자체에 접근할 수 없습니다. 사이드바에 직원 관리 메뉴가 보이지 않고, 직접 URL로 접근하면 접근 제한 화면이 표시되며 대시보드로 자동 이동됩니다.

권한 외에도 운영 모드에 따라 일부 영역이 추가로 보이거나 숨겨집니다. 본사 통합 모드는 본사 권한자에 한해 활성화되며, 통합 모드에서만 소속 지점 컬럼·소속 지점 필터·전 지점 합산 카드가 노출됩니다. 락커·운동복 미사용 지점에서는 해당 컬럼이 자동 hidden되고, 상담 기능 미사용 지점에서는 관련 카드가 hidden됩니다.

권한이 부족해서 액션이 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 1차 진입점(사이드바·헤더 등록 버튼·명단 다운로드)에서는 메뉴 자체가 숨겨지고, 화면 내부의 버튼은 hidden 또는 비활성화로 처리되며, 직접 URL 접근으로 모달까지 도달한 경우에는 백엔드 응답이 403이 되어 토스트 안내와 함께 변경이 차단됩니다. 모든 권한 차단 이벤트는 감사 로그에 기록됩니다.

## 14. 핵심 디자인 요청사항

이 화면이 운영자에게 잘 작동하려면 다음 디자인 원칙이 시각적으로 명확히 드러나야 합니다.

직무 배지는 7종이 색상으로 즉시 구분되어야 합니다. Owner(지점장)은 짙은 청색, 매니저는 청록, FC는 보라, 트레이너는 녹색, 스태프는 회색, 프런트는 옅은 회색, 골프프로는 골드 톤 같은 식으로 멀리서 봐도 직무가 짐작되도록 합니다. 색맹 운영자를 고려해 텍스트 라벨이 색상과 함께 항상 표시됩니다.

재직 상태 배지는 재직(success/녹색), 휴직(warning/주황), 퇴사(neutral/회색)로 강하게 분리되며, 휴직 직원의 행은 본문 배경이 살짝 옅게 톤다운되어 한눈에 비활성 상태임이 드러납니다. 퇴사 직원의 행은 체크박스 disabled와 함께 본문 텍스트도 회색으로 처리됩니다.

요약 카드 4개는 한눈에 비교가 가능하도록 동일 크기·동일 그리드로 배치되며, 카드 안의 숫자는 가장 큰 폰트로, 라벨은 그 아래 작은 글씨로 배치합니다. 본사 통합 모드에서는 "전 지점 합산"이라는 부제가 카드 하단에 작은 글씨로 붙어, 운영자가 현재 합산 범위를 즉시 인지할 수 있어야 합니다.

상세 패널은 우측에서 부드럽게 슬라이드 인 되며, 본문 가로폭이 동시에 축소되는 애니메이션이 함께 일어납니다. 패널 내부 5개 카드는 카드별로 독립된 스켈레톤 로딩 톤을 사용하고, 카드 하나가 실패하면 그 카드만 옅은 빨강 톤의 [재시도] 버튼이 노출되어 부분 실패가 직관적으로 드러납니다.

테이블 가독성이 가장 중요하므로, 행 간격은 충분히 넓게, 폰트 크기는 일반 텍스트보다 약간 크게, 컬럼 정렬은 직원명·연락처는 좌측 정렬, 입사일은 우측 정렬, 직무·재직 상태 배지는 중앙 정렬로 통일합니다. 메모 컬럼은 30자에 말줄임을 적용하되, hover 시 툴팁으로 전체 메모(또는 최신 1건)를 표시합니다.

모바일에서는 테이블이 카드형 리스트로 자동 전환되어, 한 행에 직원 사진·이름·직무·재직 상태가 위에, 연락처·입사일·소속 지점이 아래에 표시되는 2단 카드 구조를 사용합니다. 상세 패널은 풀스크린 슬라이드 전환됩니다.

진행 스피너와 로딩 스켈레톤은 동일한 톤으로 통일하며, 일괄 작업 진행 중에는 테이블 상단에 진행 바가 함께 표시되어 어느 정도 진행되었는지 시각적으로 표현됩니다.

본사 통합 모드의 지점 컬럼은 좌측 끝에 가까운 위치에 두어, 운영자가 직원명과 지점을 동시에 빠르게 인지할 수 있게 합니다. 지점별 합산 카운트가 토스트나 결과 카드에 노출될 때는 지점명 라벨이 색상 배지로 표시되어 어느 지점의 결과인지 즉시 알아볼 수 있어야 합니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

이 화면은 단순한 UI가 아니라 직원 운영의 정책 결정이 그대로 반영된 도구입니다. 다른 문서를 보지 않아도 이 화면을 구현·운영하는 사람이 알아야 할 정책을 모두 풀어 씁니다.

직원 분류는 직무(인사·운영 분류값)와 재직 상태(시스템 상태값) 두 축으로 명확히 분리됩니다. 직무는 Owner(지점장)·매니저·FC·트레이너·스태프·프런트·골프프로 7종이며, 멀티 선택과 변경이 가능하고 변경 시 SCR-081 권한 매핑이 자동 재평가됩니다. 단, 직무 자체가 관리자웹 메뉴 접근 권한을 결정하지는 않으며, 메뉴 권한은 SCR-081에서 별도로 매핑됩니다. 재직 상태는 재직(active)·휴직(onLeave)·퇴사(resigned) 3종이며, 단일 선택입니다. 휴직 → 재직 전환은 매니저+, 재직 → 휴직 전환도 매니저+, 휴직 → 퇴사 직행은 휴직 시 사전 정리된 인계가 있다는 전제 하에 매니저+가 가능합니다. 퇴사로의 일괄 변경은 SCR-062 4단계 위자드를 거치는 단계별 처리만 허용되며 일괄 단축은 차단됩니다.

본사 통합 모드는 본사 권한자(슈퍼관리자·본사 최고관리자)에게만 활성화됩니다. 이는 데이터 노출 범위 제어와 보안 정책의 결과이며, 일반 지점 사용자는 자기 지점 외 데이터에 접근할 수 없습니다. 통합 모드의 일괄 작업은 직원의 실제 `branchId`를 기준으로 분산 저장되어, 메시지·근태·급여 같은 후속 처리가 잘못된 지점에 묶이지 않도록 보장합니다. 본사 통합 모드의 메시지 발송은 지점별 발송자 권한이 자동 검증되어, 권한 없는 지점 직원은 발송 대상에서 자동 제외됩니다.

퇴사 처리는 운영 실수의 위험이 매우 크므로 권한이 단계적으로 제한됩니다. 일반적인 퇴사 처리 생성·진행은 매니저+가 가능하지만, 퇴사 취소(24시간 이내·인계 미진행 한정)·정산 미완료 강제 확정·과거일 즉시 퇴사 강행은 Owner(지점장)+에게만 허용됩니다. 퇴사 처리는 직원 상태 변경과 로그인 계정 비활성화를 동시에 수행하며, 활성 세션도 즉시 만료됩니다. "퇴사처리" 텍스트를 정확히 입력해야 최종 버튼이 활성화되는 이중 확인 절차(DLG-060-002)로 실수를 방지합니다.

직원 1명 = 로그인 계정 1개 원칙이 유지됩니다. 직원 저장 시 users row와 Supabase Auth 사용자가 동시에 생성·동기화되며, 퇴사 시 즉시 deactivate되어 로그인이 차단됩니다. `SUPABASE_SERVICE_ROLE_KEY` 환경변수 미설정 시 Auth 동기화는 건너뛰되 users 동기화는 진행되며, UI에 경고 토스트가 표시됩니다. 계정 잠금·해제·임시 비밀번호 재발급은 owner+ 또는 정책상 허용된 보안관리자에게만 허용됩니다.

인사 메모는 매니저·Owner(지점장)만 작성·조회 가능하며, 직원 본인에게는 섹션 자체가 hidden되어 메모 존재 자체가 비공개로 유지됩니다. 카테고리는 근태·면담·민원·기타 4종 단일 선택이며, 작성자(actor_id)와 작성·수정 일시가 자동 기록되고, 수정·삭제는 작성자 본인 또는 Owner(지점장)만 가능합니다. 삭제는 soft-delete 방식이며 감사 로그에 기록됩니다. 30일 이상 미열람 메모는 매니저 대시보드에 알림으로 노출됩니다.

명단 엑셀 다운로드는 본사 통합 모드에서는 본사 권한자만, 일반 지점 모드에서는 매니저+만 사용할 수 있습니다. FC·트레이너·스태프·프런트는 다운로드 자체가 차단됩니다. 1,000명 초과 시 백그라운드 잡으로 전환되어 알림 센터로 결과가 전달되며, 파일명은 `yyyymmdd_지점_직원목록.xlsx`(통합은 `yyyymmdd_전체_직원목록.xlsx`) 규칙을 따릅니다. 노무사·세무사 제출용 자료로 활용되며, 본사 통합 다운로드에는 소속 지점 컬럼이 자동으로 추가됩니다.

근태·급여 자동 연동은 직원 등록·퇴사·휴직 이벤트가 발생하면 즉시 반영됩니다. PAY-STF-02 급여 관리는 직원 등록·퇴사 시 다음 월 급여 계산 대상 풀이 자동 갱신되며, 시급제·건별 직원은 PAY-STF-01 근태 데이터를 입력으로 받아 자동 계산됩니다. 휴직 직원은 휴직 기간 급여가 미산정되며, 퇴사 직원은 퇴사 확정일까지 일할 계산됩니다.

전자 근로계약서 연계는 STF-EXT-01 저장 시 옵션 ON 시 이메일·카카오로 자동 발송되어 서명 완료 시 인사 파일에 자동 저장됩니다. 이는 테넌트 정책에 따라 선택적으로 활성화됩니다. 임금 정산·4대 보험 상실 신고는 외부 노무사 시스템에서 별도 처리되며, 시스템 안에서는 안내 박스만 표시됩니다.

감사 로그는 이 화면에서 발생하는 모든 일괄 작업·복구·이관·삭제·메모 CRUD·계정 보안 액션을 비동기로 기록하며, 5초 안에 SCR-097 감사 로그 화면에서 조회 가능해야 합니다. 기록 필드는 `actor_id`·`staff_ids[]`·`action_type`·`branch_id`·`before`·`after`·`reason`·`timestamp`입니다. 모든 권한 차단 이벤트도 함께 기록되어 사후 권한 우회 시도를 추적할 수 있게 합니다.

세션 상태(필터·페이지·검색어)는 페이지 이탈 시 세션 스토리지에 5분 TTL로 저장됩니다. 같은 운영 흐름을 복귀 후에도 이어서 진행할 수 있도록 하기 위한 정책이며, 5분 초과 시에는 기본 상태로 복원됩니다.

검색 디바운스 300ms와 이름·연락처 OR 매칭 정책은 직원 목록 외 다른 검색 영역에도 공통 적용됩니다. 디바운스 도중 추가 입력이 들어오면 이전 요청은 cancel 처리됩니다.

본사·지점 권한 분리 정책에 따라 본사 소유(전사 권한 템플릿·공통 정책·KPI 감사)와 지점 소유(직원 실제 운영·현장 결제·수업 운영)는 명확히 분리됩니다. 직원 등록·수정 자체는 지점 소유이지만, 권한 템플릿과 직무 매핑 정책은 본사 소유이므로 SCR-081 권한 설정과 짝지어 운영됩니다.

이상의 모든 정책은 이 화면을 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다. 정책이 바뀌면 이 문서가 함께 갱신되어야 하며, 코드 변경과 정책 변경은 항상 짝지어 진행됩니다.
