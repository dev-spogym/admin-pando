# SCR-091 구버전 슈퍼 대시보드 리다이렉트 페이지

## 2. 화면 개요와 목적

SCR-091은 구버전 슈퍼 대시보드 진입 경로(`/super-dashboard`)를 보존하기 위한 호환 화면입니다. 외부 도구·북마크·기존 알림 링크가 이 URL을 사용하고 있을 수 있으므로 페이지 자체를 제거하지 않고 리다이렉트 처리합니다.

전 지점 통합 대시보드의 정본 화면은 D01 `SCR-101 대시보드 통합`이며, 일반 지점 권한자의 대시보드는 D10 `SCR-090 지점 대시보드`입니다. 사용자가 `/super-dashboard`에 접근하면 세션 권한을 판정한 뒤 `/` route로 자동 이동시키고, `/`에서 권한별로 SCR-101 또는 SCR-090이 표시됩니다.

이 화면이 다루는 운영 흐름은 단 하나입니다. 사용자가 어떤 권한이든 `/super-dashboard`로 접근하면, 본 화면은 화면 영역 없이 즉시 권한 판정을 수행하고 `/` route로 이동시킵니다. 이 과정에서 화면 본체나 위젯, 데이터 카드를 렌더링하지 않습니다.

## 3. 진입 경로와 인접 화면

진입 경로는 단 하나입니다. 사용자가 `/super-dashboard` URL을 직접 입력하거나 구버전 북마크·외부 링크로 이 경로에 도달하는 경우입니다. 사이드바·헤더에는 더 이상 SCR-091로 가는 직접 메뉴가 없으며, 본사 권한자의 본사 통합 대시보드 진입은 `/` route의 SCR-101을 통해 이루어집니다.

빠져나가는 인접 화면은 권한과 세션 상태에 따라 결정됩니다. `superAdmin` / `primary` 세션은 `/` route의 SCR-101 대시보드 통합으로 이동되고, `Owner(지점장)` / `manager` / `fc` / `trainer` / `staff` / `readonly` 세션은 `/` route의 SCR-090 지점 대시보드로 이동됩니다. 로그인이 되어 있지 않으면 `/login`으로 이동되고, 세션이 무효하거나 권한 판정에서 명백히 차단되어야 하는 경우에는 D01 공통 접근 제한 안내가 표시됩니다.

## 4. 레이아웃과 UI 구성

본 화면은 독립적인 UI가 없습니다. 사용자에게는 권한 판정과 라우팅이 끝날 때까지 짧은 공통 로딩 인디케이터만 보이며, 판정이 끝나면 즉시 `/` route 또는 `/login`으로 이동합니다. 권한 부족·세션 무효 상태에서만 D01 공통 접근 제한 안내 화면이 잠시 표시될 수 있습니다.

## 5. 탭 구성과 탭별 동작

탭은 존재하지 않습니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

본 화면에는 사용자가 직접 누르는 버튼이나 링크가 없습니다. 진입 즉시 자동 리다이렉트만 발생합니다.

## 7. 호출되는 모달 동작

호출되는 모달이 없습니다.

## 8. 토스트와 확인 팝업과 알럿

리다이렉트 도중에는 별도의 토스트나 확인 팝업을 띄우지 않습니다. 세션 무효·권한 부족 시 D01 공통 접근 제한 안내 화면을 짧게 표시한 뒤 적절한 경로(`/login` 또는 대시보드)로 이동합니다.

## 9. 데이터 흐름과 외부 연동

이 화면은 데이터 카드나 KPI 위젯을 직접 조회하지 않습니다. 진입 시 클라이언트와 백엔드가 세션 토큰을 검증하고, 권한 클레임(`role`)을 읽어 라우팅 결정만 수행합니다. 전 지점 KPI·지점별 현황·히스토리 로그 같은 본문 데이터는 모두 SCR-101과 SCR-090이 각자 책임지고 조회합니다.

## 10. 화면 상태와 예외 처리

| 상태 | 설명 |
|---|---|
| 리다이렉트 중 | 권한 판정 후 `/` route로 이동하는 동안 공통 로딩 표시 |
| 세션 없음 | `/login`으로 이동 |
| 권한 없음 / 세션 무효 | 공통 접근 제한 안내 후 적절한 경로로 자동 이동 |

예외 케이스별 처리는 다음과 같습니다. 세션이 없으면 즉시 `/login`으로 이동하고, 토큰이 만료되었거나 무효하면 공통 접근 제한 안내 후 `/login`으로 이동합니다. 권한 클레임이 손상되어 판정할 수 없는 경우에도 접근 제한 안내가 표시된 뒤 `/login`으로 이동합니다. 백엔드와의 세션 확인이 일시적으로 실패하면 짧은 재시도 후 그래도 실패하면 공통 접근 제한 안내로 이동합니다.

## 11. 권한별 처리

| 권한 | 보이는 영역 | 처리 결과 |
|---|---|---|
| superAdmin / primary | 별도 화면 없음 — `/` route의 SCR-101 대시보드 통합 | SCR-101로 자동 이동 |
| Owner(지점장) / manager / fc / trainer / staff / readonly | 별도 화면 없음 — `/` route의 SCR-090 지점 대시보드 | SCR-090으로 자동 이동 |
| 세션 없음 | 로그인 필요 안내 | `/login`으로 이동 |

권한 모델은 D01 `SCR-100 로그인`과 D01 공통 권한 매트릭스를 따르며, SCR-091 자체에서는 어떤 권한도 별도로 부여하거나 회수하지 않습니다.

## 14. 핵심 디자인 요청사항

본 화면은 UI 자체를 가지지 않으므로 별도 디자인 요청이 없습니다. 다만 리다이렉트 도중 공통 로딩 인디케이터는 D01 공통 디자인 시스템의 페이지 전체 로딩 패턴을 그대로 사용합니다. 사용자가 리다이렉트가 일어났다는 사실을 인지할 필요는 없도록, 깜빡임 없이 부드럽게 다음 화면으로 전환되어야 합니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

본 화면은 호환 처리 화면이므로 운영 정책의 본체는 SCR-101과 SCR-090에 있습니다. SCR-091에 직접 연결된 정책은 다음과 같습니다.

정본 화면 분리 정책은 전 지점 통합 대시보드의 정본을 D01 `SCR-101 대시보드 통합`으로 단일화한다는 것입니다. 본사 권한자(`superAdmin` / `primary`)는 `/` route의 SCR-101을 정본 진입 경로로 사용하며, SCR-091은 외부 도구나 구버전 북마크가 사용하는 `/super-dashboard` 경로만 리다이렉트로 보존합니다.

권한별 진입 분기 정책은 `/super-dashboard`에 접근한 세션의 권한 클레임만 보고 `/` route로 이동한다는 것입니다. 세션이 무효하거나 권한이 없으면 D01 공통 접근 제한 안내를 거쳐 `/login`으로 이동합니다.

데이터 비조회 정책은 SCR-091이 어떤 KPI나 위젯 데이터도 직접 조회하지 않는다는 것입니다. 전 지점 KPI·지점별 현황·히스토리 로그·지점 전환 같은 본문 동작은 모두 SCR-101이 담당하며, SCR-091은 단순 라우팅 호환 화면입니다.

감사 로그 정책은 본 화면이 자체적으로 별도 감사 로그를 발생시키지 않는다는 것입니다. 리다이렉트 후 진입한 SCR-101 또는 SCR-090에서 일어나는 행위가 각 화면 정책에 따라 SCR-097 감사 로그에 기록됩니다. 다만 세션 무효·토큰 만료로 차단된 진입은 D01 공통 인증 차단 로그 정책에 따라 기록될 수 있습니다.

이상의 모든 정책은 이 화면을 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다.
