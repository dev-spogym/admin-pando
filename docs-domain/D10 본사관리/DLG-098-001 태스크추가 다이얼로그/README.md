## 2. 다이얼로그 개요와 호출 트리거

태스크 추가 다이얼로그는 오늘의 할 일 페이지(SCR-098)에서 운영자가 임시 업무를 새로 등록하면서 제목·우선순위·담당자·마감 시각·메모·공유 범위를 한 번에 입력하는 등록 폼입니다. 본사관리 도메인의 일일 업무 시작점인 SCR-098은 자동 생성 7종 태스크(만료 예정·미수금·노쇼·생일·홀딩·재상담·체성분)와 운영자가 수동 추가한 태스크가 함께 표시되는데, 본 다이얼로그는 수동 추가 흐름의 단일 진입점입니다. 저장 즉시 태스크 목록에 새 항목으로 표시되고 KPI 센터(HQ-03) 액션 큐와의 양방향 동기화가 자동 트리거됩니다.

호출 트리거는 SCR-098 오늘의 할 일 페이지 상단의 [+ 할 일 추가] 버튼 클릭입니다. 이 버튼은 readonly 권한자를 제외한 모든 권한자(superAdmin, primary, owner, manager, fc, staff)에게 노출되며, 추가된 태스크의 공유 범위에 따라 본인만 또는 같은 지점 전 직원이 접근할 수 있습니다. 모바일에서는 풀스크린 형태로 다이얼로그가 표시되어 가독성과 입력 편의가 확보됩니다.

## 3. 입력 필드와 UI 구성

다이얼로그는 가로 약 480px 폭의 모달이며 세로 콘텐츠가 입력 필드 단위로 구성됩니다. 상단에는 "할 일 추가"라는 제목과 X 닫기 버튼이 있고, 본문에는 제목 입력란, 상세 설명 입력란, 우선순위 라디오, 담당자 검색 드롭다운, 마감 시각 입력, 공유 범위 라디오가 차례로 배치되며 하단에는 [취소] 버튼과 [추가] 버튼이 우측 정렬로 배치됩니다.

제목 입력란(필수, 1~100자)은 다이얼로그 진입 시 자동 포커스되어 운영자가 바로 입력할 수 있습니다. 상세 설명 입력란(선택, 최대 500자)은 멀티라인 텍스트 영역이며 입력 글자 수 카운터가 함께 표시됩니다. 우선순위 라디오는 "높음 / 보통 / 낮음" 3종이며 기본값은 "보통"이고, 자동 생성 7종 태스크와 동일한 색상 시스템이 적용됩니다(높음=빨강, 보통=노랑, 낮음=회색).

담당자 검색 드롭다운은 본인 지점 직원 중에서 다중 선택 가능하며 기본값은 본인입니다. 검색어 입력 시 직원명·직책으로 실시간 매칭되며, 본사 권한자(superAdmin/primary)는 전 지점 직원을, owner는 자기 지점 직원만 검색할 수 있습니다. 검색 결과가 없으면 "직원을 찾을 수 없습니다" 안내가 표시되며, 담당자 미지정 저장도 허용되지만 저장 후 "담당자 없음" 라벨로 목록에 표시됩니다.

마감 시각 입력(선택)은 시:분(HH:mm) 형식의 시간만 입력하며 오늘 날짜 기준입니다. 자정(00:00) 이후 시각은 다음 날로 자동 해석되는 것이 아니라 오늘 마감으로 처리되고, 마감 시각이 이미 지난 경우(예: 오전 9시에 11시 마감 입력 후 12시에 저장) 인라인 경고가 표시되지만 저장은 허용됩니다.

공유 범위 라디오는 "개인 / 지점" 2종이며 기본값은 "개인"입니다. "개인"으로 등록된 태스크는 본인만 조회·완료 가능하며, "지점"으로 등록된 태스크는 같은 지점 직원 모두에게 표시되고 담당자가 본인이 아니라도 owner는 완료 처리할 수 있습니다.

[추가] 버튼은 제목이 입력된 경우에만 활성화되며, 클릭 시 로딩 상태로 전환되어 중복 클릭이 차단됩니다. [취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 입력 도중인 경우 즉시 닫히고 변경 없이 부모 화면이 유지됩니다.

## 4. 검증 규칙

제목은 필수이며 1~100자 길이 제한이 있고, 미입력 시 인라인 오류 "제목을 입력해주세요"가 표시되며 [추가] 버튼이 비활성화됩니다. 이모지를 포함한 모든 유니코드 문자가 허용되며 좌우 공백은 자동으로 트림됩니다.

상세 설명은 선택이며 최대 500자입니다. 500자를 초과하면 입력 자체가 차단되고 카운터가 빨강으로 표시됩니다. 우선순위는 라디오로 강제 선택되어 누락되지 않으며, 기본값 "보통"이 항상 적용됩니다.

담당자 미지정은 허용되지만 본사 권한자가 owner 권한 외 직원을 담당자로 지정한 경우 백엔드에서 권한 일관성 검증이 수행되며, 검증 실패 시 "지정한 담당자가 권한 정책에 맞지 않습니다" 오류가 표시됩니다. owner는 자기 지점 직원만 담당자로 지정할 수 있고, 매니저 이하는 본인만 담당자로 지정 가능합니다.

마감 시각은 선택이며 HH:mm 형식의 24시간제만 허용됩니다. 형식 오류는 인라인으로 즉시 표시됩니다. 마감 시각이 현재 시각보다 과거인 경우 노랑 경고 "마감 시각이 이미 지났습니다"가 표시되지만 저장은 허용됩니다.

공유 범위는 라디오로 강제 선택되며 기본값 "개인"이 항상 적용됩니다. 매니저 이하 권한자는 "지점" 공유 범위 선택이 차단되며 라디오 자체가 비활성화됩니다.

## 5. 확인 / 취소 액션

[추가] 버튼을 누르면 다이얼로그가 로딩 상태로 전환되어 주요 버튼이 비활성화되고, 백엔드에 태스크 생성 트랜잭션이 전송됩니다. 트랜잭션 내에서 태스크 레코드 생성, 담당자에게 인앱 알림 발송(공유 범위 "지점"이고 본인이 아닌 경우), KPI 센터 액션 큐와의 동기화 트리거(자동 생성 카테고리에 해당하는 경우만), 감사 로그 INSERT가 한 트랜잭션으로 수행됩니다.

성공하면 다이얼로그가 닫히고 부모 화면(SCR-098)의 태스크 목록에 새 항목이 즉시 추가됩니다. 새 항목은 우선순위 정렬 기준(높음→보통→낮음)에 따라 적절한 위치에 삽입되며, 같은 우선순위 내에서는 마감 시각 오름차순으로 정렬됩니다. 마감 시각 미설정 태스크는 목록 하단에 배치됩니다. 우측 상단에 "할 일이 추가되었어요" 성공 토스트가 표시되고 진행 현황 요약 카드의 전체 항목 수와 완료율 분모가 즉시 갱신됩니다.

[취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 변경 없이 즉시 닫힙니다. 입력 도중이라도 추가 확인 없이 닫히는 이유는 등록 흐름이 짧고 입력값 손실 부담이 작기 때문입니다.

## 6. 예외 처리

저장 트랜잭션 실패 시 모달이 닫히지 않고 "저장에 실패했습니다. 다시 시도해 주세요" 토스트가 표시되며 입력값이 유지됩니다. 자동 재시도 1회 후 실패 시 사용자 액션을 기다립니다.

담당자 검색 API 실패 시 인라인 오류 "직원 검색에 실패했습니다" 표시 후 검색 필드가 초기화되며, 사용자는 검색어를 다시 입력해 재시도할 수 있습니다. 담당자 미지정으로 저장도 가능합니다.

권한 정책 검증 실패(예: 매니저가 본인 외 직원을 담당자로 지정 시도) 시 "지정한 담당자가 권한 정책에 맞지 않습니다" 오류가 표시되고 [추가] 버튼이 비활성화됩니다. 사용자는 담당자를 본인으로 변경하거나 권한자에게 위임해야 합니다.

마감 시각이 과거인 경우 노랑 경고가 표시되지만 저장은 허용됩니다. 이는 운영자가 의도적으로 과거 시각을 기록하는 경우(예: 이미 지난 회의 시간을 사후 등록)를 허용하기 위함입니다.

KPI 센터 액션 큐 동기화가 실패하더라도 태스크 자체는 정상 생성되며, 동기화 재시도는 백그라운드 큐로 위임됩니다(최대 3회 재시도). 재시도 실패 시 운영자에게 "KPI 큐 동기화에 실패했습니다" 별도 알림이 발송됩니다.

감사 로그 기록 실패는 사용자에게 표시되지 않으며(태스크 처리는 정상 완료) 백그라운드 재시도 3회 후 실패 시에만 관리자 알림이 발송됩니다. 이는 감사 로그 일시 장애가 운영 흐름을 막지 않도록 하는 정책입니다.

권한이 없는 계정이 직접 API로 태스크 생성을 시도하면 백엔드 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다.

## 7. 권한별 처리

본 다이얼로그는 readonly를 제외한 모든 권한자(superAdmin, primary, owner, manager, fc, staff)에게 호출 가능합니다. 권한별로 가능한 옵션이 다르게 제한됩니다.

superAdmin와 primary는 전 지점 직원을 담당자로 지정할 수 있으며 공유 범위 "지점"도 자유롭게 선택할 수 있습니다. 다만 본사 권한자가 지점 공유 태스크를 만드는 경우 어느 지점에 공유할지 명시적으로 선택해야 하며, 공유 지점 선택 드롭다운이 추가로 노출됩니다.

Owner(지점장)은 자기 지점 직원을 담당자로 지정할 수 있고 자기 지점 내 "지점" 공유 범위를 선택할 수 있습니다. 다른 지점 직원 선택은 검색 결과에서 차단됩니다.

매니저(manager), FC(fc), 스태프(staff)는 본인만 담당자로 지정 가능하며 공유 범위 "지점" 선택이 차단되어 라디오 자체가 비활성화됩니다. 즉, 이 권한자들이 추가하는 태스크는 "개인" 공유 범위로 고정됩니다. 단, owner가 "지점" 공유 범위로 추가한 태스크에 매니저 이하가 담당자로 지정되는 경우는 본 다이얼로그가 아닌 owner의 추가 흐름에서 처리됩니다.

읽기 전용(readonly)은 본 다이얼로그를 호출할 수 없습니다. 부모 화면(SCR-098)의 [+ 할 일 추가] 버튼이 readonly에게는 hidden 처리되며, 직접 URL 또는 콘솔 우회로 다이얼로그가 호출되더라도 백엔드 응답이 403으로 차단됩니다.

권한 부족으로 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 부모 화면의 호출 버튼이 hidden 또는 비활성화 처리됩니다. 둘째, 다이얼로그 내 옵션(공유 범위·담당자 검색 범위)이 권한에 맞게 자동 제한됩니다. 셋째, 직접 API 호출 우회 시 백엔드 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다.

## 8. 운영 정책 (이 다이얼로그에 연결된 부분)

태스크 생명 주기 정책에 따라 본 다이얼로그로 추가된 태스크는 오늘 날짜에만 표시됩니다. 자정(00:00)이 지나면 새 날짜 기준 태스크 목록이 표시되며 전날 미완료 태스크는 자동 이월되지 않습니다. 이월이 필요한 경우 운영자가 새 날짜에 동일 내용으로 재등록해야 하며, 전날 23:50에 미완료 알림이 담당자에게 앱 푸시로 발송되어 누락을 방지합니다.

KPI 센터 액션 큐 연동 정책에 따라 본 다이얼로그로 추가된 태스크는 기본적으로 KPI 큐와 무관한 임시 업무로 처리되지만, 운영자가 의도적으로 자동 생성 7종 카테고리(만료·미수금·노쇼·생일·홀딩·재상담·체성분)와 동일한 형식으로 추가한 경우 백엔드 카테고리 매칭 로직이 KPI 큐와 양방향 동기화를 자동 트리거합니다. 동기화 실패는 백그라운드 재시도 큐로 위임됩니다.

공유 범위 정책에 따라 "개인" 태스크는 본인만 조회·완료 가능하고, "지점" 태스크는 같은 지점 직원 모두에게 표시됩니다. 지점 공유 태스크의 담당자는 다중 선택이 가능하며, 담당자 중 누구나 완료 처리할 수 있고 완료 처리 시 다른 담당자에게 알림이 발송됩니다. 본사 권한자가 만든 지점 공유 태스크는 명시적으로 선택한 지점에만 노출되며, 다른 지점에는 RLS로 차단됩니다.

우선순위 정렬 정책에 따라 태스크 목록은 우선순위(높음→보통→낮음) 1차 정렬, 마감 시각 오름차순 2차 정렬로 자동 정렬됩니다. 마감 시각 미설정 태스크는 같은 우선순위 내 가장 하단에 배치됩니다. 운영자가 드래그앤드롭으로 수동 정렬한 경우 수동 정렬이 자동 정렬보다 우선 적용되지만 우선순위 배지는 그대로 유지됩니다.

담당자 권한 정책에 따라 담당자 선택 가능 범위가 권한별로 다르게 제한됩니다. 슈퍼관리자·primary는 전 지점 직원, owner는 자기 지점 직원, 매니저 이하는 본인으로 제한됩니다. 이는 운영 책임 소재의 명확성을 보장하기 위한 정책이며, 백엔드에서도 동일하게 검증됩니다.

마감 알림 정책에 따라 마감 시각이 설정된 태스크는 마감 30분 전 담당자에게 인앱 푸시 알림이 자동 발송됩니다. 마감 시각 미설정 태스크는 알림 대상에서 제외됩니다.

감사 로그 정책에 따라 모든 태스크 생성 이벤트는 SCR-097 감사 로그에 기록됩니다. 기록되는 필드는 `actor_id`(생성자), `task_id`(태스크 ID), `action=TASK_CREATE`, `before=null`, `after`(제목·우선순위·담당자·마감 시각·공유 범위·메모 스냅샷), `branch_id`(소속 지점), `timestamp`이며 비동기 INSERT로 5초 안에 감사 로그 화면에서 조회 가능해야 합니다.

자동 생성 7종 태스크와의 구분 정책에 따라 본 다이얼로그로 추가된 태스크는 "수동 추가" 메타 태그가 자동으로 부여되며, KPI 센터의 자동 생성 카테고리(만료·미수금·노쇼·생일·홀딩·재상담·체성분)와 시각적으로 구분됩니다(자동 생성은 카테고리 배지, 수동 추가는 메모 아이콘). 자동 생성 7종은 매일 06:00 배치에서 생성되며 본 다이얼로그를 통하지 않습니다.

## 11. 핵심 디자인 요청사항

다이얼로그는 가로 약 480px 폭의 모달이며 모바일에서는 풀스크린 형태로 자동 전환되어 가독성과 입력 편의가 확보됩니다. 입력 폼은 제목·상세·옵션의 3단 구성으로 시각적으로 분리되며, 각 영역 사이에는 충분한 여백이 확보되어 시선이 자연스럽게 흐릅니다.

제목 입력란은 다이얼로그 진입 시 자동 포커스되어 운영자가 키보드 입력만으로 바로 작성을 시작할 수 있어야 합니다. 폰트 크기는 일반 텍스트보다 크고 강조되어 가장 중요한 필드임이 시각적으로 드러납니다. 필수 표시는 라벨 옆 빨강 별표(*)로 명확히 합니다.

우선순위 라디오는 색상이 함께 적용된 배지 형태로 시각화됩니다. 높음은 빨강, 보통은 노랑, 낮음은 회색이며 자동 생성 7종 태스크와 동일한 색상 시스템이 사용되어 일관성이 유지됩니다. 선택된 옵션은 강한 그림자와 함께 시각적으로 강조됩니다.

담당자 검색 드롭다운은 검색어 입력 시 실시간 매칭 결과를 검색창 아래에 펼쳐 보여주며, 직원 항목에는 프로필 사진·이름·직책·소속 지점이 한 줄에 표시됩니다. 다중 선택된 담당자는 검색창 아래에 칩 형태로 누적 표시되며, 각 칩의 X 버튼으로 개별 해제가 가능합니다.

마감 시각 입력은 시간 선택 컴포넌트(시·분 드롭다운 또는 직접 입력)로 제공되며, 입력란 옆에 "현재 시각" 토글 버튼이 함께 배치되어 한 클릭으로 현재 시각을 자동 채울 수 있습니다. 과거 시각 입력 시 입력란 옆에 작은 노랑 경고 아이콘과 함께 "마감 시각이 이미 지났습니다" 인라인 메시지가 표시됩니다.

공유 범위 라디오는 "개인" 옆에 본인 아이콘, "지점" 옆에 지점 아이콘이 함께 표시되어 직관적으로 구분됩니다. 매니저 이하 권한자에게는 "지점" 옵션이 회색 처리되며 호버 시 "owner 이상 권한자만 지점 공유가 가능합니다" 툴팁이 표시됩니다.

[추가] 버튼은 주 액션 색상(브랜드 컬러)으로, [취소] 버튼은 보조 색상으로 분리되어 시각적 위계가 명확히 드러납니다. 로딩 상태에서는 [추가] 버튼이 스피너로 전환되고 모든 입력 필드가 비활성화되어 사용자가 변경할 수 없게 차단됩니다. 성공 토스트는 우측 상단에 녹색 계열로 5초 표시되며, 목록에 추가된 새 항목이 짧은 하이라이트 애니메이션으로 강조되어 운영자가 즉시 인식할 수 있어야 합니다.
