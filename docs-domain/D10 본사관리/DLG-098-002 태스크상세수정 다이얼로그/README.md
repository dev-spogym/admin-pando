## 2. 다이얼로그 개요와 호출 트리거

태스크 상세 수정 다이얼로그는 오늘의 할 일 페이지(SCR-098)에 등록된 기존 태스크의 제목·상세 설명·우선순위·담당자·마감 시각·메모·공유 범위·완료 여부를 수정하는 편집 폼입니다. 자동 생성 7종 태스크(만료 예정·미수금·노쇼·생일·홀딩·재상담·체성분)와 수동 추가 태스크 모두 본 다이얼로그로 수정할 수 있으며, 자동 생성 태스크는 카테고리·대상 회원 메타 정보가 readonly로 추가 표시됩니다. 저장 시 변경 사항이 KPI 센터 액션 큐와 양방향 동기화되고 모든 변경 이력은 감사 로그(SCR-097)에 누적 기록됩니다.

호출 트리거는 두 가지입니다. 첫 번째는 SCR-098 태스크 목록 행 우측의 [수정] 버튼 클릭이며, 본인이 담당자이거나 owner 이상 권한자에게만 활성화됩니다. 두 번째는 태스크 행 더블 클릭이며 동일 권한 조건이 적용됩니다. 완료 처리된 태스크는 행이 흐림 처리되지만 수정은 여전히 가능하며, 본 다이얼로그 내에서 완료 여부 토글로 미완료 복원도 수행할 수 있습니다. 다이얼로그가 열리는 즉시 기존 태스크 내용이 모든 필드에 자동 로드됩니다.

## 3. 입력 필드와 UI 구성

다이얼로그는 가로 약 480px 폭의 모달이며 세로 콘텐츠가 입력 필드 단위로 구성됩니다. 상단에는 "할 일 수정"이라는 제목과 함께 마지막 수정자·수정 시각이 작은 글씨로 표시되며 우측에 X 닫기 버튼이 있고, 본문에는 제목, 상세 설명, 우선순위, 담당자, 마감 시각, 공유 범위, 완료 여부 토글, 변경 이력 보기 링크가 차례로 배치되며 하단에는 [취소] 버튼과 [저장] 버튼이 우측 정렬로 배치됩니다.

각 입력 필드는 기존 값이 자동 로드된 상태로 표시됩니다. 제목 입력란(필수, 1~100자)에는 기존 제목이 채워지고 진입 즉시 자동 포커스되어 수정이 바로 시작될 수 있습니다. 상세 설명 입력란(선택, 최대 500자)에는 기존 메모가 채워지며 입력 글자 수 카운터가 함께 표시됩니다. 우선순위 라디오는 기존 값이 선택된 상태로 표시되고, 담당자 검색 드롭다운은 기존 담당자 칩이 누적 표시된 상태로 시작되며 추가·해제가 가능합니다.

마감 시각 입력은 기존 값으로 채워지며 비어 있던 경우 빈 상태로 표시됩니다. "현재 시각" 토글 버튼이 함께 배치되어 한 클릭으로 현재 시각으로 갱신할 수 있습니다. 공유 범위 라디오는 기존 값이 선택된 상태이며, 매니저 이하 권한자에게는 "지점" 옵션이 비활성화됩니다.

완료 여부 토글은 본 다이얼로그에서만 노출되는 추가 필드입니다(추가 다이얼로그 DLG-098-001에는 없습니다). 토글이 ON이면 태스크가 완료 상태로 즉시 마킹되며 저장 시 완료 일시가 기록되고, OFF로 전환하면 미완료 상태로 복원됩니다. 완료 복원 이력도 감사 로그에 누적됩니다.

본문 하단에는 "변경 이력 보기" 링크가 작은 글씨로 노출됩니다. 클릭 시 인라인으로 변경 이력 패널이 펼쳐져 최근 5건의 변경(누가, 언제, 어떤 필드를 무엇에서 무엇으로)이 시계열로 표시됩니다. 자동 생성 7종 태스크의 경우 카테고리 배지(만료·미수금·노쇼·생일·홀딩·재상담·체성분 중 하나)와 대상 회원 정보가 readonly로 추가 표시되어 운영자가 어떤 자동 트리거로 생성되었는지 추적할 수 있습니다.

[저장] 버튼은 기존 값에서 변경이 발생한 경우에만 활성화되며(변경 사항이 없으면 비활성화), 클릭 시 로딩 상태로 전환되어 중복 클릭이 차단됩니다. [취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 입력 도중인 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인을 한 번 더 묻습니다.

## 4. 검증 규칙

제목은 필수이며 1~100자 길이 제한이 있고, 좌우 공백이 자동 트림되어 빈 값이 되면 인라인 오류 "제목을 입력해주세요"가 표시되며 [저장] 버튼이 비활성화됩니다. 이모지를 포함한 모든 유니코드 문자가 허용됩니다.

상세 설명은 선택이며 최대 500자입니다. 500자를 초과하면 입력 자체가 차단되고 카운터가 빨강으로 표시됩니다. 우선순위는 라디오로 강제 선택되어 누락되지 않으며, 빈 값으로 저장될 수 없습니다.

담당자 권한 정책 검증은 추가 다이얼로그와 동일하게 적용됩니다. 슈퍼관리자·primary는 전 지점 직원, owner는 자기 지점 직원, 매니저 이하는 본인으로 제한되며 위반 시 "지정한 담당자가 권한 정책에 맞지 않습니다" 오류가 표시됩니다. 다만 본 다이얼로그가 매니저 이하 담당자에게 호출된 경우, 담당자 변경 자체가 차단되어(자기 자신 외 선택 불가) 위반이 발생할 일이 없습니다.

마감 시각 형식 오류는 인라인으로 즉시 표시됩니다. 마감 시각이 현재 시각보다 과거인 경우 노랑 경고가 표시되지만 저장은 허용됩니다.

공유 범위 변경은 추가 다이얼로그와 동일한 권한 제한이 적용됩니다. 또한 본 다이얼로그에서 공유 범위를 "지점"에서 "개인"으로 좁히는 경우, 기존에 해당 태스크를 보고 있던 다른 직원에게는 자동으로 사라지므로 인라인 경고 "이 태스크가 다른 직원에게 더 이상 보이지 않게 됩니다"가 표시됩니다.

자동 생성 7종 태스크의 카테고리 배지와 대상 회원 정보는 readonly로 표시되며 운영자가 변경할 수 없습니다. 이는 자동 생성 메타 정보의 무결성을 보장하기 위한 정책입니다.

## 5. 확인 / 취소 액션

[저장] 버튼을 누르면 다이얼로그가 로딩 상태로 전환되어 주요 버튼이 비활성화되고, 백엔드에 태스크 수정 트랜잭션이 전송됩니다. 트랜잭션 내에서 변경된 필드만 PATCH 방식으로 업데이트되고, 변경 전·후 값이 감사 로그에 INSERT되며, 담당자가 변경된 경우 신규 담당자에게 인앱 알림이 발송되고 이전 담당자에게는 "담당이 변경되었습니다" 안내가 발송됩니다. KPI 센터 액션 큐와 자동 양방향 동기화가 트리거되며, 완료 여부 토글이 변경된 경우 완료율 분자가 갱신되고 진행 현황 요약 카드도 즉시 재계산됩니다.

성공하면 다이얼로그가 닫히고 부모 화면(SCR-098)의 태스크 목록에서 해당 행이 즉시 갱신되며 짧은 하이라이트 애니메이션으로 변경 사실이 시각적으로 강조됩니다. 우선순위가 변경된 경우 목록 정렬이 자동 재정렬되어 변경된 행이 새 위치로 부드럽게 이동합니다. 우측 상단에 "할 일이 수정되었어요" 성공 토스트가 표시됩니다.

완료 여부 토글만 변경한 경우(다른 필드는 그대로)의 흐름은 행의 체크박스를 직접 클릭한 경우와 동일하게 처리됩니다. 완료 상태가 변경되면 진행 현황 요약 카드의 완료율 프로그레스 바가 즉시 갱신되고, 완료율 100% 도달 시 "모든 할 일 완료!" 축하 메시지가 부모 화면에 표시됩니다.

[취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 입력 도중인 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인 yes/no가 한 번 더 표시됩니다. 확정 시 변경 없이 다이얼로그가 닫히고 부모 화면이 그대로 유지됩니다.

## 6. 예외 처리

저장 트랜잭션 실패 시 모달이 닫히지 않고 "저장에 실패했습니다. 다시 시도해주세요" 토스트가 표시되며 입력값이 유지됩니다. 자동 재시도 1회 후 실패 시 사용자 액션을 기다립니다.

다른 운영자가 같은 태스크를 동시에 편집한 경우 optimistic lock 위반이 발생하며 "다른 운영자가 동시에 편집했어요" 모달이 표시됩니다. 모달에는 변경 전·후 비교 카드가 함께 표시되어 사용자가 자신의 변경과 다른 운영자의 변경을 비교한 뒤 새로고침 또는 강제 저장(주의 안내 후) 중 선택할 수 있습니다.

수정 도중 다른 운영자가 해당 태스크를 삭제한 경우 저장 시 "태스크가 삭제되었습니다" 안내가 표시되고 다이얼로그가 자동 닫힙니다. 부모 화면은 새로고침으로 최신 상태를 반영합니다.

자동 생성 7종 태스크의 카테고리·대상 회원 정보 변경 시도는 readonly 필드이므로 UI에서 차단되지만, 우회로 시도된 경우 백엔드에서 400 응답으로 차단되고 "자동 생성 태스크의 메타 정보는 수정할 수 없습니다" 오류가 표시됩니다.

권한 없는 사용자가 본인이 담당자가 아닌 태스크를 수정 시도한 경우(예: 매니저가 다른 직원 담당 태스크 직접 URL 호출) 백엔드 403으로 차단되고 "본인 담당 항목만 수정할 수 있습니다" 토스트가 표시되며 다이얼로그가 자동 닫힙니다. 감사 로그에 권한 우회 시도가 기록됩니다.

KPI 센터 액션 큐 동기화 실패 시 태스크 수정 자체는 정상 처리되며 동기화는 백그라운드 큐로 위임됩니다(최대 3회 재시도). 재시도 실패 시 "KPI 큐 동기화에 실패했습니다" 별도 알림이 운영자에게 발송됩니다.

담당자 변경 알림 발송 실패 시 신규·이전 담당자 알림은 백그라운드 재시도 큐로 위임됩니다. 실패 시 운영자에게 "알림 발송이 실패했어요. 직접 안내해주세요" 별도 알림이 발송됩니다.

자정(00:00)이 지난 직후 수정 시도 시 태스크가 어제 날짜로 분류되어 오늘 목록에서 사라지는 케이스는 백엔드 응답에 "어제 날짜 태스크입니다. 새 날짜에 등록하세요" 안내가 포함되어 다이얼로그가 자동 닫힙니다.

## 7. 권한별 처리

본 다이얼로그는 readonly를 제외한 모든 권한자에게 호출 가능하지만, 수정 가능 범위는 권한별로 다르게 제한됩니다.

슈퍼관리자(superAdmin)와 본사 최고관리자(primary)는 전 지점의 모든 태스크를 수정할 수 있으며 담당자도 전 지점 직원으로 자유 변경 가능합니다. 자동 생성 7종 태스크의 카테고리·대상 회원 메타 정보는 readonly이지만 다른 모든 필드는 수정 가능합니다.

Owner(지점장)은 자기 지점 태스크를 수정할 수 있으며 담당자는 자기 지점 직원으로 제한됩니다. 본인이 담당자가 아니어도 자기 지점 태스크의 [수정] 버튼이 활성화됩니다.

매니저(manager), FC(fc), 스태프(staff)는 본인이 담당자로 지정된 태스크만 수정할 수 있습니다. 본인이 담당자가 아닌 태스크의 [수정] 버튼은 비활성화되며, 직접 URL 호출 시 백엔드 403으로 차단됩니다. 담당자 변경은 차단되어 자기 자신 외 선택이 불가능합니다.

읽기 전용(readonly)은 본 다이얼로그를 호출할 수 없습니다. 부모 화면(SCR-098)의 [수정] 버튼이 readonly에게는 hidden 처리되며, 행 더블 클릭도 비활성화됩니다.

완료 여부 토글은 추가 권한 정책이 적용됩니다. 본인이 담당자인 경우 완료/미완료 자유 전환이 가능하며, owner 이상은 자기 지점 모든 태스크의 완료 여부를 변경할 수 있습니다. 매니저 이하가 본인이 담당이 아닌 태스크의 완료 토글을 시도하면 "본인 담당 항목만 완료 처리할 수 있습니다" 토스트가 표시됩니다(다만 매니저 이하는 애초에 본인 담당 외 태스크의 본 다이얼로그를 열 수 없으므로 이 케이스는 직접 API 우회 시에만 발생합니다).

권한 부족으로 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 부모 화면의 [수정] 버튼이 비활성화 또는 hidden 처리됩니다. 둘째, 다이얼로그 내 필드(담당자·공유 범위)가 권한에 맞게 자동 제한됩니다. 셋째, 직접 API 호출 우회 시 백엔드 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다.

## 8. 운영 정책 (이 다이얼로그에 연결된 부분)

태스크 수정 가능 범위 정책에 따라 자동 생성 7종 태스크의 카테고리·대상 회원 메타 정보는 readonly로 보호됩니다. 이는 자동 생성 메타 정보의 무결성을 보장해 KPI 센터와의 양방향 동기화가 깨지지 않도록 하기 위한 정책입니다. 자동 생성 7종은 매일 06:00 배치로 생성되며, 본 다이얼로그를 통해 운영자가 수정할 수 있는 것은 제목·상세·우선순위·담당자·마감 시각·공유 범위·완료 여부에 한정됩니다.

변경 이력 누적 정책에 따라 모든 수정 이벤트는 감사 로그(SCR-097)에 누적 기록됩니다. 기록되는 필드는 `actor_id`(수정자), `task_id`(태스크 ID), `action=TASK_UPDATE`, `before`(이전 값 스냅샷), `after`(신규 값 스냅샷), `changed_fields[]`(변경된 필드 목록), `branch_id`(소속 지점), `timestamp`이며 비동기 INSERT로 5초 안에 감사 로그 화면에서 조회 가능해야 합니다. 변경 이력 보기 링크는 이 감사 로그의 일부를 인라인으로 표시합니다.

완료 복원 정책에 따라 본 다이얼로그의 완료 여부 토글로 완료→미완료 복원이 자유롭게 가능합니다. 복원 이력도 감사 로그에 누적되며, 행의 체크박스를 직접 클릭한 완료 처리와 동일한 흐름으로 처리됩니다. 완료 복원은 KPI 센터 액션 큐와 자동 동기화되어 양쪽 시스템의 일관성이 유지됩니다.

담당자 변경 알림 정책에 따라 담당자가 변경된 경우 신규 담당자에게는 "새 할 일이 배정되었습니다" 인앱 알림이, 이전 담당자에게는 "할 일 담당이 변경되었습니다" 인앱 알림이 자동 발송됩니다. 발송 실패는 백그라운드 재시도 큐로 위임됩니다.

공유 범위 변경 정책에 따라 "지점"에서 "개인"으로 좁히는 경우 기존에 해당 태스크를 보고 있던 다른 직원의 시야에서 자동으로 사라집니다. 운영자에게는 사전 경고가 표시되며 명시적으로 진행 시 변경 즉시 적용됩니다. 반대로 "개인"에서 "지점"으로 확장하는 경우 같은 지점 직원 모두에게 새로 노출되며, 알림은 추가로 발송되지 않습니다.

우선순위 변경 정책에 따라 우선순위가 변경되면 부모 화면의 태스크 목록이 자동 재정렬됩니다. 정렬 기준은 우선순위(높음→보통→낮음) 1차, 마감 시각 오름차순 2차이며 수동 드래그 정렬이 설정된 태스크는 수동 정렬이 우선 적용됩니다.

KPI 센터 동기화 정책에 따라 KPI 액션 큐에서 자동 생성된 태스크의 완료/미완료 상태는 본 다이얼로그의 완료 여부 토글과 양방향으로 즉시 동기화됩니다. 동기화는 실시간 이벤트로 처리되며 실패 시 백그라운드 재시도 큐로 위임됩니다.

마감 시각 변경 알림 정책에 따라 마감 시각이 변경되면 기존 30분 전 알림 스케줄이 자동 갱신됩니다. 마감 시각이 이미 지난 시점으로 변경되면 알림은 발송되지 않습니다.

태스크 삭제는 본 다이얼로그에서 직접 지원되지 않습니다. 삭제가 필요한 경우 부모 화면의 [삭제] 버튼으로 별도 확인 모달을 거쳐야 하며, 이는 실수에 의한 영구 삭제를 방지하기 위한 정책입니다. 삭제는 영구 처리이며 복구 불가, 재등록만 가능합니다.

자정 날짜 변경 정책에 따라 자정(00:00)이 지나면 오늘 날짜 기준 태스크 목록이 새로 표시되며, 본 다이얼로그가 열린 상태에서 자정이 지나면 백엔드 응답에 "어제 날짜 태스크입니다" 안내가 포함되어 다이얼로그가 자동 닫힙니다.

## 11. 핵심 디자인 요청사항

다이얼로그는 가로 약 480px 폭의 모달이며 모바일에서는 풀스크린 형태로 자동 전환되어 가독성과 입력 편의가 확보됩니다. 헤더에는 "할 일 수정" 제목과 함께 마지막 수정자·수정 시각이 작은 글씨로 표시되어 운영자가 누가 마지막으로 변경했는지 즉시 인식할 수 있어야 합니다.

기존 값이 자동 로드된 입력 필드는 진입 즉시 시각적으로 강조되어 운영자가 어떤 값이 채워져 있는지 한눈에 파악할 수 있습니다. 변경된 필드는 좌측에 작은 점 표식이 추가로 표시되어 "이 필드가 수정되었음"을 시각적으로 알리며, 저장 전까지 모든 변경 사항이 점 표식으로 누적 표시됩니다.

자동 생성 7종 태스크의 카테고리 배지와 대상 회원 정보는 readonly 영역에 회색 배경으로 분리 배치되며, 자물쇠 아이콘과 함께 "자동 생성 메타 정보" 라벨이 명확히 표시됩니다. 운영자가 readonly 영역을 클릭하면 작은 툴팁 "자동 생성 태스크의 메타 정보는 수정할 수 없습니다"가 안내됩니다.

완료 여부 토글은 다이얼로그 본문 하단에 큰 토글 스위치로 배치되며, ON일 때 초록색, OFF일 때 회색으로 시각화됩니다. 완료 처리 시 입력 필드 전반에 짧은 페이드 효과가 적용되어 완료 상태로 전환됨을 시각적으로 알립니다.

변경 이력 보기 링크는 본문 하단에 작은 글씨로 노출되며, 클릭 시 인라인 패널이 슬라이드 다운으로 펼쳐져 최근 5건의 변경이 시계열로 표시됩니다. 각 이력 행에는 변경자 프로필 사진, 변경 시각, 변경된 필드와 전·후 값이 한 줄에 정리되어 표시됩니다.

담당자 변경 시 신규·이전 담당자에게 알림이 발송됨을 운영자가 사전 인지할 수 있도록, 담당자 칩을 변경하면 칩 아래에 "변경 시 알림이 발송됩니다" 작은 안내가 인라인으로 표시됩니다. 공유 범위를 "지점"에서 "개인"으로 좁히는 경우에도 라디오 아래에 노랑 경고가 명시적으로 표시됩니다.

[저장] 버튼은 변경 사항이 있을 때만 활성화되며 변경이 없으면 비활성 상태로 유지됩니다. 이는 운영자에게 "아무것도 변경되지 않았다"는 사실을 시각적으로 알리는 신호이며, 변경 발생 즉시 버튼이 활성 색상으로 전환되는 부드러운 애니메이션이 적용됩니다. [취소] 버튼은 보조 색상으로 분리되며 우측 정렬로 배치됩니다.

로딩 상태에서는 [저장] 버튼이 스피너로 전환되고 모든 입력 필드가 비활성화되어 사용자가 변경할 수 없게 차단됩니다. 성공 토스트는 우측 상단에 녹색 계열로 5초 표시되며 부모 화면 목록에서 변경된 행이 짧은 하이라이트 애니메이션으로 강조되어 운영자가 즉시 인식할 수 있어야 합니다. 우선순위가 변경되어 행이 새 위치로 이동하는 경우에는 부드러운 슬라이드 애니메이션이 적용되어 자연스러운 시각적 흐름이 제공됩니다.
