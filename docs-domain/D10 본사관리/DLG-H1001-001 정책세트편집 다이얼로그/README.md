## 2. 다이얼로그 개요와 호출 트리거

정책 세트 편집 다이얼로그는 본사 슈퍼관리자가 자동화 정책 세트의 기본 정보, 적용 범위, 스텝 리스트(기준일·채널·템플릿·필수 여부·지점 토글 허용 여부), 지점 수정 허용 범위를 한 번에 입력·수정·복제하는 핵심 편집 폼입니다. 본 다이얼로그는 만료 알림과 운영 자동화 정책을 세트 단위로 라이브러리화해 신규 지점에 자동 적용하고 기존 지점에 일괄 배포하는 본사 운영의 단일 진입점입니다. 고정 D-day 대신 본사가 입력한 기준일 step 리스트 구조를 사용하므로 운영자가 D-30·D-7·D-1 같은 임의 기준일을 자유롭게 조합할 수 있습니다.

호출 트리거는 세 가지입니다. 첫 번째는 SCR-H1001 자동화 정책 라이브러리 헤더의 [+ 정책 세트] 버튼 클릭이며 신규 생성 모드로 다이얼로그가 빈 폼 상태로 열립니다. 두 번째는 정책 카드 또는 정책 테이블 행의 [편집] 버튼 클릭이며 기존 정책 세트가 모든 필드에 자동 로드된 수정 모드로 열립니다. 세 번째는 정책 카드의 [복제] 버튼 클릭이며 원본 정책의 스텝과 설정이 복사된 상태로 새 이름 입력만 요구하는 복제 모드로 열리고, 복제 직후 상태는 "중지"로 시작되어 운영자가 명시적으로 활성화해야 합니다. 본 다이얼로그는 슈퍼관리자(superAdmin)와 본사 최고관리자(primary)에게만 호출 가능하며, 그 외 권한자에게는 부모 화면 자체가 차단됩니다.

## 3. 입력 필드와 UI 구성

다이얼로그는 가로 약 800px 폭의 모달로, 스텝 리스트가 다수 카드로 누적될 수 있으므로 세로 스크롤이 다이얼로그 내부에서만 발생하고 헤더와 푸터(버튼 영역)는 sticky로 항상 노출됩니다. 상단에는 모드별 제목("정책 세트 생성" / "정책 세트 수정" / "정책 세트 복제")과 함께 수정 모드에서는 마지막 수정자·수정 시각이 작은 글씨로 따라붙고, 우측에 X 닫기 버튼이 있습니다. 본문은 기본정보 섹션, 적용 범위 섹션, 스텝 리스트 섹션, 지점 수정 허용 범위 섹션의 4단 구성이며 하단에는 [취소] 버튼, [시뮬레이션 실행] 버튼, [저장] 버튼이 우측 정렬로 배치됩니다.

기본정보 섹션에는 정책명 입력란(필수, 1~50자, 괄호·하이픈 허용, 이모지 차단, 전사 unique), 정책 성격 라디오(만료 알림 / 운영 자동화), 사용 상태 라디오(사용중 / 중지), 기본 여부 체크박스("이 정책을 기본 정책으로 지정"), 정책 설명 텍스트 영역(선택, 최대 200자)이 포함됩니다. 기본 정책 체크박스는 전사에 1개만 지정 가능하므로, 이미 다른 정책이 기본으로 지정된 상태에서 체크하면 "현재 기본 정책({기존 정책명})을 대체합니다" 안내가 인라인으로 표시됩니다.

적용 범위 섹션에는 적용 범위 라디오(전사 / 특정 지점군)가 있고, "특정 지점군"을 선택하면 지점 선택 멀티 체크박스가 펼쳐집니다. 지점 선택 영역에는 지점명 검색창과 함께 전체 선택·해제 토글이 함께 배치되며, 선택된 지점 수가 우측에 카운터로 표시됩니다. "전사"를 선택하면 전체 지점에 자동 적용되며 신규 지점 등록 시에도 자동 배포됩니다.

스텝 리스트 섹션은 본 다이얼로그의 핵심 영역입니다. 상단에 [+ 스텝 추가] 버튼이 있고, 그 아래에 등록된 스텝이 카드 리스트로 누적 표시됩니다. 각 스텝 카드에는 기준일 입력(음수=만료 전 N일, 양수=만료 후 N일, 정수만), 채널 다중 선택 체크박스(SMS / 카카오 / 앱푸시), 템플릿 선택 드롭다운(테넌트 활성 템플릿 목록), 필수/선택 토글, 지점 토글 허용 라디오(허용 / 채널만 변경 허용 / 변경 불가), 카드 우측 [삭제] 버튼이 포함됩니다. 카드 좌측에는 드래그 핸들이 있어 순서를 임의 조정할 수 있지만, 저장 시점에는 기준일 오름차순으로 자동 재정렬됩니다(같은 기준일은 등록 순 유지). 동일 기준일 스텝이 둘 이상이면 경고 배지 "동일 기준일 스텝이 있어요"가 카드 위에 표시됩니다.

지점 수정 허용 범위 섹션은 정책 세트 전체에 대한 글로벌 기본값을 설정하는 영역입니다. 각 스텝 카드의 지점 토글 허용 라디오는 스텝별 독립 설정이지만, 본 섹션에서는 일괄 기본값(허용 / 채널만 변경 허용 / 변경 불가)을 설정해 신규 스텝 추가 시 자동으로 그 값으로 시작되게 합니다.

[저장] 버튼은 정책명이 입력되고 스텝이 최소 1개 이상 등록되어야 활성화되며 클릭 시 로딩 상태로 전환됩니다. [시뮬레이션 실행] 버튼은 저장 전 검증용이며, 가상 회원의 이용권 만료일 임의 설정으로 스텝 발송 타이밍을 미리보기로 표시합니다. [취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 입력 도중인 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인을 한 번 더 묻습니다.

## 4. 검증 규칙

정책명은 필수이며 1~50자 길이 제한이 있고, 괄호·하이픈은 허용되지만 이모지는 차단됩니다. 전사 unique 제약이 있어 중복 시 인라인 오류 "이미 사용 중인 정책명이에요"가 표시됩니다. 복제 모드에서는 원본 정책명에 "(복제)" 접미사가 자동 부여되어 중복을 사전 방지하지만, 동일 접미사가 이미 존재하면 운영자가 새 이름을 직접 입력해야 합니다.

스텝은 최소 1개 이상 등록되어야 저장 가능하며, 0개로 저장 시도 시 인라인 오류 "스텝을 최소 1개 이상 추가해주세요"가 표시되고 [저장] 버튼이 비활성화됩니다. 기준일은 정수만 허용되며 음수(만료 전)·양수(만료 후) 모두 가능합니다. 0(만료 당일) 입력도 허용됩니다. 형식 오류는 인라인으로 즉시 표시됩니다.

동일 기준일 스텝이 둘 이상이면 경고 배너 "동일 기준일 스텝이 있어요"가 표시되며, 사용자 확인 후 강제 저장은 허용되되 이중 발송 책임이 운영자에게 있음이 명시됩니다. 채널이 다중 선택된 스텝(같은 기준일에 2개 이상 채널)은 동일 시점에 2개 채널로 발송되므로 "동일 시점에 {채널 수}개 채널로 발송됩니다" 안내 팝업이 저장 전 표시되어 운영자가 의도를 확인합니다.

채널 가용성 검증은 저장 시점에 자동 수행됩니다. 선택된 채널(SMS / 카카오 / 앱푸시)이 테넌트에 활성화되어 있지 않으면 경고 "해당 채널은 현재 비활성 상태입니다"가 표시되며, 저장은 허용되되 실제 발송 시 실패 가능성이 안내됩니다.

기본 정책 체크박스는 전사 unique 제약이 있으며, 체크 시 기존 기본 정책이 자동 해제되어 새 정책이 기본으로 지정됩니다. 기존 기본 정책을 중지하거나 삭제하려는 경우 본 다이얼로그가 아닌 부모 화면의 [중지] 또는 [삭제] 액션에서 차단되며 "다른 세트를 기본으로 지정 후 시도해주세요" 안내가 표시됩니다.

필수 스텝(required=true)을 삭제하려는 시도는 인라인 오류 "필수 스텝은 삭제할 수 없습니다"로 차단됩니다. 필수→선택 변경은 본사 슈퍼관리자(superAdmin)만 가능하며, 변경 시 인라인 경고 "필수 스텝을 선택으로 변경하면 지점이 OFF로 토글할 수 있습니다"가 표시됩니다.

적용 범위가 "전사"에서 "특정 지점군"으로 변경되는 경우 기존 전사 적용 지점 중 새 범위 외 지점에는 자동 해제 알림이 발송됨이 인라인 경고로 사전 표시되며, 운영자가 확인해야 [저장]이 가능합니다.

## 5. 확인 / 취소 액션

[저장] 버튼을 누르면 다이얼로그가 로딩 상태로 전환되어 주요 버튼이 비활성화되고, 백엔드에 정책 세트 저장 트랜잭션이 전송됩니다. 트랜잭션 내에서 정책 세트 레코드 생성·수정, 스텝 리스트 일괄 INSERT/UPDATE/DELETE, 이전 버전 스냅샷 보존(수정 모드, 최대 10개 FIFO), 영향 범위 내 지점 정책 캐시 무효화·재적용 배치 트리거, 기본 정책 변경 시 기존 기본 자동 해제, 감사 로그 INSERT가 한 트랜잭션으로 수행됩니다.

수정 모드에서 영향 범위(현재 적용 중인 지점 수)가 1개 이상이면 [저장] 클릭 시 인라인 확인 다이얼로그 "{개수}개 지점에 즉시 적용됩니다. 계속하시겠습니까?"가 한 번 더 표시됩니다. 영향 범위가 0개면 별도 고지 없이 즉시 저장됩니다. 적용 범위가 변경된 경우 변경 전·후 지점 수가 화살표 형태로 시각화되어 영향 범위가 명확히 인식됩니다.

성공하면 다이얼로그가 닫히고 부모 화면(SCR-H1001)의 정책 세트 카드·테이블이 즉시 갱신되며 변경된 항목이 짧은 하이라이트 애니메이션으로 강조됩니다. 우측 상단에 "정책 세트가 저장되었어요" 성공 토스트가 표시되고, 토스트 내부에 "감사 로그 확인" 보조 액션이 함께 노출됩니다. 영향 범위 지점에는 백그라운드 재적용 배치가 실행되며 진행 상황은 알림 센터(NFR-19)를 통해 운영자에게 전달됩니다.

[시뮬레이션 실행] 버튼을 누르면 가상 회원 데이터(이용권 만료일 임의 설정)에 현재 입력된 정책을 적용해 스텝 발송 타이밍을 미리보기로 표시합니다. 결과는 다이얼로그 내 임시 패널로 렌더되며 DB에는 저장되지 않습니다. 시뮬레이션 결과를 확인한 후 운영자가 [저장]을 눌러 실제 적용하거나 입력값을 추가 조정할 수 있습니다.

[취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 입력 도중인 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인 yes/no가 한 번 더 표시됩니다. 확정 시 변경 없이 다이얼로그가 닫히고 부모 화면이 그대로 유지됩니다.

## 6. 예외 처리

저장 트랜잭션 실패 시 모달이 닫히지 않고 "저장에 실패했습니다. 다시 시도해주세요" 토스트가 표시되며 입력값이 유지됩니다. 자동 재시도 1회 후 실패 시 사용자 액션을 기다리며, 트랜잭션은 전체 롤백되어 부분 저장은 발생하지 않습니다.

정책명 중복(전사 unique 위반)은 인라인 오류 "이미 사용 중인 정책명이에요"로 표시되고 [저장] 버튼이 비활성화됩니다. 복제 모드에서는 "(복제)" 접미사가 자동 부여되지만 동일 접미사 정책이 이미 존재하면 새 이름을 직접 입력해야 합니다.

스텝 0개 저장 시도는 인라인 오류 "스텝을 최소 1개 이상 추가해주세요"로 차단됩니다. 동일 기준일 스텝은 경고 배너로 표시되지만 강제 저장은 허용됩니다. 필수 스텝 삭제 시도는 인라인 오류로 차단됩니다.

다른 운영자가 같은 정책 세트를 동시 편집한 경우 optimistic lock 위반이 발생하며 "다른 운영자가 동시에 편집했어요" 모달이 표시됩니다. 모달에는 변경 전·후 비교 카드가 함께 표시되어 사용자가 자신의 변경과 다른 운영자의 변경을 비교한 뒤 새로고침 또는 강제 저장(주의 안내 후) 중 선택할 수 있습니다.

채널 가용성 검증 실패(테넌트에 비활성 채널 선택)는 경고로 표시되며 저장은 허용됩니다. 다만 실제 발송 시 실패할 가능성이 안내되며, 발송 실패는 본 다이얼로그가 아닌 발송 실패 모니터링(실패율 임계값 30% 초과 시 자동 알림)이 별도 처리합니다.

SET-EXT-01 외부 연동 알림 세트와의 충돌이 감지된 경우(같은 지점에 외부 연동과 본 정책이 모두 적용) 경고 배지 "외부 연동 세트와 충돌"이 표시되며 충돌 상세 패널이 인라인으로 펼쳐집니다. SET-EXT-01이 우선순위를 가지므로 본 정책은 충돌 지점에 적용되지 않음이 명시되며, 운영자는 적용 범위를 조정해 충돌을 해소할 수 있습니다.

기본 정책 중지·삭제 시도는 본 다이얼로그가 아닌 부모 화면의 [중지]·[삭제] 액션에서 차단되며 "기본 정책은 중지·삭제할 수 없습니다. 다른 세트를 기본으로 지정 후 시도해주세요" 안내가 표시됩니다.

영향 범위 재적용 배치가 부분 실패한 경우 정책 저장 자체는 성공한 상태로 유지되지만, 알림 센터에 "재적용 실패 지점 {개수}개" 별도 알림이 발송되며 실패 지점 목록과 수동 재적용 버튼이 제공됩니다.

권한 없는 계정이 직접 API로 저장을 시도하면 백엔드 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다.

## 7. 권한별 처리

본 다이얼로그는 슈퍼관리자(superAdmin)와 본사 최고관리자(primary)에게만 호출 가능합니다. 부모 화면(SCR-H1001) 자체가 superAdmin/primary 외 권한자에게는 접근 차단(403)이므로, 본 다이얼로그도 동일하게 차단됩니다.

Owner(지점장)은 본 다이얼로그를 호출할 수 없으며, 자기 지점의 정책 토글·채널 변경은 별도 화면(SCR-080A 지점 자동화)에서 본사가 허용한 범위 안에서만 가능합니다. 스텝 자체의 추가·삭제·기준일 변경은 본사 권한이므로 owner 권한에서는 차단됩니다.

매니저(manager), FC(fc), 트레이너(trainer), 스태프(staff), 프런트(front), 읽기 전용(readonly)은 부모 화면 자체에 접근할 수 없으므로 본 다이얼로그도 호출할 수 없습니다.

필수 스텝의 필수→선택 변경 권한은 본사 슈퍼관리자(superAdmin)에 한정됩니다. primary는 정책 세트 생성·수정·복제는 가능하지만 필수 스텝의 필수 속성을 선택으로 강등시키는 행위는 차단됩니다. 이는 본사 표준의 무결성을 보장하기 위한 정책이며, primary가 시도하면 "필수→선택 변경은 superAdmin 권한이 필요합니다" 오류가 표시됩니다.

기본 정책 지정 변경 권한은 superAdmin과 primary 모두 가능하지만, 기본 정책의 중지·삭제는 다른 정책을 새 기본으로 지정한 후에만 가능합니다.

권한 부족으로 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 부모 화면 자체가 403으로 차단되어 본 다이얼로그가 호출되지 않습니다. 둘째, primary가 필수→선택 변경을 시도하면 인라인 오류로 차단됩니다. 셋째, 직접 API 호출 우회 시 백엔드 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다.

## 8. 운영 정책 (이 다이얼로그에 연결된 부분)

기준일 step 리스트 구조 정책에 따라 본 다이얼로그는 고정 D-day 대신 본사가 입력한 임의 기준일 step 리스트를 사용합니다. 기준일은 음수(이용권 만료 전 N일)·양수(만료 후 N일)·0(만료 당일) 모두 허용되며, 스텝 저장 시 기준일 오름차순으로 자동 정렬됩니다(같은 기준일은 등록 순 유지). 이는 D-30·D-7·D-1·만료 당일·만료 후 +3·+7 같은 임의 조합을 본사가 자유롭게 운영할 수 있도록 설계된 정책입니다.

기본 정책 세트 정책에 따라 전사에 1개만 지정 가능하며, 신규 지점 등록 시 자동 적용됩니다. 기본 정책은 중지·삭제 불가이며 다른 세트를 기본으로 지정한 후에만 변경할 수 있습니다. 이는 신규 지점 온보딩의 정책 공백을 방지하기 위한 운영 안전 장치입니다.

지점 수정 허용 범위 3단계 정책에 따라 본 다이얼로그에서 스텝별로 ① 스텝별 토글 허용(스텝 ON/OFF 가능) ② 채널만 변경 허용 ③ 변경 불가 중 하나를 독립 설정할 수 있습니다. 이 설정은 지점이 SCR-080A 지점 자동화 화면에서 정책을 커스터마이징할 때 영향을 미치며, "변경 불가"로 설정된 스텝은 지점 측에 잠금 아이콘으로 표시됩니다.

필수 스텝 잠금 정책에 따라 필수(required) 스텝은 지점에서 OFF 토글이 불가능합니다. 필수→선택 변경 권한은 본사 슈퍼관리자(superAdmin)에 한정되며, primary가 시도하면 차단됩니다. 이는 본사 표준의 무결성을 보장하기 위한 정책입니다.

정책 버전 관리 정책에 따라 수정 시 이전 버전 스냅샷이 보존되며 최대 10개 FIFO로 관리됩니다. 11번째 수정 발생 시 가장 오래된 버전 1개가 자동 삭제됩니다. 이전 버전은 부모 화면의 [롤백] 기능에서 선택해 복원할 수 있으며, 롤백 시 현재 정책이 해당 버전으로 즉시 교체되고 영향 지점에 재적용 트리거가 발생합니다.

시뮬레이션 정책에 따라 본 다이얼로그의 [시뮬레이션 실행] 버튼은 가상 회원 데이터에 현재 입력된 정책을 적용해 스텝 발송 타이밍 미리보기를 표시합니다. 실제 발송은 일어나지 않으며 결과는 DB에 저장되지 않습니다. 이는 운영자가 실제 배포 전 정책을 사전 검증하기 위한 안전 장치입니다.

정책 충돌 감지 정책에 따라 동일 지점에 2개 이상의 정책 세트가 겹쳐 적용될 경우 충돌 경고가 본 다이얼로그 저장 시 노출되며, 충돌 해소 전까지 두 번째 정책 적용이 차단됩니다. SET-EXT-01 외부 연동 알림 세트와의 충돌은 SET-EXT-01이 우선순위를 가지며, 본 정책은 충돌 지점에 적용되지 않음이 명시됩니다.

채널 가용성 검증 정책에 따라 스텝 저장 시 선택된 채널(SMS / 카카오 / 앱푸시)이 테넌트에 활성화된 채널인지 자동 검증됩니다. 비활성 채널 선택 시 경고가 표시되며 저장은 허용되되 실제 발송 실패 가능성이 안내됩니다.

채널 다중 선택 정책에 따라 동일 기준일 스텝에 채널을 2개 이상 선택하면 동일 시점에 모든 채널로 발송됩니다. 저장 전 "동일 시점에 {채널 수}개 채널로 발송됩니다" 안내 팝업이 표시되어 운영자가 중복 발송 의도를 명시적으로 확인합니다.

적용 범위 변경 정책에 따라 "전사 → 특정 지점군" 변경 시 기존 전사 적용 지점 중 새 범위 외 지점에는 자동 해제 알림이 발송됩니다. 운영자는 인라인 경고로 사전 인지한 뒤 저장해야 합니다.

복제 정책에 따라 본 다이얼로그를 복제 모드로 호출하면 원본 정책 세트의 모든 스텝과 설정이 복사된 상태로 새 이름 입력만 요구됩니다. 복제 직후 상태는 "중지"로 시작되며, 운영자가 명시적으로 "사용중"으로 변경한 후에만 실제 적용됩니다. 이는 원본을 보존하면서 변형 버전을 안전하게 운영하기 위한 정책입니다.

감사 로그 정책에 따라 정책 세트 생성·수정·복제 모든 이벤트는 SCR-097 감사 로그에 기록됩니다. 기록되는 필드는 `policy_set_id`(정책 세트 ID), `actor_id`(처리 운영자), `action`(CREATE / UPDATE / DUPLICATE), `diff_snapshot`(변경된 필드 전·후 값 스냅샷), `affected_branch_count`(영향 지점 수), `timestamp`이며 비동기 INSERT로 5초 안에 감사 로그 화면에서 조회 가능해야 합니다.

발송 실패 모니터링 정책은 본 다이얼로그가 직접 처리하지 않지만, 정책 저장 후 실제 스텝 발송 실행 단계에서 실패율 임계값(30%)을 초과하면 자동 알림이 발송되고 정책 일시 중단 고려 안내가 제공됩니다.

PDF 내보내기 정책에 따라 정책 세트 전체(스텝 목록 포함)를 PDF로 내보낼 수 있으며 헤더에 생성자·생성일·버전 번호가 자동 삽입됩니다. PDF 내보내기는 본 다이얼로그가 아닌 부모 화면(SCR-H1001)의 [PDF 내보내기] 액션에서 처리됩니다.

## 11. 핵심 디자인 요청사항

다이얼로그는 가로 약 800px 폭의 모달로 스텝 리스트가 누적될 수 있으므로 세로 스크롤이 다이얼로그 내부에서만 발생하고 헤더·푸터는 sticky로 항상 노출됩니다. 헤더에는 모드별 제목과 함께 수정 모드에서 마지막 수정자·수정 시각이 작은 글씨로 표시되어 운영자가 누가 마지막으로 변경했는지 즉시 인식할 수 있어야 합니다.

본문은 기본정보 / 적용 범위 / 스텝 리스트 / 지점 수정 허용 범위의 4단 섹션으로 시각적으로 명확히 분리되며 각 섹션 제목은 작은 헤더로 표시됩니다. 섹션 사이에는 충분한 여백이 확보되어 시선이 자연스럽게 흐릅니다.

기본 정책 체크박스는 별 아이콘과 함께 시각적으로 강조되며, 이미 다른 정책이 기본으로 지정된 경우 체크 시 "현재 기본 정책({기존 정책명})을 대체합니다" 안내가 인라인으로 노랑 배경 카드 형태로 표시됩니다.

적용 범위 라디오의 "특정 지점군"을 선택하면 지점 선택 멀티 체크박스가 슬라이드 다운 애니메이션으로 펼쳐지며, 검색창과 전체 선택·해제 토글이 함께 배치되어 다수 지점 선택의 편의가 보장됩니다. 선택된 지점 수는 우측 상단에 카운터로 강조 표시됩니다.

스텝 리스트 섹션은 본 다이얼로그의 핵심 영역으로, 카드 리스트가 운영자가 가장 자주 보는 영역입니다. 각 스텝 카드에는 기준일이 큰 폰트로 강조 표시되며 음수는 "만료 -7일", 양수는 "만료 +3일", 0은 "만료 당일" 같은 자연어 라벨이 함께 노출되어 의미가 즉시 인식되어야 합니다. 카드 좌측에는 드래그 핸들이 명확히 표시되어 순서 조정이 가능함을 시각적으로 알립니다.

채널 다중 선택 체크박스는 SMS·카카오·앱푸시 아이콘과 함께 표시되어 채널이 즉시 식별되며, 선택된 채널은 강한 색상으로 강조됩니다. 필수/선택 토글은 잠금 아이콘과 함께 표시되어 필수 스텝의 의미가 명확히 드러나야 합니다.

동일 기준일 스텝이 둘 이상이면 해당 카드 위에 노랑 경고 배너가 펼쳐져 시각적으로 즉시 인지됩니다. 채널이 비활성 상태이거나 SET-EXT-01과 충돌하는 경우에도 같은 형태의 경고 배너가 표시되어 운영자가 문제를 사전 발견할 수 있어야 합니다.

지점 수정 허용 범위 섹션은 라디오 그룹으로 명확히 구분되며, 각 옵션 옆에 짧은 정책 설명이 작은 글씨로 따라붙어 운영자의 의사결정을 돕습니다.

[시뮬레이션 실행] 버튼은 [저장] 버튼과 시각적으로 분리되어 보조 액션 색상으로 배치되며, 클릭 시 다이얼로그 하단에 시뮬레이션 결과 패널이 슬라이드 업으로 펼쳐져 가상 회원의 스텝 발송 타이밍이 시각화됩니다. 결과 패널은 닫기 버튼으로 다시 접을 수 있으며 DB에 저장되지 않음이 명시됩니다.

[저장] 버튼은 주 액션 색상(브랜드 컬러)으로, [취소] 버튼은 보조 색상으로 분리되어 시각적 위계가 명확히 드러납니다. 영향 범위 1개 이상의 수정 모드에서는 [저장] 버튼 옆에 작은 안내 아이콘이 나타나 호버 시 "{개수}개 지점에 즉시 적용됩니다" 툴팁이 표시됩니다. 로딩 상태에서는 [저장] 버튼이 스피너로 전환되고 모든 입력 필드가 비활성화되어 사용자가 변경할 수 없게 차단됩니다.

성공 토스트는 우측 상단에 녹색 계열로 5초 표시되며 "감사 로그 확인" 보조 액션이 함께 노출되어 변경 내용을 운영자가 즉시 추적할 수 있어야 합니다. 부모 화면의 정책 세트 카드가 새로 갱신될 때는 짧은 하이라이트 애니메이션으로 변경 사실이 시각적으로 강조됩니다.
