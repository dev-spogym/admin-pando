## 2. 다이얼로그 개요와 호출 트리거

신규 지점 등록 다이얼로그는 본사 슈퍼관리자가 가맹·직영 신규 지점을 시스템에 등록하면서 지점 기본 정보, 운영 시작일, 초기 Owner(지점장), 정책 세트 적용을 한 번에 입력하는 등록 폼입니다. 등록 즉시 본사 표준 정책 세트(HQ-09)가 자동 적용되고, 초기 Owner(지점장)으로 매핑된 직원에게 owner 권한이 부여되며, 운영 시작일이 미래이면 `오픈 예정`으로 시작했다가 도래일에 자동 `운영 중`으로 전환됩니다. 신규 가맹 계약 체결 직후 시스템 등록의 단일 진입점이며, 등록 완료 후 온보딩 대시보드(SCR-096)로의 자연스러운 전이가 제공됩니다.

호출 트리거는 두 가지입니다. 첫 번째는 지점 관리 페이지(SCR-092) 헤더의 [+ 신규 지점 등록] 버튼 클릭이며, 권한이 있는 슈퍼관리자·primary에게만 활성화됩니다. 두 번째는 지점이 0개인 신규 본사가 슈퍼 대시보드(SCR-091)에 진입했을 때 표시되는 [지점 등록] CTA 클릭이며, 이 경로로 들어오면 SCR-092로 이동하면서 본 다이얼로그가 자동으로 열립니다. 본사 라이선스 한도를 초과한 경우 트리거 버튼 자체가 비활성화되고 호버 시 "라이선스 한도 초과" 안내가 표시되어 다이얼로그가 호출되지 않습니다.

## 3. 입력 필드와 UI 구성

다이얼로그는 가로 약 560px 폭의 모달이며 세로 스크롤이 발생할 수 있는 입력 폼 구조를 가집니다. 상단에는 "신규 지점 등록"이라는 제목과 X 닫기 버튼이 있고, 본문에는 입력 필드가 섹션 단위로 묶여 있으며 하단에는 [취소] 버튼과 [등록] 버튼이 우측 정렬로 배치됩니다.

기본 정보 섹션에는 지점명 입력란(필수, 1~50자, 특수문자 일부 허용·이모지 차단), 지점 코드 입력란(필수, 시스템 내부 식별자, 중복 불가, 자동 생성 토글로 BR0001 형태 자동 채움 가능), 대표 연락처 입력란(010-XXXX-XXXX 또는 02-XXXX-XXXX 자동 포맷)이 포함됩니다. 주소 정보 섹션에는 주소 입력란과 [주소 검색] 버튼이 함께 배치되며 다음 우편번호 또는 카카오 주소 API 팝업을 호출해 선택한 주소가 자동 입력되고 위경도가 함께 저장됩니다. 상세 주소 입력란은 별도로 분리되어 동·호수 등을 자유 입력할 수 있습니다.

운영 정보 섹션에는 운영 시작일 캘린더(필수, 과거일 입력 시 경고와 함께 즉시 `운영 중`으로 처리), 초기 Owner(지점장) 검색 드롭다운(필수, 직원관리에서 등록된 직원만 선택 가능, 다른 지점 소속인 경우 이동 확인 모달 트리거), 수용 가능 회원 수 입력란(선택, 숫자만), 지점 관리자 계정 이메일 입력란(필수, 초기 관리자 계정 생성용, 초대 이메일 발송 대상)이 포함됩니다. 정책 적용 섹션에는 본사 표준 정책 세트 자동 적용 체크박스(기본 ON, 본사 정책 미설정 시 비활성화되고 HQ-09 진입 링크 노출)와 정책 세트 선택 드롭다운이 함께 표시됩니다.

[등록] 버튼은 모든 필수 항목이 채워지고 검증을 통과해야 활성화되며, 클릭 시 로딩 상태로 전환되어 중복 클릭이 차단됩니다. [취소] 버튼과 X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작을 트리거하되, 입력 도중인 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인을 한 번 더 묻습니다.

## 4. 검증 규칙

지점명은 필수이며 1~50자 길이 제한이 있고, 괄호·하이픈 같은 일부 특수문자는 허용되지만 이모지는 차단됩니다. 지점 코드는 필수이며 시스템 내 unique 제약을 가지고 자동 생성(BR + 4자리 시퀀스) 또는 수동 입력이 가능하며, 중복 시 인라인으로 "이미 사용 중인 코드입니다" 오류가 표시되고 자동 생성이 권장됩니다. 등록 후 코드 변경은 데이터 무결성 보호를 위해 영구 불가합니다.

연락처는 010-XXXX-XXXX 형식으로 자동 포맷되며, 02-XXXX-XXXX 같은 일반 전화도 허용됩니다. 형식 오류는 인라인 오류로 즉시 표시됩니다. 주소는 [주소 검색] 버튼을 통한 선택만 허용되며, 직접 입력은 허용되지 않습니다. 주소 미선택 시 "주소를 선택해주세요" 인라인 오류가 표시되고 [등록] 버튼이 비활성화됩니다.

운영 시작일은 캘린더로만 입력 가능하며, 과거일 선택 시 경고와 함께 즉시 `운영 중` 상태로 처리됩니다(자동 `오픈 예정` 전환 안 됨). 초기 Owner(지점장)은 필수이며 직원관리(STF)에 등록된 직원 중에서만 선택할 수 있고, 다른 지점 소속 직원을 선택하면 "다른 지점 소속 직원입니다, 이동하시겠습니까?" 확인 모달이 표시됩니다. 미선택 시 "초기 Owner(지점장)은 필수입니다" 인라인 오류가 표시됩니다.

본사 표준 정책 세트가 설정되어 있지 않으면 "본사 표준 정책이 없습니다" 안내와 함께 정책 라이브러리(HQ-09, SCR-H1001) 진입 링크가 인라인으로 노출되고, 정책 자동 적용 체크박스가 비활성화됩니다. 본사 라이선스 한도를 초과한 상태면 [등록] 버튼이 비활성화되고 "라이선스 한도 초과" 안내가 표시되며, 본사 영업팀 문의 안내가 함께 따라옵니다.

## 5. 확인 / 취소 액션

[등록] 버튼을 누르면 다이얼로그가 로딩 상태로 전환되어 주요 버튼이 비활성화되고, 백엔드에 지점 생성 트랜잭션이 전송됩니다. 트랜잭션 내에서 지점 레코드 생성, 본사 표준 정책 세트 자동 복제·적용, 초기 Owner(지점장)에 owner 권한 부여, 기존 Owner(지점장) 권한 회수(다른 지점 소속이었던 경우), 본사 표준 알림 템플릿 활성화, 기본 KPI 목표(0) 설정이 한 번에 수행됩니다.

성공하면 다이얼로그가 닫히고 부모 화면(SCR-092)의 지점 목록 테이블 가장 위에 새 지점 행이 즉시 추가되며, 우측 상단에 "지점이 등록되었어요" 성공 토스트가 표시됩니다. 토스트 내부에는 "온보딩 대시보드로 이동" 보조 액션이 함께 표시되어 운영자가 SCR-096으로 자연스럽게 전이할 수 있습니다. 동시에 지점 관리자 계정 이메일로 초대 이메일이 자동 발송되고, 운영 시작일이 미래이면 상태 배지가 `오픈 예정`(노랑)으로, 과거 또는 오늘이면 `운영 중`(초록)으로 표시됩니다.

[취소] 또는 X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작을 트리거하며, 입력 도중인 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인 yes/no가 한 번 더 표시됩니다. 확정 시 변경 없이 다이얼로그가 닫히고 부모 화면이 그대로 유지됩니다.

## 6. 예외 처리

지점 코드 중복은 인라인 오류 "이미 사용 중인 코드입니다"로 표시되고 자동 생성 권장 안내가 따라옵니다. 지점명·주소·초기 Owner(지점장) 미입력은 각각 해당 필드 인라인 오류로 표시되며 [등록] 버튼이 비활성화됩니다. 초기 Owner(지점장)이 다른 지점 소속이면 확인 모달이 표시되며 [이동] 선택 시 기존 소속에서 회수 후 신규 매핑됩니다.

본사 정책 미설정 상태에서 등록을 시도하면 정책 자동 적용 체크박스가 비활성화되고 HQ-09 진입 안내가 표시됩니다. 운영 시작일을 과거로 입력하면 경고가 표시되고 즉시 `운영 중`으로 처리됩니다. 지점 수 한도 초과 시 [등록] 버튼이 비활성화되며 "라이선스 한도 초과" 안내가 표시됩니다.

트랜잭션 실패 시 모달이 닫히지 않고 "저장에 실패했습니다. 다시 시도해주세요" 토스트가 표시되며 입력값이 유지됩니다. 자동 재시도 1회 후 실패 시 사용자 액션을 기다립니다. 정책 세트 자동 적용이 실패하면 지점은 생성되지만 경고와 함께 수동 적용 안내가 표시되고 HQ-09 진입 링크가 토스트 보조 액션으로 노출됩니다. 주소 검색 API 오류 시 "주소 검색 실패, 다시 시도" 안내가 표시되며 재시도가 가능합니다. 동시 등록 충돌(같은 코드로 동시 시도)은 optimistic lock으로 차단되고 새로고침 후 재시도가 안내됩니다.

## 7. 권한별 처리

본 다이얼로그는 superAdmin와 primary에게만 호출 가능합니다. 부모 화면(SCR-092) 헤더의 [+ 신규 지점 등록] 버튼이 이 권한자에게만 표시되며, 그 외 권한자에게는 hidden 처리됩니다.

Owner(지점장)은 본 다이얼로그를 호출할 수 없으며, 직접 URL이나 콘솔 우회로 다이얼로그가 호출되더라도 백엔드 응답이 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다. 매니저 이하(manager, fc, trainer, staff, front, readonly) 권한자는 부모 화면 자체에 접근할 수 없으므로 본 다이얼로그도 호출할 수 없습니다.

권한 부족으로 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 부모 화면의 호출 버튼이 hidden 처리됩니다. 둘째, 직접 URL 접근으로 다이얼로그까지 도달한 경우에는 백엔드 응답이 403이 되어 "권한이 없어요" 토스트가 표시되고 다이얼로그가 자동 닫힙니다. 셋째, 모든 권한 차단 이벤트는 감사 로그(SCR-097)에 actor_id·attempted_action·timestamp로 기록되어 사후 추적이 가능합니다.

## 8. 운영 정책 (이 다이얼로그에 연결된 부분)

지점 코드 고유성은 시스템 내 unique 제약으로 강제되며, 자동 생성(BR + 4자리 시퀀스) 또는 수동 입력이 가능합니다. 등록 후 코드 변경은 데이터 무결성 보호를 위해 영구 불가하며, 변경이 필요한 경우 신규 등록 후 회원·매출·이용권 데이터 이관 절차를 거쳐야 합니다.

초기 Owner(지점장) 매핑 정책은 직원관리(STF) 등록 직원만 선택 가능하며, 다른 지점 소속 직원을 선택하면 이동 확인 모달이 표시됩니다. 매핑 확정 시 owner 권한이 자동 부여되고 기존 Owner(지점장) 권한은 회수됩니다.

정책 세트 자동 적용 정책은 본사 표준(HQ-09 기본 정책)이 자동으로 복제되어 신규 지점에 적용됩니다. 본사 표준 정책이 설정되어 있지 않으면 자동 적용 체크박스가 비활성화되고 HQ-09 진입 안내가 표시됩니다. 지점별 커스터마이징은 등록 후 SCR-080A 지점 자동화에서 별도로 수행됩니다.

운영 시작일 정책은 캘린더 입력만 허용되며, 미래일 선택 시 `오픈 예정` 상태로 시작했다가 운영 시작일 도래 배치(매일 00:00)가 자동으로 `운영 중`으로 전환합니다. 과거일 입력 시 경고와 함께 즉시 `운영 중`으로 처리됩니다.

라이선스 한도 정책은 본사 라이선스 계약에 따라 최대 등록 가능 지점 수를 제한합니다. 한도 초과 시 [등록] 버튼이 비활성화되고 본사 영업팀 문의가 안내되며, 백엔드에서도 트랜잭션이 차단됩니다.

감사 로그 정책은 모든 지점 등록 이벤트를 SCR-097 감사 로그에 기록합니다. 기록되는 필드는 `actor_id`(등록 운영자), `branch_id`(신규 지점), `action=BRANCH_CREATE`, `before=null`, `after`(지점명·코드·주소·운영 시작일·Owner(지점장)·정책 세트 스냅샷), `timestamp`이며, 5초 안에 감사 로그 화면에서 조회 가능해야 합니다.

신규 지점 등록 직후 자동 트리거는 정책 세트 자동 적용 + 본사 표준 알림 템플릿 활성 + 기본 KPI 목표(0) 설정 + 초기 Owner(지점장) owner 권한 부여 + 지점 관리자 계정 초대 이메일 발송이 한 트랜잭션으로 실행됩니다. 어느 하나라도 실패하면 전체 롤백되어 데이터 일관성이 보장됩니다.

## 11. 핵심 디자인 요청사항

다이얼로그는 가로 약 560px 폭으로 데스크톱과 태블릿에서 모두 적절히 보이도록 설계되며, 입력 폼이 길어지면 세로 스크롤이 다이얼로그 내부에서만 발생하고 헤더와 푸터(버튼 영역)는 sticky로 항상 노출됩니다. 입력 필드는 섹션 단위(기본 정보 / 주소 / 운영 정보 / 정책)로 구분되어 시각적으로 분리되며, 섹션 제목은 작은 헤더로 표시됩니다.

필수 필드는 라벨 옆에 빨강 별표(*)로 표시되고, 인라인 오류는 필드 바로 아래에 빨강 텍스트로 즉시 표시됩니다. 지점 코드의 자동 생성 토글은 입력란 우측에 작은 토글 스위치로 배치되어 운영자가 직접 입력과 자동 생성을 즉시 전환할 수 있어야 합니다. 주소 검색 버튼은 주소 입력란과 한 줄에 배치되며, 검색 후 선택된 주소가 자동 채워지면 입력란이 readonly로 잠기고 [재검색] 버튼만 활성화됩니다.

운영 시작일 캘린더는 오늘 날짜가 강조 표시되고, 과거일 선택 시 캘린더 셀에 노랑 배경으로 경고가 시각화됩니다. 초기 Owner(지점장) 검색 드롭다운은 직원명 검색과 함께 직원의 현재 소속 지점이 작은 회색 글씨로 표시되어 다른 지점 소속 여부를 운영자가 클릭 전에 확인할 수 있어야 합니다.

[등록] 버튼은 주 액션 색상(브랜드 컬러)으로, [취소] 버튼은 보조 색상으로 분리되며 우측 정렬로 배치됩니다. 로딩 상태에서는 [등록] 버튼이 스피너로 전환되고 모든 입력 필드가 비활성화되어 사용자가 변경할 수 없게 차단됩니다. 성공 토스트는 우측 상단에 녹색 계열로 5초 표시되며 "온보딩 대시보드로 이동" 보조 액션이 함께 노출되어 자연스러운 다음 단계 전이가 가능해야 합니다.
