## 2. 다이얼로그 개요와 호출 트리거

지점 비활성화 확인 다이얼로그는 본사 슈퍼관리자가 운영 중인 지점을 `임시휴업` 상태로 전환하기 전에 영향 범위를 안내하고 최종 확인을 받는 파괴적 액션 확인 모달입니다. 비활성화 시 해당 지점의 모든 직원 계정 접근이 차단되고, 회원 앱에서 해당 지점 표시가 중단되며, 진행 중인 예약 처리 방법이 결정되어야 하므로 신중한 확인이 필요한 의사결정 흐름입니다. 임시휴업과 폐점은 별도 의사결정이며, 본 다이얼로그는 임시휴업 전환을 기본 동작으로 다루고 폐점 처리는 별도 흐름에서 호출됩니다.

호출 트리거는 지점 관리 페이지(SCR-092)의 지점 목록 테이블 행 우측 [비활성화] 버튼 클릭입니다. 이 버튼은 superAdmin와 primary에게만 활성화되며, Owner(지점장)에게는 hidden 또는 비활성으로 표시됩니다. 이미 `임시휴업` 또는 `폐점` 상태인 지점에서는 버튼이 다른 동작(재활성화 또는 폐점 처리)으로 바뀌거나 비활성화되어 본 다이얼로그가 호출되지 않습니다.

## 3. 입력 필드와 UI 구성

다이얼로그는 가로 약 480px 폭의 모달이며 세로 콘텐츠가 영향 안내 카드와 입력 필드로 구성됩니다. 상단에는 "지점을 비활성화하시겠습니까?"라는 빨강 계열의 강한 톤 제목과 X 닫기 버튼이 있고, 본문에는 비활성화 대상 지점명·코드, 영향 안내 카드, 비활성화 예정일 선택, 사유 입력이 차례로 배치되며 하단에는 [취소] 버튼과 [비활성화 확인] 버튼이 우측 정렬로 배치됩니다. [비활성화 확인] 버튼은 빨강 계열의 파괴적 액션 색상이 적용됩니다.

대상 지점 표시 영역에는 지점명, 지점 코드, 현재 운영 상태 배지(`운영 중`)가 카드 형태로 정리되어 노출됩니다. 영향 안내 카드에는 정량 데이터가 함께 표시되어 운영자가 영향 범위를 즉시 파악할 수 있습니다. 활성 회원 수(예: "활성 회원 1,234명에 영향"), 진행 중 예약 건수(예: "진행 예약 56건"), 직원 수(예: "직원 12명 접근 차단"), 현재 진행 중인 이용권 수가 카운트와 함께 표시되며, 각 항목 옆에 처리 방법이 한 줄로 안내됩니다(이용권은 자동 홀딩, 직원은 접근 차단, 예약은 처리 방식 선택, 회원 앱에서는 표시 중단).

이용권 자동 홀딩 토글(기본 ON), 진행 예약 처리 방식 라디오(자동 취소 / 유지)가 세부 옵션으로 배치되며, 각 옵션 옆에는 해당 정책에 대한 짧은 설명이 작은 글씨로 따라붙어 운영자의 의사결정을 돕습니다. 비활성화 예정일 라디오는 "즉시 / 날짜 지정" 두 옵션이며, "날짜 지정"을 선택하면 캘린더 입력이 활성화됩니다. 사유 입력 텍스트 영역(최대 200자, 선택)에는 리모델링·휴업 신고·운영 점검 같은 사전 정의된 사유 선택 드롭다운이 함께 노출되어 운영자가 자유 입력 또는 사전 정의 사유를 고를 수 있습니다.

[비활성화 확인] 버튼은 클릭 시 로딩 상태로 전환되어 중복 클릭이 차단됩니다. [취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작을 트리거하며 입력 도중인 경우 즉시 닫히고 변경 없이 부모 화면이 유지됩니다(파괴적 액션이 아직 시작되지 않았기 때문에 추가 확인이 필요 없습니다).

## 4. 검증 규칙

비활성화 대상 지점은 현재 상태가 `운영 중` 또는 `오픈 예정`이어야 합니다. 이미 `임시휴업` 또는 `폐점` 상태이면 호출 자체가 차단되어 본 다이얼로그가 열리지 않습니다. 진행 중 예약 처리 방식은 진행 예약이 1건 이상 존재할 때만 노출되며, 0건일 때는 라디오 영역 자체가 hidden 처리됩니다.

비활성화 예정일을 "날짜 지정"으로 선택한 경우 캘린더 입력이 필수이며 오늘 이후 날짜만 선택할 수 있습니다. 과거 날짜 또는 미선택 시 인라인 오류가 표시되고 [비활성화 확인] 버튼이 비활성화됩니다. "즉시"를 선택한 경우 캘린더 입력은 hidden 처리되며, 확정 즉시 운영 상태가 변경됩니다.

활성 회원이 50명을 초과하는 대규모 지점의 비활성화는 안전 장치로 사용자가 직접 지점명을 텍스트 박스에 정확히 입력해야 [비활성화 확인] 버튼이 활성화됩니다. 이는 실수에 의한 대규모 운영 중단을 방지하기 위한 정책입니다.

## 5. 확인 / 취소 액션

[비활성화 확인] 버튼을 누르면 다이얼로그가 로딩 상태로 전환되어 주요 버튼이 비활성화되고, 백엔드에 지점 비활성화 트랜잭션이 전송됩니다. 트랜잭션 내에서 지점 운영 상태가 `임시휴업`으로 변경되고, 해당 지점 직원 계정의 접근이 차단되며, 회원 앱에서 해당 지점 표시가 중단되고, 이용권 자동 홀딩 토글이 ON이면 진행 중 회원 이용권이 일괄 홀딩 처리됩니다. 진행 예약 처리 방식이 "자동 취소"이면 예약이 일괄 취소되고 회원에게 취소 알림이 발송되며, "유지"이면 예약은 그대로 두되 회원 앱에서는 비활성 지점 표시가 추가됩니다.

성공하면 다이얼로그가 닫히고 부모 화면(SCR-092)의 지점 목록 테이블에서 해당 행의 상태 배지가 즉시 `임시휴업`(주황)으로 변경되며 행 자체가 흐림 처리됩니다. 우측 상단에 "지점이 비활성화되었어요" 성공 토스트가 표시되고, 토스트 내부에 "감사 로그 확인" 보조 액션이 함께 노출되어 SCR-097로 즉시 전이할 수 있습니다. 동시에 영향받는 직원과 관리자에게 알림 센터(NFR-19)를 통해 인앱 알림이 발송됩니다.

[취소], X 닫기, ESC, 배경 클릭은 모두 동일한 취소 동작이며 변경 없이 즉시 닫힙니다. 입력 도중이라도 추가 확인 없이 닫히는 이유는 파괴적 액션이 아직 시작되지 않았고 입력값이 휘발성이기 때문입니다.

## 6. 예외 처리

비활성화 트랜잭션 부분 실패(예: 직원 계정 접근 차단은 성공했지만 이용권 일괄 홀딩이 실패한 경우)는 일관성 보장을 위해 전체 롤백됩니다. 부분 성공 모드는 지원하지 않으며, 다이얼로그가 닫히지 않고 "비활성화에 실패했습니다. 다시 시도해주세요" 토스트가 표시됩니다. 자동 재시도 1회 후 실패 시 사용자 액션을 기다립니다.

진행 예약 처리 방식이 "자동 취소"인 경우 일부 예약의 취소 알림 발송이 실패할 수 있으며, 이는 백그라운드 재시도(최대 3회) 큐로 위임되어 트랜잭션 자체에는 영향을 주지 않습니다. 알림 발송 실패 회원 목록은 별도 리포트로 운영자에게 제공됩니다.

이용권 자동 홀딩 토글이 ON이지만 일부 회원의 이용권 상태가 동시 변경 중(예: 다른 운영자가 환불 처리 중)인 경우 optimistic lock 위반이 발생하며 "다른 운영자가 동시에 편집했어요" 안내 모달이 표시됩니다. 사용자는 최신 데이터를 새로고침한 뒤 다시 시도해야 합니다.

이미 `임시휴업` 또는 `폐점` 상태인 지점에서 본 다이얼로그가 호출되면(예: 부모 화면이 stale 상태) "이미 비활성화된 지점입니다" 안내가 표시되고 다이얼로그가 자동 닫힙니다. 부모 화면은 자동 새로고침으로 최신 상태를 반영합니다.

대상 지점의 활성 회원이 50명을 초과하는데 지점명 입력 검증을 통과하지 않으면 [비활성화 확인] 버튼이 비활성화되며 인라인 오류 "지점명을 정확히 입력해주세요"가 표시됩니다. 권한이 없는 계정이 직접 API를 호출해 비활성화를 시도하면 백엔드 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다.

## 7. 권한별 처리

본 다이얼로그는 superAdmin와 primary에게만 호출 가능합니다. 부모 화면(SCR-092)의 지점 목록 행 [비활성화] 버튼이 이 권한자에게만 활성화되며, 그 외 권한자에게는 hidden 처리됩니다.

Owner(지점장)은 본 다이얼로그를 호출할 수 없으며, 자기 지점이라도 비활성화 권한이 없습니다. 직접 URL이나 콘솔 우회로 다이얼로그가 호출되더라도 백엔드 응답이 403으로 차단되고 감사 로그에 권한 우회 시도가 기록됩니다. 매니저 이하 권한자는 부모 화면 자체에 접근할 수 없으므로 본 다이얼로그도 호출할 수 없습니다.

권한 부족으로 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 부모 화면의 [비활성화] 버튼이 hidden 처리됩니다. 둘째, 직접 URL 접근으로 다이얼로그까지 도달한 경우에는 백엔드 응답이 403이 되어 "권한이 없어요" 토스트가 표시되고 다이얼로그가 자동 닫힙니다. 셋째, 모든 권한 차단 이벤트는 감사 로그(SCR-097)에 actor_id·branch_id·attempted_action·timestamp로 기록되어 사후 추적이 가능합니다.

## 8. 운영 정책 (이 다이얼로그에 연결된 부분)

임시휴업 정책은 진행 중 회원·이용권을 유지하면서 신규 가입·결제·예약만 차단합니다. 이용권 자동 홀딩 토글이 ON이면 진행 중 회원 이용권이 일괄 홀딩되어 만료일이 휴업 기간만큼 자동 연장됩니다. 토글이 OFF면 이용권은 그대로 두되 회원 앱에서는 비활성 지점 표시가 추가됩니다. 휴업 종료 후 정상화 절차는 별도 흐름(재활성화)에서 처리됩니다.

진행 예약 처리 정책은 "자동 취소" 또는 "유지" 중 운영자가 선택합니다. "자동 취소"이면 예약이 일괄 취소되고 회원에게 취소 알림(SMS/카카오/앱푸시)이 발송되며, 환불이 필요한 결제는 별도 환불 흐름으로 위임됩니다. "유지"이면 예약은 그대로 두되 회원 앱에서는 "지점 비활성화 중" 안내가 추가되어 회원이 자체적으로 취소·변경할 수 있도록 안내됩니다.

직원 계정 접근 차단 정책은 비활성화 트랜잭션 직후 즉시 적용됩니다. 해당 지점에 소속된 모든 직원 계정의 권한이 비활성화되며, 직원이 관리자 웹에 로그인하면 "소속 지점이 비활성화되었습니다" 안내와 함께 본사 문의 가이드가 표시됩니다. 직원 계정 자체가 삭제되지는 않으며, 재활성화 시 권한이 자동 복원됩니다.

회원 앱 표시 중단 정책은 비활성화 직후 적용됩니다. 회원 앱의 지점 검색·예약·출석·결제 화면에서 해당 지점이 숨김 처리되며, 회원이 직접 URL이나 즐겨찾기로 접근하더라도 "현재 비활성화된 지점입니다" 안내가 표시됩니다.

비활성화 예정일 정책은 "즉시" 또는 "날짜 지정" 중 선택 가능하며, "날짜 지정"인 경우 지정일 자정 배치로 자동 전환됩니다. 지정일 도래 전까지는 운영 상태가 `운영 중`으로 유지되며, 지정일이 다가오면 D-7·D-3·D-1 시점에 회원과 직원에게 사전 안내 알림이 자동 발송됩니다.

감사 로그 정책은 모든 지점 비활성화 이벤트를 SCR-097 감사 로그에 기록합니다. 기록되는 필드는 `actor_id`(처리 운영자), `branch_id`(대상 지점), `action=BRANCH_DEACTIVATE`, `before`(이전 운영 상태·이용권 홀딩 여부·예약 처리 방식), `after`(임시휴업 상태·적용된 정책), `reason`(입력 사유), `affected_member_count`, `affected_staff_count`, `affected_reservation_count`, `timestamp`이며 5초 안에 감사 로그 화면에서 조회 가능해야 합니다.

대규모 지점 보호 정책은 활성 회원이 50명을 초과하는 지점의 비활성화 시 사용자가 직접 지점명을 입력해야 확인 버튼이 활성화되는 안전 장치로 작동합니다. 이는 실수에 의한 대규모 운영 중단을 방지하기 위한 정책이며, 본사 슈퍼관리자의 의도된 의사결정임을 명시적으로 확인받습니다.

알림 발송 정책은 비활성화 직후 영향받는 직원과 관리자에게 알림 센터(NFR-19)를 통해 인앱 알림을 발송하며, 진행 예약 자동 취소 시 회원에게는 SMS/카카오/앱푸시 다중 채널로 취소 알림이 발송됩니다. 알림 발송 실패는 백그라운드 재시도 큐로 위임되어 최대 3회 재시도됩니다.

폐점 처리는 본 다이얼로그가 아닌 별도 흐름에서 처리됩니다. 폐점은 활성 회원 환불·이관(MBR-ADV-02)이 강제되고 데이터가 6개월 보관 후 아카이브되는 회복 불가능 처리이므로, 임시휴업과는 의사결정 흐름이 분리됩니다.

## 11. 핵심 디자인 요청사항

다이얼로그는 가로 약 480px 폭의 모달로 데스크톱과 태블릿에서 모두 적절히 표시되며, 파괴적 액션임을 명확히 알리기 위해 헤더 영역과 [비활성화 확인] 버튼에 빨강 계열의 강한 톤이 적용됩니다. 헤더 제목은 "지점을 비활성화하시겠습니까?"로 의문문 형태이며, 운영자가 의사결정을 신중히 하도록 유도합니다.

영향 안내 카드는 정량 데이터(활성 회원·진행 예약·직원·이용권 카운트)가 큰 숫자로 강조 표시되어 영향 범위가 즉시 인식됩니다. 각 카운트 옆에는 처리 방법이 한 줄로 따라붙어 운영자가 비활성화 후 어떤 일이 일어나는지 한눈에 파악할 수 있어야 합니다.

이용권 자동 홀딩 토글과 진행 예약 처리 방식 라디오는 카드 하단에 시각적으로 분리되어 배치되며, 각 옵션 옆에는 짧은 정책 설명이 작은 글씨로 따라붙습니다. 비활성화 예정일 라디오에서 "날짜 지정"을 선택하면 캘린더 입력이 자연스럽게 펼쳐지는 슬라이드 다운 애니메이션이 적용되어 폼 변화가 매끄럽게 표현됩니다.

활성 회원 50명 초과 지점의 안전 장치(지점명 입력 검증)는 별도 카드로 강조되며, 입력란 라벨이 빨강 별표(*)와 함께 "확인을 위해 지점명을 정확히 입력해주세요"라는 안내 문구로 명확히 안내됩니다. 입력값이 지점명과 일치하면 [비활성화 확인] 버튼이 시각적으로 활성화되어 운영자가 진행 가능 여부를 즉시 확인할 수 있습니다.

[비활성화 확인] 버튼은 빨강 계열의 파괴적 액션 색상이며, [취소] 버튼은 보조 색상으로 분리되어 시각적 위계가 명확히 드러납니다. 로딩 상태에서는 [비활성화 확인] 버튼이 스피너로 전환되고 모든 입력 필드가 비활성화되어 사용자가 변경할 수 없게 차단됩니다. 성공 토스트는 우측 상단에 녹색 계열로 5초 표시되며 "감사 로그 확인" 보조 액션이 함께 노출되어 비활성화 결과를 운영자가 즉시 추적할 수 있어야 합니다.
