## 2. 화면 개요와 목적

리드 관리 페이지는 아직 회원으로 등록되지 않은 잠재 고객(문의·상담 대상)을 등록하고, 신규·연락완료·상담예정·방문완료·등록완료·미전환·보류의 7단계 상담 파이프라인별 진행 상황을 추적해 회원 전환율을 높이는 마케팅 도메인의 핵심 허브 화면입니다. FC(피트니스 코치)는 본인 담당 리드의 후속 상담을 관리하고, 매니저는 전체 리드 전환율을 모니터링하며, Owner(지점장)은 9종 유입 경로별 ROI를 분석해 마케팅 예산을 배분합니다. 슈퍼관리자(본사)는 통합 모드로 진입해 지점별 전환율을 비교하면서 저전환 지점에 본사 마케팅 지원 여부를 결정합니다.

이 화면이 다루는 운영 흐름은 매우 다양합니다. 매니저는 전화로 들어온 신규 문의를 즉시 등록하고, FC는 통화 후 메모를 작성하면서 카드를 신규에서 연락완료 컬럼으로 드래그해 단계를 변경하며, 상담을 잡으면 후속 예정일을 등록하고, 방문이 끝나면 등록완료로 카드를 이동시켜 회원 마스터를 자동 생성합니다. 미전환이 되면 사유(가격·거리·시간·경쟁·기타)를 입력해 마케팅 전략 반영 근거를 남기고, 보류가 30일을 넘으면 노랑 배지가 자동으로 붙어 재상담 권유 액션이 등록됩니다. 매니저는 외부 광고 대행사가 전달한 `[신규DB]` 엑셀을 업로드해 C/D/E열(경로) + N/R/V열(상담 방식)을 자동 매핑한 뒤 일괄 등록하기도 합니다.

따라서 이 화면은 단순한 리드 테이블이 아니라, 칸반 DnD 단계 변경 / 회원 마스터 자동 전환 / 외부 데이터 매핑 / 보류 회수 자동화 / 권한·상태·정책까지 모두 반영된 마케팅 운영 허브로 동작해야 합니다.

## 3. 진입 경로와 인접 화면

리드 관리 페이지에 진입하는 경로는 다음과 같이 여러 가지가 있고, 각 경로마다 진입 직후 화면의 초기 상태가 조금씩 달라집니다.

첫 번째 경로는 사이드바입니다. 좌측 사이드바의 "마케팅" 메뉴 아래 "리드 관리" 항목을 클릭하면 진입합니다. 이 경우 URL은 단순히 `/leads`가 되고, 화면은 기본 필터 상태(상태 필터: 전체, 뷰: 목록, 정렬: 문의일 내림차순)로 시작합니다.

두 번째 경로는 대시보드 또는 마케팅 홈의 리드 지표 카드 클릭입니다. 대시보드(SCR-101)에서 "이번 달 신규 리드 수", "전환 대기 중 리드 수", "보류 30일 경과 리드 수" 같은 지표 카드를 클릭하면 리드 관리 페이지로 이동하면서, 그 지표에 대응하는 필터가 URL 쿼리 파라미터로 자동 적용된 상태로 진입합니다. 예를 들어 "보류 30일 경과 리드 수" 카드를 누르면 `/leads?status=보류&aged=30d`처럼 30일 이상 보류된 리드만 보이는 상태로 열립니다.

세 번째 경로는 알림 센터(SCR-104)의 리드 관련 알림 클릭입니다. "오늘 후속 예정 리드 N건" 같은 알림은 리드 관리 페이지로 이동하면서 후속 예정일이 오늘인 본인 담당 리드만 필터링됩니다. "보류 30일 경과 리드" 알림은 보류 + 30일 경과 필터가 적용됩니다.

네 번째 경로는 외부 도구에서 공유받은 북마크·딥링크입니다. URL 쿼리 파라미터로 필터·검색·뷰·페이지 상태가 모두 보존되므로, FC가 "이번 주 상담예정 + 본인 담당" 같은 자주 쓰는 필터 조합을 북마크해 두고 매일 같은 URL로 진입할 수 있습니다.

다섯 번째 경로는 회원 목록(SCR-M001)에서 신규 등록 시 "기존 리드 연결" 옵션을 선택했을 때입니다. 회원 등록 화면에서 연락처를 입력하면 동일 연락처 리드 검색이 일어나고, 일치 리드가 있으면 리드 관리 페이지로 잠시 이동해 해당 리드 카드를 선택하게 됩니다.

이 화면에서 다시 빠져나가는 인접 화면으로는, 카드의 등록완료 DnD 시 자동 생성된 회원으로 진입하는 회원 상세(SCR-M004), 회원 마스터 생성 직후 등록 화면으로 안내되는 회원 등록(SCR-M002), 리드 그룹 발송으로 진입하는 메시지 발송(SCR-071), 카드의 담당 FC 이름을 누르면 진입하는 직원 상세(STF-02), 그리고 모든 단계 변경·등록·삭제·회원 전환 이벤트가 기록되는 감사 로그(SCR-097)가 있습니다.

## 4. 레이아웃과 UI 구성

리드 관리 페이지는 위에서 아래로 차곡차곡 쌓이는 세로형 단일 컬럼 레이아웃을 기본으로 합니다. 데스크톱에서는 가로 폭이 충분하므로 우측 상담 상세 패널이 슬라이드 인 될 때 본문 가로폭이 자동으로 축소됩니다. 태블릿에서는 본문 가로폭을 유지하면서 상담 상세 패널이 우측 오버레이로 뜨고, 모바일에서는 카드를 누르면 풀스크린으로 상담 상세가 진입합니다. 화면은 위에서부터 다음 영역들이 순서대로 배치됩니다.

가장 위에는 페이지 헤더가 있습니다. 헤더 좌측에는 "리드 관리"라는 페이지 타이틀과 함께, 현재 조회 중인 지점이 "전체 지점(통합)"인지 특정 지점인지를 알려주는 지점 컨텍스트 배지가 따라옵니다. 헤더 우측에는 "+ 리드 등록" 버튼이 큼지막하게 배치되어 있고, 그 옆에 "엑셀 임포트(신규DB)" 보조 버튼이 있어 외부 광고 대행사가 전달한 `[신규DB]` 엑셀을 업로드할 수 있습니다. 헤더 가장 오른쪽 끝에는 "휴지통 보기" 토글이 있는데, 켜면 30일 이내 soft delete된 리드가 별도 섹션에 표시되고 복구 버튼이 활성화됩니다.

페이지 헤더 바로 아래에는 요약 지표 카드 5개가 가로로 배치됩니다. 첫 번째 카드는 "전체 리드 수"로 등록된 모든 리드의 합계를 보여주며, 클릭 시 상태 필터가 "전체"로 자동 적용됩니다. 두 번째 카드는 "등록 전환 수"로 등록완료 단계에 도달한 리드 카운트이며, 클릭 시 등록완료 필터가 적용됩니다. 세 번째 카드는 "전환율"로 등록완료 ÷ 전체 ×100으로 계산되며, 5분 캐시되어 단계 변경·등록·삭제 시 즉시 무효화·재계산됩니다. 네 번째 카드는 "대기 중"으로 신규 + 연락완료 합계를 보여주며, 후속 상담이 필요한 리드 규모를 한눈에 보여줍니다. 다섯 번째 카드는 "미전환율"로 미전환 ÷ 전체 ×100이며, 이 수치가 평소보다 급등하면 운영자가 유입 경로별 분석으로 이동해 원인을 파악합니다. 본사 통합 모드에서는 모든 카드의 숫자가 전 지점 합산으로 표시되고, 카드 아래 작은 글씨로 "전 지점 합산"이라는 주석이 붙습니다.

요약 카드 바로 아래에는 상태별 분포 카드가 7종 가로로 배치됩니다. 신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류 각각의 카운트가 카드 한 장에 한 상태씩 표시되며, 0건인 상태는 자동으로 숨겨집니다. 각 카드를 누르면 그 상태로 즉시 필터링되어 단계별 후속 액션 검토가 빨라집니다. 보류 카드에는 30일 이상 경과 리드 수가 작게 같이 표시되어 "보류 12명 (30일+ 3명)" 형태로 운영자가 재활성 대상 규모를 즉시 인지하도록 합니다.

그 아래에는 필터 바가 있습니다. 가장 왼쪽에는 통합 검색창이 있고, 리드 이름·연락처·담당 FC를 동시에 OR 조건으로 검색할 수 있습니다. 검색은 입력 후 300ms 디바운스가 적용되어 타이핑이 끝나면 자동으로 결과가 갱신되며, 최소 2자 이상 입력해야 검색이 시작되고 최대 50자까지 입력할 수 있습니다. 검색창 우측에는 상태 필터(7종 다중 선택), 유입경로 필터(간판/인터넷/전단지/추천/SNS/카카오톡/전화문의/방문/기타 9종), 문의 유형 필터(WI 방문/TI 전화문의/체험/일일입장 4종), 후속 예정일 범위(오늘/이번 주/이번 달/지난 기간) 드롭다운이 배치됩니다. 적용된 필터는 검색 바 아래에 칩 형태로 나란히 표시되며, 각 칩의 X 버튼을 누르면 해당 필터만 제거되고 "전체 해제" 링크를 누르면 모든 필터가 한 번에 초기화됩니다.

필터 바 우측 끝에는 뷰 전환 토글이 있습니다. "목록 뷰"와 "칸반 뷰" 두 가지 중 선택할 수 있고, 어느 뷰가 선택되었는지는 URL 쿼리 파라미터 `view`로 반영되어 북마크에도 보존됩니다.

목록 뷰가 선택된 경우, 필터 바 아래에 리드 목록 테이블이 표시됩니다. 테이블의 컬럼은 좌측부터 문의일, 이름, 연락처, 유입경로 배지, 상담 단계 배지, 담당 FC, 후속 예정일, 메모 미리보기, 상담 방식(1차/2차/3차), 행 액션(수정/삭제) 순서로 배치됩니다. 본사 통합 모드가 아닐 때는 "소속 지점" 컬럼이 숨겨집니다. 상담 단계 배지는 7종에 따라 색상이 분기되며, 신규는 파랑, 연락완료는 청록, 상담예정은 보라, 방문완료는 노랑, 등록완료는 녹색, 미전환은 회색, 보류는 주황색으로 표시됩니다. 보류 30일+ 리드는 노랑 테두리가 추가로 둘러집니다. 후속 예정일이 오늘 이전인 미수행 리드는 후속 예정일 셀이 빨갛게 강조되어 운영자가 즉시 인지하도록 합니다. 이름 클릭은 우측 상담 상세 패널을 슬라이드 인 시키고, 담당 FC 이름을 클릭하면 직원 상세(STF-02)로 이동합니다.

칸반 뷰가 선택된 경우, 필터 바 아래에 가로로 7개 컬럼이 펼쳐집니다. 신규·연락완료·상담예정·방문완료·등록완료·미전환·보류 컬럼 각각에 카드 형태로 리드가 쌓이며, 컬럼 헤더에는 상태명과 함께 그 컬럼의 리드 수가 배지로 표시됩니다. 카드에는 이름, 연락처 끝 4자리, 유입경로 아이콘, 후속 예정일(상대 시간 표시), 메모 첫 줄, 담당 FC 이니셜이 담깁니다. 카드를 마우스로 잡고 다른 상태 컬럼으로 드래그앤드롭(DnD)하면 상담 단계가 즉시 변경되고, 변경 이력이 자동 기록됩니다. 등록완료 컬럼으로 드롭하면 "회원으로 전환하시겠습니까?" 확인 모달이 뜨고, 미전환 컬럼으로 드롭하면 미전환 사유 모달(가격/거리/시간/경쟁/기타)이 강제로 나타납니다.

칸반 뷰의 컬럼 비어있음 상태는 "없음"이라는 회색 텍스트로 표시되며, 컬럼 자체는 항상 보입니다. 컬럼별 카드는 후속 예정일이 가까운 순으로 자동 정렬되고, 보류 컬럼만은 보류 일수(오래된 순)로 정렬해 재활성 대상이 위에 오도록 합니다.

테이블 또는 칸반 뷰 우측에는 상담 상세 패널이 슬라이드 인 됩니다. 패널 헤더에는 리드 이름과 연락처, 그리고 우측 상단에 닫기(X) 버튼이 있습니다. 패널 본문에는 메모 영역(작성·수정·삭제 가능, 변경 시 작성자·시각이 함께 기록), 후속 액션 등록 영역(전화/방문/문자 중 선택 + 일시 입력 + 후속 메모), 단계 변경 타임라인(어느 운영자가 언제 어떤 단계에서 어떤 단계로 옮겼는지 시간순 표시), 그리고 패널 하단에는 "회원 상세로 이동"(등록완료된 경우만 활성화), "메시지 발송"(SCR-071로 이동, 이 리드 한 명을 수신자로 자동 채워넣음) 같은 빠른 액션 버튼이 배치됩니다.

페이지 가장 아래에는 페이지네이션 영역이 있습니다(목록 뷰에서만 활성). 좌측에는 페이지당 표시 건수 선택 드롭다운(20·50·100), 가운데에는 페이지 번호 이동 컨트롤, 우측에는 "총 N건" 합계가 표시됩니다. 페이지당 건수와 현재 페이지 번호 모두 URL 쿼리 파라미터로 보존됩니다.

## 5. 뷰 구성과 뷰별 동작

이 화면은 뷰가 두 가지로 분기되어 있고, 운영자의 작업 맥락에 따라 자유롭게 전환됩니다.

목록 뷰는 데이터 검토·검색·필터 결합·세부 컬럼 비교에 적합한 뷰입니다. 후속 예정일이 임박한 리드를 한꺼번에 확인하거나, 특정 유입 경로의 미전환률을 분석하거나, 외부 신규DB로 일괄 임포트된 리드의 상담 방식(대면/유선/부재)을 검토할 때 사용합니다. 컬럼 정렬은 헤더 클릭으로 변경 가능하며, 정렬 상태는 URL에 반영됩니다. 페이지네이션이 활성화되어 있어 수백 건의 리드도 효율적으로 다룰 수 있습니다.

칸반 뷰는 일상 운영에서 가장 자주 쓰이는 뷰입니다. FC가 출근 직후 본인 담당 리드의 상태를 한눈에 보고, 통화 후 카드를 신규에서 연락완료로 옮기고, 방문 후 등록완료로 옮기는 작업이 모두 DnD 한 번으로 끝납니다. 칸반 뷰는 페이지네이션이 없고 컬럼별 무한 스크롤이 적용되어 카드가 많아도 한 화면에서 처리할 수 있습니다.

뷰를 전환해도 검색·필터·정렬 같은 다른 상태는 그대로 유지되고, 뷰가 바뀌면서 데이터 fetch는 새로 일어나지 않습니다(클라이언트 렌더링만 바뀜). 단, 칸반 뷰에서 DnD로 카드를 옮기면 그 즉시 단계가 변경되고 다른 운영자에게도 실시간 반영됩니다(웹소켓 또는 폴링).

## 6. 버튼·아이콘·링크 액션 전체 정의

이 화면에 등장하는 모든 클릭 가능한 요소를 빠짐없이 정의합니다.

요약 지표 카드 5개는 각각 클릭 가능합니다. 전체 리드 수 카드를 누르면 상태 필터가 전체로 자동 변경되고, 등록 전환 수 카드를 누르면 등록완료 필터가, 전환율 카드를 누르면 등록완료 필터가, 대기 중 카드를 누르면 신규 + 연락완료 다중 필터가, 미전환율 카드를 누르면 미전환 필터가 자동 적용됩니다. 어떤 카드를 누르든 페이지는 1페이지로 리셋되고 검색어는 유지됩니다.

상태별 분포 카드 7종도 클릭 가능합니다. 신규 카드를 누르면 상태 필터가 신규로, 보류 카드를 누르면 보류로 자동 적용됩니다. 카드 자체가 액션 트리거이므로 운영자가 상태를 바꿔가며 빠르게 탐색할 수 있습니다.

페이지 헤더의 "+ 리드 등록" 버튼은 DLG-070-001 리드 등록·수정 다이얼로그를 빈 폼 상태로 엽니다. 권한이 없는 계정(트레이너·스태프·readonly)에서는 이 버튼이 아예 보이지 않습니다.

"엑셀 임포트(신규DB)" 버튼은 파일 선택 다이얼로그를 열어 xlsx 파일을 받습니다. 업로드 후 자동으로 C/D/E열(경로·상세경로) + N/R/V열(상담 방식) 매핑 검증이 수행되고, 누락 컬럼이 있으면 "필수 컬럼이 누락되었습니다" 모달이 떠 임포트가 차단됩니다. 성공 시 미리보기 단계 → 확인 클릭 → 일괄 INSERT가 일어나고, 결과가 토스트로 "N건 임포트 완료 / M건 중복 스킵"으로 표시됩니다.

"휴지통 보기" 토글은 켜면 화면 하단에 별도 섹션이 펼쳐지면서 30일 이내 soft delete된 리드가 표시되고, 각 행에 "복구" 버튼이 노출됩니다. 복구 버튼을 누르면 즉시 활성으로 돌아오며 토스트가 표시됩니다. 30일이 경과한 리드는 자동 영구 삭제 배치(매일 04:00)로 사라져 휴지통에도 보이지 않습니다.

리드 목록 테이블의 행 [수정] 버튼은 DLG-070-001을 해당 리드 데이터로 채워서 엽니다. 행 [삭제] 버튼은 DLG-070-002 리드 삭제 확인 다이얼로그를 엽니다. 삭제 권한이 없는 FC 계정에서는 이 버튼이 보이지 않습니다.

이름 클릭은 상담 상세 패널을 슬라이드 인 시키며, 패널이 이미 열려있으면 그 안의 내용을 새 리드 정보로 교체합니다. 담당 FC 이름 클릭은 STF-02 직원 상세로 이동합니다.

칸반 뷰의 카드 DnD는 단계 변경을 즉시 트리거합니다. 등록완료로 드롭하면 "회원으로 전환하시겠습니까?" 확인 모달이 뜨고, 확인을 누르면 회원 마스터(MBR-01)가 자동 생성됩니다. 이때 이름·연락처·유입 경로는 그대로 승계되고, `lead_member_map`에 매핑이 저장됩니다. 회원 등록이 완료된 후 자동으로 회원 등록 화면(SCR-M002)으로 이동할지 여부는 모달에서 옵션으로 선택할 수 있습니다.

미전환으로 드롭하면 미전환 사유 모달이 강제로 뜹니다. 사유 옵션은 가격·거리·시간·경쟁·기타 5종이며, 기타를 선택하면 텍스트 입력 박스가 추가로 노출됩니다. 사유를 입력하지 않으면 단계 변경이 차단되며 카드가 원래 컬럼으로 되돌아갑니다.

등록완료에서 다른 단계로의 회귀 시도(예: 등록완료 → 방문완료)는 일반 운영자에게는 차단됩니다. "이미 회원으로 전환된 리드입니다" 모달이 뜨고 카드가 등록완료 컬럼으로 되돌아갑니다. 슈퍼관리자만 강행 권한이 있어 추가 확인 후 회귀가 가능합니다.

상담 상세 패널의 메모 영역은 자유 텍스트 입력이며, [저장] 버튼으로 보관됩니다. 메모 수정은 작성자 본인 또는 매니저 이상만 가능하며, 수정 시 "최초 작성: X, 최근 수정: Y" 형식으로 작성·수정자 정보가 표시됩니다.

후속 액션 등록 영역은 전화/방문/문자 중 종류 선택 + 일시 입력 + 후속 메모로 구성되며, 등록하면 후속 예정일이 카드와 테이블에 즉시 반영되고 D-1 자동 알림 큐가 등록됩니다.

상담 상세 패널 하단의 "메시지 발송" 버튼은 SCR-071로 이동하면서 이 리드 한 명을 수신자로 자동 채워 넣습니다. "회원 상세로 이동" 버튼은 등록완료된 리드에서만 활성화되어 매핑된 회원의 SCR-M004로 이동합니다.

모든 버튼은 클릭 후 응답이 돌아오기 전까지 자동으로 비활성화되어 더블클릭이나 연타로 인한 중복 요청이 차단됩니다. 칸반 DnD 중에는 다른 사용자의 같은 카드 변경이 optimistic lock으로 잠겨, 충돌 시 "다른 운영자가 변경 중입니다, 새로고침 후 시도" 모달이 표시됩니다.

## 7. 호출되는 모달 동작

이 화면에서 호출되는 모달은 두 가지(DLG-070-001 리드 등록·수정, DLG-070-002 리드 삭제 확인)와 인라인 보조 모달 두 가지(등록완료 회원 전환 확인, 미전환 사유 입력)입니다. 각각 어떤 트리거로 열리고, 어떤 입력을 받고, 확인/취소를 누르면 부모 화면에서 어떤 변화가 일어나는지를 모두 풀어 씁니다.

### 7-1. DLG-070-001 리드 등록·수정 다이얼로그

리드 등록·수정 다이얼로그는 신규 잠재 고객을 등록하거나 기존 리드의 정보를 수정하는 모달입니다. 리드 관리 페이지에서는 두 가지 트리거로 열립니다. 첫 번째는 페이지 헤더의 "+ 리드 등록" 버튼 클릭으로 빈 폼 상태로 열리고, 두 번째는 행의 [수정] 버튼 또는 카드의 더보기 → 수정 클릭으로 기존 리드 데이터가 채워진 상태로 열립니다.

모달 상단에는 신규 등록 시 "리드 등록", 수정 시 "리드 수정"이라는 제목이 표시됩니다. 본문에는 이름(필수, 1~30자), 연락처(010-XXXX-XXXX 자동 포맷, 외국인 +82 허용), 문의 유형(WI 방문 / TI 전화문의 / 체험 / 일일입장 4종 라디오, 기본값 TI), 유입경로 1차(간판/인터넷/홍보물/회원소개/기타 드롭다운), 상세경로 2차(블로그/인스타/당근/지역카페/현수막/전단지/소개자명 등 텍스트 + 자유 입력), 상담 방식(1차/2차/3차 각각 대면/유선/부재 드롭다운), 상태(7종 드롭다운, 기본 신규), 담당 FC(직원 검색 자동완성, 기본 본인), 문의일(날짜 선택기, 기본 오늘), 후속 예정일(날짜 선택기, 오늘 이후만 입력 가능), 메모(textarea, 0~500자) 입력 필드가 있습니다.

저장 시 검증은 다음 순서로 일어납니다. 첫째, 이름 빈 값이거나 30자 초과면 "이름을 입력하세요(1~30자)"가 인라인 표시됩니다. 둘째, 연락처 형식 검증이 일어나며 잘못된 형식이면 "010-XXXX-XXXX 형식으로 입력"이 표시됩니다. 셋째, 같은 연락처의 리드가 이미 있으면 "동일 연락처의 리드가 이미 존재합니다" 모달에 기존 리드 카드가 표시되고 [기존 리드 보기] / [신규 등록 강행] / [취소] 선택을 받습니다. 넷째, 같은 연락처의 회원이 이미 있으면 "이미 회원으로 등록된 번호입니다" 모달에 기존 회원 카드가 표시되고 리드 등록 자체가 차단됩니다(매니저 이상은 정책 옵션에 따라 회원 메모로 변환 옵션 가능). 다섯째, 후속 예정일이 과거면 "후속 예정일은 오늘 이후로 입력해주세요"가 인라인 표시됩니다. 여섯째, 상담 방식이 대면/유선/부재 외 값이면 "잘못된 값입니다"가 표시됩니다.

확인을 누르면 모달이 로딩 상태로 전환되고, 백엔드에 등록 또는 수정 요청이 전송됩니다. 성공 시 모달이 닫히고 부모 화면(리드 관리)의 목록/칸반이 즉시 갱신되며, 우측 상단에 "리드를 등록했어요" 또는 "리드 정보를 수정했어요" 토스트가 표시됩니다. 신규 등록의 경우 새 리드는 신규 컬럼 최상단에 표시되고, 담당 FC에게 알림 센터(NFR-19)로 알림이 발송됩니다. 취소·ESC·배경 클릭은 변경 사항이 있는 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" yes/no 확인을 한 번 더 묻습니다.

권한별 차이는 다음과 같습니다. 슈퍼관리자·Owner(지점장)·매니저는 모든 필드 편집 가능, FC는 본인 담당 리드만 수정 가능(다른 FC 담당 리드는 strict_owner 모드에서 [수정] 버튼 자체가 hidden), 트레이너·스태프·readonly는 진입 차단(모달 호출 전 부모 화면 버튼 자체가 숨김).

### 7-2. DLG-070-002 리드 삭제 확인 다이얼로그

리드 삭제 확인 다이얼로그는 리드를 삭제하기 전에 실수로 인한 데이터 손실을 막기 위해 최종 확인을 받는 모달입니다. 행의 [삭제] 버튼 또는 칸반 카드 우상단 더보기 → 삭제 클릭으로 열립니다.

모달 상단에는 "리드 삭제"라는 제목과 함께 "이 리드를 삭제하시겠습니까?"라는 경고 문구가 표시됩니다. 본문에는 삭제 대상 리드의 이름·연락처·문의일·담당 FC가 요약 카드로 표시되고, 그 아래에 "삭제된 데이터는 30일간 휴지통에 보관됩니다. 30일이 지나면 영구 삭제됩니다"라는 안내가 표시됩니다. 등록완료된 리드는 회원 마스터와 매핑되어 있으므로, 매핑이 있으면 "이 리드는 회원으로 전환되었습니다. 삭제 시 회원과의 매핑만 해제되고 회원 정보는 유지됩니다"라는 추가 경고가 표시됩니다.

확인을 누르면 모달이 로딩 상태로 전환되어 백엔드 soft delete 요청이 전송됩니다. 성공 시 모달이 닫히고 목록/칸반에서 해당 리드가 사라지며 "리드를 삭제했어요" 토스트가 표시됩니다. 30일 휴지통 보관이며 "휴지통 보기" 토글을 통해 복구 가능합니다. 취소를 누르면 모달이 닫히고 아무 변경도 일어나지 않습니다.

권한별 차이는 다음과 같습니다. 슈퍼관리자·Owner(지점장)·매니저만 삭제 가능, FC는 [삭제] 버튼 자체가 hidden, 트레이너·스태프·readonly는 화면 접근 불가.

### 7-3. 등록완료 회원 전환 확인 모달(인라인)

칸반 뷰에서 카드를 등록완료 컬럼으로 DnD하면 자동으로 표시되는 인라인 확인 모달입니다. "회원으로 전환하시겠습니까?"라는 제목과 함께 변환 대상 리드의 이름·연락처·유입 경로가 표시되고, "회원 마스터(MBR-01)가 자동 생성되며 리드↔회원 매핑이 저장됩니다"라는 안내가 따라옵니다. 추가 옵션으로 "회원 등록 화면(SCR-M002)으로 자동 이동" 체크박스가 있어, 체크되어 있으면 전환 완료 후 SCR-M002로 자동 이동해 추가 정보(주소·생년월일·이용권 등)를 마저 입력할 수 있습니다.

확인 → 회원 마스터 자동 생성 → 리드↔회원 매핑 INSERT → 등록 전환수 카운트 +1 → 전환율 자동 재계산 → 감사 로그 기록 → 토스트 "회원으로 전환했어요". 회원 마스터 생성에 실패하면(중복 연락처·시스템 오류 등) 토스트 "회원 등록 실패, 다시 시도해주세요"가 표시되고 단계는 미변경 + 트랜잭션 롤백됩니다. 취소는 카드를 원래 컬럼으로 되돌립니다.

### 7-4. 미전환 사유 입력 모달(인라인)

칸반 뷰에서 카드를 미전환 컬럼으로 DnD하면 강제로 표시되는 인라인 모달입니다. "미전환 사유를 선택해주세요"라는 제목과 함께 가격·거리·시간·경쟁·기타 5종 라디오 버튼이 표시됩니다. 기타를 선택하면 텍스트 입력 박스가 추가로 노출되어 자유 입력을 받습니다.

확인 → 사유와 함께 단계 변경 → 미전환 카운트 +1 → 미전환율 자동 재계산 → 사유별 통계 누적 → 감사 로그 기록. 사유를 입력하지 않으면 확인 버튼이 비활성화되며, 취소를 누르면 카드가 원래 컬럼으로 되돌아갑니다.

## 8. 토스트와 확인 팝업과 알럿

리드 관리 페이지에서 발생하는 모든 알림성 UI는 다음과 같은 패턴으로 동작합니다.

성공 토스트는 우측 상단에 녹색 계열로 5초 동안 표시되며, "리드를 등록했어요", "리드 정보를 수정했어요", "리드를 삭제했어요", "회원으로 전환했어요", "후속 액션을 등록했어요", "N건 임포트 완료" 같은 짧은 문구로 결과를 알려줍니다.

실패 토스트는 우측 상단에 빨강 계열로 표시되며, "데이터를 불러오지 못했어요", "권한이 없어요", "다른 운영자가 변경 중입니다", "회원 등록 실패, 다시 시도해주세요" 같은 문구와 함께 "다시 시도" 같은 보조 액션 버튼이 따라옵니다. 네트워크 오류는 1회 자동 재시도 후 사용자 액션을 기다립니다.

DnD 단계 변경 락 충돌 시에는 토스트가 아닌 모달이 뜹니다. "다른 운영자가 변경 중입니다, 새로고침 후 시도"라는 제목과 함께 "새로고침" 버튼이 있고, 누르면 화면이 다시 데이터를 fetch합니다.

보류 30일 경과 리드는 카드와 행에 노랑 테두리가 자동으로 둘러지고, 카드 우상단에 "보류 30d+" 배지가 작게 표시됩니다. 별도 토스트는 뜨지 않지만, 매일 04:00 보류 감지 배치가 돌면 담당 FC에게 알림 센터로 "보류 30일 경과 리드 N건" 알림이 발송됩니다.

확인 팝업은 별도의 다이얼로그가 아닌 단순한 yes/no 형태입니다. 모달 입력 도중 ESC 또는 배경 클릭으로 닫으려고 할 때 "변경 사항이 사라집니다. 닫으시겠습니까?" yes/no 확인이 뜨고, "전체 해제" 링크로 모든 필터를 초기화할 때는 별도 확인 없이 즉시 초기화됩니다.

알럿은 차단형 안내로, 권한 없는 계정이 직접 URL로 접근했을 때 페이지 본문이 전부 사라지고 "이 화면에 접근할 권한이 없습니다. 3초 후 대시보드로 이동합니다"라는 메시지가 표시된 후 자동 이동합니다.

## 9. 데이터 흐름과 외부 연동

이 화면은 여러 데이터 소스와 외부 연동에 의존합니다. 화면 단위로 어떤 데이터가 어디서 오고 어디로 가는지를 모두 풀어 씁니다.

화면 진입 시점에는 리드 목록 조회 API(`GET /api/leads`)가 호출됩니다. 요청에는 현재 활성화된 뷰, 상태 필터, 유입경로 필터, 문의 유형 필터, 검색어, 페이지 번호, 페이지당 건수, 정렬 기준이 쿼리 파라미터로 들어갑니다. 본사 통합 모드일 때는 `branchId` 파라미터가 빠지거나 `all`로 전달되어 전체 지점의 리드가 합산 조회됩니다. 응답으로는 리드 배열, 총 건수, 페이지 정보, 5개 요약 카드의 카운트, 7개 상태별 분포 카운트가 함께 내려옵니다.

전환율 통계는 `GET /api/leads/conversion-stats`로 별도 조회되며, 5분 캐시가 적용됩니다. 캐시는 단계 변경·등록·삭제 시 무효화되어 즉시 재계산되며, 5분 안에 같은 화면이 여러 번 열려도 같은 통계가 빠르게 표시됩니다.

리드 등록은 `POST /api/leads`, 수정은 `PUT /api/leads/:id`, 삭제는 `DELETE /api/leads/:id`(soft delete)로 처리됩니다. 단계 변경은 `POST /api/leads/:id/stage`로 (from_stage, to_stage, reason?)를 받으며, 응답으로는 변경된 리드의 최신 정보가 반환되어 화면이 즉시 갱신됩니다. 변경 이력은 `lead_stage_history` 테이블에 (lead_id, from_stage, to_stage, actor_id, ts, reason) append-only로 INSERT됩니다.

등록완료 → 회원 전환은 트랜잭션으로 처리됩니다. 리드의 단계가 등록완료로 변경되는 시점에 회원 마스터(MBR-01)가 자동 생성되고, 같은 트랜잭션에서 `lead_member_map`이 INSERT됩니다. 회원 마스터 생성 실패 시 전체 롤백되어 단계는 미변경 상태로 남고, 운영자에게 에러 토스트가 표시됩니다.

후속 액션 등록은 `POST /api/leads/:id/follow-up`으로 (type, scheduled_at, memo)를 받으며, D-1 자동 알림 큐에 등록됩니다. 후속 예정일 -1일 시점에 담당 FC에게 알림 센터로 푸시 알림이 발송됩니다.

외부 신규DB 엑셀 임포트는 별도 webhook 엔드포인트(`POST /api/leads/import`)로 처리됩니다. 클라이언트가 엑셀 파일을 업로드하면 서버에서 C/D/E/N/R/V열 매핑을 자동 검증한 후 일괄 INSERT가 일어납니다. 연락처 중복은 자동 스킵되고, 결과 토스트에 "N건 임포트 완료 / M건 중복 스킵"이 표시됩니다.

상담 단계 변경, 후속 액션 등록, 회원 전환, 등록·수정·삭제는 모두 감사 로그(SCR-097)에 비동기로 INSERT됩니다. 기록되는 필드는 `actor_id`, `lead_id`, `action`, `old_value`, `new_value`, `timestamp`입니다. 감사 로그 INSERT는 작업 결과 응답이 사용자에게 돌아간 후 5초 안에 보장됩니다.

칸반 DnD 변경은 다른 운영자에게 실시간 반영됩니다. 같은 화면을 보는 다른 운영자의 칸반에는 카드가 자동으로 이동하며, 메모와 후속 액션도 실시간으로 업데이트됩니다(WebSocket 또는 5초 폴링).

보류 30일 경과 리드 감지는 매일 04:00 배치(`leads-aged-hold-batch`)가 담당합니다. 보류 상태로 들어간 후 30일이 경과한 리드를 추출해 노랑 배지를 부여하고, 60일 경과 시 자동 미전환 전환 옵션(테넌트 정책 활성 시)을 실행합니다. 담당 FC에게는 알림 센터로 보류 30일+ 리드 N건 알림이 발송됩니다.

휴지통 영구 삭제는 매일 04:00 배치(`leads-trash-purge`)가 담당합니다. soft delete 후 30일이 경과한 리드는 영구 삭제되어 휴지통에서도 사라집니다.

세그먼트 자동 갱신(MBR-EXT-04)은 CRM 리드를 세그먼트 조건으로 사용할 수 있게 해 줍니다. "30일 이상 보류 리드", "추천 경로 리드" 같은 세그먼트가 자동 갱신되어 캠페인(MKT-06) 또는 메시지 발송(MKT-01)에서 수신자로 활용됩니다.

회원 병합(MBR-EXT-01) 시에는 부 계정에 매핑된 리드 이력이 주 계정으로 이관되어, 리드 단계 변경 이력과 메모가 보존됩니다.

화면에서 호출하는 주요 API 엔드포인트는 다음과 같습니다. 리드 목록 조회 `GET /api/leads`, 리드 등록 `POST /api/leads`, 리드 수정 `PUT /api/leads/:id`, 리드 삭제 `DELETE /api/leads/:id`, 단계 변경 `POST /api/leads/:id/stage`, 단계 타임라인 조회 `GET /api/leads/:id/timeline`, 후속 액션 등록 `POST /api/leads/:id/follow-up`, 전환율 통계 조회 `GET /api/leads/conversion-stats`, 외부 신규DB 임포트 `POST /api/leads/import`.

## 10. 화면 상태와 예외 처리

리드 관리 페이지는 다음 상태들을 가질 수 있고, 각 상태마다 사용자에게 보이는 모습이 달라집니다.

로딩 중 상태에서는 테이블/칸반 자리에 행 또는 카드 모양의 스켈레톤이 표시됩니다. 요약 카드 자리에도 숫자 대신 스켈레톤이 표시되며, 헤더의 버튼과 필터 바는 미리 렌더되지만 상호작용은 잠시 막혀 있습니다.

정상 목록 상태는 200 응답과 함께 리드가 한 명 이상 존재할 때 표시되는 가장 일반적인 상태입니다. 목록 또는 칸반에 리드가 채워지고 페이지네이션이 활성화되며, 모든 버튼이 권한에 맞게 활성/비활성으로 동작합니다.

리드 없음 상태는 어떤 필터도 적용되지 않은 상태에서 리드 자체가 0건인 경우입니다. "등록된 리드가 없습니다"라는 안내와 "+ 리드 등록 하기" CTA 버튼이 표시됩니다.

검색 결과 없음 상태는 필터나 검색을 적용한 결과가 0건일 때 표시됩니다. "검색 결과가 없어요"라는 안내와 "필터 초기화" 버튼이 표시됩니다.

칸반 컬럼 비어있음 상태는 특정 상태 컬럼에 리드가 0건인 경우입니다. 컬럼 자체는 유지되고 카드 자리에 "없음" 회색 텍스트가 표시됩니다.

오류 상태는 서버에서 5xx 응답이 오거나 네트워크 타임아웃이 발생했을 때 표시됩니다. 화면 중앙에 큰 에러 아이콘과 "데이터를 불러오지 못했어요" 메시지, "다시 시도" 버튼이 표시되며 자동 재시도가 1회 백그라운드에서 일어납니다.

접근 불가 상태는 권한이 없는 계정(트레이너·스태프·readonly)이 직접 URL로 접근했을 때 표시됩니다. 페이지 본문이 전부 가려지고 "이 화면에 접근할 권한이 없습니다"라는 메시지와 함께 3초 카운트다운이 진행되어 대시보드로 자동 이동합니다.

휴지통 보기 상태는 헤더의 토글이 켜진 상태로, 일반 목록 아래에 별도 섹션이 펼쳐지면서 30일 이내 soft delete된 리드가 표시되고 각 행에 복구 버튼이 노출됩니다.

상담 상세 패널 열림 상태는 리드를 클릭해 우측 패널이 슬라이드 인 된 상태입니다. 본문 가로폭이 약 65%로 축소되면서 우측에 35% 폭의 패널이 표시되며, 패널 내부의 메모·후속 액션·타임라인이 모두 활성화됩니다.

DnD 변경 진행 중 상태에서는 카드에 진행 스피너가 잠시 표시되고, 같은 카드를 다시 잡을 수 없습니다. 변경이 완료되면 카드가 새 컬럼에 자리잡고 스피너가 사라집니다.

예외 케이스별 처리는 다음과 같이 정의됩니다.

네트워크 오류(5xx 또는 timeout)가 발생하면 "데이터를 불러오지 못했어요" 토스트와 다시 시도 버튼이 표시됩니다. 자동 재시도 1회 후 사용자 액션을 기다립니다.

권한 없는 계정 접근 시 접근 제한 화면이 표시되고 대시보드로 자동 이동합니다.

연락처 중복 등록 시도 시 "동일 연락처의 리드가 이미 존재합니다" 모달에 기존 리드 카드가 표시되고 [기존 리드 보기] / [신규 등록 강행] / [취소] 선택을 받습니다.

연락처가 기존 회원과 일치하면 "이미 회원으로 등록된 번호입니다" 모달이 표시되고 신규 리드 등록이 차단됩니다.

등록완료 → 다른 단계 회귀 시도 시 "이미 회원으로 전환된 리드입니다" 모달이 표시되며, 슈퍼관리자만 강행 권한을 갖습니다.

미전환 단계 이동 시 사유를 입력하지 않으면 단계 변경이 차단됩니다.

DnD 동시 변경 충돌 시 optimistic lock으로 후행 변경이 차단되고 "다른 운영자가 변경 중입니다" 모달이 표시됩니다.

외부 신규DB 임포트 시 C/D/E/N/R/V 컬럼이 누락되면 "필수 컬럼이 누락되었습니다" 모달이 표시되며 임포트가 차단됩니다.

상담 방식이 대면/유선/부재 외 값이면 "잘못된 값입니다" 인라인 에러와 함께 저장이 차단됩니다.

후속 예정일이 과거이면 "후속 예정일은 오늘 이후로 입력해주세요" 인라인 에러가 표시됩니다.

FC가 다른 FC 담당 리드를 수정·삭제하려고 하면 strict_owner 모드에서는 버튼이 hidden, branch_open 모드에서는 수정 가능합니다.

회원 전환 시 회원 마스터 생성 실패 시 트랜잭션 전체 롤백 + 단계 미변경 + 에러 토스트 + 운영자 재시도 안내가 표시됩니다.

이름 30자 초과 시 인라인 "30자 이내" 에러가 표시되며 저장 차단.

이모지 입력 시 자동 제거 또는 차단(정책에 따라).

연락처가 010 형식 또는 +82 형식이 아니면 인라인 에러.

휴지통 30일 경과는 자동 영구 삭제되어 복구 불가.

통합 모드에서 다른 지점 리드 수정 시도 시 "해당 지점 권한이 없습니다" 안내가 표시되고 조회만 허용됩니다.

## 11. 권한별 처리

이 화면은 권한에 따라 진입 가능 여부, 보이는 영역, 가능한 액션이 모두 달라집니다. 각 권한별로 어떻게 동작해야 하는지를 빠짐없이 정의합니다.

슈퍼관리자(superAdmin)와 본사 최고관리자(primary)는 모든 기능을 사용할 수 있습니다. 화면 진입에 제약이 없고, 헤더에서 지점 전환 드롭다운이 노출되어 전체 지점(통합)과 개별 지점을 자유롭게 전환할 수 있습니다. 통합 모드에서는 모든 지점의 리드가 합산 조회되고 목록 테이블에 "소속 지점" 컬럼이 자동으로 표시됩니다. 등록·수정·삭제·DnD·외부 임포트·회원 전환·휴지통 복구·등록완료 회귀 강행까지 이 화면의 모든 기능을 사용할 수 있습니다.

Owner(지점장)은 자기가 속한 브랜드의 지점 리드 전체를 조회할 수 있습니다. 본사 통합 모드 토글은 표시되지 않거나 비활성화되며, 자기 지점에 한정해서 작업합니다. 등록·수정·삭제·DnD·외부 임포트·회원 전환·휴지통 복구를 모두 수행할 수 있고, 본사 모드 전용 기능(등록완료 회귀 강행, PII 일시 해제)은 사용할 수 없습니다.

매니저(manager)는 자기 지점의 리드 전체를 조회할 수 있고, 등록·수정·삭제·DnD·외부 임포트·회원 전환·휴지통 복구를 모두 수행할 수 있습니다. 슈퍼관리자만 가능한 기능은 사용할 수 없습니다.

FC(피트니스 코치, fc)는 자기 지점의 전체 리드를 조회할 수 있지만, 기본적으로 자기가 담당하는 리드가 우선 노출됩니다. "담당 리드만 보기" 토글이 추가로 표시되어 본인 담당 리드만 필터링할 수도 있습니다. 등록 가능, 수정은 strict_owner 모드에서는 본인 담당만, branch_open 모드에서는 전체 가능, 삭제는 불가능(버튼 hidden), DnD는 strict_owner 모드에서는 본인 담당만, 외부 임포트는 정책에 따라 가능 또는 불가. 회원 전환은 본인 담당 리드에 한정해서 가능합니다.

트레이너(trainer)와 스태프(staff)는 마케팅 도메인 접근이 차단되어 있어 이 화면 자체에 진입할 수 없습니다. 사이드바에 메뉴가 보이지 않고, 직접 URL 접근 시 접근 제한 화면이 표시되며 대시보드로 자동 이동합니다.

읽기 전용(readonly)도 이 화면 자체에 접근할 수 없습니다.

권한 외에도 운영 모드에 따라 일부 영역이 추가로 보이거나 숨겨집니다. 통합 운영 모드(브랜드 단위)가 활성화된 경우 본사 권한자에 한해 통합 토글이 표시되고, 통합 모드에서만 소속 지점 컬럼이 노출됩니다. 외부 신규DB 임포트는 테넌트 설정에서 활성화된 지점만 사용 가능합니다.

권한이 부족해서 액션이 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 사이드바·헤더의 1차 진입점에서는 메뉴 자체가 숨겨집니다. 둘째, 화면 내부의 버튼은 권한이 부족하면 아예 보이지 않거나(삭제·외부 임포트) 비활성화 상태로 표시됩니다. 셋째, 클릭 가능하지만 권한이 모자란 경우(예: 직접 URL 접근으로 모달까지 도달)에는 백엔드 응답이 403이 되어 "권한이 없어요" 토스트가 표시되고 변경이 적용되지 않습니다. 모든 권한 차단 이벤트는 감사 로그에 기록되어, 사후에 권한 우회 시도를 추적할 수 있게 합니다.

```mermaid
    E --> F

    G -->|200 정상| H[요약 카드 + 상태 분포 + 테이블/칸반]
```

## 13. 에러와 예외 흐름

에러와 예외 상황에서의 분기를 별도 흐름으로 표현합니다.

```mermaid
flowchart TD
    A([액션 트리거]) --> B{서버 응답}
    B -->|5xx / timeout| C[자동 재시도 1회]
    C --> D{재시도 성공?}
    D -->|성공| E[정상 흐름 복귀]
    D -->|실패| F[다시 시도 버튼 + 사용자 대기]

    B -->|409 optimistic lock| I["다른 운영자가 변경 중" 모달]
```

## 14. 핵심 디자인 요청사항

이 화면이 운영자에게 잘 작동하려면 다음 디자인 원칙이 시각적으로 명확히 드러나야 합니다.

상태 배지 7종은 색상과 라벨이 동시에 인식되어야 합니다. 신규는 파랑, 연락완료는 청록, 상담예정은 보라, 방문완료는 노랑, 등록완료는 녹색, 미전환은 회색, 보류는 주황색으로 강하게 구분해 운영자가 멀리서도 컬럼/카드만 보고 단계를 알 수 있어야 합니다. 색맹 운영자를 위해 텍스트 라벨이 색상과 함께 항상 표시됩니다. 보류 30일+는 노랑 테두리가 추가되어 시선을 끕니다.

요약 카드 5개와 상태 분포 카드 7개는 동일 크기·동일 그리드로 배치되며, 카드 안의 숫자는 가장 큰 폰트로, 라벨은 그 아래 작은 글씨로 배치합니다. 카드 호버 시 약간의 그림자와 색상 변화로 클릭 가능함을 알려야 합니다.

칸반 뷰의 컬럼은 가로로 7개가 펼쳐지므로 가로 스크롤이 자연스러워야 하고, 컬럼 헤더는 상단 고정되어 스크롤 시에도 항상 보입니다. 카드 사이는 적절한 간격이 필요하며, DnD 중인 카드는 약간 들린 그림자 효과로 드래그 상태를 시각화합니다. 드롭 영역은 점선 박스로 강조되어 어디로 떨어질지 명확히 보입니다.

목록 뷰의 테이블 가독성이 가장 중요하므로 행 간격은 충분히 넓게, 폰트 크기는 일반 텍스트보다 약간 크게, 컬럼 정렬은 이름·메모는 좌측, 숫자(전환율)는 우측, 상태·유입경로 배지는 중앙 정렬로 통일합니다.

상담 상세 패널은 부드럽게 슬라이드 인 되며, 본문 가로폭이 동시에 축소되는 애니메이션이 함께 일어나야 합니다. 패널 내부는 위에서부터 리드 정보 헤더, 메모, 후속 액션, 타임라인 순으로 배치되며 타임라인은 세로 점선과 함께 단계별 색상 배지가 시간순으로 쌓입니다.

모달은 화면 중앙에 떠 있고, 배경은 반투명 검정으로 덮여 부모 화면이 살짝 보이는 정도로 처리합니다. 모달 내부의 필수 필드는 빨간 별표(*)로 표시되고, 검증 에러는 필드 바로 아래 빨간 텍스트로 인라인 표시됩니다.

모바일에서는 칸반 뷰가 좌우 슬라이드 카드형 컬럼으로 자동 전환되어, 한 번에 한 컬럼만 보이며 좌우 스와이프로 다른 상태 컬럼으로 이동합니다. 목록 뷰는 행이 카드형으로 자동 전환되어, 한 카드에 이름·연락처·상태·유입경로 배지가 함께 표시됩니다.

진행 스피너와 로딩 스켈레톤은 동일한 톤으로 통일하여 운영자가 어떤 영역이 로딩 중인지 직관적으로 파악할 수 있어야 합니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

이 화면은 단순한 UI가 아니라 마케팅 운영의 정책 결정이 그대로 반영된 도구입니다. 다른 문서를 보지 않아도 이 화면을 구현·운영하는 사람이 알아야 할 정책을 모두 풀어 씁니다.

상담 단계는 7종으로 고정됩니다. 신규(아직 첫 접촉 전), 연락완료(1차 연락 완료), 상담예정(상담 일정 확정 또는 진행 중), 방문완료(방문/체험/상담 완료), 등록완료(회원 등록 또는 결제 전환 완료), 미전환(종료된 리드), 보류(추후 재접촉 대상)의 의미는 운영 합의로 고정되어 있으며 임의 추가·삭제가 불가능합니다. 단계가 바뀔 때마다 `lead_stage_history`에 (lead_id, from_stage, to_stage, actor_id, ts, reason) append-only로 INSERT됩니다.

운영기획서 `01_리드_회원_운영기획서.md` 3.1절은 첫 단계를 "신규문의"로 정의하지만 본 화면·기능명세서·DLG-070-001 모달은 모두 "신규"로 표기합니다. 두 표기는 동일 상태를 가리키며 운영기획서의 풀네임을 화면에 노출 시 칸반 컬럼 폭이 좁아 운영 편의상 단축 표기를 채택했습니다. 검색·필터·DnD·감사 로그·API 응답값(`stage` enum) 모두 단축 표기 `신규`를 정본으로 사용하며, 운영기획서의 "신규문의" 표기를 검색해도 동일 상태로 매핑되도록 backend alias가 적용됩니다.

유입 경로는 9종으로 고정됩니다. 간판 / 인터넷 / 전단지 / 추천 / SNS / 카카오톡 / 전화문의 / 방문 / 기타. 등록 시 필수 선택이며, 기타를 선택하면 자유 텍스트 메모로 보충합니다. 등록 완료자의 가입경로 분포는 리드 전체가 아닌 등록완료자 기준으로 별도 집계됩니다.

문의 유형은 4종으로 분리되어 운영됩니다. WI(방문, Walk-In) / TI(전화문의, Telephone Inquiry) / 체험 / 일일입장. 외부 `[신규DB]` C열 매핑 값으로 저장되며 화면 라벨 "방문"은 `WI`, "전화문의"는 `TI`로 매핑됩니다. WI와 TI는 합산하지 않고 2분할 카드 또는 비교 막대로 표시하는 것이 KPI 표시 원칙입니다.

상담 방식은 3종으로 제한됩니다. 대면 / 유선 / 부재. 외부 `[신규DB]` N/R/V열의 1차·2차·3차 상담 방식이며, 이 외 값 입력은 차단됩니다. TI 문의 중 1차·2차·3차 어느 한 곳에라도 대면이 기록되면 그 리드는 TI 방문 전환으로 집계됩니다.

연락처 중복 검증은 두 단계로 일어납니다. 동일 연락처 리드 등록 시 기존 리드 카드 노출 후 신규 등록 여부를 운영자에게 묻고, 기존 회원 번호와 일치하면 신규 리드 등록을 차단합니다. 이미 회원으로 존재하는 전화번호는 신규 리드 생성보다 "기존 회원 연결"을 우선 제안하는 것이 운영 원칙입니다.

등록완료 회원 전환은 단계 변경의 가장 중요한 트랜잭션입니다. 등록완료 단계 진입 시 회원 마스터(MBR-01) 자동 생성 + 리드↔회원 매핑(`lead_member_map`) 저장이 같은 트랜잭션에서 일어나며, 매핑 시점에 이름·연락처·유입 경로가 회원 마스터로 승계됩니다. 회원 전환은 1회만 가능하며, 등록완료에서 다른 단계로 회귀는 일반 운영자에게 차단되고 슈퍼관리자만 강행 가능합니다.

미전환 사유는 필수 입력입니다. 가격·거리·시간·경쟁·기타 5종 중 선택이며, 기타는 텍스트 보충이 필수입니다. 사유는 사유별 통계로 누적되어 마케팅 전략 반영의 근거가 됩니다.

DnD 단계 변경은 optimistic lock으로 동시 변경 충돌을 막습니다. 두 운영자가 같은 카드를 동시에 옮기면 후행 변경이 차단되고 새로고침 안내가 표시됩니다.

전환율과 미전환율은 5분 캐시로 운영됩니다. 등록완료 ÷ 전체 = 전환율, 미전환 ÷ 전체 = 미전환율로 계산되며, 단계 변경·등록·삭제 시 즉시 캐시 무효화 + 재계산됩니다.

FC 가시성은 strict_owner 모드와 branch_open 모드 두 가지로 운영됩니다. strict_owner 모드는 본인 담당 리드만 단계 변경 가능, branch_open 모드는 소속 센터 전체 리드 단계 변경 가능. 두 모드 모두 조회는 소속 센터 전체에 열려 있고, 삭제 권한은 FC에게 없습니다.

삭제 권한은 슈퍼관리자·Owner(지점장)·매니저에 한정됩니다. soft delete 30일 휴지통 보관 후 영구 삭제되며, 휴지통 영구 삭제는 매일 04:00 배치가 담당합니다.

후속 예정일은 오늘 이후만 입력 가능하며, D-1 자동 알림이 담당 FC에게 발송됩니다. 미수행 시 카드에 빨강 표시가 자동으로 붙어 운영자가 즉시 인지하도록 합니다.

보류 30일 경과는 자동 노랑 배지 부여 + 후속 액션 등록 권유 알림이 매일 04:00 배치로 발송됩니다. 60일 경과 시 자동 미전환 전환 옵션은 테넌트 정책으로 활성/비활성 선택할 수 있습니다.

외부 신규DB 임포트는 C/D/E열(경로·상세경로) + N/R/V열(상담 방식) 매핑이 필수입니다. 누락 시 임포트가 차단되고, 연락처 중복은 자동 스킵되며 결과가 토스트로 안내됩니다.

이름 정책은 1~30자, 특수문자 일부 허용(이모지 차단). 연락처 정책은 010-XXXX-XXXX 형식 자동 포맷, 외국인 +82 허용. 메모 정책은 0~500자 자유 텍스트.

감사 로그는 리드 관리에서 발생하는 모든 등록·수정·삭제·단계 변경·후속 액션·회원 전환을 비동기로 기록합니다. 기록되는 필드는 actor_id·lead_id·action·old_value·new_value·timestamp이며, SCR-097 감사 로그 화면에서 5초 안에 조회 가능합니다.

KPI 측정 기준은 운영 정책의 일부로서 이 화면의 요약 카드와 연결됩니다. WI 등록률은 WI 등록완료 수 ÷ WI 전체 리드 수로 측정합니다. TI 등록률은 TI 등록완료 수 ÷ TI 전체 리드 수입니다. TI 방문 전환율은 TI 리드 중 상담 방식에 대면이 기록된 리드 수 ÷ TI 전체 리드 수로 측정합니다. 체험 → 등록 전환율은 체험 리드의 등록완료 수 ÷ 체험 전체 리드 수, 일일입장 → 회원 전환율도 동일 방식으로 측정합니다. 회원소개 유입 비중은 추천 경로 리드와 등록자의 전체 대비 비중, 가입경로 분포는 등록완료자 기준으로 산출합니다.

본사 통합 모드는 본사 권한자(슈퍼관리자·본사 최고관리자)에게만 활성화됩니다. 일반 지점 사용자는 자기 지점 외 리드 데이터에 접근할 수 없으며, 통합 모드에서의 회원 전환은 회원의 실제 `branchId`를 기준으로 등록됩니다.

검색 디바운스 300ms와 최소 2자 / 최대 50자 입력 제한은 검색 부하 분산과 의미 없는 단일 글자 쿼리 차단을 위한 정책입니다.

리드↔회원 매핑은 회원 병합(MBR-EXT-01) 시에도 보존되어, 부 계정에 매핑된 리드 이력이 주 계정으로 이관되며 단계 변경 이력과 메모가 모두 살아남습니다.

이상의 모든 정책은 이 화면을 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다. 정책이 바뀌면 이 문서가 함께 갱신되어야 하며, 코드 변경과 정책 변경은 항상 짝지어 진행됩니다.
