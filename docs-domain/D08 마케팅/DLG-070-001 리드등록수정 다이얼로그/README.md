## 2. 다이얼로그 목적과 사용 맥락

리드 등록/수정 다이얼로그는 신규 잠재 고객(리드)을 등록하거나 기존 리드 정보를 수정하는 모달입니다. 문의 경로·상담 단계·담당 FC를 함께 기록해 체계적인 상담 파이프라인을 구성하며, 외부 광고 대행사가 전달한 `[신규DB]` 엑셀의 컬럼 매핑 표준에 맞춰 데이터를 받습니다. 이 다이얼로그는 SCR-070에서 가장 자주 호출되는 모달이며, 매니저는 신규 전화 문의를 즉시 등록하고 FC는 후속 상담 정보를 보완 입력합니다.

호출 트리거는 세 가지입니다. 첫째, SCR-070 페이지 헤더의 "+ 리드 등록" 버튼은 빈 폼 상태로 다이얼로그를 엽니다. 둘째, 리드 목록 테이블의 행 [수정] 버튼 또는 칸반 카드의 더보기 메뉴 → 수정은 기존 리드 데이터가 채워진 상태로 다이얼로그를 엽니다. 셋째, 회원 등록 화면(SCR-M002)에서 "리드로 분류" 옵션을 선택했을 때도 이 다이얼로그가 호출되어 회원 등록 흐름을 리드 등록으로 전환합니다.

## 3. 입력 필드 전체 정의

다이얼로그 본문의 입력 필드를 빠짐없이 정의합니다.

이름 필드는 필수입니다. 텍스트 입력이며 1~30자 제한이 적용됩니다. 30자 초과 시 인라인 에러 "30자 이내"가 표시되고 저장이 차단됩니다. 이모지는 자동으로 제거되거나 차단됩니다(테넌트 정책). 특수문자 일부는 허용됩니다.

연락처 필드는 필수입니다. 전화번호를 입력하며 010-XXXX-XXXX 형식으로 자동 포맷됩니다. 입력 시 하이픈이 자동 삽입되어 운영자가 숫자만 입력해도 표준 형식으로 변환됩니다. 외국인 회원의 경우 +82 시작 형식이 허용되며, 그 외 형식(011/016/019/지역번호)은 차단됩니다. 잘못된 형식이면 "010-XXXX-XXXX 형식으로 입력" 인라인 에러가 표시됩니다.

문의 유형 필드는 필수입니다. WI(방문) / TI(전화문의) / 체험 / 일일입장 4종 라디오 버튼이며 기본값은 TI(전화문의)입니다. 외부 `[신규DB]` 엑셀의 C열 `경로` 매핑 값이며 화면 라벨 "방문"은 내부 `WI`, "전화문의"는 내부 `TI`로 저장됩니다.

유입경로(1차) 드롭다운은 간판 / 인터넷 / 홍보물 / 회원소개 / 기타 5종입니다. 외부 `[신규DB]` 엑셀의 D열 `상세 경로1` 매핑.

상세경로(2차) 텍스트 입력은 블로그 / 인스타 / 당근 / 지역카페 / 현수막 / 전단지 / 소개자명 등 자유 입력입니다. 외부 `[신규DB]` 엑셀의 E열 `상세 경로2` 매핑. 1차 유입경로를 선택한 후 그에 맞는 추천 옵션이 자동완성으로 나타나며, 자유 입력도 가능합니다.

상담 방식(1차/2차/3차) 드롭다운은 각각 대면 / 유선 / 부재 3종 중 선택합니다. 외부 `[신규DB]` 엑셀의 N열(1차) / R열(2차) / V열(3차) 매핑입니다. 이 3종 외 값이 입력되면 "잘못된 값입니다, 대면/유선/부재 중 선택해주세요" 인라인 에러가 표시되고 저장이 차단됩니다. TI(전화문의) 리드에서 1차/2차/3차 어느 하나라도 `대면`이 기록되면 그 리드는 TI 방문 전환으로 별도 집계됩니다.

상태 드롭다운은 신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류 7종이며 기본값은 신규입니다. 신규 등록 시 보통 신규로 두지만 외부 데이터 임포트나 운영 흐름에 따라 다른 상태로 직접 시작할 수 있습니다.

담당 FC 텍스트 입력은 직원 검색 자동완성 방식입니다. 입력하면 직원 마스터(STF-02)에서 매칭되는 FC 이름이 추천되어 선택할 수 있고, 기본값은 로그인한 운영자 본인(FC 권한인 경우)입니다.

문의일 날짜 선택기는 기본값이 오늘이며 과거 날짜도 입력 가능합니다(외부 신규DB 임포트나 지난 문의 데이터 입력 시 사용).

후속 예정일 날짜 선택기는 다음 상담 또는 연락 예정일을 입력합니다. 오늘 이후만 입력 가능하며 과거 입력 시 "후속 예정일은 오늘 이후로 입력해주세요" 인라인 에러가 표시됩니다.

메모 textarea는 0~500자 자유 입력입니다. 문의 내용·특이사항·운영자 코멘트 등을 자유롭게 기록합니다.

## 4. 검증 흐름과 우선순위

저장 버튼 클릭 시 검증은 다음 순서로 일어납니다.

첫째, 이름이 빈 값이거나 30자를 초과하면 "이름을 입력하세요(1~30자)" 인라인 에러가 표시되고 저장이 차단됩니다.

둘째, 연락처 형식 검증이 일어나며 010-XXXX-XXXX 또는 +82 형식이 아니면 "010-XXXX-XXXX 형식으로 입력" 인라인 에러가 표시됩니다.

셋째, 같은 연락처의 리드가 이미 존재하면 "동일 연락처의 리드가 이미 존재합니다" 모달이 추가로 뜨고 기존 리드 카드가 표시됩니다. 운영자는 [기존 리드 보기] / [신규 등록 강행] / [취소] 중 선택할 수 있습니다.

넷째, 같은 연락처의 회원이 이미 존재하면 "이미 회원으로 등록된 번호입니다" 모달이 뜨고 기존 회원 카드가 표시됩니다. 리드 등록 자체가 차단되며, 매니저 이상 권한자는 정책 옵션에 따라 회원 메모로 변환할 수 있습니다.

다섯째, 후속 예정일이 과거이면 "후속 예정일은 오늘 이후로 입력해주세요" 인라인 에러가 표시됩니다.

여섯째, 상담 방식이 대면/유선/부재 외 값이면 "잘못된 값입니다" 인라인 에러가 표시됩니다.

일곱째, 메모가 500자를 초과하면 "500자 이내" 인라인 에러가 표시됩니다.

모든 검증을 통과하면 저장이 진행되며, 백엔드에 등록(POST) 또는 수정(PUT) 요청이 전송됩니다.

## 5. 저장 흐름과 부모 화면 변화

저장 버튼 클릭 후 모달이 로딩 상태로 전환되어 주요 버튼이 모두 비활성화됩니다(중복 요청 차단). 백엔드 응답을 기다리는 동안 저장 버튼은 스피너로 바뀌고 사용자는 다른 영역을 조작할 수 없습니다.

성공 응답을 받으면 모달이 자동으로 닫히고, 부모 화면(SCR-070 리드 관리)의 목록·칸반이 즉시 갱신됩니다. 우측 상단에 신규 등록의 경우 "리드를 등록했어요" 토스트, 수정의 경우 "리드 정보를 수정했어요" 토스트가 녹색 5초로 표시됩니다.

신규 등록 시에는 새 리드가 신규 컬럼 최상단에 표시되고, 담당 FC에게 알림 센터(NFR-19)로 "신규 리드가 배정되었어요" 알림이 발송됩니다. 본사 통합 모드에서는 해당 지점의 매니저 그룹에도 알림이 발송됩니다.

수정 시에는 변경된 필드가 칸반/목록에 즉시 반영되며, 단계가 변경된 경우 변경 이력(lead_stage_history)이 append-only로 INSERT됩니다.

부분 실패 또는 네트워크 오류 시 모달은 닫히지 않고 입력값은 유지됩니다. 빨강 톤 인라인 에러 또는 토스트로 사유가 안내되며 운영자가 재시도하거나 취소할 수 있습니다. 자동 재시도 1회가 백그라운드에서 일어난 후 사용자 액션을 기다립니다.

취소 버튼·ESC 키·배경 클릭은 변경 사항이 없으면 모달이 즉시 닫히고, 변경 사항이 있는 경우 "변경 사항이 사라집니다. 닫으시겠습니까?" yes/no 확인이 한 번 더 표시됩니다. 운영자가 확인하면 모달이 닫히고 변경은 사라지며, 취소를 선택하면 모달이 유지됩니다.

## 6. 외부 신규DB 데이터 매핑

이 다이얼로그의 입력 필드는 외부 광고 대행사가 전달하는 `[신규DB]` 엑셀의 컬럼과 매핑되어 있어, 매니저가 엑셀을 일괄 임포트할 때도 같은 필드 구조로 자동 등록됩니다.

| 입력 항목 | 외부 컬럼 | 매핑 기준 |
|---|---|---|
| 상태 / 결과 | `[신규DB]` A열 | 등록·관리·실패 매핑 |
| 문의 유형 | `[신규DB]` C열 `경로` | WI=방문, TI=전화문의, 체험, 일일입장 |
| 상세 경로 | `[신규DB]` D/E열 | D열 상세 경로1, E열 상세 경로2 |
| 상담 방식 (1차) | `[신규DB]` N열 | 대면/유선/부재 |
| 상담 방식 (2차) | `[신규DB]` R열 | 대면/유선/부재 |
| 상담 방식 (3차) | `[신규DB]` V열 | 대면/유선/부재 |

엑셀 임포트 시 위 매핑이 자동 적용되며, 매핑 검증 실패 시 "필수 컬럼이 누락되었습니다(C/D/E/N/R/V)" 모달이 표시되고 임포트가 차단됩니다.

수기 입력 시에도 같은 표준이 적용되므로 외부 데이터와 내부 데이터의 정합성이 유지됩니다.

## 7. 권한별 동작

슈퍼관리자·본사 최고관리자는 모든 필드 편집 가능하며 본사 통합 모드에서 다른 지점 리드도 수정할 수 있습니다.

센터장(owner)과 매니저(manager)는 자기 지점 리드의 모든 필드를 편집할 수 있고, 신규 등록 시 담당 FC를 자유롭게 지정할 수 있습니다.

FC(피트니스 코치)는 본인 담당 리드만 수정 가능합니다. strict_owner 모드에서는 다른 FC 담당 리드의 [수정] 버튼이 부모 화면에서 hidden되어 모달 호출 자체가 차단되고, branch_open 모드에서는 모달은 열리지만 담당 FC 변경은 불가합니다. 신규 등록은 가능하며 담당 FC 기본값이 본인으로 자동 설정됩니다.

트레이너·스태프·readonly는 다이얼로그 진입 자체가 차단되며 부모 화면에서 [수정] 및 "+ 리드 등록" 버튼이 hidden 처리됩니다.

권한 부족 상태에서 직접 API 호출이 일어나면 백엔드 응답이 403이 되어 "권한이 없어요" 토스트가 표시되고 변경이 적용되지 않으며, 권한 차단 이벤트가 감사 로그에 기록됩니다.

## 8. 화면 상태

기본 표시 상태에서는 부모 화면에서 선택한 대상의 최신 값을 불러와 표시합니다. 신규 등록은 빈 폼이며 기본값(문의 유형 TI, 상태 신규, 문의일 오늘, 담당 FC 본인 등)이 자동 채워집니다. 수정은 기존 데이터가 모두 채워집니다.

입력/수정 중 상태에서는 필수값 누락·형식 오류·권한 제한이 인라인 메시지로 즉시 표시됩니다. 변경 사항이 감지되면 저장 버튼이 강조 톤으로 활성화되고, 취소·ESC·배경 클릭 시 변경 사항 확인 모달이 뜹니다.

저장/처리 중 상태에서는 주요 버튼이 모두 비활성화되고 저장 버튼이 스피너로 바뀝니다. 중복 요청은 차단되며, 백그라운드 자동 재시도 1회가 일어난 후 사용자 액션을 기다립니다.

완료 상태에서는 모달이 닫히고 부모 화면 데이터가 갱신되며 토스트로 결과가 안내됩니다.

실패 상태에서는 모달이 닫히지 않고 입력값이 유지되며 실패 사유가 인라인 메시지 또는 토스트로 안내됩니다.

연락처 중복(리드) 또는 회원 충돌 상태에서는 별도의 충돌 안내 모달이 추가로 뜨고, 사용자 선택(기존 보기/강행/취소)에 따라 흐름이 분기됩니다.

## 9. 데이터 흐름과 외부 연동

신규 등록은 `POST /api/leads` API로 처리됩니다. 요청 본문에 모든 입력 필드와 함께 actor_id(현재 운영자), branch_id, source(`manual` 또는 `import`)가 포함됩니다.

수정은 `PUT /api/leads/:id` API로 처리됩니다. 변경된 필드만 전송하는 부분 업데이트(PATCH-style)도 지원됩니다.

연락처 중복 검증은 별도 API(`GET /api/leads/check-duplicate?phone=...`)가 저장 직전에 호출되어 동일 연락처 리드와 회원 존재 여부를 확인합니다.

저장 성공 시 감사 로그(SCR-097)에 비동기 INSERT가 일어나며 actor_id, lead_id, action(create/update), old_value, new_value, timestamp가 기록됩니다.

신규 등록 시 담당 FC에게 알림 센터(NFR-19)로 알림이 발송되며, 신규 단계로 자동 분류되어 다른 운영자에게도 칸반 실시간 반영(WebSocket 또는 5초 폴링)됩니다.

세그먼트 자동 갱신(MBR-EXT-04)이 신규 리드 등록 시점에 트리거되어 "신규 추천 리드", "30일 이상 보류 리드" 같은 세그먼트가 자동 업데이트됩니다.

본사 통합 모드에서는 branch_id가 운영자의 소속 지점 또는 슈퍼관리자가 선택한 지점으로 자동 설정됩니다.

## 10. 예외 처리

이름 빈 값 → 인라인 에러 "이름을 입력하세요" + 저장 차단.

이름 30자 초과 → 인라인 에러 "30자 이내" + 차단.

연락처 형식 오류 → 인라인 에러 "010-XXXX-XXXX 형식으로 입력" + 차단.

연락처 중복(리드) → 모달 + 기존 리드 카드 + [기존 보기]/[신규 강행]/[취소] 선택.

연락처 중복(회원) → 모달 + "이미 회원으로 등록된 번호" + 등록 차단(매니저+는 정책에 따라 회원 메모 변환 옵션).

후속 예정일 과거 → 인라인 에러 "오늘 이후로 입력" + 차단.

상담 방식 외 값 → 인라인 에러 "대면/유선/부재 중 선택" + 차단.

메모 500자 초과 → 인라인 에러 "500자 이내" + 차단.

FC가 다른 FC 담당 리드 수정 시도(strict_owner) → 부모 화면 버튼 hidden, 모달 호출 차단.

권한 부족 직접 API 호출 → 403 응답 + "권한이 없어요" 토스트 + 감사 로그.

네트워크 오류 → 자동 재시도 1회 + 다시 시도 안내.

동시 편집 충돌(409 optimistic lock) → "다른 운영자가 변경 중" 모달 + 새로고침 안내.

이모지 입력 → 자동 제거 또는 차단(정책).

엑셀 임포트 시 컬럼 누락 → "필수 컬럼이 누락되었습니다(C/D/E/N/R/V)" + 임포트 차단.

엑셀 임포트 시 중복 연락처 → 자동 스킵 + 결과 토스트 "N건 임포트 / M건 중복 스킵".

## 11. 토스트와 확인 팝업

성공 토스트: "리드를 등록했어요" / "리드 정보를 수정했어요" / "N건 임포트 완료 / M건 중복 스킵"이 우측 상단 녹색 5초.

실패 토스트: "권한이 없어요" / "다른 운영자가 변경 중" / "네트워크 오류, 다시 시도해주세요"가 빨강 톤.

확인 팝업: 변경 사항 있는 모달 닫기 시도 시 "변경 사항이 사라집니다. 닫으시겠습니까?" yes/no.

연락처 중복(리드) 모달: 기존 리드 카드 표시 + [기존 보기]/[신규 강행]/[취소] 선택 모달.

연락처 중복(회원) 모달: 기존 회원 카드 표시 + 등록 차단 + [회원 상세 보기] 옵션.

알럿: 권한 없는 직접 URL 접근 시 부모 화면에서 차단 화면.

## 13. 디자인 요청사항

모달은 화면 중앙에 표시되며 배경은 반투명 검정으로 부모 화면이 살짝 보이는 정도로 처리됩니다.

필수 필드는 빨간 별표(*)로 표시되고, 검증 에러는 필드 바로 아래 빨간 텍스트로 인라인 표시됩니다.

연락처 입력 필드는 자동 포맷팅으로 운영자가 숫자만 입력해도 010-XXXX-XXXX 형태로 자동 변환됩니다.

문의 유형 라디오 버튼은 4개가 가로 배치되며, 기본값 TI는 시각적으로 강조됩니다.

유입경로 드롭다운은 1차 선택에 따라 2차 추천 옵션이 자동완성되는 형태로 표시됩니다.

상담 방식(1차/2차/3차)는 3개 드롭다운이 가로로 나란히 배치되어 한 줄에 모두 보입니다.

저장 버튼은 모든 검증이 통과되어 변경 사항이 있을 때만 강조 톤으로 활성화됩니다.

연락처 중복 모달은 기존 리드 카드 또는 회원 카드가 시각적으로 명확히 보여서 운영자가 즉시 인지할 수 있어야 합니다.

모바일에서는 모달이 풀스크린으로 자동 전환되며, 입력 필드가 세로로 스택됩니다.

## 14. 운영 정책 (이 다이얼로그에 연결된 부분)

이름 정책: 1~30자. 이모지 차단. 특수문자 일부 허용.

연락처 정책: 010-XXXX-XXXX 자동 포맷. 외국인 +82 허용. 그 외 형식 차단.

문의 유형 4종: WI(방문) / TI(전화문의) / 체험 / 일일입장. 외부 [신규DB] C열 매핑. 화면 라벨 "방문"=WI, "전화문의"=TI.

유입 경로 9종: 간판 / 인터넷 / 전단지 / 추천 / SNS / 카카오톡 / 전화문의 / 방문 / 기타. 등록 시 필수 선택.

상담 방식 3종: 대면 / 유선 / 부재. 외부 [신규DB] N/R/V열 1차·2차·3차. 외 값 입력 시 차단.

연락처 중복 검증: 동일 연락처 리드 등록 시 기존 카드 노출 후 신규 등록 여부 확인. 기존 회원 번호와 일치 시 신규 리드 등록 차단.

상태 7종 고정: 신규 / 연락완료 / 상담예정 / 방문완료 / 등록완료 / 미전환 / 보류. 단계 변경 이력 자동 기록.

후속 예정일 정책: 오늘 이후만 입력. D-1 자동 알림 발송.

메모 정책: 0~500자 자유 입력.

권한별 가시성: 슈퍼관리자/센터장/매니저 전체 필드 편집. FC 본인 담당만 수정(strict_owner) 또는 전체 수정(branch_open). 트레이너·스태프·readonly 차단.

엑셀 임포트 매핑: A열(상태) / C열(문의 유형) / D/E열(유입·상세) / N/R/V열(상담 방식). 누락 시 차단.

감사 로그: 등록·수정 모두 SCR-097 기록(actor_id, lead_id, action, old_value, new_value, timestamp).

세그먼트 연계: 신규 리드는 세그먼트 자동 갱신 트리거(MBR-EXT-04). "30일 이상 보류 리드", "추천 경로 리드" 등 세그먼트 자동 업데이트.

알림 발송: 신규 리드 등록 시 담당 FC에게 알림 센터(NFR-19) 푸시 + 본사 통합 모드에서는 매니저 그룹 알림.

이상의 모든 정책은 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다.
