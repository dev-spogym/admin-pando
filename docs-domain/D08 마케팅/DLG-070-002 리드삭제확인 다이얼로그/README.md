## 2. 다이얼로그 목적과 사용 맥락

리드 삭제 확인 다이얼로그는 리드를 삭제하기 전에 실수로 인한 데이터 손실을 막기 위해 최종 확인을 받는 모달입니다. 삭제된 리드는 30일간 휴지통에 보관되어 복구할 수 있지만 30일이 지나면 영구 삭제되므로, 운영자가 의도하지 않은 삭제를 막기 위해 위험 확인(Destructive Confirmation) 패턴을 사용합니다.

호출 트리거는 두 가지입니다. SCR-070의 행 [삭제] 버튼 또는 칸반 카드 우상단의 더보기 메뉴 → 삭제. FC 권한 계정에서는 부모 화면에서 [삭제] 버튼 자체가 hidden되어 모달 호출 자체가 차단됩니다.

## 3. 다이얼로그 구성

모달 상단에는 "리드 삭제"라는 제목과 함께 경고 아이콘(예: 휴지통 또는 느낌표)이 표시됩니다.

본문에는 안내 메시지 "이 리드를 삭제하시겠습니까? 삭제된 데이터는 30일간 휴지통에 보관됩니다. 30일이 지나면 영구 삭제됩니다"가 표시됩니다.

대상 리드 요약 카드가 본문 가운데에 표시됩니다. 카드에는 리드 이름, 연락처(마스킹 없이), 문의일, 담당 FC, 현재 상태 배지가 포함되어 운영자가 삭제 대상을 정확히 확인할 수 있습니다.

등록완료된 리드(회원 마스터와 매핑된 경우)는 추가 경고 영역이 표시됩니다. "이 리드는 회원으로 전환되었습니다. 삭제 시 회원과의 매핑만 해제되고 회원 정보는 유지됩니다"라는 안내가 노랑 톤으로 표시되어 운영자가 회원 마스터에는 영향이 없음을 인지하도록 합니다.

모달 하단에는 "삭제" 버튼(빨강 톤 위험 액션)과 "취소" 버튼이 우측 정렬로 배치됩니다. 삭제 버튼은 처음에는 약간 강조되어 있지만, 매니저 이상 권한자는 별도의 추가 확인 없이 클릭만으로 삭제가 진행됩니다.

## 4. 액션과 부모 화면 변화

삭제 버튼 클릭 시 모달이 로딩 상태로 전환되어 두 버튼이 모두 비활성화됩니다. `DELETE /api/leads/:id` API가 호출되어 soft delete가 진행됩니다(`deleted_at` 컬럼에 현재 시각 저장).

성공 응답을 받으면 모달이 자동으로 닫히고, 부모 화면의 목록/칸반에서 해당 리드가 즉시 사라집니다. 우측 상단에 "리드를 삭제했어요" 토스트가 녹색 5초로 표시됩니다.

삭제된 리드는 30일 휴지통에 보관됩니다. SCR-070 헤더의 "휴지통 보기" 토글을 켜면 화면 하단에 별도 섹션이 펼쳐지면서 30일 이내 삭제된 리드가 표시되고, 각 행에 "복구" 버튼이 노출됩니다. 복구 버튼을 누르면 즉시 활성 상태로 돌아오며 "리드를 복구했어요" 토스트가 표시됩니다. 30일 경과 시 자동 영구 삭제 배치(매일 04:00)로 사라져 휴지통에서도 보이지 않습니다.

등록완료된 리드 삭제 시에는 `lead_member_map` 매핑이 함께 해제되지만 회원 마스터 자체는 유지됩니다. 회원 상세(SCR-M004)에서는 "리드 출처 매핑이 해제되었습니다" 정보 알림이 표시됩니다.

취소 버튼·ESC 키·배경 클릭은 즉시 모달을 닫고 아무 변경도 일어나지 않습니다.

## 5. 권한별 동작

superAdmin·primary·Owner(지점장)·매니저는 모달을 호출하고 삭제 액션을 수행할 수 있습니다.

FC는 부모 화면에서 [삭제] 버튼이 hidden되어 모달 호출 자체가 차단됩니다.

트레이너·스태프·readonly는 부모 화면 자체에 접근할 수 없습니다.

권한 부족 상태에서 직접 API 호출이 일어나면 403 응답 + "권한이 없어요" 토스트가 표시되고 감사 로그에 기록됩니다.

## 6. 데이터 흐름과 외부 연동

`DELETE /api/leads/:id`로 soft delete 처리. `deleted_at` 컬럼에 현재 시각 저장.

휴지통 영구 삭제 배치: 매일 04:00에 `deleted_at` + 30일 경과 리드 영구 삭제 + 매핑·이력도 함께 정리.

감사 로그(SCR-097)에 비동기 INSERT: actor_id, lead_id, action(delete), reason(선택, 향후 사유 입력 옵션 추가 가능), timestamp.

등록완료 리드 삭제 시 `lead_member_map` 매핑 해제. 회원 마스터는 유지되며 회원 상세에서 "리드 출처 해제" 알림.

세그먼트 자동 갱신(MBR-EXT-04) 트리거: 삭제된 리드가 속한 세그먼트가 자동 재계산됩니다.

## 7. 예외 처리

권한 부족 → 부모 화면 버튼 hidden + 직접 API 호출 시 403 + 감사 로그.

네트워크 오류 → 자동 재시도 1회 + 실패 시 사용자 다시 시도 안내. 모달은 닫히지 않음.

동시 삭제 시도(409) → "다른 운영자가 이미 처리했어요" 안내 + 모달 자동 닫힘 + 목록 갱신.

이미 삭제된 리드(404) → 모달 자동 닫힘 + "이미 삭제된 리드입니다" 안내.

휴지통 30일 경과 → 자동 영구 삭제로 복구 불가.

회원 마스터 매핑된 리드 삭제 → 매핑만 해제, 회원은 유지.

## 8. 토스트와 확인 팝업

성공: "리드를 삭제했어요" / "리드를 복구했어요" 녹색 5초.

실패: "권한이 없어요" / "이미 삭제된 리드입니다" / "다른 운영자가 이미 처리했어요" / "네트워크 오류, 다시 시도해주세요".

별도 yes/no 추가 확인은 없습니다(모달 자체가 확인 단계). 매니저 이상의 권한자는 두 단계 확인 부담을 줄이기 위해 한 번의 클릭으로 삭제가 진행됩니다.

## 10. 디자인 요청사항

모달은 작은 사이즈로 화면 중앙. 배경 반투명 검정.

제목 옆에 경고 아이콘(빨강 또는 주황) 표시.

대상 리드 요약 카드는 모달 내부에 살짝 강조된 톤으로 표시되어 운영자가 삭제 대상을 정확히 인지하도록 합니다.

등록완료 매핑 추가 경고는 노랑 톤 박스로 본문 아래에 별도 표시.

삭제 버튼은 빨강 톤(위험 액션), 취소 버튼은 회색 톤(기본).

삭제 버튼 클릭 후 로딩 스피너 표시. 두 버튼 모두 비활성화.

모바일에서는 모달이 풀스크린으로 자동 전환.

## 11. 운영 정책

soft delete 30일 휴지통 보관 → 30일 경과 자동 영구 삭제(매일 04:00 배치).

권한: 슈퍼관리자/Owner(지점장)/매니저 가능. FC 버튼 hidden. 트레이너/스태프/readonly 차단.

등록완료된 리드 삭제 시 lead_member_map 해제, 회원 마스터 유지.

감사 로그: 삭제·복구 모두 SCR-097 기록.

세그먼트 자동 갱신(MBR-EXT-04) 트리거: 삭제된 리드 세그먼트 자동 재계산.

동시 처리 충돌은 last-write-wins으로 처리.
