## 2. 다이얼로그 목적과 사용 맥락

수동 적립·차감 다이얼로그는 관리자가 특정 회원의 마일리지를 직접 적립하거나 차감하는 모달입니다. 시스템 오류 보정, 이벤트 지급, 환불 차감, 사은품 차감, 결제 실수 정정 등 예외적인 마일리지 조정 상황에 활용합니다.

운영 시나리오: 회원 보상 10,000점 수동 적립(사은품 추가 보상), 결제 실수 5,000점 차감(결제 취소 정정), 이벤트 참여 보상 3,000점 적립, 시스템 오류로 잘못 적립된 마일리지 차감 보정.

호출 트리거는 SCR-074 행 [수동 조정] 버튼 또는 SCR-M004 회원 상세의 "마일리지 조정" 빠른 액션. FC 권한 계정에서는 버튼 hidden(조회만 가능).

## 3. 다이얼로그 구성

모달 상단에는 "수동 적립·차감" 제목과 닫기(X) 버튼.

대상 회원 정보 카드: 회원 이름, 연락처, 현재 마일리지 잔액이 상단에 표시되어 운영자가 조정 대상 회원과 현재 잔액을 정확히 인지할 수 있게 합니다.

조정 유형 선택 라디오: "적립" / "차감" 2종.

조정 금액 입력: 적립/차감할 마일리지 포인트를 숫자로 입력. 0보다 큰 정수. 0 이하 또는 소수 입력 차단.

조정 후 잔액 미리보기 영역: 입력한 금액에 따라 조정 후 예상 잔액이 실시간으로 표시(예: "현재 50,000점 + 적립 10,000점 = 60,000점" 또는 "현재 50,000점 - 차감 5,000점 = 45,000점").

차감 시 잔액 부족 경고: 차감 금액이 현재 잔액보다 크면 노랑 톤 또는 빨강 톤 경고 "잔액 부족, 현재 잔액 N점" 표시. 마이너스 잔액 허용 정책이 활성이면 진행 가능, 차단 정책이면 저장 차단.

사유 입력 textarea: 필수. 1~200자. 조정 사유를 입력하며 이력에 영구 기록되어 향후 확인용으로 사용됩니다(예: "사은품 추가 보상", "결제 취소 정정", "이벤트 참여 보상").

비고 입력 textarea: 선택. 0~500자. 추가 메모.

모달 하단에는 "확인" 버튼(강조)과 "취소" 버튼.

## 4. 검증과 저장 흐름

저장 검증 순서:

조정 유형 미선택 → 확인 버튼 비활성.

조정 금액 0 이하 또는 소수 → "0보다 큰 정수" 인라인 에러.

사유 미입력 → "사유는 필수입니다" 인라인 에러 + 저장 차단.

사유 200자 초과 → "200자 이내" 인라인 에러.

비고 500자 초과 → "500자 이내" 인라인 에러.

차감 시 잔액 부족 → 정책에 따라 차단 또는 진행. 차단 정책이면 "잔액 부족, 차감 가능 금액 N점" + 저장 차단. 허용 정책이면 경고만 표시.

검증 통과 시 `POST /api/mileage/:memberId/adjust` API → 응답 받아 모달 닫힘 + 부모 화면 갱신 + "마일리지를 조정했어요" 토스트.

`mileage_log`에 append-only INSERT(type[적립/차감], amount, reason, actor_id, ts, source(manual)). 수정·삭제 불가. 보정 필요 시 새 INSERT.

회원앱에 잔액 즉시 동기화(1초 이내). 회원 상세(SCR-M004)의 이력 패널에 새 항목 추가.

취소·ESC·배경 클릭은 변경 사항 있으면 yes/no 확인.

## 5. 권한별 동작

슈퍼관리자·본사: 모든 회원 수동 조정 가능.

센터장·매니저: 소속 지점 회원 수동 조정 가능.

FC: 부모 화면에서 [수동 조정] 버튼 hidden. 다이얼로그 호출 차단. 조회만 가능.

회원 본인: 회원앱에서 잔액·이력 조회만 가능(수동 조정 불가).

트레이너·스태프·readonly: 부모 화면 접근 차단.

## 6. 데이터 흐름

수동 조정 `POST /api/mileage/:memberId/adjust` (type, amount, reason, note).

`mileage_log` INSERT(append-only) + 잔액 갱신.

회원앱 동기화: 잔액 변경 시 회원앱 즉시 반영.

세그먼트 자동 갱신(MBR-EXT-04): 마일리지 잔액 변화로 인한 세그먼트 변동 자동 처리.

소멸 일자 계산: 적립의 경우 적립일 + 소멸 정책(12개월 기본)으로 자동 소멸 일자 설정. FIFO 자동 소멸 배치(매일 04:00)에 포함.

요약 카드 캐시 무효화(5분 캐시).

감사 로그(SCR-097) INSERT: actor_id, member_id, action(adjust), type, amount, reason, timestamp.

## 7. 예외 처리

조정 금액 0 이하/소수 → 인라인 에러.

사유 미입력 → 저장 차단.

사유 200자 초과 → 인라인 에러.

비고 500자 초과 → 인라인 에러.

차감 시 잔액 부족 → 정책에 따라 차단/허용.

권한 부족 → 부모 화면 버튼 hidden + 직접 API 호출 시 403.

동시 조정 충돌(409) → "다른 운영자가 이미 처리했어요" 안내 + 새로고침.

회원 탈퇴 후 조정 시도 → 차단 + "탈퇴 회원은 조정 불가" 안내.

가족 그룹 분리 시점 조정 → 분리 후 개별 잔액으로 처리.

회원 이관 진행 중 조정 → 이관 트랜잭션 잠금 + 잠시 후 재시도 안내.

네트워크 오류 → 자동 재시도 1회 + 사용자 대기.

이미 소멸된 마일리지 차감 시도 → 불가(소멸은 별도 처리).

## 8. 토스트와 확인 팝업

성공: "마일리지를 조정했어요(+10,000점)" 녹색 5초.

실패: "잔액 부족, 차감 가능 금액 N점" / "권한이 없어요" / "사유는 필수입니다" 빨강 톤.

확인 팝업: 큰 금액 조정(예: 100,000점 이상) 시 "큰 금액 조정입니다. 진행하시겠습니까?" 추가 확인 yes/no.

차감 시 잔액 부족(허용 정책) 시 "잔액이 마이너스로 전환됩니다" 노랑 경고 + 확인.

## 10. 디자인 요청사항

대상 회원 정보 카드는 모달 상단에 강조 톤. 현재 잔액이 가장 굵게 표시.

조정 유형 라디오는 적립(녹색 톤)과 차감(빨강 톤)으로 시각적 구분.

조정 후 잔액 미리보기는 실시간 갱신되며 차감으로 마이너스가 되면 빨강 강조.

사유 입력 textarea는 필수 표시(*). 빈 값일 때 인라인 에러.

확인 버튼은 강조 톤. 모든 검증 통과 시에만 활성.

모바일 풀스크린.

## 11. 운영 정책

조정 유형 2종: 적립 / 차감.

조정 금액: 0보다 큰 정수. 0 이하 또는 소수 입력 차단.

사유 필수: 1~200자. 미입력 시 저장 차단. 이력에 영구 기록.

비고 선택: 0~500자.

잔액 부족 정책: 차감 시 잔액 부족 시 차단 또는 마이너스 허용(테넌트 정책).

append-only 이력: 적립·차감·소멸·환불 모두 INSERT only. 수정·삭제 불가. 보정은 새 INSERT.

소멸 일자: 수동 적립도 적립일 + 소멸 정책(12개월 기본)으로 자동 소멸 일자 설정. FIFO 소멸 대상.

회원앱 동기화: 잔액 변경 즉시 회원앱 반영.

권한별: 슈퍼관리자/센터장/매니저 가능. FC/트레이너/스태프/readonly 차단(조회만).

회원 본인 회원앱 조회만 가능.

세그먼트 자동 갱신(MBR-EXT-04) 트리거.

요약 카드 5분 캐시 무효화.

감사 로그: 수동 조정 SCR-097 기록(actor_id, member_id, action(adjust), type, amount, reason).

큰 금액 조정 추가 확인: 100,000점 이상 시 yes/no 한 번 더 확인(테넌트 설정).
