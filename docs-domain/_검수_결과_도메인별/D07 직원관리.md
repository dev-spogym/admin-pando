## 6. 사용자 결정 필요 항목

### 6-1. 직원 등록·수정 권한 정본 결정

- 사용자 요청: "직원 등록·수정 owner 이상"
- 본 도메인 정의: "Owner(지점장)·매니저(manager) 모두 가능" (SCR-061 L228, SCR-060 L222)
- 기능명세서 STF-01 L125·STF-EXT-01 정의: 동일하게 매니저+ 가능
- 운영기획서 05 10절: 본 항목 부재

본 도메인 README는 "매니저+ 가능"을 일관 명시하고 있으므로 검수 단계에서 수정하지 않았습니다. 후보는 다음과 같습니다.

- 후보 A: 사용자 요청 기준으로 SCR-061·SCR-060의 직원 등록·수정 권한을 "owner 이상"으로 상향(매니저는 조회만). 기능명세서·운영기획서도 함께 갱신 필요.
- 후보 B: 현 도메인 정의 유지(매니저+ 가능). 사용자 요청을 운영기획서 10절에 명시 권한 항목으로 추가하는 방식으로 처리.

검수에서는 후보 B를 임시 채택하고 사용자 결정 요청 항목으로 분리했습니다.

### 6-2. 급여 형태 / 정책 템플릿 지급 방식 분류 체계 통합 여부

- 현재 도메인 README는 두 분류 체계를 분리 운영(SCR-061은 "월급/시급/건별/혼합", DLG-064-003은 "정률/고정급/시급/혼합제")하도록 본 검수에서 정렬됨.
- 다만 두 분류가 같은 "급여 형태"라는 용어를 두 차원으로 사용하고 있어 운영자 혼동 가능성이 있음.

- 후보 A: 직원 측 분류와 정책 템플릿 분류를 같은 4종으로 통합. 예: 둘 다 "월급/시급/정률/혼합" 또는 둘 다 "고정급/시급/정률/혼합"으로 정리. 기능명세서 STF-EXT-01·PAY-STF-02 둘 다 갱신 필요.
- 후보 B: 현 분리 유지. 본 검수가 적용한 분리 명시 안내가 운영자 혼동을 방지함.

검수에서는 후보 B를 임시 채택했고 SCR-064 운영 정책 섹션에 두 차원 분리 안내를 보강했습니다.

### 6-3. 근태 기록 타입(출근·퇴근·외출·복귀) v2 도입 여부

- 사용자 요청은 4종 트랜잭션 타입을 검증하라 했으나, 본 시스템 v1은 출근/퇴근 두 시각 필드 + 6종 상태 배지(외근·휴가 포함) 모델로 운영 중.
- 외출/복귀 별도 트랜잭션 타입을 v2에서 도입할지, 또는 별도 모듈(휴가·외근 등록)로 분리 운영을 유지할지 결정 필요.

- 후보 A: v2에서 외출/복귀 트랜잭션 타입을 별도 모델로 도입. PAY-STF-01·SCR-063·DLG-내부 누락 추가에 모두 4종 트랜잭션 타입을 추가.
- 후보 B: 현 v1 모델 유지. 외근은 일별 상태 배지로, 외출/복귀는 별도 트랜잭션 타입 없이 운영. 본 검수가 보강한 v1 범위 명시로 충돌 없음.

검수에서는 후보 B를 임시 채택하고 SCR-063에 v1 범위 명시를 보강했습니다.

### 6-4. 전자계약 5단계 모델 도입 여부

- 사용자 요청은 "전자계약 5단계 연계"이나, 본 시스템 v1은 3단계 흐름(옵션 ON 저장 → 자동 발송 → 직원 서명 → 인사 파일 저장).
- 5단계 모델이 무엇을 의미하는지(예: 1단계 발송 큐 적재, 2단계 이메일 발송, 3단계 카카오 발송, 4단계 직원 서명, 5단계 인사 파일 저장)에 대한 정의가 원천 소스·운영기획서에 부재.

- 후보 A: 5단계 모델을 별도 정의해 STF-EXT-04 전자 근로계약 기능명세서를 신설하고, SCR-061·DLG-내부 발송 확인 모달에 5단계 진행 상태를 시각화.
- 후보 B: 현 3단계 흐름 유지. STF-EXT-04는 STF-EXT-01에 alias로만 부착(본 검수가 보강한 인덱스 매핑 유지).

검수에서는 후보 B를 임시 채택했고 도메인 인덱스에 STF-EXT-04 alias만 명시했습니다.

## 7. 종합 평가

D07 직원관리 도메인 13개 문서는 직원 1명 = 계정 1개 원칙, 권한 분리(매니저 편집 → Owner(지점장) 확정), 근태-급여 자동 연동, 확정 → 명세서 자동 생성 → 무효 처리, 전월 잠금, 5년 보존, 외부 노무 처리 연계, 본인 인사 정보 readonly 접근 같은 핵심 운영 정책이 매우 일관되게 녹아 있습니다. 모달·팝업·토스트 호출 관계도 부모 ↔ 자식 양방향으로 누락 없이 정합합니다.

유일한 의미 있는 카테고리 간 불일치는 "급여 형태" 분류 체계가 두 차원(직원 측 입력 vs 정책 템플릿 지급 방식)을 같은 용어로 혼용한 것이었으며, 본 검수에서 SCR-061·SCR-064·DLG-064-003 사이에 정렬하고 두 차원 분리 안내를 SCR-064 운영 정책 섹션에 보강했습니다. 4개 다이얼로그(DLG-060-001/DLG-061-001/DLG-064-001/DLG-064-003)의 권한 섹션에 9역할 영문 키워드 풀세트를 병기해 권한 매트릭스 표기 일관성도 회복했습니다.

사용자 요청의 "근태 기록 타입 4종(출근·퇴근·외출·복귀)"과 "전자계약 5단계 연계"는 본 시스템 v1 정의와 일치하지 않으나, 검수 단계에서 v1 범위를 명시하고 STF-EXT-04 계약코드 alias를 도메인 인덱스에 보강했습니다. v2 도입 여부는 사용자 결정 요청 항목으로 분리했습니다.

남은 결정 사항은 직원 등록 권한 정본 결정, 급여 형태 분류 통합 여부, 외출/복귀 v2 도입 여부, 전자계약 5단계 모델 도입 여부 4건이며, 모두 본 도메인 검수 범위 밖이므로 사용자 결정 요청 항목으로 분리했습니다.
