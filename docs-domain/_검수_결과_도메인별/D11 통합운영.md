## 1. 카테고리 간 불일치 검수

### 1.1 통합 출석(SCR-I001/IoT-07) vs 출석 관리 설정(D09 SCR-086/SET-EXT-05) 책임 분리

**현황**
- `docs-domain/D09 설정관리/SCR-086`은 `SET-EXT-05` 출석 인정 시간·지각 기준·자동 출석·QR 출석·정정 권한·보관 기간(법정 12개월 이상)을 다루는 "정책 설정 화면"으로 유지됨.
- `docs-domain/D11 통합운영/SCR-I001`은 RSV-04 출결 처리 정본을 다루는 운영 화면.
- 운영용 기획문서 `08_계약코드_정합성_점검.md` 47–53행이 명시한 원칙: "`RSV-04`는 출석/결석/노쇼/지각 처리 운영 기능이므로 D11 통합운영 / IoT-07에만 `contract_codes: [RSV-04]`를 유지한다. `SET-EXT-05`는 alias가 제거되어 SCR-I002 키오스크 설정으로 흡수되었다."

**판정**
- 부분 합치. D11 도메인 README 100행은 "`SET-EXT-05`(출석 설정) alias가 제거되어 SCR-I002 키오스크 설정으로 흡수"라고 명시. 그러나 docs-domain D09에는 여전히 SCR-086 출석 관리 설정 페이지가 SET-EXT-05 코드로 단독 존재.
- D11 SCR-I001에는 "출석 정책의 단일 진입점은 SCR-I002"라고 명시되어 있지만, **SCR-I001의 책임이 "RSV-04 출결 처리 정본"이고 출석 정책의 일부(인정 시간·지각·자동 출석 등)는 D09 SCR-086 또는 SCR-I002로 흡수되었다는 책임 분리 문장이 도메인 README에 명시되어 있지 않음**.
- 위험: 운영자가 동일한 출석 정책 항목(예: 보관 기간·QR 출석 토글·자동 출석)을 SCR-086과 SCR-I002 두 군데에서 찾을 수 있어 단일 진입점 원칙이 흐려짐.

**권고**
- D11 도메인 README "계약코드 매핑" 절(92–100행)에 다음 한 줄을 보강 권고 (직접 보정 §5에서 반영):
  > "출석 정책(인정 시간·지각·자동 출석·QR 출석·정정 권한·보관 기간)은 D09 SCR-086 출석 관리 설정에서 단독 관리하며, 키오스크 단말에서 적용되는 출입 규칙(만료 회원 허용·중복 방지 시간·미수금·영업시간·락커 후처리)은 SCR-I002 키오스크 설정에서 관리한다. D11 통합운영은 두 정책의 적용 결과를 RSV-04 출결 처리 정본으로 적재·운영하는 책임을 갖는다."

### 1.2 키오스크 설정(D09 SCR-082) vs 키오스크 운영 현황(D11 SCR-I008) 분리

**현황**
- `관리자문서_통합_ID대응표.md` 44·47행: `SCR-H904-키오스크IoT설정 → SCR-082A`(D09)이며 `SCR-082 + SCR-082A`를 묶는 운영 허브로 표기. 반면 D11 SCR-I002는 "SCR-082 + SCR-082A를 D11로 통합한 단일 진입점"으로 선언됨.
- `docs-domain/D09 설정관리/SCR-082`는 여전히 `IoT-01` 기능코드로 독립 화면처럼 존재.
- D11 SCR-I008은 IoT-06 운영 모니터링 화면이며, SCR-I002와 명확히 분리됨.

**판정**
- SCR-I002(설정 단일 진입점) ↔ SCR-I008(운영 모니터링) 분리는 D11 도메인 README·SCR-I002·SCR-I003·SCR-I008 모두에서 일관되게 작성됨 (양호).
- 그러나 **D09 SCR-082·SCR-082A 화면이 docs-domain에 그대로 잔존하면서 IoT-01 코드로 별도 화면 취급되어 있음**. 통합 ID 대응표는 D11에서 통합되었다고 명시하므로 D09 화면은 alias/deprecated 표시가 필요. (D09 도메인 검수 범위이므로 본 보고서에서는 권고만 명시)
- SCR-I008과 SCR-I003의 보완 관계도 SCR-I008 README 30행("SCR-I003은 기기 등록·제어 중심, SCR-I008은 운영 모니터링 중심으로 보완 관계")에서 명확히 작성됨.

**권고**
- D11 책임 자체는 일관되어 있어 직접 보정 불필요. D09 검수 단계에서 SCR-082·SCR-082A에 "D11 SCR-I002로 통합됨" 안내를 보강할 것을 잔여 권고로 남김.

### 1.3 IoT 4종(출입·체성분·옷락커·키오스크 부착) 분류

**현황**
- D11 도메인 README 60–62행: "SCR-I003은 **5종 기기**(게이트·키오스크·락커 컨트롤러·InBody·카드 리더)를 동일 데이터 모델로 관리".
- SCR-I003 README 30·66행: 동일하게 5종 표기.
- 원천 기능명세서 `IoT-03-IoT연동관리/00-기본기능.md` 15·29행: "지점에 설치된 IoT 장비(**출입 게이트, 키오스크, 락커 컨트롤러, InBody 측정기**)" 본문에서는 4종으로 작성, 그러나 "기기 5종(게이트 / 키오스크 / 락커 컨트롤러 / InBody / 카드 리더)"이라는 명시도 29행에 등장 — 동일 문서 내에서도 4종/5종이 혼재.
- 검수 항목 텍스트(IoT 4종)는 "출입·체성분·옷락커·키오스크 부착"이라는 기능 카테고리 분류였고, docs-domain의 5종 기기 분류와는 축이 다름.

**판정**
- **4종 vs 5종 혼재**: 검수 항목 텍스트가 말하는 "IoT 4종"은 SCR-I003 탭/카테고리가 아니라 "기능 영역"(출입 게이트 / 체성분 / 옷 락커 / 키오스크 부착 IoT)으로 보임. 도메인 README가 채택한 "5종 기기"(게이트·키오스크·락커 컨트롤러·InBody·카드 리더)는 SCR-I003에서 등록·관리되는 단말 유형의 분류이므로 축이 다름.
- 기능 영역 4종은 다음과 같이 매핑됨:
  - 출입 게이트: SCR-I003 게이트 관리 탭 + IoT 기기 탭(게이트 유형) + 출입 로그 탭
  - 체성분(InBody): SCR-I006 체성분 통합 관리 + IoT 기기 탭(InBody 유형) + EXT-INBODY 채널 3종
  - 옷 락커(컨트롤러): SCR-I004 옷 락커 운영 관리 + IoT 기기 탭(락커 컨트롤러 유형)
  - 키오스크 부착 IoT(KIO-402 양방향, 카드 리더 등): SCR-I002 키오스크 설정 + SCR-I003 IoT 기기 탭(키오스크·카드 리더 유형) + SCR-I008 키오스크 운영 현황
- 도메인 README와 SCR-I003 사이는 5종 기기 분류로 일관되므로 docs-domain 내부에서는 불일치 없음.

**권고**
- 두 축(기능 영역 4종 vs 단말 유형 5종)이 혼동되지 않도록 도메인 README의 "키오스크 연동 매트릭스" 절 위쪽 또는 "도메인 핵심 운영 정책 §3" 안에 4종 기능 영역 매핑을 보강 권고 (직접 보정 §5에서 반영).

## 2. 운영 정책 녹임 적절성

### 2.1 통합 출석 운영 룰 — branchId 기준 분산 저장

- SCR-I001 §8 138행·§11 240행: "본사 통합 모드의 일괄 작업은 회원의 실제 `branchId` 기준으로 분산 저장되어 지점별로 결과가 그루핑됩니다" 명시 (양호).
- SCR-I001 §15 347행: 동일 정책이 운영 정책 절에도 풀어 적힘 (양호).
- DLG-I001 §13 276행: "본사 통합 모드 차단 정책 — 본사 권한자가 통합 모드 상태에서 수동 등록을 시도하면 차단된다 ... 본사 권한자가 지점을 선택하면 그 지점의 owner 권한으로 동작" (양호).

**판정**: branchId 기준 분산 저장 정책이 SCR-I001·DLG-I001 모두에 일관되게 녹아 있음 (양호).

### 2.2 키오스크 모니터링 heartbeat 5분

- SCR-I003 §15 374행: "heartbeat 임계 정책 — 단말 60초 주기 송신, 서버가 5분 초과 미수신 시 자동 오프라인 전환" (양호).
- SCR-I008 §15 339–341행: "OFFLINE 임계값 정책 — heartbeat 미수신 5분 초과 시 자동 오프라인 / 폴링 주기 — 서버 30초 간격 / 단말 송신 60초" (양호).
- SCR-I001 §9 163행: "키오스크 단말 오프라인 감지(SCR-I003 heartbeat 미수신 5분 초과)" — SCR-I003 정책을 정확히 참조.
- SCR-I006 §15 337행: "장비 오프라인 감지 정책 — SCR-I003 heartbeat 결과 사용해 동기화 / 5분 이상 미수신 시 자동 오프라인" (양호).

**판정**: heartbeat 5분 정책이 모든 관련 화면에 일관되게 녹아 있고 정책 원천(SCR-I003)도 명시됨 (양호).

### 4.2 staff·front 출석 처리 한정

- SCR-I001 §11 234행: "스태프(staff)는 자기 지점의 출석 현황을 조회하고 락커 배정과 단일 퇴실 처리까지 수행 가능. 수동 출석 등록은 회원 한정으로 가능하지만 직원 수동 등록은 차단. 일괄 퇴실은 owner·manager 권한 한정."

**불일치 의심**: 검수 항목 텍스트는 "staff·front 출석 처리 한정"이라고 명시. 실제로 DLG-I001은 "staff = 회원 수동 등록만 가능"으로 출석 처리에 접근 가능. SCR-I001은 staff에게 락커 배정과 단일 퇴실 권한 부여. 두 화면 정책이 정합함.

**판정**: staff·front(매니저=프런트) 출석 처리 한정 규칙이 명확히 작성됨. 다만 "프런트" 영문 키워드가 manager와 동일(매니저=manager·프런트)으로 표기되어 별도 영문 키워드(`front`)가 사용되지 않음 — 영문 키워드 보강 필요 (§5에서 처리).

### 보정 1. D11 도메인 README — 출석 정책 책임 분리 및 9역할 영문 키워드 보강

### 보정 2. DLG-I001 §3 진입 경로 4번 제거

SCR-I008과의 양방향 매핑 불일치 해소를 위해 DLG-I001 §3 4번 "SCR-I008 키오스크 운영 현황의 장애 키오스크 카드에서 '수동 출석 보완' 액션" 진입 경로를 보수적으로 제거하고, 동일 흐름은 "SCR-I001 헤더 수동 출석 등록 버튼을 통해" 처리됨을 명시한다.

### 보정 3. DLG-I002 §3 진입 경로 5번 제거

SCR-I004 헤더에 "배정" 버튼이 존재하지 않으므로 DLG-I002 §3 5번 "SCR-I004 옷 락커 운영 관리의 헤더 '배정' 액션(빈 락커 + 미배정 회원을 한 번에 매칭)" 진입 경로를 제거한다.

### 보정 4. DLG-I003 §3 진입 경로 2·4번 정합화

## 6. 잔여 권고 사항 (이번 직접 보정 범위 외)

1. **D09 SCR-082·SCR-082A**: 통합 ID 대응표 기준 D11 SCR-I002로 통합되었음을 D09 도메인 검수 단계에서 alias/deprecated 표시로 보강할 것.
2. **D09 SCR-086 출석 관리 설정 vs D11 SCR-I001 책임 분리**: 본 보정은 D11 도메인 README에만 가벼운 안내를 추가했고, D09 SCR-086 본문에는 "정책 단독 관리, RSV-04 출결 처리 적재는 D11 SCR-I001" 안내가 보강되어야 두 도메인 검수 결과가 정합한다.
3. **IoT-03 원천 명세서의 5종/4종 혼재**: IoT-03 본문 15·29행에서 "4종 / 5종(게이트·키오스크·락커 컨트롤러·InBody·카드 리더)"이 동시 등장. 원천 명세서 정합화 시 5종으로 통일 권고.
4. **9역할 중 `front`·`골프프로`(golfPro)·`FC` 영문 키워드 부재**: docs-domain 전반에서 "매니저(manager·프런트)" "FC(상담사)" 같은 한글·영문 혼재 표기가 있어 9역할 영문 키워드(superAdmin / primary / owner / manager / staff / front / trainer / golfPro / fc / readonly 중 사용 합의된 7~9개)를 D01 공통 README 또는 권한 매트릭스 문서에서 단일 원천으로 정의해 둘 것을 권고.
5. **SCR-I008 데이터 미연동 배너**: SCR-I008 README가 "퍼블리싱 완료 / 데이터 미연동 단계"임을 §1·§4·§9·§15에 명시하고 있어, 향후 실제 heartbeat 연동 시점에 운영 정책 §15의 "데이터 미연동 환경 정책" 단락을 폐기 처리해야 함을 유지보수 메모로 남김.
6. **DLG-I001 §1 메타의 부모 화면**: 진입 경로 4번을 제거함에 따라 부모 화면은 "SCR-I001 통합 출석 관리"로 단일화. 메타 본문은 이미 단일이라 추가 변경 불필요.
