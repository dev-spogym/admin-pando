## 0. 요약

D09 설정관리 도메인 28개 README는 전반적으로 운영 정책 05(7종 표준 역할·9×5 권한 매트릭스·6종 민감 기능·본사 지점 소유권 분리)와 06(고정 D-day 폐기·정책 세트/스텝 구조·만료 기준 계산)을 충실히 반영하고 있다. 미저장 변경 손실 방지(DLG-080-001) 공통 패턴은 SCR-080·082·082A·083·086·088 6개 화면에 일관 적용되어 있으며, SET-EXT-01의 자동화 정책 라이브러리·지점 적용 분리, SET-04 커스텀 역할의 SCR-081과 SCR-087 single source-of-truth 동기화, SET-03의 PG 토큰 보안·grace period 7일·재가입 90일·5년 청구 이력 영구 보관, SET-EXT-03의 슈퍼관리자 전용 복원·AES-256·SHA-256 무결성 검증·복원 사유 필수 입력 정책이 정합적으로 녹아 있다.

다만 다음 8건의 불일치·누락을 확인하고 보정 권한이 있는 9건은 직접 수정, 운영 정책 결정이 필요한 1건은 권고로 남겼다.

- **A-1 [보고]**: SCR-089 백업 다운로드 권한이 동일 문서 내에서 "슈퍼관리자 전용"(§54·§74)과 "owner 다운로드 가능"(§150)으로 모순됨. 운영 정책 결정 후 일괄 정합화 권고.
- **A-2 [정합]**: 권한 7종 표준과 trainer/golf_trainer/front 직무값 분리 — 도메인 README §93·§125, SCR-081 §330, SCR-087 §197이 운영 정책 05 §3·§4와 일관 일치.
- **A-3 [정합]**: 9×5 권한 매트릭스 — SCR-081·SCR-087이 동일한 "9 메뉴 그룹(회원·수업·매출·상품·직원·급여·시설·메시지·설정) × 5 권한(접근·조회·생성·수정·삭제)" 구조를 사용하며 운영 정책 §3 "페이지 접근·조회·수정·승인·일괄처리" 5종과 매트릭스 라벨이 정합.
- **A-4 [정합]**: 본사 정책 세트 step 구조·고정 D-day 폐기 — SCR-080A·DLG-080A-001이 운영 정책 06 §4·§5와 정합. 본사 필수 스텝 자물쇠 표시·지점 토글 허용·본사 고정 시각·24h 롤백·강제 배포 흐름 일관.
- **A-5 [정합]**: 만료 기준 계산 4원칙(실제 조정된 만료일 / 홀딩 반영 후 재계산 / 환불·취소 종료 이용권 제외 / 재등록 완료 시 이전 알림 중단) — SCR-080A §308·도메인 README §97과 정합.
- **A-6 [정합]**: 계약코드 정합성 — SCR-080A·SCR-086은 운영 정책 08의 "파생 기획" 결정에 따라 `contract_codes` alias 미부여, `contract_status: 파생 기획`만 명시. SCR-080(SET-01)·SCR-081(SET-02 + AUTH-03·AUTH-04·CTR-05)·SCR-082(IoT-01)·SCR-083(IoT-02)·SCR-084(SET-03)·SCR-087(SET-04)·SCR-088(SET-05)·SCR-089(SET-EXT-03)은 계약 본기능 alias가 정확.
- **B-1 [보정]**: 도메인 README §93 "7종 권한 템플릿" 표 라벨에 9역할 영문 키워드(trainer·front 포함)가 누락 — 영문 키 보강.
- **B-2 [보정]**: SCR-086 §143·SCR-088 §143의 차단 역할 나열에 영문 키워드(`trainer`·`front`) 누락 — 영문 키 보강.
- **B-3 [보정]**: SCR-082A §11·§99 권한 처리에 9역할 영문 키워드(`fc`·`trainer`·`staff`·`front`·`readonly`) 풀이 부족 — 영문 키 보강.
- **C-1 [정합]**: DLG-080·080A·081·084·085·087·089 15종 다이얼로그 호출 관계가 부모 화면 README에 모두 정확히 등재. DLG-080-001 미저장 경고 부모 화면은 SCR-080·082·082A·083·086·088 6개로 SCR-080A는 §69에서 별도 추적 정책으로 명시(누락 아님).
- **C-2 [보정]**: SCR-085 §92의 DLG-085-002 호출 관계가 "게시 중 공지는 종료 처리 후에야 삭제 가능"으로 안내되지만, 부모 화면 SCR-085 §145에는 "매니저는 [삭제] 버튼 hidden"이 명시되어 DLG-085-002의 권한 차단이 부모 화면에 일관 등재되어 있어 정합. 보정 없음.
- **D-1 [정합]**: 권한 설정·커스텀 역할 — SCR-081 §38·§240·§348·SCR-087 §38·§132이 모두 "owner와 superAdmin/primary 접근, 매니저 이하 차단"으로 일관. 운영 정책 05 §10 "권한 템플릿 관리 = superAdmin 또는 primary"와 정합(owner는 자기 지점 RLS branchId 필터 내 편집 가능).
- **D-2 [정합]**: 구독 결제(SET-03) owner 이상 — SCR-084 §132·§225·DLG-084-001 §75·DLG-084-002 §63이 모두 "매니저 이하 재무 정보 보호 차단"으로 정합.
- **D-3 [정합]**: 백업 복원(SET-EXT-03) owner 이상 — SCR-089 §150 "owner는 슈퍼관리자 승인 후 실행", DLG-089-001 §89 "owner는 [복원]이 [승인 요청]으로 표시, 이 모달 미호출", DLG-089-002 §87 "owner는 자기 지점 설정 편집 가능"이 정합. 다만 다운로드 권한 정의가 A-1과 같이 SCR-089 내부에서 모순.

## A. 카테고리 간 불일치

### A-1. SCR-089 백업 파일 다운로드 권한 모순 [중요 - 보고]

**문제**: SCR-089 README 내부에서 백업 파일 다운로드 권한 정의가 모순된다.

| 위치 | 다운로드 권한 정의 |
|---|---|
| SCR-089 §54 (수동 백업 카드) | "다운로드는 슈퍼관리자 전용이며 파일 암호화·서명 URL 만료·감사 로그 기록 정책이 확정된 뒤 활성화됩니다." |
| SCR-089 §74 ([최신 백업 다운로드] 버튼) | "가장 최근 성공한 백업 파일을 다운로드합니다. 서명된 URL이 1시간 유효합니다. 슈퍼관리자 전용입니다." |
| SCR-089 §150 (권한별 처리 owner) | "센터장(owner)은 소속 지점 백업 이력 조회와 수동 백업·다운로드가 가능합니다." |

§54·§74는 다운로드가 superAdmin/primary 전용이라고 명시하지만, §150은 owner도 다운로드 가능하다고 명시한다. 운영 정책 05 §10 표에는 백업 다운로드 권한이 별도 명시되어 있지 않으나, "권한 템플릿 관리 = superAdmin 또는 primary"와 "민감 기능 상위 권한 제한"(AUTH-04 — 6종 민감 기능 포함, 다만 백업 다운로드는 6종에 포함되지 않음) 기조를 고려할 때 어느 쪽이 정답인지 명확하지 않다.

**판단**: 백업 파일은 회원 PII와 결제·매출 데이터를 모두 포함하는 전사 스냅샷이므로 다운로드 권한은 슈퍼관리자(superAdmin/primary)로 제한하는 §54·§74가 운영 안전성 측면에서 합리적이다. owner의 자기 지점 데이터 다운로드는 별도 화면(예: 매출 화면의 CSV 내보내기·회원 목록 내보내기)으로 분리하는 것이 운영 일관성을 보장한다.

**조치**: 보안·결재 정책 변경 영향이 크므로 **직접 수정 보류, 기획자 확인 후 일괄 정합화 권고**. 권고안:
- SCR-089 §150 (owner 권한별 처리)를 "센터장(owner)은 소속 지점 백업 이력 조회와 수동 백업 트리거가 가능합니다. 백업 파일 다운로드는 슈퍼관리자 전용이며, owner의 [다운로드] 버튼은 비활성 또는 [요청] 형태로 표시됩니다."로 변경.
- SCR-089 §15 (운영 정책) "슈퍼관리자 전용 복원 접근"(§259)과 동일한 격으로 "슈퍼관리자 전용 다운로드 접근" 항목을 추가.
- 또는 반대 결정(owner도 자기 지점 백업 다운로드 가능)인 경우 §54·§74의 "슈퍼관리자 전용" 표현을 "슈퍼관리자 + 자기 지점 owner"로 수정.

### A-2. 권한 7종 표준 + 직무값 분리 [정합]

운영 정책 05 §3·§4의 "관리자 웹 7종 표준 역할(superAdmin·primary·owner·manager·fc·staff·readonly) + trainer/golf_trainer/front는 직무값 또는 회원앱 역할"이라는 결론이 D09 전반에 일관 반영되어 있다.

- 도메인 README §93·§125: "7종 권한 템플릿 + trainer/golf_trainer/front 직무값 분리" 명시.
- SCR-081 §30·§54·§68·§330: 좌측 카드 정렬과 운영 정책 모두 "기본 7종 → 커스텀 역할 순서". §330은 "front는 staff에 포함되며 trainer는 회원앱 또는 수업 운영 관점의 역할로 다뤄집니다"로 운영 정책 §4 결론을 그대로 반영.
- SCR-087 §30·§197: 동일한 7종 + 커스텀 역할 구조.
- DLG-081-003 §31·§93·DLG-081-005 §31·§95: 이름 중복 차단 시 "기본 7종 역할명 및 한글 표기 중복 차단" 일관.

trainer·front·readonly의 권한별 처리 항목은 각 SCR의 §11(권한별 처리)에 9역할 모두 등장(§125의 도메인 README 원칙 "9개 역할 모두 적시" 충족). 일부 SCR(SCR-086·SCR-082A·SCR-088)에서 영문 키워드 표기 누락은 B-2·B-3에서 직접 보정.

### A-3. 9×5 권한 매트릭스 [정합]

운영 정책 05 §3 "페이지 접근·조회·수정·승인·일괄처리"의 5종 권한과 D09의 매트릭스 라벨(접근·조회·생성·수정·삭제)이 표현은 다르지만 RBAC 구조의 핵심인 "5종 권한 × 9개 메뉴 그룹"은 일관 유지. SCR-081 §30·§56·§90·§148·§328·§336·SCR-087 §30·§50·§187·§201·§215가 동일한 매트릭스 구조를 사용하고, DLG-081-002 §90 "충돌 6종 패턴"이 5종 권한 간 논리 모순 패턴을 정의.

### A-4. 본사 정책 세트 step 구조 / 고정 D-day 폐기 [정합]

운영 정책 06 §2·§4·§5·§6과 SCR-080A·DLG-080A-001이 정확히 일치한다.

- 고정 `D-30 / D-14 / D-7 / D-3 / D-1` 폐기 — SCR-080A §33·§288 "고정 D-day UI 전제 사용 안 함" 명시.
- 정책 세트 5항목(정책명·적용 범위·사용 상태·기본 여부·지점 수정 허용) + 정책 스텝 6항목(기준일·스텝명·채널·메시지 템플릿·필수 여부·지점 토글 허용) — SCR-080A §57·§290 모두 반영.
- 본사 필수 step의 자물쇠 표시·본사 고정 시각 회색 톤·지점 토글 허용 명시 — SCR-080A §57·§89·§91 정합.
- 표준형/집중형/최소형 정책 세트 예시 — 운영 정책 06 §6과 SCR-080A §288 일치.

### A-5. 만료 기준 계산 4원칙 [정합]

운영 정책 06 §7의 4원칙(실제 조정된 만료일 / 홀딩 반영 후 재계산 / 환불·취소 종료 이용권 제외 / 재등록 완료 시 이전 알림 중단)이 SCR-080A §308·도메인 README §97에 모두 반영. 운영 예외 처리(수신 동의 없는 채널 자동 제외 / 묶음 처리 / 담당 FC 없는 회원 공용 큐)도 SCR-080A §310에 정합.

### A-7. 키오스크 설정·IoT 설정 분리 [정합]

운영 정책 06 §8과 운영 메모에 따른 키오스크 본체·키오스크 부착 IoT·센터 출입 게이트의 3축 분리가 D09 SCR 3종에 명확히 반영되어 있다.

- SCR-082 키오스크 설정: 화면 구성·출석 방식·기능 표시 토글·미리보기 (단말기 자체의 화면).
- SCR-082A 키오스크 IoT 설정 §28: "키오스크 본체에 부착되는 IoT 주변 장치(얼굴 인식 카메라·QR 스캐너·회원번호 키패드)". SCR-082·SCR-083과의 책임 경계가 명시.
- SCR-083 IoT 출입 관리 §28: "센터의 출입 게이트와 출입 인증 장치". SCR-082A가 키오스크 단말기 부착 IoT를 다루는 데 반해 SCR-083은 센터 출입 게이트 자체를 관리한다는 점이 §28·§40에서 정합.

세 화면 모두 양방향 진입 경로(예: SCR-082 얼굴 인식 활성 → SCR-082A 카메라 등록 안내 / SCR-082A 카메라 등록 → SCR-082 출석 방식 활성 안내)가 명시되어 운영 흐름이 끊기지 않는다.

### A-8. 구독 플랜 분류 [정합]

SCR-084 §48의 "플랜 비교 카드"는 "이용 가능한 전체 플랜이 카드 형태로 가로 배치되며, 각 카드에 포함 기능·월 요금·회원 수 한도 표시"로 명시. 플랜 명칭(예: Free·Basic·Pro·Enterprise)을 구체화하지 않은 점이 향후 운영 결정 여지를 남기는 합리적 추상화이며, 운영 정책 05·06에는 플랜 분류 정의가 없으므로 SCR-084의 추상 명시가 정합. 다운그레이드 데이터 한도 초과 경고·업그레이드 일할 차액 청구는 SCR-084 §195·§197·DLG-084-001 §109·§111에 정합 명시.

### A-9. 다국어 적용 기준 [정합]

SCR-088 §29의 다국어 적용 5원칙(키오스크 활성 언어 최소 1개·기본 언어 비활성화 차단·타임존 표시 계층만 적용·UTC 저장·번역 부족 키 한국어 fallback)이 §202·§214·§216·§218·§220에 모두 풀려 있다. 자동 번역과 공지 자동 번역의 SET-EXT-04 연계는 SCR-088 §246·DLG-085-001 §160·SCR-085 §227에 일관 명시. 키오스크 표시 언어 동기화는 SCR-088 §242·SCR-082 §57·SCR-082 §80에 정합.

## B. 운영 정책 녹임 적절성

### B-1. 도메인 README §93 7종 권한 템플릿 표 영문 키워드 보강 [직접 수정 - 완료]

### B-2. SCR-086 §143·SCR-088 §143 차단 역할 영문 키워드 보강 [직접 수정 - 완료]

## D. 권한 정책

### D-1. 권한 설정·커스텀 역할 superAdmin/primary + owner 제한 [정합]

운영 정책 05 §10 표 "권한 템플릿 관리 = superAdmin 또는 primary"와 D09 SCR-081·SCR-087의 권한 정의가 정합.

- 메뉴 노출: SCR-081 §38 "owner와 superAdmin/primary에게만 노출" / SCR-087 §38 동일.
- owner 편집 범위: SCR-081 §238·§348·SCR-087 §130 "RLS branchId 필터로 자기 지점 역할만 편집".
- 매니저 이하 차단: SCR-081 §240·SCR-087 §132 "사이드바 메뉴 hidden + 직접 URL 차단 + 3초 후 대시보드 이동".
- superAdmin 카드 시스템 잠금: SCR-081 §60·§184·§200·DLG-081-001 §57·DLG-081-004 §57 일관.

운영 정책 §10 "권한 템플릿 관리 = superAdmin 또는 primary"는 SCR-081의 owner 편집 권한(자기 지점 한정)과 정합. owner는 자기 지점 운영 책임자로서 자기 지점의 매니저·FC·staff 권한 매트릭스를 조정할 수 있으나, 본사 통합 모드(전 지점 일괄 조정)는 불가.

### D-2. 구독 결제(SET-03) owner 이상 [정합]

운영 정책 05 §10 표에는 구독 결제 권한이 별도 명시되어 있지 않으나, 도메인 README §78 "매니저 이하는 재무 정보 보호 정책에 따라 접근 차단"이 명시. SCR-084 §132·§225·DLG-084-001 §75·DLG-084-002 §63이 모두 일관:

- 메뉴 노출: owner와 superAdmin/primary에게만 노출.
- 매니저·FC·트레이너·스태프·프런트·readonly 차단: 부모 화면 진입 자체 차단.
- 다중 지점: 본사 슈퍼관리자만 통합 조회.

### D-3. 백업 복원(SET-EXT-03) owner 이상 [정합 / A-1 다운로드 권한은 보고]

운영 정책 05 §6 "본사 KPI 및 감사 기준"의 본사 소유와 AUTH-05 감사 로그 정책에 따라 복원은 슈퍼관리자 전용 또는 owner의 슈퍼관리자 승인 후 실행. D09에 일관 반영.

- 메뉴 노출: SCR-089 §38 "owner와 superAdmin/primary에게만 노출".
- 복원 권한: SCR-089 §150·DLG-089-001 §89 "owner는 [복원]이 [승인 요청]으로 표시, 슈퍼관리자 승인 후 자동 복원".
- 매니저 이하 차단: SCR-089 §152 "부모 화면 접근 자체 차단".
- 복원 사유 필수 입력 + 영구 보관: DLG-089-001 §43·§77·§141 일관.

다운로드 권한은 A-1에서 별도 보고(SCR-089 내부 모순).

## F. 기획자 확인 요청 사항

다음 1건은 운영 정책 결정이 필요하므로 직접 수정하지 않고 보고한다.

### F-1. SCR-089 백업 파일 다운로드 권한 정합화 (A-1)

SCR-089 §54·§74의 "슈퍼관리자 전용 다운로드"와 §150의 "owner 다운로드 가능"이 모순. 다음 두 결정안 중 하나로 일괄 정합화 요청.

- 결정안 A (보수적·권장): 다운로드는 superAdmin/primary 전용. owner는 백업 트리거·조회만 가능. §150 수정.
- 결정안 B: owner도 자기 지점 백업 파일 다운로드 가능. §54·§74의 "슈퍼관리자 전용"을 "슈퍼관리자 + 자기 지점 owner"로 수정.

운영 정책 05 §6 본사 KPI·감사 기준이 본사 소유라는 점, 백업 파일이 전사 PII와 재무 데이터를 모두 포함한다는 점을 고려할 때 결정안 A가 운영 안전성 측면에서 합리적.
