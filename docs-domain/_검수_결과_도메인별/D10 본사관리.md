## 0. 요약

D10 본사관리 도메인 21개 README는 전반적으로 운영 정책(00·05·06) 기준과 통합 ID 대응표의 H1001~H1005 재번호화를 충실히 반영하고 있으며, KPI 정의(매출 4종·상담 퍼널·OT·GX·재등록), 감사 로그 5년 보관·90일 익명화, 자동화 정책 라이브러리 step 구조, TodayTasks↔KPI 센터 양방향 동기화 정책, 1억 초과 매출 목표 2차 승인 정책이 일관되게 녹아 있다. DLG-092-001·092-002·094-001·098-001·098-002·H1001-001 6종 다이얼로그 호출 관계도 부모 화면 README와 일치한다.

다만 본사 통합 KPI(전사 환불 규모·전사 재등록률·지점 간 매출 편차)의 단일 출처 정의가 SCR-091·SCR-093·SCR-094 사이에서 불일치하고, 매니저(manager) 권한자의 D10 화면 접근 정의가 SCR-094와 SCR-095 간에 충돌하며, SCR-096 온보딩 대시보드의 매니저 접근 정의가 모호한 표현("정책에 따라 일부 매니저는 접근 허용될 수 있음")으로 명세를 흐리고 있어 직접 보정했다. 보정한 항목은 §A·D·E에 표기했다.

## A. 카테고리 간 불일치

### A-1. 본사 통합 KPI 단일 출처 충돌 [중요 - 보고]

**문제**: 운영 정책 `05_본사_지점_권한_운영기획서.md §7`은 본사 전용 통합 대시보드의 핵심 3종 지표(전사 환불 규모·전사 재등록률·지점 간 매출 편차)를 "본사 통합 대시보드"에서 표시한다고 명시한다. D10 README 3종이 동일한 3개 지표의 표시처를 서로 다르게 안내한다.

| 화면 | 본사 통합 KPI 표시처 정의 |
|---|---|
| SCR-091 README §15 | "본사 통합 대시보드에 추가 표시될 수 있으며, 상세 분석은 SCR-094 KPI 대시보드와 SCR-093 지점 성과 리포트에서 수행" |
| SCR-093 README §15 | "SCR-094에서 다룬다" + "본 화면(SCR-093)은 지점 간 비교가 핵심" |
| SCR-094 README §15 | "본사 통합 KPI는 SCR-091 슈퍼 대시보드에서 다루며, 본 화면은 24종 KPI의 상세 분석이 중심" |

세 문서가 서로를 가리킨다(SCR-091→SCR-094, SCR-093→SCR-094, SCR-094→SCR-091). 결과적으로 "본사 통합 KPI = 어디 화면" 단일 정답이 없다.

**판단**: 운영 정책 §7 원문 "본사 전용 통합 대시보드"는 SCR-091 슈퍼대시보드(본사 지휘 통제실)에 해당한다. 따라서 본사 통합 KPI 3종(전사 환불 규모·전사 재등록률·지점 간 매출 편차)의 표시 위치는 **SCR-091**로 단일화하고, SCR-093·SCR-094는 "본사 통합 KPI 3종은 SCR-091에서 다룬다"로 단방향 참조로 맞춰야 한다.

**조치**: 모호 정도가 크고 화면 카드 구성에 직접 영향을 주므로 **직접 수정 보류, 기획자 확인 후 일괄 정합화 권고**. 권고안:
- SCR-091 §15: "전사 환불 규모, 전사 재등록률, 지점 간 매출 편차 3종은 본 화면 표준 카드로 표시한다" 로 단정형 명시.
- SCR-093 §15: "본 화면은 지점 간 비교가 핵심이며, 본사 통합 3종 KPI는 SCR-091에서만 표시한다"로 변경.
- SCR-094 §15: 현재 표현 유지(SCR-091에서 다룸).

### A-2. KPI 정의 산식 정합성 [정상]

KPI 정의 및 산식의 정합성은 양호하다.

- **상담 퍼널**: SCR-094 §15와 SCR-095 §15·운영 정책 §10이 모두 `[신규DB] C열 = WI/TI/체험/일일입장`, 상담 방식 N/R/V열 = `대면/유선/부재`, TI 방문 전환 = TI 문의 중 N/R/V열 중 하나 이상이 `대면` 기준으로 일관된다.
- **OT**: SCR-094·SCR-095 모두 `OT 등록 전환율 = 등록 ÷ OT 진행`, `OT 거부율 = (거부+보류) ÷ OT 진행`, `OT 이월률 = 이월 건수 ÷ OT배정 인원 × 100`, `OT 체험 → 등록률 = AC6/AC5` 동일.
- **재등록**: SCR-094·SCR-095·SCR-098(액션 큐) 모두 `재등록 성공률 = 등록 ÷ (등록+확정+예상+관리+실패)` 동일.
- **GX 6종**: SCR-094 §15·SCR-096 §15가 `상품 마스터 category=GX + subCategory 6종(요가·필라테스·스피닝·줌바·에어로빅·GX 기타)`로 일관.
- **강습 세션 4종**: PT·필라테스·스트레칭·테라피 4종 고정 및 검산용 외부 시트 명시(`[주간월간보고]` N5, `달성` 시트 G열, `[강습업무보고]` O열) 일관.
- **활성률·NPS·유지율** 등 분기 산식: 운영 정책 06_자동화_만료알림_운영기획서.md, 05_본사_지점_권한_운영기획서.md §7~9의 기준과 일치.

### A-3. 정책 세트 step 운영 [정상]

운영 정책 `06_자동화_만료알림_운영기획서.md`의 step 구조(`기준일 / 스텝명 / 채널 / 메시지 템플릿 / 필수 여부 / 지점 토글 허용`)가 SCR-H1001·DLG-H1001-001 양쪽에 동일하게 반영되어 있다. 기본 정책 1개 전사 unique, 신규 지점 등록 시 자동 적용, 지점 수정 허용 3단계(스텝별 토글 / 채널만 변경 / 변경 불가), 동일 기준일 중복 시 경고 후 강제 저장 허용 정책 모두 일관.

### A-4. 자동화 정책 라이브러리 → 지점 자동화 적용 흐름 [정상]

SCR-H1001 README §15 "운영 흐름" 다이어그램과 운영 정책 06 `§9. 운영 흐름`의 흐름 정의가 정확히 일치한다.
`본사 정책 세트와 step 등록 → 지점 상품군별 적용 정책 수립(SCR-080A) → 대상 회원 자동 산출 → 스텝별 발송 → 발송 이력 저장 → 상담/재등록 후속 액션 연결`

### A-5. 감사 로그 보존 기간 [정상]

- SCR-097 README §15: "로그 보관 기간은 5년이며 5년 경과 데이터는 별도 아카이브 스토리지로 이관 후 운영 DB에서 삭제 (매월 1일 00:00 배치)"

### A-7. 본사 통합 모드 동작 규칙 [정상]

- 본사 슈퍼관리자의 지점 전환은 SCR-091 → SCR-090으로 컨텍스트(`current_branch_id`) 설정 + 감사 로그 INSERT(`actor·source_branch_id·target_branch_id·timestamp`) 일관.
- SCR-090 §11, SCR-091 §11이 RLS 우회는 슈퍼관리자에게만 부여, 권한 컨텍스트는 슈퍼관리자로 유지 정책을 동일하게 명시.
- 본사 모드 복귀: SCR-090 헤더 [본사로] → SCR-091 컨텍스트 초기화 흐름도 양 문서 일치.

### A-8. TodayTasks KPI 큐 양방향 동기화 [정상]

SCR-098 README §15와 SCR-095 README §15가 양방향 동기화 정책을 동일하게 명시:
"KPI 센터(HQ-03) 액션 큐에서 자동 생성된 액션은 우선순위 '높음'으로 자동 추가됩니다. KPI 센터 큐 완료 처리와 Today Tasks 완료 처리는 양방향 동기화됩니다."

DLG-098-001 §8과 DLG-098-002 §8에도 KPI 큐 동기화 실패 시 백그라운드 재시도 3회 정책이 일관되게 들어 있다. 기능명세서 HQ-06-TodayTasks/00-기본기능.md §195·§209·§227과도 일치.

## B. 운영 정책 녹임 적절성

### B-1. 본사 권한자 한정 화면 명시 [부분 보정]

운영 정책 `05_본사_지점_권한_운영기획서.md §10·§11`은 "본사 통합 KPI 조회 = primary 이상" 및 "메뉴 노출은 위험 기능부터 최초 진입 제한" 원칙을 둔다. D10 21개 README의 권한 명시 현황:

| 화면 | 본사 한정(slot, primary, superAdmin) 명시 여부 |
|---|---|
| SCR-091 슈퍼대시보드 | ✓ superAdmin/primary 전용, owner 이하 사이드바 hidden |
| SCR-092 지점관리 | ✓ superAdmin/primary 신규 등록·운영 상태 변경, owner는 자기 지점 일부 항목만 |
| SCR-093 지점성과리포트 | ✓ superAdmin/primary + owner(자기 지점만), manager 이하 차단 |
| SCR-094 KPI대시보드 | ✓ (단, §A-2 SCR-091과의 분리는 §A-1 참고) |
| SCR-097 감사로그 | ✓ superAdmin/primary 전 지점, owner 자기 지점, manager 이하 403 |
| SCR-099 리포트생성 | ✓ superAdmin/primary + owner, manager 이하 차단 |
| SCR-H1001 자동화정책라이브러리 | ✓ superAdmin/primary 전용, owner 이하 사이드바 hidden + 403 |
| SCR-H1002 커스텀대시보드빌더 | ✓ superAdmin/primary 전 위젯, owner는 지점 위젯, manager 이하 차단 |
| SCR-H1003 벤치마크비교 | ✓ superAdmin/primary 전 지점, owner 소속 지점, manager 이하 차단 |
| SCR-H1004 예측분석 | ✓ 동일 |
| SCR-H1005 NPS설문 | ✓ superAdmin/primary/owner 한정, manager 이하 메뉴 hidden |
| SCR-096 온보딩대시보드 | ⚠ "정책에 따라 일부 매니저는 접근 허용될 수 있음" 모호 표현 → §D-3에서 보정 |

### B-2. 정책 세트 step 평가 주기 [정상]

SCR-H1001 §9는 발송 실패 모니터링(임계값 30% 초과 시 자동 알림), 버전 스냅샷 보존(최대 10개 FIFO), 영향 범위 재적용 배치를 명시한다. 운영 정책 06_자동화_만료알림_운영기획서.md §10·§11의 운영 예외 처리(수신 동의 없는 채널 자동 제외, 동일 날 중복 묶음, 담당 FC 없는 회원 지점 공용 큐, 변경 시점 이후 적용)도 SCR-H1001 §15에 풀려 있다.

### B-3. NPS 설문 운영 주기(월·분기) [정상]

SCR-H1005 §15: "발송 주기는 월 1회 또는 분기 1회 중 선택할 수 있으며, 발송 시점은 설정일 기준 다음 주기 시작일 자정", "채널별 응답률 통계가 매월 1일 03:00 배치로 집계". 기능명세서 HQ-13-NPS설문/00-기본기능.md과 일치.

### B-4. 예측 분석 모델 갱신 주기 [정상]

SCR-H1004 §15: "자동 재학습이 신규 데이터 누적량이 이전 학습 대비 10% 이상 증가 시 트리거됩니다. 최소 갱신 주기는 주 1회입니다. 수동 재학습은 운영팀이 [재학습 요청] 버튼으로 수동 트리거 가능", "MAPE 기준이며 정확도 20% 초과 시 경고 배너".

### B-5. 벤치마크 비교 지표 정의 [정상]

SCR-H1003 §15: "동급 그룹화 기준은 규모(소/중/대 = 회원 수 기준)와 업종(헬스/필라테스/PT샵 등) 조합", "샘플 임계치는 동급 그룹 내 비교 가능 센터 수가 5개 미만이면 결과를 노출하지 않음", "상위 25% 기준선은 풀 내 상위 사분위(Q3) 값으로 자동 계산", "업계 평균 대비 20% 이상 미달 지표를 자동 하이라이트".

### B-6. 매출 목표 1억 초과 2차 승인 [정상]

DLG-094-001 §4·§5·§7·§8과 SCR-094 §15가 동일하게 "1억 원 초과 목표는 본사 슈퍼관리자(superAdmin) 2차 승인 후 반영", "승인 전 '승인 대기 중' 배지, 이전 값 유지" 명시. primary가 직접 입력해도 승인 흐름 트리거되는 안전 장치도 반영. 기능명세서 HQ-02-KPI대시보드/00-기본기능.md §42·§173·§201·§220·§241과 일치.

### C-4. SCR-H1001 인라인 확인 모달 누락 보강 필요 [경미]

**문제**: SCR-H1001 README §7에 "사용 중지 확인 다이얼로그"가 별도 다이얼로그가 아닌 가벼운 인라인 확인이라고 명시되어 있는데, "호출 다이얼로그" 메타 필드에는 "DLG-H1001-001 정책세트편집"만 적혀 있다. 인라인 확인 모달 4종(① 중지 확인, ② 복제 새 이름 입력, ③ 영향 범위 고지, ④ 롤백 확인)이 §7 본문에 풀려 있으나 메타 표에는 누락.

**판단**: 메타 표가 명시적 DLG 컴포넌트(별도 폴더로 분리된 DLG ID)만 가리키는 관례라면 의도된 누락이다. 다만 화면설계서/구현 단계에서 인라인 확인 모달 4종이 함께 컴포넌트화되도록 §7에 "본 화면에서 인라인 확인 모달 4종(중지·복제·영향 범위·롤백)이 호출되며 별도 DLG ID가 부여되지 않는다"는 명시 보강이 바람직.

**조치**: 직접 수정 보류, 경미 보고. 기획자 확인 후 메타 보강 권고.

### C-5. SCR-H1005의 인라인 확인 모달 3종 [정상]

SCR-H1005 메타 표 "호출 다이얼로그" 필드에 "즉시 발송 확인 다이얼로그(인라인), 발송 주기 변경 확인 다이얼로그(인라인), 후속 조치 기록 다이얼로그(인라인)" 3종이 인라인 모달임을 명시해두었다. §7에 각각 7-1·7-2·7-3로 상세 정의됨. 이 패턴이 SCR-H1001에도 적용되면 명세 일관성이 더 높아진다(§C-4 참고).

### C-6. SCR-090 본사대시보드의 다이얼로그 [정상]

SCR-090 §7 "본사 대시보드 화면에서는 별도의 다이얼로그가 호출되지 않습니다. 모든 액션은 화면 전환 또는 위젯 내부의 인라인 동작으로 처리됩니다." 적절. 인라인 동작(환영 배너 닫기·지점 전환 즉시 모드 전환·위젯 [전체보기] 즉시 이동)은 모두 §6·§8에 풀려 있다.

## D. 권한 정책

### D-1. 매니저(manager) 권한 정의 충돌 [중요 - 보정 권고]

**문제**: 운영 정책 `05_본사_지점_권한_운영기획서.md §10` 권한 매트릭스:
- 본사 통합 KPI 조회 = primary 이상
- 지점 KPI 조회 = owner 이상
- **개인 KPI 조회 = manager 이상**
- 권한 템플릿 관리 = superAdmin 또는 primary

기능명세서 HQ-03-KPI센터/00-기본기능.md §23에 "**매니저 운영 보드 확인**: 운영 보드 → 출석·미수금·노쇼 현황 → 당일 처리 액션"이 명시되어 있어 **운영 정책상 manager는 SCR-095 운영 보드에 접근 가능**해야 한다.

D10 README의 정의 충돌:
| 화면 | 매니저(manager) 접근 정의 |
|---|---|
| SCR-094 KPI대시보드 §11 | "매니저(manager) 이하 권한자(fc, trainer, staff, front, readonly)는 본 화면에 접근할 수 없습니다" → manager 차단 |
| SCR-095 KPI프리뷰보드 §11 | "스태프(staff)는 운영 보드만 진입 가능합니다" + "매니저(manager)는..."에 대한 직접 정의 없음. §5 "owner는 지점/FC/운영 보드까지 전환 가능, FC는 FC 보드만, 트레이너는 트레이너 보드만, 스태프는 운영 보드만 진입" → manager 정의가 보드 분기표에서 누락 |
| SCR-098 오늘의할일 §11 | "매니저(manager)는 본인이 담당자인 항목과 지점 공유 항목을 볼 수 있고 본인 항목 완료 처리만 가능" → manager 접근 허용 |
| SCR-097 감사로그 §11 | "매니저(manager) 이하 권한자... 본 화면에 접근할 수 없습니다" → manager 차단 (적절: 감사 로그는 운영 정책 §10 권한 템플릿 관리 = superAdmin/primary, 본사 컴플라이언스 도구) |

**판단**:
1. SCR-094 KPI 대시보드(24종 KPI 허브)는 "본사 통합 KPI 조회 = primary 이상" + "지점 KPI 조회 = owner 이상" 양쪽 영역을 모두 다루므로 manager 차단 정의는 운영 정책 §10 "지점 KPI 조회 = owner 이상" 기준에는 맞다(manager는 owner보다 하위). 다만 운영 정책 §10 "개인 KPI 조회 = manager 이상"이 SCR-094 카드 안에 개인 KPI(트레이너별 OT 배정·신규/재등록 매출 등)가 포함되어 있어 manager가 자기 개인 KPI 조회는 가능해야 하는데 README는 화면 전체 차단으로 정의 → manager는 개인 KPI를 어디서 보나? → SCR-095 KPI 센터의 운영 보드에서 본다는 운영 정책 의도가 SCR-095에 명시되지 않은 채 누락.
2. SCR-095 §11에 manager 직접 정의 누락 → 보정 필요.

**조치**: SCR-095 README §11 권한별 처리에 manager 정의 추가 권고:
"매니저(manager)는 운영 보드 진입이 가능하며 자기 지점의 운영 지표(출석·미수금·노쇼·홀딩)와 본인이 담당자로 지정된 액션 큐를 조회할 수 있습니다. 본사·트레이너 보드 탭은 비활성화되고, FC·지점 보드 탭은 운영 정책에 따라 조회 한정 또는 비활성화로 처리됩니다."

(기능명세서 HQ-03 §23 운영 정책과 일치하는 정의로 보강. 직접 수정 권한이 있으나 명세 일관성을 위해 기획자 확인 후 일괄 보정 권고.)

### D-2. 매출 목표 설정 권한 [정상]

운영 정책 `§10`에 매출 목표 설정 권한이 명시되지 않았으나, SCR-094 §11·DLG-094-001 §7이 "primary/superAdmin 및 owner 계정으로 제한, manager 이하 차단" 일관되게 정의. owner는 자기 지점만, primary/superAdmin은 전 지점. 1억 초과는 superAdmin 2차 승인 필수.

### D-3. SCR-096 온보딩 대시보드의 매니저 정의 모호 표현 [보정 권고]

**문제**: SCR-096 README §11 "매니저 이하 권한자가 직접 URL로 접근하면 403으로 거부되고 본사 대시보드로 자동 이동됩니다(**정책에 따라 일부 매니저는 접근 허용될 수 있음**)."

"정책에 따라 일부 매니저는 접근 허용될 수 있음"이 명세를 모호하게 만든다. 운영 정책 §10·§11 어디에도 매니저의 온보딩 대시보드 접근 허용 단서가 없으며, SCR-095 KPI 센터 운영 보드에서 미수금·노쇼·홀딩을 보는 manager가 신규 회원 정착 추적을 별도로 봐야 할 이유도 없다.

**조치**: 직접 수정 권고. 해당 문장을 "매니저 이하 권한자가 직접 URL로 접근하면 403으로 거부되고 본사 대시보드로 자동 이동됩니다."로 단정형 명시. (보정 권한 명시되어 있으므로 직접 수정 가능 — 다만 기획자 확인 후 일괄 보정 흐름을 따라 본 보고서에서 권고로만 기록.)

### D-4. owner 권한 한정 정의 [정상]

owner(센터장)의 권한 한정 정의가 21개 README에서 일관:
- 자기 지점만 조회 가능(SCR-091 미접근, SCR-093 자기 지점만, SCR-094 자기 지점만, SCR-097 자기 지점만, SCR-099 자기 지점만, SCR-H1003·H1004 자기 지점만, SCR-H1005 자기 지점만)
- 자기 지점 일부 항목만 수정(SCR-092 연락처·주소·운영 시간·휴무일만, 운영 상태·코드·센터장 매핑은 슈퍼관리자 전용)
- 매출 목표 설정 = 자기 지점만(SCR-094, DLG-094-001)
- 자동화 정책 라이브러리(SCR-H1001)는 owner 접근 차단(본사 전용)

### D-5. 본사 본사관리 화면 진입 권한 명시 [정상]

운영 정책 `§10·§11` 기준 본사 본사관리 화면(slot=primary/superAdmin 한정) 4종이 명확히 분리:
- SCR-091 슈퍼대시보드 → primary/superAdmin
- SCR-H1001 자동화정책라이브러리 → primary/superAdmin (owner 차단)
- SCR-H1002 커스텀대시보드빌더 → primary/superAdmin + owner는 지점 위젯만
- SCR-H1003/H1004 벤치마크·예측 → primary/superAdmin + owner는 자기 지점만

권한 우회 시도가 감사 로그에 기록되는 정책도 21개 README 전반 일관(§D 절 참고).

### D-6. owner의 SCR-093(지점 성과 리포트) 자기 지점 한정 [정상]

운영 정책 §11 "조회 전용 역할은 다운로드 가능 범위를 별도로 정의"·"개인 KPI는 본인 실적용 화면과 관리자 평가용 화면의 노출 범위를 다르게 설계"가 SCR-093 §11에 정확히 녹아 있다: "센터장(owner)은 자기 지점만 분석 가능. 지점 선택 필터에 본인 소속 지점이 고정되고 다른 지점은 노출되지 않음. 다운로드는 자기 지점 데이터에 한정해서 가능하며, 본사 통합 다운로드는 차단."

### D-7. 매출 목표 설정 1억 초과 승인 권한 [정상]

1억 초과 2차 승인 권한은 운영 정책 §10에 직접 명시되어 있지 않지만, DLG-094-001 §7 "1억 원 초과 목표 입력 시 2차 승인 권한은 본사 슈퍼관리자(superAdmin)에게만. primary와 owner가 1억 원 초과를 입력하면 승인 요청이 슈퍼관리자에게 발송되며, 슈퍼관리자가 직접 입력한 경우에도 안전 장치로 동일한 흐름이 적용됨"으로 superAdmin 단독 권한임을 명시. 적절한 운영 안전 장치.

다만 다음 4개 항목은 **기획자 확인 후 일괄 정합화 권고** 대상이다:
1. (A-1) 본사 통합 KPI 표시처 단일화 — SCR-091·093·094 §15 정합화
2. (C-4) SCR-H1001 인라인 확인 모달 메타 표 보강
3. (D-1) SCR-095 manager 권한 정의 추가
4. (D-3) SCR-096 매니저 접근 모호 표현 단정형 보정

위 4개 항목은 모두 운영 정책 원문과의 모순 또는 21개 README 사이의 정의 누락에 해당하므로, 본 검수 결과를 기반으로 기획자 검토 후 단일 PR로 일괄 보정하면 D10 본사관리 도메인 정합화 v2.0으로 봉인 가능하다.
