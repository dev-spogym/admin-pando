## 2. 추가 미보정 권고 사항 (모호한 케이스 - 보고서에만 기록)

### 2.1 KPI-OT 계약코드 신설 검토 필요

- 대상: `DLG-C010 강사상세 다이얼로그/README.md` line 16
- 현재 표기: `계약코드 | CLS-06, KPI-OT`
- 이슈: `KPI-OT`는 `docs/admin/운영용_기획문서/08_계약코드_정합성_점검.md`의 최초 계약코드 136종에 등록되어 있지 않다. 신규 기획코드 또는 비계약 alias로 분류 필요.
- 권고: `contract_status: 신규기획` 또는 `비계약` 명시 후 `LEGACY_UNCLASSIFIED_IDS` 등록 여부 본사 확인.
- 보정하지 않은 사유: 계약코드 신설은 본사 승인이 필요한 사항이며 임의 변경 금지(원칙 4 - "신규 기획코드가 필요한 경우 기존 계약코드 전체와 중복되면 안 된다").

### 2.2 RSV-03 / RSV-04 alias 표시 불일치

- 대상: `SCR-C002 수업관리 페이지/README.md`은 `계약코드 | CLS-02, RSV-03` 명시. `SCR-C014 출석QR체크인 페이지/README.md`은 `계약코드 | CLS-14`만 명시.
- 이슈: 08 계약코드 정합성 점검에 따르면 RSV-04(출결 처리)는 IoT-07에 귀속되며 출석 관련 화면(CLS-14, CLS-11)은 alias 표기 정책이 명확하지 않음.
- 권고: 출석 관련 화면에 `RSV-04`를 alias로 표기할지 본사 승인 후 일괄 추가. 단, "RSV-04는 IoT-07에만 contract_codes 유지" 정책이 확정 시 추가 표기 불필요.
- 보정하지 않은 사유: 계약코드 alias 정책은 본사 정합성 점검 문서에 따라 IoT-07에만 유지로 명시되어 있어 D04에서 임의 추가 불가.

### 2.3 양도 정책 활성/비활성 일관성

- 대상: `SCR-C007 횟수관리 페이지/README.md` line 122, line 105
- 이슈: "변경 유형: 자동 차감 / 수동 조정(추가) / 수동 조정(차감) / 환불 복구 / 양도의 5종" 중 양도는 테넌트 정책 활성 시에만 노출이라고만 명시. DLG-C012/DLG-C013에서는 양도 옵션이 별도 언급되지 않아 모달 단계 정합화 필요.
- 권고: DLG-C012 "조정 유형"에 "추가/차감" 외 "양도 출/입"을 테넌트 정책 활성 시 추가하거나 별도 모달로 분리할지 본사 결정 필요.
- 보정하지 않은 사유: 양도 정책 자체가 테넌트 옵션이며, 본사 표준 기능 범위에 포함되는지 별도 확인 필요.

### 2.4 7일 경과 정책의 적용 범위 명확화

- 대상: `DLG-C003 수업등록수정_관리 다이얼로그/README.md`
- 이슈: DLG-C011, DLG-C005에 7일 경과 trainer 수정 차단 정책이 명시되었으나, DLG-C003의 출석 정정 영역(완료 수업 한정)에는 7일 정책 명시 부재. DLG-C003에서는 동시 수정 충돌만 다룸.
- 권고: DLG-C003에 7일 경과 trainer 정정 차단 정책 명시 추가 또는 명시적 면제 사유 기록 필요.
- 보정하지 않은 사유: DLG-C003은 "수업 정보 수정"과 "출석 정정"을 모두 담당하므로 7일 정책의 적용 범위(정보 수정 vs 출석 정정 둘 다인지)를 본사 확정 후 명시 필요.

### 2.5 자동 페널티 vs 잔여 0 처리 정책 일관성

- 대상: `SCR-C008 페널티관리 페이지/README.md` line 62, 74, 125
- 이슈: "횟수 차감 vs 잔여 0인 경우 보류 또는 다음 결제 후 차감" 정책이 본문에 있으나 DLG-C014/DLG-C015 어느 모달에서 처리되는지 분기 모달 명시 부재.
- 권고: 어느 모달에서 옵션(보류/다음 결제 차감) 선택을 운영자가 하는지 명확화.
- 보정하지 않은 사유: 모달 책임 경계가 본사 기획에서 확정되지 않음.

### 2.6 SCR-C016 예약 목록 DLG 부재의 의도성 확인 필요

- 대상: `SCR-C016 예약목록 페이지/README.md` line 56
- 이슈: "별도 호출 다이얼로그가 없으며 예약 취소는 사유 입력 + 확인 팝업, 상태 정정은 정정 사유 입력 모달로 처리됩니다"라고 명시했으나 해당 인라인 모달에 DLG 코드를 부여하지 않은 정책적 의도가 모호.
- 권고: 정정 모달이 인라인이라도 DLG-C017(또는 유사) 코드 부여 일관성 확인. 다만 화면설계서에서 별도 DLG 디렉토리가 없어서 의도된 정책일 가능성 높음.
- 보정하지 않은 사유: 화면설계서 디렉토리 구조와 일관(`docs/admin/화면설계서/D04-수업관리/`에 SCR-C016 별도 DLG 없음).

## 4. 결론

D04 수업관리 도메인의 32개 README는 자기완결형 기획 문서로서 핵심 정책 본문이 매우 일관되게 작성되어 있다. 강습 세션 유형 4종, 출결 멱등성 키, 자동 노쇼 A05, 7일 경과 정책, 본사 표준 잠금, 영구 보관 vs 5년 보관, 1·3·5 단계 페널티, 대기열 자동 스킵 같은 핵심 운영 정책은 SCR↔DLG, DLG↔DLG, 운영기획서↔README 사이에 모두 정합되어 있다.

다만 다음 4건은 카테고리 간 수치/라벨/링크 정합화가 필요했으며 직접 보정 9건을 완료했다:
1. SCR-C008의 단계별 페널티 값이 DLG-C015 본사 권장값과 불일치 → 정합화
2. SCR-C001에 OT 거부+보류 04/29 정책 연결 부재 → 보강
3. SCR-C009 [대안] vs DLG-C016 [대안 제시] 호출 트리거 라벨 → 일관화
4. SCR-C005 정원 상한선(1~99) 명시 부재 → 보강

추가로 6건의 모호한 케이스는 본사 결정 또는 별도 협의가 필요한 사항이라 보고서에 권고 형태로 기록했으며 직접 보정하지 않았다.

본 검수 이후 D04 도메인은 카테고리 간 정합성·운영 정책 녹임·모달 호출 관계·권한 정책 4축 모두 정합화된 상태이며, 추후 본사 결정 사항(KPI-OT 계약코드, 양도 정책, DLG-C003 7일 정책 적용 범위 등)이 확정되면 권고 2.1~2.6을 반영해 추가 보정할 수 있다.
