### 2.1 동일 ID 중복 다이얼로그(P001~P008 양쪽)의 상위 정합성 메타 표 분리

- 대상: `DLG-P001 상품등록모달`/`DLG-P001 전지점배포`, `DLG-P002 상품수정모달`/`DLG-P002 작업취소확인`, `DLG-P003 가격이력`/`DLG-P003 상품삭제확인`, `DLG-P004 비활성화안내`/`DLG-P004 할인규칙등록`, `DLG-P005 상품가져오기`/`DLG-P005 할인규칙수정`, `DLG-P006 상품삭제확인(비교)`/`DLG-P006 할인규칙삭제확인`, `DLG-P007 상품이미지업로드`/`DLG-P007 할인정책추가수정`, `DLG-P008 가격이력조회`/`DLG-P008 할인정책삭제확인`
- 이슈: 화면설계서 디렉토리 구조에 따라 P001~P008이 양쪽으로 8쌍(16개) 중복 ID로 부여되어 있어 키워드 검색 시 두 다이얼로그가 동시에 매칭됨. 각 다이얼로그의 부모 화면 메타에서는 풀 네임(예: `DLG-P003 상품삭제확인`, `DLG-P003 가격이력`)으로 풀 경로를 명시하고 있어 정합화 자체는 OK.
- 권고: 향후 DB·코드 식별자(예: `dialog_id`) 마이그레이션 시에는 `DLG-P003a 가격이력`, `DLG-P003b 상품삭제확인` 같은 명시 접미사 또는 도메인별 prefix(예: `DLG-P-PROD-003 가격이력`, `DLG-P-PROD-006 상품삭제확인-비교`) 정책을 본사 합의 후 적용 권장.
- 보정하지 않은 사유: 화면설계서 디렉토리 구조 자체가 양쪽 중복 ID를 의도적으로 유지하고 있으며, 본사 기획에서 식별자 마이그레이션이 확정되지 않음.

### 2.2 PRD-EXT-01/PRD-EXT-02 계약코드 등록 상태 확인 필요

- 대상: `SCR-P002 상품등록수정 페이지/README.md`(`PRD-EXT-01`), `SCR-P003 상품상세패널 페이지/README.md`(`PRD-EXT-02`)
- 이슈: `docs/admin/운영용_기획문서/08_계약코드_정합성_점검.md`의 "기능명세서 id 기준 재정렬 후보"에 `PRD-EXT-01`, `PRD-EXT-02`가 명시되어 있으며 기존 136 계약코드에는 없음. 두 코드 모두 `PRD` prefix를 사용하지만 EXT 접미사가 신규 기획임을 시사.
- 권고: `contract_status: 신규기획` 또는 `파생기획`(PRD-01 본체에서 분리된 화면 확장) 명시 후 `LEGACY_UNCLASSIFIED_IDS` 등록 여부 본사 확인. 두 화면 모두 자기완결 메타 표에 `계약 상태 | 계약 범위 본기능`으로 명시되어 있는데, 08 계약코드 정합성 점검 문서 결정에 따라 `파생기획` 또는 `신규기획`으로 수정 필요할 수 있음.
- 보정하지 않은 사유: 계약코드 alias 정책은 본사 정합성 점검 문서에 따라 본사 확정 후 일괄 변경이 적절. 임의 변경 금지(원칙 4).

### 2.3 DLG-P010 카탈로그설정 vs DLG-P011 카탈로그편집 책임 경계 미세 중복

- 대상: `DLG-P010 카탈로그설정 다이얼로그/README.md` line 22-28, `DLG-P011 카탈로그편집 다이얼로그/README.md` line 23-31
- 이슈: DLG-P010 카탈로그설정은 "노출 항목·정렬·컬럼·테마·헤더 노출" 옵션을 다루고, DLG-P011 카탈로그편집은 "헤더 문구·추천 코멘트·카드 순서·이미지·노출 OFF"를 다룸. "헤더 노출(로고/연락처/운영시간)"은 P010, "헤더 문구"는 P011로 분리 명시되어 있으나, 운영자가 "헤더"를 한 모달에서만 변경할 수 있을 거라고 혼동할 가능성이 있음.
- 권고: DLG-P010/P011 모두에 "이 모달은 X를 다루고, Y는 P011/P010에서 다룹니다" 명시도 강화. 또는 두 모달 간 "다른 설정 열기" 빠른 진입 링크 추가.
- 보정하지 않은 사유: 본사 합의된 책임 분리 정책이며 양 모달 메타에 책임이 명시되어 있어 정합성 자체는 OK. UX 보강은 디자인 단계에서 별도 검토.

### 2.4 SCR-P008 시즌가격관리에 운영 정책 구분 5종 키워드 부재

- 대상: `SCR-P008 시즌가격관리 페이지/README.md`
- 이슈: 운영 정책 구분 5종(단일지점·법인·홈&오피스·주말·통합)은 회원권 계열 상품(MEMBERSHIP)의 필수 속성이므로 SCR-P002에서만 명시되어 있음. 시즌 가격은 전 카테고리(MEMBERSHIP/PT/GX/PRODUCT/SERVICE)에 적용 가능하므로 운영 정책 5종이 누락된 것은 의도된 분리로 판단되지만, 본사 정의 시즌이 "단일지점 회원권"에만 적용되는지 "통합 회원권"에도 적용되는지의 정책이 명시 부재.
- 권고: SCR-P008과 DLG-P016에 "시즌 가격은 상품의 운영 정책 구분(단일지점/법인/홈&오피스/주말/통합)과 무관하게 대상 상품에 적용되며, 본사 정의 시즌은 전 지점 자동 동기화 후 운영 정책 구분에 따라 결제 시점에 결제 가능 회원만 매칭됩니다" 안내 추가 권장.
- 보정하지 않은 사유: 의도된 분리이며 SCR-P002에서 운영 정책 5종이 충실히 명시되어 있어 정합성 자체는 OK. 본사 결정 사항 확인 후 추가 보강 권장.

### 2.5 PRD-04 할인 자동 적용 조건 AND/OR vs PRD-08 시즌 가격 자동 매칭 정책 명시도

- 대상: `SCR-P004 할인설정 페이지/README.md` line 166, `SCR-P008 시즌가격관리 페이지/README.md` line 140
- 이슈: SCR-P004는 "자동 적용 조건 다중 선택(VIP + 세그먼트)은 AND/OR 토글로 조합 정책을 명시"라고 운영자에게 토글을 노출. SCR-P008은 "재등록 우대 시즌은 만료 30일 이내 회원에게 자동 매칭"이라고만 명시. 시즌 가격에서 회원 등급(VIP/Gold/Silver) + 세그먼트 + 만료 30일 이내 등 다중 조건이 가능한지 정책이 명확치 않음.
- 권고: SCR-P008/DLG-P016에 시즌 가격 자동 매칭의 회원 조건이 PRD-04 자동 적용 조건과 동일한 AND/OR 토글로 처리되는지, 아니면 단일 조건(예: 만료 임박 30일 이내)만 지원되는지 명확화.
- 보정하지 않은 사유: 시즌 가격 자동 매칭의 회원 조건 다중성은 본사 기획에서 확정 안 됨. 추후 본사 결정 후 명시 권장.

### 2.6 DLG-P012 입고등록 / DLG-P013 출고등록의 거래처 자동 완성 정책 부재

- 대상: `DLG-P012 입고등록 다이얼로그/README.md`, `DLG-P013 출고등록 다이얼로그/README.md`, `SCR-P007 재고관리 페이지/README.md` line 137
- 이슈: SCR-P007 운영 정책에 "거래처 정보 정책은 텍스트 자유 입력이며 거래처별 통계는 정규화 후 집계됩니다. 오타로 통계가 흩어지지 않도록 자동 완성이 권장됩니다"라고 명시되어 있으나, DLG-P012/P013 두 모달에 자동 완성 UI 구현 정책이 명시 부재.
- 권고: DLG-P012 입고등록의 거래처 입력 필드에 자동 완성(최근 입력한 거래처 상위 N개 + 기존 거래처 정규화 매칭) 정책을 모달 책임으로 명시. SCR-P007이 정책을 가지지만 모달이 실 구현 책임을 명확히 가져가야 정합성이 보장됨.
- 보정하지 않은 사유: 자동 완성 정책은 본사 기획에서 권장 사항으로만 명시되어 있어 강제 정책이 아님. 모달 구현 시 자동 완성 도입 여부 본사 확정 권장.

## 4. 결론

D05 상품관리 도메인의 33개 README는 자기완결형 기획 문서로서 핵심 정책 본문이 **D04 도메인보다 더 일관되게** 작성되어 있다. 상품 마스터의 단일 정본 정책, 가격 변경 자동 기록, 시즌 가격 자동 활성/비활성 매시 Cron, POS 자동 차감, 5분 캐시, 낙관적 락, 판매 이력 보호, 전 지점 배포 권한 같은 핵심 운영 정책은 SCR↔DLG, DLG↔DLG, 운영기획서↔README 사이에 모두 정합되어 있다.

특히 다음 정책들이 33개 README 전반에 동일 표현으로 녹아 있어 정합성이 높았다:
1. **할인 우선순위**: "시즌가격 → 할인 → 쿠폰 → 마일리지" (도메인 README + SCR-P004 + SCR-P008 + DLG-P007 일관)
2. **시즌 자동 처리**: "매시 정각 Cron 배치 + 시작일 자동 활성 + 종료일 23:59 자동 비활성" (도메인 README + SCR-P008 + DLG-P016 동일 표현)
3. **판매 이력 분기**: 판매 이력 0건 → DLG-P003 완전 삭제, 1건 이상 → DLG-P004 비활성 전환 (모든 호출 화면에서 동일 분기 흐름)
4. **GX 6종 시스템 고정**: 요가·필라테스·스피닝·줌바·에어로빅·GX 기타 (SCR + DLG + 매출통계·KPI 대시보드 동일 키)
5. **권한 9역할 + 추가 역할**: superAdmin/primary/owner/manager + productEditor/inventoryManager/staff/fc/trainer/frontDesk/readonly (도메인 README 권한 표 보강 완료)

- 권고 2.1: 동일 ID 중복 다이얼로그(P001~P008 양쪽)의 식별자 마이그레이션 정책
