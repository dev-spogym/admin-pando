## 1. 보정 사항 (직접 수정)

### 1-1. SCR-S001 매출현황 페이지 — `호출 다이얼로그` 표에 DLG-S005 보강

근거: 본문 7-1절에 "메모 영역 옆 편집 아이콘을 누르면 DLG-S005 메모 편집 모달이 열립니다", 12장 mermaid에 `X -->|메모 편집| Y[DLG-S005 메모 편집]` 표기가 있으나, 1장 메타 표의 `호출 다이얼로그` 항목에는 DLG-S005가 누락되어 있었다.

수정 전:
```
| 호출 다이얼로그 | DLG-S001 매출상세, DLG-S012 목표매출설정 |
```
수정 후:
```
| 호출 다이얼로그 | DLG-S001 매출상세, DLG-S005 메모편집(DLG-S001 경유), DLG-S012 목표매출설정 |
```

### 1-2. SCR-S002 POS판매 페이지 — `호출 다이얼로그` 표에 DLG-S016 보강

근거: 본문 2장·4장·6장·12장에서 "결제링크 발송" 버튼이 `SCR-S003 + DLG-S016 발송 경로`로 진입한다고 반복 명시되어 있다. DLG-S016 호출이 SCR-S003을 경유한 간접 호출이라도 부모 화면의 모달 호출 트리거가 POS의 버튼에서 시작되므로 표에 알리는 것이 정합화 원칙(섹션 7 모달 검증)에 부합한다.

수정 전:
```
| 호출 다이얼로그 | DLG-S002 구매자검색 |
```
수정 후:
```
| 호출 다이얼로그 | DLG-S002 구매자검색, DLG-S016 결제링크발송(SCR-S003 경유) |
```

> 두 보정 모두 본문에 이미 모달이 풀어 쓰여 있어 추가 본문 변경은 불필요하다.

## 2. 검수 항목별 상세

### A. 카테고리 간 불일치

#### A-1. 결제 수단 명칭 일관성
- 도메인 전반에서 표준 명칭은 **카드·현금·계좌이체·포인트** 4종이다. SCR-S003·SCR-S007·SCR-S008·SCR-S012·DLG-S008·DLG-S013에서 모두 동일하게 사용된다.
- **참고 사항(보고만)**: SCR-S005 통계관리는 레거시 ERP 17 컬럼 정합성을 위해 `카드 / 현금 / 상품권 / 포인트` 순서를 유지하고 있다. "상품권"은 운영기획서·다른 SCR/DLG에서는 사용하지 않는 명칭이지만, SCR-S005는 `[월매출]` 시트 17 컬럼 매핑 정책(15장)에 따라 의도적으로 시트 명칭을 그대로 유지한다. 자체 정합 — 추후 운영기획서에 "상품권 결제 수단의 운영상 위치"가 정의되면 SCR-S005에 각주를 추가해야 한다. (수정하지 않음, 의미 일치 유지)
- "플랫폼 잔여 캐시" 명칭은 D03 도메인 어디에도 사용되지 않는다. 운영기획서 02번 문서에도 등장하지 않으므로 검수 범위 외이며, 향후 신규 결제수단으로 도입될 경우 PRD 갱신과 함께 D03 명세에 반영해야 한다.

#### A-2. 환불 정책 정합성
- **위약금 정책 세트(기본)**: 7일 이내 0% / 8~30일 30% / 30일 초과 50%. SCR-S007 15장과 SCR-S012 9장이 동일 정의를 사용한다.
- **환불 계산식**: `환불 가능액 = 원결제 - 기환불 누계 - 위약금 - 기사용`. SCR-S007 본문·SCR-S012 15장·DLG-S006·DLG-S013·DLG-S015·SCR-S008(미수 상계)·SCR-S009(할부 환불) 모두 동일.
- **사용분 차감·위약금·기환불 누계**: 환불 상태가 아니라 환불 "계산 항목"임을 SCR-S012 15장이 명시. DLG-S013·DLG-S014 모달은 이 6개 행(원결제·기사용 차감금·위약금·기환불 누계·이번 환불 가능액·최종 환불액)을 동일 순서로 표시.
- **위약금 면제 권한**: 슈퍼관리자·센터장만 가능, 매니저 차단. SCR-S007 11장·SCR-S012 11장·DLG-S013 권한 표가 일치.
- **결과**: 일관성 양호.

#### A-3. 매출 인식 기준
- **결제 완료 시점 인식**: 영수증 첨부 등록은 영수증 등록 성공 시, 결제링크는 PG webhook 수신 시, 수기 등록은 본사 INSERT 시. SCR-S001 15장이 정본.
- **선수익금 인식**: GAAP/K-IFRS 발생주의에 따라 서비스 제공일 비례 인식. SCR-S006 15장(인식 공식: `총액 × (경과일 / 총 서비스일수)`) + 매일 03:00 일별 배치 + 매월 1일 04:00 검증 배치. SCR-S012·SCR-S007 webhook 도착 시 인식 차감.
- **순매출 정의**: `총매출 - 환불 - 할인`. SCR-S001 15장과 SCR-S005 15장(VAT 제외 순매출 명시)이 정합.
- **결과**: 일관성 양호.

#### A-4. 결제 취소 vs 부분 환불 분기
- 결제 취소·부분 환불은 **항상 SCR-S012에서 처리**되며 SCR-S003은 결제 등록만, SCR-S007은 분석·조회 허브이다. SCR-S003 본문 3장은 "결제 등록 후 즉시 취소 시도 시 SCR-S012로 안내"라고 명시.
- 결제링크 미완료 결제는 환불이 아니라 SCR-S016 링크 취소로 분기. SCR-S007 10장·SCR-S008 10장·SCR-S012 10장이 모두 동일하게 명시.
- **결과**: 정합.

#### A-5. 세금계산서 발행 규칙
- **법인 결제 → 자동 발행 가능 큐 등록**: PAY-01 webhook 도착 시 SAL-EXT-02 발행 가능 큐 자동 INSERT. SCR-S003 9장·SCR-S010 9장 일치.
- **마이너스 세금계산서 자동 발행**: SAL-EXT-04 환불 webhook 도착 시 SAL-EXT-02에서 자동 발행. SCR-S007 15장 + SCR-S010 15장 + SCR-S012 15장 + DLG-S014 모달 안내 + DLG-S010 권한 표가 일치.
- **발행 후 수정 불가**: SCR-S010 본문 + DLG-S011 권한 표에서 동일 표현.
- **국세청 60초 타임아웃 + 자동 폴링**: SCR-S010 9장·DLG-S011에서 일관 표기.
- **일별 1000건 한도**: SCR-S010 8장 + DLG-S011에서 일관.
- **결과**: 정합.

#### A-6. 미수금 관리 기준
- 발생 유형 4종(계약금 잔액 / 결제링크 미결제 / 수기 분할 / 정기 할부 미납) — 한 원장으로 통합. SCR-S008 15장 정본.
- 미수금 **신규 생성은 SCR-S008에서 직접 하지 않는다** — PAY-01·PAY-06·SAL-EXT-01 이벤트에서만 자동 등록. SCR-S008 2장 페이지 안내 텍스트 + 15장 정책이 일치.
- 연체 30일 임계 + 매일 04:00 일괄 알림, 만료 D-7/D-3 알림(NFR-05) 모두 SCR-S008 9장·15장 + SCR-S009 9장이 일치.
- **할부 ↔ 미수 자동 동기화**: SAL-EXT-01 회차 미납이 PAY-03에 자동 INSERT, 회수 시 양쪽 갱신. SCR-S009 15장·SCR-S008 15장·DLG-S008 본문이 일치.
- **결과**: 정합.

#### A-7. 할부 결제 처리 단계
- **수기 분할 vs 정기 할부 구분**: SCR-S009는 `collectionMode=INSTALLMENT_PLAN` 전용. 계약금만 받고 잔액을 단기 미수로 두는 건은 SCR-S008에서 우선 다룸. SCR-S009 2장·15장이 분리 명시.
- **회차 한도 24회·회차당 최소 1만원·말일 보정(1/31→2/28)·시작일 등록일 이후**: SCR-S009 15장 + DLG-S009 검증이 일치.
- **할부 등록 권한**: 매니저+ 만, FC 등록 불가. SCR-S009 11장 + DLG-S009 권한 표(`fc, staff, front, trainer, readonly` 사용 불가) 일치.
- **결과**: 정합.

#### D-1. 9역할 영문 키워드 일관성

## 3. 보고 사항 (수정하지 않은 모호 항목)

1. **SCR-S005 통계관리의 "상품권" 결제 수단**: 도메인 다른 화면에서는 사용하지 않는 명칭이지만, 17 컬럼 시트 매핑 정책에 따라 의도적으로 유지되고 있다. PRD 측에서 "상품권"의 운영상 정의(예: 외부 발행 상품권 결제, 사내 발행 바우처, 카카오선물 등)가 확정되면 SCR-S005에 각주 추가 및 SCR-S003 결제 등록 영역에 동등 처리 필요.

2. **결제 한도 정책 토글**: SCR-S003 15장이 "FC 1회 등록 최대 1000만원(정책 토글로 변경 가능)"으로 명시했다. 정책 토글의 실제 저장 위치(설정 화면 또는 운영기획서)가 어디인지는 D03 도메인 문서에 명시되지 않음. D09 설정관리 또는 D10 본사관리 도메인 검수 시 연계 확인 필요.

3. **5분 중복 결제 윈도우의 운영 정책 토글 위치**: SCR-S003·DLG-S004가 "운영 정책으로 조정 가능"이라고만 명시. 토글 저장 위치 동일 이슈.

4. **카드 인쇄 노란색 합계 행**: SCR-S005 14장이 "인쇄 시에도 노란색 유지"를 요구하지만, 인쇄 CSS 정책 자체는 명세서에 정의되지 않음. 디자인 시스템(Pencil.dev) 인쇄 토큰 도입 시 함께 처리 권장.

5. **본사 통합 모드의 보안 경계**: SCR-S001·S004·S005·S006·S007·S008·S009·S010·S011·S012 모든 화면이 본사 통합 모드를 다루고 있고 RLS 누락 시 보안 알림이 발송되도록 일관 명시되어 있다. 그러나 RLS 정책 자체의 정의(`branchId=all` 처리, 슈퍼관리자 디버그 콘솔)는 D10 본사관리·D09 설정관리 도메인에 정의되어 있을 가능성이 높음 — 교차 도메인 검수 시 확인 필요.

## 4. 결론

D03 매출관리 도메인은 PRD 통합본의 핵심 임계값(60초·7일·3회·5%·1000만원·10%·30%/50% 위약금·5분)과 자동화 정책(PAY-01·PAY-03·PAY-06·SAL-04·SAL-EXT-01·SAL-EXT-02·SAL-EXT-04 webhook + 배치)이 SCR 12개·DLG 16개 전반에 균일하게 녹아 있다. 환불 계산·매출 인식·세금계산서·결제링크 만료·미수금 추적 같은 기준 데이터가 화면 간에 모순 없이 동일하게 인용되어 있어 의미적 정합성은 양호하다.

검수 중 발견한 명백한 정합성 흠은 SCR-S001과 SCR-S002의 메타 표 `호출 다이얼로그` 항목 누락 2건이었으며 직접 보정했다. 그 외 1건의 "상품권" 명칭 모호와 4건의 운영 정책 토글 저장 위치는 D03 자체의 문제가 아니라 D09·D10 교차 도메인에서 후속 점검할 항목이다.
