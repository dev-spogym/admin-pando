## 2. 다이얼로그 개요와 목적

옷 락커 배정 다이얼로그는 출석 완료 후 옷 락커가 미배정 상태인 회원에게 빈 락커를 선택해 배정하는 모달입니다. 본 다이얼로그는 SCR-I001 통합 출석 관리와 SCR-I004 옷 락커 운영 관리의 양쪽 화면에서 공통으로 호출되며, 호출 진입 경로에 따라 모달의 동작이 약간 달라집니다. 회원이 먼저 결정되어 모달이 열리는 경우 빈 락커만 고르면 되고, 락커가 먼저 결정되어 모달이 열리는 경우 회원을 추가로 선택해야 합니다.

이 다이얼로그가 다루는 운영 흐름은 다양합니다. 평일 06:00 ~ 09:00 / 18:00 ~ 22:00 러시아워에 출석이 폭주하면 미배정 락커 회원이 누적되고, 운영자가 SCR-I001의 "미배정 락커" 카드를 누르거나 SCR-I004의 미배정 회원 패널을 열어 회원별로 본 다이얼로그를 호출합니다. SCR-I002 키오스크 설정의 락커 후처리 정책이 "수동 배정 대기"인 지점에서는 모든 락커 배정이 본 다이얼로그를 통해 수동으로 이루어지며, "자동 배정 시도" 정책이라도 자동 배정 실패 시(자동 배정 존에 빈 락커 없음) 미배정 상태로 떨어지면 운영자가 본 다이얼로그로 수동 배정합니다. 회원이 락커 대상이 아니거나 이미 다른 락커를 사용 중이면 배정이 차단됩니다.

따라서 이 다이얼로그는 단순한 선택 폼이 아니라, 회원 이용권 락커 대상 검증 · 빈 락커 그리드 표시 · 사용 중 / 점검 중 락커 선택 차단 · 자동 배정 존 우선 강조(옵션) · 부모 화면 실시간 동기화(SCR-I001 옷 락커 컬럼과 SCR-I004 그리드 동시 갱신) · 감사 로그 기록까지 모두 반영된 락커 배정 도구로 동작해야 합니다.

## 3. 진입 경로

옷 락커 배정 다이얼로그는 두 부모 화면에서 다음 경로로 호출됩니다.

첫 번째 경로는 SCR-I001 통합 출석 관리의 행 액션 "락커 배정" 버튼입니다. 옷 락커 컬럼이 "미배정"인 행에서 호출되며, 회원이 결정된 상태로 모달이 열려 빈 락커만 선택하면 됩니다.

두 번째 경로는 SCR-I001 통합 출석 관리의 미배정 회원 패널(우측 패널)의 "배정" 버튼입니다. 패널에서 회원을 골라 클릭하므로 회원이 결정된 상태로 진입합니다.

세 번째 경로는 SCR-I004 옷 락커 운영 관리의 미배정 회원 패널 카드의 "배정" 버튼입니다. 첫·두 번째 경로와 동일하게 회원이 결정된 상태로 진입합니다.

네 번째 경로는 SCR-I004 옷 락커 운영 관리의 락커 그리드에서 빈 락커 칸을 클릭한 후 펼쳐진 정보 팝업의 "배정" 버튼입니다. 이 경로는 락커가 먼저 결정된 상태이므로 모달 안에서 미배정 회원 드롭다운으로 회원을 추가 선택해야 합니다.

다섯 번째 경로는 SCR-I004 옷 락커 운영 관리의 헤더 "배정" 액션(빈 락커 + 미배정 회원을 한 번에 매칭)이며, 모달에 빈 락커 선택 영역과 미배정 회원 드롭다운이 모두 표시됩니다.

본사 통합 모드의 본사 권한자가 직접 호출하면 모달이 열리지 않고 "지점 선택 후 배정 가능합니다" 안내가 표시되고 차단됩니다.

## 4. 레이아웃과 UI 구성

옷 락커 배정 다이얼로그는 부모 화면(SCR-I001 또는 SCR-I004) 위에 오버레이로 표시되는 모달 팝업입니다. 모달은 화면 중앙에 정렬되며, 본문 폭은 약 640 ~ 760px 정도로 빈 락커 그리드가 한눈에 들어오는 크기로 설계됩니다.

모달 상단에는 "옷 락커 배정"이라는 제목이 표시되고 우측 상단에 닫기(X) 버튼이 있습니다. 제목 아래에는 짧은 운영 설명이 작은 글씨로 안내됩니다.

본문 상단에는 대상 회원 정보 영역이 있습니다. 이 영역은 회원이 먼저 결정된 진입 경로에서는 자동으로 채워져 표시되고, 락커가 먼저 결정된 진입 경로에서는 회원 드롭다운으로 운영자가 선택합니다. 회원 정보 영역에는 회원 사진(또는 기본 아바타), 이름, 회원번호, 출석 시각, 회원권 유형(일반·VIP 등), 보유 중인 고정 락커 번호(있는 경우)가 한 줄로 읽기 전용으로 표시됩니다. 회원이 락커 대상이 아닌 경우(이용권에 락커 미포함) 또는 이미 다른 옷 락커를 사용 중인 경우에는 회원 정보 영역 아래에 빨강 안내가 표시되고 빈 락커 선택이 비활성화됩니다.

회원 정보 아래에는 빈 락커 선택 영역이 배치됩니다. 락커는 번호 순서로 그리드 형태로 표시되며, 각 칸이 한 락커를 나타냅니다. 칸에는 락커 번호와 상태가 작게 표시되고, 빈 락커(선택 가능)는 녹색 톤·사용 중 락커(선택 불가)는 회색 톤·점검 중 락커(선택 불가)는 노란색 톤 + 망치 아이콘으로 분기됩니다. 자동 배정 존(SCR-I002 키오스크 설정의 락커 후처리 탭에서 정한)에 속한 락커는 칸 좌측 상단에 작은 별표 아이콘이 표시되어 정책 영향을 받는 락커임을 알려줍니다.

운영자가 빈 락커 칸을 클릭하면 선택 상태가 강조됩니다(칸 둘레에 진한 테두리, 배경 색상 변화). 사용 중·점검 중 칸을 클릭하면 선택되지 않고 짧은 흔들림 애니메이션과 함께 안내 토스트가 표시됩니다.

빈 락커가 0개인 상태에서는 그리드 자리에 "배정 가능한 락커가 없습니다" 안내가 표시되며 "배정" 버튼이 비활성화됩니다. 이 경우 운영자는 본 모달을 닫고 SCR-I004에서 회수 또는 일괄 해제로 빈 락커를 확보한 뒤 다시 시도해야 합니다.

빈 락커 선택 영역 위에는 락커 존 필터 드롭다운이 있어 특정 존(A존·B존·자동 배정 존 등)의 락커만 좁힐 수 있습니다. 락커 수가 많은 지점에서 운영자가 빠르게 찾을 수 있게 하는 보조 도구입니다.

모달 하단에는 두 버튼이 있습니다. "배정" 버튼은 회원과 빈 락커가 모두 선택되어야 활성화되며, 비활성 상태에서는 회색 톤으로 표시됩니다. "취소" 버튼은 선택 내용을 폐기하고 모달을 닫습니다. ESC 키 또는 배경 클릭으로도 취소와 동일하게 동작하며, 선택 도중에는 별도 확인 팝업 없이 즉시 닫힙니다(입력이 단순 선택이므로 손실 위험이 작음).

## 5. 다이얼로그 동작과 입력 검증

옷 락커 배정 다이얼로그는 진입 경로에 따라 두 가지 모드로 동작합니다.

회원 결정 모드는 진입 경로 1·2·3·5의 일부에서 사용됩니다. 회원이 이미 결정된 상태로 모달이 열리고, 운영자는 빈 락커만 선택하면 됩니다. 회원 정보 영역은 자동으로 채워져 있고 변경 불가합니다.

락커 결정 모드는 진입 경로 4와 5의 일부에서 사용됩니다. 빈 락커가 이미 결정된 상태로 모달이 열리고, 모달 본문 상단에 미배정 회원 드롭다운이 추가로 표시됩니다. 운영자가 드롭다운에서 회원을 선택해야 "배정" 버튼이 활성화됩니다.

회원 결정 직후에는 다음 검증이 자동 수행됩니다. 회원의 이용권에 락커가 포함되어 있는지 검증되며, 락커 대상이 아니면 빨강 안내 "이 회원은 락커 대상이 아닙니다"가 표시되고 빈 락커 선택이 비활성화됩니다. 회원이 이미 다른 옷 락커를 사용 중인지 검증되며, 이미 사용 중이면 "이 회원은 이미 다른 옷 락커를 사용 중입니다 - 락커 N번" 안내가 표시되고 선택이 비활성화됩니다. 회원이 출석 미완료 상태인 경우(부모 화면의 데이터 갱신 지연) "이 회원은 출석이 확인되지 않습니다. 출석 처리 후 배정해주세요" 안내가 표시됩니다.

빈 락커 선택 시점에는 다른 운영자가 같은 락커를 동시에 변경했는지 optimistic lock으로 검증됩니다. WebSocket으로 락커 상태 변화가 실시간 동기화되어 있어 일반적으로 모달 안에서 동시 변경이 발생하지 않지만, 모달을 연 후 다른 운영자가 그 락커를 다른 회원에게 배정한 경우 본 모달에서 그 칸을 선택하면 즉시 "다른 운영자가 이 락커를 사용했어요" 안내가 표시되고 자동으로 그리드가 새로고침됩니다.

"배정" 버튼 클릭 시점에 최종 검증이 수행됩니다. 회원이 락커 대상이고, 빈 락커가 여전히 빈 상태이며, 운영자의 권한이 유효한 경우에만 배정이 실행됩니다.

배정 성공 시 모달이 닫히고 부모 화면이 즉시 갱신됩니다. SCR-I001 통합 출석 관리에서 호출된 경우 해당 행의 옷 락커 컬럼이 "수동배정(번호)"로 즉시 갱신되고 미배정 회원 패널에서 해당 회원이 제거됩니다. SCR-I004 옷 락커 운영 관리에서 호출된 경우 락커 그리드의 해당 락커가 "사용 중" 상태로 전환되고 통계 카드 "미배정 대기" 카운트가 감소합니다. WebSocket으로 다른 운영자의 화면에도 변경이 실시간 반영됩니다.

본사 통합 모드의 본사 권한자가 모달을 호출하려고 하면 모달이 열리지 않고 "지점 선택 후 배정 가능합니다" 안내가 토스트로 표시됩니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

이 다이얼로그의 모든 클릭 가능한 요소를 빠짐없이 정의합니다.

모달 우측 상단의 닫기(X) 버튼은 선택 내용을 폐기하고 모달을 닫습니다. 선택 도중이라도 별도 확인 팝업 없이 즉시 닫힙니다.

락커 결정 모드에서 모달 상단의 미배정 회원 드롭다운은 현재 미배정 회원 목록을 표시합니다. 각 항목에는 회원명·회원번호·출석 시각·회원권 유형이 표시됩니다. 항목을 선택하면 회원 정보 영역이 채워지고 빈 락커 선택 영역이 활성화됩니다.

락커 존 필터 드롭다운은 전체·존A·존B·자동 배정 존 같은 옵션을 제공하며, 선택 시 빈 락커 그리드에 해당 존의 락커만 표시됩니다.

빈 락커 그리드의 각 칸은 클릭으로 선택됩니다. 선택된 칸은 진한 테두리와 배경색 변화로 강조되며, 다른 칸을 클릭하면 이전 선택이 해제됩니다. 사용 중·점검 중 칸을 클릭하면 선택되지 않고 흔들림 애니메이션과 토스트(사용 중: "이미 사용 중인 락커입니다", 점검 중: "점검 중인 락커는 선택할 수 없습니다")가 표시됩니다.

모달 하단의 "배정" 버튼은 회원과 빈 락커가 모두 선택되어야 활성화됩니다. 활성 상태에서 누르면 배정 처리가 시작되고 버튼이 로딩 스피너로 바뀌면서 다른 액션이 비활성화됩니다.

모달 하단의 "취소" 버튼은 선택 내용을 폐기하고 모달을 닫습니다.

회원이 락커 대상이 아닌 경우 회원 정보 영역 아래에 표시되는 "락커 상품 안내" 링크(선택 사항)는 D05 상품 관리로 이동해 회원에게 락커 상품 결제를 안내할 수 있게 합니다.

빈 락커 0개 안내 아래의 "옷 락커 운영 관리로 이동" 링크는 SCR-I004로 이동해 회수 또는 일괄 해제로 빈 락커를 확보할 수 있게 합니다.

## 7. 토스트와 확인 팝업과 알럿

옷 락커 배정 다이얼로그에서 발생하는 알림성 UI는 다음 패턴으로 동작합니다.

성공 토스트는 모달이 닫힌 후 부모 화면에 우측 상단으로 녹색 계열 5초간 표시됩니다. "락커가 배정되었습니다 - 락커 번호 N"이라는 문구로 결과를 알려주며, 부모 화면이 SCR-I004인 경우 해당 락커 칸이 잠시 강조되어 운영자가 결과를 시각적으로 인지합니다.

실패 토스트는 빨강 계열로 표시되며, "이 회원은 락커 대상이 아닙니다", "이 회원은 이미 다른 락커를 사용 중입니다", "배정 가능한 락커가 없습니다", "다른 운영자가 이 락커를 사용했어요", "권한이 없어요", "지점 선택 후 배정 가능합니다" 같은 문구가 표시됩니다. 일부 실패는 모달 내 인라인 메시지로 표시되어 운영자가 다른 락커를 선택하거나 다른 회원을 선택하도록 유도합니다.

경고 토스트 / 인라인 안내는 사용 중·점검 중 락커 클릭 시 노란 안내로 표시됩니다.

확인 팝업은 본 모달에서 거의 사용하지 않습니다. 선택 입력이 단순하기 때문에 닫기 시 별도 확인 없이 즉시 닫힙니다.

알럿은 권한이 부족한 사용자가 부모 화면에서 호출하려고 했을 때 부모 화면에서 차단되어 본 모달이 열리지 않으므로, 다이얼로그 내에서는 별도 알럿이 거의 발생하지 않습니다. 본사 통합 모드 차단도 부모 화면에서 차단됩니다.

## 8. 데이터 흐름과 외부 연동

다이얼로그가 열릴 때 부모 화면의 컨텍스트(회원 ID 또는 락커 ID, 지점, 권한)가 props로 전달됩니다. 본사 통합 모드 + 지점 미선택 상태이면 모달 자체가 열리지 않습니다.

회원 결정 모드에서는 `GET /api/lockers/clothing/empty?branchId=:id`로 현재 지점의 빈 락커 목록을 조회합니다. 응답에는 락커 ID·번호·존·자동 배정 존 여부가 포함됩니다.

락커 결정 모드에서는 `GET /api/lockers/clothing/unassigned-members?branchId=:id`로 현재 미배정 회원 목록을 추가로 조회합니다. 응답에는 회원 ID·이름·회원번호·출석 시각·회원권 유형·고정 락커 번호가 포함됩니다.

회원이 결정되는 시점에 `GET /api/members/:id/locker-eligibility`로 회원의 이용권 락커 대상 여부와 현재 다른 락커 사용 여부를 검증합니다. 응답에는 락커 대상 여부 boolean, 현재 사용 중인 락커 번호(있는 경우), 출석 완료 여부가 포함됩니다.

배정은 `POST /api/lockers/clothing/:id/assign`으로 호출되며, 요청 본문에 회원 ID가 포함됩니다. 응답으로는 갱신된 락커 상태와 SCR-I001의 옷 락커 컬럼 갱신 데이터가 함께 내려옵니다.

WebSocket으로 락커 상태 변화가 실시간 동기화됩니다. 다른 운영자가 같은 락커를 변경하면 본 모달의 그리드가 즉시 갱신되어, 모달을 닫지 않고도 최신 상태가 반영됩니다.

배정 성공 시 본 모달의 변경 사항은 부모 화면 양쪽(SCR-I001과 SCR-I004)에 WebSocket으로 실시간 푸시됩니다. SCR-I001의 옷 락커 컬럼이 "수동배정(번호)"로 갱신되고, SCR-I004의 락커 그리드와 통계 카드가 동기화됩니다. 회원앱 SCR-MA-159에도 회원의 오늘 락커 정보가 갱신됩니다.

배정 액션은 SCR-097 감사 로그에 비동기로 INSERT됩니다. 기록 필드는 `actor_id`(운영자 ID), `target_locker_id`, `action`(LOCKER_ASSIGN), `member_id`, `before_state`(EMPTY), `after_state`(IN_USE), `assigned_at`, `timestamp`입니다. 감사 로그 INSERT는 응답이 사용자에게 돌아간 후 5초 안에 보장됩니다.

키오스크 자동 배정(SCR-I002 락커 후처리 탭의 "자동 배정 시도" 정책)은 본 모달을 거치지 않고 시스템이 직접 배정 API를 호출합니다. 자동 배정 실패 시(자동 배정 존에 빈 락커 없음) 미배정 상태로 떨어지면 운영자가 본 모달로 수동 배정합니다. 본 모달과 자동 배정은 동일한 API 엔드포인트를 사용하므로 데이터 정합성이 보장됩니다.

화면에서 호출하는 주요 API 엔드포인트는 다음과 같습니다. 빈 락커 목록 `GET /api/lockers/clothing/empty`, 미배정 회원 목록 `GET /api/lockers/clothing/unassigned-members`, 회원 락커 적격성 검증 `GET /api/members/:id/locker-eligibility`, 배정 `POST /api/lockers/clothing/:id/assign`, 실시간 동기화 `WS /api/lockers/clothing/stream`.

## 9. 화면 상태와 예외 처리

옷 락커 배정 다이얼로그는 다음 상태들을 가집니다.

기본 락커 선택 대기 상태(회원 결정 모드)에서는 회원 정보가 자동으로 채워져 있고, 빈 락커 그리드가 표시되며, "배정" 버튼이 비활성화 상태입니다.

기본 회원 선택 대기 상태(락커 결정 모드)에서는 락커 정보가 자동으로 채워져 있고, 미배정 회원 드롭다운이 표시되며, "배정" 버튼이 비활성화 상태입니다.

락커 선택됨 상태에서는 선택된 락커 칸이 강조 표시되고 "배정" 버튼이 활성화됩니다.

빈 락커 없음 상태에서는 그리드 자리에 "배정 가능한 락커가 없습니다" 안내가 표시되고 "배정" 버튼이 비활성화됩니다. "옷 락커 운영 관리로 이동" 링크가 함께 표시됩니다.

배정 진행 중 상태에서는 "배정" 버튼이 로딩 스피너로 바뀌고 다른 액션이 비활성화됩니다.

배정 성공 상태에서는 모달이 닫히면서 부모 화면의 해당 영역이 갱신되고 성공 토스트가 표시됩니다.

배정 실패 상태에서는 인라인 또는 토스트로 실패 사유가 표시되고, 운영자는 다른 락커를 선택하거나 모달을 닫고 다시 시도할 수 있습니다.

예외 케이스별 처리는 다음과 같이 정의됩니다.

회원 락커 대상 아님(이용권에 락커 미포함) 상태에서는 회원 정보 영역 아래에 빨강 안내 "이 회원은 락커 대상이 아닙니다"가 표시되고, "락커 상품 안내" 링크로 D05 상품 관리 이동이 제공됩니다. 빈 락커 선택은 비활성화됩니다.

회원이 이미 다른 옷 락커를 사용 중인 경우 "이 회원은 이미 다른 옷 락커를 사용 중입니다 - 락커 N번" 안내가 표시되고 빈 락커 선택이 비활성화됩니다. 운영자는 본 모달을 닫고 기존 락커를 회수한 뒤 다시 시도하거나, 같은 락커를 계속 사용하도록 안내할 수 있습니다.

회원이 출석 미완료 상태인 경우(부모 화면의 데이터 갱신 지연) "이 회원은 출석이 확인되지 않습니다. 출석 처리 후 배정해주세요" 안내가 표시됩니다. 운영자는 모달을 닫고 출석을 먼저 확인한 뒤 다시 시도합니다.

빈 락커가 0개인 상태에서는 "배정 가능한 락커가 없습니다" 안내가 표시되고 "옷 락커 운영 관리로 이동" 링크가 제공됩니다.

사용 중 락커 클릭 시 흔들림 애니메이션과 "이미 사용 중인 락커입니다" 토스트가 표시되며 선택되지 않습니다.

점검 중 락커 클릭 시 흔들림 애니메이션과 "점검 중인 락커는 선택할 수 없습니다" 토스트가 표시됩니다.

다른 운영자가 같은 락커를 동시에 변경한 경우(optimistic lock 위반) "다른 운영자가 이 락커를 사용했어요" 안내가 표시되고 그리드가 즉시 새로고침됩니다. 운영자는 다른 빈 락커를 선택해 다시 시도합니다.

다른 운영자가 같은 회원에게 다른 락커를 동시에 배정한 경우 본 모달의 "배정" 클릭이 실패하고 "이 회원은 방금 다른 락커가 배정되었습니다" 안내가 표시되며 모달이 자동으로 닫힙니다.

본사 통합 모드 + 지점 미선택 상태에서는 모달이 열리지 않고 "지점 선택 후 배정 가능합니다" 토스트가 부모 화면에 표시됩니다.

권한 강등(운영자가 모달을 연 후 권한이 변경된 경우)이 발생하면 "배정" 클릭 시점에 백엔드가 403을 반환하고 "권한이 변경되었습니다" 안내가 표시됩니다.

WebSocket 연결 끊김 상태에서는 그리드가 30초 폴링으로 갱신되며 상단에 노란 배너로 "실시간 동기화 끊김" 안내가 표시됩니다.

## 10. 권한별 처리

이 다이얼로그는 권한에 따라 가능한 액션이 달라집니다.

슈퍼관리자·primary는 본사 통합 모드에서는 모달이 열리지 않고 "지점 선택 후 배정 가능합니다" 안내가 표시됩니다. 지점 선택 후에는 owner 권한으로 동작해 락커 배정이 가능합니다.

owner(센터장)은 자기 지점의 모든 회원에게 락커를 배정할 수 있습니다. 모달의 모든 기능을 사용할 수 있고 부모 화면 양쪽에서 호출 가능합니다.

매니저(manager·프런트)는 자기 지점의 락커 배정이 가능합니다. owner와 동일한 권한입니다.

스태프(staff)는 자기 지점의 락커 배정이 가능합니다.

강사(trainer)와 readonly는 본 모달에 접근할 수 없습니다. 부모 화면의 "배정" 버튼이 보이지 않거나 비활성화되어 있어 호출 자체가 불가능합니다.

본사 통합 모드의 본사 권한자는 변경 액션이 차단됩니다.

권한 차단 이벤트는 감사 로그에 기록됩니다.

## 12. 핵심 디자인 요청사항

모달은 부모 화면의 중앙에 정렬되며, 본문 폭은 빈 락커 그리드가 한눈에 들어오는 약 640 ~ 760px로 설계됩니다. 배경은 어둡게 처리되어 모달에 시선이 집중되도록 합니다.

대상 회원 정보 영역은 카드형 컴포넌트로 명확히 분리되어 표시되며, 사진(또는 기본 아바타)·이름·회원번호·출석 시각·회원권 유형·보유 고정 락커가 한 줄로 노출됩니다. 회원이 락커 대상이 아닌 경우 카드 아래에 빨강 안내가 부드러운 페이드인으로 표시됩니다.

빈 락커 그리드는 락커 번호 순으로 격자 배치되며, 한 칸이 한 락커를 명확히 대표합니다. 칸 크기는 손가락 터치에도 충분히 큰 크기로 설계되며, 빈 락커는 부드러운 녹색 톤·사용 중은 회색 톤·점검 중은 노란색 톤 + 망치 아이콘으로 색상 분기됩니다.

자동 배정 존 락커는 칸 좌측 상단에 작은 별표 아이콘이 부드럽게 표시되어, 운영자가 자동 배정 정책의 범위를 시각적으로 인지하면서도 시야를 가리지 않도록 합니다.

빈 락커 칸 호버 시 약한 색상 변화와 작은 그림자로 클릭 가능함을 알리고, 클릭 시 진한 테두리와 배경색 변화로 선택 상태가 명확히 강조됩니다. 다른 칸을 클릭하면 이전 선택이 부드럽게 해제되고 새 선택이 즉시 강조됩니다.

사용 중·점검 중 칸 클릭 시 흔들림 애니메이션이 0.5초 정도 부드럽게 일어나고 동시에 토스트가 표시되어, 운영자가 클릭이 실패했음을 즉시 인지합니다.

빈 락커 0개 상태에서는 그리드 자리에 빈 상태 일러스트 또는 큰 아이콘과 함께 "배정 가능한 락커가 없습니다" 안내가 표시되며, "옷 락커 운영 관리로 이동" 링크가 강조 버튼으로 노출됩니다.

배정 진행 중에는 "배정" 버튼이 로딩 스피너로 부드럽게 전환되고, 응답이 돌아오면 모달이 부드러운 페이드아웃으로 사라지면서 부모 화면의 해당 영역이 슬라이드 또는 색상 변화로 갱신됩니다.

WebSocket 실시간 동기화 시 다른 운영자의 변경이 본 모달에 반영되면 해당 칸이 1.5초 동안 노란색으로 부드럽게 강조되어 운영자가 변경을 즉시 인지합니다.

모바일에서는 모달이 풀스크린으로 전환되어 빈 락커 그리드가 세로 스크롤로 표시됩니다. 칸 크기는 더 커져 손가락 터치에 적합한 크기로 자동 조정됩니다.

진행 스피너와 로딩 스켈레톤은 다른 D11 화면과 동일한 톤으로 통일됩니다.

## 13. 운영 정책 (이 다이얼로그에 연결된 부분)

회원 적격성 검증 정책은 락커 배정 전에 회원의 이용권에 락커가 포함되어 있고 락커 상품이 만료되지 않은 상태여야 한다는 것입니다. 락커 미대상 회원은 D05 상품 관리로 안내되어 락커 상품을 결제한 뒤 배정 가능합니다.

다른 락커 중복 사용 차단 정책은 한 회원이 동시에 두 개의 옷 락커를 사용할 수 없다는 것입니다. 운영자가 같은 회원에게 다른 락커를 배정하려고 하면 차단되고, 기존 락커를 회수한 뒤 다시 시도해야 합니다.

출석 미완료 회원 배정 차단 정책은 출석이 확인되지 않은 회원에게는 락커를 배정할 수 없다는 것입니다. 옷 락커는 출석 기반 당일용이므로 출석이 선행되어야 합니다. 출석 처리 후 다시 배정 시도해야 합니다.

빈 락커 부족 시 운영 정책은 빈 락커가 0개일 때 SCR-I004로 이동해 회수 또는 일괄 해제로 빈 락커를 확보한 뒤 다시 시도하는 흐름을 제공합니다. 회수가 어려운 경우(모든 락커가 사용 중인 정상 상황) 회원에게 락커 사용이 불가함을 안내해야 합니다.

사용 중·점검 중 락커 선택 차단 정책은 데이터 무결성을 위한 정책입니다. 사용 중 락커를 다른 회원에게 동시 배정하면 락커 키 분실이나 짐 혼동 같은 운영 사고가 발생할 수 있으므로 시각적·기술적으로 차단합니다.

자동 배정 우선 정책은 SCR-I002 락커 후처리 탭의 "자동 배정 시도" 정책이 활성화된 지점에서 키오스크가 출석 직후 자동으로 자동 배정 존의 빈 락커를 선택해 배정한다는 것입니다. 본 모달은 자동 배정 실패 또는 "수동 배정 대기" 정책 지점에서 사용되며, 자동 배정 존을 시각적으로 강조해 운영자가 자동 배정 존을 우선 선택하도록 유도합니다.

실시간 동기화 정책은 WebSocket으로 모든 운영자의 화면에 락커 상태 변화가 즉시 반영된다는 것입니다. 본 모달의 그리드도 실시간 갱신되어 모달을 닫지 않고도 최신 상태가 보입니다.

Optimistic Lock 정책은 두 운영자가 같은 락커를 동시에 변경하면 후행 요청이 거부된다는 것입니다. 본 모달에서 락커를 선택한 후 배정 클릭 직전에 다른 운영자가 그 락커를 사용하면 본 모달의 배정이 실패하고 그리드가 새로고침되어 운영자가 다른 락커를 선택할 수 있게 합니다.

본사 통합 모드 차단 정책은 본사 권한자가 통합 모드(전체 지점) 상태에서 락커 배정을 시도하면 차단된다는 것입니다. 락커는 지점 단위로 운영되므로 지점 선택이 명확해야 합니다.

권한 분리 정책은 락커 배정이 owner·매니저·스태프 모두 가능하다는 것입니다. 옷 락커는 운영 단순 작업이므로 권한이 넓게 열려 있습니다. 강사·readonly는 부모 화면에서부터 접근이 차단됩니다.

부모 화면 동기화 정책은 본 모달의 배정 결과가 SCR-I001과 SCR-I004 양쪽에 동시 반영된다는 것입니다. 같은 데이터 원천을 사용하므로 운영자가 어느 화면에서 호출하든 결과가 일관됩니다.

감사 로그 정책은 모든 배정·차단·optimistic lock 위반이 SCR-097에 비동기로 INSERT된다는 것입니다. `actor_id`, `target_locker_id`, `action`, `member_id`, `before_state`, `after_state`, `assigned_at`, `timestamp`가 기록되어 운영 행위의 추적성을 보장합니다.

데이터 원천 단일 정책은 본 모달, 키오스크 자동 배정, SCR-I001 직접 호출, SCR-I004 직접 호출이 모두 동일한 API 엔드포인트(`POST /api/lockers/clothing/:id/assign`)를 사용한다는 것입니다. 데이터 정합성과 감사 추적성을 단일 원천으로 통일하기 위한 정책입니다.

이상의 모든 정책은 이 다이얼로그를 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다.
