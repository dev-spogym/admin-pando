# D11 통합운영 도메인

## 도메인 개요

D11 통합운영 도메인은 키오스크·IoT·옷 락커·체성분·회원 건강·키오스크 운영 모니터링을 한 도메인으로 묶은 admin-pando의 통합 운영 허브입니다. 본 도메인은 회원의 출입(키오스크) → 출석(통합 출석 관리) → 락커 사용(옷 락커 / 고정 락커) → 체성분 측정(InBody 연동 / 수기) → 회원 건강 요약(Health Connect 포함) → 키오스크 운영 모니터링까지 회원이 센터에 머무르는 동안 발생하는 모든 IoT 기반 운영 흐름을 일관된 데이터 모델과 정책 원천으로 처리합니다.

본 도메인의 모든 화면은 `docs/admin/기능명세서/D11-통합운영/`, `docs/admin/화면설계서/D11-통합운영/`, `docs/admin/운영용_기획문서/00_통합운영_개요.md` + `06_자동화_만료알림_운영기획서.md`, `docs/admin/KIOSK-연동매트릭스.md`의 내용을 자기완결형 요구사항 정의서 형식으로 풀어 쓴 산출물입니다. 각 화면 문서는 다른 문서를 함께 보지 않아도 한 장만으로 구현이 가능한 깊이로 작성되었습니다.

## 도메인 핵심 운영 정책

### 1. 데이터 단일 원천 정책

D11 도메인의 모든 화면은 단일 데이터 원천을 사용합니다. 키오스크·앱·수동에서 발생한 출석은 동일 모델로 저장되어 SCR-I001, 회원앱 SCR-MA-111, SCR-101 대시보드에 동일 데이터가 반영됩니다. 옷 락커 배정은 키오스크 자동 배정·SCR-I001 수동·SCR-I004 수동·DLG-I002가 모두 같은 API를 사용합니다. 체성분은 InBody 실시간 API·파일 업로드·수기 등록이 같은 모델로 저장되어 SCR-I006 / SCR-I007 / 회원 상세에 일관되게 노출됩니다.

### 2. 키오스크 단말 정책 단일 진입점 (SCR-I002)

SCR-I002 키오스크 설정은 키오스크 단말 운영 설정의 단일 진입점입니다. 키오스크는 부팅 시 또는 KIO-402 "설정 새로고침"으로 SCR-I002 값을 수신합니다. 단말 단위(얼굴인식·인증 수단·메뉴 노출)와 지점 단위(출입 정책·골프·공지) 정책이 분리되어 운영됩니다. 본사 슈퍼관리자는 전 지점 조회만 가능하며 변경은 지점 owner가 수행하는 거버넌스 모델입니다.

### 3. IoT 통합 관리 (SCR-I003)

SCR-I003은 5종 기기(게이트·키오스크·락커 컨트롤러·InBody·카드 리더)를 동일 데이터 모델로 관리합니다. heartbeat 60초 송신 + 5분 임계로 자동 오프라인 전환 + NFR-19 알림이 통일된 흐름이며, 펌웨어 OTA·원격 명령 큐·30일 soft delete 복구·휴무일 캘린더 자동 적용까지 IoT 라이프사이클 전반을 처리합니다.

### 4. 락커 모델 분리 (SCR-I004 / SCR-I005)

옷 락커(출석 기반 당일용)와 고정 락커(상품 계약 기반 장기)는 명확히 분리되는 모델입니다. 옷 락커는 SCR-I004 + DLG-I002 + 키오스크 자동 배정(SCR-I002 정책)으로 운영되고, 고정 락커는 SCR-I005에서 회원 락커 상품 보유 검증을 거쳐 배정됩니다. 두 모델을 섞지 않는 것이 본 도메인의 설계 원칙입니다.

### 5. 체성분 검수 정책 (SCR-I006)

체성분은 3종 채널(InBody 실시간 API · 파일 업로드 · 수기 등록 DLG-I003)을 모두 지원하며 자동 검수 분류가 일관됩니다. 회원 매칭 실패·중복 의심(5분 이내 동일 수치)·값 이상치(체중 20~300kg·골격근량 5~80kg·체지방률 3~60% 범위 밖)는 자동으로 검수 대기로 분류됩니다. owner 등록 + 정상 값만 자동 확정되며, 매니저·강사 등록은 미확정 상태로 owner 확정이 필요합니다. 확정 데이터만 SCR-I007과 회원 상세에 노출됩니다.

### 6. Health Connect v1 정책 (SCR-I007)

Health Connect는 회원앱 SCR-MA-159 연동 기반의 선택 기능이며, v1 수집 범위는 걸음수 / 이동 거리 / 활동 kcal / 운동 세션의 4종으로 제한됩니다. 심박수 / 수면 / 의료 데이터는 수집·표시하지 않습니다. 미연동 회원도 센터 출석·체성분 운영에 영향이 없으며, 활동량 비교는 운영 상담용 참고 지표로만 사용합니다.

### 7. 본사 통합 모드 정책

본사 권한자는 D11의 모든 화면에서 전 지점을 조회할 수 있지만, 변경 액션(수동 출석·락커 배정·체성분 등록·키오스크 설정·IoT 제어·원격 재시작)은 차단됩니다. "지점 선택 후 등록 가능합니다" 안내가 일관되게 표시되며, 본사가 정책 표준을 제시하고 지점 owner가 자기 책임 하에 적용하는 거버넌스 모델입니다.

D11 도메인에서 사용하는 권한 9역할의 영문 키워드는 다음과 같이 통일합니다. 본사 슈퍼관리자 = `superAdmin`, 본사 최고관리자 = `primary`, Owner(지점장) = `owner`, 매니저(프런트 포함) = `manager`(별도 표기 시 `front`), 스태프 = `staff`, 강사 = `trainer`, 골프프로 = `golfPro`, 상담사 = `fc`, 읽기 전용 = `readonly`. D11 화면에서 "매니저(manager·프런트)" 표기는 `manager`와 `front`를 동일 권한 그룹으로 묶은 약식 표현이며, 락커 배정·단일 퇴실 등 운영 행위에서 동일 정책이 적용됩니다.

### 8. 자동화 / 만료 알림 정책

만료 알림은 본사가 정책 세트(`06_자동화_만료알림_운영기획서`)로 등록하고 지점이 적용 정책을 수립하는 step 기반 구조입니다. 고정 D-30·D-14·D-7 가정은 사용하지 않으며, 본사가 등록한 step에 따라 동적으로 결정됩니다. 만료 회원의 키오스크 출석은 SCR-I002의 "만료 회원 허용" 정책에 따라 차단 또는 경고로 분기됩니다.

### 9. EXT-INBODY / Health Connect / Samsung Health / Google Fit 외부 연동

D11 도메인은 EXT-INBODY(InBody 실시간 API), Health Connect(Android 하이브리드 앱 경유), Samsung Health · Google Fit 같은 외부 시스템과 연동됩니다. 모든 외부 연동은 토큰 기반 인증·heartbeat 모니터링·자동 재시도 3회 + 30초 폴링 fallback이 일관된 패턴으로 처리됩니다.

### 10. 감사 로그 일관성

D11 도메인의 모든 변경 액션(수동 출석·퇴실·일괄 퇴실·락커 배정·회수·고장·복구·일괄 해제·체성분 등록·검수·확정·원격 재시작·기기 등록·삭제·게이트 개방·키오스크 설정 변경)은 SCR-097 감사 로그에 비동기로 INSERT됩니다. `actor_id`, `target_id`, `action`, `before`, `after`, `reason`, `timestamp`가 일관된 필드 구조로 기록되어 운영 행위의 추적성을 보장합니다.

## 계약코드 매핑

| 계약코드 | 대표 기능 코드 | 대표 화면 |
|---|---|---|
| RSV-04 (출결 처리 정본) | IoT-07 | SCR-I001, DLG-I001 |
| FAC-EXT-01 (옷 락커·고정 물품 락커) | IoT-04 | SCR-I004, SCR-I005, DLG-I002 |
| KSET-01 ~ KSET-05 (키오스크 설정 전 영역) | IoT-08 | SCR-I002 |

`RSV-04`는 출석/결석/노쇼/지각을 처리하는 운영 기능이므로 D11 통합운영 / IoT-07 통합 출석 관리에만 `contract_codes`를 유지합니다. `SET-EXT-05`(출석 설정)는 alias가 제거되어 SCR-I002 키오스크 설정으로 흡수되었습니다.

### 책임 분리(출석 정책 vs 출결 처리 정본)

출석 정책의 책임은 다음과 같이 두 축으로 나뉩니다.

- 출석 인정 시간·지각 기준·자동 출석·QR 출석 토글·정정 권한·보관 기간(법정 최소 12개월)은 D09 SCR-086 출석 관리 설정에서 단독 관리합니다.
- 키오스크 단말 차원의 출입 규칙(만료 회원 허용·중복 출석 방지 시간·미수금 처리·직원 출석 허용·영업시간·락커 후처리·얼굴인식 정지 판정 시간)은 SCR-I002 키오스크 설정에서 관리합니다.
- D11 통합운영(특히 SCR-I001)은 위 두 정책의 적용 결과를 `RSV-04` 출결 처리 정본으로 적재·운영하는 책임을 갖습니다.

### IoT 4종 기능 영역 매핑 (단말 유형 5종과 별도 축)

기능 명세서·운영 기준에서의 "IoT 4종"은 SCR-I003에서 등록되는 단말 유형 5종(게이트·키오스크·락커 컨트롤러·InBody·카드 리더)과는 별개의 축이며, 다음과 같이 D11 화면에 매핑됩니다.

| IoT 기능 영역 | 대표 화면 / 다이얼로그 | 비고 |
|---|---|---|
| 출입 게이트(IoT-03) | SCR-I003 게이트 관리 탭 + 출입 로그 탭 | 단말 유형 = 게이트 |
| 체성분(IoT-05) | SCR-I006 체성분 통합 관리, SCR-I007 회원 건강 연동 요약, DLG-I003 | 단말 유형 = InBody, 채널 = EXT-INBODY/파일/수기 |

## 작성 패턴

본 도메인의 모든 화면 문서는 D02 회원관리 SCR-M001 회원 목록 페이지와 동일한 15개 섹션 구조를 따릅니다.

1. 화면 메타 정보
2. 화면 개요와 목적
3. 진입 경로와 인접 화면
4. 레이아웃과 UI 구성
5. 탭 구성과 탭별 동작
6. 버튼·아이콘·링크 액션 전체 정의
7. 호출되는 모달 동작
8. 토스트와 확인 팝업과 알럿
9. 데이터 흐름과 외부 연동
10. 화면 상태와 예외 처리
11. 권한별 처리
12. 메인 흐름 (mermaid 다이어그램)
13. 에러와 예외 흐름 (mermaid 다이어그램)
14. 핵심 디자인 요청사항
15. 운영 정책 (이 화면에 연결된 부분)

다이얼로그 문서는 13개 섹션 구조로 작성되며, 화면 문서와 동일한 자기완결성을 유지합니다.
