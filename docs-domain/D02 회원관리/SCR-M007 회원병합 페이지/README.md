## 2. 화면 개요와 목적

회원 병합 페이지는 동일인으로 판단되는 중복 회원 계정 두 개를 하나로 합치는 화면입니다. 연락처 변경 후 재등록, 회원 본인 인증 실수로 신규 등록, 시스템 마이그레이션 시 중복 발생, 가맹점 합병 시 동일 회원의 양 지점 중복, 양도 후 양수자 계정에 이용권 합산 같은 케이스에서 사용됩니다. 양쪽 데이터를 하나의 주 계정으로 통합하면서 출석 이력·결제 이력·상담 메모·체성분 기록·이용권·마일리지·운동프로그램 같은 모든 이력 데이터를 유지합니다. 부 계정은 즉시 삭제되지 않고 비활성 상태(`status=MERGED_INACTIVE`)로 전환되어 90일 동안 복구 가능 상태로 보존되며 X11 PII 마스킹 대상에 포함됩니다.

병합은 매우 민감한 작업으로 되돌리기 어렵기 때문에 "병합" 텍스트 입력 + 권한 검증 + 비교 화면 + 단계별 확인을 통해 실수를 방지합니다. 5분 이내에 한해 별도 [최근 병합 취소] 메뉴를 통해 취소 가능하지만(정책에 따라 활성) 그 이후는 hard rollback이 불가능합니다.

운영 현장의 가장 흔한 시나리오는 연락처 변경 후 재등록한 회원의 이전 이력과 신규 이력을 통합하는 것입니다. 회원이 번호 분실로 새 번호로 다시 등록한 경우 운영자가 이전 회원 ID와 신규 회원 ID를 발견하고 병합으로 정리합니다. 두 번째로 흔한 케이스는 본인 인증 실수로 신규 등록한 매니저가 회원 본인을 못 알아보고 새 ID를 만든 경우인데, 당일 등록 분은 "최근 등록" 카드로 노출되어 빠르게 정리할 수 있습니다.

## 3. 진입 경로와 인접 화면

회원 병합 페이지에 들어오는 일반적인 경로는 사이드바 "회원관리 > 회원 병합" 항목 또는 회원 목록·회원 상세의 메뉴에서 "회원 병합" 진입입니다. 회원 상세에서 진입하면 현재 회원이 병합 대상 후보로 미리 선택되어 검색이 빠르게 시작됩니다.

이 화면에서 빠져나가는 인접 화면으로는 병합 성공 후 자동 이동하는 주 계정의 회원 상세(SCR-M004), 가족 그룹 정리가 필요한 경우 진입하는 SCR-M008 가족 회원, 모든 병합 이벤트가 기록되는 SCR-097 감사 로그가 있습니다.

## 4. 레이아웃과 UI 구성

회원 병합 페이지는 위에서 아래로 차곡차곡 쌓이는 레이아웃입니다. 가장 위에는 페이지 헤더("회원 병합"이라는 타이틀과 함께 권한 안내 배지가 있어 일반 매니저는 진입 차단됨)가 있습니다.

헤더 아래에는 중복 회원 검색 영역이 있습니다. 검색 입력란에 이름·연락처·생년월일 중 하나 이상을 입력하고 검색 버튼을 누르면 OR 매칭으로 결과가 나옵니다. 결과 카드에는 회원명·연락처·생년월일·현재 이용권·등록일·상태가 표시됩니다.

검색 결과 카드에서 주 계정과 부 계정을 각각 선택합니다. 주 계정은 병합 후 남길 계정이며 일반적으로 이력이 더 많거나 회원 본인 인증이 더 명확한 쪽을 선택합니다. 부 계정은 병합 후 비활성될 계정입니다. 동일 회원을 주/부로 동시 선택하면 빨강 강조 + "다른 계정을 선택해주세요" 안내가 표시되고 부 계정 선택이 차단됩니다.

두 계정이 모두 선택되면 비교 화면이 펼쳐집니다. 비교 화면은 두 컬럼 레이아웃으로 좌측에 주 계정 정보, 우측에 부 계정 정보가 나란히 표시됩니다. 비교 항목은 이름·연락처·생년월일·이메일·프로필 사진·이용권 목록·등록일·최근 방문일·마일리지·결제 누적·세그먼트·가족 그룹입니다. 차이가 있는 항목은 강조 표시되어 운영자가 즉시 식별할 수 있습니다.

비교 화면 아래에는 병합 항목 선택 영역이 있습니다. 이름·연락처·프로필 사진·생년월일·이메일·주소 같은 일부 항목에서 어느 쪽 계정 값을 채택할지 라디오로 선택합니다. 그 외 필드(이용권·마일리지·결제·출석·상담·체성분·운동프로그램 등)는 주 계정 우선으로 자동 통합됩니다.

병합 항목 선택 영역 아래에는 병합 후 처리 안내 박스가 있습니다. "부 계정의 모든 이력은 주 계정으로 이전됩니다", "부 계정은 즉시 삭제되지 않고 비활성 처리됩니다(90일 보관)", "병합은 되돌리기 어렵습니다(5분 이내 취소만 가능)" 같은 명확한 안내가 표시됩니다.

이용권 합산, 마일리지 합산, 가족 그룹 처리, 미수금 이전 같은 부가 영향에 대한 경고 박스가 그 아래에 표시됩니다. 양 계정 모두 활성 이용권이 있으면 노랑 경고 + 합산 안내가, 부 계정이 가족 그룹 대표였다면 빨강 경고 + 그룹 해체 안내가, 부 계정에 환불 진행 중 결제가 있으면 빨강 박스 + 병합 차단 안내가 표시됩니다.

페이지 하단에는 액션 바가 있습니다. 좌측에 "취소" 버튼, 우측에 "병합" 버튼이 있으며 병합 버튼은 모든 검증을 통과한 경우에만 활성화됩니다. 차단 사유(부 계정 환불 진행 중 등)가 있으면 영구 비활성됩니다.

## 5. 검색과 병합 실행 흐름

중복 회원 검색은 이름·연락처·생년월일 중 1개 이상으로 OR 매칭합니다. 검색 결과가 0건이면 "검색 결과가 없어요" + 검색 조건 확장 안내가 표시됩니다. 검색 결과 카드에서 주 계정을 클릭하면 좌측 비교 영역에 선택되고, 다시 부 계정을 클릭하면 우측 비교 영역에 선택됩니다. 동일 회원을 부 계정으로 선택하면 차단됩니다.

본사 통합 모드에서 슈퍼관리자만 지점 간 병합이 가능합니다. 센터장은 소속 지점 내 회원 간만 병합할 수 있으며 다른 지점 회원은 검색 결과에 노출되지 않습니다. 통합 모드 미사용 + 지점 간 병합 시도 시에도 검색 결과에서 타 지점 회원이 미노출됩니다.

병합 항목 선택에서 어느 쪽 값을 채택할지 결정합니다. 이름·연락처·프로필 사진·생년월일·이메일·주소는 라디오로 선택하며 그 외 필드는 주 계정 우선 자동 통합입니다.

차단 사유 자동 점검이 실행됩니다. 부 계정에 환불 진행 중 결제가 있으면 "환불 완료 후 재시도" 안내와 함께 병합 차단됩니다. 부 계정이 가족 그룹 대표면 "그룹이 해체됩니다" 경고가 표시되고 그룹 운영 정책 확인 후 진행 가능합니다. 부 계정에 미수금이 있으면 자동으로 주 계정으로 이전됨이 안내됩니다(회원 채무 보존). 부 계정이 홀딩/정지/탈퇴 상태면 주 계정 상태가 우선 통합됨이 안내됩니다.

"병합" 버튼을 누르면 DLG-M028 회원 병합 확인 다이얼로그가 열립니다. 다이얼로그에서 "병합" 텍스트를 정확히 입력해야 [실행] 버튼이 활성화됩니다. 한글·영문 구분이 엄격합니다.

[실행]을 누르면 `POST /api/members/merge`가 호출됩니다. 백엔드는 단일 트랜잭션 안에서 다음을 처리합니다. 회원 정보 통합(주/부 선택 결과 적용), 이력 외래키 일괄 UPDATE(consultations·payments·attendance·body_composition·classes·family_members·coupons·mileage 등 모든 회원 관련 테이블의 `member_id`를 부 → 주), 가족 그룹 분리(부 계정의 가족 연결만 해제), 등급(MBR-EXT-03) 재산정 트리거, 알림 발송, SCR-097 감사 로그 INSERT. 1개라도 실패하면 전체 롤백됩니다.

성공 시 부 계정이 `status=MERGED_INACTIVE`로 전환되고 주 계정의 회원 상세(SCR-M004)로 이동하면서 성공 토스트가 표시됩니다. 양 계정의 등록 연락처로 카카오 알림톡 "회원 정보가 통합되었어요" 발송이 트리거됩니다.

5분 이내 취소 정책이 활성화된 테넌트에서는 별도 [최근 병합 취소] 메뉴가 제공됩니다. 그 이후는 hard rollback이 불가능하므로 새 회원 등록으로 분리해야 합니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

검색 입력란은 이름·연락처·생년월일 중 1개 이상을 받습니다. 검색 버튼은 입력값이 있을 때만 활성화됩니다.

검색 결과 카드는 클릭으로 주 계정 또는 부 계정으로 선택됩니다. 좌측에 "주 계정으로 선택" 버튼, 우측에 "부 계정으로 선택" 버튼이 카드에 붙어 있습니다.

비교 화면의 병합 항목 라디오는 각 행마다 좌/우 두 옵션이 있고 클릭으로 즉시 선택됩니다.

하단 액션 바의 "취소" 버튼은 선택 상태를 초기화하고 사이드바 또는 호출 직전 화면으로 돌아갑니다. "병합" 버튼은 두 계정 모두 선택 + 차단 사유 없음 조건을 만족하면 활성화되고 누르면 DLG-M028이 호출됩니다.

5분 이내 취소 정책 활성 시 별도 메뉴 "최근 병합 취소"가 페이지 상단 또는 우측에 표시되며 누르면 가장 최근 병합을 되돌립니다.

## 7. 호출되는 모달 동작

### 7-1. DLG-M028 회원 병합 확인 다이얼로그

회원 병합 확인 다이얼로그는 회원 병합 페이지에서 "병합" 버튼을 눌렀을 때 호출됩니다. 모달 상단에는 "회원 병합 확인"이라는 제목과 함께 기준 회원(병합 후 유지될 주 계정 — 회원명·회원번호·가입일)과 대상 회원(병합 후 삭제될 부 계정 — 회원명·회원번호·가입일)이 좌우로 표시됩니다.

모달 본문에는 병합 후 데이터 합산 미리보기가 표시됩니다. 이용권은 기준 + 대상 이용권 목록이 합쳐져 표시되고, 출석 이력은 통합 건수, 마일리지는 합산 잔액, 결제 이력은 통합 건수가 미리보기로 제공됩니다. 또한 주의 안내 메시지("병합 후 대상 계정은 비활성 처리되며 90일 후 PII 마스킹 대상이 됩니다")가 강조 표시됩니다.

본문 하단에는 "병합" 텍스트를 정확히 입력하는 텍스트 입력란이 있습니다. 한글·영문 구분이 엄격하며 정확히 입력해야 [실행] 버튼이 활성화됩니다. 오타가 있으면 빨강 강조 + [실행] 비활성 상태가 유지됩니다.

[실행] 버튼을 누르면 모달이 로딩 상태로 전환되어 모든 버튼이 비활성화됩니다. 백엔드 단일 트랜잭션 호출이 시작되며 성공 시 모달이 닫히고 주 계정의 회원 상세로 자동 이동합니다.

실패 시 모달은 닫히지 않고 에러 메시지가 표시됩니다. 외래키 cascade 실패 시 전체 롤백 + 운영자 알림 + 재시도 옵션이 제공됩니다. 동시 편집 충돌(병합 도중 한쪽 회원이 탈퇴 처리됨)은 409 Conflict + "회원 상태가 변경되었습니다" 모달이 표시되고 새로고침 후 재시도하도록 안내됩니다.

[취소] 버튼이나 ESC 키, 배경 클릭으로 모달을 닫을 수 있으며 이 경우 회원 병합 페이지로 복귀합니다(선택 상태는 유지됩니다).

## 8. 토스트와 확인 팝업과 알럿

성공 토스트는 주 계정의 회원 상세로 이동하면서 우측 상단에 녹색 톤으로 표시됩니다. "두 회원이 통합되었어요. 부 계정 △△는 90일 후 마스킹됩니다"라는 안내가 5초간 유지됩니다.

실패 토스트는 빨강 톤으로 표시됩니다. 부 계정 환불 진행 중 시 "환불 완료 후 재시도해주세요", 외래키 cascade 실패 시 "병합 처리 실패. 본사 문의" 안내가 표시됩니다.

검색 결과 0건 시 "검색 결과가 없어요" + 조건 확장 안내(이름·연락처·생년월일 중 1개라도 입력하면 검색 가능)가 표시됩니다. 동일 회원 선택 시도 시 빨강 강조 + "다른 계정을 선택해주세요" 안내가 표시되고 부 계정 선택이 차단됩니다.

양 계정 활성 이용권 존재 시 노랑 경고 박스 + "양 계정 모두 활성 이용권이 있어요. 잔여 횟수가 합산됩니다" 안내가 비교 화면 상단에 표시됩니다. 부 계정 환불 진행 중 시 빨강 박스 + "환불 완료 후 재시도" 안내와 함께 병합 버튼이 영구 비활성됩니다. 부 계정 가족 그룹 대표 시 빨강 경고 + "그룹이 해체됩니다" 안내가 표시됩니다.

권한 부족(매니저·FC·트레이너·스태프·프런트가 진입 시도) 시 접근 제한 알럿 + "지점 간 병합은 본사 권한자만 가능합니다" 안내(센터장이 타 지점 회원 병합 시도 시) 후 대시보드로 자동 이동됩니다.

DLG-M028 텍스트 오타 시 빨강 강조 + [실행] 비활성 상태가 유지됩니다.

5분 경과 후 취소 시도 시 "취소 가능 시간이 지났어요. 새 회원 등록으로 분리해주세요" 안내가 표시됩니다.

회원 알림톡 발송 실패 시 병합 자체는 성공한 상태에서 알림 실패 토스트가 표시되며 운영자가 수동 안내하도록 권장됩니다.

## 9. 데이터 흐름과 외부 연동

중복 회원 검색은 `GET /api/members/duplicates`를 호출하며 요청 파라미터로 이름·연락처·생년월일이 OR 매칭됩니다. 응답에는 검색 결과 회원 카드 배열과 각 회원의 마스킹 상태(90일 경과 회원은 마스킹 표시)가 포함됩니다.

병합 미리보기는 `GET /api/members/merge/preview`를 호출해 두 계정 ID를 전달하면 합산 결과(이용권·출석·마일리지·결제·세그먼트·가족 그룹·차단 사유)가 응답됩니다.

병합 실행은 `POST /api/members/merge`를 호출합니다. 요청 본문에는 주 계정 ID, 부 계정 ID, 병합 항목 선택 결과, 사유가 포함됩니다. 백엔드는 단일 트랜잭션 안에서 외래키 cascade UPDATE를 수행하며 모든 회원 관련 테이블의 `member_id`를 부 → 주로 변경합니다.

5분 이내 취소는 `POST /api/members/merge/cancel`을 호출하며 가장 최근 병합 트랜잭션을 되돌립니다.

병합 후 자동화 체인이 트리거됩니다. MBR-EXT-03 등급 시스템은 병합 트랜잭션 내부에서 누적 결제 합산 후 등급 즉시 재산정합니다. MBR-EXT-04 세그먼트 자동 재계산 배치(D+1 새벽 4시)가 주 계정의 세그먼트 라벨을 갱신합니다. MBR-EXT-02 가족 그룹은 부 계정의 가족 연결만 해제되고 주 계정 그룹은 유지됩니다. 부 계정이 그룹 대표였다면 자동 해체 + 운영자 알림이 발송됩니다.

NFR-19 알림 센터를 통해 양 지점 운영자에게 push가 발송되고, 카카오 알림톡으로 회원 본인에게 양 번호로 "회원 정보가 통합되었어요" 발송이 트리거됩니다.

X11 PII 마스킹 배치는 부 계정이 비활성으로 전환된 후 90일이 경과한 시점에 자동 마스킹을 적용합니다. 1년 후 hard delete가 정책에 따라 수행됩니다.

본사 정산은 병합 시 결제 누적 합산으로 등급 갱신과 정산 정책 영향이 발생할 수 있습니다(선택적).

화면에서 호출하는 주요 API: 중복 회원 검색 `GET /api/members/duplicates`, 병합 미리보기 `GET /api/members/merge/preview`, 병합 실행 `POST /api/members/merge`, 병합 취소(5분 이내) `POST /api/members/merge/cancel`.

## 10. 화면 상태와 예외 처리

화면 상태는 다음과 같이 정의됩니다.

초기 검색 상태는 두 계정 모두 미선택이며 검색 안내가 표시됩니다. 주 계정만 선택 상태는 부 계정 선택 대기이며 우측 비교 영역에 "부 계정을 선택해주세요" 안내가 표시됩니다.

두 계정 모두 선택 상태는 비교 화면 + 병합 항목 선택 + 병합 버튼 활성 가능 상태입니다. 단 차단 사유(부 계정 환불 진행 중 등)가 있으면 병합 버튼은 영구 비활성 유지됩니다.

처리 중 상태는 DLG-M028 [실행] 후 백엔드 트랜잭션 도중이며 모달이 로딩 상태입니다. 병합 완료 상태는 주 계정 회원 상세로 자동 이동하기 직전의 짧은 순간이며 사용자에게는 별도로 보이지 않습니다.

예외 케이스별 처리는 다음과 같습니다. 검색 결과 0건은 조건 확장 안내로 처리됩니다. 동일 회원 선택은 부 계정 선택 차단으로 처리됩니다.

양 계정 활성 이용권 존재는 노랑 경고 + 합산 안내로 진행 가능합니다. 두 계정의 결제 누적이 모두 큰 경우에는 등급 재산정 안내(MBR-EXT-03 갱신 트리거)가 표시됩니다.

두 계정의 가족 그룹이 서로 다른 경우 노랑 경고 + "주 계정의 가족 그룹이 유지되며 부 계정의 가족 연결은 해제됩니다" 안내가 표시됩니다. 두 계정의 세그먼트 라벨이 다른 경우 D+1 배치에서 자동 재계산되며 별도 알림은 없습니다.

부 계정에 미수금이 있는 경우 자동으로 주 계정으로 이전됨(회원 채무 보존)이 안내됩니다. 부 계정에 환불 진행 중 결제가 있는 경우 빨강 박스 + "환불 완료 후 재시도" + 병합 차단으로 처리됩니다. 부 계정의 홀딩/정지/탈퇴 상태는 주 계정 상태로 통합됩니다(주 계정 우선).

지점 간 병합 시도 시 본사 권한자가 아니면 접근 제한이 표시됩니다. 본사 통합 모드 미사용 + 지점 간 시도는 검색 결과에서 타 지점 회원이 미노출되어 자연스럽게 차단됩니다.

병합 도중 한쪽 회원이 탈퇴 처리되는 동시성 충돌은 409 Conflict + 트랜잭션 롤백 + 새로고침 안내로 처리됩니다. DLG-M028 텍스트 오타는 빨강 강조 + [실행] 비활성으로 차단됩니다.

5분 경과 후 취소 시도는 "취소 가능 시간이 지났어요" 안내로 차단됩니다. 트랜잭션 도중 외래키 cascade 실패는 전체 롤백 + 운영자 알림 + 재시도 또는 본사 문의 안내로 처리됩니다. 회원 알림톡 발송 실패는 병합 자체는 성공한 상태에서 알림 실패 토스트가 표시됩니다.

미성년자·사망 같은 특수 케이스는 본사 슈퍼관리자만 처리 가능하며 사망확인서·동의서 등 증빙 첨부가 별도 시스템으로 요구됩니다.

네트워크 끊김(저장 도중)은 트랜잭션 롤백 + 자동 재시도 1회로 처리됩니다.

## 11. 권한별 처리

이 화면은 권한에 따라 진입 가능 여부와 병합 범위가 모두 달라집니다.

슈퍼관리자(superAdmin)와 본사 최고관리자(primary)는 전체 회원 병합이 가능합니다. 지점 간 병합도 가능하며 가맹점 합병 같은 케이스를 처리합니다. 미성년자·사망 같은 특수 케이스도 본사 슈퍼관리자만 처리 가능합니다.

센터장(owner)은 소속 지점 내 회원 병합만 가능합니다. 다른 지점 회원은 검색 결과에 노출되지 않으며 직접 ID 지정 시도 시 422로 거부됩니다.

매니저(manager), FC(fc), 트레이너(trainer), 스태프(staff), 프런트(front), readonly는 이 화면에 진입할 수 없습니다. 직접 URL 진입 시 접근 제한 알럿 후 대시보드로 자동 이동됩니다.

권한별 차단은 단계적으로 일관 적용됩니다. 사이드바·진입 메뉴·페이지 본문·백엔드 응답까지 4단계로 차단되며 모든 권한 차단 이벤트는 감사 로그에 기록됩니다.

## 14. 핵심 디자인 요청사항

회원 병합 화면이 운영자에게 잘 작동하려면 다음 디자인 원칙이 시각적으로 명확해야 합니다.

검색 결과 카드의 정보 밀도가 적절해야 합니다. 회원명을 큰 글씨로, 연락처·생년월일·이용권·등록일은 작은 글씨로 배치하고 클릭 가능 영역이 명확히 구분되어야 합니다.

비교 화면은 좌/우 두 컬럼이 동일 크기로 배치되며 같은 항목이 같은 높이에 있어 비교가 쉽도록 합니다. 차이가 있는 항목은 강조 색상으로 표시되어 운영자가 즉시 식별할 수 있어야 합니다.

병합 항목 라디오는 각 항목 행에서 좌/우 옵션이 명확히 구분되어야 합니다. 선택된 옵션은 강조 색상 + 굵은 테두리로 표시됩니다.

차단 사유 박스(부 계정 환불 진행 중, 가족 그룹 대표 등)는 빨강 또는 주황 톤으로 강조 표시되어 운영자가 무심코 진행하는 사고를 막아야 합니다. 차단 사유가 명확히 텍스트로도 표시되어 색맹 운영자도 차단 이유를 이해할 수 있어야 합니다.

병합 버튼은 모든 검증을 통과한 경우에만 활성화되며 비활성 상태에서는 회색 + "차단 사유 해결 필요" 또는 "주/부 계정 선택 필요" 같은 안내가 툴팁으로 표시됩니다.

DLG-M028의 "병합" 텍스트 입력란은 정확 일치 시 초록 강조, 오타 시 빨강 강조로 시각적 피드백을 즉시 제공합니다.

처리 중 상태에서는 화면 전체에 dim 오버레이가 표시되고 가운데에 큰 스피너와 함께 "회원 정보를 통합하고 있어요. 잠시만 기다려 주세요"라는 안내가 표시됩니다.

5분 이내 취소 메뉴는 페이지 상단에 카운트다운과 함께 표시되어 운영자가 즉시 인식할 수 있어야 합니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

회원 병합은 되돌리기 어려운 작업이며 외래키 cascade로 모든 회원 관련 테이블에 영향을 주므로, 이 화면을 지탱하는 정책이 매우 엄격합니다.

병합 권한 정책은 본사 슈퍼관리자(전 지점 + 지점 간), 센터장(소속 지점 내), 그 외 모든 권한 차단입니다. 매니저 이하의 권한자가 병합을 처리하면 운영 실수의 영향이 너무 크기 때문에 권한이 엄격히 통제됩니다.

DLG-M028 텍스트 일치 정책은 "병합" 한글·영문 구분 엄격 입력으로 의도하지 않은 병합을 막는 안전장치입니다.

부 계정 비활성 처리 정책은 즉시 삭제 안 하고 `status=MERGED_INACTIVE`로 90일 보관 후 X11 PII 마스킹, 1년 후 hard delete(정책에 따라)입니다. 이 단계적 처리는 잘못된 병합을 복구할 가능성을 일정 기간 유지하기 위한 정책입니다.

5분 이내 취소 정책(선택적)은 별도 [최근 병합 취소] 메뉴를 통해 가장 최근 병합을 되돌리는 것입니다. 5분이 지나면 hard rollback이 불가능하므로 새 회원 등록으로 분리해야 합니다.

외래키 cascade 일괄 UPDATE 정책은 모든 회원 관련 테이블(consultations·payments·attendance·body_composition·classes·family_members·coupons·mileage 등)의 `member_id`를 부 → 주로 변경하는 것입니다. 트랜잭션 원자성이 보장되어 1개라도 실패하면 전체 롤백됩니다.

이용권 통합 정책은 양 계정의 활성 이용권을 모두 주 계정으로 이전하고 잔여 횟수·기간을 합산하는 것입니다. 동일 상품은 합산되고 다른 상품은 각각 유지됩니다.

마일리지 합산 정책은 부 계정 마일리지를 주 계정에 더하며 만료된 마일리지는 이전하지 않습니다.

결제 누적 합산 정책은 등급(MBR-EXT-03) 산정 기준이 되는 누적 결제 금액·이용 기간·방문 횟수가 합산되며 병합 트랜잭션 내부에서 등급 즉시 재산정 트리거가 발동됩니다.

가족 그룹 처리 정책은 주 계정의 가족 그룹이 유지되며 부 계정의 가족 연결은 해제됩니다. 부 계정이 다른 그룹의 대표였다면 그룹 자동 해체 + 운영자 알림이 발송됩니다.

미수금·환불·홀딩 처리 정책은 다음과 같습니다. 부 계정 미수금은 주 계정으로 이전(회원 채무 보존)되고, 환불 진행 중 결제는 병합 차단(완료 후 재시도)되고, 홀딩/정지/탈퇴 상태는 주 계정 상태가 우선됩니다.

지점 간 병합 정책은 본사 슈퍼관리자만 가능하며 일반 센터장은 동일 지점 내만 병합할 수 있습니다(RBAC 강화).

알림 발송 정책은 회원 본인에게 카카오 알림톡으로 "회원 정보가 통합되었어요"가 양 계정 등록 연락처 모두로 발송되는 것입니다.

병합 항목 선택 정책은 이름·연락처·프로필 사진·생년월일·이메일·주소는 주/부 중 선택 가능하고 그 외 필드는 주 계정 우선 자동입니다.

PII 정합성 정책은 병합 후 부 계정의 이름·연락처가 주 계정으로 통합되거나 부 계정에 그대로 남아 PII 마스킹 정책(X11) 대상이 되는 것입니다.

감사 로그 상세도 정책은 병합 사유 / 선택한 필드 값 / 양 계정 ID / 통합 후 회원 ID / 운영자 / 시각이 모두 기록되는 것입니다. 사후 추적성이 매우 중요한 작업이기 때문입니다.

미성년자·사망 케이스 정책은 본사 슈퍼관리자만 처리 가능하며 사망확인서·동의서 등 증빙 첨부가 별도 시스템으로 요구됩니다. 일반 매니저나 센터장이 임의로 처리할 수 없는 민감 케이스입니다.

이상의 모든 정책은 이 화면을 구현하고 운영하는 사람이 별도 문서 없이 이 한 장으로 이해할 수 있도록 풀어 적었습니다. 정책이 바뀌면 이 문서가 함께 갱신되어야 하며, 코드 변경과 정책 변경은 항상 짝지어 진행됩니다.
