## 2. 다이얼로그 목적

탈퇴 처리 다이얼로그는 회원을 탈퇴 상태(`status=WITHDRAWN`)로 변경하기 전에 개인정보 마스킹 처리 및 서비스 이용 중단 사실을 안내하고 최종 확인을 받는 모달입니다. 또한 탈퇴/삭제 회원을 활성 상태로 복구하는 역방향 모드도 함께 처리합니다.

탈퇴는 단순 비활성이 아닙니다. 회원 데이터는 보존되지만 서비스 이용이 즉시 중단되고 X11 PII 마스킹 90일 카운트가 시작됩니다. 잘못된 탈퇴는 회원 클레임과 정산 문제를 일으키므로 신중한 확인이 필요합니다.

이 모달은 세 가지 모드로 동작합니다. 단일 탈퇴 모드(한 명의 회원 탈퇴), 일괄 탈퇴 모드(2명 이상 일괄 탈퇴, 매니저 이상 권한 + "탈퇴" 텍스트 직접 입력 안전장치), 역방향 복구 모드(탈퇴/삭제 회원의 복구 확인).

## 3. 부모 화면 호출 맥락

### SCR-M001 회원 목록에서의 호출

회원 목록의 일괄 작업 바에서 "일괄 탈퇴" 버튼(owner 이상)을 누르면 일괄 모드로 호출됩니다. 선택된 회원이 한 명이면 단일 모드, 두 명 이상이면 일괄 모드입니다. 일괄 모드에서는 안전 장치로 사용자가 "탈퇴" 텍스트를 입력해야 확인 버튼이 활성화됩니다.

삭제·탈퇴 회원 보기 토글이 켜진 상태에서 회원 행의 "복구" 버튼을 누르면 역방향 모드로 열립니다.

확인 성공 후 부모 화면의 회원 행 상태 배지가 즉시 갱신되거나 회원 목록에서 사라지며(필터 적용 따라) 성공 토스트가 표시됩니다. 일괄 모드 부분 실패 시 결과 카드와 실패 리포트 CSV 다운로드 링크가 제공됩니다.

### SCR-M004 회원 상세에서의 호출

회원 상세 헤더의 "탈퇴" 버튼으로 호출됩니다. 단일 모드로 열려 사유를 선택하고 확인합니다. 미수금이나 미사용 이용권이 있으면 강제 탈퇴/정산 후 탈퇴 선택 모달이 추가로 표시되며 강제 탈퇴는 권한자만 가능합니다.

탈퇴·삭제 상태 회원의 회원 상세에서 헤더의 "복구" 버튼(권한자만 노출)으로 역방향 복구 모드가 호출됩니다.

## 4. 모달 구성요소

### 정방향(탈퇴 처리) 모드

모달 상단에는 "탈퇴 처리하시겠습니까?"라는 제목과 함께 빨강 톤의 경고 메시지 "탈퇴 처리 시 개인정보가 마스킹되며 서비스 이용이 중단됩니다"가 강조 표시됩니다.

단일 모드에서는 대상 회원명과 현재 상태가 카드 형태로 표시됩니다. 일괄 모드에서는 선택된 회원 수(예: "총 50명 선택"), 처리 가능 회원 수, 차단 회원 수가 카드로 나란히 표시되고 차단 회원이 있으면 사유별로 묶어 보여줍니다. 차단 사유는 미수금이 있는 경우, 환불 필요 이용권을 가진 경우, 진행 중인 예약이 있는 경우, 가족 회원의 대표 회원인 경우, 이미 탈퇴·삭제된 경우의 다섯 가지로 분류됩니다.

탈퇴 사유 선택 드롭다운이 있으며 본인 요청 / 장기 미이용 / 기타 중에서 고릅니다.

일괄 모드(2명 이상)에서는 안전 장치로 사용자가 "탈퇴"라는 단어를 텍스트 박스에 직접 입력해야 [확인] 버튼이 활성화됩니다. 단일 모드에서는 이 텍스트 입력 단계가 생략됩니다.

[확인] 버튼과 [취소] 버튼이 하단에 있습니다.

### 역방향(복구) 모드

모달 상단에 "회원을 복구하시겠습니까?"라는 제목과 함께 대상 회원명·현재 상태(WITHDRAWN 또는 DELETED)·복구 후 상태(ACTIVE)가 표시됩니다.

복구 시 동일 연락처를 가진 신규 회원이 이미 존재하면 "동일 연락처의 신규 회원이 있어요" 충돌 안내가 표시되고 강제 복구(부 계정으로 분리) / 회원 병합으로 이동 / 취소 중에서 선택하게 됩니다.

[복구] 버튼은 일반 복구 시 즉시 활성, 충돌 시 충돌 처리 선택 후 활성화됩니다.

## 5. 동작 흐름

### 탈퇴 흐름

[확인] 클릭 시 단일 모드는 `PATCH /api/members/:id/status`(status=WITHDRAWN), 일괄 모드는 `POST /api/members/bulk-action`(action=WITHDRAW)이 호출됩니다. 요청 본문에는 회원 ID, 사유, version, "탈퇴" 텍스트 입력 결과(일괄 모드)가 포함됩니다.

성공 시 처리 가능 회원만 탈퇴 처리되어 상태가 `WITHDRAWN`으로 변경되고, X11 PII 마스킹 배치(매일 새벽 5시)의 대상으로 90일 카운트가 등록됩니다. 차단 회원은 변경 없이 그대로 두고 결과 토스트와 실패 리포트 CSV에서 회원별 차단 사유가 표시됩니다.

모든 처리 결과는 SCR-097 감사 로그에 actor_id·member_ids[]·action=WITHDRAW·reason·timestamp로 기록됩니다.

회원이 가족 그룹 대표이면 자동 분리 + 다음 활성 회원 자동 승계가 발동됩니다. 모든 멤버 비활성 시 그룹 자동 해체됩니다.

### 복구 흐름

[복구] 클릭 시 `POST /api/members/:id/restore`가 호출됩니다. 백엔드는 동일 연락처 신규 회원 검증 후 상태를 ACTIVE로 변경합니다.

충돌 시 강제 복구(부 계정으로 분리)를 선택하면 별도 회원 ID로 복구되고, 회원 병합으로 이동을 선택하면 MBR-EXT-01 회원 병합 화면(SCR-M007)으로 진입합니다.

## 6. 권한별 처리

단일 탈퇴는 매니저 이상이 가능합니다. 일괄 탈퇴는 owner(센터장) 이상으로 제한되어 회원 목록의 "일괄 탈퇴" 버튼이 매니저에게는 hidden 처리됩니다.

회원 복구는 owner·manager·슈퍼관리자가 가능합니다. 권한이 없으면 복구 버튼이 부모 화면에 노출되지 않습니다.

미수금/이용권 잔여가 있는 회원의 강제 탈퇴는 owner 이상만 가능합니다.

FC·트레이너·스태프·프런트·readonly는 이 모달에 진입할 수 없습니다.

## 8. 데이터 흐름과 외부 연동

탈퇴: `PATCH /api/members/:id/status` 또는 `POST /api/members/bulk-action`. 복구: `POST /api/members/:id/restore`.

X11 PII 마스킹 배치(매일 새벽 5시)가 탈퇴 90일 경과 회원의 이름·연락처·이메일을 마스킹값으로 덮어씁니다. 1년 후 hard delete 정책(테넌트별)이 적용될 수 있습니다.

SCR-097 감사 로그 INSERT, NFR-19 알림 센터 회원 알림톡 발송(탈퇴 안내), 가족 그룹 자동 분리 트리거가 발동됩니다.

## 9. 예외 처리

차단 사유(미수금·환불 필요 이용권·진행 예약·가족 대표·이미 탈퇴) 회원은 일괄 모드에서 처리 불가 목록에 분리되며 사유와 함께 표시됩니다.

권한 부족(403)·동시 편집 충돌(409)·네트워크 끊김 처리는 일반 정책과 동일합니다.

복구 시 동일 연락처 신규 회원 존재 충돌은 강제/병합/취소 선택지로 처리됩니다.

일괄 모드 "탈퇴" 텍스트 오타는 빨강 강조 + [확인] 비활성으로 차단됩니다.

ESC/배경 클릭 시 입력 도중이면 "변경 사항이 사라집니다. 닫으시겠습니까?" 한 번 더 확인합니다.

## 10. 운영 정책

탈퇴 처리 정책은 status=WITHDRAWN으로 변경하며 데이터를 보존하는 것입니다. 회원이 추후 복귀할 가능성과 환불·정산 후속 처리 가능성을 위해 즉시 hard delete하지 않습니다.

X11 PII 마스킹 90일 정책은 탈퇴 후 90일이 경과한 회원의 이름·연락처·이메일을 자동 마스킹하는 것입니다. 본사 권한자가 사유 입력 시 일시 해제가 가능합니다.

일괄 탈퇴 권한 정책은 owner 이상으로 제한되며 1회 최대 100명까지로 제한됩니다.

일괄 탈퇴 안전장치 정책은 2명 이상 처리 시 "탈퇴" 텍스트 직접 입력 후 활성화입니다.

차단 사유 자동 검증 정책은 미수금·환불 필요·진행 예약·가족 대표·이미 탈퇴된 회원을 자동 제외하는 것입니다.

회원 복구 권한 정책은 owner·manager·슈퍼관리자에 한정합니다.

동일 연락처 신규 회원 충돌 처리 정책은 강제 복구(부 계정으로) / 회원 병합으로 이동 / 취소를 운영자가 직접 선택하는 것입니다.

가족 그룹 자동 분리 정책은 탈퇴 회원이 가족 그룹 대표였다면 다음 활성 회원이 자동 승계되고 모두 비활성이면 그룹 자동 해체되는 것입니다.

감사 로그 정책은 모든 탈퇴·복구 이벤트를 SCR-097에 기록합니다.
