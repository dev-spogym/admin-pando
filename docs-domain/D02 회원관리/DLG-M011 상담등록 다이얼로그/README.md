## 2. 다이얼로그 목적

상담 등록·수정 다이얼로그는 회원과의 상담 내용을 체계적으로 기록하거나 수정하는 모달입니다. 상담 일시, 유형, 채널, 상태, 결과, 연결 매출, 후속조치를 입력하여 상담 이력을 관리합니다. 회원 상세의 상담이력 탭에서 시간 순으로 누적됩니다.

운영 현장에서 FC가 D-7 만료 임박 회원에게 리텐션 상담을 진행한 후 결과를 기록하거나, 매니저가 콜·온라인 사전 상담 결과를 기록하거나, 상담 예약을 등록·관리할 때 사용됩니다.

## 3. 부모 화면 호출 맥락

회원 상세(SCR-M004) 상담이력 탭의 "상담 추가" 버튼(등록 모드) 또는 기존 상담 행의 "수정" 버튼(수정 모드)으로 호출됩니다.

확인 성공 후 부모 화면의 상담이력 목록이 즉시 갱신됩니다. 수정 모드에서는 변경된 행이 갱신됩니다.

## 4. 모달 구성요소

모달 상단에는 "상담 이력 추가" 또는 "상담 이력 수정" 제목이 표시됩니다.

상담 일시 입력란은 캘린더 + 시간 선택이며 기본값은 등록 모드에서 현재 시각, 수정 모드에서 기존 값입니다. 수정 가능합니다.

상담 유형 선택 드롭다운은 상담 / OT / 체험 / 재등록상담 중 단일 선택입니다.

상담 채널 선택 드롭다운은 방문 / 전화 / 카카오톡 / DM / SNS / 기타 중 단일 선택입니다.

담당자 입력란은 현재 로그인 관리자가 기본값으로 채워지며 변경 가능합니다.

상태 선택 드롭다운은 예정 / 완료 / 취소 / 노쇼 중 단일 선택입니다.

결과 선택 드롭다운은 등록 / 미등록 / 보류 중 단일 선택입니다.

연결 매출 선택 드롭다운은 선택 사항이며 회원의 결제 이력 중 하나를 연결할 수 있습니다.

상담 내용 입력 텍스트 영역과 후속조치 입력란이 있습니다.

[저장] 버튼과 [취소] 버튼이 하단에 있습니다.

## 5. 동작 흐름

[저장] 클릭 시 등록은 `POST /api/consultations`, 수정은 `PATCH /api/consultations/:id`를 호출합니다. 백엔드는 Supabase `consultations` 테이블에 저장하며 `memberId`·`branchId`·`scheduledAt`·`completedAt`·`channel` 컬럼을 사용합니다.

수정 시 SCR-097 감사 로그의 상세 메시지 또는 변경 후 값에 `상담 이력 수정됨` 문구가 자동 포함됩니다(단순 수정이라도 사실관계가 바뀔 수 있으므로 명시).

성공 시 모달이 닫히고 부모 화면의 상담이력 목록이 갱신되며 토스트가 표시됩니다.

[취소] 또는 ESC 또는 배경 클릭은 모달을 즉시 닫습니다.

## 6. 권한별 처리

owner·manager·fc가 상담 등록·수정 가능합니다. trainer·staff는 본인 작성 건만 24시간 이내 수정 가능(정책에 따라). readonly는 조회만 가능합니다.

작성자 본인 + 상위 권한자만 수정 가능합니다. FC가 작성한 상담은 매니저 이상이 수정 가능합니다.

## 7. 화면 상태

| 상태 | 설명 |
|---|---|
| 기본 표시 (등록) | 빈 폼 + 담당자 자동 채움 |
| 기본 표시 (수정) | 기존 값 자동 채움 |
| 입력 중 | dirty 마크 |
| 처리 중 | 버튼 비활성 + 로딩 |
| 완료 | 모달 닫기 + 부모 갱신 + 토스트 |

## 8. 데이터 흐름

Supabase `consultations` 테이블 INSERT/UPDATE. `consultations` 컬럼: `id`, `memberId`, `branchId`, `scheduledAt`, `completedAt`, `channel`, `type`, `consultantId`, `status`, `result`, `linkedPaymentId`, `content`, `followUp`, `createdAt`, `updatedAt`.

SCR-097 감사 로그 INSERT, 수정 시 `상담 이력 수정됨` 문구 자동 포함.

## 9. 예외 처리

권한 부족·동시 편집·네트워크 끊김은 일반 정책과 동일합니다.

작성자 본인이 아닌 경우 수정 시도 시 백엔드 403 + "본인 작성 상담만 수정 가능" 안내입니다.

## 10. 운영 정책

상담 데이터 저장소 정책은 Supabase `consultations`이며 `memberId`·`branchId`·`scheduledAt`·`completedAt`·`channel`을 사용하는 것입니다.

상담 수정 시 히스토리 로그 자동 prefix 정책은 변경 후 메시지에 `상담 이력 수정됨` 문구가 자동 포함되어야 하는 것입니다. 사후 추적성을 위한 정책입니다.

작성자 권한 정책은 작성자 본인 + 상위 권한자만 수정 가능합니다.

상담 채널 6종 정책은 방문/전화/카카오톡/DM/SNS/기타로 일관 정의됩니다.
