## 2. 다이얼로그 개요와 목적

중복 결제 경고 다이얼로그는 동일 회원에 대해 동일 상품이 단기간(5분 이내)에 재등록될 경우 직원에게 경고를 표시하는 모달입니다. 실수로 인한 이중 결제 등록을 방지하며, 직원이 의도적인 재구매임을 확인한 경우에만 영수증 기반 결제 등록을 계속 진행할 수 있도록 합니다. 운영 실수와 부정 결제를 사전에 차단하는 안전 장치 역할을 하며, 운영자의 의도 확인과 추적성 확보가 핵심 목적입니다.

## 3. 호출 트리거와 진입 경로

이 다이얼로그는 단일 트리거로 호출됩니다. SCR-S003 결제 처리 화면에서 [결제 등록] 버튼을 누른 직후, 또는 DLG-S003 결제 확인의 [결제 완료 등록]을 누른 직후 시스템이 중복 결제 검사 API를 호출하여 동일 회원·동일 상품·동일 금액의 결제가 5분 이내 있으면 DLG-S003 대신 또는 그 다음에 이 모달이 자동으로 표시됩니다.

중복 결제 감지 윈도우는 5분이 기본이며, 운영 정책으로 조정 가능합니다. 매니저 이상은 승인 후 진행할 수 있으며, FC는 매니저에게 승인 요청을 보내는 추가 검증 흐름이 적용될 수 있습니다.

## 4. 레이아웃과 UI 구성

다이얼로그는 화면 중앙에 표시되는 중간 크기(데스크톱 약 500px 너비) 모달입니다. 모달 상단에 경고 아이콘(노랑 또는 빨강 삼각형)과 "중복 결제 경고"라는 제목이 표시됩니다. 우측 상단 [X 닫기] 아이콘은 표시되지 않습니다(경고 보호 정책).

상단 헤더 아래에는 경고 메시지가 큰 폰트로 표시됩니다. "동일 회원에게 동일 상품이 최근 결제된 이력이 있습니다"라는 안내가 빨강 또는 강조 색상으로 표시됩니다.

경고 메시지 아래에는 기존 결제 정보 카드가 있습니다. 중복 감지된 이전 결제의 날짜, 시간, 상품명, 금액, 처리 직원이 표시되어 직원이 기존 결제와 새 결제의 차이를 시각적으로 확인할 수 있습니다. 두 결제의 시간 차이(예: "3분 전")도 함께 표시됩니다.

기존 결제 정보 아래에는 현재 진행 중인 결제의 요약이 표시됩니다. 회원명, 상품명, 금액이 한 행으로 표시되어 무엇이 중복으로 감지되었는지를 명확히 알립니다.

가장 아래에는 두 개의 액션 버튼이 가로로 배치됩니다. 좌측에는 [취소] 버튼(회색 보조 색상), 우측에는 [계속 진행] 버튼(빨강 또는 강조 색상)이 배치되어 운영자가 의도적으로 진행할 때 강조 색상이 위험을 시각적으로 알립니다.

ESC 키 또는 배경 클릭으로 닫히지 않습니다(경고 보호 정책).

## 5. 버튼·아이콘·링크 액션 전체 정의

[계속 진행] 버튼은 중복임을 인지하고 결제 완료 등록을 그대로 진행합니다. 모달이 닫히고 결제 등록 API가 호출되어 DLG-S003 결제 확인 모달(또는 결제 완료 화면)로 자동 진행됩니다. 운영자의 진행 선택은 SCR-097 감사 로그에 기록됩니다.

[취소] 버튼은 결제를 중단하고 SCR-S002 POS 화면으로 복귀합니다. 입력된 결제 정보는 SCR-S003에 유지되어, 운영자가 다시 결제 시도를 할 수 있습니다(이번에는 5분이 지나서 중복 경고가 발동하지 않거나 다른 조건이 변경된 경우).

기존 결제 정보 카드의 결제 ID는 클릭 가능하며, 클릭 시 DLG-S001 매출 상세를 별도 모달로 열어 기존 결제의 전체 정보를 확인할 수 있습니다.

모달에는 회원 상세나 상품 상세 같은 다른 페이지 이동 액션은 없습니다. 결제 진행 의사 결정에만 집중합니다.

모든 버튼은 클릭 후 응답이 돌아오기 전까지 자동으로 비활성화됩니다.

## 6. 다이얼로그 상태와 예외 처리

기본 표시 상태는 경고 메시지·기존 결제 정보·현재 결제 요약·액션 버튼이 표시되는 상태입니다.

저장/처리 중 상태는 [계속 진행] 클릭 후 결제 등록 API가 호출되는 중으로, 두 버튼이 모두 비활성화됩니다.

완료 상태는 결제 등록이 성공적으로 진행되어 결제 완료 화면으로 전환된 상태입니다.

실패 상태는 결제 등록 실패 시 SCR-S003 결제 입력 화면으로 복귀하고 토스트가 표시되는 상태입니다.

매니저 승인 대기 상태는 FC가 [계속 진행]을 시도했을 때 매니저 승인이 필요한 경우, 추가 승인 요청 안내가 표시되는 상태입니다(정책 토글).

예외 케이스별 처리는 다음과 같이 정의됩니다. 동시에 다중 운영자가 같은 회원에게 결제 시도 시 두 운영자 모두 중복 경고를 받을 수 있으며, row-level lock으로 실제 결제 등록은 직렬화됩니다. 기존 결제가 이미 환불된 경우에도 중복 감지 윈도우(5분)에 포함되며 안내 텍스트에 "(환불됨)" 라벨이 추가됩니다. 매니저 승인 토글이 켜진 정책에서 FC가 [계속 진행]을 시도하면 매니저 승인 요청 알림이 발송되고 결제는 보류됩니다. 운영자가 [취소]를 누른 후 SCR-S003에서 결제 정보를 수정하지 않고 다시 [결제 등록]을 누르면 동일한 중복 경고가 다시 발동합니다.

## 7. 권한별 처리

슈퍼관리자·본사 최고관리자·Owner(지점장)·매니저는 [계속 진행]을 자유롭게 사용할 수 있습니다.

FC는 정책에 따라 [계속 진행] 시 매니저 승인 요청이 발송될 수 있습니다(정책 토글). 승인 전에는 결제 등록이 보류됩니다.

트레이너·스태프는 SCR-S003 자체 접근이 차단되므로 이 모달도 호출되지 않습니다.

readonly는 진입 차단됩니다.

모든 [계속 진행]과 [취소] 선택은 SCR-097 감사 로그에 기록됩니다.

## 8. 데이터 흐름과 외부 연동

중복 결제 검사는 `POST /api/payments/check-duplicate` API로 호출됩니다. 응답으로는 중복 감지 여부, 기존 결제 정보(결제 ID·날짜·상품명·금액·처리 직원), 시간 차이가 내려옵니다.

[계속 진행] 클릭 시 `POST /api/payments/receipt-registration` API가 호출되며, 중복 경고 발동 후 진행임을 알리는 플래그(`override_duplicate=true`)가 함께 전송됩니다.

[취소] 클릭 시 SCR-S002로 복귀하며 SCR-097 감사 로그에 "중복 경고 취소" 이벤트가 기록됩니다.

중복 결제 감지 윈도우는 5분이 기본이며, 운영 정책 토글로 조정 가능합니다(예: 1분·10분).

매니저 승인 워크플로우(정책 토글) 활성 시 FC가 [계속 진행]을 시도하면 매니저 승인 요청이 NFR-19 알림 센터로 발송됩니다.

감사 로그는 중복 경고 발동·진행·취소를 모두 SCR-097에 기록합니다. 기록 필드는 `actor_id`, `payment_id`, `duplicate_payment_id`, `action`(triggered/proceeded/cancelled), `timestamp`입니다.

## 10. 핵심 디자인 요청사항

다이얼로그는 화면 중앙에 표시되는 중간 크기(약 500px) 모달로, 경고 의도가 시각적으로 강하게 전달되도록 디자인됩니다.

모달 상단의 경고 아이콘은 노랑 삼각형(주의) 또는 빨강 삼각형(경고)으로 표시되어 위험 수위에 따라 색상이 분기됩니다. 경고 메시지는 페이지 전체에서 가장 큰 폰트로 빨강 또는 강조 색상으로 표시됩니다.

기존 결제 정보 카드와 현재 결제 요약은 좌우 또는 상하로 나란히 배치되어 운영자가 두 결제를 시각적으로 비교할 수 있도록 합니다. 시간 차이("3분 전")는 강조 색상으로 표시됩니다.

[계속 진행] 버튼은 빨강 또는 강조 색상의 큰 버튼으로 우측에 배치되어 위험이 동반된 액션임을 시각적으로 알립니다. [취소] 버튼은 좌측에 회색 보조 색상으로 배치됩니다.

ESC 또는 배경 클릭으로 닫히지 않음을 시각적으로 표현하기 위해 배경 오버레이는 진한 색상으로 처리하고 모달 외부 클릭 시 미세한 흔들림 애니메이션이 적용될 수 있습니다.

진행 스피너와 로딩 스켈레톤은 매출관리 전체에서 동일한 톤으로 통일됩니다.

## 11. 운영 정책

중복 결제 감지 윈도우 정책은 5분이 기본이며, 운영 정책 토글로 조정 가능합니다. 동일 회원·동일 상품·동일 금액 기준입니다.

권한별 진행 권한 정책은 매니저+ 가 자유롭게 [계속 진행] 가능하며, FC는 매니저 승인 워크플로우(정책 토글)가 활성된 경우 승인을 받아야 진행 가능합니다.

감사 로그 정책은 중복 경고 발동·진행·취소를 모두 SCR-097에 기록합니다. 기록 필드는 `actor_id`, `payment_id`, `duplicate_payment_id`, `action`, `timestamp`입니다.

트랜잭션 보호 정책은 모달이 ESC 또는 배경 클릭으로 닫히지 않도록 보장합니다.

매니저 승인 워크플로우 정책(토글)은 FC의 [계속 진행]을 매니저 승인 후 처리하도록 합니다. 부정 결제 사고가 잦은 환경에서 활성화하며, 일반 운영에서는 비활성화될 수 있습니다.

환불된 기존 결제 처리 정책은 기존 결제가 이미 환불된 경우에도 중복 감지 윈도우에 포함되며 안내 텍스트에 "(환불됨)" 라벨을 추가합니다. 환불 후 재결제는 정상적인 운영 흐름이지만, 5분 이내 재결제는 여전히 운영 실수 가능성이 있으므로 경고를 유지합니다.

비정상 패턴 알림 정책은 동일 운영자가 짧은 시간에 다중 중복 경고를 발동시키면 본사 슈퍼관리자에게 알림이 발송되어 운영 실수나 부정 결제 의심을 조기에 감지합니다.

이상의 모든 정책은 이 다이얼로그를 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다.
