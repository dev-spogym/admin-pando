## 2. 다이얼로그 개요와 목적

결제 확인 다이얼로그는 현장 결제 등록을 최종 확정하기 전 구매자·상품·금액·포인트 사용액·결제일시·영수증 첨부 상태를 한 번 더 검토하는 모달입니다. 실수로 인한 잘못된 등록을 방지하고, 외부 POS 또는 현금 수납이 정상 완료된 건만 CRM에 결제완료와 회원/이용권 등록 완료 상태로 반영합니다. 이 모달은 결제 등록 트랜잭션의 마지막 게이트이며, 한 번 [결제 완료 등록]을 누르면 결제완료가 즉시 적용되고 매출 현황과 회원 카드가 갱신됩니다.

## 3. 호출 트리거와 진입 경로

첫 번째이자 주된 트리거는 SCR-S003 결제 처리 화면의 [결제 등록] 버튼 클릭입니다. 영수증 첨부, 금액 일치, 결제일시 입력, 필수 회원/포인트 검증을 모두 통과한 상태에서만 호출됩니다.

두 번째 트리거는 SCR-S002 POS 판매에서 긴급 확인이 필요한 경우(예: 결제 직전 확인 한 번 더 보기)로 매우 드물게 사용됩니다.

다이얼로그가 열리는 시점에 시스템은 중복 결제 감지를 수행하며, 동일 회원·동일 상품·동일 금액의 결제가 5분 이내 있으면 DLG-S003 대신 DLG-S004 중복 결제 경고가 먼저 호출됩니다.

## 4. 레이아웃과 UI 구성

다이얼로그는 화면 중앙에 표시되는 큰 크기(데스크톱 약 700px 너비) 모달입니다. 모달 상단에 "결제 확인" 제목이 표시되고, 우측 상단에 [X 닫기] 아이콘은 표시되지 않습니다(트랜잭션 보호).

상단 헤더 아래에는 구매자 정보가 카드형으로 표시됩니다. 선택된 회원 이름과 연락처, 비회원이면 "비회원" 라벨이 표시됩니다.

구매자 정보 아래에는 상품 목록이 표 형태로 표시됩니다. 결제 예정 상품명·수량·단가가 행으로 표시되고, 마지막 행에 총 정가 합계가 표시됩니다.

상품 목록 아래에는 금액 영역이 있습니다. 정가 / 할인 항목 / 할인 금액 / 최종 결제 금액이 순서대로 표시되며, 최종 결제 금액은 페이지 전체에서 가장 큰 폰트로 강조됩니다.

금액 영역 아래에는 결제 방식 카드가 있습니다. 결제 경로(현장 결제 POS / 결제링크 발송), 링크 만료일시(LINK인 경우), 수납 방식(현장 전액 / 계약금 등록 / 잔액 등록), 당일 등록 금액과 잔액(계약금 등록인 경우)이 표시됩니다.

결제 방식 카드 아래에는 현장 결제 등록 정보 카드가 있습니다. 결제 수단(혼합결제 행 요약), 결제가격(수단별 합계), 포인트 사용 여부와 사용액, 결제일시, 영수증 파일명(또는 파일 수), FC 메모가 표시됩니다.

가장 아래에는 [결제 완료 등록] 버튼과 [취소] 버튼이 가로로 배치됩니다. [결제 완료 등록] 버튼은 강조 색상의 큰 버튼이며, 처리 중에는 "등록 중..."으로 변경되고 비활성화됩니다. [취소] 버튼은 모달을 닫고 SCR-S003 결제 입력 화면으로 복귀합니다.

ESC 키 또는 배경 클릭으로 닫히지 않습니다(트랜잭션 보호 정책). 명시적인 [취소] 또는 [결제 완료 등록] 버튼만 사용 가능합니다.

## 5. 버튼·아이콘·링크 액션 전체 정의

[결제 완료 등록] 버튼은 결제 등록 API(`POST /api/payments/receipt-registration`)를 호출합니다. 처리 중에는 버튼이 "등록 중..."으로 변경되고 모든 입력이 잠깁니다. 성공 시 모달이 닫히고 부모 화면이 결제 완료 화면으로 전환되며, 실패 시 실패 사유 토스트가 표시되고 입력값은 유지됩니다.

[취소] 버튼은 모달을 닫고 SCR-S003 결제 입력 화면으로 복귀합니다. 입력된 정보는 모두 유지되어 운영자가 필요시 수정 후 다시 [결제 등록]을 시도할 수 있습니다.

영수증 파일명을 클릭하면 영수증 미리보기가 별도 모달로 표시됩니다.

모달에는 회원 상세 진입, 환불 진입 같은 다른 액션 버튼이 없습니다. 트랜잭션 최종 확인에만 집중합니다.

모든 버튼은 클릭 후 응답이 돌아오기 전까지 자동으로 비활성화됩니다.

## 6. 다이얼로그 상태와 예외 처리

기본 표시 상태는 부모 화면에서 입력한 모든 결제 정보가 카드형으로 표시되는 상태입니다.

저장/처리 중 상태는 [결제 완료 등록] 클릭 후 서버 처리 중으로, 버튼이 "등록 중..."으로 변경되고 모든 입력이 잠깁니다. 60초 타임아웃이 적용됩니다.

완료 상태는 결제 등록 성공 후 부모 화면이 결제 완료 화면으로 전환되며 모달이 자동 닫히는 상태입니다.

실패 상태는 결제 저장 실패, 영수증 업로드 실패, 동시성 충돌 등으로 실패한 상태입니다. 토스트가 표시되고 입력값은 유지됩니다.

중복 결제 경고 상태는 5분 이내 동일 결제 감지 시 DLG-S004 중복 결제 경고 모달이 먼저 호출되는 상태입니다.

예외 케이스별 처리는 다음과 같이 정의됩니다. 결제 저장 실패 시 "결제 등록에 실패했습니다" 토스트와 재시도 안내가 표시됩니다. 영수증 업로드 실패 시 "영수증 업로드에 실패했습니다" 토스트와 재시도가 안내됩니다. 동시성 충돌(포인트 잔액 락) 시 "잠시 후 다시 시도해주세요" 안내와 자동 재시도가 일어납니다. 60초 타임아웃 시 처리 결과 확인 안내가 표시됩니다. 중복 결제 감지 시 DLG-S004로 분기됩니다. 결제일시가 미래 시각인 경우 차단되고 정정이 안내됩니다.

## 7. 권한별 처리

슈퍼관리자·본사 최고관리자·Owner(지점장)·매니저·FC는 결제 확인 모달을 사용 가능합니다. FC는 1회 등록 최대 1000만원 한도가 적용됩니다.

트레이너·스태프는 SCR-S003 자체 접근이 차단되므로 이 모달도 호출되지 않습니다.

readonly는 진입 차단됩니다.

권한 차단 시 호출 화면에서 권한 안내, 모든 권한 차단 이벤트는 감사 로그에 기록됩니다.

## 8. 데이터 흐름과 외부 연동

[결제 완료 등록] 버튼은 `POST /api/payments/receipt-registration` API를 호출합니다. 요청에는 장바구니 상품, 회원 ID, 혼합결제 행, 포인트 사용액, 결제일시, 영수증 파일 ID, VAN/POS 결과, 지점 귀속 필드, 수납 방식, 이용권 개시 옵션, 잔액 처리 방식, 할인 정보가 모두 포함됩니다.

트랜잭션 내에서 결제 INSERT, 회원/이용권 활성화, 포인트 차감, 재고 감소, SAL-04 선수익금 등록, PAY-03 미수금 등록(계약금 + 잔액인 경우), SAL-EXT-02 세금계산서 발행 가능 큐 등록(법인 회원), 감사 로그 INSERT가 함께 커밋됩니다.

중복 결제 감지는 `POST /api/payments/check-duplicate` API로 모달 진입 직전 또는 [결제 완료 등록] 직후에 호출되어 5분 이내 동일 결제를 감지합니다.

PAY-01 결제 webhook은 SCR-S001 매출 현황·SCR-M004 회원 카드에 5초 이내 자동 반영됩니다.

감사 로그는 결제 등록 시도·성공·실패·중복 경고 발동을 모두 SCR-097에 비동기로 기록합니다.

## 10. 핵심 디자인 요청사항

다이얼로그는 데스크톱에서 큰 크기(약 700px)로 표시되며, 모바일에서는 풀스크린 시트로 자동 전환됩니다. 부모 화면을 어둡게 처리하고 중앙에 표시되며, ESC 또는 배경 클릭으로는 닫히지 않습니다(트랜잭션 보호).

최종 결제 금액은 페이지 전체에서 가장 큰 폰트로 빨강 또는 강조 색상으로 표시되어, 운영자가 결제 금액을 마지막으로 확인할 수 있도록 합니다.

구매자 정보, 상품 목록, 금액, 결제 방식, 결제 등록 정보는 각각 분리된 카드형 섹션으로 표시되어 빠르게 스캔 가능합니다.

[결제 완료 등록] 버튼은 모달 하단 우측에 큰 강조 색상 버튼으로 배치되며, 처리 중에는 작은 스피너와 "등록 중..." 텍스트가 함께 표시됩니다. [취소] 버튼은 좌측 또는 [결제 완료 등록] 옆에 보조 색상으로 배치됩니다.

영수증 파일 영역에는 작은 영수증 아이콘과 파일명이 표시되고, 호버 시 미리보기 가능함이 명확히 인지됩니다.

진행 스피너와 로딩 스켈레톤은 매출관리 전체에서 동일한 톤으로 통일됩니다.

## 11. 운영 정책

영수증 첨부 필수 정책은 현장 결제 등록이 영수증 파일 첨부 없이 완료될 수 없음을 명시합니다. 첨부가 없으면 SCR-S003의 [결제 등록] 버튼이 활성화되지 않아 DLG-S003 자체가 호출되지 않습니다.

금액 일치 검증 정책은 `혼합결제 행 합계 + 포인트 사용액 = 장바구니 최종 합계`가 정확히 일치해야 [결제 등록]이 활성화됨을 보장합니다.

결제 완료 즉시 반영 정책은 [결제 완료 등록] 성공 시 결제완료와 회원/이용권 등록 완료가 동시에 반영되며, 5초 이내 SCR-S001 매출 현황과 SCR-M004 회원 카드가 갱신됨을 보장합니다.

중복 결제 감지 윈도우 정책은 5분이며, 동일 회원·동일 상품·동일 금액 결제가 5분 이내 재등록되면 DLG-S004로 분기됩니다.

트랜잭션 보호 정책은 모달이 ESC 또는 배경 클릭으로 닫히지 않도록 보장합니다. 명시적인 [취소] 또는 [결제 완료 등록]만 사용 가능합니다.

권한별 결제 한도 정책은 FC가 1회 등록 최대 1000만원이며, 한도 초과 시 매니저 승인 요청이 발송됩니다. 매니저+ 는 무제한입니다.

감사 로그 정책은 결제 등록 시도·성공·실패를 모두 SCR-097에 기록합니다. 기록 필드는 `payment_id`, `actor_id`, `amount`, `method`, `receipt_file_id`, `result`, `timestamp`입니다.

영수증 보관 정책은 영수증 파일을 결제 기록과 연결해 5년간 보관합니다.

이상의 모든 정책은 이 다이얼로그를 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다.
