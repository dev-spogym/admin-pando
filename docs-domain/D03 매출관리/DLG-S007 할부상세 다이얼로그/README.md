## 2. 다이얼로그 목적과 사용 맥락

할부 상세 다이얼로그는 회원이 분할 납부(`collectionMode=INSTALLMENT_PLAN`)로 가입한 할부 계약의 전체 회차 진행 상황을 한 화면에서 보고, 그 자리에서 미납 회차의 납입 처리를 시작하거나 중도 상환을 요청하는 도구입니다. SAL-EXT-01 운영 시나리오에서 매월 출근 직후 카운터 매니저가 가장 자주 여는 다이얼로그 중 하나이며, 한 명의 회원이 가진 여러 할부 계약 중에서 어느 회차가 완료되었고 어느 회차가 미납되었는지를 즉시 파악하는 핵심 도구입니다.

이 다이얼로그가 다루는 운영 흐름은 다섯 가지로 나뉩니다. 첫째는 매월 회차 입금 확인 흐름으로, 운영자가 통장에서 회원 입금을 확인한 뒤 다이얼로그에서 해당 회차를 선택해 납입 처리를 시작합니다. 둘째는 회원 상담 흐름으로, 회원이 "내가 몇 회차까지 냈는지" 문의했을 때 운영자가 즉시 답할 수 있도록 정보를 제공합니다. 셋째는 미납 회차 회수 흐름으로, 30일+ 연체된 회차가 빨강 강조로 표시되어 운영자가 즉시 회원 연락에 들어갑니다. 넷째는 중도 상환 흐름으로, 회원이 잔여 회차를 일괄 납부하고자 할 때 다이얼로그에서 중도 상환 액션을 진행합니다. 다섯째는 계약 해지(환불 진입) 흐름으로, 할부 진행 중 환불이 발생해 잔여 회차를 일괄 취소해야 할 때 SAL-EXT-04 환불 화면으로 진입합니다.

다이얼로그는 회차 단위로 데이터를 표시하며, 한 회차마다 예정일·완료일·금액·상태·납입 처리 액션이 한 행으로 묶여 있습니다. 미납 회차에는 경고 색상과 아이콘이 함께 표시되어 시각적으로 즉시 식별됩니다.

## 3. 호출 트리거와 부모 화면 컨텍스트

이 다이얼로그는 다음 네 가지 진입점에서 호출됩니다.

첫 번째 진입점은 SCR-S009 할부 결제 관리 페이지의 계약 행 클릭입니다. 행 어디를 누르더라도 다이얼로그가 열립니다(액션 버튼 영역 제외). 부모 화면은 다이얼로그에 `installmentId`를 전달하고, 다이얼로그는 이를 기반으로 회차 목록을 조회합니다.

두 번째 진입점은 SCR-M004 회원 상세 페이지의 할부 이력 탭에서 특정 할부 계약 행을 클릭하는 경우입니다. 회원 단위로 묶인 할부 이력 중 한 건을 골라 진입합니다.

세 번째 진입점은 SCR-S008 미수금 관리에서 발생 유형이 "정기 할부 미납"인 미수금 행의 "할부 상세 보기" 링크입니다. 미수금 화면에서 회차 미납을 발견한 운영자가 그 미수금이 속한 할부 계약 전체를 확인하기 위해 진입합니다.

네 번째 진입점은 DLG-S001 매출 상세 다이얼로그의 할부 연계 카드에서 "할부 상세 보기" 링크입니다. 원 매출 상세를 보던 운영자가 그 매출에 묶인 할부 계약의 회차 진행을 확인하기 위해 진입합니다.

다이얼로그가 받는 컨텍스트는 `installmentId`(필수), 부모 화면 식별자(복귀 처리용), 그리고 부모 화면에서 미리 캐시된 일부 요약 정보(있을 경우)입니다. 캐시는 첫 표시 깜빡임을 줄이는 용도로만 쓰이고, 실제 데이터는 API 응답으로 교체됩니다.

## 4. 레이아웃과 UI 구성

다이얼로그는 데스크톱에서 가로 720px의 중앙 정렬 모달이며, 회차 목록이 길어지면 모달 내부 스크롤로 처리됩니다. 모바일에서는 풀스크린 시트로 전환됩니다. 위에서 아래로 다음 영역이 순차 배치됩니다.

가장 위에는 다이얼로그 헤더가 있습니다. 좌측에 "할부 상세" 제목과 할부 번호(`I-2026-0312-00045` 형식)가 표시되고, 그 옆에 계약 상태 배지(진행중/완납/미납/해지)가 색상으로 표시됩니다. 우측 끝에 X 닫기 버튼이 있습니다.

헤더 아래에는 계약 요약 카드가 강조 영역으로 표시됩니다. 좌측에 회원명·연락처(연락처는 클릭 시 SMS 발송 진입), 가운데에 상품명·계약 출처(현장 결제 연계/직접 등록/결제링크 연계), 우측에 총 할부 금액·납입 완료 금액·잔여 금액 세 숫자가 큰 글씨로 표시됩니다. 잔여 금액은 빨강 강조 색상으로 표시되어 운영자가 한눈에 회수 잔액을 인식할 수 있게 합니다. 그 아래 보조 행에는 총 회차 / 납입 완료 회차(예: "12 / 4"), 다음 납입 예정일, 진행률 프로그레스 바가 표시됩니다.

요약 카드 아래에는 회차 목록 테이블이 있습니다. 컬럼은 좌측부터 회차 번호, 예정일, 완료일, 회차 금액, 상태 배지(예정/완료/미납), 회차 행 액션(납입 처리 버튼 / 메모 버튼)입니다. 회차 행은 상태에 따라 시각적으로 분기됩니다. "완료" 회차는 회색 톤으로 차분하게 표시되고 완료일이 채워져 있습니다. "예정" 회차는 기본 톤으로 표시되고 완료일이 빈 칸입니다. "미납" 회차는 행 배경에 옅은 빨강 음영이 들어가고, 예정일 텍스트가 빨강 굵게 표시되며, 좌측에 경고 아이콘이 붙습니다. 30일+ 연체된 회차는 추가로 "30일+ 연체" 배지가 우측에 노출됩니다.

회차 행 우측 액션 영역에는 "납입 처리" 버튼과 "메모" 버튼이 있습니다. "납입 처리" 버튼은 상태가 "예정" 또는 "미납"인 회차에서만 활성화되고, "완료" 회차에서는 회색 비활성으로 표시됩니다. 누르면 DLG-S008 납입 처리 다이얼로그가 해당 회차 컨텍스트로 열립니다. "메모" 버튼은 모든 회차에서 활성화되며, 누르면 DLG-S005 메모 편집 다이얼로그가 해당 회차를 대상으로 열립니다.

회차 테이블 아래에는 액션 바가 있습니다. 좌측에는 "메모 전체 보기" 텍스트 링크(회차 메모를 모두 펼쳐 볼 수 있는 보기 토글), 우측에는 권한별로 노출이 분기되는 후속 액션 버튼들이 배치됩니다. 권한이 매니저 이상이면 "중도 상환" 버튼이 활성화되어 누르면 중도 상환 확인 모달이 열립니다. 권한이 슈퍼관리자이면 "계약 해지" 버튼이 추가로 표시되어 SAL-EXT-04 환불 화면으로 진입합니다(잔여 회차 일괄 취소 흐름). 권한이 부족한 계정에서는 이 버튼들이 아예 보이지 않습니다.

다이얼로그 가장 아래에는 닫기 액션 영역이 있습니다. 좌측에 "감사 로그 보기" 링크(SCR-097의 이 할부 관련 이벤트 필터), 우측에 "닫기" 버튼이 배치됩니다. 회차 변경(중도 상환·납입 처리 완료) 후 부모 화면이 갱신되어야 하므로, 다이얼로그는 변경 사항이 있으면 닫힐 때 부모 화면에 갱신 신호를 전달합니다.

## 5. 회차 상태 표시와 자동 미납 감지

회차 상태는 SAL-EXT-01 규칙에 따라 다음 세 가지로 표시됩니다. "예정"은 납입 예정일이 미래이거나 오늘인 회차로, 아직 입금 처리되지 않은 상태입니다. "완료"는 운영자가 납입 처리를 완료해 입금이 확인된 회차입니다. "미납"은 납입 예정일이 지났는데도 입금 처리되지 않은 회차로, 매일 00:01 자동 미납 감지 크론이 예정일 + 1일이 지난 예정 회차를 자동으로 "미납"으로 전환합니다.

다이얼로그는 자동 미납 감지의 결과를 그대로 보여주며, 미납 회차에는 다음 추가 정보가 표시됩니다. 첫째, 행 배경에 옅은 빨강 음영이 들어갑니다. 둘째, 예정일 텍스트가 빨강 굵게 표시됩니다. 셋째, 회차 좌측에 경고 아이콘이 붙습니다. 넷째, 연체 일수가 작은 회색 글씨로 함께 표시됩니다(예: "12일 연체"). 다섯째, 연체 30일을 초과한 회차에는 "30일+ 연체" 빨강 배지가 우측에 추가됩니다.

미납 회차는 PAY-03 미수금 관리에도 자동으로 INSERT되어 미수금 목록에서 함께 관리됩니다. 다이얼로그에서 납입 처리가 완료되면 PAY-03 측 미수금도 자동으로 갱신됩니다(SAL-EXT-01 "PAY-03 동기화" 규칙).

자동 미납 감지가 누락된 경우(예: 크론 실패) 다이얼로그는 운영자가 수동으로 회차 상태를 새로고침할 수 있는 작은 새로고침 아이콘을 헤더에 노출합니다. 누르면 즉시 GET이 재호출되어 최신 상태로 갱신됩니다.

## 6. 회차 펼침과 회차별 메모

회차 행은 기본적으로 한 줄로 표시되지만, 운영자가 행을 클릭하면 그 회차에 대한 추가 정보(회차별 메모 미리보기·납입 시도 이력·연체 알림 발송 이력)가 펼쳐집니다. 회차별 메모는 DLG-S005를 통해 작성되며, 미리보기는 30자 + 말줄임으로 표시되고 "전체 보기" 버튼으로 펼쳐집니다.

같은 회차에 대한 납입 시도가 이전에 실패한 경우(예: 입금액이 회차 금액에 미달해 부분 입금 처리됨), 그 시도 이력이 펼침 영역에 시간순으로 표시됩니다. 각 시도는 시도 일시, 시도 금액, 결과(성공/실패/부분)로 한 줄씩 노출됩니다.

연체 알림 발송 이력은 NFR-05 만료 알림 배치가 D-3·D-Day에 발송한 회원·운영자 알림이 시간순으로 표시되어, 운영자가 회원에게 이미 어떤 알림이 전달되었는지를 확인할 수 있습니다.

회차 펼침과 메모 편집은 다이얼로그를 닫지 않은 상태에서 동작하며, 메모 편집은 별도 다이얼로그(DLG-S005)가 위에 겹쳐 표시됩니다.

## 7. 확인·취소 동작과 부모 화면 갱신

이 다이얼로그는 회차 자체의 상태를 직접 변경하지 않지만, 후속 액션(납입 처리·중도 상환·계약 해지)을 트리거합니다. 각 후속 액션은 다음과 같이 동작합니다.

납입 처리 버튼을 누르면 DLG-S008 납입 처리 다이얼로그가 해당 회차 컨텍스트로 열립니다. 납입 처리가 성공적으로 완료되면 DLG-S008이 닫히고 이 다이얼로그가 다시 활성화되면서, 해당 회차의 상태가 "완료"로 갱신되고 잔여 금액·진행률·다음 납입 예정일이 즉시 재계산되어 표시됩니다. 추가로 우측 상단에 "n회차 납입을 처리했어요" 토스트가 표시됩니다.

중도 상환 버튼을 누르면 다이얼로그 위에 중도 상환 확인 모달이 겹쳐 표시됩니다. 모달에는 잔여 금액 합계, 일괄 처리 대상 회차 목록, 결제 수단 선택 드롭다운이 표시되며, 확인을 누르면 모든 잔여 회차가 일괄 완료 처리되고 계약 상태가 "완납"으로 갱신됩니다. 처리 완료 후 영수증 출력 옵션이 추가로 제공됩니다.

계약 해지 버튼(슈퍼관리자만 노출)을 누르면 SAL-EXT-04 결제 취소·부분 환불 화면으로 즉시 이동합니다. 이동 시 이 다이얼로그는 자동으로 닫히고, SAL-EXT-04 화면에서 환불 처리가 완료되면 잔여 회차가 일괄 취소되고 계약 상태가 "해지"로 갱신됩니다.

닫기 버튼은 다이얼로그를 닫고 부모 화면으로 복귀합니다. 다이얼로그 진입 후 회차 상태가 한 번이라도 변경되었으면(납입 처리 또는 중도 상환), 부모 화면에 갱신 신호를 보내 목록·요약 카드가 다시 fetch됩니다. 변경이 없었으면 부모 화면은 그대로 유지됩니다.

ESC 키와 배경 클릭도 닫기와 동일하게 동작하지만, 회차 메모 편집(DLG-S005) 또는 중도 상환 확인 모달이 열려 있는 동안에는 ESC가 그 하위 모달을 먼저 닫는 방식으로 우선순위가 작동합니다.

다이얼로그의 모든 후속 액션은 SCR-097 감사 로그에 비동기 기록됩니다. 납입 처리는 `installment_round_paid`(DLG-S008 측에서 기록), 중도 상환은 `installment_early_repay`, 계약 해지는 SAL-EXT-04 측에서 환불 처리와 함께 `installment_cancel`로 기록됩니다. 다이얼로그 진입 자체도 `installment_view`로 기록됩니다.

## 8. 화면 상태

다이얼로그는 다음 상태들을 가지며 각 상태마다 보이는 모습이 달라집니다.

로딩 중 상태에서는 요약 카드와 회차 테이블이 스켈레톤으로 표시되고, 닫기 버튼만 활성화됩니다.

정상 표시 상태는 계약이 "진행중"이고 회차가 정상적으로 진행되는 상태로, 회차 테이블이 채워지고 후속 액션 버튼들이 권한에 따라 노출됩니다.

미납 강조 상태는 회차 중 하나 이상이 "미납"인 상태로, 해당 회차 행에 빨강 음영과 경고 아이콘이 표시됩니다. 30일+ 연체가 포함되면 "30일+ 연체" 배지가 추가됩니다.

완납 상태는 계약 상태가 "완납"인 상태로, 헤더 배지가 녹색 "완납"으로 표시되고 모든 회차 행이 "완료"로 표시되며, 중도 상환·계약 해지 버튼이 모두 비활성화됩니다.

해지 상태는 계약 상태가 "해지"인 상태로, 헤더 배지가 회색 "해지"로 표시되고 모든 후속 액션이 비활성화됩니다.

후속 액션 진행 중 상태는 DLG-S008 또는 중도 상환 모달이 열려 있는 상태로, 이 다이얼로그 자체는 어둡게 처리되고 하위 모달이 강조됩니다.

새로고침 필요 상태는 자동 미납 감지 크론이 실패한 의심 상태로, 헤더에 새로고침 아이콘이 깜빡임 표시됩니다.

권한 부족 상태는 후속 액션 권한이 없는 계정이 진입한 경우로, 후속 액션 버튼이 모두 숨겨지고 회차 행도 조회만 가능하도록 표시됩니다.

오류 상태는 5xx 또는 타임아웃으로 API 응답을 받지 못한 경우로, 다이얼로그 중앙에 에러 메시지와 다시 시도 버튼이 표시됩니다.

5년+ 익명화 상태는 회원 식별 정보가 마스킹된 상태로, 회원명·연락처가 마스킹 형태로 표시됩니다.

## 9. 예외 처리

네트워크 오류로 할부 정보 로드에 실패하면 다이얼로그 중앙에 "할부 정보를 불러오지 못했어요" 메시지와 "다시 시도" 버튼이 표시됩니다. 자동 재시도는 1회 백그라운드에서 수행되며, 실패하면 사용자 액션을 기다립니다.

PAY-03 동기화 실패가 발생한 회차(SAL-EXT-01의 동기화 자동 재시도 3회 실패 상태)는 회차 행에 "동기화 오류" 작은 배지가 표시되고, 운영자가 수동 새로고침을 시도할 수 있도록 안내됩니다.

자동 미납 감지가 누락된 의심 상태(예정일 + 1일 경과인데 여전히 "예정"으로 표시된 회차)가 감지되면 헤더에 경고 배지와 새로고침 아이콘이 깜빡이며, 누르면 강제 동기화가 트리거됩니다.

납입 처리 시도 중 동시성 충돌(다른 운영자가 같은 회차를 동시에 납입 처리한 경우)이 발생하면 DLG-S008 측에서 "잠시 후 다시 시도해주세요" 안내가 표시되고, 이 다이얼로그로 복귀 시 최신 상태로 자동 새로고침됩니다.

중도 상환 시도 중 환불이 진행 중인 계약이 감지되면 "환불 진행 중인 계약입니다. 환불 완료 후 중도 상환이 가능합니다"라는 차단 안내가 표시되고, SAL-EXT-04 환불 화면으로의 진입 링크가 제공됩니다.

회원이 탈퇴 처리된 상태에서 다이얼로그 진입 시, 회원명에 "(탈퇴)" 라벨이 붙고 회원 카드 진입 링크가 비활성화됩니다. 단 할부 계약 자체는 유지되어 회수 추진은 계속 가능합니다.

회차 D-3 알림 발송이 실패한 경우(NFR-05 실패 운영자 알림이 발송된 회차) 그 회차 행 펼침 영역에 "D-3 알림 발송 실패 - 운영자가 직접 연락 필요" 안내가 표시됩니다.

본사 통합 모드 권한 미달 상태에서 다른 지점 할부 상세를 직접 URL로 접근한 경우, 다이얼로그가 열리지 않고 부모 화면에 "권한이 없어요" 토스트가 표시됩니다.

## 10. 권한별 처리

superAdmin와 primary는 전체 지점의 모든 할부 계약 상세를 조회하고 납입 처리·중도 상환·계약 해지까지 모두 수행할 수 있습니다.

Owner(지점장)과 매니저(manager)는 자기 지점의 할부 계약 상세를 조회하고 납입 처리·중도 상환까지 수행할 수 있습니다. 계약 해지는 슈퍼관리자만 가능하므로 버튼이 노출되지 않습니다.

FC(fc)는 자기가 담당하는 회원의 할부 계약을 조회하고 납입 처리·메모 편집을 수행할 수 있습니다. 중도 상환과 계약 해지는 권한이 없습니다. SAL-EXT-01 운영 정책에 따라 FC는 할부 신규 등록도 불가하지만, 기존 계약의 납입 처리는 담당 회원에 한해 가능합니다.

스태프(staff)와 프런트(front)는 자기 지점의 할부 계약을 조회만 할 수 있으며, 납입 처리·중도 상환·계약 해지는 모두 불가능합니다. 메모 편집은 본인 작성 메모에 한해 가능합니다.

트레이너(trainer)는 본인이 담당하는 회원의 할부 계약을 조회만 할 수 있습니다. 모든 후속 액션이 비활성화됩니다.

읽기 전용(readonly)은 자기 지점의 할부 계약을 조회만 가능하며, 모든 액션 버튼이 숨겨집니다.

권한 우회 시도(직접 API 호출)는 403으로 차단되고 감사 로그에 기록됩니다.

## 13. 핵심 디자인 요청사항

계약 요약 카드는 다이얼로그의 시각적 중심이 되어야 하며, 총 할부 금액·납입 완료 금액·잔여 금액의 세 숫자가 한눈에 비교되도록 동일 행에 큰 폰트로 배치합니다. 잔여 금액은 빨강 강조로 표시되어 운영자가 회수 우선순위를 즉시 인식할 수 있게 합니다.

진행률 프로그레스 바는 총 회차 대비 완료 회차의 비율을 시각화하며, 미납 회차가 있으면 프로그레스 바 안에 미납 구간을 별도 색상(주황)으로 표시해 단순 완료율과 구분합니다.

회차 테이블의 행은 상태에 따라 명확하게 시각적 분기가 일어나야 합니다. 완료는 회색 톤, 예정은 기본 톤, 미납은 옅은 빨강 음영, 30일+ 연체는 더 진한 빨강 배지가 우측에 추가되는 식의 점진적 강조를 통해 운영자가 시선을 자동으로 미납 회차로 향하게 합니다.

회차 행 우측의 "납입 처리" 버튼은 행 호버 시에만 명확하게 보이도록 처리하거나, 모바일에서는 항상 노출되는 식으로 디바이스별로 정보 밀도를 조절합니다.

후속 액션 버튼(중도 상환·계약 해지)은 다이얼로그 하단 액션 바에서 명확하게 구분되며, 계약 해지처럼 위험도가 높은 액션은 빨강 보더의 보조 버튼으로 표시되어 클릭 전 사용자의 주의를 한 번 더 환기시킵니다.

회차 펼침은 부드러운 아코디언 애니메이션으로 진행되며, 펼침 영역 안의 메모 미리보기·시도 이력·알림 이력은 작은 카드 형태로 정보 구분이 명확해야 합니다.

모바일에서는 회차 테이블이 카드형 리스트로 자동 전환되어, 한 회차마다 위에는 회차 번호·예정일·상태, 아래에는 금액·액션 버튼이 2단 구조로 배치됩니다.

다이얼로그 헤더의 새로고침 아이콘은 자동 미납 감지 의심 상태에서만 깜빡이며, 평상시에는 작은 회색 아이콘으로 차분하게 자리잡고 있어야 합니다.

## 14. 운영 정책 (이 다이얼로그에 연결된 부분)

이 다이얼로그는 SAL-EXT-01 "본 화면 범위: `collectionMode=INSTALLMENT_PLAN` 계약만 노출" 정책에 따라 정기 분납 계약만 표시합니다. 계약금만 받고 잔액을 단기 미수로 남긴 건(`collectionMode=DEPOSIT`)은 이 다이얼로그가 아닌 PAY-03 미수금 관리에서 다룹니다.

자동 미납 감지는 매일 00:01 크론으로 동작하며, 다이얼로그가 표시하는 회차 상태는 이 크론의 결과를 그대로 따릅니다. 운영자는 크론 의심 상태에서 수동 새로고침을 통해 강제 동기화를 트리거할 수 있지만, 정상 운영에서는 자동 동기화로 충분합니다.

미납 회차의 PAY-03 자동 INSERT는 한쪽에서 회수 처리되면 양쪽이 자동 갱신되는 정합성을 보장합니다. 이 다이얼로그에서 납입 처리를 완료하면 미수금 관리 화면의 같은 미수금 행이 자동으로 "완료"로 전환됩니다.

회차당 분납액은 잔액 ÷ 총 회차로 자동 계산되며, 끝수 보정은 마지막 회차에 적용됩니다(예: 100,000 / 3 → 33,333 / 33,333 / 33,334). 다이얼로그는 이 계산 결과를 그대로 표시합니다.

중도 상환은 잔여 회차를 일괄 완납 처리하고 계약 상태를 "완납"으로 갱신합니다. 중도 상환 권한은 매니저 이상이며, FC는 중도 상환을 진행할 수 없습니다.

계약 해지는 SAL-EXT-04 환불 화면으로 위임됩니다. 다이얼로그 자체에서는 잔여 회차를 직접 취소하지 않고, 환불 화면에서 잔여 미수금 상계와 환불 계산이 함께 처리됩니다. 이는 환불·할부·미수가 한 트랜잭션으로 묶여야 한다는 운영 정합성 요구의 결과입니다.

회원 탈퇴 후에도 할부 계약은 유지되어 회수 추진이 계속 가능합니다. SAL-EXT-01 "회원 탈퇴 후 할부: 탈퇴 회원도 할부 계약 유지, 회원 카드 진입 차단" 정책의 시각화입니다.

본사 통합 모드는 본사 슈퍼관리자만 사용 가능하며, 일반 지점 사용자는 자기 지점 계약만 조회할 수 있습니다.

회차 D-3 자동 알림(NFR-05)은 회차 예정일 3일 전 회원·운영자에게 발송됩니다. 다이얼로그에서 알림 발송 이력을 회차 펼침으로 확인할 수 있어, 운영자가 이미 발송된 알림을 중복으로 보내는 일을 방지합니다.

반복 미납 회원(3회 이상 미납)은 운영자 알림이 별도로 발송되며, 다이얼로그에서도 회원명 옆에 "주의" 라벨이 표시됩니다. 이는 영업 품질 관리와 회수 위험 회원 식별을 위한 정책입니다.

조회 이벤트(`installment_view`)와 후속 액션(`installment_early_repay`, `installment_cancel`)은 모두 감사 로그에 기록되어, 누가 언제 어떤 할부 계약에 어떤 액션을 했는지가 사후에도 재구성 가능합니다.

이상의 정책은 할부 상세 다이얼로그가 단순 조회가 아닌 회수·완납·해지의 의사결정 시작점임을 보여줍니다. 정책이 바뀌면 이 문서도 함께 갱신되어야 합니다.
