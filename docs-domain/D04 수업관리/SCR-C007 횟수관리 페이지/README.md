## 2. 화면 개요와 목적

횟수 관리 페이지는 PT 이용권을 보유한 회원의 잔여 횟수를 조회하고, 시스템 오류 보상·환불·출석 정정 같은 사유로 횟수를 수동 조정하는 화면입니다. 수업 완료 시 자동 차감이 기본이지만 운영 현장에서는 시스템 오류로 회원이 수업을 못 받은 경우, 잘못 차감된 출석을 복구하는 경우, 환불·양도 등으로 수동 조정이 필요한 경우가 자주 발생합니다. 본 화면은 매니저가 사유와 함께 횟수를 정확히 정정할 수 있도록 하고, 모든 변경은 append-only 이력으로 보존되어 분쟁 시 증빙으로 활용됩니다.

## 3. 진입 경로와 인접 화면

사이드바의 "수업관리 > 횟수 관리" 또는 D04 도메인 탭 내비게이션의 "횟수 관리" 탭, `/lesson-counts` 직접 진입으로 들어옵니다. 인접 화면은 SCR-C002 수업관리(자동 차감 원천), SCR-M004 회원 상세, SCR-S007 환불(환불 시 자동 복구), SCR-097 감사 로그입니다.

## 4. 레이아웃과 UI 구성

페이지 헤더 아래에는 회원 검색 입력(이름·연락처 통합, 디바운스 300ms, 연락처는 하이픈 제거 후 비교)과 필터 토글(잔여 횟수 부족 3회 이하, 만료 임박 7일 이내, 이용권 종류 PT/OT)이 있습니다.

본문은 회원 목록 테이블이며 좌측부터 회원명(클릭 시 SCR-M004), 연락처, 이용권명(PT 10회·OT 2회 등), 구매 횟수, 사용 횟수, 잔여 횟수, 만료일, 액션([조정] [이력])이 표시됩니다. 잔여 컬럼은 0회 빨강, 1~3회 주황, 4회 이상 기본 색상으로 강조됩니다. 만료 임박(7일 이내)은 주황 배지, 만료는 빨강 배지로 함께 표시됩니다.

본사 통합 모드에서는 지점 컬럼이 추가로 노출됩니다.

## 5. 탭 구성과 탭별 동작

본 화면 자체에는 별도 탭이 없고 D04 도메인 공통 탭 내비게이션 안의 "횟수 관리"가 활성된 상태입니다. 필터 토글(잔여 부족·만료 임박·이용권 종류)이 2차 분기 역할을 합니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

검색 입력은 디바운스 300ms 후 자동 재조회됩니다. 필터 토글 변경도 즉시 반영됩니다. 행의 [조정] 버튼은 매니저+에게만 노출되며 DLG-C012 횟수 조정 모달을 엽니다. [이력] 버튼은 DLG-C013 차감 이력 모달을 엽니다. 회원명 클릭은 SCR-M004 회원 상세로 이동합니다.

## 7. 호출되는 모달 동작

### 7-1. DLG-C012 횟수 조정 다이얼로그
입력 항목은 조정 유형(추가/차감), 조정 횟수, 사유(필수 5자 이상), 비고(선택)입니다. 모달 상단에는 현재 잔여 → 변경 후 잔여 미리보기가 표시되어 운영자가 결과를 확인한 뒤 저장합니다. 차감으로 잔여가 음수가 되면 차단됩니다. 만료된 이용권은 차감 불가이고 추가는 정책에 따라 허용됩니다(보상 등). 저장 시 회원 알림 발송 토글이 있으며 기본 ON, manager+가 OFF로 설정할 수 있습니다.

### 7-2. DLG-C013 차감 이력 다이얼로그
모든 변경 이력이 시간 역순(최신 우선)으로 표시되며 변경 유형(자동 차감/수동 조정 추가/수동 조정 차감/환불 복구/양도) 필터가 제공됩니다. 컬럼은 일시, 변경 유형, 수업명(자동 차감인 경우), 변경 횟수(+/-), 변경 후 잔여, 처리자, 사유입니다. 이력은 append-only이며 삭제할 수 없고 정정은 새 이력 추가(역방향 조정)로만 가능합니다.

## 8. 토스트와 확인 팝업과 알럿

성공 토스트는 "회원의 횟수를 추가했어요"·"회원의 횟수를 차감했어요" 같이 표시됩니다. 차단 안내는 "잔여가 부족해요", "만료된 이용권은 차감할 수 없어요", "사유를 5자 이상 입력해주세요"입니다. 자동 차감 중복은 멱등성 키로 차단되고 로그에 skip 기록됩니다.

## 9. 데이터 흐름과 외부 연동

API는 횟수 조회 `GET /api/lesson-counts`, 이력 조회 `GET /api/lesson-counts/:memberId/history`, 수동 조정 `POST /api/lesson-counts/:memberId/adjust`, 자동 차감 webhook `POST /api/lesson-counts/auto-deduct`입니다. 자동 차감은 예약 기반 출석이면 booking_id 우선, 예약 없는 수동 체크인은 member_id+lesson_id 조합을 멱등성 키로 사용합니다. lesson_id 단독 키는 한 수업의 여러 회원 차감을 중복으로 오판할 수 있으므로 사용하지 않습니다.

환불 처리(SCR-S007) 시 잔여가 자동 복구되고, 회원 탈퇴 webhook 시 잔여 환불 처리가 정책에 따라 동작합니다. 만료 임박(D-7) 회원에게는 매일 09:00 만료 임박 알림 잡이 SMS·카톡을 발송하며, 잔여 부족(3회 이하)은 매주 월요일 마케팅 잡으로 세그먼트화됩니다. 모든 변경은 SCR-097 감사 로그에 actor·member_id·delta·before·after·reason으로 기록됩니다.

## 10. 화면 상태와 예외 처리

기본 목록은 전체 PT 회원(잔여 1회 이상)이며, 잔여 부족 토글 ON 시 3회 이하만 표시됩니다. 만료 임박은 주황, 만료는 빨강 배지로 강조됩니다. 검색 결과 0건은 "검색 결과가 없어요"가 표시됩니다. 본사 통합 모드 활성 시 지점 컬럼이 추가됩니다.

예외로 사유 미입력·5자 미만은 인라인 에러, 차감 시 잔여 음수는 차단, 만료된 이용권 차감은 차단, 자동 차감 중복은 멱등성 키 skip, 환불 트랜잭션 충돌은 자동 재시도, 동시 조정 충돌은 낙관적 락 재로드, 권한 부족(FC) 시 [조정] 버튼 숨김, 회원 탈퇴 후 잔여는 자동 환불 처리됩니다.

## 11. 권한별 처리

슈퍼관리자·본사 최고관리자·센터장·매니저는 조정·이력 조회를 모두 수행합니다. 트레이너는 담당 회원의 이력 조회만 가능하고 조정은 불가합니다. FC·스태프는 조회·이력 조회만 가능하며 조정 버튼이 숨겨집니다. readonly는 접근 불가입니다.

## 14. 핵심 디자인 요청사항

잔여 컬럼은 색상 강도가 가장 두드러져 운영자가 행을 스캔하는 즉시 위험 회원을 인지할 수 있어야 합니다. 만료 임박·만료 배지는 회원명 옆에 작은 색상 배지로 함께 표시되어 잔여와 만료라는 두 축이 한 행에서 동시에 보입니다. DLG-C012의 변경 미리보기(현재 → 변경 후)는 큰 숫자 + 화살표로 시각화되어 운영자가 클릭 직전에 의도를 확실히 확인할 수 있게 합니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

수업 완료(출석 처리) 시 PT 횟수가 자동 차감되며 환불 처리 시 자동 복구됩니다. 수동 조정 권한은 매니저+로 한정되고 트레이너는 이력 조회만 가능합니다. 모든 수동 조정에 사유 텍스트 최소 5자가 필수이며 이력은 append-only로 영구 보관됩니다.

만료 임박 정의는 만료일 D-7 이내이며 주황 배지 + 회원 안내(MKT) 연동입니다. 잔여 음수 방지는 차감 시 자동 차단이며 만료된 이용권은 차감이 차단되고 추가는 정책에 따라 허용됩니다(보상 등).

자동 차감 멱등성은 예약 기반 출석이면 booking_id, 예약 없는 수동 체크인은 member_id+lesson_id 조합으로 처리됩니다. lesson_id 단독 키는 한 수업의 여러 회원 차감을 중복 오판할 수 있으므로 사용하지 않습니다.

변경 유형은 자동 차감 / 수동 조정(추가) / 수동 조정(차감) / 환불 복구 / 양도의 5종으로 분류되며 양도는 테넌트 정책 활성 시에만 노출됩니다(한쪽 차감 + 다른 쪽 추가 트랜잭션). 잔여 색상은 0 빨강, 1~3 주황, 4+ 기본이며 만료일 정책은 이용권 발급 시 결정되어 잔여 0이어도 만료 전까지 추가 결제로 연장 가능합니다.

차감 이력 보관 기간은 영구이며 분쟁 대응을 위한 정책입니다. 본사 통합 모드는 슈퍼관리자·primary가 지점 컬럼 + 전 지점 합산으로 조회할 수 있게 합니다. 검색 정규화는 연락처 하이픈 제거 후 비교, 디바운스 300ms는 부하 분산과 의미 없는 검색 차단을 위한 정책입니다.
