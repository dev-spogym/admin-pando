## 2. 다이얼로그 개요와 목적

회원이 수업 취소를 요청했을 때 단순히 취소만 처리하는 대신, 비슷한 조건의 다른 수업 일정을 자동으로 추천해 회원에게 제안하는 모달입니다. 회원이 제안을 수락하면 기존 취소가 처리되면서 새 수업으로의 예약이 자동으로 완료되고, 회원이 제안을 거절하면 원래의 취소 요청이 그대로 진행됩니다. 회원 이탈을 줄이고 빈 자리 활용률을 높이는 동시에, 운영자가 직접 회원에게 전화해 다른 수업을 제안하는 반복 업무를 줄이는 것이 목적입니다. 본 모달은 SCR-C009 일정 요청 처리 화면의 취소 요청 행에서만 호출되며, 일반 예약 취소 흐름(예약 목록 SCR-C016의 행 액션)에는 사용되지 않습니다.

## 3. 호출 트리거와 진입 시 초기값

SCR-C009 일정 요청 처리 화면의 취소 요청 건 행에서 [대안 제시] 버튼을 클릭하면 모달이 열립니다. 모달이 열릴 때 원래 취소 요청된 수업의 정보(수업명, 일시, 강사)가 자동으로 상단에 읽기 전용으로 표시되고, 같은 수업 유형의 다른 날짜·시간 수업 중 잔여 자리가 있는 수업이 자동으로 후보 목록에 채워집니다. 후보 목록은 원래 수업 시각으로부터 ±7일 이내의 같은 유형 수업을 시각 가까운 순으로 정렬하며, 회원의 이용권 유효 기간 안에 있는 수업만 노출됩니다. 후보가 한 건도 없는 경우 "추천 가능한 대안 일정이 없어요. 직접 입력해 주세요"라는 안내와 함께 직접 일정 입력 영역이 펼쳐집니다.

## 4. 레이아웃과 입력 항목

모달 헤더에는 "대안 일정 제시" 제목과 닫기 X 버튼이 있습니다.

본문 영역은 위에서 아래로 다섯 개의 섹션이 쌓입니다. 첫 번째는 원래 수업 정보 카드로 회원명, 원래 수업명, 일시, 강사, 회원의 취소 사유(SCR-C009 요청 본문에서 가져옴)가 읽기 전용으로 표시됩니다. 두 번째는 대안 일정 후보 목록 테이블로, 컬럼은 좌측부터 수업명, 날짜·시간, 강사, 장소, 잔여 자리 수, 우측의 [이 일정으로 제안] 버튼 순서로 배치됩니다. 한 행을 클릭하면 행이 강조 표시되고 모달 하단 [제안 발송] 버튼이 활성화됩니다. 후보 목록 위쪽에는 필터 칩(같은 강사만 / 같은 시간대만 / 같은 장소만)이 노출되어, 사용자가 추천을 더 좁힐 수 있습니다. 세 번째는 직접 일정 입력 영역으로, 후보 목록에 적합한 일정이 없을 때 운영자가 직접 수업을 검색해서 선택할 수 있습니다. 수업 검색은 수업명·강사명으로 자동완성되며, 검색 결과 중 잔여 자리가 있는 수업만 선택 가능합니다. 네 번째는 안내 메시지 입력 textarea(선택, 0~300자)로 회원에게 전달할 추가 메시지를 입력할 수 있습니다. 다섯 번째는 회원 응답 대기 시간 설정 카드로 "회원이 N시간 안에 응답하지 않으면 자동으로 거절 처리" 토글과 시간 입력(1~48시간, 기본 12시간)이 배치됩니다.

모달 하단에는 [제안 발송] 버튼과 [취소] 버튼이 있고, [취소] 좌측에 작은 보조 링크 [대안 없이 취소 처리]가 노출되어 누르면 부모 화면의 일반 취소 처리 흐름으로 즉시 전환됩니다.

## 5. 액션과 검증

[제안 발송] 버튼은 클릭 시 다음 검증이 수행됩니다. 첫째, 후보 목록에서 한 건이 선택되었거나 직접 일정 입력에서 한 건이 선택되었는지 확인합니다(둘 다 비어 있으면 인라인 안내가 표시되고 차단됩니다). 둘째, 선택된 대안 일정의 잔여 자리가 여전히 1 이상인지 실시간으로 재확인합니다(직전에 다른 운영자가 같은 자리에 예약을 잡았을 가능성). 셋째, 회원의 이용권이 대안 일정 날짜에 유효한지 확인합니다(이용권 만료일이 대안 일정 이전이면 차단). 넷째, 회원이 대안 일정 시각에 이미 다른 수업을 예약한 상태가 아닌지 확인합니다(중복 예약 방지).

모든 검증을 통과하면 즉시 회원에게 NFR-19 알림 센터를 통해 회원앱 푸시 또는 SMS로 "OOO 수업의 대안 일정을 제안드려요" 알림이 자동 발송되고, 안에는 대안 일정 정보와 [수락] / [거절] 버튼이 함께 들어갑니다. 본 모달은 닫히고 부모 화면의 취소 요청 행에는 "대안 제안 발송됨" 회색 배지가 표시되며, 회원의 응답을 대기하는 보류 상태로 전환됩니다.

회원이 수락하면 기존 취소 요청이 즉시 처리(취소 완료 + PT 횟수 자동 복구)되고, 대안 일정으로 새 예약이 자동 생성됩니다. 회원이 거절하면 원래 취소 요청이 그대로 진행되어 단순 취소로 종결됩니다. 응답 대기 시간(기본 12시간)이 지나도 회원이 응답하지 않으면 자동으로 거절 처리되어 단순 취소로 종결되며, 운영자에게는 "대안 제안이 응답 없이 만료되었어요" 알림이 전달됩니다.

[취소] 버튼은 모달을 닫지만 입력 도중이면 "변경 사항이 사라집니다. 닫으시겠습니까?" 확인을 한 번 더 묻습니다. [대안 없이 취소 처리] 링크는 클릭 시 모달이 즉시 닫히고 부모 화면의 일반 취소 처리 흐름이 트리거되어, 원래의 취소 요청이 별도의 추가 입력 없이 그대로 진행됩니다.

## 6. 화면 상태와 예외 처리

기본 표시 상태는 부모 화면에서 받은 취소 요청 컨텍스트로 후보 목록이 자동 채워진 상태입니다. 후보 없음 상태는 ±7일 안에 같은 유형의 잔여 자리 있는 수업이 한 건도 없을 때이며, "추천 가능한 대안이 없어요"와 함께 직접 입력 영역이 자동 펼쳐집니다. 입력/수정 중 상태는 후보 미선택·잔여 자리 0·이용권 만료·중복 예약 같은 검증 실패를 인라인 메시지로 표시합니다. 저장/처리 중 상태에서는 주요 버튼이 비활성화되어 중복 발송을 막습니다. 완료 상태에서는 성공 토스트와 함께 모달이 닫히고 부모 행이 "대안 제안 발송됨" 배지로 갱신됩니다. 실패 상태에서는 실패 사유가 토스트 또는 인라인으로 안내되고 입력값은 유지됩니다.

예외 케이스로 후보 잔여 자리 동시 점유·이용권 만료·중복 예약·회원 알림 발송 채널 미설정·동시 편집 충돌(낙관적 락)·회원이 이미 응답한 다른 대안 제안의 존재가 있으며 각각 인라인 빨강 안내와 함께 발송이 차단됩니다.

## 7. 권한별 동작

owner / manager / superAdmin / primary는 대안 일정 제시를 자유롭게 수행할 수 있습니다. 본사 통합 모드의 본사 권한자는 모든 지점 회원에게 대안을 제안할 수 있고, 일반 매니저는 자기 지점 회원에게만 제안할 수 있습니다. fc / staff는 대안 제시 권한이 있어 모달 진입과 발송까지 가능하지만, 직접 일정 입력 영역에서 다른 지점의 수업을 선택할 수는 없습니다(같은 지점의 수업으로 한정). trainer는 본인 담당 수업의 취소 요청에 한해 대안 제시를 수행할 수 있고, 후보 목록에는 본인 담당 수업 중 잔여 자리가 있는 수업이 우선 노출됩니다. readonly는 진입 자체가 차단되어 부모 화면에서 권한 안내가 표시됩니다.

본사 통합 모드에서 본사 권한자가 본인 디바이스의 지점과 다른 지점의 대안을 제시하려고 하면 "지점이 다른 대안은 회원이 거부할 가능성이 높아요. 정말 진행하시겠습니까?"라는 추가 확인이 표시되어, 회원 경험이 깨지지 않도록 가이드합니다.

## 8. 부모 화면과의 상호작용

발송 성공 시 모달이 닫히고 SCR-C009 일정 요청 처리의 해당 취소 요청 행이 "대안 제안 발송됨" 회색 배지로 갱신됩니다. 동시에 부모 화면의 요청 카운트 카드("처리 대기", "대안 발송됨")가 즉시 재계산되어 운영자가 현재 보류 중인 케이스를 한눈에 추적할 수 있게 됩니다. 회원이 수락하면 부모 행이 "대안 수락 → 새 예약 완료"로 갱신되면서 사라지고, 거절하거나 응답 만료되면 부모 행이 "단순 취소 완료"로 갱신되면서 일반 취소 흐름으로 마무리됩니다.

대안 수락 결과는 예약 목록(SCR-C016)에도 즉시 반영되어, 원래 예약은 "취소" 상태로 새 예약은 "예약완료" 상태로 동기화됩니다. 회원 상세(SCR-M004)의 예약 이력에도 두 건이 시간순으로 누적되어, 회원이 어느 수업에서 어느 수업으로 이동했는지 추적 가능해집니다.

## 9. 데이터 흐름과 외부 연동

API는 후보 일정 조회 `GET /api/lessons/alternatives?originalLessonId=&memberId=&range=±7d`, 직접 일정 검색 `GET /api/lessons/search?q=`, 대안 제안 발송 `POST /api/cancel-requests/:id/propose-alternative`, 회원 응답 처리 `POST /api/cancel-requests/:id/alternative-response`입니다. 후보 일정 조회는 회원의 이용권 유효 기간, 회원의 기존 예약, 후보 수업의 잔여 자리, 같은 강습 세션 유형 일치 여부를 모두 고려해서 추천 점수를 매기고 점수 높은 순으로 정렬합니다.

대안 제안 발송은 트랜잭션 안에서 제안 레코드 INSERT, 알림 큐 적재, 응답 대기 타이머 등록, 감사 로그 INSERT가 동시에 수행됩니다. 회원이 응답하면 응답 처리 API가 호출되어, 수락이면 기존 취소를 처리하면서 새 예약을 자동 생성하고, 거절이면 기존 취소만 처리합니다. 응답 대기 시간이 지나면 자동 만료 잡(매분 실행)이 만료된 제안을 자동 거절 처리로 전환합니다.

모든 대안 제안과 응답·만료는 SCR-097 감사 로그에 `actor`·`cancel_request_id`·`alternative_lesson_id`·`action`(PROPOSE/ACCEPT/REJECT/EXPIRE)·`timestamp`로 비동기 INSERT됩니다. 회원 알림은 NFR-19 알림 센터를 통해 회원앱 푸시 또는 SMS로 발송되며, 알림 본문에 수락/거절 버튼이 deep link로 들어가 회원이 회원앱을 열지 않고도 응답할 수 있도록 합니다.

## 12. 디자인 요청사항

원래 수업 정보 카드는 모달 상단에 큰 시각적 영역으로 배치되어, 운영자가 "어떤 수업의 대안을 찾고 있는지"를 즉시 인지할 수 있어야 합니다. 회원의 취소 사유는 작은 톤으로 보조 표시되어, 운영자가 사유를 참고하면서 적합한 대안을 고를 수 있게 합니다(예: "시간 안 됨" 사유라면 다른 시간대 우선, "강사 변경" 사유라면 다른 강사 우선).

대안 후보 목록은 점수 순으로 정렬되어 가장 적합한 후보가 맨 위에 노출되며, 점수 산정 기준(시각 유사도·강사 유사도·장소 유사도·잔여 자리)이 작은 배지로 행 옆에 표시됩니다. [이 일정으로 제안] 버튼은 행 우측에 명확히 배치되어 한 번의 클릭으로 선택이 가능해야 합니다. 필터 칩(같은 강사만·같은 시간대만·같은 장소만)은 후보 목록 위쪽에 배치되어, 운영자가 회원의 취소 사유에 맞춰 후보를 빠르게 좁힐 수 있게 합니다.

직접 일정 입력 영역은 후보가 없거나 후보 외 일정을 제안하고 싶을 때만 펼쳐지는 접이식 영역으로 배치되어, 일반 흐름에서는 시각적으로 산만하지 않게 합니다. 응답 대기 시간 설정은 기본값 12시간이 큰 글씨로 노출되고, 1~48시간 범위 슬라이더로 시각적으로 조정 가능하게 합니다. 회원 응답 흐름의 안내(수락 시·거절 시·만료 시)는 모달 하단에 작은 가이드 텍스트로 항상 표시되어, 운영자가 발송 후 어떤 결과가 가능한지 미리 알 수 있게 합니다.

## 13. 운영 정책

대안 일정 제시는 회원의 단순 취소를 한 단계 늦추고 운영적 회복 기회를 만드는 도구입니다. 회원이 자발적으로 취소를 원하는 경우(예: 시간 안 됨·강사 변경·당일 컨디션) 대안을 제안하면 일정 비율(센터별 데이터로 측정)에서 새 예약으로 전환되어 회원 이탈을 줄이고 빈 자리 활용률을 높입니다. 따라서 본 모달은 SCR-C009 일정 요청 처리에서만 호출되며, 일반 예약 목록(SCR-C016)의 취소 행 액션에는 사용되지 않습니다. 일반 취소 흐름은 더 빠르고 마찰 없는 처리를 우선해야 하기 때문입니다.

대안 후보의 추천 범위는 원래 수업 시각으로부터 ±7일 이내, 같은 강습 세션 유형 또는 같은 수업 유형이며, 회원의 이용권 유효 기간 안에 있는 수업만 노출됩니다. 추천 점수는 시각 유사도(가까울수록 높음), 강사 유사도(같은 강사면 가산), 장소 유사도(같은 장소면 가산), 잔여 자리 여유(여유 클수록 가산)를 합산해서 매겨지며, 운영자가 직접 필터 칩으로 가산 기준을 조정할 수 있습니다.

회원 응답 대기 시간의 기본값은 12시간이며 1~48시간 범위에서 조정 가능합니다. 응답 대기 시간이 너무 길면 회원이 잊거나 빈 자리가 다른 회원에게 가는 운영 손실이 발생하고, 너무 짧으면 회원이 답할 기회가 부족합니다. 본사는 센터별 평균 응답 시간을 모니터링해 권장값을 분기마다 조정합니다.

본 모달의 발송과 회원 응답·만료는 모두 감사 로그에 5초 안에 기록되어 SCR-097에서 조회 가능하며, 분쟁 시 누가 언제 어떤 대안을 제안했고 회원이 어떻게 응답했는지가 영구 보관됩니다. 자동 만료 처리는 매분 실행되는 만료 잡이 담당하며, 만료 시점에 운영자에게 "대안 제안이 응답 없이 만료되었어요" 알림이 자동 발송되어 후속 처리가 끊김 없이 이어집니다. trainer는 본인 담당 수업의 취소 요청에 한해 본 모달을 사용할 수 있어, 트레이너가 본인 회원의 이탈을 직접 막을 수 있는 운영 도구로도 작동합니다.
