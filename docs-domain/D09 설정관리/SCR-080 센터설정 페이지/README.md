## 2. 화면 개요와 목적

센터 설정 페이지는 한 센터를 운영하는 데 필요한 모든 기본 정보를 한 곳에서 관리하는 설정 도메인의 진입 허브 화면입니다. 신규 오픈 직후 가장 먼저 채워야 할 센터명·로고·사업자등록번호·운영시간 같은 핵심 메타데이터부터, 채널별 알림 정책, 운영자 화면 테마, 수건과 운동복 같은 일일 비품 재고까지 네 개의 탭으로 묶어 단일 진입점에서 처리하도록 구성되어 있습니다. 이 화면에서 변경된 값은 회원앱과 키오스크와 세금계산서와 매출 화면에까지 즉시 영향을 주기 때문에, 변경 행위 자체가 운영 정책 결정과 사실상 동일한 무게를 가집니다.

이 화면을 사용하는 운영 흐름은 매우 다양합니다. 신규 오픈 센터의 Owner(지점장)은 로고·센터명·사업자번호·연락처·주소·업종을 일괄로 채워 운영을 시작하고, 계절이 바뀌거나 휴일 공지를 적용할 때는 평일·주말 운영시간만 빠르게 조정합니다. 본사 슈퍼관리자는 사업자번호가 바뀌었을 때 10자리 형식 검증을 거쳐 세금계산서 발행이 끊기지 않도록 정합화하고, 본사 표준 컬러를 일괄 적용해 모든 지점의 운영자 화면을 통일합니다. 매니저는 알림설정 탭만 열어서 앱 푸시 다섯 종, 이메일 두 종, SMS 두 종의 토글 상태가 본사 정책과 어긋나지 않는지 점검하고, 문제가 있으면 Owner(지점장)에게 보고합니다. 프런트나 매니저가 수건 입고 카운트와 일일 발급 한도를 입력해 잔여 수량이 자동 계산되도록 하면, 비품 부족 알림이 발생하기 전에 운영자가 미리 대응할 수 있습니다. 다크 테마로 야간 운영 가독성을 높이고 싶을 때, VAT 포함/별도 표기를 결제 화면 정합성에 맞게 조정할 때, 외부 표준 컬러를 마케팅 캠페인에 맞춰 임시 적용할 때도 모두 이 화면에서 처리됩니다.

이런 다양한 운영 흐름이 한 화면 안에서 정확히 분기되도록, 센터 설정 페이지는 네 개의 탭 구조와 권한별 노출 제어, 미저장 변경 감지, 외부 API 의존성을 한 묶음으로 다룹니다. 단순한 폼이 아니라 회원앱·키오스크·결제·세금계산서·알림 채널까지 영향을 주는 운영 허브로 동작하기 때문에, 입력값 검증과 저장 후 즉시 동기화, 그리고 미저장 변경 손실 방지(DLG-080-001)가 화면의 책임 범위에 함께 들어갑니다.

## 3. 진입 경로와 인접 화면

센터 설정 페이지에 진입하는 경로는 다음과 같이 여러 가지가 있고, 각 경로마다 진입 직후 어떤 탭이 활성되는지가 달라집니다.

첫 번째 경로는 사이드바입니다. 좌측 사이드바의 "설정" 메뉴 아래 "센터 설정" 항목을 누르면 진입하며, URL은 `/settings`가 되고, 화면은 기본정보 탭이 자동으로 활성된 상태로 시작합니다. 사이드바 메뉴 자체는 권한이 매니저 이상에게만 보이며, FC·트레이너·스태프·프런트·readonly 계정에는 메뉴 자체가 노출되지 않습니다.

두 번째 경로는 헤더 우측의 사용자 메뉴에서 "센터 설정"을 직접 누르는 경우입니다. 이 경로에서는 항상 기본정보 탭으로 진입합니다.

세 번째 경로는 다른 화면에서 발생한 안내 배지나 인라인 링크를 통한 진입입니다. 예를 들어 매출 화면에서 VAT 표기가 잘못 보이는 경우 "센터 설정에서 VAT 설정을 확인해 주세요" 안내가 표시되고, 그 링크를 누르면 기본정보 탭의 VAT 설정 위치까지 자동 스크롤된 상태로 진입합니다. 알림 센터(NFR-19)에서 "물품 잔여가 0개입니다"와 같은 알림을 누르면 물품 관리 탭으로 직접 진입합니다.

네 번째 경로는 운영 모드 토글 변경 직후의 자동 진입입니다. 본사 슈퍼관리자가 다크 테마를 전 지점에 일괄 적용한 직후에는 변경 결과를 확인하라는 안내와 함께 이 화면의 테마설정 탭으로 이동시킬 수 있습니다.

이 화면에서 빠져나가는 인접 화면으로는 사이드바 하위의 SCR-080A 지점 자동화 적용(만료 알림 정책 적용), SCR-082 키오스크 설정(센터 로고·표시 언어 정합화), SCR-083 IoT 출입 관리(센터 운영시간과 출입 시각 검증), SCR-088 다국어 설정(언어와 화폐 단위 통일), 그리고 모든 저장 이벤트가 기록되는 SCR-097 감사 로그가 있습니다. 특히 회원앱·키오스크·세금계산서는 별도 화면이 아닌 외부 면이지만, 이 화면의 저장은 그 외부 면에까지 즉시 push 되므로 사실상 인접 영향 면으로 간주합니다.

## 4. 레이아웃과 UI 구성

센터 설정 페이지는 위에서 아래로 차곡차곡 쌓이는 세로형 단일 컬럼 레이아웃을 기본으로 하며, 데스크톱·태블릿·모바일에서 동일한 구조를 유지합니다. 모바일에서는 탭 헤더가 가로 스크롤로 전환되고, 각 탭 내부의 입력 그리드가 1단으로 풀어집니다.

가장 위에는 페이지 헤더가 있습니다. 헤더 좌측에는 "센터 설정"이라는 페이지 타이틀과 함께 현재 편집 중인 센터의 이름과 지점 컨텍스트 배지가 따라옵니다. 본사 슈퍼관리자가 통합 모드에서 진입한 경우, 헤더 좌측에 "전체 지점(통합)" 배지가 추가로 표시되며 우측에는 "어느 지점의 설정을 편집할지" 고르는 드롭다운이 노출됩니다. 일반 지점 운영자(Owner(지점장)·매니저)에게는 이 드롭다운이 보이지 않고 자기 지점의 설정만 편집합니다. 헤더 우측 끝에는 "변경 사항 저장" 버튼이 있는데, 변경 사항이 한 건도 없을 때는 비활성 상태로 보이고, 변경이 발생한 순간 활성 상태로 바뀌면서 그 옆에 "저장되지 않은 변경 사항" 노랑 배지가 따라옵니다.

페이지 헤더 바로 아래에는 공통 영향도 프리뷰 영역이 있습니다. 이 영역은 현재 탭에서 변경한 값이 저장될 때 어떤 운영 정책에 영향이 가는지를 미리 알려줍니다. 예를 들어 평일 운영시간을 조정하면 "출석·예약 정책의 영업시간 기준이 새 시간으로 갱신됩니다"라는 안내가 표시되고, 알림 토글을 끄면 "오늘 이후 발생하는 알림 발송이 차단됩니다"라는 안내가 표시되며, 메인 컬러를 변경하면 "본사 표준 컬러와 다릅니다"라는 비교 안내가 표시되는 식입니다. 변경 사항이 없으면 "변경 없음" 회색 배지가 표시되고, 변경이 한 건이라도 발생하면 "저장 전 검토 필요" 주황 배지로 바뀝니다.

영향도 프리뷰 아래에는 탭 헤더가 있습니다. 네 개의 탭은 좌측부터 기본정보 / 알림설정 / 테마설정 / 물품 관리 순서로 배치되며, 각 탭 라벨 우측에는 그 탭에 미저장 변경이 있을 때 작은 빨강 점이 표시되어 운영자가 어느 탭에 변경이 남아 있는지 한눈에 알 수 있도록 합니다. 매니저가 진입했을 때는 알림설정 탭만 활성 상태로 보이고 나머지 세 탭은 비활성 또는 숨김 처리됩니다(테넌트 정책에 따라 결정).

탭 본문은 각 탭마다 다른 구성으로 펼쳐집니다.

기본정보 탭은 가장 위에 센터 로고 업로드 영역이 있고, 그 아래로 센터명·사업자등록번호·센터 소개·대표 연락처·주소·업종·평일 운영시간·주말 운영시간·VAT 설정이 위에서 아래로 배치됩니다. 로고는 정사각 또는 가로형 권장이며 미리보기와 함께 5MB 이내 PNG/JPG 업로드 영역이 있습니다. 센터명은 1~50자 필수이고, 사업자등록번호는 10자리 숫자 입력 후 옆의 "외부 검증" 버튼으로 추가 검증을 시도할 수 있습니다. 대표 연락처는 010 입력 시 자동 하이픈 포맷이 적용되고, 주소는 "주소 검색" 버튼으로 외부 우편번호 API를 호출해 도로명 주소와 우편번호를 자동으로 채웁니다. 업종은 11종 다중 선택(헬스·필라테스·PT샵·골프·요가·크로스핏·복싱·수영·태권도·스피닝·기타) 중 최소 1개 선택이 필수입니다. 평일·주말 운영시간은 오픈 시각과 마감 시각을 HH:mm 형식으로 입력하며, 마감 시각이 오픈보다 같거나 빠르면 저장이 차단됩니다(24시간 운영은 00:00~24:00 형식으로 입력). VAT 설정은 부가세 포함/별도 두 옵션 중 하나를 선택하며, 저장된 숫자 데이터는 변경하지 않고 결제·매출·세금계산서 화면의 표시 형식에만 영향을 줍니다.

알림설정 탭은 위에서부터 앱 푸시 5종, 이메일 2종, SMS 2종의 토글이 그룹별로 묶여 표시됩니다. 앱 푸시는 입장 알림·만료 임박·결제 완료·수업 예약·수업 취소이고, 이메일은 주간 리포트와 만료 예정 안내이며, SMS는 결제 완료와 만료 임박입니다. 토글을 누르면 즉시 발송이 차단되거나 활성되는 것이 아니라, 저장 버튼을 누른 후에 비로소 적용되는 점이 이 탭의 핵심 규칙입니다. 토글 그룹 아래에는 "메시지 플랫폼 연동 요약" 카드가 있어 현재 연결된 알림톡·SMS provider, 발신 프로필(SMS 발신 번호 또는 카카오 발신 프로필), 승인 템플릿 수, 예상 비용 기준(플랫폼 API 응답 기준), 최근 동기화 시각이 함께 표시됩니다. 이 카드는 조회 전용이며 관리자에서 단가를 직접 수정하지 않습니다.

테마설정 탭은 화면 모드 라이트/다크/시스템 라디오, 메인 컬러 HEX 색상 선택기, 보조 컬러 HEX 색상 선택기, 글자 크기 작게/기본/크게 세 옵션으로 구성됩니다. 메인 컬러와 보조 컬러가 동일하면 가독성 경고가 인라인으로 표시되지만, 저장 자체는 진행할 수 있습니다. 테마 변경의 적용 범위는 테넌트 정책에 따라 운영자 본인에게만 적용되는 모드와 전 운영자에게 일괄 적용되는 모드 두 가지로 갈리며, 본사 슈퍼관리자는 전사 적용 모드를 사용할 수 있습니다.

물품 관리 탭은 수건 대·소, 운동복 상·하의 네 종류의 일일 재고를 관리하는 영역입니다. 각 물품마다 재고 수량, 1일 발급 한도, 잔여 수량 세 칸이 표시되며, 잔여 수량은 운영자가 직접 입력하지 않고 "재고 수량 - 오늘 발급 수량"으로 자동 계산되어 표시됩니다. 1일 발급 한도가 재고 수량을 초과하면 인라인 경고가 표시되며, 잔여가 0이 되면 알림 센터로 운영자 알림이 자동 발송됩니다. 매일 자정에는 일별 발급 카운터가 리셋되어 다음 날 한도가 다시 한도값으로 회복됩니다.

마지막으로 페이지 최하단에는 액션 풋바가 fixed로 떠 있어 페이지를 스크롤해도 항상 보이며, "변경 사항 저장" 버튼과 "변경 취소(초기화)" 버튼이 좌우로 배치됩니다. 변경 취소를 누르면 마지막 저장 시점으로 즉시 복원되고, 변경 사항 저장은 모든 탭의 변경을 한 번에 커밋합니다.

## 5. 탭 구성과 탭별 동작

이 화면은 네 개의 탭이 좌우로 펼쳐져 있고, 어느 탭을 누르더라도 검색이나 페이지 같은 다른 상태는 없기 때문에 단순한 좌우 전환만 일어납니다. 다만 각 탭에 미저장 변경이 남아 있는지 여부는 화면 전체가 추적하며, 미저장 상태에서 다른 탭을 누르면 DLG-080-001 미저장 경고가 즉시 떠서 변경 손실을 막습니다.

기본정보 탭은 진입 시 자동으로 활성되는 디폴트 탭으로, 회원앱·키오스크·세금계산서·홈페이지까지 영향이 가장 광범위한 항목들을 다룹니다. 저장 시점에는 회원앱과 키오스크에 즉시 push 동기화가 발생해 센터명·로고·운영시간이 외부 면에 그대로 반영됩니다.

알림설정 탭은 매니저가 진입했을 때 조회만 가능한 유일한 탭입니다. 매니저가 다른 탭을 직접 URL로 시도하면 권한 부족 안내가 표시됩니다. 토글 변경은 저장 후에만 발송 정책에 반영되며, 저장 직전까지는 운영자가 실수로 즉시 발송을 차단하거나 활성화할 수 없도록 안전장치가 걸려 있습니다.

테마설정 탭의 변경은 테넌트 정책에 따라 적용 범위가 달라지며, 본인 적용 모드에서는 자신의 화면만 즉시 바뀌고, 전체 적용 모드에서는 저장 직후 모든 운영자의 화면에 새 테마가 적용됩니다. 본사 슈퍼관리자는 전사 적용 모드를 활용해 표준 컬러를 일괄 적용할 수 있습니다.

물품 관리 탭은 실시간 잔여 계산이 동작하는 탭으로, 운영자가 발급 한도를 변경하는 동안 그 옆의 잔여 수량도 즉시 재계산되어 표시됩니다. 다만 잔여 수량이 자동 계산이므로 직접 편집하지 않으며, 재고 수량과 1일 발급 한도만 편집 가능합니다.

탭 전환 시 미저장 변경이 한 건이라도 있으면 DLG-080-001이 표시되고 운영자는 저장·이탈·취소 중 하나를 선택해야 합니다. 저장을 선택하면 자동 저장 후 새 탭으로 이동하고, 이탈을 선택하면 변경을 버리고 새 탭으로 이동하며, 취소를 선택하면 현재 탭에 그대로 머뭅니다.

## 6. 버튼·아이콘·링크 액션 전체 정의

이 화면에 등장하는 모든 클릭 가능한 요소를 빠짐없이 정의합니다.

페이지 헤더의 지점 컨텍스트 드롭다운은 본사 슈퍼관리자에게만 노출되며, 누르면 편집할 지점 목록이 펼쳐지고 선택한 순간 그 지점의 설정값을 다시 fetch해 모든 탭의 입력값이 새로 채워집니다. 이때 이전 지점에 미저장 변경이 남아 있으면 DLG-080-001이 떠서 손실을 막습니다.

기본정보 탭의 로고 업로드 영역은 클릭하면 파일 선택 다이얼로그가 열리고, 드래그 앤 드롭도 지원합니다. 업로드 후에는 그 자리에서 미리보기가 갱신되며, 5MB 초과나 PNG/JPG 외 형식은 업로드 단계에서 차단됩니다. 업로드된 파일은 저장 버튼을 누르기 전까지는 임시 영역에 보관되며 저장 시 영구화됩니다.

사업자등록번호 옆의 "외부 검증" 버튼은 사업자번호를 외부 검증 API로 보내 등록 여부를 확인합니다. 검증 API가 실패하면 "검증 실패, 형식만 확인됨" 안내가 표시되고 진행은 가능합니다.

주소 입력 옆의 "주소 검색" 버튼은 외부 우편번호 API 팝업을 열어 사용자가 검색한 결과를 클릭하면 도로명 주소와 우편번호가 자동으로 채워집니다. 외부 API가 실패하면 수동 입력으로 진행할 수 있습니다.

업종 드롭다운은 다중 선택 가능한 체크박스 형태이며, 선택된 업종은 칩으로 본문에 표시됩니다. 칩의 X 버튼으로 개별 해제가 가능하고, 마지막 하나를 해제하려고 하면 "최소 1개 선택 필요" 안내가 표시되어 차단됩니다.

평일·주말 운영시간의 시각 입력은 HH:mm 형식으로 직접 타이핑하거나 시간 피커로 선택할 수 있습니다. 마감 시각이 오픈 시각보다 같거나 빠르면 인라인 경고가 표시되고 저장이 차단됩니다.

VAT 설정의 토글은 누르면 즉시 상태가 바뀌고 영향도 프리뷰가 갱신되지만, 실제 결제·매출·세금계산서 화면에는 저장 후에 비로소 반영됩니다.

알림설정 탭의 토글들은 누르는 즉시 UI 상태만 바뀌고 영향도 프리뷰가 "저장 시 알림 정책 적용" 안내를 표시합니다. 저장 후에야 다음 알림부터 새 정책이 적용됩니다. 토글을 매니저가 누르려고 하면 토글 자체가 비활성 상태로 표시되어 클릭이 받아들여지지 않습니다.

메시지 플랫폼 연동 요약 카드의 "최근 동기화 시각" 우측에는 새로고침 아이콘이 있고, 누르면 플랫폼 API로 다시 조회해 발신 프로필·승인 템플릿·예상 비용을 갱신합니다. 조회 실패 시 "발송 정보 동기화 실패" 안내와 함께 재조회 버튼이 표시됩니다.

테마설정 탭의 화면 모드 라디오는 누르면 즉시 운영자 본인의 화면 모드가 미리보기로 바뀌지만, 저장 전에는 다른 운영자에게는 영향이 가지 않습니다. 메인 컬러와 보조 컬러의 색상 선택기는 HEX 입력 또는 색상 팔레트로 고르며, 동일 색상이면 가독성 경고가 표시되지만 저장은 가능합니다.

물품 관리 탭의 각 입력 칸은 숫자만 받아들이며 음수와 소수는 입력이 거절됩니다. 1일 발급 한도가 재고 수량을 초과하면 인라인 경고가 표시되지만 저장은 가능합니다(운영자의 입고 예정을 미리 반영하기 위함).

페이지 최하단 액션 풋바의 "변경 사항 저장" 버튼은 변경이 한 건이라도 있을 때만 활성화되며, 누르면 모든 탭의 변경이 한 번에 백엔드로 전송됩니다. 변경 취소(초기화) 버튼은 마지막 저장 시점으로 모든 입력값을 되돌리며, 누르기 전에 "변경 사항이 사라집니다. 초기화하시겠습니까?"라는 확인이 한 번 더 표시됩니다.

모든 버튼은 클릭 후 응답이 돌아오기 전까지 자동으로 비활성화되어 더블클릭이나 연타로 인한 중복 요청이 차단됩니다.

## 7. 호출되는 모달 동작

이 화면에서 호출되는 모달은 DLG-080-001 미저장 경고 하나입니다.

### 7-1. DLG-080-001 미저장 경고 다이얼로그

미저장 경고 다이얼로그는 운영자가 변경 사항을 저장하지 않은 상태에서 다른 탭이나 다른 페이지로 이동하려고 할 때 변경 손실을 막기 위해 강제로 표시되는 모달입니다. 이 화면에서는 세 가지 트리거로 열립니다. 첫 번째 트리거는 탭 헤더에서 다른 탭을 클릭한 경우이고, 두 번째 트리거는 페이지 헤더의 지점 컨텍스트 드롭다운에서 다른 지점을 선택한 경우이며, 세 번째 트리거는 사이드바·헤더 메뉴·브라우저 뒤로가기 등으로 페이지 자체를 떠나려고 하는 경우입니다.

모달 상단에는 "저장되지 않은 변경 사항이 있습니다"라는 제목이 표시되고, 그 아래에 어떤 탭의 어떤 항목이 변경되었는지가 짧게 요약됩니다. 예를 들어 "기본정보 탭: 센터명, 평일 운영시간 변경" 같은 형식입니다. 하단에는 세 개의 버튼이 있습니다. "저장" 버튼은 현재 변경을 즉시 백엔드에 저장한 후 새 위치로 이동하고, "이탈" 버튼은 변경을 폐기한 후 새 위치로 이동하며, "취소" 버튼은 모달을 닫고 현재 탭에 그대로 머무릅니다. ESC 키나 배경 클릭은 취소와 동일하게 동작합니다.

이 모달의 자세한 동작은 DLG-080-001 다이얼로그 문서에서 자기완결로 다시 정의되며, 이 화면의 책임은 미저장 변경 감지와 정확한 트리거에 한정됩니다.

## 8. 토스트와 확인 팝업과 알럿

센터 설정 페이지에서 발생하는 모든 알림성 UI는 다음과 같은 패턴으로 동작합니다.

성공 토스트는 우측 상단에 녹색 계열로 3초 동안 표시되며, "변경 사항이 저장되었습니다", "주소 검색이 완료되었습니다", "발송 정보가 갱신되었습니다" 같은 짧은 문구로 결과를 알려줍니다. 저장 토스트는 어떤 탭의 어떤 항목이 저장되었는지 간단히 요약합니다.

실패 토스트는 우측 상단에 빨강 계열로 표시되며, "저장에 실패했습니다", "주소 검색에 실패했습니다", "사업자번호 검증에 실패했습니다", "발송 정보 동기화에 실패했습니다" 같은 문구와 함께 다시 시도 버튼이 따라옵니다. 네트워크 오류는 1회 자동 재시도 후 사용자 액션을 기다립니다.

확인 팝업은 변경 취소(초기화)를 누를 때 한 번 더 묻는 yes/no 형태로 표시됩니다.

알럿은 권한이 없는 계정이 직접 URL로 접근했을 때 표시되는 차단형 안내로, 페이지 본문이 가려지고 "이 화면에 접근할 권한이 없습니다. 3초 후 대시보드로 이동합니다"라는 메시지가 표시된 후 자동 이동합니다.

매니저가 알림설정 탭 외의 영역을 직접 URL로 시도한 경우, 본문 자체는 보이지만 모든 입력 필드가 읽기 전용으로 표시되고 저장 버튼이 hidden 처리됩니다.

## 9. 데이터 흐름과 외부 연동

이 화면은 여러 데이터 소스와 외부 API에 의존합니다. 화면 단위로 어떤 데이터가 어디서 오고 어디로 가는지를 모두 풀어 씁니다.

화면 진입 시점에는 센터 설정 조회 API `GET /api/settings/center`가 호출되어 기본정보·테마·물품 관리 탭의 값이 한 번에 내려옵니다. 알림설정은 별도 엔드포인트 `GET /api/settings/notifications`로 조회되며, 이 응답에는 9종 토글의 현재 상태가 포함됩니다. 본사 슈퍼관리자가 통합 모드에서 다른 지점을 선택하면 `branchId` 쿼리 파라미터를 바꾸어 같은 엔드포인트를 다시 호출합니다.

저장 시점에는 각 탭별로 별도 엔드포인트가 동작합니다. 기본정보는 `PUT /api/settings/center`로, 알림설정은 `PUT /api/settings/notifications`로, 테마는 `PUT /api/settings/theme`로, 물품 관리는 `PUT /api/settings/inventory`로 저장됩니다. 한 번의 저장 버튼 클릭으로 여러 탭에 변경이 있는 경우, 각 엔드포인트를 병렬 호출하고 모두 성공한 후에 성공 토스트가 표시됩니다. 일부만 성공하면 성공한 탭은 그대로 두고 실패한 탭에 한해 재시도가 안내됩니다.

로고 업로드는 `POST /api/settings/center/logo`로 처리되며, 멀티파트 업로드로 진행됩니다. 업로드된 파일은 즉시 미리보기에 표시되지만 저장 버튼을 누르기 전까지는 영구화되지 않습니다.

사업자번호 외부 검증은 `POST /api/settings/center/verify-business-no`로 처리되며, 외부 API가 응답하지 않거나 오류를 반환하면 형식 검증만 수행하고 진행을 허용합니다.

주소 검색은 `GET /api/settings/center/address-search`로 처리되며, 외부 우편번호 API의 결과를 받아 도로명 주소와 우편번호를 자동으로 채웁니다.

메시지 플랫폼 연동 요약은 플랫폼 API 응답을 그대로 노출하며, "최근 동기화 시각" 옆의 새로고침 버튼을 누르면 다시 조회가 일어납니다. 이 데이터는 조회 전용이며 관리자에서 단가를 직접 수정하지 않습니다.

회원앱과 키오스크 push는 기본정보 탭 저장 시 자동으로 트리거되며, 센터명·로고·운영시간이 변경된 경우 회원앱과 키오스크 기기에 MQTT/WebSocket 신호로 push 됩니다. 미연결 키오스크는 다음 connect 시점에 동기화됩니다.

물품 잔여 자동 계산은 매 발급 트랜잭션마다 잔여 = 재고 - 오늘 발급으로 재계산되며, 잔여가 0이 되는 순간 알림 센터(NFR-19)로 운영자 알림이 자동 발송됩니다. 매일 자정에는 일별 발급 카운터가 리셋 배치로 초기화됩니다.

테마 적용 범위가 "전체 적용"인 경우 저장 직후 모든 운영자의 클라이언트가 새 테마를 fetch하도록 push 알림이 전송됩니다. "본인 적용"인 경우에는 본인의 다음 페이지 로드 시점부터 적용됩니다.

VAT 설정 변경은 결제·매출·세금계산서 화면의 표시 형식에만 영향을 주며 저장 데이터(숫자값)는 변경되지 않습니다.

모든 변경은 감사 로그 시스템(SCR-097)에 비동기로 INSERT되며, 기록되는 필드는 actor_id(운영자 ID), branchId(지점 ID), tab(어느 탭의 변경인지), diff JSON(변경 전/후 값 차이), timestamp(변경 시각)입니다. 감사 로그 INSERT는 저장 응답이 사용자에게 돌아간 후 5초 안에 보장됩니다.

화면에서 호출하는 주요 API 엔드포인트를 한 번에 정리하면 다음과 같습니다. 조회는 `GET /api/settings/center`, `GET /api/settings/notifications`이고, 저장은 `PUT /api/settings/center`, `PUT /api/settings/notifications`, `PUT /api/settings/theme`, `PUT /api/settings/inventory`이며, 로고 업로드는 `POST /api/settings/center/logo`, 사업자번호 검증은 `POST /api/settings/center/verify-business-no`, 주소 검색은 `GET /api/settings/center/address-search`입니다.

## 10. 화면 상태와 예외 처리

센터 설정 페이지는 다음 상태들을 가질 수 있고, 각 상태마다 사용자에게 보이는 모습이 달라집니다.

로딩 중 상태에서는 각 탭의 입력 자리에 스켈레톤이 표시되어 데이터를 불러오고 있음을 알려줍니다. 헤더와 탭 헤더는 미리 렌더되지만 상호작용은 잠시 막힙니다.

기본 상태는 200 응답과 함께 저장된 값이 모두 채워진 상태입니다. 저장 버튼은 비활성 상태로 보이고, 모든 입력은 권한에 맞게 편집 가능 또는 읽기 전용으로 표시됩니다.

수정 중 상태는 한 건 이상 변경이 발생한 상태입니다. 영향도 프리뷰가 "저장 전 검토 필요" 배지로 바뀌고, 액션 풋바의 저장 버튼이 활성화되며, 변경이 발생한 탭의 라벨 옆에 빨강 점이 표시됩니다.

저장 중 상태에서는 액션 풋바의 모든 버튼이 비활성화되고 저장 버튼 자리에 진행 스피너가 표시됩니다. 다른 탭으로 이동하는 동작도 일시적으로 차단됩니다.

저장 완료 상태에서는 성공 토스트가 표시되고 영향도 프리뷰가 "변경 없음" 배지로 돌아갑니다. 빨강 점들은 모두 사라집니다.

저장 부분 실패 상태에서는 성공한 탭은 정상으로 표시되지만 실패한 탭은 "저장 실패, 다시 시도" 안내와 함께 그 탭의 변경 사항이 그대로 남아 있습니다.

탭 이동 경고 상태는 DLG-080-001이 열린 상태입니다. 모달이 닫힐 때까지 부모 화면은 비활성 상태로 유지됩니다.

권한 제한 상태는 매니저로 진입했거나 owner가 다른 지점 설정에 접근을 시도한 경우입니다. 매니저는 알림설정 탭만 활성 상태로 보이고 다른 탭은 비활성 또는 hidden 처리됩니다. owner는 본인 지점 외의 데이터는 RLS branchId 필터로 응답 자체에서 차단됩니다.

오류 상태는 서버에서 5xx 응답이 오거나 네트워크 타임아웃이 발생했을 때입니다. 본문 중앙에 큰 에러 아이콘과 "데이터를 불러오지 못했어요" 메시지, 그리고 다시 시도 버튼이 표시됩니다.

예외 케이스별 처리는 다음과 같이 정의됩니다.

센터명을 비우거나 50자를 초과하면 인라인 카운터와 함께 에러가 표시되고 저장이 차단됩니다. 사업자등록번호가 10자리 숫자 형식을 벗어나면 형식 오류 안내가 표시되고 저장이 차단됩니다. 외부 사업자번호 검증 API가 실패하면 "검증 실패, 형식만 확인됨" 안내가 표시되지만 진행은 가능합니다.

로고가 5MB를 초과하거나 PNG/JPG가 아닌 형식이면 업로드 단계에서 차단됩니다. 평일·주말 운영시간의 마감 시각이 오픈보다 같거나 빠르면 저장이 차단되며, 24시간 운영은 00:00~24:00 형식으로만 허용됩니다.

업종을 한 개도 선택하지 않으면 "업종 1개 이상 선택" 안내가 표시되고 저장이 차단됩니다.

알림 토글은 변경 후 저장 전에는 발송 정책에 적용되지 않으며, 운영자가 실수로 즉시 발송을 차단하거나 활성할 수 없도록 보장됩니다.

메인 컬러와 보조 컬러가 동일하면 가독성 경고가 표시되지만 저장은 가능합니다.

물품 1일 발급 한도가 재고 수량을 초과하면 인라인 경고가 표시되지만 저장은 가능합니다(입고 예정을 미리 반영하기 위함).

미저장 변경이 있는 상태에서 탭 이동·지점 전환·페이지 이탈을 시도하면 DLG-080-001이 강제 표시됩니다.

매니저가 알림설정 외 탭에 직접 URL로 접근하면 본문은 보이지만 입력 필드는 모두 읽기 전용으로 표시되고 저장 버튼이 hidden 됩니다.

owner가 다른 지점의 설정에 접근하려고 하면 RLS branchId 필터로 응답 자체가 차단되어 본인 지점의 데이터만 보입니다.

저장 API가 실패하면 "저장 실패" 토스트와 다시 시도 버튼이 표시되며, 부분 실패의 경우 실패한 탭에 한해 재시도가 가능합니다.

외부 우편번호 API가 실패하면 "주소 검색 실패" 안내와 함께 수동 입력이 허용됩니다.

메시지 플랫폼 메타데이터 조회가 실패하면 "발송 정보 동기화 실패" 안내와 함께 재조회 버튼이 표시됩니다.

권한이 부족한 계정이 화면 자체에 접근하면 사이드바 메뉴가 보이지 않고, 직접 URL로 접근하면 권한 차단 화면이 표시됩니다.

## 11. 권한별 처리

이 화면은 권한에 따라 진입 가능 여부, 보이는 탭, 가능한 액션이 모두 달라집니다. 각 권한별로 어떻게 동작해야 하는지를 빠짐없이 정의합니다.

superAdmin와 primary는 모든 기능을 사용할 수 있습니다. 화면 진입에 제약이 없고, 헤더에서 지점 컨텍스트 드롭다운이 노출되어 전체 지점을 자유롭게 전환할 수 있습니다. 네 개의 모든 탭이 활성 상태이며, 로고 업로드, 사업자번호 외부 검증, 주소 검색, VAT 변경, 알림 토글 변경, 테마 전사 적용, 물품 재고 관리까지 이 화면의 모든 기능을 사용할 수 있습니다. 테마 적용 범위를 "전체 적용"으로 두면 저장 직후 모든 운영자의 화면 모드와 컬러가 바뀝니다.

Owner(지점장)은 자기 지점의 설정 전체를 편집할 수 있습니다. 지점 컨텍스트 드롭다운은 표시되지 않거나 자기 지점만 선택 가능한 상태로 노출되며, 본사 표준 컬러를 일괄 변경하는 권한은 없습니다. 네 개의 모든 탭이 활성 상태이고, 사업자번호 변경, 운영시간 조정, 로고 교체, 업종 변경, 알림 토글 변경, 테마 변경, 물품 재고 관리가 모두 가능합니다. 다만 본사 모드 전용 기능(전체 지점 통합 다운로드, 전사 테마 적용)은 사용할 수 없습니다.

매니저(manager)는 알림설정 탭만 조회 가능하며 다른 세 탭은 비활성 또는 hidden 처리됩니다. 알림설정 탭에서도 토글을 직접 누를 수 없고 현재 상태를 조회만 할 수 있으며, "메시지 플랫폼 연동 요약" 카드의 새로고침 버튼만 사용할 수 있습니다. 저장 버튼은 hidden 처리됩니다. 매니저가 다른 탭의 URL로 직접 접근하면 본문이 읽기 전용으로 표시되고 저장 버튼은 보이지 않습니다.

FC(fc), 트레이너(trainer), 스태프(staff), 프런트(front)는 이 화면 자체에 접근할 수 없습니다. 사이드바에 설정 메뉴가 보이지 않고, 직접 URL로 접근하면 권한 차단 화면이 표시되며 3초 후 대시보드로 자동 이동됩니다.

읽기 전용(readonly)도 이 화면 자체에 접근할 수 없습니다. 메뉴 자체가 보이지 않고 직접 URL 접근도 차단됩니다.

권한 외에도 운영 모드에 따라 일부 영역이 추가로 보이거나 숨겨집니다. 본사 슈퍼관리자가 통합 모드에서 진입한 경우, 헤더에 지점 컨텍스트 드롭다운이 노출되어 다른 지점의 설정을 직접 편집할 수 있습니다. 테마 적용 모드가 "전체 적용"으로 설정된 테넌트에서는 본사 슈퍼관리자가 변경 시 전 운영자에게 영향이 가는 점이 영향도 프리뷰에 명시되고, "본인 적용" 모드에서는 본인 화면만 바뀝니다.

권한이 부족해서 액션이 차단된 경우의 사용자 경험은 단계별로 일관됩니다. 첫째, 사이드바·헤더 같은 1차 진입점에서는 메뉴 자체가 숨겨집니다. 둘째, 화면 내부의 탭은 권한이 부족하면 비활성 상태로 표시되거나(매니저 시) 본문이 읽기 전용으로 보입니다. 셋째, 토글·버튼은 권한이 모자라면 비활성 상태로 표시되거나 hidden 됩니다. 넷째, 직접 URL로 접근해 백엔드까지 도달한 요청이 권한 부족인 경우 403이 반환되고 "권한이 없어요" 토스트가 표시됩니다. 모든 권한 차단 이벤트는 감사 로그에 기록되어 사후에 권한 우회 시도를 추적할 수 있도록 합니다.

## 12. 메인 흐름

센터 설정 페이지의 핵심 동작 흐름을 다이어그램으로 표현합니다. 사용자가 화면에 진입한 시점부터 저장까지의 가장 일반적인 정상 흐름입니다.

```mermaid
flowchart TD
    A([센터 설정 진입]) --> B{권한}
    B -->|FC / 트레이너 / 스태프 / readonly| C[권한 차단 + 대시보드 이동]
    B -->|매니저| D[알림설정 탭만 조회]
    B -->|Owner(지점장) / primary / superAdmin| E[전체 탭 활성]
    E --> F{탭 선택}
    F -->|기본정보| G[센터명·로고·사업자·운영시간 편집]
    F -->|알림설정| H[앱푸시·이메일·SMS 토글 + 메시지 플랫폼 조회]
    F -->|테마설정| I[화면 모드·컬러·글자 크기 편집]
    F -->|물품 관리| J[수건·운동복 재고·1일 한도 편집]
    G --> K{변경 있음?}
    H --> K
    I --> K
    J --> K
    K -->|예| L[영향도 프리뷰 갱신 + 저장 활성]
    L --> M{사용자 액션}
    M -->|저장| N[병렬 PUT 호출]
    M -->|취소| O[마지막 저장 시점으로 복원]
    M -->|탭/페이지 이동| P[DLG-080-001 미저장 경고]
    N --> Q{응답}
    Q -->|전체 성공| R[성공 토스트 + 회원앱/키오스크 push + 감사 로그]
    Q -->|부분 실패| S[성공 탭 완료 + 실패 탭 재시도 안내]
    Q -->|전체 실패| T[실패 토스트 + 다시 시도]
    P --> U{선택}
    U -->|저장| N
    U -->|이탈| V[변경 폐기 + 이동]
    U -->|취소| F
```

## 13. 에러와 예외 흐름

에러와 예외 상황에서의 분기를 별도 흐름으로 표현합니다.

```mermaid
flowchart TD
    A([액션 트리거]) --> B{서버 응답}
    B -->|5xx / timeout| C[자동 재시도 1회]
    C --> D{성공?}
    D -->|성공| E[정상 흐름 복귀]
    D -->|실패| F[다시 시도 버튼 + 사용자 대기]
    B -->|401 / 403| G["권한이 없어요" 토스트]
    G --> H[탭/버튼 비활성 + 감사 로그]
    B -->|422 형식 오류| I[인라인 검증 메시지]
    I --> J[해당 필드 포커스 + 저장 차단]
    B -->|부분 실패| K[성공 탭은 완료 / 실패 탭 재시도 안내]
    B -->|외부 사업자번호 API 실패| L["형식만 확인됨" 진행 가능]
    B -->|외부 주소 API 실패| M["주소 검색 실패" 수동 입력]
    B -->|메시지 플랫폼 조회 실패| N["발송 정보 동기화 실패" 재조회]
    B -->|로고 5MB 초과 / 형식 불일치| O[업로드 차단]
    B -->|업종 미선택| P["업종 1개 이상" 저장 차단]
    B -->|운영시간 마감 < 오픈| Q["시각 오류" 저장 차단]
    B -->|미저장 + 탭/페이지 이동| R[DLG-080-001 강제]
    B -->|매니저 직접 URL| S[본문 읽기 전용 + 저장 hidden]
    B -->|Owner(지점장) 타 지점 접근| T[RLS branchId 차단]
    B -->|회원앱/키오스크 push 실패| U[저장은 성공 + 운영자 알림]
    B -->|물품 잔여 0개| V[NFR-19 운영자 알림]
```

## 14. 핵심 디자인 요청사항

이 화면이 운영자에게 잘 작동하려면 다음 디자인 원칙이 시각적으로 명확히 드러나야 합니다. 색상 토큰·간격·폰트 같은 일반적 디자인 시스템 규칙은 별도로 다루고, 여기서는 센터 설정 화면에 고유한 디자인 요청만 적습니다.

탭 헤더는 네 개의 탭이 한눈에 들어오도록 동일 크기로 좌측 정렬되며, 어느 탭에 미저장 변경이 있는지를 알리는 빨강 점이 라벨 우측 상단에 작게 표시되어 운영자가 페이지 안에서 어디에 변경이 남아 있는지 즉시 파악할 수 있어야 합니다. 매니저로 진입한 경우 알림설정 탭만 활성 색상, 나머지는 회색 비활성으로 명확히 구분됩니다.

영향도 프리뷰 영역은 페이지 헤더와 탭 헤더 사이의 가로 폭을 모두 차지하며, "변경 없음" 회색 배지와 "저장 전 검토 필요" 주황 배지의 시각적 차이가 멀리서도 인식 가능해야 합니다. 영향 항목이 여러 개일 때는 칩 형태로 옆으로 나열되어 어떤 종류의 영향인지(운영시간, 알림, 컬러, 물품)가 색상과 아이콘으로 구분됩니다.

기본정보 탭의 로고 업로드 영역은 정사각 또는 가로형 미리보기와 함께 드래그 앤 드롭 영역이 충분히 넓게 보이도록 디자인되어, 운영자가 파일 선택 다이얼로그를 열지 않고도 파일을 떨어뜨릴 수 있어야 합니다.

알림설정 탭의 토글은 시각적으로 ON/OFF 상태가 색상과 위치 모두로 명확히 구분되며, 매니저 진입 시에는 비활성 톤으로 흐려져 "조회만 가능" 상태임이 즉시 인식 가능해야 합니다. 메시지 플랫폼 연동 요약 카드는 토글 그룹과 시각적으로 분리되어 "조회 전용 정보"임을 한눈에 알 수 있어야 합니다.

테마설정 탭의 컬러 선택기는 현재 색상의 미리보기 박스와 HEX 입력란이 나란히 표시되며, 메인과 보조 컬러가 동일할 때 가독성 경고가 인라인 색상 변화로 즉시 드러나야 합니다.

물품 관리 탭의 각 물품은 카드형 그리드로 배치되어 수건 대·수건 소·운동복 상의·운동복 하의가 한눈에 비교 가능해야 합니다. 잔여 수량은 자동 계산되어 회색 톤의 큰 숫자로 표시되며, 잔여가 0이면 빨강 톤으로 강조되어 운영자에게 즉시 신호가 갑니다.

액션 풋바는 페이지 최하단에 fixed로 떠 있어 페이지를 스크롤해도 항상 보이며, "변경 사항 저장" 버튼은 변경이 있을 때 활성 색상으로 강조됩니다. 저장 중에는 버튼 자리에 스피너가 표시되어 운영자가 응답을 기다리고 있음을 알 수 있습니다.

진행 스피너와 로딩 스켈레톤은 동일한 톤으로 통일되어 어떤 영역이 로딩 중인지 직관적으로 파악할 수 있어야 합니다.

## 15. 운영 정책 (이 화면에 연결된 부분)

이 화면은 단순한 폼이 아니라 회원앱·키오스크·결제·세금계산서·알림 채널까지 영향을 주는 운영 정책의 결정 도구입니다. 다른 문서를 보지 않아도 이 화면을 구현·운영하는 사람이 알아야 할 정책을 모두 풀어 씁니다.

본사와 지점의 소유권 분리 원칙에 따라 센터 설정의 모든 항목은 지점 소유로 운영됩니다. 본사는 표준 컬러·표준 알림 템플릿·표준 메시지 플랫폼 같은 공통 자산을 정의하지만, 지점 단위의 센터명·사업자번호·운영시간·물품 재고는 지점이 직접 편집합니다. 본사 슈퍼관리자는 통합 모드에서 다른 지점의 설정을 편집할 수 있지만 이는 본사 정책 배포 또는 지원 목적의 우회 기능이며, 일반적인 운영 권한은 지점에 위임됩니다.

권한 정책에 따라 슈퍼관리자와 primary는 모든 탭을 사용할 수 있고, owner는 자기 지점의 모든 탭을, 매니저는 알림설정 탭만 조회로, FC/트레이너/스태프/프런트/readonly는 화면 자체에 접근할 수 없습니다. 이 권한 차이는 운영 안전성과 데이터 보호를 위한 정책 결정이며, 특히 사업자번호와 VAT 설정은 세금계산서 발행에 직접 영향을 주므로 Owner(지점장) 이상에게만 편집 권한이 부여됩니다.

알림 토글의 즉시 차단 정책은 운영자의 실수로 인한 즉시 발송 중단이나 활성화를 방지하기 위해 설계되었습니다. 토글을 누르는 순간이 아니라 저장 버튼을 누른 후에야 발송 정책이 변경되며, 이는 매일 발송되는 알림이 의도치 않게 끊기거나 폭주하는 사고를 예방합니다.

미저장 변경 손실 방지(DLG-080-001) 정책은 모든 탭 전환과 페이지 이탈에 적용됩니다. 변경 입력 중 다른 작업으로 이동할 때 강제로 저장·이탈·취소를 선택하도록 함으로써, 운영자가 입력했던 내용이 사라지는 것을 막습니다.

로고 정책은 PNG/JPG 5MB 이내로 제한되며 권장 비율은 정사각형 또는 가로형입니다. 이는 회원앱·키오스크·홈페이지에서 동일한 로고가 다양한 비율로 노출되기 때문에 호환성을 보장하는 기준입니다.

업종 11종(헬스·필라테스·PT샵·골프·요가·크로스핏·복싱·수영·태권도·스피닝·기타)은 다중 선택을 허용하되 최소 1개를 강제합니다. 이는 회원앱의 검색·추천 알고리즘과 본사 통계 분석에 사용되는 메타데이터이며, 빈 값은 통계 누락의 원인이 되므로 차단됩니다.

운영시간 정책은 HH:mm 형식이며 마감 시각이 오픈보다 같거나 빨라야 합니다. 24시간 운영은 00:00~24:00 표기를 사용합니다. 운영시간은 출석 인정 시간(SCR-086 출석 관리 설정)과 IoT 출입 인정 시간(SCR-083)의 기준이 되므로 변경 시 그 화면들의 정책에도 즉시 영향이 갑니다.

VAT 설정은 부가세 포함/별도 토글이며, 저장된 숫자 데이터는 변경하지 않고 결제·매출·세금계산서 화면의 표시 형식에만 영향을 줍니다. 이는 매출 데이터의 일관성을 보장하면서도 화면 표기만 운영 정책에 맞춰 바꿀 수 있도록 한 설계입니다.

알림 채널 9종은 앱 푸시 5종(입장·만료 임박·결제 완료·수업 예약·수업 취소), 이메일 2종(주간 리포트·만료 예정), SMS 2종(결제 완료·만료 임박)으로 고정되어 있으며, 채널별 발송은 메시지 플랫폼(알림톡/SMS provider)을 통해 처리됩니다. 단가는 플랫폼 API 응답을 그대로 사용하며, 관리자에서 직접 단가를 수정하지 않습니다. 이는 비용 정합성을 외부 플랫폼 책임 영역에 위임하는 정책입니다.

테마 적용 범위는 테넌트 정책 토글로 "본인 적용"과 "전체 적용" 두 가지가 있으며, 본사 슈퍼관리자가 전체 적용으로 본사 표준 컬러를 일괄 배포할 수 있습니다. 본인 적용 모드에서는 운영자 개개인이 자기 화면 모드와 컬러를 자유롭게 고를 수 있고, 전체 적용 모드에서는 슈퍼관리자의 결정이 모든 운영자에게 즉시 적용됩니다.

물품 관리 정책은 수건 대·수건 소·운동복 상의·운동복 하의 4종을 기본으로 하며, 1일 발급 한도는 재고 수량 이하로 설정하는 것이 정상이지만 입고 예정을 미리 반영하는 경우에는 한도가 재고를 초과해도 저장이 허용됩니다(경고만 표시). 잔여 수량은 운영자가 직접 입력하지 않고 재고 - 오늘 발급 수량으로 자동 계산되며, 잔여 0개 도달 시 알림 센터로 운영자 알림이 자동 발송됩니다. 매일 자정에는 일별 발급 카운터가 리셋 배치로 0으로 초기화됩니다.

owner의 RLS branchId 필터는 자기 지점의 데이터에만 접근할 수 있도록 응답 단계에서 차단됩니다. 본사 슈퍼관리자와 primary는 전 지점에 접근할 수 있으며, 다른 지점 편집은 감사 로그에 그 지점 ID와 함께 기록됩니다.

회원앱과 키오스크 push는 기본정보 탭 저장 시점에 자동으로 트리거되며, 센터명·로고·운영시간이 변경되면 즉시 외부 면에 반영됩니다. 미연결 키오스크는 다음 connect 시점에 동기화되며, push 실패가 발생하면 저장 자체는 완료된 상태에서 운영자 알림이 별도로 발송됩니다.

감사 로그는 모든 탭의 저장 이벤트를 비동기로 기록하며, 5초 안에 SCR-097 감사 로그 화면에서 조회 가능해야 합니다. 기록되는 필드는 actor_id, branchId, tab(어느 탭의 변경인지), diff JSON(변경 전/후 값 차이), timestamp이며, 사업자번호·VAT·운영시간 같은 민감 변경은 특별 표시되어 사후 추적이 용이하도록 합니다.

이상의 모든 정책은 이 화면을 구현하고 운영하는 사람이 별도 문서 없이 이 한 장만 보면 이해할 수 있도록 풀어 적었습니다. 정책이 바뀌면 이 문서가 함께 갱신되어야 하며, 코드 변경과 정책 변경은 항상 짝지어 진행됩니다.
